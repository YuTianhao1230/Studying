# 搜索系统基础

## 知识点解析

### 概述

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。

### 典型链路

```text
Query 输入
  -> Query 理解
  -> 召回
  -> 粗排
  -> 精排
  -> 重排
  -> 展示
  -> 点击 / 转化反馈
```

### Query 理解

目标是理解用户到底想要什么。

常见任务：

- 分词。
- 拼写纠错。
- 同义词扩展。
- 意图识别。
- 实体识别。
- Query 改写。
- 多轮上下文理解。

在 AI 搜索中，还会出现：

- 任务拆解。
- 子问题生成。
- 边想边搜。
- Deep Research。
- 搜索结果归纳和引用。

### 召回

召回负责从海量候选中快速找出可能相关的结果。

常见方式：

- 关键词召回：BM25、倒排索引。
- 向量召回：Embedding + ANN。
- 图召回：基于用户、内容、关系图。
- 规则召回：运营规则、业务强约束。
- 多路召回：多个召回源合并。

### 排序

排序负责判断候选结果的相关性和价值。

常见特征：

- Query 特征。
- 文档 / 商品 / 视频特征。
- 用户画像。
- 行为历史。
- 上下文特征。
- 交叉特征。

常见模型：

- Learning to Rank。
- Cross-Encoder。
- Two-Tower + Reranker。
- Transformer 排序模型。
- LLM Reranker。

### 重排

重排不仅看单个结果分数，还要优化列表整体体验。

关注：

- 多样性。
- 去重。
- 新鲜度。
- 安全过滤。
- 商业规则。
- 探索与利用。

### LLM 对搜索的影响

LLM 让搜索从“找页面”走向“完成任务”：

- Query 改写更强。
- 能进行多跳检索。
- 能综合多来源信息。
- 能生成摘要和答案。
- 能通过 Agentic Search 主动拆解问题。

但也带来新问题：

- 幻觉。
- 引用不可靠。
- 延迟变高。
- 成本增加。
- 搜索结果和生成答案难以对齐。

### 常见指标

- Recall@K。
- Precision@K。
- NDCG。
- MRR。
- CTR。
- SAT Click。
- Zero-result Rate。
- Reformulation Rate。
- Answer Faithfulness。

## 面试应对

### 搜索系统基础 解决什么业务问题？

回答思路：点明它根据用户 Query 从海量文档/商品/视频中找相关结果，并按相关性、质量和业务目标排序展示，用 NDCG/MRR/Recall@K/CTR 等衡量。

回答模板：

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。 它关注用户、内容、广告或商品之间的匹配效率，最终要用点击、转化、留存、GMV、NDCG、AUC 或在线 A/B 指标验证。

### 搜索系统基础 的核心机制是什么？

回答思路：串起“Query 理解-召回-粗排-精排-重排”链路，强调搜索特有的 Query 理解（分词/纠错/意图）和多路召回（BM25 关键词+向量 ANN），再把信号转成排序问题。

回答模板：

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。 核心是把用户行为、内容特征和上下文信号转成可学习的排序或匹配问题。

### 搜索系统基础 的常见风险是什么？

回答思路：结合搜索特点讲 Query 理解偏差、零结果率、离线线上不一致，以及引入 LLM 后的幻觉、引用不可靠、延迟和成本上升等新问题。

回答模板：

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。 常见风险包括样本选择偏差、曝光偏差、位置偏差、冷启动、数据泄漏，以及离线指标提升但线上收益不明显。
