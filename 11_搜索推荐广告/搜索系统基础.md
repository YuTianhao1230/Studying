# 搜索系统基础

## 一句话解释

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。

## 典型链路

```text
Query 输入
  -> Query 理解
  -> 召回
  -> 粗排
  -> 精排
  -> 重排
  -> 展示
  -> 点击 / 转化反馈
```

## Query 理解

目标是理解用户到底想要什么。

常见任务：

- 分词。
- 拼写纠错。
- 同义词扩展。
- 意图识别。
- 实体识别。
- Query 改写。
- 多轮上下文理解。

在 AI 搜索中，还会出现：

- 任务拆解。
- 子问题生成。
- 边想边搜。
- Deep Research。
- 搜索结果归纳和引用。

## 召回

召回负责从海量候选中快速找出可能相关的结果。

常见方式：

- 关键词召回：BM25、倒排索引。
- 向量召回：Embedding + ANN。
- 图召回：基于用户、内容、关系图。
- 规则召回：运营规则、业务强约束。
- 多路召回：多个召回源合并。

## 排序

排序负责判断候选结果的相关性和价值。

常见特征：

- Query 特征。
- 文档 / 商品 / 视频特征。
- 用户画像。
- 行为历史。
- 上下文特征。
- 交叉特征。

常见模型：

- Learning to Rank。
- Cross-Encoder。
- Two-Tower + Reranker。
- Transformer 排序模型。
- LLM Reranker。

## 重排

重排不仅看单个结果分数，还要优化列表整体体验。

关注：

- 多样性。
- 去重。
- 新鲜度。
- 安全过滤。
- 商业规则。
- 探索与利用。

## LLM 对搜索的影响

LLM 让搜索从“找页面”走向“完成任务”：

- Query 改写更强。
- 能进行多跳检索。
- 能综合多来源信息。
- 能生成摘要和答案。
- 能通过 Agentic Search 主动拆解问题。

但也带来新问题：

- 幻觉。
- 引用不可靠。
- 延迟变高。
- 成本增加。
- 搜索结果和生成答案难以对齐。

## 常见指标

- Recall@K。
- Precision@K。
- NDCG。
- MRR。
- CTR。
- SAT Click。
- Zero-result Rate。
- Reformulation Rate。
- Answer Faithfulness。

## 面试可能怎么问

1. 搜索系统完整链路是什么？
   - 回答思路：先给一句话定义，再说明它解决什么问题，最后补一个工程例子或常见风险。
   - 回答模板：搜索系统完整链路 是 搜索系统基础 里的核心概念，主要解决系统在能力、效率、稳定性或可控性上的问题。面试中要说明它的定义、适用场景、限制，以及在真实工程中如何验证它有效。
2. BM25 和向量召回有什么区别？
   - 回答思路：先分别定义两个概念，再从目标、机制、适用场景和工程取舍四个角度对比。
   - 回答模板：先分别定义两个对象，再比较目标、机制、适用场景和风险。围绕 搜索系统基础，关键是说明它们解决的问题不同。
3. Query 改写会带来什么收益和风险？
   - 回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。
   - 回答模板：这个问题在 搜索系统基础 场景下，核心是说明它解决什么实际工程问题，以及如何落地。完整回答需要覆盖目标、执行方式、失败风险和验证指标。
4. 如何设计 LLM 搜索系统？
   - 回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。
   - 回答模板：我会把 设计 LLM 搜索系统 拆成几个步骤：先明确目标和输入输出，再设计关键模块或策略，然后加入失败处理和权限/质量约束，最后用离线指标、线上指标或回归测试验证效果。在 搜索系统基础 场景里，重点是能落到真实工程流程。
5. 如何评估搜索结果相关性？
   - 回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。
   - 回答模板：离线可以用人工标注结合 NDCG、MRR、Precision@K、Recall@K；线上看 CTR、SAT click、改写率、停留和转化。AI 搜索还要检查答案忠实性和引用正确性。
