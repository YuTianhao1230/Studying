# 推荐系统基础

## 一句话解释

推荐系统是根据用户、物品、上下文和历史行为，预测用户可能感兴趣内容并排序展示的系统。

## 典型链路

```text
用户请求
  -> 候选召回
  -> 粗排
  -> 精排
  -> 重排
  -> 规则过滤
  -> 展示
  -> 用户反馈
  -> 样本构造
  -> 模型训练
```

## 为什么要分层

线上候选物品可能有百万到亿级，不可能对所有物品都用复杂模型精排。

分层目标：

- 召回：尽可能找全相关候选。
- 粗排：快速过滤明显不相关候选。
- 精排：用更复杂模型精细预测。
- 重排：兼顾多样性、业务规则、体验约束。

## 常见模型

### 1. 协同过滤

根据用户-物品交互矩阵找相似用户或相似物品。

优点：

- 简单。
- 可解释。
- 不依赖复杂内容特征。

缺点：

- 冷启动困难。
- 稀疏矩阵效果差。

### 2. Two-Tower

用户塔和物品塔分别编码，最后用向量相似度匹配。

适合：

- 大规模召回。
- 向量检索。
- 用户和物品特征丰富的场景。

### 3. Wide & Deep / DeepFM / DCN

结合记忆能力和泛化能力，常用于 CTR/CVR 预估。

关注点：

- 稀疏特征 embedding。
- 特征交叉。
- 多目标学习。

### 4. 序列推荐

建模用户行为序列，例如点击、收藏、购买、停留。

常见方向：

- DIN / DIEN。
- Transformer-based RecSys。
- 生成式推荐。

## 大模型对推荐的影响

LLM/VLM 正在进入推荐链路：

- 商品和内容理解。
- Query / 用户意图理解。
- 多模态特征增强。
- 生成式推荐理由。
- Agentic Reasoning，用工具和中间推理缩小候选空间。

但推荐系统仍然要面对线上约束：

- 低延迟。
- 高吞吐。
- 成本可控。
- 可解释和可监控。
- A/B 实验验证。

## 常见指标

- CTR：点击率。
- CVR：转化率。
- GMV：成交金额。
- Watch Time：观看时长。
- Retention：留存。
- AUC / GAUC：排序能力。
- NDCG / MRR / Recall@K：排序和召回效果。

## 常见问题

### 1. 冷启动

新用户或新物品缺少历史行为。

解决：

- 内容特征。
- 热门兜底。
- 探索流量。
- 多模态理解。
- 规则召回。

### 2. 曝光偏差

模型只看到被展示过的样本，没展示的物品没有反馈。

解决：

- 探索策略。
- IPS / debias。
- 随机桶数据。
- 反事实评估。

### 3. 离线和线上不一致

离线 AUC 涨，不代表线上 CTR/GMV 一定涨。

原因：

- 样本分布变化。
- 训练-serving skew。
- 业务规则干扰。
- 多目标冲突。
- 用户体验指标未覆盖。

## 面试可能怎么问

1. 推荐系统为什么要分召回、粗排、精排、重排？

3. 如何处理冷启动问题？
   - 回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。
   - 回答模板：我会把 处理冷启动问题 拆成几个步骤：先明确目标和输入输出，再设计关键模块或策略，然后加入失败处理和权限/质量约束，最后用离线指标、线上指标或回归测试验证效果。在 推荐系统基础 场景里，重点是能落到真实工程流程。
4. 离线 AUC 提升但线上 CTR 不涨，怎么排查？
   - 回答思路：先确认现象和数据可信度，再分层定位数据、模型、系统和业务策略问题。
   - 回答模板：先查实验分桶和样本量，再查特征一致性、Top-K 位置收益、分群效果、延迟变化和策略覆盖。AUC 提升可能没有影响真实曝光位置。
