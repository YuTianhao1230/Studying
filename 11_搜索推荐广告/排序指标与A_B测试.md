# 排序指标与 A/B 测试

## 一句话解释

排序指标衡量模型离线排序能力，A/B 测试衡量算法改动在线上真实用户中的业务效果。算法工程师需要同时理解二者，并能解释它们不一致的原因。

## 离线排序指标

### AUC

AUC 衡量模型把正样本排在负样本前面的概率。

适合：

- 二分类排序。
- CTR/CVR 预估。
- 阈值不固定的排序问题。

局限：

- 不直接反映 Top-K 体验。
- 对用户粒度差异不敏感。
- 类别极不平衡时可能误导。

### GAUC

GAUC 是按用户或 group 分组计算 AUC 后加权平均。

更适合推荐/广告，因为排序通常发生在同一个用户或同一个请求内部。

### NDCG

NDCG 衡量排序列表前几位的相关性质量。

适合：

- 搜索排序。
- 推荐列表。
- 多级相关性标签。

### MRR

MRR 关注第一个相关结果出现的位置。

适合：

- 问答检索。
- 搜索首条结果质量。
- 工具或文档检索。

### Recall@K

Recall@K 衡量前 K 个结果中覆盖了多少相关结果。

适合：

- 召回阶段。
- 向量检索。
- RAG 文档召回。

## 线上业务指标

常见指标：

- CTR：点击率。
- CVR：转化率。
- GMV：成交额。
- Watch Time：观看时长。
- Retention：留存。
- User Satisfaction：满意度。
- Bad Case Rate：坏例率。
- Latency：延迟。
- Crash / Error Rate：稳定性。

## A/B 测试基本流程

```text
提出假设
  -> 选择实验指标
  -> 设计实验分桶
  -> 计算样本量和实验周期
  -> 灰度上线
  -> 监控护栏指标
  -> 统计显著性分析
  -> 决策放量 / 回滚 / 继续实验
```

## 核心概念

### 1. 实验假设

不要只说“新模型更好”，而要说清楚：

```text
新模型通过提升 Query-Item 匹配能力，使 CTR 提升，同时不显著伤害延迟和转化。
```

### 2. 主指标和护栏指标

- 主指标：用于判断实验是否成功。
- 护栏指标：用于防止副作用。

例如推荐系统：

- 主指标：CTR、Watch Time、GMV。
- 护栏指标：负反馈率、延迟、投诉率、内容安全。

### 3. 显著性

线上指标存在随机波动，需要判断提升是否可信。

常见关注：

- p-value。
- 置信区间。
- 最小样本量。
- 实验周期。
- 新奇效应。

### 4. SRM

SRM，Sample Ratio Mismatch，表示实验分桶比例异常。

如果 AB 组流量比例明显不符合预期，实验结果不可信。

## 离线涨、线上不涨的常见原因

- 离线数据和线上分布不同。
- 离线指标没有覆盖真实业务目标。
- 训练-serving skew。
- 样本选择偏差。
- 位置偏差。
- 模型校准变差。
- 策略规则覆盖了模型收益。
- 延迟增加抵消效果收益。
- 实验周期太短。
- 用户分群收益不均。

## 面试回答框架

如果被问“离线 AUC 涨了但线上 CTR 没涨怎么办”，可以这样回答：

```text
我会先确认实验本身是否可信，比如分桶、样本量、SRM、实验周期。
然后检查链路一致性，比如训练-serving skew、特征缺失、模型版本和策略覆盖。
接着分析指标匹配问题，AUC 提升是否发生在真正影响 Top-K 展示的位置。
最后做分群和 bad case 分析，看收益是否只集中在部分用户或场景，并决定继续迭代、缩小流量或回滚。
```

## 面试可能怎么问

1. AUC、GAUC、NDCG、MRR 分别适合什么场景？
   - 回答思路：先给适用条件，再给不适用条件，最后说明真实系统里如何组合使用。
   - 回答模板：AUC 适合二分类排序，GAUC 适合用户/请求粒度推荐广告，NDCG 适合多级相关性的列表排序，MRR 适合关注第一个正确结果的位置。
2. 推荐系统为什么不能只看 AUC？
   - 回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。
   - 回答模板：AUC 是离线整体排序指标，不直接代表 Top-K 体验、业务收益或用户满意度。线上还要看 CTR、GMV、留存、负反馈、延迟和分群效果。
3. 如何设计一次 A/B 测试？
   - 回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。
   - 回答模板：先定义实验假设、主指标和护栏指标，再做随机分桶、样本量估算、实验周期设定和灰度上线。分析时检查 SRM、显著性、置信区间和业务价值。
4. 什么是 SRM？
   - 回答思路：先给一句话定义，再说明它解决什么问题，最后补一个工程例子或常见风险。
   - 回答模板：SRM 是 排序指标与A B测试 里的核心概念，主要解决系统在能力、效率、稳定性或可控性上的问题。面试中要说明它的定义、适用场景、限制，以及在真实工程中如何验证它有效。
5. 离线指标和线上指标不一致怎么排查？
   - 回答思路：先确认现象和数据可信度，再分层定位数据、模型、系统和业务策略问题。
   - 回答模板：先确认实验可信度，再查训练-serving skew、样本分布、指标定义、策略覆盖、延迟和分群差异，最后结合 bad case 定位。
