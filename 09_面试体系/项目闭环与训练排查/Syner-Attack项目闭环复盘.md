# Syner-Attack项目闭环复盘

## 项目定位

Syner-Attack 是一个围绕视觉语言模型鲁棒性的研究项目，目标是提升多模态对抗样本在不同 VLP/VLM/MLLM 之间的黑盒迁移攻击能力。项目的核心不是单纯实现一个攻击脚本，而是把方法设计、baseline 对齐、跨模型评估、消融实验、防御评估、计算开销分析和论文返修证据组织成一个完整研究闭环。

从面试角度看，这个项目能体现三类能力：

1. 研究问题拆解：如何从 reviewer concern 反推需要补的实验和论证。
2. 多模态机制理解：如何解释图像特征、文本语义和跨模态对齐之间的攻击关系。
3. 实验闭环能力：如何保证 baseline 公平、指标可信、结果可复现、结论不过度外推。

## 项目背景

原始论文提出的核心思路是通过双流攻击破坏多模态模型的跨模态对齐：

- 图像侧：通过 feature-level disruption 和 image-text alignment disruption 生成视觉对抗扰动。
- 文本侧：通过 Visual-Guided Text Attack 根据视觉相关性选择更关键的词进行替换。
- 联合目标：同时扰动图像和文本，让攻击不只依赖单一模态，从而提升跨模型和跨任务迁移性。

返修阶段的关键压力来自审稿意见。审稿人认可问题重要性和实验覆盖面，但集中质疑以下几点：

| 审稿关注 | 本质问题 | 需要补的证据 |
| --- | --- | --- |
| 商业/现代 MLLM 只有定性案例 | 真实威胁声明缺少统计支撑 | MLLM 定量 ASR、样本量、提示模板、对比方法 |
| 技术新颖性被认为是已有方法组合 | 方法贡献表达不够聚焦 | 跨模态解耦定义、机制分析、互补性证据 |
| baseline 公平性不清楚 | 结果可能来自更强攻击预算 | 统一扰动预算、超参数、协议、复现来源 |
| 语义保持不足 | 文本攻击可能改变任务本身 | 文本语义相似度、人工或自动 fluency/semantic check |
| 防御评估缺失 | 实际鲁棒性意义不完整 | JPEG、bit-depth、blur/noise、resize padding 等防御 |
| 计算开销未量化 | 工程代价不清楚 | wall-clock、sec/img、显存、forward pass 对比 |

## 项目闭环

### 问题定义

这个项目首先要明确攻击任务的输入、输出和约束。输入包括图像和文本，输出是对抗图像和对抗文本，目标是在源模型上构造扰动，并迁移到未知目标模型。约束包括图像扰动预算、文本语义保持、词替换数量、模型访问方式和评测协议。

面试中需要强调：Syner-Attack 不是只追求白盒源模型上的攻击成功，而是追求黑盒迁移性。因此结果必须覆盖不同模型架构、不同任务、不同目标模型和不同防御条件。

### 方法设计

方法上可以拆成三个模块：

1. 图像特征扰动：让对抗图像偏离原图在视觉编码器中的表征。
2. 跨模态对齐扰动：降低对抗图像与原文本或目标文本之间的跨模态相似度。
3. 视觉引导文本攻击：根据视觉相关性选择更影响图文对齐的文本词，而不是只按语言模型重要性替换。

这里的关键表达是“协同双流攻击”。如果只攻击图像，文本仍可能提供稳定语义锚点；如果只攻击文本，图像仍可能维持视觉证据；联合攻击则同时破坏视觉特征和图文对齐关系，目标是让下游模型难以通过另一模态补救。

### 评测设计

返修阶段的评测要覆盖四层：

| 评测层 | 目的 | 典型指标 |
| --- | --- | --- |
| 传统 VLP 任务 | 验证与既有工作可比 | ITR ASR、TR ASR、caption metric drop |
| 现代开源 MLLM | 回应“评估过时” | CLIP-proxy ASR、answer shift rate |
| 商业 MLLM | 支撑真实威胁声明 | GPT-4o 等 API 模型定量 ASR |
| 防御下评估 | 验证攻击鲁棒性 | JPEG/blur/noise/bit-depth 后 ASR |

评测设计里最重要的是协议对齐。对于 GLEAM 这类直接 baseline，要尽量复用相同数据集、相同样本数、相同指标定义和相同防御设置。如果无法完全一致，需要在论文中明确说明差异来源。

### 结果组织

论文返修不是“补实验越多越好”，而是把每个实验对应到 reviewer concern：

- MLLM 定量评估回答“是否只在旧 VLP 上有效”。
- image-only vs image-and-text 回答“文本攻击是否真的有贡献”。
- VGA 消融回答“视觉引导词选择是否优于普通 BERT-Attack”。
- 扰动预算消融回答“收益是否来自更大 epsilon”。
- 防御评估回答“简单预处理是否能抹掉攻击效果”。
- 计算开销回答“方法是否实用”。
- alignment disruption 指标回答“跨模态解耦是否只是口号”。

## 面试表达

### 请介绍一下 Syner-Attack 这个项目。

回答思路：先讲研究问题，再讲方法模块，最后讲返修阶段如何补证据。

回答模板：

Syner-Attack 是我做的一个多模态对抗攻击研究项目，目标是提升攻击样本在视觉语言模型和多模态大模型之间的迁移性。传统攻击很多只扰动图像或只扰动文本，容易被另一模态提供的语义信息纠正。我的思路是同时从图像特征、图文对齐和文本语义三个层面破坏多模态关联：图像侧用 feature loss 和 alignment loss 生成扰动，文本侧用视觉相关性指导词替换。返修阶段我重点把原来偏定性的商业 MLLM 案例，升级成定量 ASR、baseline 对齐、防御评估、计算开销和消融实验，从而让论文结论有更完整的证据链。

### 这个项目最大的技术难点是什么？

回答思路：不要只说攻击实现难，要说“研究主张如何被证据支撑”。

回答模板：

我认为最大的难点不是把攻击算法跑通，而是证明它确实带来了跨模态迁移收益。因为审稿人会质疑方法只是 MI-FGSM、TI、BERT-Attack 和 CLIP similarity 的组合。所以返修时需要把贡献从“堆组件”重新表述为“跨模态解耦机制”，并用实验支撑：比如单独图像攻击、单独文本攻击、联合攻击的对比，VGA 消融，alignment disruption 指标，以及不同 MLLM 上的定量 ASR。只有这些证据闭环起来，才能说明方法不是简单组合，而是两个模态攻击信号之间确实存在互补性。

### 你怎么保证 baseline 比较公平？

回答思路：围绕预算、数据、模型、指标和复现来源回答。

回答模板：

我会从五个方面保证公平性。第一是数据一致，使用相同的数据集、样本量和采样协议。第二是扰动预算一致，比如图像 epsilon、迭代步数、文本替换比例都要明确。第三是模型一致，源模型和目标模型要在表格里写清楚。第四是指标一致，不能一个方法报 R@1 ASR，另一个方法报混合指标。第五是复现来源一致，如果某些 baseline 直接引用原论文结果，某些是本地复现，就要解释差异。返修时我会优先和 GLEAM 的 Table 3、Table 4 协议对齐，因为它是最直接的近邻工作。

### 如何回应“你的方法新颖性不足”？

回答思路：承认组件有继承关系，但把贡献定位到机制和系统验证。

回答模板：

我不会把每个组件都说成全新。更准确的表述是：已有工作分别研究了图像攻击、文本攻击或对齐攻击，但缺少对双流扰动如何共同破坏跨模态对齐的系统分析。Syner-Attack 的贡献在于把 feature-level disruption、alignment disruption 和 visual-guided text attack 放在统一迁移攻击框架下，并通过消融、对齐破坏指标和 MLLM 定量评估证明这些信号具有互补性。也就是说，创新点应落在跨模态解耦机制的发现和验证，而不是单个优化器或单个损失函数。

### 如何设计 MLLM 定量评估？

回答思路：讲清样本量、模型、提示模板、ASR 定义、重复实验和统计口径。

回答模板：

我会先固定一批 clean image-text 样本，生成对应的 Syner 和 baseline 对抗样本。目标模型覆盖开源 MLLM 和商业 API，例如 LLaVA、Qwen2-VL、InstructBLIP、GPT-4o 等。提示模板不能只有 describe this image，需要覆盖描述、问答、具体属性询问等多种形式。ASR 可以定义为攻击后回答与 clean 回答语义不一致的比例，或者用 CLIP-proxy/Judge 做自动判定。为了减少随机性，商业 API 至少要固定 temperature，并在样本量、过滤规则和失败重试策略上保持一致。最终表格要同时报告样本量、ASR、baseline 和协议说明。

### 如果实验结果不如 GLEAM 怎么办？

回答思路：强调真实报告和分场景分析，不强行包装。

回答模板：

如果某些模型上不如 GLEAM，我会真实报告结果，然后做分场景分析。可能原因包括 GLEAM 的 NURBS 变换对某些模型的视觉前处理更有效，或者 Syner 的文本侧扰动在该协议下没有被目标模型充分使用。接下来我会看 image-only、text-only、image-and-text 的对比，判断收益来自哪个分支；再看扰动预算、防御设置和语义保持约束是否限制了攻击强度。论文里可以把结论收敛成“在多数设置下具备强迁移性，并在某些模型上存在方法适配差异”，而不是过度声称全面最优。

### 如何把这个项目讲成一个研究闭环？

回答思路：按 reviewer concern -> 实验 -> 结论 -> 论文修改组织。

回答模板：

这个项目的闭环是从审稿问题反推实验和写作修改。审稿人质疑 MLLM 评估不足，我补定量 ASR 和协议；质疑新颖性，我补跨模态解耦定义和消融；质疑公平性，我补 baseline 预算和复现说明；质疑语义保持，我补文本扰动质量验证；质疑实用性，我补防御和计算开销。每个实验都不是孤立跑分，而是对应一个论文主张。最终目标是让论文从“方法描述 + 结果表格”变成“问题、机制、证据、边界和可复现协议”完整闭环。

## 常见追问

### 为什么双流攻击可能比单图像攻击更强？

回答模板：

多模态模型通常会同时利用图像证据和文本上下文。如果只扰动图像，文本仍然可能让模型保持正确语义；如果只扰动文本，图像仍然能提供视觉锚点。双流攻击同时削弱视觉表示和图文对齐关系，相当于减少模型从另一模态恢复语义的机会。尤其在检索、caption 和 MLLM 场景中，图像与文本之间的相似度和互证关系很关键，所以联合扰动可能带来更强迁移性。

### 文本攻击怎么避免改变原始语义？

回答模板：

文本攻击必须加语义保持约束，不能为了攻击成功随意替换关键词。我会限制替换比例，优先替换对视觉对齐重要但不改变核心语义的词，并用 embedding similarity、语言模型困惑度、语法检查或人工抽检验证 fluency 和 semantic preservation。对于会改变实体、数量、属性或关系的替换，要直接过滤。否则攻击成功可能只是因为任务输入被改了，而不是模型被攻击了。

### 防御评估怎么做？

回答模板：

防御评估应覆盖简单输入变换和一致性检测两类。简单变换包括 JPEG 压缩、bit-depth reduction、Gaussian blur/noise、random resize padding，主要测试扰动是否容易被预处理抹掉。一致性检测可以比较 clean/augmented 输入下的图文相似度或输出稳定性。报告时不能只说防御后 ASR 下降，还要说明攻击是否仍高于 baseline，以及防御本身对 clean 样本性能有没有损伤。

### 计算开销怎么比较？

回答模板：

计算开销应该至少报告 wall-clock time、sec/img、显存峰值和 forward/backward 次数。如果和 GLEAM 比较，要在同样硬件、同样 batch、同样迭代步数和同样样本规模下测。对于文本攻击，还要单独说明词重要性计算、候选词生成和语义过滤的额外开销。这样才能回答方法是否只是效果好但成本不可接受。
