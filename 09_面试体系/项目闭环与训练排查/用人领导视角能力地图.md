# 用人领导视角能力地图

## 知识点解析

### 概述

如果我是用人领导，看模型训练方向候选人时，不会只看他是否知道 SFT、DPO、FSDP、vLLM 这些名词，而会重点判断他能不能把一个模型项目从问题定义推进到可验证结果。结合你的项目经历，最应该展示的是五类能力：

1. 研究问题拆解能力。
2. 数据闭环和数据质量能力。
3. 大模型训练工程能力。
4. 评测实验和归因能力。
5. 业务上线和工程稳定性能力。

## 能力地图

### 研究问题拆解

| 面试官想看 | 你的项目证据 | 表达重点 |
| --- | --- | --- |
| 能否从模糊问题中定义技术目标 | Syner-Attack 的 cross-modal decoupling；关键帧识别的完成态定义 | 把问题从“攻击有效/识别关键帧”拆成可测量目标 |
| 能否面对质疑重新组织证据 | Syner-Attack 返修路线 | reviewer concern -> 实验设计 -> 论文表格 |
| 能否不过度声称 | Syner-Attack novelty 争议 | 承认组件继承，强调机制验证和系统评估 |

高质量回答：

我不会只把项目描述成“做了一个模型”或“实现了一个方法”，而是先定义可验证问题。比如 Syner-Attack 中，我把审稿人对 novelty 和 MLLM 评估的质疑转成实验任务；关键帧识别中，我把人工经验里的完成态拆成可训练和可评测的规则。这种问题拆解决定后续实验是否有效。

### 数据闭环和数据质量

| 面试官想看 | 你的项目证据 | 表达重点 |
| --- | --- | --- |
| 是否知道数据决定模型上限 | 关键帧 15w+ 数据、172 个训练指标、110 个测试指标 | 数据不是量越多越好，标准和质量更关键 |
| 是否能识别标签噪声 | 204 个 bad case 中 68 个标注误差 | GT 需要被验证，不能盲信 |
| 是否有回流机制 | 三轮 27000+ 高质量样本返修 | 数据飞轮/主动学习闭环 |
| 是否避免污染 | CoT 不泄漏 GT、评测集隔离 | 训练、评测、回归集分离 |

高质量回答：

我在关键帧项目里最大的收获是，模型效果问题经常不是单纯模型能力问题，而是数据标准和标签质量问题。如果不先做 bad case 归因和标注标准沉淀，继续训练可能是在放大噪声。因此我把数据闭环设计成模型筛错、人工复查、重标回流、分桶评测和回归验证，而不是简单把错例加入训练集。

### 大模型训练工程

| 面试官想看 | 你的项目证据 | 表达重点 |
| --- | --- | --- |
| 是否跑过完整训练链路 | mllm-data -> msswift_scripts -> mllm-evaluation | 数据构建、训练、推理、评测、case 分析 |
| 是否理解资源和环境 | 开发机、云盘、GPU 队列、集群选择 | 资源与数据同集群，debug 和正式训练分离 |
| 是否有复现意识 | version、disk_prefix、checkpoint、prediction、metrics | 每次实验要能回查 |
| 是否知道训练风险 | OOM、NaN、hang、吞吐、checkpoint | 有系统排查框架 |

高质量回答：

我理解训练工程不是提交一个训练任务，而是维护一条可复现链路。关键帧项目里，数据处理、训练、推理和评测分别在不同代码库和平台中完成，所以必须管理数据版本、模型输出路径、checkpoint 对应关系和评测脚本。否则指标变化无法归因，也无法支撑上线判断。

### 评测实验和归因

| 面试官想看 | 你的项目证据 | 表达重点 |
| --- | --- | --- |
| 是否知道平均指标不足 | 全量 ACC、业务线 ACC、分指标 ACC | 平均值会掩盖核心业务短板 |
| 是否会设计消融 | Syner 的 image-only/text-only/VGA/预算消融 | 每个消融回答一个问题 |
| 是否会做 bad case 分析 | 关键帧错误 taxonomy | 错误类型决定优化策略 |
| 是否能判断指标可信 | GT 复核、协议对齐、baseline 公平性 | 先保证评测可信，再谈提升 |

高质量回答：

我看实验结果时不会只看平均指标。关键帧项目要拆到业务线和 task_type，因为高优业务线达标比全量平均更重要；Syner-Attack 要看不同目标模型、不同攻击分支和不同防御条件，因为单个表格不能证明迁移性。评测的核心是让每个指标回答一个明确问题。

### 业务上线和工程稳定性

| 面试官想看 | 你的项目证据 | 表达重点 |
| --- | --- | --- |
| 是否理解离线到线上差异 | 关键帧模型 5 月底上线 | 接口、字段、预处理、后处理一致 |
| 是否做过容量评估 | 单卡并发 20、QPM 22 | 压测和服务边界 |
| 是否能定位系统瓶颈 | 图片下载 30s、模型推理 3s | 不把所有问题归因到模型 |
| 是否知道上线风险 | 超时、失败、队列、fallback、版本回滚 | 模型服务要稳定可恢复 |

高质量回答：

上线前我会把离线模型看成整个服务链路的一部分，而不是只看模型推理。关键帧项目里，端到端耗时主要来自图片下载，而模型推理只有几秒。如果不拆链路，很容易把优化方向误判成换模型或加 GPU。上线验证要同时看效果、延迟、吞吐、失败率和字段映射。

### 最容易被追问但容易答虚的问题

#### 你说模型效果提升，怎么证明不是数据泄漏？

回答模板：

我会从数据切分和评测集隔离来证明。关键帧任务里需要避免同一视频、相邻帧或同一采集批次同时进入训练和测试；bad case 回流后，原评测集如果被用于训练，就不能继续作为最终泛化评测。更可靠的做法是保留独立 holdout 和业务回归集，记录每次数据版本和样本来源，并抽样做人审确认。

#### 你说数据飞轮有效，怎么证明不是只过拟合高优业务线？

回答模板：

我会同时看目标业务线和全量指标。如果高优业务线提升，但全量或其他业务线明显退化，就说明数据配比有问题。还要看历史回归 case 是否保持稳定，bad case 类型是否真的减少。数据飞轮的目标不是把模型训练成只会某几个指标，而是在不损伤基础能力的情况下提升准出短板。

#### 你说 CoT 有用，怎么证明不是增加 token 后的表面收益？

回答模板：

我会做 Direct SFT、Structured CoT SFT 和 CoT+RL 的对照，并比较最终时间误差、格式合法率、边界证据正确率和输出长度。CoT 的价值不应该只体现在回答更长，而要体现在首次完成态判断更准、前后帧解释更可验证。如果 CoT 变长但时间精度不升，说明它只是解释文本，不是有效训练信号。

#### 你说 Syner-Attack 有跨模态协同，怎么证明？

回答模板：

我会用消融证明。分别跑 image-only、text-only 和 image-and-text，看联合攻击是否显著优于单模态；再拆 feature loss、alignment loss 和 VGA，看每个模块是否贡献不同错误模式。还可以引入 alignment disruption 指标，验证攻击后图文相似度下降是否和 ASR 提升相关。这样才能说明协同不是口号，而是有可测量证据。

## 最终定位

你的项目经历适合被包装成“模型训练闭环型候选人”，而不是只做某个算法点：

- 能做研究问题拆解：Syner-Attack。
- 能做数据闭环：关键帧识别数据飞轮。
- 能做训练工程：mllm-data、msswift、mllm-evaluation 链路。
- 能做评测归因：分桶指标、bad case、GT 复查。
- 能做上线落地：接口、压测、吞吐、线上回测。

面试中要持续把回答拉回这条主线：我不是只知道模型概念，而是能把模型训练任务从问题、数据、训练、评测、部署到迭代闭环做完整。
