## 面试官真正想判断什么

### 能否定义问题

好的项目回答不是先讲技术名词，而是先说清楚业务或研究问题是什么。Syner-Attack 的问题是“如何让多模态对抗攻击具备可迁移、可解释、可定量验证的跨模型攻击能力”；关键帧识别的问题是“如何把人工判断 UI 完成态的经验过程标准化、模型化、评测化、上线化”。

### 能否形成闭环

面试官会关注你是否只做了一个实验，还是建立了完整闭环。完整闭环至少包括：

1. 问题定义：目标、输入、输出、约束、业务或论文评价标准。
2. 数据构建：数据来源、标注规则、schema、清洗、切分、版本。
3. 模型训练：基座选择、训练范式、超参数、资源、训练稳定性。
4. 评测验证：离线指标、分桶指标、bad case、统计显著性、消融。
5. 工程上线：接口、吞吐、延迟、监控、回滚、失败处理。
6. 迭代机制：数据回流、错误归因、下一轮优先级。

### 能否做归因

模型效果不好时，优秀回答不会直接说“换模型”或“加数据”，而是先定位瓶颈：

- 标注标准是否一致。
- 数据分布是否偏移。
- 训练集和评测集是否泄漏。
- 模型是否缺少细粒度视觉能力。
- 推理输入是否漏掉关键帧。
- 指标实现和后处理是否正确。
- 线上链路是否和离线评测一致。

### 能否把结果讲成证据

项目中每个数字都应该回答一个问题：

- 平均 ACC 提升说明整体能力提升。
- 业务线 ACC 提升说明核心交付目标达成。
- bad case 中标注误差占比说明数据质量是瓶颈之一。
- 三轮数据飞轮收益说明定向返修比平均补量更有效。
- 压测 QPM 和平均耗时说明服务容量边界。
- ASR、扰动预算、防御评估说明攻击方法的真实有效性和鲁棒性。

## 面试回答的统一结构

### 项目介绍

回答思路：用 30 秒讲清楚背景、目标、你的职责和结果。

回答模板：

我做过两个比较能体现训练和评测闭环的项目。第一个是 Syner-Attack，它是围绕 VLM/MLLM 对抗攻击的研究项目，我主要推进从攻击方法、baseline 对齐、MLLM 定量评估、防御评估到论文返修证据的完整闭环。第二个是视频关键帧识别能力建设，它是业务中的多模态时间定位任务，我负责把人工关键帧判断经验转化成可训练数据、评测指标、数据飞轮和线上服务，最终支撑模型上线和持续迭代。这两个项目分别体现了研究问题拆解和工业模型训练工程落地。

### 项目深挖

回答思路：不要只讲做了什么，要讲每一步为什么必要。

回答模板：

我会按“问题定义、数据构建、模型训练、评测验证、上线或论文产出、迭代复盘”来讲。因为模型训练项目最容易出现的问题是只看单次指标，而忽略数据质量、评测口径和工程链路。我的做法是先把目标和准出标准定义清楚，再把数据、模型、评测和错误回流打通；每一轮实验都能回答一个具体问题，例如是标注噪声导致错误，还是模型细粒度感知不足，或者是推理输入采样策略导致边界帧被漏掉。

### 项目价值

回答思路：把技术动作落到业务、论文或工程收益上。

回答模板：

我理解项目价值不能只看模型分数，而要看它是否改变了原有流程。关键帧识别项目里，价值是把人工标注瓶颈转成模型预标和数据飞轮，让数据回流周期更短、标注成本下降、核心业务线指标达到准出。Syner-Attack 里，价值是把原来容易被审稿人质疑的定性攻击案例，升级成可复现的定量评估、baseline 对齐、防御实验和机制论证，让论文主张有更强证据支撑。
