# 简历项目表达与STAR故事库

## 知识点解析

### 概述

项目经历在简历和面试里的目标不是“把做过的事全写上”，而是让面试官快速判断三件事：

1. 你解决的问题是否真实重要。
2. 你是否有清晰 ownership，而不是只参与执行。
3. 你的方法是否形成了可验证结果和可复用沉淀。

对于模型训练岗位，项目表达要尽量避免空泛词，例如“参与模型优化”“负责数据处理”“提升模型效果”。更好的表达应该包含：

- 任务背景：为什么要做。
- 技术难点：难在哪里。
- 你的动作：你具体推动了什么。
- 量化结果：提升多少、覆盖多少、上线了吗。
- 方法沉淀：能否迁移到下一轮项目。

## 简历项目写法

### 关键帧识别项目

#### 简历标题

视频关键帧识别多模态模型训练与上线

#### 简历 bullet 版本

- 面向移动端 UI 性能评估场景，建设视频关键帧识别模型，将人工判断指标结束帧的流程标准化为可训练、可评测、可上线的多模态时间定位能力。
- 设计 task_type 级标注标准，将完成态、排除条件、豁免条件、首选证据和备选证据写入训练与评测链路，解决不同业务指标完成态定义不一致的问题。
- 搭建 bad case 驱动的数据飞轮，完成模型预测错误样本筛选、人工复查、relabel、数据回流和再训练；沉淀 15w+ 样本，三轮返修 27000+ 高质量样本。
- 推动模型训练、推理、评测和上线闭环，平均 ACC 从 75.714 提升至 84.876，国际电商 ACC 从 84.093 提升至 95.933，线上 3 帧误差回测平均达到 90.05%。
- 参与模型服务接入与压测，拆解端到端耗时瓶颈，定位图片下载约 30s、模型推理约 3s，确定单卡并发 20、QPM 约 22 的部署边界。

#### 面试 30 秒版本

回答模板：

我做过一个视频关键帧识别模型项目，目标是从移动端操作录屏中自动定位业务指标结束帧，替代部分人工标注。这个任务难点在于不同 task_type 的完成态标准不一样，人工 GT 也存在噪声。我主要做了标注标准沉淀、bad case 归因、数据飞轮、训练评测和上线联调。最终沉淀 15w+ 样本，三轮返修 27000+ 高质量数据，平均 ACC 从 75.714 提升到 84.876，国际电商 ACC 从 84.093 提升到 95.933，并完成线上部署和回测。

#### 面试 2 分钟版本

回答模板：

这个项目可以按闭环讲。最开始的问题是人工标注 UI 性能指标结束帧成本高，而且不同人对完成态理解不一致。比如有些指标要等待商品图和营销 banner 完全加载，有些指标只需要首帧出现，有些元素属于豁免项。我的第一步是把这些人工经验沉淀成 task_type 级标注标准，拆成完成态、排除条件、豁免条件和关键证据。第二步是做数据治理和 bad case 归因，我发现一部分错误不是模型错，而是人工 GT 本身偏早或偏晚，所以不能盲目回流。第三步是搭建数据飞轮，用模型筛错、人工复查、relabel、回流训练的方式定向提升高优业务线。第四步是训练和评测闭环，既看全量 ACC，也看业务线和分指标 ACC。最后是上线联调和压测，保证离线效果能在线上服务中稳定被消费。这个项目让我比较系统地理解了训练工程里数据标准、评测口径、模型能力和线上链路之间的关系。

### Syner-Attack 项目

#### 简历标题

Syner-Attack 多模态对抗攻击研究与论文返修

#### 简历 bullet 版本

- 围绕 VLM/MLLM 黑盒迁移攻击问题，研究 Syner-Attack 双流多模态对抗攻击框架，通过图像侧 feature/alignment loss 与文本侧 visual-guided word replacement 联合破坏跨模态对齐。
- 针对审稿人关于 MLLM 定量评估不足、技术新颖性、baseline 公平性、语义保持和防御评估的质疑，拆解返修优先级并补充实验协议。
- 对齐 GLEAM 等近邻 baseline，补充开源/商业 MLLM CLIP-proxy ASR、防御下 ITR、计算开销、image-only vs image-and-text、VGA 和扰动预算等结果。
- 将论文主张从“攻击有效”升级为“跨模态解耦机制可被定量证据支撑”，用消融、对齐破坏指标和 MLLM ASR 组织返修证据链。

#### 面试 30 秒版本

回答模板：

Syner-Attack 是我做的多模态对抗攻击研究项目，目标是提升对抗样本在视觉语言模型和多模态大模型之间的黑盒迁移性。方法上同时攻击图像和文本：图像侧破坏视觉特征和图文对齐，文本侧用视觉相关性指导词替换。返修阶段我主要围绕审稿人质疑补强证据，包括 MLLM 定量 ASR、baseline 对齐、防御评估、计算开销和消融实验，让论文从定性案例升级为可复现、可比较的研究闭环。

#### 面试 2 分钟版本

回答模板：

这个项目的核心问题是，多模态模型里图像和文本会互相提供语义锚点，所以只攻击单一模态时，另一模态可能帮助模型恢复正确理解。Syner-Attack 的思路是同时破坏视觉表征、图文对齐和文本语义，使攻击具备更强迁移性。返修时最大的挑战不是代码实现，而是审稿人认为方法像已有组件组合，而且现代 MLLM 评估不足。因此我把任务拆成几条证据线：第一，补开源和商业 MLLM 定量 ASR；第二，对齐 GLEAM 的协议和防御实验，保证比较公平；第三，做 image-only、text-only、image-and-text 和 VGA 消融，证明各模块贡献；第四，补计算开销和语义保持验证。这样项目就从单纯方法实现，变成了围绕 reviewer concern 的研究证据闭环。

## STAR 故事库

### 故事一：发现模型效果问题的根因其实是标注质量

| 维度 | 内容 |
| --- | --- |
| Situation | 关键帧识别模型在部分指标上效果不稳定，直接看指标很难判断是模型能力不足还是数据问题。 |
| Task | 需要定位错误来源，并决定下一轮是补数据、修标注标准、换模型还是调推理策略。 |
| Action | 抽取 bad case 做人工复查，按 task_type 标准检查 GT 前、GT、GT 后帧，区分模型错、GT 错、标准冲突和小元素漏看。 |
| Result | 在 204 个 bad case 中发现 68 个标注误差，返修样本中 relabel 占约 61.45%；据此推动重标和数据回流，而不是盲目继续训练。 |

面试表达：

我遇到过一个典型问题：模型效果不好时，团队一开始容易倾向于认为是模型能力不够。但我抽样复查 bad case 后发现，相当一部分错误其实来自人工 GT 偏早或偏晚。于是我把错误分成标注问题、模型能力问题、标准冲突和推理粒度问题，再决定对应处理方式。这个过程避免了把错误标签继续回流训练，也让后续数据飞轮更有针对性。

### 故事二：把人工经验转成可训练标准

| 维度 | 内容 |
| --- | --- |
| Situation | 不同业务指标对完成态的定义不同，人工标注经验分散，模型容易学到平均策略。 |
| Task | 需要把人工判断过程结构化，让模型能按业务规则判断关键帧。 |
| Action | 将 task_type 标准拆成完成态、排除条件、豁免条件、首选证据和备选证据，并写入 prompt、训练数据和评测说明。 |
| Result | prompt 和标注标准对齐后，1 epoch 快速验证中平均 ACC 从 73.886 提升到 81.54，国际电商 ACC 从 84.466 提升到 95.418。 |

面试表达：

我发现关键帧识别不是简单让模型看页面是否出现，而是要理解每个指标的业务完成态。所以我把人工标注经验拆成结构化规则，例如哪些元素必须等待、哪些元素可以豁免、首选证据是什么、遮挡时看什么备选证据。这相当于给模型补业务先验，实验上也带来了明显提升。

### 故事三：论文返修中把质疑转成实验清单

| 维度 | 内容 |
| --- | --- |
| Situation | Syner-Attack 审稿意见集中质疑 MLLM 评估不足、novelty 不足、baseline 不公平、缺少防御和计算开销。 |
| Task | 需要把分散的 reviewer concern 转成可执行返修路线。 |
| Action | 按 P0/P1/P2 拆分实验：MLLM 定量 ASR、跨模态解耦定义、GLEAM 协议对齐、防御评估、计算开销、扰动预算和 VGA 消融。 |
| Result | 形成了以 reviewer concern 为索引的实验和写作闭环，让每张表和每个消融都能回答一个明确质疑。 |

面试表达：

这个项目让我意识到，研究返修不能只是补更多实验，而是要让每个实验回答一个明确质疑。我把审稿意见拆成优先级：最关键的是 MLLM 定量评估和 novelty 论证，其次是公平性、防御和计算开销。这样返修工作就从“补结果”变成了“补证据链”。

### 故事四：上线服务瓶颈不在模型推理

| 维度 | 内容 |
| --- | --- |
| Situation | 关键帧模型准备上线，需要确认端到端服务耗时和并发能力。 |
| Task | 需要定位性能瓶颈并给出部署配置建议。 |
| Action | 拆分图片下载、预处理、模型推理、后处理等耗时，并做单卡并发压测。 |
| Result | 发现串行图片下载约 30s，模型推理约 3s，瓶颈主要在下载链路；单卡并发控制在 20 左右较合适，QPM 约 22。 |

面试表达：

上线前我没有只看模型推理时间，而是拆了端到端链路。结果发现模型推理只有几秒，主要耗时来自图片下载。这说明如果只盯模型优化，会把资源投错方向。后续应该优先优化并发下载、缓存和链路调度，同时用压测结果确定服务并发上限。

## 简历表达禁忌

### 不要写得像旁观者

不推荐：

- 参与关键帧识别模型优化。
- 参与数据处理和模型训练。
- 参与对抗攻击论文实验。

更推荐：

- 建设关键帧识别数据飞轮，完成 bad case 归因、relabel 回流和分桶评测。
- 将人工标注标准结构化为 task_type 级完成态、排除条件和豁免条件，提升模型业务准出能力。
- 对齐 GLEAM 协议补充 MLLM 定量 ASR、防御评估和计算开销实验，支撑 Syner-Attack 论文返修。

### 不要只写指标，不写动作

不推荐：

- 将国际电商 ACC 提升到 95.933。

更推荐：

- 通过 task_type 标注标准沉淀和三轮高优数据飞轮，将国际电商 ACC 从 84.093 提升到 95.933。

### 不要只写动作，不写结果

不推荐：

- 设计了数据飞轮和 bad case 分析流程。

更推荐：

- 设计“模型筛 bad case -> 人工复查 -> relabel -> 回流训练”的数据飞轮，三轮返修 27000+ 高质量样本，并将平均 ACC 从 75.714 提升到 84.876。
