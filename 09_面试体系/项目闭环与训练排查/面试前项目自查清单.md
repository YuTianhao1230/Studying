# 面试前项目自查清单

## 使用方式

这份清单用于面试前逐项确认：每个项目是否能讲清楚、是否有数字支撑、是否能回答追问、是否知道边界。它比知识点复习更接近真实面试准备。

## 项目总览自查

### 每个项目都要能回答

- 项目一句话是什么。
- 为什么要做这个项目。
- 你负责哪一部分。
- 输入和输出是什么。
- 关键技术难点是什么。
- 你做了哪些具体动作。
- 结果提升多少。
- 怎么证明提升可信。
- 遇到最大问题是什么。
- 如果重做会怎么优化。

### 每个项目都要准备的证据

| 证据类型 | 需要准备 |
| --- | --- |
| 指标 | 起点、终点、提升幅度、样本量、误差阈值 |
| 数据 | 数据来源、规模、切分、版本、清洗规则 |
| 实验 | baseline、消融、对照组、随机性控制 |
| case | 成功 case、失败 case、典型 bad case |
| 工程 | 训练脚本、评测脚本、部署链路、压测结果 |
| 风险 | 当前方案限制、未解决问题、下一步计划 |

## 关键帧识别项目自查

### 必须记牢的数字

| 数字 | 含义 |
| --- | --- |
| 15w+ | 已沉淀关键帧识别相关样本规模 |
| 11w+ | 训练集规模，覆盖 172 个指标 |
| 4w+ | 测试集规模，覆盖 110 个指标 |
| 27000+ | 三轮数据飞轮返修高质量样本 |
| 75.714 -> 84.876 | 平均 ACC 提升 |
| 84.093 -> 95.933 | 国际电商 ACC 提升 |
| 90.05% | 国际电商关键帧识别 3 帧误差线上回测平均 |
| 19% | 标注成本下降 |
| 9.5% | 提效贡献占比 |
| 68/204 | bad case 人工筛查中发现的标注误差 |
| 61.45% | 返修样本中 relabel 占比 |
| 30s vs 3s | 图片下载约 30s，模型推理约 3s |
| 并发 20 / QPM 22 | 单卡部署压测建议边界 |

### 必须准备的典型 case

1. 标注标准冲突 case：同一 UI 元素在不同指标下等待规则不同。
2. GT 偏晚 case：人工等待了不该等待的顶部导航、悬浮按钮或非关键区域。
3. 模型漏看 case：购物车角标、小头像、小价格、banner 文案等小元素。
4. 时间边界 case：0.5s 仍模糊，0.6s 首次清晰稳定。
5. 二次刷新 case：页面首轮短暂停稳，但后续核心商品区域刷新，不能提前判完成。

### 必须能讲清楚的技术判断

- 为什么关键帧识别不是普通视频理解。
- 为什么完成态定义比模型结构更重要。
- 为什么 bad case 不能直接回流训练。
- 为什么数据飞轮要按业务价值和错误类型排序。
- 为什么 CoT 数据要避免 GT 泄漏。
- 为什么粗筛 + 精筛能兼顾成本和精度。
- 为什么上线瓶颈可能在图片下载而不是模型推理。

### 可能被追问的风险边界

| 追问 | 应答方向 |
| --- | --- |
| 95.933 是否说明全部业务都达标？ | 不说明，需要看业务线、分指标和长尾指标；平均值会掩盖局部短板 |
| 三轮数据飞轮是否会过拟合高优业务线？ | 有风险，所以要保留全量回归集，并观察其他业务线是否退化 |
| CoT 会不会只是让模型学会说理由？ | 有风险，所以 CoT 必须绑定时间证据、UI 状态和最终 answer，并做程序化过滤 |
| 人工 GT 都可能错，评测还可信吗？ | 需要通过抽检、重标、标准版本和干净 holdout 提升评测可信度 |
| 上线后如何继续迭代？ | 线上回放、失败样本抽检、数据飞轮、分桶监控、版本回归 |

## Syner-Attack 项目自查

### 必须记牢的主线

1. 问题：多模态对抗样本如何提升跨模型、跨任务、跨范式迁移性。
2. 方法：图像侧 feature/alignment loss，文本侧 VGA，联合破坏图文对齐。
3. 审稿质疑：MLLM 定量不足、novelty 不足、公平性不清、语义保持、防御和计算开销缺失。
4. 返修动作：MLLM ASR、GLEAM 对齐、防御评估、计算开销、VGA/扰动预算/协同消融、语义保持。
5. 表达策略：从“提出全新攻击组件”调整为“揭示并验证跨模态解耦机制”。

### 必须准备的对比维度

| 维度 | 要讲清楚 |
| --- | --- |
| Syner vs GLEAM | 协议对齐、MLLM 定量、开源模型补充、防御设置 |
| Syner vs SGA | 是否只做图像侧对齐破坏，是否有文本侧视觉引导 |
| image-only vs image-and-text | 文本分支是否真的带来增益 |
| VGA vs BERT-Attack | 词重要性是否引入视觉相关性 |
| feature loss vs alignment loss | 两个损失是否互补 |
| clean vs defense | 简单预处理是否显著降低 ASR |

### 可能被追问的风险边界

| 追问 | 应答方向 |
| --- | --- |
| 这是不是已有方法组合？ | 承认组件继承，强调跨模态解耦机制、双流互补和系统验证 |
| 同时改图像和文本是否现实？ | 讨论 threat model，补 image-only 和 text-fixed 设置作为更现实边界 |
| 文本替换是否改变语义？ | 讲相似度过滤、词性约束、实体关系保护和人工抽检 |
| 商业 API 评估是否稳定？ | 固定 prompt、temperature、样本量、重试策略，报告协议 |
| ASR 是否足够说明攻击成功？ | 结合语义不一致、caption drop、CLIP-proxy、人工/Judge 验证 |

## 训练工程自查

### 必须能讲清的链路

- 数据如何从原始采集变成训练 JSON。
- 训练脚本和推理脚本分别在哪里跑。
- checkpoint 和 prediction 如何对应。
- metrics.jsonl 和 metrics_global.jsonl 分别表示什么。
- bad case HTML 如何用于人工复查。
- 回流数据如何替换旧数据。
- 实验 version 如何管理。

### 必须准备的排查例子

| 场景 | 最好准备的项目例子 |
| --- | --- |
| OOM | 视频帧数、max_pixels、batch size、activation 或保存 tensor 导致显存增长 |
| 吞吐低 | 图片下载 30s vs 模型推理 3s |
| 指标异常 | GT 错误、parser 错误、task_type 标准冲突 |
| 训练慢 | 数据处理 10000 条需要 8-10 小时，需要分片和缓存 |
| 线上离线不一致 | 抽帧、字段映射、模型版本、后处理不一致 |

## 面试中的反问

用人领导通常喜欢候选人有问题意识。可以准备以下反问：

1. 团队当前模型训练链路里，数据质量和模型结构哪个是主要瓶颈？
2. 训练任务的评测更看重离线 benchmark，还是线上业务指标？
3. 团队是否有固定的 bad case 回流和数据版本管理机制？
4. 大模型训练中，团队更关注预训练、后训练、评测，还是推理部署？
5. 对模型训练工程师，团队更期望偏算法研究、训练系统，还是数据闭环？

## 最后自检

面试前如果不能回答下面这些问题，需要回去补材料：

- 我能否用 30 秒讲清关键帧识别项目？
- 我能否用 2 分钟讲清关键帧识别的完整闭环？
- 我能否解释为什么 95.933 这个指标可信？
- 我能否讲一个 GT 错误的 bad case？
- 我能否讲一个模型能力不足的 bad case？
- 我能否讲清数据飞轮和主动学习的关系？
- 我能否讲清 CoT 蒸馏为什么不是简单生成长解释？
- 我能否讲清训练、推理、评测、上线各自的产物？
- 我能否讲清 Syner-Attack 的 novelty 争议和回应策略？
- 我能否回答 OOM、NaN、loss spike、吞吐低、多机 hang 的排查流程？
