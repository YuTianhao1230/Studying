# 项目面试追问总表

## 使用方式

这张表用于面试前快速自查。每个问题都不是为了背标准答案，而是提醒你把项目事实、技术判断和结果证据连起来。

## HR 面常见追问

| 问题 | 考察点 | 回答重点 |
| --- | --- | --- |
| 你最有代表性的项目是什么？ | 项目选择能力和表达优先级 | 优先讲关键帧识别和 Syner-Attack，一个工业闭环，一个研究闭环 |
| 你在项目中具体负责什么？ | 是否有真实 ownership | 讲清你负责问题拆解、数据治理、训练评测、bad case 归因、返修证据或上线联调 |
| 项目中最大的困难是什么？ | 遇到复杂问题时是否能推进 | 关键帧讲标注标准不一致和数据质量；Syner 讲审稿质疑和证据补强 |
| 你如何证明自己做的事情有效？ | 结果意识 | 讲指标变化、分桶结果、bad case 变化、上线回测、论文表格 |
| 如果重做这个项目，你会怎么优化？ | 复盘能力 | 关键帧讲 UI primitive、粗筛精筛、CoT/RL；Syner 讲 MLLM 协议、语义保持、防御评估 |

## 高质量项目回答模板

### 30 秒版本

我做过一个视频关键帧识别模型项目，目标是从移动端操作录屏中自动定位业务指标结束帧，替代部分人工标注。这个项目的难点不是单纯视频理解，而是不同 task_type 的完成态标准不同，且人工 GT 存在噪声。我主要做了标注标准沉淀、bad case 归因、数据飞轮、训练评测和上线联调。最终沉淀 15w+ 样本，三轮返修 27000+ 高质量数据，平均 ACC 从 75.714 提升到 84.876，国际电商 ACC 从 84.093 提升到 95.933，并完成线上部署和回测。

### 2 分钟版本

这个项目可以按闭环讲。第一步是问题定义：关键帧识别要根据 task_type 找到完成态第一次成立的时间点，不同指标有不同完成态和豁免条件。第二步是数据治理：我把原始人工标注数据处理成可训练视频样本，保留 fps、frame_count、duration、task_type、data_version 等字段，并通过 bad case 人工复查发现一部分错误来自 GT 本身。第三步是训练迭代：围绕高优业务线做数据飞轮，模型筛错、人工重标、回流训练，而不是平均补数据。第四步是评测：同时看全量 ACC、业务线 ACC、分指标 ACC 和 bad case 分布。第五步是上线：对齐接口字段，拆解端到端耗时，发现瓶颈主要在图片下载而不是模型推理，并通过压测确定单卡并发和 QPM。这个项目让我形成了一个判断：模型训练效果不是只靠换模型，数据标准、评测口径和工程链路同样决定上限。

### 研究项目版本

Syner-Attack 是我做的多模态对抗攻击研究项目，目标是提升对抗样本在 VLP 和 MLLM 间的黑盒迁移性。原方法通过图像侧 feature/alignment loss 和文本侧 visual-guided word replacement 同时破坏视觉表征和图文对齐。返修阶段我重点围绕审稿人质疑补证据：把商业 MLLM 的定性案例升级为定量 ASR，按 GLEAM 协议对齐 baseline，补充 image-only vs image-and-text、VGA、扰动预算、防御和计算开销消融，并重新定义 cross-modal decoupling。这个项目体现的是从 reviewer concern 到实验设计再到论文叙述的研究闭环。
