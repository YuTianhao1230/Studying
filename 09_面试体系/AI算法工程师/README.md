## 面试官综合考察维度

### 基础理论

- 是否理解数学、概率、优化的基本概念。
- 是否能解释模型为什么这样设计，而不是只背结论。
- 是否能把 loss、指标、优化目标和业务目标联系起来。

### 模型能力

- 是否理解传统机器学习和深度学习模型的适用边界。
- 是否掌握 Transformer、大语言模型、多模态模型的核心机制。
- 是否理解训练、微调、对齐、推理之间的关系。

### 数据能力

- 是否重视数据质量、数据版本和数据隔离。
- 是否能识别标签噪声、数据泄漏、分布漂移。
- 是否能构建可靠的训练集、验证集、测试集和回归集。

### 工程能力

- 是否能写稳定、可复现、可维护的训练与评测代码。
- 是否理解并发、断点续跑、日志、监控、错误恢复。
- 是否能把模型接入线上服务并分析性能瓶颈。
- 是否能结合真实项目讲清楚数据构建、训练、推理、评测、上线和回流闭环。

### 实验判断

- 是否能设计控制变量实验。
- 是否能做 bad case 分析和错误归因。
- 是否能判断指标提升是否可信、是否值得上线。
- 是否能根据 loss、eval 指标、显存、吞吐和 bad case 现象调整训练超参数。

### 项目闭环

- 是否能把 Syner-Attack 这类研究项目讲成“问题定义 -> 方法设计 -> baseline 对齐 -> 消融/防御/计算开销 -> 论文证据”的闭环。
- 是否能把关键帧识别这类业务项目讲成“标注标准 -> 数据 schema -> 训练工程 -> 分桶评测 -> bad case 归因 -> 数据飞轮 -> 上线压测”的闭环。
- 是否能在追问中区分模型能力问题、数据质量问题、评测口径问题和线上链路问题。

### 产品与安全

- 是否理解模型效果、成本、延迟、安全之间的 tradeoff。
- 是否能识别 prompt injection、隐私泄露、越权工具调用等风险。
- 是否能把算法目标转化为真实用户价值。

## 高质量回答的一般结构

1. 先定义问题和目标。
2. 再说明关键机制或原理。
3. 然后结合场景说明适用条件和限制。
4. 最后给出排查、优化或落地方案。

示例：

```text
这个问题本质是在考察 X。
核心机制是 Y。
在实际系统中，需要注意 A、B、C。
如果出现异常，我会先验证 P，再检查 Q，最后通过 R 做闭环。
```
