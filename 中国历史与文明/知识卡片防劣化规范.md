# 中国史知识卡片防劣化规范

## 1. 文档定位

本文件是 `/mlx_devbox/users/yutianhao/Studying/中国历史与文明/` 下历史知识卡片生成、补充、改写、拆分、合并、迁移和校对时的统一质量规范。处理本目录内容前，应先阅读本文件，再检查目标目录的 `README.md`、目标卡片和相关索引。

本目录用于中国历史与文明兴趣阅读，不设置考题、自测、笔面试章节或背诵模板。正文应完整、准确、自包含，并明确区分考古证据、传世文献、后世解释、传说和文学加工。

涉及地图、时间线、人物关系图、图片、动态图、视频或在线交互资源时，还必须完整阅读并遵循根目录的[历史知识库可视化与外部资源规范](<../历史知识库可视化与外部资源规范.md>)。

## 2. 核心原则

1. 一个对象保留一个权威正文，其他位置通过相对链接引用。
2. 先讲清人物、事件、故事或文物本身，再补充影响和关联阅读。
3. 不编造年代、人物关系、引文、史料结论、文物信息或图片来源。
4. 对年代不明、记载冲突、真伪有争议的内容明确标注证据层级和不确定性。
5. 不以现代价值判断代替历史叙述，不把后世制度和概念直接套用于更早时期。
6. README 只承担目录简介和直属内容索引，不存放历史正文。

## 3. 一票否决项

出现以下任一问题，卡片不得视为完成：

- 把神话、传说、小说情节或后世附会写成已证实史实。
- 编造精确年份、亲属关系、师承关系、私人交往、原始引文或考古结论。
- 把不同人物、同名人物、不同事件或不同器物混为一体。
- 只列标签、结论或评价，没有交代时间、地点、人物、起因、经过和结果。
- 用人物故事代替人物生平，或用成语典故代替完整历史事件。
- 将“收藏于某馆”写成“当前正在展出”，但没有展览状态证据。
- 图片、地图、关系图与正文冲突，或没有说明示意性质和来源。
- 新增卡片后未更新最近一级 README 或对应查询索引。
- 移动、合并、重命名或删除文件后留下断链、旧路径或孤立卡片。
- 覆盖、回滚或清理来源不明的未提交改动。
- 留下空章节、占位符、聊天口吻、审计过程或未完成标记。

## 4. 目录与唯一归属

14 个时期目录统一放在 `历史时期/` 下，与 `城市与古都/`、`建筑与遗址/`、`自然地理与历史区域/`、`科技与发明/`、`文化与社会生活/`、`博物馆/`、`文物专题/`、`跨时代专题/` 和 `索引/` 并列。跨时代地图归入对应跨时代专题，具体事件地图归入相应时期，不单独建立地图知识域。

每个时代按以下职责组织：

| 类型 | 核心职责 |
| --- | --- |
| 时代概览 | 交代时间范围、政权并立、主线阶段和阅读入口 |
| 重要人物 | 一人一卡介绍身份、生平、重要活动、结局与史料记载 |
| 历史事件 | 完整叙述战争、联盟、改革、制度变化、继承变化和文化活动 |
| 成语与典故 | 讲清词义、背景、故事经过、结局、用法和出处 |
| 文物 | 说明器物形制、年代、出土或传承信息、历史意义和收藏机构 |

跨时代人物只保留一篇权威人物卡；同一故事产生多个成语时共用一篇正文；不同寓言或不同事件分别保存。混合卡必须先迁移独有内容，再删除旧卡并更新全部引用。

## 5. 卡片内容要求

### 5.1 重要人物

历史人物卡应包含：

1. `人物简介`：姓名、身份、时代、生卒年或活动时期、常见称谓。
2. `生平时间线`：列出可核实的重要年份、时期和事件；不确定时使用“约”“传统记载”或朝代范围。
3. `生平与重要事件`：按时间顺序写明出身、主要活动、关键转折和结局。
4. `历史记载`：列出相关史书、篇目、文集或可靠研究及其记载重点。
5. `关联阅读`：链接相关事件、典故、人物和文物，不重复维护正文。

神话、传说与文学人物改用“身份与来源”“故事或作品中的经历”“文本记载”，不得伪造生卒年、官职或历史事件。人物卡不设置“怎样理解”“现代启示”“怎样避免单一归罪”等抽象章节来代替生平。

### 5.2 成语与典故

故事型卡片通常采用“故事背景—故事经过—结局与后续—成语含义与用法—出处与记载”。名句、思想术语和没有完整情节的文本典故，可采用“典故背景与原文—含义与用法—出处与记载”。

必须先交代人物、时代和起因，再按时间顺序讲述发展、转折和结局。不得只写故事摘要，也不设置“放回历史主线”“怎样连回历史主线”“易混点”“史实边界”等模板章节。确需说明传说、文学加工或不同记载时，在“出处与记载”中具体说明。

### 5.3 历史事件

历史事件卡至少说明：

- 时间、地点、参与方和时代背景。
- 直接起因、深层条件和各方目标。
- 关键阶段、转折点与因果链。
- 直接结果、后续影响和历史边界。
- 相关史料及存在争议的解释。

事件正文聚焦独立历史进程，相关人物生平和成语故事通过链接引用。战争、联盟、制度变化、继承变化和重大社会文化活动优先于平铺式事项罗列。

### 5.4 文物与博物馆

文物卡应区分名称、别称、器类、年代、材质、尺寸、出土或传承信息、收藏机构、形制特征和历史意义。不能从纹饰或用途推导没有证据支持的具体事件。

博物馆索引负责导览和馆藏入口，不重复保存时代正文。必须区分馆藏、借展、复制品、模型和当前展出状态；古籍、拓本与画像应区分制作或版本年代和内容所涉时代。

### 5.5 跨时代专题与地理路线

跨时代专题围绕稳定问题组织，例如制度、财政、选官、军事、人口迁徙、边疆治理、法律和社会生活。专题卡应比较不同时期的延续、变化和条件，不能把各时代结论简单拼接。

地图和路线图必须标明示意性质、时间截面、方向、关键节点和不确定边界。现代行政区只能辅助定位，不能代替历史地理名称和当时辖域。

### 5.6 城市与古都

城市卡统一采用“位置与城市身份—图片与图注—城市发展与历史联系—主要空间与辨析—参考资料—关联阅读”结构。

- 区分现代城市、古代城址和历代都城，不把同名城市视为位置与范围从未变化。
- 说明城市成为都城、港口或区域中心的交通、政治与经济条件。
- 不写成旅游攻略，不以“几朝古都”等宣传口径代替具体阶段。
- 现存城墙、街区或建筑不能直接代表更早都城全貌。

### 5.7 建筑与遗址

建筑与遗址卡统一采用“位置与遗址身份—图片与图注—营建演变与历史联系—遗址范围与辨析—参考资料—关联阅读”结构。

- 区分始建、扩建、重建、修缮和现代保护状态。
- 说明建筑群、遗址范围与单体照片之间的关系。
- 考古发现、文献记载、复原展示与传说分别陈述。
- 不写成景点介绍，不以现存材料、色彩或缺损状态冒充始建原貌。

### 5.8 自然地理与历史区域

自然地理与历史区域卡统一采用“地理位置与区域身份—图片与图注—形成机制与历史联系—空间范围与辨析—参考资料—关联阅读”结构。

- 自然地理范围、历史地理概念和现代行政区分别说明。
- 解释水系、地形、气候、绿洲或通道的作用，但不采用地理决定论。
- 河道、湖泊、海岸、绿洲与路线可能随时代变化，应标出时间边界。
- 区域名称在不同时期口径不同时，列出代表性差异，不给出虚假固定边界。

### 5.9 科技与发明

科技卡统一采用“技术对象—形成与演变—工艺或运作机制—历史作用与边界—参考资料—关联阅读”的基本结构，并按对象调整标题。

- 区分首次文字记载、早期实物、工艺成熟、广泛应用和社会影响，不压缩成单一“发明时刻”。
- 不把长期积累归功于一位人物；人物贡献应与前代工艺、组织和后世传播共同说明。
- 解释材料、流程、维护、成本和适用条件，不只列“领先世界”或发明名称。
- 现代科学评价与历史知识体系分别陈述，医学、材料和工程效果不得由传统声誉直接推出。

### 5.10 文化与社会生活

文化生活卡围绕节日、饮食、服饰、住宅、娱乐和公共空间组织，正文至少说明对象身份、历史形成、具体实践、地区或阶层差异和认识边界。

- 区分国家礼制、地方习俗、家庭实践、文学叙事与现代节假日制度。
- 不把今天的全国统一形式倒推到所有朝代，也不为复杂民俗强行寻找唯一人物或事件起源。
- 宫廷、士人和富裕家庭材料不能代替普通社会的全部生活。
- 现代复兴、旅游展示和文化遗产认定属于新的历史阶段，应与古代实践区分。

### 5.11 索引目录

综合查询、人物、事件、典故、文物和主题阅读索引统一放在 `索引/`。主题索引只组合权威正文，不保存第二份知识内容。“奇观”等名称是阅读视角，不是官方排名或价值判断。

- 每个入口链接最具体的权威卡片；没有正文的对象不得只以名称占位。
- 同一对象可进入多个主题索引，但正文保持唯一。
- 游戏、影视或大众文化作品可用于内部查缺，不在历史卡片、目录名称和索引正文中体现其机制或分类。
- 新增主题索引前应至少有五个可链接的代表性对象，避免单条目的空分类。

## 6. 人物关系图

每个时代的“重要人物”目录必须维护 `人物关系图.md`，并提供本地 PNG 预览和可缩放 SVG。

- 图谱覆盖该时代全部人物卡。
- 按家族、君臣、战争阵营、学术文化或文学关系分组；人物较多时拆成多张主题图。
- 关系边必须表达明确类型，不能由节点邻近暗示亲属、师承或私人交往。
- 同一人物可在多个分图出现；跨时代人物可作为衔接节点。
- 省略世代、政权更替、文学改编或史料争议时，必须在图例或说明中明确。
- PNG、SVG、说明卡和人物索引中的姓名、分组和关系保持一致。

## 7. 事实与来源

证据优先级通常为：考古报告与出土材料、正史和原典、可靠整理本与学术研究、博物馆或文博机构资料、通识性工具书。百度百科和普通网页只用于建立信息框架或发现线索，重要年代、身份、事件和文物信息仍需与更接近原始事实的材料核对。

引用时应做到：

- 直接引文核对原文、篇名和必要上下文。
- 传世文献记载与考古证据不一致时分别陈述。
- 历史记载、后世评价和作者分析明确区分。
- 人物画像与历史绘画注明作品名称、作者或时代及来源。
- 快速变化的展览信息注明核验日期。

## 8. 图片与资产

- 时代图片放在所属时代的 `assets/` 中，文物实物照片放在 `assets/文物/`。
- 城市、建筑遗址、自然地理、科技和文化生活图片分别放在对应模块的 `assets/` 中。
- 模块根部 `assets/` 只保存全史共用图片。
- 图片必须与相邻正文直接相关，使用有效相对路径，并提供必要的图注和来源。
- 不把现代复原图、影视剧照、想象画或 AI 生成图当作历史实物证据。
- 图片裁切、压缩或格式转换后仍应保留可识别主体和必要说明。

## 9. 索引与链接

- 新卡片加入最近一级 README；人物、事件、典故或文物同时更新 `索引/` 中的对应专项索引；所有新对象类型更新 `索引/查询索引.md`，必要时加入一个或多个主题索引。
- README 只列直属子目录和同级卡片，并用一句话说明内容。
- 整张卡片入口直接链接文件，不附加与标题同义的章节锚点。
- 人物索引、事件索引、成语与典故索引、文物索引采用稳定字段，别名合并到同一对象；人物主题索引只做精选阅读路线，不代替人物全量索引。
- 移动、重命名、合并或删除后，搜索旧路径并更新全部引用。
- 不删除独有史料、时间线、故事细节、边界说明或图片来源；合并前先完整迁移。

## 10. 修改与验证流程

修改前：

1. 运行 `git status --short`，识别已有改动。
2. 阅读目标卡片、同目录 README、时代入口和对应查询索引。
3. 搜索同名、别名、近义主题和相关事件，确认权威归属。
4. 判断任务属于新增、补充、纠错、合并、拆分、迁移还是审计。
5. 批量修改前统计候选数量并抽样核对语义。

交付前至少检查：

- 事实、年代、人物关系、引文、文物信息和图片来源可核验。
- 传说、文学、考古和史书记载已经区分。
- 人物卡、事件卡、典故卡和文物卡职责没有混淆。
- 人物关系图覆盖完整，PNG、SVG 和说明一致。
- 最近一级 README 和全局查询索引已经更新。
- 本地相对链接、图片路径、标题层级和代码围栏有效。
- 旧路径没有残留，没有新增孤立文件。
- `git diff --check` 和本次修改文件的 scoped 检查通过。
- 最终 diff 不覆盖来源不明的用户改动。

除非用户明确要求，不创建提交，不推送远端。
