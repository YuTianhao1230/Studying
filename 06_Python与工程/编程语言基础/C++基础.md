# C++ 基础

## 知识点解析

### 概述

C++ 兼顾值语义、泛型、面向对象和底层资源控制。它允许精确管理对象生命周期和内存布局，也把更多正确性责任交给程序员。面试回答应区分语言标准保证、常见实现方式和平台相关行为，避免把“通常如此”说成“必须如此”。

### 编译、链接与定义规则

C++ 源文件连同其包含的头文件构成翻译单元，分别经过预处理、编译和汇编生成目标文件，再由链接器解析符号并生成程序。头文件通常放声明、类型定义、模板定义和满足要求的内联定义；普通非内联函数或具有外部链接的变量若在多个翻译单元重复定义，可能违反单一定义规则并产生链接错误或未定义行为。

模板通常需要在实例化点可见完整定义，因此常写在头文件中。`inline` 的核心语言作用是允许满足规则的相同定义出现在多个翻译单元，不保证编译器一定进行调用展开；是否内联优化由编译器决定。

### 对象、存储期与生命周期

C++ 对象有自动、静态、线程和动态等存储期。局部自动对象通常由作用域管理并按构造的逆序析构；动态对象需要由所有权对象负责释放。工程中常把自动存储称为“栈上”，但 C++ 标准规定的是存储期和生命周期，并不强制具体内存区域。

对象生命周期开始前或结束后访问其存储，通常会产生未定义行为。常见风险包括返回局部变量的指针或引用、容器扩容后继续使用失效迭代器、释放后访问、重复释放和数组越界。未定义行为不是稳定的异常结果，编译器可以假设它不会发生并据此优化。

### 指针、引用与 const

指针是保存地址的对象，可以为空、重新指向其他对象，并在合法数组范围内进行受限算术运算。引用必须在定义时绑定到一个有效对象，此后不能改绑；对引用赋值是修改被引用对象。语言层面没有“空引用”这一合法状态，但引用仍可能因原对象生命周期结束而悬空。

| 对比项 | 指针 | 引用 |
| --- | --- | --- |
| 可为空 | 可以，用 `nullptr` 表示 | 语言语义上不应为空 |
| 可改绑 | 可以 | 不可以 |
| 使用方式 | 通常需要解引用 | 像对象别名一样使用 |
| 地址运算 | 数组边界内支持 | 不支持 |
| 悬空风险 | 有 | 同样有 |

`const T*` 表示不能通过该指针修改 `T`，`T* const` 表示指针本身不能改绑。`const T&` 可以绑定右值，并在特定直接绑定场景延长临时对象生命周期，但这种延长不会无条件跨越返回值、成员引用或间接绑定传播。接口中应优先用引用表达“必有对象”，用指针表达“可缺省”或需要改绑；两者默认都不表达所有权。

### RAII 与智能指针

RAII 把资源获取放入对象构造，把释放放入析构，使正常返回和异常展开都能按作用域释放资源。资源不仅包括内存，还包括文件、锁、套接字和事务句柄。标准容器、字符串和锁守卫都是 RAII 的典型应用。

- `std::unique_ptr<T>` 表示独占所有权，不可复制但可移动，默认应优先使用。
- `std::shared_ptr<T>` 通过引用计数共享所有权，最后一个强引用销毁时释放对象，但有计数和同步开销。
- `std::weak_ptr<T>` 不增加强引用计数，用于观察共享对象和打破 `shared_ptr` 环。
- 裸指针和引用适合表达非拥有访问，但调用者必须保证被引用对象在访问期间仍然存活。

`shared_ptr` 只能解决由同一控制块管理的共享生命周期，不能自动识别任意裸指针所有权。对同一裸指针分别构造多个 `shared_ptr` 会产生多个控制块并可能重复释放；通常应使用 `std::make_shared`，需要从对象内部获得共享引用时使用正确初始化的 `enable_shared_from_this`。

### 拷贝、移动与资源管理

拷贝构造和拷贝赋值创建独立的值语义副本；移动构造和移动赋值可以从即将销毁的对象转移资源。移动后的标准库对象仍有效但状态通常未指定，只能执行其接口允许的操作，不能假定为空。

如果类直接管理资源，通常需要同时考虑析构、拷贝构造、拷贝赋值、移动构造和移动赋值，即 Rule of Five。更推荐 Rule of Zero：把资源交给标准容器或智能指针，使编译器生成的特殊成员函数即可正确工作。用户声明析构函数等特殊成员函数会影响隐式移动操作的生成，不能仅凭出现 `std::move` 就认定发生了移动；`std::move` 本质上是允许选择移动重载的类型转换。

### 继承、多态与虚析构

通过基类指针或引用调用虚函数时，会根据对象的动态类型分派到最终覆写函数。常见实现使用虚函数表和对象中的虚表指针，但 C++ 标准只规定动态分派语义，不强制具体布局。`override` 能让编译器检查函数确实覆写基类虚函数，应优先使用。

如果对象可能通过基类指针被 `delete`，基类析构函数必须是虚函数；否则行为未定义，派生部分可能无法正确析构。若类型不用于运行时多态或禁止通过基类删除，则不必机械增加虚析构。常见接口设计是“公开虚析构”允许多态删除，或者“受保护非虚析构”禁止外部通过基类指针删除。

构造和析构期间的虚调用只分派到当前正在构造或析构的类层次，不会调用尚未构造或已经析构的派生部分。虚函数的默认实参按调用点的静态类型绑定，也不参与动态分派。按值传递派生对象给基类参数会发生对象切片，应使用基类引用或指针保留多态。

### STL 容器与迭代器边界

容器选择应根据访问模式、插入删除位置、稳定性和内存局部性：

- `std::vector` 连续存储，随机访问 O(1)，尾部追加均摊 O(1)，通常是默认序列容器。
- `std::deque` 支持两端 O(1) 插入删除，但不保证整体连续存储。
- `std::list` 节点分散，已知位置插入删除 O(1)，但查找慢且缓存局部性差。
- `std::map` 通常以平衡树实现，查找 O(log n) 且有序。
- `std::unordered_map` 平均查找 O(1)，最坏可退化到 O(n)，不保证顺序。

容器修改可能使指针、引用和迭代器失效。以 `vector` 为例，发生重新分配时所有相关指针、引用和迭代器都会失效；未重新分配时，插入点及其后的迭代器通常也会失效。具体规则必须按容器和操作查证，不能套用统一结论。

### 异常与并发边界

异常展开会析构已经完成构造的自动对象，因此 RAII 是异常安全的基础。析构函数通常不应让异常逃逸，尤其在另一个异常展开期间，否则可能调用 `std::terminate`。异常安全常分为不抛异常保证、强保证和基本保证，应根据操作成本和状态一致性选择。

多个线程无同步地并发访问同一内存位置，且至少一个访问是写操作时，通常构成数据竞争并导致未定义行为。互斥锁、原子类型和 happens-before 关系用于建立正确同步；`volatile` 在标准 C++ 中不提供线程同步或原子性，不能替代 `std::atomic`。

### 核心边界与易错点

- 引用不能改绑，但可以悬空；“引用一定安全”是错误结论。
- 指针算术只在同一数组对象及尾后位置的规则范围内有定义。
- `delete` 通过非虚析构的基类指针销毁派生对象是未定义行为。
- 虚表是常见实现，不是标准强制的数据结构。
- `std::move` 不执行移动，只把表达式转换为可供移动重载匹配的值类别。
- `shared_ptr` 的引用计数不能自动解决循环引用，也不能取代所有权设计。
- STL 复杂度通常是约定边界，不代表常数开销或最坏情况都相同。
- C++ 的 `volatile` 主要面向特殊内存访问，不是线程同步工具。

## 面试应对

### 指针和引用有什么区别，如何选择？

回答思路：从空值、改绑、语法、所有权和生命周期回答，强调二者都可能悬空。

回答模板：

指针是保存地址的对象，可以为 nullptr、可以改绑，也支持合法范围内的数组地址运算；引用是对象的别名，定义时必须绑定，之后不能改绑。接口中我通常用引用表示参数必须存在，用指针表示参数可选或需要改绑，但裸指针和引用默认都不表示所有权。两者都依赖目标对象的生命周期，原对象销毁后都会悬空，所以引用并不天然比指针更安全。

### 为什么多态基类通常需要虚析构函数？

回答思路：先给适用前提，再说明删除链路和不需要虚析构的边界。

回答模板：

当派生对象可能通过基类指针执行 delete 时，基类析构函数必须是虚函数。这样析构调用会从派生类开始逐层执行，正确释放派生类资源；如果基类析构非虚，通过基类指针删除派生对象属于未定义行为。并不是所有类都要加虚析构：不参与运行时多态的类不需要；若要禁止通过基类删除，可以把非虚析构设为 protected。常见设计原则是公开虚析构，或者受保护非虚析构。

### RAII 和智能指针分别解决什么问题？

回答思路：先说明 RAII 是通用生命周期模式，再区分 unique、shared、weak 的所有权语义。

回答模板：

RAII 把资源的获取和释放绑定到对象生命周期，使作用域结束或异常展开时都能自动清理，适用于内存、文件、锁和套接字等资源。unique_ptr 表示独占所有权，应作为默认选择；shared_ptr 用引用计数表达确实存在的共享所有权，但有额外开销且循环引用无法释放；weak_ptr 用于非拥有观察和打破环。裸指针或引用可以做临时借用，但必须由接口约定保证被访问对象仍然存活。

### 拷贝、移动以及 Rule of Zero 和 Rule of Five 如何理解？

回答思路：从资源所有权出发说明特殊成员函数的职责，再给出优先级。

回答模板：

拷贝要产生逻辑独立的值，移动则允许从即将销毁的对象转移资源；移动后的对象仍有效，但状态通常未指定。类若直接管理资源，就要成组考虑析构、拷贝构造、拷贝赋值、移动构造和移动赋值，也就是 Rule of Five。更推荐 Rule of Zero，把资源交给 vector、string 或智能指针，让编译器生成特殊成员函数。还要注意 std::move 只是类型转换，最终是否移动取决于是否存在可匹配的移动操作。

### C++ 虚函数如何实现，常见边界是什么？

回答思路：先区分标准语义和常见实现，再补构造析构、默认参数和对象切片三个边界。

回答模板：

C++ 标准规定通过基类指针或引用调用虚函数时按对象动态类型分派，主流编译器通常用虚函数表和对象中的虚表指针实现，但具体布局不是标准保证。构造和析构期间，虚调用只会分派到当前构造或析构层次；虚函数的默认实参按调用点静态类型绑定；把派生对象按值传给基类参数还会发生对象切片。工程中我会使用 override 让编译器检查覆写，并通过基类引用或智能指针保留多态。
