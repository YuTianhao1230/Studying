# 编程与算法工程能力

## 知识点解析

### 概述

编程与算法工程能力是把问题建模、算法设计和可靠实现连接起来的综合能力。本卡用于能力盘点和面试导航；并发、大文件、日志、重试、测试与可复现的实现方法统一见 [Python 工程实践](<Python工程实践.md>)。

### 能力矩阵

| 维度 | 核心能力 | 可验证产出 |
| --- | --- | --- |
| Python 语言基础 | 理解容器、作用域、迭代器、生成器、异常、类型注解和文件 IO | 能解释语义边界并写出可读实现 |
| 数据结构与算法 | 掌握数组、链表、栈、队列、[哈希表](<../10_计算机基础知识/数据结构与算法/哈希表.md>)、堆、树、图及常见算法范式 | 能证明正确性并分析时间、空间复杂度 |
| 算法实现 | 把约束转化为接口、不变量、边界条件和测试样例 | 实现结果与基准或朴素解一致 |
| 性能优化 | 使用 profiling、批处理、缓存、向量化和内存分析定位瓶颈 | 优化前后有耗时、吞吐和内存对比 |
| 工程交付 | 让程序可测试、可观测、可恢复、可复现 | 具体方法见 [Python 工程实践](<Python工程实践.md>) |

### 算法工程维度

1. **问题建模**：明确输入输出、数据规模、合法范围和目标指标，避免在错误的问题定义上优化。
2. **正确性**：给出不变量、边界条件和反例；复杂实现可用朴素算法或小规模穷举做差分验证。
3. **复杂度**：同时分析时间、空间、均摊成本和最坏情况，并把数据规模代入判断方案是否可运行。
4. **数据与数值边界**：考虑空输入、重复值、极端值、溢出、浮点误差和异常数据。
5. **性能证据**：先测量再优化，区分算法复杂度、Python 解释器开销、IO、内存和底层算子瓶颈。
6. **工程可靠性**：并发选择、流式处理、日志、重试、测试和实验复现由 [Python 工程实践](<Python工程实践.md>) 承担。
7. **可维护性**：使用清晰接口、类型约束和最少必要抽象，使算法逻辑可以独立测试和替换。

### 常见追问

- 如何证明实现正确，而不只是通过给定样例？
- 数据规模扩大十倍后，时间和内存会怎样变化？
- 如何用朴素解或不变量验证复杂优化？
- profiling 结果与复杂度分析不一致时如何排查？
- 如何定位 Python 程序内存持续上涨？

## 面试应对

### 如何评价一个人的算法工程能力？

回答思路：覆盖建模、正确性、复杂度、性能证据和工程交付。

回答模板：

我会从五个方面评价算法工程能力：先看能否把需求转成明确的输入、输出和约束；再看是否能说明算法正确性并覆盖边界；第三看能否结合数据规模分析时间和空间复杂度；第四看是否通过 profiling 和基准数据定位、验证优化；最后看实现是否有清晰接口、测试和可复现产物。只写出能跑的代码不够，还要能证明它正确、可扩展并且可维护。

### 如何把算法题解法变成可靠实现？

回答思路：从契约、不变量、边界、差分验证和性能基线回答。

回答模板：

我会先固定函数接口和输入约束，再写出算法依赖的不变量与复杂度目标。实现时显式处理空输入、重复值和极端规模等边界，并用样例、随机小数据和朴素解做差分测试。之后建立耗时和内存基线，通过 profiling 确认瓶颈，再决定是否更换数据结构、减少复杂度或做批处理和向量化，避免凭感觉优化。

### 如何定位 Python 内存持续上涨？

回答思路：先判断真实泄漏还是缓存，再定位对象增长来源。

回答模板：

我会先用进程指标确认 RSS 增长趋势，并区分一次性峰值、框架缓存和持续泄漏。然后按批次记录对象数量和关键容器长度，使用 tracemalloc、memory profiler 等工具比较内存快照，定位增长最多的调用位置。常见原因包括全局列表累积、闭包或回调持有引用、缓存无上限、未关闭文件以及保留计算图。修复后用长时间和大数据量回归验证内存是否稳定。
