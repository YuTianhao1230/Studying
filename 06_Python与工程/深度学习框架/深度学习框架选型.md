# 深度学习框架选型

## 知识点解析

### 概述

本文整理 PyTorch、TensorFlow/Keras、JAX，以及 Hugging Face Transformers、[DeepSpeed](<../../03_训练优化与对齐/训练框架与并行/DeepSpeed.md#deepspeed>)、Megatron-LM、[FSDP](<../../03_训练优化与对齐/训练框架与并行/FSDP.md#fsdp>) 等训练生态在张量计算、自动求导、研究迭代、编译优化、分布式训练和部署方面的特点与选型依据。

### 选型原则

如果目标是研究迭代、快速调试、自定义训练逻辑，通常优先 PyTorch。PyTorch 的动态图机制直观，和 Python 控制流结合紧密，适合写自定义 loss、复杂 forward、强化学习、[Agent](<../../08_Agent/基础概念/Agent.md#agent>) 训练和多模态训练。现在大模型开源生态也大量围绕 PyTorch 展开，例如 Transformers、Accelerate、[PEFT](<../../03_训练优化与对齐/后训练与对齐/PEFT 参数高效微调.md#peft-参数高效微调>)、DeepSpeed、FSDP、[vLLM](<../../05_推理部署与系统/推理工程/vLLM.md#vllm>)。

如果目标是传统工业部署、移动端、端侧、[Serving](<../../05_推理部署与系统/推理工程/Serving.md#serving>) 体系或已有 TensorFlow 生产链路，TensorFlow/Keras 仍然有价值。Keras 上手快，SavedModel、TensorFlow Serving、TFLite、TFX 等工具在部分企业生产系统里较成熟。但在大模型研究和开源训练生态里，TensorFlow 的主流程度已经明显低于 PyTorch。

如果目标是高性能数值计算、TPU、编译优化、函数式变换和大规模研究系统，JAX 更常见。JAX 的 `jit`、`vmap`、`pmap/pjit` 和 XLA 编译能力很强，Google/DeepMind 生态使用较多，但工程门槛和生态通用性相对 PyTorch 更高。

### 常见框架对比

| 框架 | 主要优势 | 主要限制 | 更适合的场景 |
| --- | --- | --- | --- |
| PyTorch | 动态图直观、调试方便、开源大模型生态强 | 生产部署需要额外工程组件 | 研究实验、大模型训练、多模态、RL、快速迭代 |
| TensorFlow/Keras | 部署生态成熟、Keras 简洁、端侧工具完整 | 大模型开源训练生态相对弱 | 传统工业链路、移动端、已有 TF 系统 |
| JAX | 函数式、XLA 编译强、TPU 生态好 | 学习曲线高，工程生态相对集中 | 高性能研究、TPU、大规模数值计算 |
| Hugging Face | 模型、数据、训练组件生态完整 | 抽象较厚，深度定制时要理解底层 | LLM/VLM 微调、推理、开源模型复现 |
| DeepSpeed/FSDP/Megatron | 解决大模型显存和并行训练 | 配置复杂，排障成本高 | 大规模分布式训练 |

### 工程使用方式

实际项目里通常不是只用一个框架，而是组合使用。

模型训练常见组合是：PyTorch 写模型和训练逻辑，Transformers 加载模型和 tokenizer，Datasets 处理数据，PEFT 做 LoRA/QLoRA，Accelerate 或 DeepSpeed/FSDP 做分布式训练，Weights & Biases / TensorBoard 做实验追踪。

模型推理常见组合是：训练产物保存为 Hugging Face 格式或 checkpoint，离线评测用 PyTorch/Transformers，线上服务可能交给 vLLM、TensorRT-LLM、TGI 或自研 Serving。

### 常见误区

框架不是越新越好。选型要看团队已有生态、训练规模、部署目标、调试成本和人才熟悉度。比如 JAX 在编译和 TPU 上很强，但如果团队主要用 PyTorch、模型来自 Hugging Face、训练框架是 DeepSpeed，那么强行切 JAX 反而会增加成本。

另一个误区是把“会用框架”等同于“会训练模型”。真正的训练能力还包括数据 pipeline、loss 设计、优化器、混合精度、分布式、checkpoint、日志监控、评测和故障排查。
