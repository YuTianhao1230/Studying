# 数据采集与多模态输入工程

## 知识点解析

### 概述

多模态 Agent 的稳定性首先取决于输入是否可用、可比、可追溯。D2C 场景同时需要 Figma 设计节点、设计截图、代码产物、Lynx 运行截图、结构树、设备参数、日志和评测元数据。数据采集卡片的目标是把外部资源变成版本化、可验证、能被 Workflow 消费的输入包，并保留状态、坐标、单位和证据。

### 一个完整输入包

```text
case/
├── 任务清单
├── 设计节点信息
├── 设计截图
├── 页面代码信息
├── 页面样式信息
├── 生成报告信息
├── 实现截图
├── 页面结构信息
├── 设备信息
├── 采集日志
└── 完整性校验信息
```

`任务清单` 至少记录：`case_id`、页面状态、Figma 设计节点标识、设计版本、实现 commit、设备型号、viewport、采集时间、资源 URI、schema 版本、任务 ID 和权限范围。原始文件只读保存，后处理产物用新文件名和处理版本区分。

### 数据采集的五个 gate

1. **身份 gate**：当前用户或机器人有权读取设计、代码、设备和评测资源。
2. **状态 gate**：页面加载完成，动态数据、弹窗、滚动位置和主题稳定。
3. **一致性 gate**：两侧 viewport、设备像素比、字体、资源和页面状态可比。
4. **完整性 gate**：截图、结构树、日志和元数据齐全，文件可解析且 checksum 正确。
5. **时效 gate**：截图和结构树来自同一采集批次，不能跨批次拼接。

任何 gate 失败都应返回对应错误，并在检测前阻断不可比输入。

### Figma 侧数据

设计侧通常需要：

- 精确的 `设计节点标识`，并关联文件、页面名和版本信息。
- 节点树和节点属性，包括 box、fill、corner、font、text、children 和路径。
- 设计截图，保留原始尺寸和导出格式。
- 设计 viewport、基准宽度和缩放信息。
- D2C 生成的 `tsx`、`css` 和报告，便于关联代码与视觉差异。

制题或评测集构造时，应选择最终态、无占位、多样化的 case，并为每题标注页面类型、粒度、结构、组件和文本标签。难度可以参考有效代码长度、UI 节点数、唯一 UI 类型和最大嵌套深度。

### Lynx 侧数据

实现侧需要：

- 真实设备或容器的页面截图。
- `页面结构信息`，包含节点类型、文本、box、样式和父子关系。
- viewport、设备型号、系统、DPR、字体和页面状态。
- 采集日志、页面加载时间、异常和截图时间。
- 结构树上传后的可访问地址或任务字段。

真实设备采集需要受控的设备连接、页面稳定等待和采集工具。设备不在线、页面未稳定、截图和树时间不一致时，必须在 manifest 中标记失败。

### 离线评测集构造流程

```text
选择最终态 Figma case
  -> 下载设计代码、CSS、报告和设计图
  -> 构建/运行 Lynx 页面
  -> 设备连接与页面状态收敛
  -> 采集截图、页面结构信息和日志
  -> 上传结构树并取得可访问资源标识
  -> 回填评测集字段
  -> 创建评测任务或本地检测任务
```

外部任务系统通常使用短期访问令牌。令牌不得写进 case、文档、脚本或日志；使用前检查有效期，失效后通过受控的刷新或服务身份重新获取。

### 图像输入方式

模型服务可能支持本地路径、对象存储地址或 Base64。应遵循：

- 本地路径只在同一进程或受控工作区内有效。
- URL 是资源引用，不等于图片内容，服务端能否访问要单独验证。
- 需要跨网络传输时才编码 Base64，并限制大小和格式。
- VLM 接口若要求真实图片，必须传两张图片的 Base64；仅传 URL 可能被服务当作普通文本引用。
- 图片顺序、角色和尺寸要写入请求元数据，不能依赖模型猜测。
- 大图先做受控缩放，同时保留原图和缩放参数。

长耗时视觉请求应设置明确的总超时和有界并发，先以低并发压测。超时或报告缺失只做有限的带退避重试，并使用请求幂等键。

### 多模态证据裁剪

整图适合判断页面关系，裁剪图适合判断组件细节。裁剪时必须保留：

- 原始 box 和裁剪 box。
- 是否做了 padding、缩放和插值。
- 图片序号与组件 ID 的映射。
- 裁剪失败原因。
- 与整图的关联 ID。

传输尺寸和 padding 要和组件实际范围分开记录。D2C 匹配复核会区分原始 `crop_box`、`crop_size`、传输尺寸和 padding 区域，减少模型按传输尺寸误判组件大小的风险。

### 结构化协议和单位

建议每个 box 统一为 `[x1, y1, x2, y2]`，明确原点、坐标空间和是否包含边界。长度字段同时记录：

```json
{
  "declared_value": 24,
  "unit": "rpx",
  "computed_px": 12,
  "viewport_width": 375,
  "reference_width": 750,
  "normalized_design_px": 24
}
```

运行时 px 与设计声明 rpx 不能直接比较。对于 750 基准：`computed_px = declared_rpx * viewport_width / 750`。跨设备比较时保留 viewport 和归一化值，否则无法归因。

### 数据清洗与隐私

输入可能包含用户昵称、头像、订单号、路径和内部资源地址。进入模型前要按业务要求脱敏；但脱敏不能破坏文本长度、布局和组件语义。应保存原始资源的访问控制信息，脱敏图和原图分开授权。

清洗阶段要做：

- 文件类型和大小检查。
- 图像是否可解码、尺寸是否合理、颜色空间是否一致。
- JSON schema 校验、字段类型和数组长度检查。
- 节点 box 越界、负尺寸、重复 ID 和父子环检查。
- 图片、结构树和日志的时间与 batch ID 对齐。
- checksum 和处理版本记录。

## 落地步骤

1. 设计 manifest 和统一资源目录。
2. 固定 Figma 设计节点标识、页面状态和设计 viewport。
3. 下载或导出设计侧文件，并记录版本和 checksum。
4. 准备页面运行环境，等待设备、页面和动态数据稳定。
5. 采集截图、结构树、设备信息和日志，绑定同一个 batch ID。
6. 做文件、schema、坐标、单位、权限和敏感信息检查。
7. 需要跨服务时上传结构树并回填资源标识。
8. 构造 VLM 请求，确认两张真实图片、图片顺序和请求契约。
9. 保存原始输入、处理产物和失败证据，再进入检测。

### VLM 响应验收

VLM 响应验收至少同时检查：

```text
HTTP status 是 2xx
  -> 响应 ok 字段为 true
  -> reportValidation 通过
  -> 报告包含 7 项子结果
  -> 分数范围为 0 到 4
  -> 布局 4 项、文本 3 项字段齐全
```

报告缺字段、全空、分数越界或只返回一段自然语言，都应视为契约失败。

## 失败与排障

| 现象 | 原因方向 | 修复方式 |
| --- | --- | --- |
| 设计图和实现图无法比较 | 设计节点标识 错、页面状态不一致、viewport 不同 | 回到状态与业务可比性 gate |
| 结构树上传成功但任务读取不到 | 资源地址权限、字段回填、服务区域或过期 | 用同身份回读并检查 manifest |
| VLM 说图片不可见 | Base64 缺失、格式错误、顺序错或 URL 无法访问 | 本地解码、记录字节大小并验收两张图片 |
| 所有尺寸都异常 | rpx/px、DPR、缩放或 box 坐标空间错误 | 对单个节点手算并比对归一化字段 |
| 裁剪组件大小被误判 | padding 或 transport size 混入 | 使用原始 crop_box 和 crop_size |
| 真机采集偶发空白 | 页面未稳定、设备连接或动画未收敛 | 增加状态等待、截图重试和设备日志 |
| 凭证突然失效 | 短期访问令牌 过期或身份不匹配 | 检查有效期，改用短期刷新或服务身份 |

## 面试应对

### 常考点及考法

- 多模态 Agent 的输入为什么比文本 Agent 难？
- 如何保证两张图和结构树是可比的？
- VLM 图片接口如何验证成功？
- rpx、px、DPR 和 viewport 如何处理？

### 解法/回答思路

从“输入包和 gate”开始回答，强调多模态问题不是只传图片，还要有状态、结构、单位、时间、版本和权限。最后讲失败时如何区分数据问题和模型问题。

### 易错点

- 只校验 HTTP 200，不校验业务响应和报告字段。
- 把 URL 当作已传入图片。
- 忽略图片顺序、裁剪 padding 和坐标空间。
- 认证凭证写入脚本或日志。

### 回答模板

可直接回答：

> 多模态 Agent 先构造可比输入包，再调用模型和工具。D2C 场景我会同时保存设计节点信息、设计截图、实现截图、结构树、设备 viewport、页面状态、采集时间和版本，并通过状态、业务可比性、文件完整性、时间对齐和权限五层 gate。图像接口要检查两张真实图片是否按角色传入，并验证 URL、Base64 或本地路径的可访问性；响应还要校验 HTTP、业务 ok、报告字段和分数范围。坐标和 rpx 必须记录声明值、换算 px、viewport 和归一化值。采集、解码、权限、单位错误都先在数据层拦截，减少把输入问题误判成 VLM 能力问题的风险。
