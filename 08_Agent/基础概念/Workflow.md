# Workflow

## 知识点解析

### 概述

Workflow 是预先设计好的多步骤执行流程，用代码或配置把 LLM、工具和规则串起来，让系统按确定路径完成任务。

### Workflow 和 Agent 的区别

Workflow 更强调“流程预定义”：

```text
步骤 A -> 步骤 B -> 步骤 C -> 输出
```

[Agent](<Agent.md>) 更强调“模型动态决策”：

```text
观察状态 -> 模型决定下一步 -> 执行 -> 再观察 -> 再决策
```

二者不是对立关系。很多生产系统会把 Workflow 和 Agent 混合使用：

- 外层用 Workflow 控制关键流程和安全边界。
- 局部让 Agent 处理开放问题、搜索、生成、调试或归纳。

### Planning 与 ReAct

Planning 是 Agent 在执行前或执行中拆解任务、安排步骤的能力；ReAct 是让推理和行动交替进行的执行模式，即 Reasoning + Acting。

ReAct 的核心循环：

```text
Thought -> Action -> Observation -> Thought -> ...
```

更工程化地说：

```text
分析当前状态
  -> 决定调用哪个工具
  -> 执行工具
  -> 读取工具结果
  -> 更新判断
  -> 继续或结束
```

#### 三种常见 Planning

**Upfront Planning**：先生成完整计划，再执行。适合需求明确、步骤相对稳定或需要用户先审查的任务；风险是计划可能因环境变化快速过期。

**Step-by-step Planning**：每执行一步后，根据结果重新规划。适合调试、代码库探索、网页操作和数据分析；风险是流程容易碎片化，因此必须有终止条件。

**Hierarchical Planning**：先拆成大阶段，再在每个阶段内细化。适合大型工程任务、多 Agent 协作和长周期自动化任务。

#### 好计划的标准

- 目标明确。
- 每一步可验证。
- 有失败处理。
- 有终止条件。
- 能区分探索、修改和验证。
- 不把未知假设写成事实。

复杂任务通常采用混合方式：先制定阶段性计划，每一步执行后根据观察结果修正。

### 常见 Workflow 模式

#### Prompt Chaining

多个 LLM 调用顺序连接，前一步输出作为后一步输入。

适合：

- 文档总结后再改写。
- 需求转 PRD，再转技术方案。
- 代码生成后再生成测试。

#### Routing

先判断任务类型，再路由到不同模型、工具或专家链路。

适合：

- 客服问题分流。
- 代码问题按语言分流。
- 多模态任务按输入类型分流。

#### Parallelization

把任务拆成多个子任务并行执行，再汇总结果。

适合：

- 多文档阅读。
- 多文件代码审查。
- 多候选答案投票。

#### Orchestrator-Workers

一个主控节点拆分任务，多个 worker 执行，最后由主控汇总。

适合：

- 大规模代码修改。
- 多模块调研。
- 复杂数据分析。

#### Evaluator-Optimizer

一个模型生成结果，另一个模型或规则系统评估，未达标则继续修改。

适合：

- 文案优化。
- 代码修复。
- Prompt 迭代。
- 测试用例补全。

### Planning 的常见失败模式

- 只计划不执行。
- 计划太细，工具结果一变就失效。
- 计划没有验收标准。
- 遇到错误后仍按旧计划执行。
- 为简单任务引入复杂规划。
- 没有最大步数、超时或重复动作检测，导致循环失控。

### 为什么 Workflow 很重要

Agent 容易开放、不可控；Workflow 能提供：

- 稳定步骤。
- 可复现执行。
- 明确验收点。
- 成本和权限控制。
- 更好的失败恢复。

### 常见误区

- 以为 Agent 越自主越好。
- 把固定流程交给模型自由规划，导致成本和不确定性上升。
- 没有在关键步骤设置校验和中止条件。
- 所有步骤都用 LLM，而不是把确定性逻辑写成代码。

### 常考点及考法

常考 Workflow 与 Agent 的区别、Prompt Chaining、Routing、Parallelization、Planning、ReAct 和质量回路。

### 解法/回答思路

先判断流程是否稳定，再说明哪些步骤固定、哪些步骤交给 Agent，并补充状态、终止、并行合并和失败恢复。

### 易错点

只强调自主性，不考虑可控性、审计、成本、循环上限和节点级验证。

### 回答模板

回答 Workflow 题目时可按“模式定义 -> 适用边界 -> 节点和状态 -> 失败与评测”的顺序说明。
## 面试应对

### Workflow 和 Agent 的区别是什么？

回答思路：抓住"预定义流程 vs 自主决策"的差异，落到两者如何组合。

回答模板：

Workflow 是预定义的流程编排，节点、顺序和边界通常由工程师提前设计；Agent 是能根据目标、上下文和工具反馈自主决策的执行单元。一个 Workflow 里可以包含多个 Agent 节点。稳定流程我会优先用 Workflow 固化，开放问题再交给 Agent。

### 什么时候应该用固定 Workflow，而不是自主 Agent？

回答思路：给出"流程稳定/规则明确/风险高/需审计"的适用条件，再给 Agent 的适用场景。

回答模板：

当流程稳定、规则明确、风险较高或需要审计复现时，应该优先用固定 Workflow，比如审批、发布、数据处理流水线。自主 Agent 更适合信息不完整、需要动态规划和工具选择的任务。工程上通常是 Workflow 控制边界，Agent 处理局部不确定性。

### 解释 Prompt Chaining、Routing、Parallelization。

回答思路：分别一句话说清串行拆解、按类型分支、并行汇总，点出都是编排模式。

回答模板：

Prompt Chaining 是把复杂任务拆成多个串行 LLM 步骤；Routing 是根据输入类型选择不同处理分支；Parallelization 是把可独立执行的子任务并行跑完再汇总。它们都是 Workflow 编排模式，目的都是降低单次 LLM 调用的不确定性。

### 如何设计一个带质量回路的 Evaluator-Optimizer？

回答思路：拆成 Generator / Evaluator / Optimizer 三角色，强调设终止条件防死循环。

回答模板：

我会把系统拆成 Generator、Evaluator 和 Optimizer。Generator 先生成候选结果，Evaluator 按 rubric 检查质量并指出问题，Optimizer 根据反馈修改。循环必须设置最大轮数、质量阈值和失败退出条件，避免无限优化。

### Workflow 如何降低 Agent 系统的不确定性？

回答思路：核心是"固定稳定步骤、只把开放判断交给 Agent"，从而可测可控可回滚。

回答模板：

Workflow 把稳定步骤固定下来，只把真正需要开放判断的部分交给 Agent。这样可以减少模型自由发挥的空间，让每个节点都能单独测试、监控和回滚，也更方便做权限控制和人工确认。

### ReAct 模式是什么？

回答思路：点明 Reasoning + Acting 的交替循环，再说明它适合需要外部反馈的多步任务。

回答模板：

ReAct 是 Reasoning and Acting 的缩写，核心是让模型在“思考、行动、观察”之间循环。模型先判断当前状态，再调用工具执行动作，然后读取工具返回结果并更新判断。它适合搜索、调试、代码修改这类需要外部反馈的多步任务。

### Planning 和 Workflow 的区别是什么？

回答思路：点明 Planning 是动态生成或更新计划，Workflow 是预先定义流程，再说明生产系统中的组合方式。

回答模板：

Planning 是 Agent 动态生成或更新计划的能力，强调根据当前状态和工具反馈调整下一步；Workflow 是工程师预先定义好的流程编排，强调稳定、可控和可复现。实际生产里我一般会用 Workflow 固定任务边界和关键节点，再让 Agent 在代码排查、资料检索或网页操作等不确定环节里做 Planning。

### 什么场景适合先规划，什么场景适合边做边规划？

回答思路：目标明确、影响面大时先规划；信息不完整、依赖环境反馈时边做边规划；复杂任务采用阶段性计划和动态修正。

回答模板：

目标明确但步骤复杂、需要用户审核或影响面较大时，适合先规划，例如代码重构或数据迁移。信息不完整、强依赖环境反馈时，适合边做边规划，例如排查报错、网页操作或多轮检索。复杂任务通常会结合两者：先制定阶段性计划，每一步执行后根据观察结果修正。

### 为什么 Agent 需要观察工具结果后再规划？

回答思路：初始信息不完整，工具结果会改变当前状态，因此不能沿着旧假设继续执行。

回答模板：

因为 Agent 的初始判断往往基于不完整信息，工具结果会改变当前状态。观察结果后再规划，可以避免沿着错误假设继续执行。例如代码调试时，运行测试后的报错会直接决定下一步该查数据、改逻辑还是调整环境。

### 如何避免 Agent 陷入无限循环？

回答思路：使用最大步数、超时、重复动作检测和明确完成条件，并保留轨迹用于复盘。

回答模板：

我会设置最大步数、超时、重复动作检测和明确的完成条件；如果多轮没有产生新信息，就要求 Agent 总结阻塞原因或转人工处理。生产系统里还应该记录 trajectory，用于发现是 Prompt、工具还是终止条件设计的问题。
