# Tool Call 与 Function Calling

## 知识点解析

### 概述

Tool Call 或 Function Calling 是让模型以结构化方式表达“需要调用外部能力”的机制。模型不直接执行函数，而是生成调用意图；外层编排器负责校验参数、检查权限、执行工具、处理错误，再把结构化结果返回给模型或下游节点。

### 为什么需要 Tool Call

模型本身不能直接访问数据库、文件、浏览器、设备或业务服务。结构化工具调用可以把自然语言目标转换为可验证的动作，并让执行结果进入下一轮决策。

### 基本流程

```text
用户目标
  -> 模型判断是否需要外部能力
  -> 生成结构化调用意图
  -> 编排器校验参数和权限
  -> 执行工具
  -> 返回结构化结果
  -> 模型继续判断或输出结论
```

### Tool Schema

工具描述通常包括：

- 名称和能力说明。
- 参数名、类型、枚举和必填字段。
- 默认值、长度、范围和单位。
- 返回数据结构和错误码。
- 只读或写入属性。
- 所需权限、超时和幂等要求。

Schema 的目标是让模型容易选择，让程序容易校验，让下游容易组合。

### 好的工具设计

- 一个工具只负责一个清晰动作。
- 名称和描述说明适用边界，不隐藏副作用。
- 参数尽量少，避免让模型重复推断。
- 返回值结构化，区分成功、空结果、失败和不确定。
- 错误信息能说明原因、是否可重试和下一步动作。
- 高风险操作支持 dry-run、人工确认、审计和回滚。
- 工具不保存请求级状态，不依赖模型自行提供权限证明。

### 常见失败模式

- 工具选错。
- 参数缺失、类型错误或单位错误。
- 调用时机过早，前置状态尚未收敛。
- 工具返回错误却被当成空结果。
- 返回内容过长，污染上下文。
- 重试造成重复副作用。
- 工具缺少资源级鉴权和输出校验。

### Tool Call 与 MCP 的关系

Tool Call 是调用机制，MCP 是外部能力接入协议。MCP 可以作为 Tool Call 的工具来源，提供能力发现、工具调用、资源读取和 Prompt 模板；但模型、编排器、MCP Client、MCP Server 和真实后端仍然各自承担不同职责。

### MCP 的三类对象

- **Tools**：可执行动作，例如查询、采集或创建任务。
- **Resources**：可读取的结构化资源，例如页面快照、规则文档和运行日志。
- **Prompts**：可复用的任务模板，但仍应经过版本、变量和输出契约控制。

### Code Execution with Tools

当工具结果很多或需要批量组合时，可以让受控脚本在沙箱中调用工具、过滤结果和生成摘要，避免把所有原始数据塞入上下文。代码执行必须限制文件系统、网络、进程、CPU、内存、运行时长和凭证访问。

### 工具结果与错误模型

推荐统一包含：

```text
success
code
data
evidence
retryable
request_id
tool_version
latency
```

错误至少区分参数错误、认证失败、权限拒绝、资源不存在、服务未就绪、限流、超时和未知错误。模型看到简洁摘要，完整错误和审计信息进入受控日志。

## 面试应对

### 常考点及考法

常考 Function Calling 流程、工具 Schema、结构化返回、失败处理、MCP 关系和代码执行安全边界。

### 解法/回答思路

先区分模型只产生调用意图、编排器负责校验执行，再说明工具设计、权限、错误码和结果验证。

### 易错点

把模型当成函数执行者，把 MCP 当成模型能力，或只讲重试而不区分参数错误、权限错误和业务空结果。

### 回答模板

可直接回答：

> Function Calling 让模型用结构化方式表达工具调用意图，但模型本身不执行函数。外层编排器负责校验 schema、身份和权限，调用真实工具，再把结构化结果返回给模型。工具设计要有清晰描述、严格参数、稳定返回、错误码、超时和幂等语义；高风险写操作还要 dry-run、人工确认、审计和回滚。MCP 是标准化的外部能力接入协议，可以提供 Tools、Resources 和 Prompts，但不能替代编排器、后端鉴权和业务规则。

### 如何处理工具调用失败？

回答思路：先区分错误类型，再决定重试、补充输入、降级、人工确认或直接失败。

回答模板：

参数错误和权限拒绝通常不重试，应返回可操作的错误；临时网络错误、服务未就绪和限流可以有限退避重试；超时要检查是否会产生副作用并使用幂等键。工具返回空结果时，还要区分“确实没有数据”和“执行失败”，不能统一当成成功。

### MCP 解决了什么问题？

回答思路：从能力发现、统一协议、跨 Agent 复用和治理成本回答，同时说明它不是安全边界。

回答模板：

MCP 通过统一协议描述和调用外部 Tools、Resources、Prompts，降低不同 Agent 接入不同系统时的适配成本。它解决的是能力接入和发现问题，不会自动解决权限、数据隔离、审计、限流和业务错误处理；这些仍需要 Client、Server 和后端共同负责。
