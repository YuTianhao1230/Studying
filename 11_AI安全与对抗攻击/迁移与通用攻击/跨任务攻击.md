# 跨任务攻击

## 知识点解析

### 概述

跨任务攻击是在一个任务或源模型上构造扰动，使其迁移到其他视觉任务或多模态任务中仍能造成性能下降，常用于评估模型共享表征的鲁棒性。

### 解决的问题

传统攻击往往只针对分类任务。跨任务攻击关注更真实的问题：一个扰动能否同时影响分类、检测、分割、检索、caption 或 VQA 等不同任务。

### 基本设定

```text
source task: semantic segmentation
target tasks: classification / detection / segmentation

learn delta on source task
evaluate delta on target tasks
```

不同任务输出不同，损失和指标也不同：

- 分类：cross entropy、accuracy drop。
- 检测：classification + bbox loss、mAP drop。
- 分割：pixel-wise CE、mIoU drop。
- 检索：contrastive similarity、Recall@K drop。

### 为什么跨任务更难

- 输出空间不同，不能直接共用任务头 loss。
- 目标任务可能使用不同模型架构。
- 分类关注全局类别，检测关注框，分割关注像素级区域。
- 攻击如果只过拟合某个任务头，迁移到其他任务会失效。

### 解决思路

1. 攻击共享 backbone 表征，而不是只攻击最后任务头。
2. 使用 dense prediction 任务作为源任务，获得更丰富梯度。
3. 引入多任务 loss 或多头判别器，约束扰动影响多种语义层级。
4. 使用模型集成，覆盖不同架构和训练目标。
5. 在未见过模型和未见过任务上做泛化评估。

### 项目表达

你的 KBS 项目可以这样组织：

```text
问题：单个任务攻击不能说明视觉系统整体脆弱。
方法：以语义分割模型为源模型，用多头判别器和源模型对抗博弈学习通用扰动。
原因：分割提供像素级监督，更容易覆盖物体边界、区域和语义结构。
验证：在分类、检测、分割任务上分别看 accuracy、mAP、mIoU 下降，并测试迁移到 ViT。
```

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 概念题 | 什么是跨任务攻击 | 源任务生成扰动，目标任务评估效果 |
| 原因题 | 为什么分割适合作源任务 | 像素级 dense supervision，覆盖局部和全局结构 |
| 实验题 | 怎么证明跨任务 | 分类 accuracy、检测 mAP、分割 mIoU 分别报告 |
| 局限题 | 为什么不能只看平均提升 | 不同任务指标不可直接平均，需要分别分析 |

### 易错点

- 把跨模型攻击和跨任务攻击混为一谈。
- 只攻击同一模型不同头，不算充分跨任务泛化。
- 不报告每个任务自己的指标。
- 源任务和目标任务数据泄漏，导致泛化证据不足。

## 面试应对

### 1. 什么是跨任务攻击，它与跨模型攻击有什么区别？

回答思路：分别定义任务输出空间和模型实例的变化，说明实验可以同时跨任务、跨模型，但两个维度不能互相替代。

回答模板：

> 跨模型攻击是在任务基本不变时，把源模型上的扰动迁移到另一个模型；跨任务攻击则是在源任务上构造扰动，再评估分类、检测、分割或检索等不同输出空间。两者可以同时发生，例如从分割 CNN 迁移到检测 ViT，但证据应拆开报告。仅更换同一任务的架构不能证明跨任务，仅更换同一 backbone 的任务头也不足以证明强跨模型泛化。

### 2. 为什么攻击共享特征比攻击任务头更可能实现跨任务迁移？

回答思路：对比任务头专用输出与 backbone 通用语义，解释 dense supervision 的潜在优势和不保证成功的边界。

回答模板：

> 分类、检测和分割的任务头、损失与标签空间不同，直接攻击最后输出容易绑定源任务。中间 backbone 特征承担边缘、区域、物体和语义表示，更可能被多个任务复用，因此最大化中间表征偏移或在 dense prediction 上获得覆盖局部与全局的梯度，通常更有利于跨任务迁移。但如果目标任务使用不同模态、完全不同的特征提取器，或只依赖扰动未影响的表示层，共享特征假设会变弱，跨任务攻击仍可能失败。

### 3. 如何设计实验来证明攻击确实跨任务有效？

回答思路：固定同一扰动，分离训练与目标任务，使用各任务原生指标和任务内基线，并检查数据与 backbone 泄漏。

回答模板：

> 我会在明确的源任务和训练数据上生成或学习扰动，冻结后直接用于未参与优化的目标任务。分类看 accuracy 或 ASR，检测看 mAP，分割看 mIoU，检索看 Recall@K，并分别与等预算随机扰动和对应任务攻击基线比较。还要区分共享 backbone、不同 backbone 以及未见数据三种设置，避免目标任务头或测试样本参与调参。若某一任务无明显下降，应按特征层、数据分布和指标敏感性分析边界，而不是只汇报平均值掩盖失败任务。
