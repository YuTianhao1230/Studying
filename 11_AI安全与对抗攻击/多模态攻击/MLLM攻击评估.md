# MLLM 攻击评估

## 知识点解析

### 概述

MLLM 攻击评估关注开放式多模态输出下如何定义攻击成功率、如何固定评估协议、如何使用人工或 LLM Judge 判断输出是否被误导。

### 解决的问题

分类任务有明确标签，攻击成功容易定义。MLLM 输出是开放文本，同一问题可能有多种合理回答，因此需要更细的评估协议。

### 常见任务和 ASR 定义

| 任务 | 攻击成功定义 |
| --- | --- |
| Image Captioning | 攻击后描述遗漏或错误描述关键对象、属性、关系 |
| VQA | 攻击后答案与标准答案不一致 |
| 图文一致性判断 | 正确图文被判不一致，或错误图文被判一致 |
| OCR/文档理解 | 关键文字、数字、表格字段识别错误 |
| 安全问答 | 攻击后输出违反安全策略 |
| CLIP-proxy | 攻击后输出和原图语义不一致，或图文相似度显著下降 |

ASR 通常写成：

```text
ASR = successful_attacks / attackable_samples
```

其中 attackable samples 应该是 clean 输入下原本回答正确或语义一致的样本。

### 评估协议

一个合格 MLLM 攻击评估要固定：

1. 模型版本：如 GPT-4o、Qwen2-VL、LLaVA-1.5。
2. Prompt 模板：避免 prompt 差异影响结果。
3. Decoding 参数：temperature、top-p、max tokens。
4. 样本集合：数据来源、样本量、过滤规则。
5. 攻击预算：图像扰动和文本替换预算。
6. Judge 规则：人工、规则、LLM Judge 或混合。
7. 失败分类：对象错、属性错、关系错、拒答、幻觉、无变化。

### Judge 设计

人工评估：

- 可信度高。
- 成本高。
- 需要标注标准和一致性检查。

LLM Judge：

- 成本低、可扩展。
- 需要固定 judge prompt。
- 对细粒度视觉事实可能不可靠。
- 最好抽样人工复核。

规则评估：

- 适合 VQA、OCR、结构化字段。
- 对开放 caption 不够灵活。

### 和 baseline 公平比较

公平比较至少对齐：

- 数据集和样本量。
- 源模型和目标模型。
- 图像扰动预算。
- 文本替换比例和语义约束。
- prompt 和 decoding 参数。
- ASR 判定规则。
- 是否允许同时改图和文本。

如果你的方法同时改图文，而 baseline 只改图，需要明确 threat model 不同，不能直接把 ASR 当成同等设置下的优势。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 指标题 | MLLM ASR 怎么定义 | 先定义任务成功条件，再过滤 clean 正确样本 |
| 协议题 | 如何保证评估公平 | 固定模型、prompt、预算、judge、样本 |
| Judge 题 | LLM Judge 有什么风险 | 偏差、幻觉、细粒度视觉事实不可靠 |
| 项目题 | 定性 case 为什么不够 | 需要样本量、统计 ASR 和失败类型分析 |

### 易错点

- 把输出变化都算攻击成功，但有些只是等价改写。
- 不过滤 clean 下原本失败的样本。
- prompt 不固定，导致结果不可比。
- 只用 LLM Judge，不做人审抽检。
- 不说明商业模型版本和调用日期。

## 面试应对

### 1. MLLM 攻击的 ASR 应该如何定义？

回答思路：先按任务给出可判定的成功条件，再强调分母只能包含 clean 下可攻击样本，并区分输出变化与语义失败。

回答模板：

> MLLM 输出是开放文本，ASR 必须先绑定任务成功条件。VQA 可定义为 clean 正确而攻击后答案错误，caption 可定义为关键对象、属性或关系出现事实性错误，OCR 则看关键字段是否识别错误。统计式是 `ASR=successful_attacks/attackable_samples`，分母只能包含 clean 输入下原本正确且满足攻击前提的样本。措辞变化、等价改写或正常拒答不能自动算攻击成功，判定规则要在实验前固定。

### 2. 人工、规则和 LLM Judge 应如何选择，怎样控制 Judge 偏差？

回答思路：按任务结构选择判定器，说明盲评、固定模板、多人一致性和人工复核，避免把 Judge 当作无误差真值。

回答模板：

> 结构化 VQA、OCR 或字段抽取优先用标准答案和规则匹配；开放 caption 或复杂语义可采用人工标注，或者 LLM Judge 加人工抽检。使用 LLM Judge 时要固定模型版本、提示词和输出格式，随机隐藏方法名称与 clean/attack 顺序，设置无法判断选项，并在代表性样本上与多人标注比较一致性。最终同时报告自动判定结果、人工复核范围和主要分歧类型，不能把 Judge 的单次输出当成绝对真值。

### 3. 如何公平比较不同 MLLM 攻击，并分析攻击失败？

回答思路：对齐模型、样本、prompt、解码、攻击权限和预算；按感知、对齐、推理、判定层拆解失败。

回答模板：

> 公平比较必须对齐目标模型版本、样本过滤、prompt、解码参数和 ASR 规则，还要对齐图像范数、文本替换率、查询次数以及是否允许同时改图文。不同 threat model 的方法应分组报告，不能把 joint attack 与 image-only baseline 当成同等预算。失败分析可按四层进行：输入扰动是否合规且可见，视觉或文本表征是否变化，跨模态对齐是否受损，最终生成是否仍被模型纠错，以及 Judge 是否误判。除总 ASR 外，我还会报告对象错、属性错、关系错、拒答和无变化等类型分布。
