# 文本对抗攻击

## 知识点解析

### 概述

文本对抗攻击通过替换、插入、删除或改写文本 token，使模型输出错误，同时尽量保持原句语义、语法和可读性。

### 解决的问题

图像扰动是连续空间优化，文本是离散 token，不能直接对字符或词做连续小扰动。文本攻击解决的是：如何在离散候选空间中找到既能误导模型又不明显改变语义的改写。

### 常见攻击粒度

| 粒度 | 方法 | 风险 |
| --- | --- | --- |
| 字符级 | 拼写扰动、插入字符、同形字符 | 容易被拼写纠错发现 |
| 词级 | 同义词替换、实体替换 | 容易改变语义 |
| 句级 | 释义改写、句式变化 | 搜索空间大，语义控制难 |
| Prompt 级 | 指令注入、上下文污染 | 更偏 LLM 安全和越狱 |

### 典型流程

1. 重要性排序：判断哪些词最影响模型输出。
2. 候选生成：用同义词词典、embedding 邻近词或 masked LM 生成替换词。
3. 语义过滤：检查句向量相似度、词性、实体类型和语法。
4. 攻击评估：选择最能降低正确输出概率或图文匹配分数的候选。
5. 预算控制：限制替换比例、编辑距离或查询次数。

### BERT-Attack 思路

BERT-Attack 使用 BERT 评估词重要性并生成上下文相关候选词。遮蔽词用于重要性评估：逐个用 `[MASK]` 替换词，观察目标模型预测变化；生成替换候选时则输入保留原词的原句，让 BERT 在原词及其上下文信息都存在的情况下给出该位置的候选：

```text
original sentence
  -> mask each word to estimate importance
  -> restore the original sentence
  -> BERT predicts candidates with the original word context retained
  -> filter by semantic similarity and POS
  -> choose candidate that maximizes attack objective
```

优势是候选词更符合上下文，句子流畅度通常比简单同义词表更好。

### 多模态文本攻击

在 VLM/MLLM 中，文本攻击不只看语言模型输出，还要看文本和图像的对齐关系。重要词通常包括：

- 物体名：dog、car、person。
- 属性词：red、small、wooden。
- 动作词：running、holding。
- 空间关系：left of、behind、under。
- 数量词：two、three。

视觉引导文本攻击会优先替换对图文匹配影响最大的词，而不是只看语言流畅度。

### 语义保持约束

文本攻击最容易被质疑语义是否改变。常见约束：

- 替换比例不超过阈值。
- 词性一致。
- 命名实体类型一致。
- 句向量相似度高于阈值。
- perplexity 不显著变差。
- 人工抽检语义和语法。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 难点题 | 文本攻击为什么比图像难 | 离散 token、语义保持、语法约束 |
| 方法题 | BERT-Attack 怎么做 | 重要性排序、MLM 候选、语义过滤、攻击选择 |
| 多模态题 | 视觉引导文本攻击是什么 | 用视觉相关性选择影响图文对齐的词 |
| 评估题 | 如何证明语义保持 | 替换率、相似度、语法、人审 |

### 易错点

- 替换核心实体后仍声称语义保持。
- 只看攻击成功，不报告替换比例。
- 用 LLM 改写但不控制目标语义。
- 把 prompt injection 和语义保持型文本扰动混为一谈。

## 面试应对

### 1. 文本对抗攻击为什么不能直接照搬图像梯度攻击？

回答思路：说明 token 的离散性与语义敏感性，再给出重要性排序、候选生成、过滤和搜索的完整流程。

回答模板：

> 图像像素位于连续空间，可以沿输入梯度做小幅更新；文本 token 是离散符号，embedding 上的一小步通常不能直接映射为合法且等义的词。文本改动还可能改变实体、数量、否定或关系，造成标签本身变化。常见流程是先估计词重要性，再用同义词或 masked LM 生成候选，通过词性、实体、语义相似度和流畅度约束过滤，最后在替换率或查询预算内选择最能提高攻击目标的改写。

### 2. 多模态中的视觉引导文本攻击与 Prompt Injection 有什么区别？

回答思路：比较攻击目标、语义约束和威胁模型，说明视觉引导为何关注物体、属性、动作与关系词。

回答模板：

> 视觉引导文本攻击仍属于语义尽量保持的输入扰动，它根据图文对齐或视觉相关性挑选物体、属性、动作和关系词，再从合法候选中搜索，使文本侧改动更直接破坏跨模态匹配。Prompt Injection 则通过指令优先级、上下文污染或越权指令改变模型行为，通常不要求与原文本语义等价。两者的攻击面、预算和成功标准不同，不能用 Prompt Injection 的成功案例证明语义保持型文本攻击有效。

### 3. 如何证明文本攻击在语义保持的前提下成功？

回答思路：攻击指标与质量约束分开报告，覆盖自动指标、人审和关键事实保护；失败时检查标签是否被改写。

回答模板：

> 我会先只在 clean 输入回答正确的样本上统计 ASR，并报告修改词数、替换比例或编辑距离。语义质量不能只靠一个句向量阈值，还要检查词性、语法、流畅度以及实体、数量、否定和空间关系是否保持，并对样本做盲法人工抽检和一致性统计。若攻击主要通过替换核心对象或改变事实标签成功，应判为语义破坏而非有效攻击；若自动相似度高但人审认为含义变化，也应以更严格规则重新评估。
