# 输入预处理防御

## 知识点解析

### 概述

输入预处理防御通过 JPEG 压缩、模糊、降 bit-depth、随机 resize padding 等方式改变输入，试图破坏对抗扰动或降低扰动影响。

### 解决的问题

许多图像扰动集中在高频或细小像素变化中。输入预处理希望在不明显伤害 clean 图像语义的前提下，削弱这些扰动。

### 常见方法

| 方法 | 思路 | 适用性 | 局限 |
| --- | --- | --- | --- |
| JPEG 压缩 | 去除部分高频信息 | 简单、低成本 | 可能损伤细节，adaptive attack 可绕过 |
| Bit-depth reduction | 降低像素精度 | 消除细小扰动 | 影响细粒度视觉任务 |
| Gaussian blur | 平滑图像 | 抑制高频噪声 | 小目标、OCR 可能受损 |
| Gaussian noise | 随机扰动输入 | 打散固定扰动 | 稳定性有限 |
| Random resize padding | 改变尺度和位置 | 对固定扰动有效 | EOT 可适配随机性 |

### 为什么不够可靠

输入预处理没有真正改变模型决策边界，只是改变输入分布。如果攻击者知道防御存在，可以把预处理纳入攻击过程：

```text
maximize E_{transform ~ T} L(f(transform(x_adv)), y)
```

这就是 EOT 思路。随机防御也可以通过对随机变换求期望梯度来绕过。

### 评估方式

1. 报告 clean 性能变化。
2. 报告攻击前后 ASR。
3. 测多种攻击和多种预算。
4. 做 adaptive attack 或 EOT attack。
5. 检查预处理是否改变原始语义。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 概念题 | JPEG 为什么可能防御扰动 | 去除高频信息 |
| 局限题 | 为什么预处理不可靠 | 不改模型边界，adaptive attack 可绕过 |
| 实验题 | 怎么评估预处理防御 | clean 性能、多攻击、多预算、EOT |
| 项目题 | 为什么做 JPEG/blur/noise 防御 | 作为低成本 baseline，验证扰动依赖性 |

### 易错点

- 预处理后 clean accuracy 大幅下降，却声称防御有效。
- 只测非自适应攻击。
- 图像被模糊到语义改变，攻击失败不公平。
- 把输入预处理当成强鲁棒性证明。

## 面试应对

### 1. 输入预处理防御的机制是什么，为什么可能有效？

回答思路：按高频抑制、量化和随机变换分类，说明这些方法改变输入而非直接优化模型边界。

回答模板：

> 输入预处理在模型前对输入做确定性或随机变换。JPEG、模糊会削弱部分高频成分，bit-depth reduction 会消除细小量化变化，random resize-padding 则破坏对固定尺度和位置的依赖。它们成本低，也能用于分析攻击依赖的信号类型，但主要是在改变输入分布，并没有直接让原模型决策边界变得平滑，因此效果高度依赖攻击是否知道这一步。

### 2. 为什么 BPDA 和 EOT 能绕过很多预处理防御？

回答思路：分别对应不可微和随机防御，给出反向近似梯度与期望梯度的核心形式。

回答模板：

> 对 JPEG、round 或量化这类不可微操作，BPDA 在前向仍使用真实预处理，反向则用恒等映射或可微近似提供梯度，使攻击能够继续优化。对随机 resize、padding 或加噪，EOT 优化 `E_{T}[L(f(T(x_adv)),y)]`，通过多次采样平均梯度，降低随机性造成的噪声。因此普通 PGD 失败可能只是没有穿过预处理，只有把已知防御纳入自适应攻击后仍有效，才支持更强的鲁棒结论。

### 3. 如何公平评估 JPEG、模糊等预处理，避免把图像损坏当成防御？

回答思路：同时报告 clean 性能、感知或任务质量、自适应攻击和多任务边界，并与等强度无攻击输入比较。

回答模板：

> 我会先测预处理对 clean accuracy、mAP、mIoU 或 OCR 准确率的影响，确保防御没有通过删除关键语义让任务本身失效。随后在相同预算下比较无防御、非自适应攻击和包含 BPDA/EOT 的自适应攻击，并扫描压缩质量、模糊核或量化位数。若攻击下降伴随 clean 指标同等幅度下降，这更像输入破坏而非选择性防御；若只对某类高频攻击有效，也应把结论限定为低成本过滤基线。
