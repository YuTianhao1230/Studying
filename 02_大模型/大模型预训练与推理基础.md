# 大模型预训练与推理基础

## 知识点解析

### 概述

大模型预训练与推理基础连接数据、Tokenizer、训练目标、规模规律、上下文扩展和生成策略。模型架构决定能力上限和计算方式，预训练决定模型获得哪些基础知识，推理策略决定这些能力如何在一次生成中被调用。面试中需要把三者连成完整链路。

### Tokenizer

Tokenizer 将文本转换为离散 Token ID。常见方法包括 BPE、WordPiece、Unigram 和 SentencePiece。

- 字符级词表小、无未登录词，但序列较长。
- 词级序列短，但词表巨大且难处理新词。
- 子词方法在词表大小、序列长度和开放词汇之间折中。

BPE 从字符或字节开始，反复合并语料中高频相邻单元。SentencePiece 直接对原始文本建模，不依赖预先空格切词，适合多语言。

Tokenizer 会影响：

- 序列长度和训练推理成本。
- 数字、代码和多语言文本的表示效率。
- 特殊 Token、Chat Template 与工具调用格式。
- 扩充词表后的 Embedding 初始化和模型兼容性。

更大的词表不一定更好，因为它会增加 Embedding 和输出层参数，也可能降低低频 Token 的训练充分度。

### 预训练目标

Decoder-only LLM 通常使用 Next-Token Prediction：

```text
L = -Σ log P(x_t | x_<t)
```

模型根据前文预测下一个 Token。训练时可以并行计算序列中所有位置的 Loss，生成时则必须自回归逐 Token 解码。

Encoder 模型常用 Masked Language Modeling，Encoder-Decoder 模型可使用去噪重建或 Seq2Seq 目标。目标选择与任务形态有关：Decoder-only 统一生成接口简单，适合规模化和多任务提示学习。

### 预训练数据

预训练数据流程通常包括：

```text
采集
  -> 格式解析
  -> 语言与质量过滤
  -> 去重
  -> 安全与隐私处理
  -> 数据配比
  -> Tokenize
  -> Sequence Packing
  -> 版本化
```

关键问题：

- 去重既要处理完全重复，也要处理近重复和跨来源转载。
- 数据配比不能只按原始体量，否则高资源语言和低质量网页会主导训练。
- 高质量代码、数学、书籍和领域数据可能采用上采样。
- Sequence Packing 将多个短样本拼入固定长度序列，减少 Padding，但要正确处理文档边界和 Attention Mask。
- 数据版本必须可追溯，避免训练集和评测集污染。

### Scaling Law

Scaling Law 描述模型参数、数据量和计算量增加时，Loss 通常按幂律下降。它的工程价值不是“模型越大越好”，而是帮助在固定计算预算下分配模型规模和训练 Token。

判断训练方案时至少要同时考虑：

- 参数规模是否与数据量匹配。
- 是否已经充分训练，而不是只堆参数。
- 数据质量和任务分布是否适合目标能力。
- 训练成本、推理成本与真实收益。

规模规律是在特定数据、架构和预算范围内观察到的经验关系，不能替代小规模验证和任务评测。

### 长上下文

上下文变长会带来注意力计算、KV Cache、训练数据和位置外推问题。

常见方法包括：

- 使用 RoPE Scaling、NTK-aware Scaling 或 YaRN 扩展位置范围。
- 使用 FlashAttention 降低 Attention 的显存读写开销。
- 使用滑动窗口、稀疏注意力或分块处理降低复杂度。
- 通过长文本继续训练，让模型适应新的长度分布。
- 使用检索和上下文压缩减少无效 Token。

支持更长的位置不等于能够有效利用全部内容。需要使用 Needle-in-a-Haystack、长文问答、跨段推理和真实业务任务验证检索与推理能力。

### 生成与采样

模型输出的是下一个 Token 的概率分布。常见策略：

- Greedy：每步选择最大概率 Token，稳定但容易模式单一。
- Beam Search：保留多个高概率序列，适合翻译等目标较确定的任务。
- Temperature：调整分布尖锐程度，越低越确定。
- Top-k：只在概率最高的 k 个 Token 中采样。
- Top-p：选择累计概率达到 p 的最小候选集合。

事实问答、代码修改和结构化输出通常使用较低随机性；创意生成可以提高 Temperature 或使用 Top-p。固定随机种子不能保证跨模型版本、硬件和内核完全一致。

### 推理时扩展

推理时扩展通过增加测试阶段计算提升复杂任务表现，常见方式包括：

- 生成更长的推理过程。
- 多次采样后做 Self-Consistency。
- 使用搜索、验证器或 Reward Model 选择候选答案。
- 将复杂任务拆成多个可验证步骤。
- 对代码和数学任务执行结果验证。

推理 Token 增加不保证效果单调提升，可能产生冗余推理、错误累积和成本上升。生产系统应同时评估准确率、完成率、延迟和 Token 成本。

### 预训练、后训练与推理的关系

| 阶段 | 主要目标 | 典型数据 | 核心风险 |
| --- | --- | --- | --- |
| 预训练 | 学习语言、知识和通用模式 | 大规模无标注或弱标注语料 | 数据污染、配比失衡、训练成本 |
| SFT | 学习指令跟随和输出格式 | 指令与回答 | 灾难性遗忘、模板过拟合 |
| 偏好/RL | 优化人类偏好或可验证目标 | 偏好对、轨迹、奖励 | Reward Hacking、能力退化 |
| 推理策略 | 在请求时选择生成路径 | Prompt、工具、搜索与验证 | 延迟、成本、错误累积 |

不能期待后训练凭空创造预训练阶段完全没有的知识，也不能用更复杂的推理策略稳定弥补错误数据和薄弱基础能力。

## 面试应对

### BPE 的基本原理是什么？

回答思路：从初始单元、频繁合并和工程权衡回答。

回答模板：

BPE 通常从字符或字节级单元开始，统计语料中最常共同出现的相邻 Token 对，并反复把高频对合并成新的子词，直到达到目标词表大小。它在词级和字符级之间折中，既能通过子词组合处理新词，又能避免序列过长。Tokenizer 的选择会影响序列长度、多语言和代码表示效率，也会影响 Embedding 参数量和推理成本。

### Scaling Law 对训练有什么实际价值？

回答思路：强调预算分配，不把它回答成简单扩模规律。

回答模板：

Scaling Law 的价值是帮助判断固定计算预算应该如何分配给模型参数和训练 Token。只扩大模型但数据不足，模型可能没有被充分训练；只增加低质量数据也不会稳定提升能力。因此我会把参数规模、数据量、数据质量和计算预算一起考虑，再通过小规模实验验证趋势。它是一种规划工具，不是模型越大效果就一定越好的保证。

### 长上下文模型的主要难点是什么？

回答思路：从计算、显存、位置外推、数据和评测回答。

回答模板：

长上下文首先会增加 Attention 计算和 KV Cache 显存，其次位置编码需要能外推到训练长度之外，模型还必须在训练数据中学会跨长距离检索和推理。工程上可以使用 FlashAttention、滑动窗口、RoPE Scaling 和上下文压缩，但支持更长输入不等于真正会利用长文本。我会同时用长文检索、跨段推理和真实业务任务验证能力，并关注延迟和 Token 成本。

### Temperature、Top-k 和 Top-p 有什么区别？

回答思路：说明一个调整整体分布，两个限制候选集合。

回答模板：

Temperature 通过缩放 Logits 调整整个概率分布的尖锐程度，值越低输出越确定。Top-k 只保留概率最高的固定 k 个 Token，Top-p 则保留累计概率达到阈值的动态候选集合。事实问答、代码和结构化输出通常使用较低随机性，创意任务可以适当提高 Temperature 或使用 Top-p。参数选择要结合正确性、重复率和多样性评测，而不是固定套一组值。
