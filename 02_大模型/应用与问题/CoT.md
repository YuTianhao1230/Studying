# CoT

## 知识点解析

### 概述

**CoT**（Chain of Thought，**思维链**）是提示工程（Prompt Engineering）领域的一个核心概念，也是大语言模型（LLM）具备复杂推理能力的关键。

简单来说，CoT 就是**让模型在输出最终答案之前，先把中间的推导步骤写出来**。

### 为什么需要 CoT？（背景）

在没有 CoT 之前，我们通常直接问模型问题，模型也直接给出答案。
*   **普通提示：** 小明有5个苹果，吃了2个，又买了3个，现在有几个？ -> **模型：** “6个。”
*   **面临的问题：** 对于简单的加减法模型能应付，但遇到复杂的**数学题、逻辑推理、常识推理**时，模型往往会“思维跳跃”，直接给出一个错误的答案。这就像小学生做数学大题不写过程，直接写个答案，很容易错。

### CoT 的核心思想

CoT 的核心是**通过逻辑过程的显式表达，辅助模型得出正确结论**。它模拟了人类解决复杂问题时的“草稿纸”思维。

#### 示例对比：
*   **Standard Prompting (标准提示):**
    *   用户：Q: [复杂数学题] A: ?
    *   模型：[直接给出一个错误答案]
*   **CoT Prompting (思维链提示):**
    *   用户：Q: [复杂数学题] 
    *   模型：首先，我们要算出...；其次，根据公式...；所以最后结果是...。**A: [正确答案]**

### CoT 的两种实现方式

#### (1) Few-shot CoT (少样本思维链)
这是 CoT 最初提出的方式（由 Google 在 2022 年提出）。
*   **做法：** 在给模型提问时，先给它一个或几个例子，这些例子里不仅有答案，还包含了**详细的解题步骤**。
*   **效果：** 模型会模仿你的解题格式，学会“先推理，再给结论”。

#### (2) Zero-shot CoT (零样本思维链)
这是目前最出名、最简单的方法（由 Kojima 等人提出）。
*   **做法：** 不需要给例子，只需要在问题的结尾加上一句话：**Lets think step by step（请一步步思考）**。
*   **原理：** 这句话像一个开关，激活了模型预训练数据中的逻辑链条，促使模型将问题拆解。

### 为什么 CoT 有效？（底层逻辑）

1.  **分配更多的计算资源（Token）：** 
    大模型生成每一个字（Token）都需要一定的计算量。如果直接出答案，模型只用了很少的计算资源。如果把推导过程写出来，模型就有了更多的“思考空间”和计算步骤来处理复杂逻辑。
2.  **降低搜索空间：**
    通过一步步写出推导过程，模型在生成每一步时都在为下一步打基础。上一个正确的步骤会成为下一个步骤的上下文（Context），从而引导模型走向正确的结局。
3.  **可解释性：**
    如果模型最后算错了，你可以通过观察它的思维链，发现它到底是哪一步算错了，方便进行调试和优化。

### CoT 的进阶变体

随着技术的发展，CoT 已经演化出了很多更高级的形式：
*   **Self-Consistency (自洽性):** 让模型对同一个问题生成多条不同的思维链，然后看哪个答案出现的次数最多（投票法），从而大幅提高准确率。
*   **Tree of Thoughts (ToT, 思维树):** 像树状图一样探索不同的推理路径，如果发现某条路走不通就回溯，适合解决极高难度的智力题（如 24 点游戏）。
*   **Graph of Thoughts (GoT, 思维图):** 允许推理路径相互交叉、回流，模拟更复杂的思维网络。

### 总结

*   **CoT 是什么：** 让模型把思考过程写出来的技术。
*   **解决了什么：** 解决了大模型在逻辑、数学、常识推理上的“短路”问题。
*   **关键词：** “请一步步思考”。

**一句话总结：** CoT 就是给大模型发了一张“草稿纸”，让它在算出答案前先列出公式和步骤。

### CoT需要复杂的训练吗，只需要加上一句话：“Let’s think step by step”就可以了吗？

**对于普通用户来说，确实只需要加上一句话；但对于模型开发者来说，这背后需要极其复杂的训练。**

我们可以从 **使用端** 和 **训练端** 两个维度来拆解：

### 在使用端（Prompting）：确实只需要一句话
如果你使用的是目前主流的大模型（如 GPT-4, Claude 3, Llama 3, [Qwen](<../模型细节/Qwen千问架构.md>) 2 等），你确实不需要做任何复杂的训练，直接加上 **Lets think step by step**（让我们一步步思考）就能显著提升逻辑推理能力。

这种现象被称为 **Zero-shot CoT**（零样本思维链）。
*   **为什么有效？** 因为这些模型在预训练阶段已经见过了大量带有逻辑推理的数据（如代码、数学题解、论文）。这句话就像一个**激活开关**，暗示模型切换到“逻辑推导模式”，而不是“概率预测下一个词模式”。

### 在训练端（Training）：CoT 是“喂”出来的
模型并不是天生就会“一步步思考”的。如果是一个完全没有经过优化的小模型，你对它说“一步步思考”，它可能会产生更严重的幻觉（胡言乱语）。

为了让模型具备这种“听话”并“逻辑严密”的能力，开发者做了以下工作：

#### (1) [SFT（有监督微调）](<../../03_训练优化与对齐/后训练与对齐/SFT 监督微调.md>)阶段：注入思维过程
开发者会准备几十万条高质量的训练数据，这些数据不是简单的 `问题 -> 答案`，而是 `问题 -> 思考过程 -> 答案`。
*   **传统数据：** “Q: 1+1等于几？ A: 2。”
*   **CoT 数据：** “Q: 1+1等于几？ A: 首先，我们确定第一个加数是1，第二个加数也是1。根据算术加法规则，1+1的结果是2。所以答案是2。”
*   **结果：** 模型通过模仿这些数据，学会了“把思维过程写出来”的模式。

#### (2) [RLVR](<../../03_训练优化与对齐/后训练与对齐/RLVR 可验证奖励强化学习.md>)/[GRPO](<../../03_训练优化与对齐/后训练与对齐/GRPO 组相对策略优化.md>)阶段：优化推理行为
如果模型在推理过程中逻辑错了，但最后答案碰巧对了，可以通过过程奖励、验证器或人工/模型评分给它较低分；只有答案和关键推理约束都满足时，才给更高奖励。

这类训练迫使模型不仅关注“结果对不对”，也关注“推理过程是否满足可验证约束”。[DPO](<../../03_训练优化与对齐/后训练与对齐/DPO 直接偏好优化.md>) 可以使用带 CoT 的 chosen/rejected 数据，但它是离线偏好优化，不属于强化学习。

#### (3) 数据比例的调优
研究发现，**代码数据（Code）**对思维链能力的形成至关重要。代码本身就是极具逻辑性的“步骤指令”。因此，在大模型预训练中加入大量代码，是模型具备 CoT 能力的前提。

### 代表性案例：OpenAI o1 的推理时计算

OpenAI o1 是推理模型路线的早期代表性案例。它的重要性在于展示了：

1. **推理时计算**：模型可以在最终回答前投入更多计算和生成步骤。
2. **推理后训练**：通过强化学习等方法，让模型学习尝试、检查和修正解题路径。
3. **能力与成本权衡**：思考预算越大，复杂任务可能更稳，但延迟和 token 成本也会增加。

后续的推理模型已经发展出不同的 thinking、RL、验证器和蒸馏路线。讨论 CoT 时，应该把 o1 作为历史上的代表性案例，而不是固定的最新标准。

### 总结：什么时候只加一句话不够用？

虽然“一句话”很神奇，但在以下三种情况下，你需要更复杂的手段：

1.  **模型太小：** 如果是参数量很小的模型（如 1B 或 3B 以下），它们往往不具备这种涌现能力，加了这句话效果也不明显。
2.  **任务极其复杂：** 对于非常复杂的几何证明、法律条文分析，简单的一句话可能让模型在中间步骤出错（一步错步步错）。这时需要使用 **Few-shot CoT**（给模型几个带步骤的示例）。
3.  **垂直领域：** 在医疗、金融等严谨领域，需要通过 **微调（Fine-tuning）** 让模型学习特定领域的思维逻辑。

**结论：** 
你看到的“轻而易举”，是因为 OpenAI、Meta、阿里等公司已经帮你完成了最困难的训练过程。**你手中的提示词，只是推开了那扇已经被造好的大门。**

### CoT 在模型后训练中的用途

CoT 不是一种单独的优化算法，而是**推理轨迹、监督信号或模型输出格式**。在后训练中，它可以出现在多个阶段，但用途不同：

| 后训练阶段 | CoT 的角色 | 是否必须有人工 CoT 标签 |
| --- | --- | --- |
| [Reasoning SFT / Long-CoT SFT](<../../03_训练优化与对齐/后训练与对齐/SFT 监督微调.md>) | 作为目标答案，教模型学习问题分解和推理格式 | 通常需要高质量 CoT 或教师生成结果 |
| Response Distillation | 作为教师模型生成的 response，蒸馏给学生模型 | 不一定需要教师 logits，黑盒 response 也可以 |
| [On-Policy Distillation 在线策略蒸馏](<../../03_训练优化与对齐/后训练与对齐/On-Policy Distillation 在线策略蒸馏.md>) | 教师针对学生自己的 rollout 提供软分布或 token-level 指导 | 通常需要教师 logits 或等价的软监督 |
| [RLVR / GRPO](<../../03_训练优化与对齐/后训练与对齐/RLVR 可验证奖励强化学习.md>) | 作为 policy 生成的推理轨迹，接受格式、过程和最终答案 reward | 不一定需要人工 CoT，通常需要 verifier 或 reward |
| RLHF / [DPO](<../../03_训练优化与对齐/后训练与对齐/DPO 直接偏好优化.md>) | 作为 chosen/rejected 回答的一部分，用于偏好对齐 | 可选，偏好数据也可以只比较最终答案 |
| 推理阶段 | 作为 test-time reasoning，增加推理步骤和计算量 | 不涉及训练标签 |

#### 1. Reasoning SFT：CoT 最直接的用途

Reasoning SFT 将普通监督目标：

```text
问题 -> 最终答案
```

扩展为：

```text
问题
  -> 任务分解
  -> 中间推理
  -> 证据或计算过程
  -> 最终答案
```

它主要教模型：

- 如何拆解复杂问题。
- 如何组织多步推理。
- 如何引用中间证据。
- 如何遵循结构化思考格式。
- 如何在推理后输出答案。

典型路线是：

```text
Base Model
  -> Long-CoT / Structured CoT SFT
  -> 学会基本推理格式和过程
```

CoT SFT 的局限是：模型主要是在模仿教师轨迹。它可能学会“像推理一样写文本”，但不一定真正提升最终答案，也可能继承教师的错误、重复和事后合理化。

#### 2. Distillation：用强教师 CoT 教学生

**Response Distillation** 是最常见的 CoT 蒸馏方式：

```text
强教师：
  问题 -> CoT -> 答案

学生：
  学习教师的 response
```

它不要求访问教师内部参数，直接使用教师生成的推理过程和答案即可。

**[On-Policy Distillation 在线策略蒸馏](<../../03_训练优化与对齐/后训练与对齐/On-Policy Distillation 在线策略蒸馏.md>)** 更进一步：

```text
学生先用自己的 policy 生成回答
  -> 教师观察学生当前的错误状态
  -> 教师提供 token-level 分布或软标签
  -> 学生学习如何修正自己的轨迹
```

| 方式 | 学生接触的状态 | 主要特点 |
| --- | --- | --- |
| Off-Policy / Response Distillation | 教师预先生成的轨迹 | 成本较低，但不一定覆盖学生自己的错误 |
| On-Policy Distillation | 学生自己生成的轨迹 | 更贴近学生真实问题，但需要教师 logits 或额外推理成本 |

如果部署时不希望输出完整 CoT，也可以让 CoT 教师帮助生成更可靠的答案，再训练学生只输出最终结论。但这种做法会丢失部分过程监督，不能简单认为“去掉 CoT 文本就等价完成蒸馏”。

#### 3. [RLVR / GRPO](<../../03_训练优化与对齐/后训练与对齐/GRPO 组相对策略优化.md>)：优化模型自己的推理轨迹

在 RLVR 或 GRPO 中，CoT 通常不是固定的人工标签，而是模型当前 policy 生成的 rollout：

```text
同一个 prompt
  -> 模型生成多条 CoT 和答案
  -> verifier / reward model 逐条评分
  -> 强化 reward 更高的轨迹
```

可验证 [Reward](<../../03_训练优化与对齐/后训练与对齐/Reward Model 与 Grader 奖励模型与评分器.md>) 可以评价：

- 最终答案是否正确。
- 中间推理是否满足规则。
- 证据引用是否真实。
- 过程是否自洽。
- 格式是否可解析。
- 是否存在重复、幻觉或 reward hacking。

RL 不一定要求每条训练数据都提供人工 CoT。很多 RLVR 数据只需要：

```text
问题 + 最终答案 + 可验证规则
```

模型自己生成 reasoning，再由数学验证器、代码单测、格式检查器或业务规则 verifier 判断结果。

典型顺序是：

```text
CoT SFT：
  先让模型学会基本推理格式。

GRPO / RLVR：
  再让模型通过 reward 优化自己生成的推理路径。
```

#### 4. RLHF / [DPO](<../../03_训练优化与对齐/后训练与对齐/DPO 直接偏好优化.md>)：可选的偏好对齐信号

CoT 也可以出现在偏好数据中：

```text
chosen：
  推理正确、证据充分、答案正确。

rejected：
  推理错误、存在幻觉、格式错误或答案错误。
```

但 CoT 不是 DPO 或 RLHF 的必要条件：

- DPO 可以只比较最终答案。
- RLHF 可以让 Reward Model 评价完整回答，也可以只评价最终结果。
- 如果 CoT 本身质量不稳定，把它直接放进偏好数据可能会放大噪声。

#### 5. 推理阶段：Test-Time Reasoning

训练完成后，模型还可以在推理阶段生成更长思考：

```text
简单任务：
  直接回答，减少延迟和 token 成本。

复杂任务：
  增加 thinking budget，生成更多中间步骤。
```

这属于推理时计算，不等于 CoT SFT，也不等于 RL。训练阶段决定模型是否具备推理能力，推理阶段决定这次请求投入多少计算预算。

### CoT 后训练的典型完整路线

```text
Base Model
  -> [Reasoning SFT / Long-CoT Cold Start](<../../03_训练优化与对齐/后训练与对齐/SFT 监督微调.md>)
  -> [RLVR / GRPO](<../../03_训练优化与对齐/后训练与对齐/GRPO 组相对策略优化.md>)
  -> Response Distillation 或 On-Policy Distillation
  -> 推理阶段按任务开启不同 thinking budget
```

不是所有项目都需要走完整路线：

```text
CoT SFT 已达到目标：
  可以不做 GRPO。

Reward 无法可靠验证：
  不应直接做 GRPO，应先修 verifier。

线上只需要短答案：
  可以使用 CoT 教师蒸馏答案，或使用 direct/cot 双模式。
```

### CoT 的作用边界

CoT 不是正确性的保证。它可能出现：

- 推理步骤看似合理但实际错误。
- 先猜答案再补理由。
- 过程冗长但没有新增信息。
- 推理文本与最终答案矛盾。
- 生成过程泄露标签或参考答案。

因此在严谨任务中，CoT 应与 [Verifier](<../../03_训练优化与对齐/后训练与对齐/Reward Model 与 Grader 奖励模型与评分器.md>) 结合：

```text
Verifier
  + 规则检查
  + 工具执行
  + 单元测试
  + 检索证据
  + 结果级指标
```

## 面试应对

### CoT 是什么？

回答思路：先定义思维链，再说明它主要用于复杂推理任务。

回答模板：

CoT 是 Chain of Thought，思维链提示。它让模型在给出最终答案前显式生成中间推理步骤，从而提升数学、逻辑、多跳问答和规划类任务的表现。它的核心价值是把复杂问题拆成多个中间判断，降低模型直接跳到答案时出错的概率。但 CoT 不等于真实推理保证，它生成的过程也可能看起来合理但实际错误。

### CoT 为什么可能提升效果？

回答思路：从问题分解、上下文中间状态和自回归生成解释。

回答模板：

大语言模型是自回归生成的，前面生成的 token 会影响后续输出。CoT 通过先生成中间步骤，把隐含推理过程显式放到上下文里，相当于给后续答案提供更多中间状态。对于需要多步计算或多条件判断的问题，这种分解能减少一步到位的错误。但如果模型基础能力不足或前面的推理步骤已经错了，CoT 也会把错误继续传播下去。

### CoT、Zero-shot CoT 和 Self-Consistency 有什么区别？

回答思路：按提示方式和解码策略区分。

回答模板：

普通 CoT 通常会在 prompt 里提供带推理步骤的示例，让模型模仿这种解题格式。Zero-shot CoT 不给示例，只用类似“请一步步思考”的指令激发推理过程。Self-Consistency 是在 CoT 基础上采样多条推理路径，再对最终答案投票或聚合，减少单条推理路径偶然出错的影响。它们的共同目标都是提高复杂推理稳定性，但成本和延迟会比直接回答更高。

### CoT 在模型后训练中主要用在哪些阶段？

回答思路：按 Reasoning SFT、蒸馏、RLVR/GRPO、偏好对齐和推理阶段区分。

回答模板：

CoT 在后训练中最主要用于 Reasoning SFT 和知识蒸馏。Reasoning SFT 把问题、推理过程和答案作为训练目标，让模型学习任务分解、证据引用和结构化推理；Response Distillation 用强教师生成的 CoT 教学生，On-Policy Distillation 则让教师针对学生自己的错误轨迹提供软监督。到了 RLVR 或 GRPO 阶段，CoT 通常是模型自己生成的 rollout，由 verifier 或 reward model 根据最终答案、过程约束、格式和证据质量评分，不一定需要人工 CoT 标签。DPO 或 RLHF 也可以使用带 CoT 的偏好数据，但不是必须。推理阶段的 thinking budget 则属于 test-time reasoning，和训练阶段的 CoT SFT、RL 是不同概念。

### CoT 在生产中有什么注意事项？

回答思路：强调延迟、成本、可控性，以及不一定要暴露完整推理过程。

回答模板：

生产中使用 CoT 要注意成本和可控性。让模型输出完整推理会增加 token 数、延迟和费用，也可能暴露不稳定或不适合展示的中间过程。很多场景可以让模型内部进行分步分析，但最终只输出简洁结论和必要依据。对于高风险任务，还需要把 CoT 和检索证据、工具校验、单元测试或规则检查结合起来，而不是把推理文本本身当成正确性保证。
