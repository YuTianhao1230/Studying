# 实习项目面试问答

## 知识点解析

### 概述

本文整理实习工作相关的面试回答，包括整体项目介绍、[关键帧检测完整训练方案](<关键帧检测/方案与训练流程/关键帧检测完整训练方案.md>)、[D2C 视觉还原度评估](<D2C/视觉还原度评估.md>)、[端模安全评估](<端模安全/安全评估总览.md>)，以及常见深挖问题的回答思路和标准模板。

### 整体工作主线

实习工作可以总结成三条线：

1. 关键帧检测模型训练：把人工关键帧判断标准化、数据化、模型化和线上化。
2. D2C 视觉还原度评估：用 [VLM](<../06_视觉多模态与生成模型/多模态模型/VLM与Vision_Instruction_Tuning.md>) 辅助判断设计稿和代码渲染图的一致性，分析评分波动和准出风险。
3. 端模安全评估：用对抗攻击和海绵攻击主动暴露端侧模型的内容安全、鲁棒性和效率风险。

其中关键帧检测是主项目，最能体现数据治理、模型训练、评测分析和工程上线闭环。

### 项目叙事的统一框架

介绍任意一条业务线时，可以按下面的顺序组织：

```text
业务问题
  -> 判断标准和风险边界
  -> 数据或样本构造
  -> 模型/规则方案
  -> 错误归因
  -> 评测与上线准出
  -> 下一轮反馈
```

这个顺序能把“做了哪些执行动作”提升为“如何建设一套可复用能力”。涉及历史指标时，应同时交代模型版本、数据集和评测口径；口径不确定时，优先回答方法、证据和趋势，不把未经确认的旧数值表述成当前结论。

回答模板：

我在实习期间主要做多模态模型训练和评测相关工作。核心项目是视频关键帧识别能力建设，目标是从移动端操作录屏中自动定位业务指标结束帧，替代部分人工标注。我主要负责 bad case 归因、标注标准沉淀、高优数据飞轮、训练评测和上线联调，最终平均 ACC 从 75.714 提升到 84.876，国际电商 ACC 从 84.093 提升到 95.933，并完成线上接入。除此之外，我还做了 D2C 视觉还原度 VLM 评估和端侧模型安全合规评测，分别沉淀了评分稳定性分析和对抗样本风险评估方法。

### 2 分钟项目介绍版本

回答模板：

我实习期间最核心的项目是视频关键帧识别。这个任务是从移动端操作录屏中找到某个性能指标的结束帧，再换算出耗时。难点不只是视频理解，而是每个 task_type 的完成态标准不同，人工标注本身也有噪声。我的工作首先是做 bad case 归因，把错误分成模型能力问题、GT 标注错误、标注标准冲突和评测口径问题；然后把人工经验沉淀成完成态、排除条件、豁免条件和首选证据，并写入 prompt 和训练数据；接着围绕国际电商等高优业务线做数据飞轮，通过模型筛错、人工重标、回流训练和分桶评测持续提升模型。最终三轮飞轮返修 27000+ 高质量样本，平均 ACC 从 75.714 提升到 84.876，国际电商 ACC 从 84.093 提升到 95.933，并在线上 3 帧误差回测达到 90.05%。

此外，我还做了两类相关工作。D2C 方向是用 VLM 评估设计稿和代码渲染图的视觉还原度，我分析了 layout/text 七个子维度的打分波动，发现通用 VLM 不能直接作为唯一准出标准，需要 rubric、结构化输出和 checker 结合。端模安全评估方向则用 SigLIP2 代理模型做黑盒迁移对抗攻击，并调研海绵攻击，沉淀了 5000+ 对抗样本和攻击参数，用于端模鲁棒性和安全准出评估。

## 面试应对

### 你在关键帧项目里最难的点是什么？

回答思路：不要说训练模型很难，要讲标准、数据和模型能力边界。

回答模板：

最难的点是把人工经验变成模型能学习和评测的标准。关键帧不是简单找页面出现，而是不同 task_type 有不同完成态，比如购物车加购要看角标数字变化，商详页加载要等头图、价格和营销 Banner 都清晰完整。人工标注里也会有噪声和前后标准不一致，所以我先做 bad case 归因，区分模型错、GT 错和标准冲突，再把完成态、排除条件、豁免条件和首选证据沉淀到 prompt 和训练数据里，最后用高优数据飞轮回流训练。

### 你怎么证明项目真的有效？

回答思路：用离线指标、分桶、线上回测和业务收益串起来。

回答模板：

我不是只看一次平均指标，而是从离线、分桶和线上三层验证。离线看平均 ACC 和国际电商等高优业务线 ACC，模型从 Base1 的平均 75.714、国际电商 84.093 提升到 Base6 的平均 84.876、国际电商 95.933。分桶上看不同 task_type、业务线和 bad case 类型，判断提升来自标准沉淀、数据飞轮还是模型能力。线上看 3 帧误差回测，国际电商平均达到 90.05%，并带来 19% 标注成本下降和 9.5% 提效贡献。

### 如果继续做，你会怎么优化关键帧模型？

回答思路：从数据、模型、推理和训练范式回答。

回答模板：

我会从四个方向继续做。第一是长尾指标治理，对训练量为 0、低于 500、低于 900 的指标分层补采和重采样。第二是更强多模态基座，重点验证 UI 小元素、边界帧和结构化输出稳定性。第三是 global-to-local 推理，先低 FPS 粗定位候选窗口，再用 30 FPS 精筛，减少边界帧漏检。第四是训练范式升级，先 Direct [SFT](<../03_训练优化与对齐/后训练与对齐/SFT 监督微调.md>) 保证基础判断，再用少量结构化 CoT 学会证据引用，最后用 `R_time + R_format + R_boundary_evidence - P_length` 做 RL，让模型不仅答对帧，还能给出可验证证据。

### D2C 评估这部分怎么讲？

回答思路：讲它是评测方法建设，不是模型训练主线。

回答模板：

D2C 这部分我主要做的是视觉还原度评估方法分析。输入是 Figma 设计图和 D2C 渲染图，输出是 layout 和 text 维度的还原度评分。我把评分拆成布局一致性、元素对齐、比例、视觉协调性、字体、文本内容、数字特殊字符等子项，并对线上短 prompt、线上完整 prompt、离线 gpt-5.5 和 gpt-5.4 做重复评分对比。结论是 VLM 能辅助发现视觉差异，但单次打分波动较大，不能作为唯一准出标准，需要更精细 rubric、结构化 JSON 输出和像素/OCR/checker 结合。

### 端模安全评估这部分怎么讲？

回答思路：从风险暴露和评测资产沉淀回答。

回答模板：

端模安全评估的目标是主动暴露端侧模型在内容安全、对抗鲁棒性和推理效率上的风险。我用 SigLIP2 作为代理模型做[黑盒迁移攻击](<../13_AI安全与对抗攻击/迁移与通用攻击/黑盒迁移攻击.md>)，构造政敏人物到动物目标类的定向攻击样本，在 eps=8、16、24 等扰动预算下评估端模输出变化。实验显示端模原始样本准确率约 76.35%，攻击场景下降到 31.35% 及以下，并沉淀了 5000+ 对抗样本。另一个方向是海绵攻击，目标不是让模型答错，而是增加推理开销；我尝试注意力密集化、稀疏激活惩罚、多尺度和频域攻击等方法，当前注意力密集化加稀疏激活惩罚效果最好。

### 如果面试官质疑“你只是调 prompt 和整理数据”，怎么回答？

回答思路：把 prompt/数据整理上升到任务标准化和训练信号治理。

回答模板：

我会承认 prompt 和数据是重要抓手，但这个项目不是简单调 prompt。关键帧任务的核心难点是业务完成态没有被模型理解，人工 GT 也存在噪声。如果不先把标准沉淀清楚，继续训练只会把错误边界放大。我的工作是把人工判断过程拆成完成态、排除条件、豁免条件和证据优先级，再通过 bad case 归因判断哪些是模型能力问题、哪些是标注问题，最后把高价值样本回流训练并用分桶指标验证。这其实是训练信号治理和业务准出体系建设。

### 如果发现 GT 也有错，你怎么保证训练不会学坏？

回答思路：强调先归因再回流。

回答模板：

我不会把所有模型预测和 GT 不一致的样本都直接当作模型错误。关键帧任务里 GT 本身可能有噪声，所以我会先回看预测帧、GT 帧和前后若干帧，再按 task_type 标准判断哪一帧才是真正首个完成态。如果确认 GT 错，就进入 relabel，而不是回流原标签；如果是标准不清，就先和业务对齐完成态、排除条件和豁免条件；只有确认是模型能力问题，才把样本作为高价值 bad case 回流训练。这样可以避免把脏标签和冲突标准喂给模型。

### 如果历史指标可能已经过期，你会怎么回答？

回答思路：先限定版本和口径，再回答可复核的方法。

回答模板：

我会先说明这个结果对应的模型版本、数据集和评测口径，确认它是过程中的历史结果，还是当前线上结论。如果当前口径无法确认，我不会直接引用旧数值，而会说明当时通过固定回归集、业务线分桶、bad case 归因和线上回测来验证优化是否有效。这样既保留实验结论，也避免把不同版本或不同评测口径的数字混在一起。

### UI 小元素识别不准，你会怎么优化？

回答思路：从数据、模型输入和结构化证据回答。

回答模板：

UI 小元素问题不能只靠一句 prompt 解决。我会先把小元素类型拆出来，比如购物车角标、营销 Banner、折扣标签、边缘商品图和 SKU 状态；然后沉淀专项样本，让模型把元素名称和视觉区域对齐；推理上可以做 global-to-local，先粗定位候选窗口，再对关键区域或高分辨率帧精筛；输出上要求模型给出区域证据，例如哪个位置的数字变化或哪个 Banner 完整加载。这样能把“看不清”和“不知道该看什么”两个问题分开处理。

### CoT 蒸馏为什么不能直接全量上？

回答思路：讲收益和风险，给分阶段方案。

回答模板：

CoT 对关键帧任务有价值，因为它能让模型输出候选窗口、时间证据、空间证据和 UI 状态，方便排查。但我不会直接全量上长 CoT，因为长输出会增加训练和推理成本，也可能出现事后合理化、GT 泄漏和证据不真实的问题。更稳的方案是先 Direct SFT 保证帧定位能力，再用少量高质量结构化 CoT 做蒸馏，最后用 RL 或 [GRPO](<../03_训练优化与对齐/后训练与对齐/GRPO 组相对策略优化.md>) 优化时间准确、格式合法、证据正确和输出长度。

### 如果搜索系很多能力不支持，你怎么推进？

回答思路：区分能力不支持和数据未跑通。

回答模板：

我会先把问题拆成能力不支持和数据未跑通两类。能力不支持通常是 keyframe_type 没有注册或没有对应标准，需要补 mapping、补标注标准和补训练样本；数据未跑通可能是图片 URL 不可下载、样本链路问题或执行失败，不应该算成模型能力不支持。搜索系不支持能力较多时，我会优先按业务价值和样本规模排序，先补核心指标的 task_type 标准和数据，再接入评测回归，避免一次性铺开导致标准和数据质量失控。
