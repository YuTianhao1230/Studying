# 并行 DE 与 PE

## 知识点解析

### 概述

本文整理关键帧检测项目中的并行 DE 与 PE 思路。DE 指数据侧治理，PE 指 prompt 与规则表达侧治理。并行 DE、PE 的核心是让数据飞轮和 prompt/标注标准迭代互相反馈，而不是串行地先堆数据再调 prompt。

### DE 是什么

在关键帧检测项目语境里，DE 可以理解为 Data Engineering 或 Data Engine，核心是数据侧工作。

DE 关注：

- 数据采集和样本覆盖。
- GT 标注质量。
- bad case 筛选和归因。
- CQC 人工复查和 relabel。
- 数据飞轮回流。
- 训练集、测试集和评测集版本管理。
- 高优业务线和长尾指标采样。

一句话：DE 解决“模型应该从什么样的数据里学，数据是否干净、覆盖是否足够、训练信号是否正确”。

### PE 是什么

PE 可以理解为 Prompt Engineering，核心是 prompt、规则和输出格式侧工作。

PE 关注：

- task_type 任务描述。
- 完成态标准。
- 排除条件。
- 豁免条件。
- 证据优先级。
- 输出格式约束。
- [CoT](<../../../02_大模型/应用与问题/CoT.md>) 或结构化推理格式。
- few-shot 示例和反例。

一句话：PE 解决“模型在推理时应该按什么规则看视频、怎么判断完成态、怎么稳定输出结果”。

### 为什么要并行

关键帧检测不是纯数据量驱动，也不是纯 prompt 驱动。

如果只做 DE：

- 数据量变多，但标准冲突和脏 GT 可能被继续放大。
- 模型可能学到人工标注中的不一致边界。
- 对新 task_type 的规则仍然不清楚。

如果只做 PE：

- prompt 写得再清楚，模型没见过足够多的小元素、角标、营销 Banner 和边界帧，也难以稳定识别。
- prompt 暴露出的失败模式没有进入训练数据，能力不会真正沉淀。

因此需要并行：

```text
PE 暴露规则理解问题
  -> DE 收集对应 bad case 和高价值样本
  -> 数据回流训练
  -> 新模型评测暴露新错误
  -> PE 修正规则、排除条件和输出格式
```

### 在关键帧检测中的具体例子

购物车加购耗时：

- PE：明确“购物车角标数字实质增加”是首选证据，只有角标被遮挡时才看“加购成功”文案。
- DE：筛出模型没看角标、误等弹窗升起、GT 标到稳定后帧的 bad case，人工重标后回流训练。

商详页加载耗时：

- PE：明确头图、价格、营销 Banner、折扣标签等是否必须完整加载。
- DE：收集营销 Banner 未加载、小面积 UI 元素漏看、边缘小图漏看的样本，做专项治理。

头图滑动耗时：

- PE：明确只取第一次滑动完成、头图居中高清定型的帧。
- DE：筛出模型跳过第一次滑动、抢跑到两图交界、等待第二次滑动的样本。

### 并行 DE、PE 的闭环

| 阶段 | DE 做什么 | PE 做什么 |
| --- | --- | --- |
| 问题发现 | 统计 bad case、分 task_type 和业务线归因 | 检查 prompt 是否表达了对应规则 |
| 标准沉淀 | 人工复查 GT，确认 relabel 和标准冲突 | 更新完成态、排除条件、豁免条件 |
| 数据回流 | 返修高优样本，构造专项训练集 | 将标准写入训练样本或 few-shot |
| 模型评测 | 看全量、业务线、task_type、bad case 类型变化 | 看输出是否遵守格式和证据优先级 |
| 下一轮迭代 | 选择新的高价值样本 | 修正 prompt 和结构化输出约束 |

### 和数据飞轮的关系

[数据飞轮](<数据飞轮与主动学习.md>)更偏 DE，但如果没有 PE，数据飞轮只能发现“错了”，不能稳定解释“为什么错、标准是什么”。

并行 DE、PE 可以让数据飞轮更有方向：

- PE 定义什么是正确完成态。
- DE 找出哪些样本违反或挑战这个定义。
- PE 根据样本修正规则边界。
- DE 将修正后的样本回流训练。

### 和 CoT/RL 的关系

结构化 CoT 和 RL 可以看成 PE 的进一步工程化：

- [CoT](<../../../02_大模型/应用与问题/CoT.md>) 格式定义模型应输出哪些证据。
- [Reward](<../../../03_训练优化与对齐/后训练与对齐/Reward Model 与 Grader 奖励模型与评分器.md>) 定义哪些输出是可验证、可奖励的。
- DE 提供高质量 CoT 蒸馏样本和错误样本。

例如：

```text
R = R_time + R_format + R_boundary_evidence - P_length
```

这里 `R_boundary_evidence` 本质上依赖 PE 定义的证据标准，也依赖 DE 提供的可靠标注和验证数据。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 概念题 | 并行 DE、PE 是什么 | DE 管数据质量和覆盖，PE 管规则表达和推理约束 |
| 项目题 | 为什么关键帧要并行做 | 任务既有数据噪声，也有业务规则理解问题 |
| 质疑题 | 这是不是只是调 prompt | 说明 prompt 只是规则载体，最终还要通过数据飞轮沉淀到模型能力 |
| 质疑题 | 这是不是只是清洗数据 | 说明没有 PE，清洗不知道按什么标准清 |
| 方法题 | 并行闭环怎么跑 | bad case -> 标准修正 -> relabel -> 训练 -> 分桶评测 |

### 易错点

- 把 DE 说成单纯补数据。
- 把 PE 说成单纯调话术。
- DE 和 PE 各做各的，没有互相反馈。
- prompt 更新后不回流训练，能力无法沉淀。
- 数据回流前不确认标注标准，容易把脏 GT 训练进去。

## 面试应对

### 并行 DE、PE 是什么？

回答思路：先解释缩写，再讲为什么要并行。

回答模板：

在关键帧项目里，我理解的 DE 是数据侧治理，PE 是 prompt 和规则表达侧治理。DE 负责采集数据、筛 bad case、修 GT、做人工重标、数据飞轮和训练集版本管理；PE 负责把 task_type 的完成态、排除条件、豁免条件、证据优先级和输出格式表达清楚。之所以要并行，是因为关键帧检测既有数据噪声和长尾覆盖问题，也有业务规则理解问题。prompt 暴露出的失败模式会进入数据飞轮，数据归因出的标准冲突也会反向修正 prompt 和标注规则。

### 为什么不能只做 DE？

回答思路：强调标准不清会放大脏标签。

回答模板：

只做 DE 容易变成单纯堆数据。如果标注标准没有被定义清楚，模型会把人工标注里的不一致边界一起学进去。例如购物车加购到底看角标数字变化，还是看“加购成功”文案，必须先通过 PE 把规则和优先级写清楚。DE 负责把符合这个标准的高质量样本回流训练，PE 负责定义什么叫符合标准。两者分开做，训练信号就不稳定。

### 为什么不能只做 PE？

回答思路：强调模型能力需要数据沉淀。

回答模板：

只做 PE 也不够。Prompt 可以告诉模型要看购物车角标、营销 Banner 或边缘小图，但如果训练数据里缺少这些小元素和边界帧样本，模型还是可能看不到或看不准。PE 能让模型知道该看什么，DE 才能让模型通过足够多的高质量样本学会怎么看。因此 prompt 修改后，还需要把对应 bad case 进入数据飞轮，通过人工重标和训练回流沉淀成模型能力。

### 面试官质疑“你就是调 prompt 和洗数据”，怎么回答？

回答思路：把工作提升到任务标准化和训练信号治理。

回答模板：

我会承认 prompt 和数据是重要抓手，但这个项目不是简单调 prompt 或洗数据。关键帧检测的本质是把人工业务判断标准转成模型可学习、可评测、可上线的能力。PE 负责把完成态、排除条件、豁免条件和证据优先级明确下来，DE 负责用 bad case 归因、GT 修正和数据飞轮把这些标准变成高质量训练信号。最后还要通过分桶评测和线上回测验证模型是否真正学会，而不是只看 prompt 改了或者数据变多了。
