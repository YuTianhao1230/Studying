# 关键帧检测：任务定义与标注标准

## 知识点解析

### 概述

本文整理关键帧检测任务的业务定义、完成态标准、排除条件、豁免条件、证据优先级和常见标注冲突，用于回答“这个任务到底难在哪里”和“标准如何沉淀成模型可学习信号”。

### 任务定义

关键帧检测的输入是一段移动端操作录屏和一个性能指标 `task_type`，输出是该指标对应的结束帧。结束帧不是视觉上“页面差不多出现”的帧，而是符合业务定义的首个完成态帧。

```text
输入：视频帧序列 + task_type + 起始帧/候选范围
输出：结束帧 index / timestamp + 判断依据
下游：耗时 = 结束帧时间 - 起始帧时间
```

因此，这个任务同时包含：

- 视频时间定位。
- UI 元素识别。
- 业务规则理解。
- 边界帧判断。
- 标注标准一致性控制。

### 为什么不是普通视频理解

普通视频理解通常问“发生了什么”，关键帧检测问“在第几帧第一次满足某个业务完成态”。这要求模型做更细粒度的时序判断。

典型难点：

- 同一个页面出现不等于页面加载完成。
- 动效结束、主体清晰、营销组件加载完成的优先级因指标而异。
- 有些局部异步变化应豁免，有些小元素变化必须等待。
- 低 FPS 抽帧可能漏掉“刚出现”的第一帧。

### 标注标准的结构

一条好的标注标准应该包含：

| 组成 | 作用 | 示例 |
| --- | --- | --- |
| 任务目标 | 明确要找哪个指标的结束帧 | 定位购物车加购耗时结束帧 |
| 必决条件 | 必须同时满足的完成态 | 头图清晰、价格出现、Banner 完整 |
| 排除条件 | 触犯即不能选 | loading、骨架屏、残影、错位、白膜 |
| 豁免条件 | 不影响完成态的变化 | 局部异步、购物车数字跳动、视频是否播放 |
| 证据优先级 | 多个信号冲突时怎么选 | 角标数字变化优先于成功文案 |
| 防抢跑规则 | 防止模型提前截帧 | 仅动画开始或大致到位不算结束 |
| 防跳过规则 | 防止模型跳到后续事件 | 只捕获第一次滑动完成帧 |

### 典型 task_type 标准

| task_type | 完成态 | 排除条件 | 豁免条件 |
| --- | --- | --- | --- |
| 商详页加载耗时 | 头图、价格、营销 Banner 和折扣标签清晰完整，页面停稳 | 占位、loading、残影、旧页面遮挡、内容截断 | 头图视频是否播放、购物车数字跳动、搜索框文字局部加载 |
| 购物车加购耗时 | 购物车角标数字实质增加；若角标被遮挡，看“加购成功”文案首次出现 | 仅飞入动效、按钮形变、数字未更新 | 弹窗完整升起、推荐商品继续加载 |
| 商详页头图滑动耗时 | 第一次滑动完成，头图居中且高清定型 | 两图交界、左右偏移、主体模糊、占位图 | 头图视频/GIF 播放状态、测试遮罩 |
| SKU 面板加载耗时 | 面板核心商品、规格、价格和按钮可见且可交互 | 面板未完全出现、核心规格缺失、价格占位 | 推荐商品、非核心区域异步加载 |

### 标准冲突如何处理

同一个 UI 元素在不同指标中可能有不同规则。例如购物车数字：

- 在“购物车加购耗时”中，角标数字变化是首选证据。
- 在“商详页加载耗时”中，购物车数字跳动可能是豁免项。

这说明标准不能写成通用一句话，而要和 `task_type` 强绑定。否则模型会学习到混乱边界。

### 标准如何进入模型

标准沉淀后有三种使用方式：

1. [Prompt](<../../../02_大模型/应用与问题/Prompt调优.md>) 注入：推理时把完成态、排除条件、豁免条件写清楚。
2. 训练数据重构：把标准和样本绑定，训练模型按指标判断。
3. 结构化 [CoT](<../../../02_大模型/应用与问题/CoT.md>)：让模型输出时间证据、空间证据、UI 状态和最终帧。

[Prompt](<../../../02_大模型/应用与问题/Prompt调优.md>) 优化不是简单“写得更长”，而是把人工标注经验转成模型可执行的判断准则。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 任务定义 | 关键帧检测和视频分类区别 | 强调首个完成态帧、业务规则和时间边界 |
| 标准问题 | 为什么人工标注不稳定 | task_type 完成态不同，排除/豁免规则不清 |
| Prompt 追问 | prompt 优化为什么有效 | 它注入业务先验，不只是调话术 |
| 数据追问 | 标准如何转成训练数据 | task_type 与完成态、证据、边界规则绑定 |

### 易错点

- 把结束帧理解成页面大致出现。
- 不区分“出现”“停稳”“完全加载”“首帧”。
- 将一个指标的豁免规则套到另一个指标。
- 只给模型看视频，不提供 task_type 标准。

## 面试应对

### 关键帧检测任务最核心的定义是什么？

回答思路：突出 task_type 绑定的首个完成态帧。

回答模板：

关键帧检测不是普通视频分类，而是给定操作录屏和性能指标 task_type，找到该指标业务定义下首个满足完成态的结束帧。不同指标的完成态不同，例如购物车加购优先看购物车角标数字变化，商详页加载要等头图、价格和营销 Banner 清晰完整，头图滑动要找第一次滑动停稳居中的帧。所以这个任务的核心是把人工标注经验沉淀成完成态、排除条件、豁免条件和证据优先级，再让模型按这些标准做时间边界判断。
