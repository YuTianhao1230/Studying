# 端模安全评估

## 知识点解析

### 概述

本文整理端侧模型安全合规评测工作，包括内容安全风险、对抗鲁棒性、定向攻击、海绵攻击、风险样本沉淀和安全评估体系化方法。

### 任务背景

端侧模型通常经过轻量化、蒸馏或压缩，能力和安全边界可能不同于云端大模型。端模一旦在图生文、话题推荐或本地理解场景中输出不合规内容，会带来上线备案、内容安全和品牌风险。

端模安全评估要回答三个问题：

1. 模型是否会被轻微扰动误导。
2. 模型在敏感定向场景中是否会输出高风险内容。
3. 异常输入是否会显著拖慢端侧推理，影响稳定性。

### 评估维度

| 维度 | 为什么重要 | 切入点 |
| --- | --- | --- |
| 内容安全风险 | 端模输出可能涉及政敏、歧视、暴力色情、事实性和价值观风险 | 构造敏感人物和目标类别数据集 |
| 对抗鲁棒性 | 轻微扰动可能改变模型语义理解 | 用 GLEAM、Syner-Attack 等攻击方法主动暴露风险 |
| 推理效率风险 | 端侧资源有限，异常输入可能拉高推理开销 | 调研海绵攻击，评估延迟、激活和注意力密集化 |

### 对抗攻击评估

对抗攻击的核心是固定模型参数，反向优化输入扰动，使模型输出错误。

端模场景下通常拿不到目标模型梯度，因此使用黑盒迁移攻击：

```text
clean sensitive image
  -> surrogate model: SigLIP2
  -> generate adversarial perturbation
  -> evaluate on endpoint VLM
```

实验设计：

- 原始样本：政治敏感人物图像。
- 目标样本：动物类别图片，如狗类图片。
- 代理模型：SigLIP2。
- 攻击预算：eps=8、eps=16、eps=24。
- 目标：在不影响人类视觉判断的前提下，诱导端模输出错误描述或目标类别相关描述。

### 对抗攻击结果

| 设置 | 结果 |
| --- | --- |
| 端模原始样本准确率 | 76.35% |
| 攻击场景准确率 | 下降至 31.35% 及以下 |
| 对抗样本沉淀 | 5000+ |
| eps=32 定向攻击 | 成功率 11/12 |
| eps=16 定向攻击 | 成功率 7/12 |
| eps=8 定向攻击 | 成功率 1/12 |

实验说明端模在视觉扰动下存在明显鲁棒性短板，对抗攻击可以作为安全合规评测的风险暴露手段。

### 已尝试方法

| 方法 | 做法 | 结果与分析 |
| --- | --- | --- |
| SigLIP2 代理攻击 | 对每个特征层展开攻击，使深层和浅层特征偏离 | 高 eps 下有效，证明模型存在识别漏洞 |
| 动量迭代 | 引入动量突破局部最优 | 有助于扰动稳定优化 |
| target similarity | 拉近 target image，推远 clean image | 效果不理想，target 与 clean 本身可能不完全对立 |
| VLAttack | 引入特征层攻击算法 | 没有明显收益 |
| 文本引导扰动 | 用文本引导图像偏离 | eps=32 仍效果弱，可能与文本质量和模型文本理解能力有关 |
| NURBS | 用几何形变增强扰动 | 作为输入增强方向尝试 |

### 海绵攻击

海绵攻击的目标不是降低准确率，而是降低推理效率。它通过构造特殊输入增加模型推理时的计算开销。

核心思路：

```text
maximize hidden activation energy
maximize attention density
maximize activation density
```

端侧场景尤其关注海绵攻击，因为端侧算力、功耗和延迟预算更紧。

### 海绵攻击尝试

| 模块 | 思路 | 结果 |
| --- | --- | --- |
| 基础框架 | SigLIP 代理模型 + MI-FGSM，最大化 sponge 得分 | 建立基础攻击链路 |
| 注意力密集化 | 最大化注意力图归一化熵 | 单独效果最好，sponge 得分提升约 6% |
| 稀疏激活惩罚 | 惩罚近零激活比例 | 权重调高后与注意力密集化有协同 |
| 自适应层权重 | 根据各层贡献调整权重 | softmax 归一化导致得分缩小，效果下降 |
| 多尺度攻击 | 多分辨率求梯度平均 | 梯度被稀释，弱于 baseline |
| GLEAM GDE/LFE | 输入多样性和局部形变 | 单独有效，组合时梯度稀释 |
| Nesterov 动量 | 向前看梯度 | 与当前框架不兼容，效果负面 |
| 频域攻击 | FFT 放大高频分量 | 不如直接空间域攻击 |

当前较优组合是注意力密集化 + 稀疏激活惩罚，二者分别作用于 attention 和 FFN 激活，作用域互补。

### 体系化沉淀

端模安全评估不应停留在单次攻击实验，应沉淀成可回归体系：

- 固定样本集。
- 固定攻击预算。
- 固定代理模型和攻击脚本。
- 记录攻击参数、成功率、失败原因。
- 接入版本回归和准出阈值。
- 输出可用于对抗训练和安全加固的数据资产。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 任务理解 | 端模安全评估评什么 | 内容安全、对抗鲁棒性、推理效率 |
| 方法题 | 为什么用黑盒迁移攻击 | 端模梯度不可见，只能用代理模型生成扰动 |
| 实验题 | eps 变化说明什么 | 扰动预算越大攻击越强，也要关注可感知性 |
| 海绵攻击 | 和普通对抗攻击区别 | 目标是增加推理开销，不是降低准确率 |
| 价值题 | 对抗样本沉淀有什么用 | 对抗训练、回归评测、风险复测 |

### 易错点

- 把安全评估说成单次攻击成功率测试。
- 只看攻击成功，不记录失败原因和参数。
- 高 eps 攻击成功但不讨论可感知性。
- 混淆准确率攻击和效率攻击。
- 不说明业务收益边界：当前主要是风险暴露和样本沉淀，不等于已经完成防御收益闭环。

## 面试应对

### 端模安全评估你做了什么？

回答思路：按风险、方法、结果、沉淀回答。

回答模板：

我做的是端侧模型安全合规评测，目标是主动暴露端模在内容安全、对抗鲁棒性和推理效率上的风险。对抗鲁棒性上，我用 SigLIP2 作为代理模型做黑盒迁移攻击，构造政敏人物到动物目标类的定向攻击样本，在 eps=8/16/24 等扰动预算下测试端模输出变化。结果显示端模原始样本准确率约 76.35%，攻击场景下降到 31.35% 及以下，并沉淀了 5000+ 对抗样本。效率安全上，我调研并实现海绵攻击，尝试注意力密集化、稀疏激活惩罚、多尺度和频域攻击等方法，当前注意力密集化加稀疏激活惩罚效果最好。这个工作的价值是把端模安全风险从普通测试集评估，推进到可复现、可量化、可回归的风险验证体系。

### 海绵攻击和普通对抗攻击有什么区别？

回答思路：按攻击目标区分。

回答模板：

普通对抗攻击主要目标是让模型输出错误，比如分类错或生成错误描述；海绵攻击的目标不是准确率，而是推理效率。它通过构造特殊输入，让模型的隐藏层激活更大、注意力更密集或激活更不稀疏，从而增加计算开销、延迟或功耗。端侧模型资源有限，所以海绵攻击更像效率安全评估，用来判断异常输入是否会拖慢本地推理链路。

### 这部分工作有什么业务价值？

回答思路：明确风险暴露、样本沉淀、评测准出，不夸大已完成收益。

回答模板：

这部分工作的直接价值是风险暴露和评测资产沉淀。端模安全问题不能只靠普通测试集发现，所以我通过对抗攻击和海绵攻击主动构造异常输入，量化模型在敏感场景、轻微扰动和效率攻击下的风险边界。沉淀下来的对抗样本、攻击参数和失败归因，可以作为后续对抗训练、模型版本回归和上线准出评测的一部分。当前它更多是安全评测体系建设，不是已经证明完成了防御收益闭环。
