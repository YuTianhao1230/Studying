# 端模安全：对抗与海绵攻击实验复盘

## 知识点解析

### 概述

本文整理[端模安全评估](<安全评估总览.md>)中的对抗攻击和海绵攻击实验复盘，重点说明威胁模型、代理模型选择、攻击目标、实验结果、失败尝试、指标口径和后续安全评测体系。

### 威胁模型

端模安全评估中的威胁模型可以拆成两类：

| 类型 | 攻击者能力 | 攻击目标 |
| --- | --- | --- |
| 黑盒迁移对抗攻击 | 不访问目标端模梯度，用代理模型生成扰动 | 让端模识别或生成错误内容 |
| 海绵攻击 | 构造异常输入，诱导模型计算更密集 | 增加推理延迟、功耗或资源占用 |

两类攻击关注点不同。前者是语义安全和鲁棒性，后者是效率安全和稳定性。

### 为什么选择代理模型

端侧模型通常不可直接获取梯度，且真实线上系统不适合做高频白盒攻击。因此使用 SigLIP2 等视觉语言代理模型生成扰动，再迁移到目标端模。

代理模型选择依据：

- 和目标端模共享相似视觉表征。
- 支持图文对齐或图像特征提取。
- 可本地访问梯度。
- 计算成本可控。

### 对抗攻击实验设计

```text
clean image: 敏感人物图像
target image/text: 动物类别或目标语义
surrogate: SigLIP2
attack: iterative feature / similarity attack
budget: eps = 8 / 16 / 24 / 32
evaluation: endpoint VLM output / accuracy / target ASR
```

核心不是让图片肉眼明显变成动物，而是在视觉基本保持的情况下，让端模输出偏离原始敏感人物语义或靠近目标类别。

### 结果解读

| 观察 | 说明 |
| --- | --- |
| 原始样本准确率约 76.35% | clean 侧本身仍有错误，ASR 统计要过滤原本错误样本 |
| 攻击后准确率降到 31.35% 及以下 | 端模存在明显对抗脆弱性 |
| eps=32 定向攻击 11/12 成功 | 高预算下攻击很强，但要讨论可感知性 |
| eps=16 定向攻击 7/12 成功 | 中等预算已有明显风险 |
| eps=8 定向攻击 1/12 成功 | 小预算定向攻击仍较难 |
| 沉淀 5000+ 对抗样本 | 可用于回归评测和后续鲁棒训练 |

### 失败尝试怎么讲

失败尝试不是负资产，能体现实验判断。

| 尝试 | 现象 | 可能原因 |
| --- | --- | --- |
| target similarity | 效果不理想 | target image 和 clean image 未必语义对立，优化方向不够明确 |
| VLAttack | 没有明显收益 | 方法假设与当前端模/代理模型不完全匹配 |
| 文本引导扰动 | eps=32 仍弱 | 文本 prompt 质量、图文对齐强度或目标类别选择受限 |
| 多尺度海绵攻击 | 弱于 baseline | 多尺度梯度平均可能稀释有效攻击方向 |
| 频域攻击 | 不如空间域 | 端模效率瓶颈不一定主要受高频分量影响 |
| Nesterov 动量 | 负面 | 和当前 [MI-FGSM](<../../13_AI安全与对抗攻击/视觉攻击方法/MI-FGSM.md>) 框架或目标函数不匹配 |

面试中可以主动说出这些失败尝试，说明你不是只跑成功实验，而是在做方法归因。

### 海绵攻击指标

海绵攻击需要区别于准确率攻击，指标应关注：

- 推理延迟增加。
- attention density。
- hidden activation energy。
- activation sparsity。
- 峰值内存。
- 端侧功耗或温升。
- timeout / crash 比例。

当前较有效组合是：

```text
attention densification + sparse activation penalty
```

前者让注意力分布更密集，后者减少近零激活比例，二者分别影响 attention 和 FFN 路径。

### 如何进入安全评测体系

实验结果要沉淀成资产：

1. 样本资产：clean image、adversarial image、target、eps、attack config。
2. 脚本资产：固定代理模型、固定攻击参数、可复现命令。
3. 指标资产：clean accuracy、attack accuracy、ASR、latency increase。
4. 回归资产：每个端模版本都跑同一批安全集。
5. 准出资产：定义高风险阈值和人工复核策略。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 威胁模型 | 你假设攻击者知道什么 | 黑盒端模，白盒代理模型，预算受限 |
| 代理模型 | 为什么用 SigLIP2 | 可访问梯度，视觉语言表征接近目标端模 |
| 失败实验 | 方法没效果怎么办 | 分析目标函数、预算、代理匹配和梯度质量 |
| 安全体系 | 实验结果怎么落地 | 样本集、脚本、指标、回归、准出 |
| 海绵攻击 | 为什么算安全问题 | 影响延迟、功耗和稳定性，不只是准确率 |

### 易错点

- 不说明 clean 原本错误样本如何处理。
- 高 eps 成功但不讲人眼可感知性。
- 把代理模型攻击成功等同于目标端模攻击成功。
- 海绵攻击只报告 loss，不报告真实延迟或资源指标。
- 安全评估只做一次，不沉淀回归集。

## 面试应对

### 端模对抗攻击实验怎么设计才公平？

回答思路：按威胁模型、预算、样本过滤和目标评估回答。

回答模板：

我会先明确威胁模型：目标端模是黑盒，不访问梯度，只用 SigLIP2 这类代理模型生成扰动。然后固定扰动预算，比如 eps=8、16、24、32，并说明像素范围和可感知性。统计 ASR 时要过滤 clean 下原本失败的样本，避免把模型本来就错的 case 算成攻击成功。最后在目标端模上看输出是否偏离原始语义或靠近目标类别，并记录攻击参数、失败原因和样本，用于后续版本回归。

### 海绵攻击结果怎么评价？

回答思路：强调它不是准确率，而是效率指标。

回答模板：

海绵攻击不能只看分类或生成是否错误，因为它的目标是拖慢模型推理。我会关注端侧真实延迟、峰值内存、功耗、timeout，以及模型内部的 attention density、hidden activation energy 和 activation sparsity。当前实验里，注意力密集化单独能提升 sponge 得分，和稀疏激活惩罚组合后更有效，说明攻击同时影响 attention 和 FFN 激活路径。但最终是否有业务风险，还要用端侧真实延迟和资源指标验证。
