# D2C 视觉还原度评估

## 知识点解析

### 概述

本文整理 D2C 场景下用 [VLM](<../../06_视觉多模态与生成模型/多模态模型/VLM与Vision_Instruction_Tuning.md>) 评估设计稿与代码渲染图视觉还原度的工作，包括任务定义、评分维度、实验设置、波动归因、模型局限和优化方向。

### D2C 是什么

D2C 通常指 Design to Code，即从设计稿自动生成前端代码。在移动端或 Lynx 场景中，D2C 的关键不只是代码能运行，还要看生成页面和 Figma 设计稿在视觉上是否足够一致。

评估对象可以抽象为：

```text
target design: Figma screenshot
generated page: D2C rendered screenshot
task: judge visual restoration quality
```

这个任务本质是视觉还原度评估，需要同时看布局、对齐、比例、文字和数字细节。

### 解决的问题

D2C 视觉评估要解决三个问题：

1. 人工评估成本高，难以对大量 case 做稳定复核。
2. 单纯像素级指标无法完整表达 UI 语义差异。
3. 通用 VLM 可以做视觉判断，但评分稳定性、粒度和业务标准对齐不足。

因此，需要把 VLM 作为评估辅助能力，而不是直接把 VLM 单次打分当成最终准出标准。

### 评估输入与输出

输入：

- Figma 目标图。
- D2C 渲染图。
- 评分 rubric。
- 需要比较的 UI 维度。

输出：

- Layout 子项评分。
- Text 子项评分。
- 总分或百分制分数。
- 差异解释。
- 结构化结果，便于后续聚合和回归。

### 评分维度

工作中使用的评分维度可分为 Layout 和 Text 两类。

Layout 满分 16 分：

| 维度 | 含义 |
| --- | --- |
| 布局一致性 | 头部、底部、侧边栏和主体区域是否出现在匹配位置。 |
| 元素对齐 | 图片、按钮、输入框和文本区域的对齐方式是否一致。 |
| 比例准确性 | 元素尺寸、宽高比、间距和整体比例是否接近。 |
| 视觉协调性 | 页面视觉平衡、密度和整体协调感是否接近。 |

Text 满分 12 分：

| 维度 | 含义 |
| --- | --- |
| 字体特征一致性 | 字体类型、字号、样式、字重和文本视觉效果是否一致。 |
| 文本内容匹配 | 可见文案、段落、按钮文字和标签是否一致，是否缺失、多出或截断。 |
| 数字与特殊字符准确性 | 日期、金额、数字、邮箱、符号和标点是否准确匹配。 |

总分可以从 28 分制换算为百分制，但这会带来分值粒度和波动放大的问题。

### 实验设置

核心实验设置：

| 项目 | 配置 |
| --- | --- |
| 样本 | 100 组 Figma 图和 D2C 渲染图 |
| 单组样例 | `figma1.png` vs `pre1.jpeg` |
| 图像尺寸 | 750 x 1020 |
| 调用方式 | 线上短 prompt、线上完整 prompt、离线 traex + gpt-5.5、离线 traex + gpt-5.4 |
| 重复策略 | 收集 5 个成功 run，最多尝试 8 次，至少 3 次成功聚合 |
| 聚合指标 | mean、std、range |

### 关键结论

| 观察 | 归因 |
| --- | --- |
| 线上短 prompt 波动最大 | 服务端内置指令不足以稳定约束 7 个子维度，Text 子项更容易摇摆。 |
| 线上完整 prompt 波动降低但均值下降 | rubric 更严格，能压低随机高分，但输出契约和线上服务预期可能冲突。 |
| 离线 gpt-5.5 最稳定 | 同一完整 prompt 下，重复评分一致性优于 gpt-5.4。 |
| 离线 gpt-5.4 复现明显波动 | 线上波动不只是服务包装问题，模型版本本身也可能是关键变量。 |

### 问题归因

D2C VLM 评分的问题可以分为两层。

评分机制问题：

- 28 分制换算百分制会放大单项波动。
- 标准模糊，“基本一致”“大致相同”这类描述难以稳定执行。
- 子项耦合，例如布局、比例、视觉协调性可能一起升降。
- 总分相同不代表子项质量相同，例如 `3333` 和 `2244` 的总分可能接近，但问题类型完全不同。

VLM 能力问题：

- VLM 很难稳定度量“偏移 6px”“字号差 1px”“间距差 8px”。
- 通用模型缺少 D2C 还原度评估的领域先验。
- 模型可能按“视觉是否明显”判断，而不是按项目验收标准判断。
- 模型难以做稳定的细粒度归因。

### 优化方向

1. 模型版本升级：例如从 gpt-5.4 验证到 gpt-5.5，比较重复评分稳定性。
2. Prompt 优化：用完整 rubric 明确每个子项评分依据。
3. 输出契约拆分：将可读 Markdown 报告和机器解析 JSON 分开。
4. 评分标准细化：把模糊标准改成可判断标准，如偏移范围、字号差、文本缺失规则。
5. 结合自动化 checker：VLM 不做唯一打分标准，像素级、OCR、布局树和组件匹配应一起作为证据。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 任务理解 | D2C 评估评什么 | 评设计稿和渲染图的 layout/text/视觉一致性 |
| 方案设计 | 为什么用 VLM | VLM 可处理语义视觉差异，但需结构化 rubric 约束 |
| 局限分析 | VLM 打分为什么波动 | 标准模糊、子项耦合、细粒度像素判断弱、模型版本差异 |
| 优化追问 | 如何让评估更稳定 | 细化 rubric、拆输出契约、多次采样聚合、结合 checker |

### 易错点

- 把 VLM 单次打分当成可靠准出结论。
- 只看总分，不看子项分布和方差。
- 用模糊评分标准要求模型稳定判断。
- 忽略模型版本和线上调用链路差异。
- 不区分视觉语义差异和像素级还原误差。

## 面试应对

### D2C 视觉还原度评估你做了什么？

回答思路：讲清任务、指标、实验、问题归因和优化建议。

回答模板：

D2C 评估的目标是比较 Figma 目标图和生成代码渲染图的视觉还原度。我把评估拆成 Layout 和 Text 两类，Layout 看布局一致性、元素对齐、比例准确性和视觉协调性，Text 看字体特征、文本内容、数字和特殊字符。实验上对 100 组样本做线上和离线多次调用对比，观察 mean、std 和 range。结论是线上短 prompt 波动最大，完整 rubric 能降低波动但会拉低均值，离线 gpt-5.5 稳定性最好。这个工作让我判断 VLM 适合作为评估辅助，但不能作为唯一准出标准，还需要细化 rubric、拆分 JSON 输出和可读报告，并结合像素级 checker、OCR 和布局规则。

### 为什么通用 VLM 不能直接作为 D2C 准出标准？

回答思路：从细粒度、稳定性、领域标准和归因解释。

回答模板：

通用 VLM 能看出明显视觉差异，但很难稳定度量 D2C 场景中的细粒度误差，比如偏移几个像素、字号差一两个像素、间距是否超过验收阈值。它还缺少项目内的评分先验，容易按视觉是否明显来判断，而不是按专家验收标准判断。另外同一个 case 多次调用可能出现分数波动，只看总分还会掩盖子项差异。因此更合理的方案是让 VLM 提供语义判断和解释，再结合结构化 rubric、像素级 checker、OCR 和组件匹配做综合评估。
