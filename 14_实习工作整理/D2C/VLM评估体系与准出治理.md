# D2C：VLM 评估体系与准出治理

## 知识点解析

### 概述

本文整理 [D2C 视觉还原度评估](<视觉还原度评估.md>)的体系化方案，重点关注 [VLM](<../../06_视觉多模态与生成模型/多模态模型/VLM与Vision_Instruction_Tuning.md>) 打分不稳定的原因、rubric 设计、结构化输出、自动化 checker 组合和上线准出治理。

### 为什么 D2C 需要专门评估

D2C 的目标不是“代码能运行”，而是生成页面和设计稿视觉一致。视觉还原度包含：

- 页面结构是否一致。
- 元素位置和尺寸是否接近。
- 文案是否完整准确。
- 数字、符号、颜色、字体是否正确。
- 视觉层级和密度是否符合设计稿。

这类差异既有像素级，也有语义级，所以单一指标不够。

### VLM 适合做什么

VLM 适合：

- 发现明显布局错位。
- 识别文本缺失、截断和错写。
- 判断组件语义是否一致。
- 给出人类可读差异解释。
- 辅助人工 review 聚焦问题区域。

VLM 不适合单独负责：

- 精确像素偏移。
- 字号、圆角、间距的微小差异。
- 多次调用完全稳定打分。
- 强准出门禁。

### 评分体系

建议保留 Layout + Text 两大类，但把每个子项定义成可执行规则。

| 类别 | 子项 | 判断方式 |
| --- | --- | --- |
| Layout | 布局一致性 | 主要区域是否存在且相对位置一致 |
| Layout | 元素对齐 | 组件边界、中心线、间距是否明显偏离 |
| Layout | 比例准确性 | 图片、按钮、卡片的宽高和大小关系是否接近 |
| Layout | 视觉协调性 | 页面密度、层级和整体观感是否接近 |
| Text | 字体特征 | 字号、字重、样式、颜色是否明显不一致 |
| Text | 文本内容 | 文案是否缺失、多出、截断、错别字 |
| Text | 数字特殊字符 | 金额、日期、数量、邮箱、符号是否一致 |

### 为什么打分会波动

| 原因 | 表现 | 解决方式 |
| --- | --- | --- |
| 标准模糊 | “基本一致”每次理解不同 | 把评分标准改成可判定规则 |
| 子项耦合 | 布局错位导致比例和协调性一起变 | 要求分项解释，不只看总分 |
| 细粒度弱 | 几 px 偏移、字号差异难判断 | 接入像素/OCR/layout checker |
| 输出契约冲突 | Markdown 可读但 JSON 不稳定 | 可读报告和机器 JSON 分离 |
| 模型版本差异 | gpt-5.4 和 gpt-5.5 稳定性不同 | 固定模型版本并做重复评测 |

### 准出治理方案

更合理的准出不是“VLM 分数超过阈值就通过”，而是分层：

```text
hard checker
  -> OCR/text checker
  -> layout/component checker
  -> VLM semantic judge
  -> human review for uncertain cases
```

分层含义：

- Hard checker：页面是否成功渲染、截图尺寸是否正确、关键节点是否存在。
- OCR/text checker：文案、数字、特殊字符强校验。
- Layout checker：组件位置、尺寸、间距、层级关系。
- VLM judge：语义视觉差异和整体质量解释。
- Human review：高风险和模型分歧 case 兜底。

### 输出结构

建议输出两份结果：

机器可解析 JSON：

```json
{
  "layout_score": 13,
  "text_score": 10,
  "total_score": 23,
  "major_issues": ["price text mismatch", "banner shifted down"],
  "need_human_review": true
}
```

人类可读报告：

```text
主要问题：
1. 商品价格数字不一致。
2. 营销 Banner 相比设计稿下移。
3. 底部按钮高度接近，但文字字号略小。
```

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 评测设计 | D2C 怎么评估 | Layout/Text 分项 + checker + VLM + 人审 |
| 模型局限 | VLM 为什么不稳定 | 标准模糊、细粒度弱、输出随机性 |
| 工程方案 | 怎么做准出 | hard rule 卡死，VLM 辅助语义判断 |
| 指标设计 | 为什么不只看总分 | 总分掩盖子项差异，分项更利于修复 |

### 易错点

- 将 VLM 打分当作唯一真值。
- 只优化 prompt，不改评分标准。
- 总分相同就认为质量相同。
- 不做多次采样和方差统计。
- JSON 输出和 Markdown 报告混在一起，线上难解析。

## 面试应对

### 如果让你设计 D2C 视觉还原度准出系统，你会怎么做？

回答思路：强调 VLM 是辅助，不是唯一标准。

回答模板：

我会把 D2C 准出设计成多层评估系统，而不是只依赖 VLM 分数。最底层先做 hard checker，保证页面成功渲染、截图尺寸和关键节点存在；然后用 OCR/text checker 强校验文案、数字和特殊字符；再用 layout 或组件 checker 比较位置、尺寸、间距和层级；最后用 VLM 做语义视觉判断和差异解释。VLM 的优势是能发现整体观感和语义问题，但它对几像素偏移、字号差异和稳定打分不够可靠，所以更适合作为辅助 judge，而不是唯一准出门禁。
