# Python基础

## 知识点解析

### 概述

Python 在算法岗、数据岗、AI 岗和银行科技岗笔试中常见。高频考点包括可变/不可变对象、引用语义、深浅拷贝、装饰器、生成器、迭代器、异常、面向对象和 GIL。

### 可变对象和不可变对象

Python 中对象分为可变对象和不可变对象。可变对象创建后内容可以修改，例如 `list`、`dict`、`set`；不可变对象创建后内容不能修改，例如 `int`、`float`、`str`、`tuple`。

函数传参本质上传的是对象引用。是否能影响外部对象，取决于对象本身是否可变，以及函数内部是修改对象内容还是让局部变量重新绑定到新对象。

### 深拷贝和浅拷贝

浅拷贝只复制最外层容器，内部嵌套对象仍然共享引用；深拷贝会递归复制内部对象。对于没有嵌套可变对象的数据，浅拷贝通常够用；对于嵌套列表、字典等结构，浅拷贝可能导致修改内部对象时互相影响。

### 迭代器和生成器

迭代器实现了 `__iter__` 和 `__next__`，可以逐个返回元素。生成器是特殊迭代器，使用 `yield` 暂停和恢复执行。生成器不会一次性把全部数据放进内存，适合处理大文件、流式数据和惰性计算。

### 装饰器

装饰器本质是一个接收函数并返回新函数的高阶函数，可以在不修改原函数代码的前提下增强功能。常见用途包括日志、鉴权、缓存、计时、重试。

### GIL

GIL 是 CPython 解释器中的全局解释器锁，同一时刻通常只有一个线程执行 Python 字节码。因此 Python 多线程不适合 CPU 密集型并行计算，但适合 IO 密集型任务，因为线程等待 IO 时可以释放 GIL。CPU 密集型任务可考虑多进程、NumPy 底层释放 GIL 的计算或 C/C++ 扩展。

### 异常

Python 用 `try-except-else-finally` 处理异常。`except` 捕获异常，`else` 在没有异常时执行，`finally` 无论是否异常都会执行，常用于资源释放。不要裸写 `except:` 吞掉所有异常，否则会掩盖真实问题。

## 面试应对

### Python 的 `is` 和 `==` 有什么区别？

回答思路：从对象身份和值相等回答。

回答模板：

`==` 比较的是两个对象的值是否相等，通常会调用对象的 `__eq__` 方法；`is` 比较的是两个变量是否引用同一个对象，也就是对象身份是否相同。比如两个列表内容一样时，`==` 可能为 True，但如果它们是两个不同对象，`is` 就是 False。面试里要注意小整数和字符串驻留可能让某些对象看起来 `is` 也为 True，但不能依赖这种实现细节写业务逻辑。

### Python 多线程为什么不适合 CPU 密集型任务？

回答思路：解释 GIL，再区分 CPU 密集和 IO 密集。

回答模板：

在 CPython 中有 GIL，同一时刻通常只有一个线程执行 Python 字节码，所以多个 Python 线程不能真正并行执行 CPU 密集型计算。对于 IO 密集型任务，线程等待网络或磁盘 IO 时可以释放 GIL，因此多线程仍然有价值。CPU 密集型任务如果要利用多核，通常用多进程，或者使用 NumPy、C/C++ 扩展这类能在底层释放 GIL 的方案。
