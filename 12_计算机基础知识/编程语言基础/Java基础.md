# Java基础

## 知识点解析

### 概述

Java 基础在银行科技岗、央国企笔试和大厂后端面试中都很高频。笔试常考语法、集合、异常和面向对象；面试常追问 HashMap、ConcurrentHashMap、JVM 内存、GC、线程池和锁。

### 面向对象

Java 面向对象的核心是封装、继承和多态。封装把数据和操作封装到类中，通过访问控制保护内部状态；继承用于复用父类能力；多态让父类引用指向子类对象，运行时根据真实对象类型调用重写方法。

抽象类和接口的区别：

| 对比项 | 抽象类 | 接口 |
| --- | --- | --- |
| 关系 | is-a，强调继承层次 | can-do，强调能力约束 |
| 字段 | 可以有成员变量 | 主要是常量 |
| 方法 | 可以有普通方法和抽象方法 | 主要定义行为规范，也可有默认方法 |
| 继承数量 | 单继承 | 可实现多个接口 |

### 集合

Java 集合常见体系：

- `List`：有序、可重复，常见实现有 `ArrayList`、`LinkedList`。
- `Set`：不重复，常见实现有 `HashSet`、`TreeSet`。
- `Map`：键值对，常见实现有 `HashMap`、`TreeMap`、`ConcurrentHashMap`。
- `Queue`：队列，常用于 BFS、任务队列、线程池阻塞队列。

`ArrayList` 底层是动态数组，随机访问快，中间插入删除慢；`LinkedList` 底层是双向链表，已知节点插入删除快，但随机访问慢。

### HashMap

HashMap 底层是数组 + 链表/红黑树。put 时先根据 key 的 hash 计算桶位置，如果桶为空直接放入；如果发生冲突，则在链表或红黑树中查找相同 key，找到则覆盖，否则追加。链表过长且数组容量达到阈值后，会转成红黑树以降低查找复杂度。

HashMap 容量通常取 2 的幂，是为了用 `(n - 1) & hash` 快速计算桶下标，同时帮助 hash 分布更均匀。HashMap 线程不安全，并发扩容和写入可能导致数据覆盖、结构异常或可见性问题。

### ConcurrentHashMap

ConcurrentHashMap 是线程安全的哈希表。JDK 1.8 之后主要使用 CAS + synchronized 控制桶级别并发，读操作大多不加锁，写操作只锁局部桶，降低全表锁竞争。它适合高并发读写场景，但复合操作仍要注意原子性。

### JVM 内存

JVM 运行时内存常见区域：

- 程序计数器：记录当前线程执行位置。
- 虚拟机栈：存放方法栈帧、局部变量表、操作数栈。
- 本地方法栈：服务 Native 方法。
- 堆：存放对象实例，是 GC 主要区域。
- 方法区/元空间：存放类元数据、常量、静态变量等。

### GC

Java 判断对象是否可回收主要使用可达性分析，从 GC Roots 出发，无法到达的对象可以被回收。常见 GC 算法包括标记-清除、复制、标记-整理、分代收集。新生代对象生命周期短，常用复制算法；老年代对象存活时间长，常用标记-清除或标记-整理。

### 线程池

线程池核心参数包括核心线程数、最大线程数、阻塞队列、线程空闲存活时间、线程工厂和拒绝策略。执行流程是：优先使用核心线程；核心线程满后进入队列；队列满后创建非核心线程；达到最大线程数后触发拒绝策略。

不建议直接使用 `Executors` 创建线程池，因为默认队列或最大线程数可能过大，导致 OOM 或资源耗尽。工程上应显式设置参数。

## 面试应对

### HashMap 底层原理是什么？

回答思路：从数据结构、put 流程、冲突处理、扩容和线程安全回答。

回答模板：

HashMap 底层主要是数组加链表或红黑树。put 时先对 key 做 hash，再通过数组长度计算桶位置。如果桶为空就直接插入；如果冲突，就在链表或红黑树中查找相同 key，找到则覆盖，否则新增节点。链表过长且数组容量达到条件后会树化，降低极端冲突下的查找成本。HashMap 平均查找是 O(1)，但它不是线程安全的，并发写入和扩容可能产生问题，高并发场景应使用 ConcurrentHashMap。

### 线程池为什么重要？

回答思路：说明复用线程、控制资源、削峰，再补风险。

回答模板：

线程池的作用是复用线程、减少频繁创建销毁线程的开销，并通过队列和最大线程数控制并发资源。任务提交后，线程池会优先使用核心线程，核心线程满了进入阻塞队列，队列满了再创建非核心线程，超过最大线程数就执行拒绝策略。线程池参数如果设置不合理，可能导致任务堆积、响应变慢甚至 OOM，所以工程上要结合任务类型、QPS、耗时和机器资源来配置。
