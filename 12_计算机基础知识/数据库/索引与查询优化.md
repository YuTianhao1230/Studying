# 索引与查询优化

## 知识点解析

### 概述

索引是数据库面试最高频考点之一。核心问题包括为什么用 B+ 树、聚簇索引和非聚簇索引、覆盖索引、最左前缀、索引失效和慢 SQL 排查。

### B+ 树索引

B+ 树非叶子节点只存 key 和指针，叶子节点存数据或主键，并且叶子节点按顺序链表连接。它适合数据库索引，因为树高低、磁盘 IO 少、查询稳定，并且范围查询效率高。

### 聚簇索引和非聚簇索引

InnoDB 中主键索引是聚簇索引，叶子节点存整行数据。普通二级索引是非聚簇索引，叶子节点存主键值，查到主键后可能需要回表查询整行。

覆盖索引是指查询字段都能从索引中拿到，不需要回表。

### 联合索引和最左前缀

联合索引按字段顺序组织，例如 `(a, b, c)` 可以支持 `a`、`a,b`、`a,b,c` 的连续前缀匹配。跳过最左字段通常无法充分使用索引。

### 索引失效

常见索引失效场景：

- 在索引列上使用函数或表达式。
- 隐式类型转换。
- 前导模糊匹配，如 `LIKE '%abc'`。
- 联合索引不满足最左前缀。
- `OR` 条件中部分字段无索引。

### 慢 SQL 排查

慢 SQL 排查要看执行计划、扫描行数、索引命中、回表、排序、临时表、锁等待和数据量。`EXPLAIN` 重点看 type、key、rows、Extra。

## 面试应对

### 为什么数据库索引用 B+ 树？

回答思路：磁盘 IO、树高、范围查询、稳定性。

回答模板：

数据库索引常用 B+ 树，是因为它适合磁盘页读取和范围查询。B+ 树非叶子节点只存 key 和指针，一个页能放更多 key，树高更低，查询需要的磁盘 IO 更少。所有数据都在叶子节点，查询路径长度稳定；叶子节点之间有链表，范围查询只要定位起点后顺序扫描即可。相比哈希索引，B+ 树更适合范围查询和排序。

### 慢 SQL 怎么排查？

回答思路：先执行计划，再索引和数据量，最后锁和资源。

回答模板：

我会先确认 SQL、耗时、调用频率和数据量，再用 EXPLAIN 看执行计划，重点看是否走索引、扫描行数、join 类型、是否有 filesort 或临时表。然后检查索引设计是否匹配 WHERE、JOIN、ORDER BY，有没有函数、隐式转换、前导模糊匹配导致索引失效。如果 SQL 本身没问题，还要看锁等待、热点行、连接池和数据库资源。

### 什么是覆盖索引？

回答思路：说明索引包含查询所需字段，因此可以避免回表。

回答模板：

覆盖索引是指 SQL 查询需要的字段都能直接从索引中取得，不需要再根据主键回表查询整行数据。它能减少随机 IO，提高查询性能。例如联合索引包含 `user_id` 和 `status`，查询只需要这两个字段时，就可能直接使用覆盖索引。
