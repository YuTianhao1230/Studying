# SQL与关系模型

## 知识点解析

### 概述

本文整理 SQL 执行顺序、连接、聚合、窗口函数、关系模型、数据库范式和 ER 模型。

### SQL 执行顺序

SQL 逻辑执行顺序通常是：

```text
FROM/JOIN -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY -> LIMIT
```

`WHERE` 用于分组前过滤行，`HAVING` 用于分组后过滤聚合结果。

### 连接

| 连接 | 含义 |
| --- | --- |
| INNER JOIN | 只保留两表匹配记录 |
| LEFT JOIN | 保留左表全部记录，右表无匹配补 NULL |
| RIGHT JOIN | 保留右表全部记录 |
| FULL JOIN | 保留两边所有记录 |
| SELF JOIN | 表自己和自己连接 |

### 聚合和窗口函数

聚合函数包括 `COUNT`、`SUM`、`AVG`、`MAX`、`MIN`。窗口函数在不折叠行的情况下计算分组内排名或统计，常见有 `row_number`、`rank`、`dense_rank`。

聚合会把多行折叠为分组结果，窗口函数保留原始行。需要“每个部门一行统计”时用聚合，需要“保留员工明细并附加部门排名”时用窗口函数。

### 范式

1NF 要求字段原子；2NF 要求非主属性完全依赖候选键；3NF 要求非主属性不传递依赖候选键。范式能减少冗余和更新异常，但高并发读场景可能适当反范式。

### 关系模型基础

- 候选键：能够唯一标识元组的最小属性集合。
- 主键：从候选键中选定的一个标识。
- 外键：引用另一关系的候选键，用于维护参照完整性。
- 实体完整性：主键不能为 NULL。
- 参照完整性：外键要么为空，要么引用已存在的记录。

关系代数常见运算：

| 运算 | 含义 | SQL 对应 |
| --- | --- | --- |
| 选择 | 按条件筛选行 | `WHERE` |
| 投影 | 选择部分列 | `SELECT column` |
| 并、交、差 | 集合运算 | `UNION`、`INTERSECT`、`EXCEPT` |
| 笛卡尔积 | 两关系任意组合 | `CROSS JOIN` |
| 连接 | 按条件组合关系 | `JOIN ... ON` |

### 范式题怎么解

1. 写出候选键和函数依赖。
2. 检查字段是否满足原子性。
3. 判断非主属性是否只依赖复合键的一部分，存在则违反 2NF。
4. 判断非主属性是否通过另一个非主属性间接依赖候选键，存在则违反 3NF。
5. 根据依赖关系分解表，并检查是否无损连接、是否保持函数依赖。

范式解决的典型问题包括数据冗余、插入异常、删除异常和更新异常。

### 常见考法与解题策略

| 题型 | 解题策略 |
| --- | --- |
| SQL 执行顺序 | 按 FROM、WHERE、GROUP BY、HAVING、SELECT、ORDER BY 推导 |
| JOIN 结果行数 | 先判断连接键是否唯一，再分析一对一或一对多 |
| NULL 判断 | 使用 `IS NULL`，注意三值逻辑 |
| 聚合题 | 先确定一行输出代表什么粒度 |
| 窗口函数 | 先确定分区字段，再确定排序和窗口范围 |
| 范式判断 | 列候选键、主属性和函数依赖 |
| ER 图转关系 | 实体建表，一对多在多方放外键，多对多建中间表 |

### 易错点

- SQL 书写顺序不等于逻辑执行顺序。
- `LEFT JOIN` 后在 `WHERE` 中过滤右表字段，可能退化成 `INNER JOIN`。
- `COUNT(*)` 与 `COUNT(column)` 对 NULL 的处理不同。
- 主键一定唯一且非空，唯一约束是否允许 NULL 取决于数据库实现。
- 反范式是有意识的工程取舍，不等于随意重复数据。

## 面试应对

### WHERE 和 HAVING 有什么区别？

回答思路：从过滤时机和是否能使用聚合函数回答。

回答模板：

WHERE 是分组前过滤行，作用在原始记录上，一般不能直接使用聚合函数；HAVING 是 GROUP BY 分组之后过滤聚合结果，可以使用 COUNT、SUM 这类聚合函数。简单说，过滤明细行用 WHERE，过滤分组统计结果用 HAVING。实际优化时，应尽量把能提前过滤的条件放到 WHERE，减少后续分组和聚合的数据量。

### 数据库范式有什么用？

回答思路：说明减少冗余和异常，再补工程取舍。

回答模板：

数据库范式用于规范表结构，减少数据冗余和插入、删除、更新异常。比如 1NF 要求字段不可再分，2NF 要求非主属性完全依赖候选键，3NF 要求非主属性不能传递依赖候选键。但工程上不是范式越高越好，范式高会增加 join 成本，高并发读场景可能适当反范式，用冗余换查询性能。

### 聚合函数和窗口函数有什么区别？

回答思路：说明是否折叠原始行。

回答模板：

聚合函数配合 GROUP BY 会把多行折叠成每组一行，例如统计每个部门的平均工资；窗口函数在分组范围内计算排名、累计值或聚合结果，但保留每条原始记录，例如给每个员工附加部门内排名。需要输出明细行时通常考虑窗口函数，只需要分组统计结果时使用聚合。

### LEFT JOIN 后在 WHERE 中过滤右表字段有什么风险？

回答思路：说明 NULL 行会被过滤。

回答模板：

LEFT JOIN 原本会保留左表未匹配的记录，并把右表字段补成 NULL。如果之后在 WHERE 中要求右表字段满足普通条件，这些 NULL 行会被过滤掉，效果可能变成 INNER JOIN。若条件用于限制右表参与连接的数据，通常应写在 ON 中；如果就是要过滤匹配结果，则可以保留在 WHERE 中。
