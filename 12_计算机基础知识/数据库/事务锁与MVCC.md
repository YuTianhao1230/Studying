# 事务锁与MVCC

## 知识点解析

### 概述

事务、锁和 MVCC 解释了数据库为什么能在并发读写下保持正确性。银行科技岗尤其重视事务一致性，大厂面试则常追问隔离级别、锁范围、幻读和 MVCC 实现。

### ACID

- Atomicity 原子性：事务要么全部成功，要么全部失败。
- Consistency 一致性：事务前后数据满足约束。
- Isolation 隔离性：并发事务互不产生不合理干扰。
- Durability 持久性：提交后的修改可靠保存。

### 隔离级别

| 隔离级别 | 可能问题 |
| --- | --- |
| Read Uncommitted | 脏读、不可重复读、幻读 |
| Read Committed | 不可重复读、幻读 |
| Repeatable Read | 理论上可能幻读 |
| Serializable | 基本避免并发异常 |

脏读是读到未提交数据；不可重复读是同一行两次读取结果不同；幻读是同一范围两次查询出现新增或删除记录。

### 锁

数据库锁可按粒度分为表锁、行锁；按模式分为共享锁和排他锁。InnoDB 还涉及记录锁、间隙锁、临键锁。查询没有命中索引时，可能导致锁范围扩大。

### MVCC

MVCC 是多版本并发控制，通过版本链和 ReadView 让读操作尽量不阻塞写操作。InnoDB 中 MVCC 依赖隐藏事务 ID、undo log 和可见性判断。普通快照读通常不加锁，当前读、更新和唯一性检查仍然需要锁。

### 日志

- undo log：用于回滚和 MVCC 版本链。
- redo log：用于崩溃恢复，保证持久性。
- binlog：记录逻辑变更，用于复制和恢复。

## 面试应对

### MVCC 是什么？

回答思路：多版本、快照读、读写并发。

回答模板：

MVCC 是多版本并发控制，通过保存数据的多个历史版本，让读操作基于事务视图读取符合条件的版本，从而减少读写阻塞。在 InnoDB 中，MVCC 依赖隐藏事务 ID、undo log 版本链和 ReadView 做可见性判断。它主要服务快照读，不代表完全不需要锁，当前读、更新和唯一约束检查仍然需要锁。

### 事务隔离级别怎么理解？

回答思路：用并发异常串起来。

回答模板：

事务隔离级别是在并发性能和一致性之间做取舍。Read Uncommitted 可能脏读；Read Committed 避免脏读，但可能不可重复读；Repeatable Read 保证同一事务内重复读取同一行结果一致，但理论上仍可能幻读；Serializable 最严格，基本串行执行，并发性能最低。隔离越强，一致性越好，但并发性能通常越差。

### 脏读、不可重复读和幻读有什么区别？

回答思路：分别对应未提交数据、同一行变化和范围结果集变化。

回答模板：

脏读是读到了其他事务还没有提交的数据；不可重复读是同一事务内两次读取同一行，结果不同；幻读是同一事务内按相同范围条件查询，两次得到的记录集合不同。可以简单记为：脏读关注未提交数据，不可重复读关注同一行变化，幻读关注范围内记录数量变化。
