# 同步互斥与死锁

## 知识点解析

### 概述

本文整理并发程序中的同步、互斥、锁、信号量、PV 操作、死锁条件、银行家算法和死锁处理方法。

### 同步和互斥

互斥解决“同一时刻只能有一个线程访问临界区”的问题；同步解决“多个线程之间执行顺序”的问题。互斥关注资源独占，同步关注先后依赖。

### 常见机制

| 机制 | 作用 |
| --- | --- |
| 互斥锁 | 保护临界区 |
| 读写锁 | 读多写少场景，提高并发读 |
| 自旋锁 | 忙等，不睡眠，适合极短临界区 |
| 条件变量 | 等待某个条件成立 |
| 信号量 | 控制资源数量，支持 PV 操作 |
| 原子操作 | 硬件级不可分割操作 |

### 死锁四条件

- 互斥：资源一次只能被一个线程占用。
- 请求并保持：持有资源时继续请求新资源。
- 不可剥夺：资源不能被强制抢走。
- 循环等待：多个线程形成等待环。

### 死锁处理

死锁处理包括预防、避免、检测和恢复。工程中常见做法是统一加锁顺序、缩小锁粒度、设置锁超时、减少嵌套锁和用工具检测等待关系。

### 常见考法与解法

| 题型 | 怎么考 | 怎么解 |
| --- | --- | --- |
| PV 操作 | 补全生产者消费者、读者写者伪代码 | 先找资源数量，再找先后关系 |
| 信号量初值 | 判断互斥量和资源量初值 | 互斥通常为 1，资源量等于可用数量 |
| 死锁判断 | 给出资源分配和等待关系 | 画资源分配图或等待图找环 |
| 银行家算法 | 判断是否安全、求安全序列 | 反复找需求不超过可用资源的进程 |
| 锁选型 | 自旋锁、互斥锁、读写锁怎么选 | 根据等待时间和读写比例判断 |
| 并发 Bug | 丢失更新、竞态、可见性问题 | 找共享状态和非原子操作 |

### PV 题解题框架

P 操作用于申请资源或等待条件，V 操作用于释放资源或通知其他执行单元。

做题时先区分：

- 互斥信号量：保护临界区，初值通常为 1。
- 资源信号量：表示可用资源数量，初值等于资源数。
- 同步信号量：表示某个前置条件是否完成，初值通常为 0。

生产者消费者模型中，若缓冲区容量为 `n`：

```text
empty = n
full = 0
mutex = 1

生产者：P(empty) -> P(mutex) -> 放入数据 -> V(mutex) -> V(full)
消费者：P(full)  -> P(mutex) -> 取出数据 -> V(mutex) -> V(empty)
```

资源信号量必须先于互斥锁申请，否则线程可能持有锁并等待资源，导致其他线程无法进入临界区释放资源。

### 银行家算法

判断安全状态：

1. 计算每个进程的剩余需求 `Need = Max - Allocation`。
2. 令 `Work = Available`。
3. 查找满足 `Need <= Work` 的未完成进程。
4. 假设该进程完成，执行 `Work += Allocation`。
5. 重复直到所有进程完成，或再也找不到可完成进程。

能找到覆盖所有进程的顺序，说明系统处于安全状态；安全状态一定不会立即死锁，不安全状态表示未来可能死锁，但不等于当前已经死锁。

### 易错点

- 同步和互斥不是同义词：互斥限制同时访问，同步约束执行顺序。
- 信号量可以表示多个资源，互斥锁通常只有持有者才能解锁。
- 等待图有环在单实例资源中表示死锁，多实例资源还需进一步判断。
- 死锁、饥饿和活锁不同：死锁互相等待，饥饿长期得不到资源，活锁持续动作却无法推进。

## 面试应对

### 死锁怎么产生，怎么解决？

回答思路：四条件 + 工程方案。

回答模板：

死锁产生需要互斥、请求并保持、不可剥夺和循环等待四个条件同时成立。解决时可以破坏其中任意条件，比如统一加锁顺序破坏循环等待，减少持锁期间再申请资源，或者给锁加超时和回滚。工程里最常用的是固定锁顺序、缩小临界区、避免嵌套锁，并在必要时做死锁检测和告警。

### 自旋锁和互斥锁有什么区别？

回答思路：等待方式和适用场景。

回答模板：

自旋锁拿不到锁时不会睡眠，而是在 CPU 上循环等待，所以切换成本低，但会消耗 CPU，适合锁持有时间非常短的场景。互斥锁拿不到锁时线程可能阻塞并让出 CPU，适合临界区较长或等待时间不确定的场景。选择时要看锁竞争程度和临界区耗时。

### 死锁、活锁和饥饿有什么区别？

回答思路：从是否阻塞、是否持续执行和能否获得资源区分。

回答模板：

死锁是多个执行单元互相等待对方持有的资源，大家都无法继续；活锁是线程没有阻塞，也在不断改变状态，但彼此反复避让，系统没有实质进展；饥饿是某个线程因为调度或资源竞争长期得不到执行机会。固定加锁顺序可以预防死锁，随机退避可以缓解活锁，公平锁和合理调度可以减少饥饿。

### PV 操作题怎么分析？

回答思路：先资源、再互斥、最后同步顺序。

回答模板：

我会先列出有限资源及其数量，确定资源信号量初值；再找临界区，设置初值为 1 的互斥信号量；最后分析线程之间的先后依赖，用初值为 0 的同步信号量连接。写伪代码时通常先申请资源、再进入互斥区，退出互斥区后再通知其他线程，并检查每个 P 是否都有对应的 V。
