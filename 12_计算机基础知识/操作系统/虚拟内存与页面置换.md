# 虚拟内存与页面置换

## 知识点解析

### 概述

虚拟内存是操作系统内存管理的核心抽象。它让每个进程看到独立、连续的地址空间，再通过页表映射到物理内存，实现隔离、保护、按需加载和换页。

### 地址映射

程序使用的是虚拟地址，CPU 访问内存时需要把虚拟地址转换成物理地址。页表保存虚拟页到物理页框的映射。TLB 是页表缓存，用于加速地址转换。

虚拟地址通常拆成：

```text
虚拟页号 + 页内偏移
```

页大小决定页内偏移位数，剩余高位是虚拟页号。

### 缺页中断

如果访问的虚拟页不在物理内存中，会触发缺页中断。操作系统暂停当前进程，从磁盘或交换区加载页面到内存，更新页表后继续执行。缺页太多会导致频繁换页，严重时系统大部分时间都在换页，称为 thrashing。

### 页面置换算法

| 算法 | 思路 | 特点 |
| --- | --- | --- |
| FIFO | 淘汰最早进入内存的页 | 简单，但可能出现 Belady 异常 |
| LRU | 淘汰最近最久未使用的页 | 符合局部性，精确实现成本高 |
| OPT | 淘汰未来最长时间不用的页 | 理论最优，实际不可实现 |
| Clock | 用访问位近似 LRU | 工程实现成本较低 |

### 常见考法与解法

| 题型 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 地址划分 | 给定地址位数和页大小，求页号与偏移 | 页内偏移位数为 `log2(页大小)` |
| 页表大小 | 求虚拟页数、页表项数量和空间 | 虚拟地址空间除以页大小 |
| 地址转换 | 给出页表，求物理地址 | 查页框号并拼接页内偏移 |
| TLB 有效访问时间 | 给出命中率和各级耗时 | 按命中与未命中概率加权 |
| 页面置换 | 给出访问序列和页框数 | 逐次维护页框并统计缺页 |
| Belady 异常 | 增加页框后缺页反而增多 | FIFO 可能出现，LRU/OPT 不会 |

### 地址转换题

若页大小为 `2^k` 字节，则虚拟地址低 `k` 位是页内偏移，其余高位是虚拟页号。

```text
虚拟地址 = 虚拟页号 × 页大小 + 页内偏移
物理地址 = 物理页框号 × 页大小 + 页内偏移
```

解题步骤：

1. 根据页大小确定偏移位数。
2. 将虚拟地址拆成页号和页内偏移。
3. 查页表得到物理页框号。
4. 保持页内偏移不变，拼成物理地址。
5. 如果页表项无效，则发生缺页中断。

多级页表题还要根据每级索引位数逐级拆分虚拟页号。

### 页面置换手算

对访问序列从左到右模拟：

- FIFO：记录进入内存的先后顺序。
- LRU：每次访问后更新最近使用顺序。
- OPT：向后查看未来最晚使用或不再使用的页面。
- Clock：检查访问位，访问位为 1 时清零并继续扫描。

每访问一个不在页框中的页面就发生缺页；页框未满时直接装入，页框已满时再按算法淘汰。

### TLB 有效访问时间

如果 TLB 查询耗时为 `t`，内存访问耗时为 `m`，TLB 命中率为 `h`，且忽略缺页：

```text
EAT = h × (t + m) + (1 - h) × (t + 2m)
```

未命中时通常要先访问内存中的页表，再访问目标数据。具体题目可能给出多级页表、Cache 或并行查询约定，应按题意调整。

### 易错点

- 缺页中断属于异常，处理后可以回到原指令重新执行。
- 页大小越大，页表项数量减少，但页内碎片可能增加。
- TLB 缓存的是页表项，不是普通数据 Cache。
- LRU 不会出现 Belady 异常，但精确实现成本较高。
- 虚拟内存扩大的是可用地址空间，不会增加物理内存容量。

## 面试应对

### 为什么需要虚拟内存？

回答思路：从隔离、抽象、按需加载和扩展地址空间回答。

回答模板：

虚拟内存让每个进程看到独立、连续的地址空间，再通过页表映射到物理内存。它的好处是进程隔离更安全，程序编写更简单，而且可以按需加载页面，只有真正访问的数据才进入物理内存。虚拟内存不是凭空增加物理内存，而是通过地址映射、换页和磁盘交换扩展可用地址空间，代价是地址转换和缺页中断会带来开销。

### LRU 和 FIFO 有什么区别？

回答思路：说明淘汰依据和局部性。

回答模板：

FIFO 淘汰最早进入内存的页面，实现简单，但不考虑页面最近是否被频繁访问，可能把热点页面淘汰掉。LRU 淘汰最近最久未使用的页面，更符合程序的时间局部性，效果通常更好，但精确维护访问顺序成本较高。工程上常用 Clock 这类算法近似 LRU，在效果和实现成本之间折中。

### 缺页中断是什么？

回答思路：说明页面不在内存时，操作系统如何加载并恢复执行。

回答模板：

缺页中断是进程访问某个虚拟页时，发现这个页当前不在物理内存中，于是 CPU 触发异常进入内核。操作系统会把页面从磁盘或交换区加载到内存，必要时先淘汰其他页面，然后更新页表并恢复进程执行。缺页太频繁会导致系统大量时间花在换页上，性能会明显下降。

### 虚拟地址如何转换成物理地址？

回答思路：页号、TLB、页表、页框和偏移。

回答模板：

CPU 先把虚拟地址拆成虚拟页号和页内偏移，用虚拟页号查询 TLB；命中后直接得到物理页框号，未命中则访问页表。如果页表项有效，就把物理页框号和原页内偏移组合成物理地址；如果页面不在内存，则触发缺页中断，由操作系统调入页面、更新页表后重新执行指令。

### 页面置换题怎么手算？

回答思路：从左到右模拟页框状态并标记缺页。

回答模板：

我会画出每次访问后的页框状态，从访问序列左到右逐项判断页面是否已在内存。命中时按算法需要更新访问状态，未命中时缺页数加一；页框未满直接装入，已满再按 FIFO、LRU 或 OPT 选择淘汰页。最后统计缺页次数和缺页率，并特别检查 FIFO 是否可能出现 Belady 异常。
