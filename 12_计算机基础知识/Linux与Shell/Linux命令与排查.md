# Linux命令与排查

## 知识点解析

### 概述

Linux 命令题在央国企、银行科技岗、运维、后端和测试开发中都常见。面试重点不是背命令名，而是能根据“CPU 高、内存高、磁盘满、端口不通、接口慢”等现象选择排查路径。

### 系统资源

常用命令：

| 命令 | 作用 |
| --- | --- |
| `top` | 实时查看 CPU、内存、负载和进程 |
| `free -h` | 查看内存使用 |
| `df -h` | 查看磁盘分区空间 |
| `du -sh` | 查看目录占用 |
| `iostat` | 查看磁盘 IO |
| `vmstat` | 查看 CPU、内存、上下文切换 |

Load Average 表示系统平均负载，通常要结合 CPU 核数理解。负载高不一定只是 CPU 忙，也可能是大量进程等待 IO。

### 进程排查

`ps aux` 可以查看进程列表，`ps -ef` 更适合看父子进程关系。`kill` 用于发送信号，默认是 `SIGTERM`，表示请求进程正常退出；`kill -9` 是 `SIGKILL`，强制终止，不能被捕获或清理资源，慎用。

### 网络和端口

常用命令：

| 命令 | 作用 |
| --- | --- |
| `ss -lntp` | 查看 TCP 监听端口和进程 |
| `netstat -anp` | 查看连接状态 |
| `lsof -i :端口` | 查看端口被哪个进程占用 |
| `ping` | 检查连通性和 RTT |
| `traceroute` | 查看路由路径 |
| `curl -v` | 排查 HTTP 请求、DNS、连接和响应 |

大量 `TIME_WAIT` 通常说明本机主动关闭了大量连接；大量 `CLOSE_WAIT` 通常说明对端已关闭，但本机程序没有正确关闭 socket。

### 日志排查

常用命令包括 `tail -f` 实时追日志，`grep` 搜关键词，`less` 分页查看，`journalctl` 查看 systemd 服务日志。线上排查常见流程是先定位时间窗口，再按请求 ID、错误码、用户 ID 或 trace ID 过滤日志。

### 权限

Linux 权限分为读 `r`、写 `w`、执行 `x`，分别对应数字 4、2、1。`chmod 755 file` 表示所有者可读写执行，组用户和其他用户可读可执行。`chown` 用于修改文件所有者。

## 笔试常考

- `top`、`ps`、`kill`、`df`、`du`、`free` 的作用。
- `chmod 755`、`chmod 644` 的含义。
- `TIME_WAIT` 和 `CLOSE_WAIT` 的区别。
- 如何查端口被哪个进程占用。
- 如何查看日志最后 100 行。
- 如何统计某个关键词出现次数。

## 面试应对

### 线上 CPU 飙高怎么排查？

回答思路：先定位进程，再定位线程和代码栈。

回答模板：

我会先用 `top` 看整体负载和 CPU 占用最高的进程，再用 `ps` 或 `top -H` 看具体线程。如果是 Java 服务，会把线程 ID 转成十六进制，再用 `jstack` 找对应线程栈，看是死循环、锁竞争还是频繁 GC。如果 CPU 高同时 load 高，还要结合 `vmstat`、`iostat` 判断是不是 IO 等待导致。排查时要保留现场信息，避免一上来直接重启丢失证据。

### 端口不通怎么排查？

回答思路：从本机监听、网络连通、防火墙、服务日志逐层排查。

回答模板：

我会先在服务端用 `ss -lntp` 或 `netstat` 看端口是否监听，再用 `lsof -i` 确认对应进程。然后从客户端用 `ping`、`telnet`、`nc` 或 `curl -v` 检查网络连通和应用响应。如果本机监听正常但远端访问失败，再看防火墙、安全组、路由和 DNS。最后结合服务日志确认请求是否到达应用层。
