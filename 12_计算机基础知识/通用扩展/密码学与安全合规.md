# 密码学与安全合规

## 知识点解析

### 概述

密码学用于保护数据的机密性、完整性、身份真实性和不可抵赖性。银行和运营商笔试最常见的题型是概念辨析、算法用途匹配、TLS/证书流程和安全防护场景。中国企业信息化场景还常结合国密算法、数据安全、个人信息保护和关键信息基础设施进行考查。

### 四类密码学能力

| 能力 | 解决的问题 | 常见技术 |
| --- | --- | --- |
| 机密性 | 防止未授权读取 | 对称加密、非对称加密 |
| 完整性 | 防止数据被篡改 | 哈希、消息认证码、数字签名 |
| 身份认证 | 确认通信对方身份 | 密码、证书、数字签名、多因素认证 |
| 不可抵赖 | 防止发送方否认操作 | 数字签名、可信时间、审计 |

### 对称加密

对称加密使用同一密钥进行加密和解密，速度快，适合大量业务数据传输和存储。AES 是常见对称加密算法。对称加密的主要难点是密钥如何安全分发、保存、轮换和撤销。

分组密码通常以固定长度分组处理数据，实际使用需要选择工作模式和随机初始向量。不能把 ECB 等简单模式直接用于所有业务场景。

### 非对称加密

非对称密码使用公钥和私钥：

- 公钥可以公开。
- 私钥必须保密。
- 用公钥加密，通常由对应私钥解密。
- 用私钥签名，通常由对应公钥验证。

非对称算法计算成本较高，常用于身份认证、数字签名和密钥协商，而不是直接加密大量业务数据。

### 哈希、MAC 和数字签名

- 哈希：把任意长度输入映射成固定长度摘要，主要用于完整性校验和指纹。
- MAC：依赖共享密钥生成消息认证码，同时验证完整性和持有共享密钥的一方。
- 数字签名：发送方用私钥签名，接收方用公钥验证，可以证明来源并保护完整性。

数字签名不等于加密。签名主要解决真实性、完整性和不可抵赖；机密性仍需使用加密机制。

### 数字证书与 PKI

PKI 通过证书和信任链建立公钥与身份之间的绑定。CA 负责签发和管理证书，证书通常包含主体、公钥、有效期、签发者和 CA 签名等信息。

浏览器验证 HTTPS 证书时，通常会检查：

1. 证书是否由受信任 CA 签发。
2. 证书链是否能够建立到可信根。
3. 访问域名是否与证书主体匹配。
4. 证书是否在有效期内。
5. 证书是否被撤销或存在明显异常。

证书只能帮助确认公钥和身份的绑定，不能自动解决应用层权限、数据泄露或服务端漏洞。

### TLS 基本流程

TLS 的目标是为应用提供身份认证、机密性和完整性。简化流程：

1. 客户端发送支持的协议版本、随机数和密码套件。
2. 服务端返回证书、随机数和协商结果。
3. 客户端验证证书。
4. 双方通过密钥交换得到会话密钥。
5. 后续业务数据使用高效的对称加密和完整性保护。

TLS 通常采用“非对称机制建立信任和协商密钥，对称加密传输业务数据”的混合方式。

### 国密算法

- SM2：椭圆曲线公钥密码算法，常用于公钥加密和数字签名。
- SM3：密码杂凑算法，用于摘要和完整性校验。
- SM4：分组对称密码算法，常用于数据加密。

题目问用途时，先按“公钥、摘要、对称分组”分类，不要因为名称相近而混淆。

### 常见攻击与防护

| 攻击 | 核心问题 | 主要防护 |
| --- | --- | --- |
| SQL 注入 | 输入改变 SQL 结构 | 预编译、参数化、最小权限 |
| XSS | 恶意脚本在浏览器执行 | 输出编码、CSP、输入校验 |
| CSRF | 借用用户已有登录态发请求 | Token、SameSite、来源校验 |
| SSRF | 服务端访问攻击者指定地址 | 地址白名单、网络隔离 |
| 重放攻击 | 重复提交合法请求 | Nonce、时间戳、签名、幂等 |
| 越权 | 用户访问无权资源 | 服务端逐资源授权 |
| DDoS | 资源被大量请求耗尽 | 清洗、限流、扩容、黑名单 |

### 安全合规基础

安全合规题通常不要求背完整法律条文，而是理解以下原则：

- 数据分类分级和最小化处理。
- 个人信息处理要有明确目的和必要范围。
- 重要数据和敏感数据需要更严格的访问、加密和审计。
- 关键信息基础设施需要重点保护和风险监测。
- 发生安全事件后需要及时响应、留存证据和按要求报告。
- 生产数据不能随意复制到测试环境。

## 易错点

- Base64 是编码，不是加密。
- 哈希不是加密，通常不能通过密钥解密。
- 数字签名主要保护真实性和完整性，不等于保护机密性。
- JWT 的 Payload 默认只是编码，不应存放敏感明文。
- HTTPS 能保护传输链路，但不能替代服务端授权和业务风控。
