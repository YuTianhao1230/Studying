# 信创与国产化基础

## 知识点解析

### 概述

信创通常指信息技术应用创新，关注计算、操作系统、数据库、中间件、办公软件和安全产品的自主可控、兼容适配与产业生态。银行和运营商笔试中的信创题多为概念匹配和应用场景判断，不要求记忆所有厂商型号。

### 基本技术栈

一个信息系统通常包含：

```text
芯片/服务器 -> 操作系统 -> 数据库 -> 中间件 -> 应用软件 -> 安全与运维
```

- 芯片和服务器：提供计算、存储和网络硬件能力。
- 操作系统：管理硬件资源并提供运行环境。
- 数据库：负责结构化或非结构化数据的存储和查询。
- 中间件：提供消息、事务、应用服务、缓存和连接能力。
- 应用软件：实现银行、通信、办公和业务功能。
- 安全与运维：负责身份、审计、监控、备份和故障恢复。

国产化替代不是只替换 CPU，而是要考虑整条软硬件链路的兼容性、稳定性、安全性和迁移成本。

### 兼容适配

系统迁移到不同软硬件环境时，常见适配问题包括：

- 指令集和编译器差异。
- 操作系统接口和驱动差异。
- 数据库 SQL 方言、类型和函数差异。
- 中间件协议、事务和连接池差异。
- 文件编码、字节序和字符集差异。
- 性能、容量、监控和备份能力差异。

迁移流程通常包括环境评估、应用改造、数据迁移、兼容性测试、性能测试、安全测试、灰度切换和回滚预案。

### 数据库迁移

数据库迁移不能只复制表结构和数据，还要检查：

- 数据类型和精度。
- 索引、约束、视图和触发器。
- 存储过程和函数的 SQL 方言。
- 事务隔离和锁行为。
- 字符集、排序规则和时区。
- 备份恢复、主从复制和高可用。
- 数据量、并发量和慢查询表现。

迁移完成后需要做数据总量、关键字段、汇总金额、交易流水和业务结果校验。

### 国产密码与安全

信创环境通常会结合国密算法、密码设备、证书体系和安全审计：

- SM2：公钥密码和数字签名。
- SM3：密码杂凑。
- SM4：对称分组加密。
- 密码模块：保护密钥并完成密码运算。
- 证书体系：绑定身份和公钥。

使用国密算法不代表系统自动安全，仍需要正确的密钥生命周期管理、权限控制、漏洞修复和审计。

### 适配测试

适配测试关注应用是否能够在目标软硬件环境中正确运行。常见测试包括：

- 功能测试。
- 兼容性测试。
- 性能和容量测试。
- 稳定性和长时间运行测试。
- 安全测试。
- 数据迁移和回滚测试。
- 灾备切换测试。

“能启动”不等于完成适配。关键交易、边界数据、异常处理和故障恢复都必须验证。

### 银行和运营商场景

- 银行：核心系统、数据库、中间件、柜面和办公系统的兼容迁移。
- 运营商：网络设备、云平台、计费系统、数据平台和运维系统的自主可控。
- 共同要求：稳定运行、数据安全、供应链安全、连续服务和可回滚。

## 笔试常考

- 信创技术栈的层次。
- 国产化替代和单纯更换硬件的区别。
- 数据库迁移的风险。
- 兼容性测试、性能测试和安全测试的区别。
- SM2、SM3、SM4 的用途。
- 为什么迁移必须有回滚和灾备预案。

## 易错点

- 信创不是单一产品，也不是只换 CPU。
- 国产化不等于天然安全或性能一定更高。
- 数据迁移不仅要校验行数，还要校验关键业务结果。
- 适配测试不等于只验证程序能启动。
- 迁移方案必须同时考虑性能、稳定性、运维和回滚。
