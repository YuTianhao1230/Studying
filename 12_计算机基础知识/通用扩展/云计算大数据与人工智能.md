# 云计算、大数据与人工智能

## 知识点解析

### 概述

云计算、大数据和人工智能是银行数字化转型、运营商云网融合和算力网络常见的技术背景。笔试重点是概念边界、组件用途、架构分层和应用场景，不宜把所有技术都背成产品名称。

### 云计算基本特征

云计算通过资源池化和服务化方式提供计算、存储、网络、数据库和软件能力，常见特征包括：

- 按需自助服务。
- 广泛网络访问。
- 资源池化。
- 快速弹性伸缩。
- 可计量服务。

### 服务模型与部署模型

| 模型 | 提供内容 | 用户主要负责 |
| --- | --- | --- |
| IaaS | 虚拟机、网络、存储 | 操作系统以上的软件和数据 |
| PaaS | 运行环境、数据库、中间件 | 应用和数据 |
| SaaS | 可直接使用的软件 | 业务配置和使用 |

| 部署 | 特点 |
| --- | --- |
| 公有云 | 多租户共享云平台资源 |
| 私有云 | 面向单一组织，便于控制和合规 |
| 混合云 | 私有环境与公有云协同 |
| 多云 | 同时使用多个云服务提供方 |

### 虚拟化与容器

虚拟机通过 Hypervisor 把物理硬件抽象为多个虚拟计算环境，每个虚拟机可以运行完整操作系统。容器通常共享宿主机内核，把应用及其依赖打包成可移植运行单元。

容器编排平台通常负责：

- 容器调度。
- 服务发现和负载均衡。
- 滚动发布和版本回滚。
- 故障重启和健康检查。
- 自动扩缩容。

容器启动快、资源开销小，但安全隔离和内核依赖需要重点配置。容器不是没有状态，数据库等有状态服务需要额外设计存储和故障恢复。

### 云原生与微服务

云原生常见技术思想包括容器化、服务化、自动化交付、弹性伸缩、可观测性和声明式管理。微服务把系统按业务能力拆分为多个服务，优点是独立部署和扩展，代价是网络调用、分布式事务、配置管理和故障排查复杂度上升。

### 大数据 5V

- Volume：数据规模大。
- Velocity：产生和处理速度快。
- Variety：结构化、半结构化和非结构化数据并存。
- Veracity：数据质量和真实性。
- Value：从数据中提取价值。

### 大数据组件

| 组件 | 主要作用 |
| --- | --- |
| HDFS | 分布式文件存储 |
| MapReduce | 分布式批处理计算 |
| Hive | 面向数据仓库的 SQL 分析 |
| Spark | 通用分布式计算 |
| Kafka | 消息和事件流 |
| Flink | 流式计算和实时处理 |

HDFS 解决“数据放在哪里”，MapReduce、Spark 和 Flink 解决“数据如何计算”，Hive 解决“如何用类 SQL 方式分析”。Kafka 主要承担数据采集和事件流转，不能简单等同于数据库。

### 数据仓库与数据湖

- OLTP：面向日常交易，强调并发、低延迟和事务一致性。
- OLAP：面向分析，强调多维聚合和复杂查询。
- 数据仓库：经过建模和治理的分析型数据存储。
- 数据湖：以较原始形式存放多类型数据，再按需要处理。
- ETL：抽取、转换、加载。
- ELT：先加载，再在目标平台转换。

银行核心交易通常偏 OLTP，经营分析、监管报表和用户画像通常偏 OLAP。

### 人工智能基础

- 监督学习：使用带标签样本学习输入到输出的映射。
- 无监督学习：从无标签数据中发现结构。
- 半监督学习：结合少量标签和大量无标签数据。
- 强化学习：通过奖励和环境交互学习策略。
- 深度学习：使用多层神经网络学习表示。
- 生成式 AI：生成文本、图像、音频、视频或代码。

常见训练概念：

- 训练集用于学习参数。
- 验证集用于调参和模型选择。
- 测试集用于评估泛化能力。
- 过拟合是训练集效果好但新数据效果差。
- 欠拟合是模型无法充分学习数据规律。

分类任务常见指标：

```text
准确率 = 预测正确样本数 / 总样本数
精确率 = TP / (TP + FP)
召回率 = TP / (TP + FN)
F1 = 2 × 精确率 × 召回率 / (精确率 + 召回率)
```

### 生成式人工智能

大语言模型通过大量语料学习语言模式，推理时根据上下文预测后续 token。常见工程概念包括预训练、微调、提示词、向量表示、检索增强生成和幻觉。

- RAG：先检索外部知识，再把结果提供给模型生成回答。
- 幻觉：模型生成了表面合理但事实错误的内容。
- 评估：要分别考察准确性、相关性、安全性、时延和成本。

### 银行和运营商应用

- 银行：智能客服、反欺诈、信用评估、营销推荐、运营分析、智能运维。
- 运营商：网络优化、流量预测、故障诊断、客服、边缘推理和物联网分析。

应用 AI 时还要考虑数据质量、隐私保护、模型偏差、可解释性、审计和人工复核。

## 易错点

- 云计算不是单纯把服务器搬到互联网上。
- 容器不等于虚拟机，二者隔离方式和资源开销不同。
- Kafka 是消息和事件流平台，不是关系数据库。
- 训练准确率高不代表模型泛化能力强。
- 召回率高和精确率高通常需要结合具体业务取舍。
