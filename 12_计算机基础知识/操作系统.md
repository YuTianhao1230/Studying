# 操作系统面试笔试要点

## 知识点解析

### 概述

操作系统是连接硬件和应用程序的基础软件，核心职责是管理 CPU、内存、文件、设备和并发执行。面试中常考的问题不是让人背 API，而是看候选人是否理解“资源如何被抽象、隔离、调度和保护”。

### 进程、线程和协程

进程是资源分配的基本单位，拥有独立地址空间、文件描述符、页表等资源。线程是 CPU 调度的基本单位，同一进程内的线程共享地址空间和大部分资源，但有各自的栈、寄存器和线程上下文。

协程是用户态的轻量级执行单元，调度通常由语言运行时或框架完成，切换成本低，但如果协程执行阻塞系统调用，可能阻塞所在的线程。

| 对比项 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 资源隔离 | 强 | 弱，共享进程资源 | 更弱，依赖运行时 |
| 切换成本 | 高 | 中 | 低 |
| 调度者 | 操作系统 | 操作系统 | 用户态运行时 |
| 常见用途 | 服务隔离、多进程并行 | 并发任务、共享内存计算 | 高并发 IO、异步任务 |

### 进程通信

常见 IPC 方式包括管道、消息队列、共享内存、信号量、Socket 和文件。共享内存速度快，因为数据不需要在内核和用户空间反复拷贝，但需要配合同步机制避免竞态。Socket 支持跨机器通信，是分布式系统的基础。

### 用户态和内核态

用户态运行普通应用程序，权限受限；内核态运行操作系统内核，能直接访问硬件和关键资源。区分二者是为了安全隔离和系统稳定。应用程序要访问文件、网络、进程管理等能力时，需要通过系统调用进入内核态。

### 上下文切换

上下文切换是 CPU 从一个执行实体切到另一个执行实体时保存和恢复寄存器、程序计数器、栈指针、页表等状态的过程。频繁上下文切换会带来 CPU 开销和缓存失效，因此高并发系统需要控制线程数量，避免无意义的切换。

### 进程调度

调度算法决定 CPU 分给谁。常见算法包括先来先服务、短作业优先、时间片轮转、优先级调度和多级反馈队列。面试重点通常是理解吞吐量、响应时间、公平性和饥饿问题之间的取舍。

### 同步、互斥和锁

互斥解决同一时间只能有一个执行单元访问临界区的问题；同步解决多个执行单元之间的先后顺序问题。常见机制包括互斥锁、读写锁、自旋锁、条件变量、信号量和原子操作。

自旋锁不会让线程睡眠，而是在 CPU 上循环等待，适合锁持有时间极短的场景；互斥锁在竞争失败时可能阻塞线程，适合临界区较长的场景。

### 死锁

死锁通常需要四个必要条件同时成立：

- 互斥：资源不能被多个线程同时占用。
- 请求并保持：持有资源的同时继续请求新资源。
- 不可剥夺：资源不能被强制抢走。
- 循环等待：多个线程形成资源等待环。

破坏任意一个条件都可以预防死锁。工程上常用的做法是固定加锁顺序、减少锁粒度、加超时和回滚、使用死锁检测。

### 内存管理

操作系统通过虚拟内存给每个进程提供独立连续的地址空间。虚拟地址通过页表映射到物理地址，这样可以实现进程隔离、按需加载、内存共享和换页。

分页把内存拆成固定大小的页，避免外部碎片；分段按逻辑模块划分，便于表达代码段、数据段、堆、栈等逻辑结构，但容易产生外部碎片。现代系统通常以分页为主。

### 虚拟内存和缺页中断

虚拟内存允许程序使用比物理内存更大的地址空间。页面真正被访问时，如果不在物理内存中，会触发缺页中断，由操作系统把页面从磁盘加载到内存。缺页太多会导致频繁换页，严重时出现 thrashing，系统大部分时间都在换页而不是执行程序。

### 文件系统和 IO

文件系统负责把磁盘块组织成文件和目录，并维护元数据。IO 可以分为阻塞 IO、非阻塞 IO、IO 多路复用、异步 IO。高并发网络服务常用 epoll 这类 IO 多路复用机制，用少量线程管理大量连接。

## 笔试常考

### 复杂度与计算题

- 给定页大小和虚拟地址位数，计算页号、页内偏移、页表项数量。
- 给定访问序列和物理页框数，手算 FIFO、LRU、OPT 缺页次数。
- 给定进程到达时间和运行时间，计算 FCFS、SJF、RR 下的平均等待时间和周转时间。
- 给定资源分配表，判断是否安全状态，使用银行家算法找安全序列。

### 高频判断题

- 线程共享进程地址空间，但不共享各自的栈和寄存器上下文。
- 死锁的四个必要条件同时成立才可能死锁。
- 自旋锁适合短临界区，不适合长时间等待。
- 虚拟内存不是凭空增加物理内存，而是通过地址映射和换页扩展可用地址空间。
- 页表项通常包含物理页框号、有效位、访问位、修改位和权限位。

## 央国企与大厂查漏补缺

### 操作系统基本特征

现代操作系统的基本特征包括并发、共享、虚拟和异步。其中并发和共享是最基本的特征。并发表示多个程序在宏观上同时推进；共享表示系统资源可以被多个进程共同使用；虚拟表示把一个物理资源抽象成多个逻辑资源；异步表示进程执行速度不可预知，需要依靠调度和同步保证正确性。

### 进程状态转换

常见进程状态包括就绪、运行、阻塞。就绪态表示具备运行条件但等待 CPU；运行态表示正在占用 CPU；阻塞态表示等待 IO、锁、信号量等事件。时间片用完通常从运行态回到就绪态；等待 IO 会从运行态进入阻塞态；IO 完成后从阻塞态回到就绪态。

### 孤儿进程和僵尸进程

孤儿进程是父进程先退出、子进程仍在运行的进程，通常会被 init 或 systemd 接管。僵尸进程是子进程已经退出，但父进程还没有调用 wait/waitpid 回收退出状态，导致进程表项暂时保留。僵尸进程本身不再运行，但大量僵尸进程会占用进程表资源。

### PV 操作和信号量

信号量用于控制并发访问资源。P 操作表示申请资源，信号量减一，如果结果小于零则阻塞；V 操作表示释放资源，信号量加一，如果有等待进程则唤醒。互斥信号量初值通常为 1，资源计数信号量初值通常为可用资源数量。

### 页面置换算法

常见页面置换算法：

| 算法 | 思路 | 特点 |
| --- | --- | --- |
| FIFO | 淘汰最早进入内存的页面 | 简单，但可能出现 Belady 异常 |
| LRU | 淘汰最近最久未使用的页面 | 符合局部性，但精确实现成本较高 |
| OPT | 淘汰未来最长时间不会访问的页面 | 理论最优，实际不可直接实现 |
| Clock | 用访问位近似 LRU | 实现成本较低，工程常用 |

### 段页式存储

分页按固定大小管理内存，便于消除外部碎片；分段按逻辑模块管理内存，便于共享和保护。段页式存储先按逻辑段划分，再在每个段内分页，兼顾逻辑表达和物理内存管理，但地址转换过程更复杂。

### Linux 排查命令

| 命令 | 常见用途 |
| --- | --- |
| `top` | 查看 CPU、内存、负载和进程资源占用 |
| `ps` | 查看进程状态 |
| `free` | 查看内存使用情况 |
| `df`/`du` | 查看磁盘空间和目录占用 |
| `netstat`/`ss` | 查看连接、端口和 TCP 状态 |
| `lsof` | 查看进程打开的文件和端口 |
| `strace` | 跟踪系统调用，定位阻塞在 IO、锁或系统调用的位置 |
| `iostat`/`vmstat` | 查看磁盘 IO、CPU、内存和上下文切换 |

## 面试应对

### 进程和线程有什么区别？

回答思路：从资源归属、调度、通信成本和故障隔离四点回答。

回答模板：

进程是资源分配的基本单位，有独立地址空间和资源；线程是 CPU 调度的基本单位，同一进程内线程共享地址空间、文件描述符等资源，但有自己的栈和寄存器上下文。进程之间隔离性强，通信成本高；线程之间共享数据方便，但需要处理同步和竞态问题。工程上，如果强调隔离和稳定性会用多进程，如果强调共享内存和轻量并发会用多线程。

### 为什么需要虚拟内存？

回答思路：强调抽象、隔离、按需加载和扩展地址空间。

回答模板：

虚拟内存给每个进程提供独立、连续的地址空间，再由页表把虚拟地址映射到物理地址。它的好处有三点：第一是进程隔离，一个进程不能随便访问另一个进程的内存；第二是简化编程，程序看到的是连续地址；第三是支持按需加载和换页，只有真正访问的页面才需要进入物理内存。代价是地址转换和缺页中断会带来额外开销。

### 死锁怎么产生，怎么解决？

回答思路：先说四个条件，再说预防、避免、检测和恢复。

回答模板：

死锁产生需要互斥、请求并保持、不可剥夺和循环等待四个条件同时成立。解决思路可以分几类：预防是破坏这些条件，比如统一加锁顺序来破坏循环等待；避免是运行前判断资源分配是否安全，例如银行家算法；检测是运行中发现等待环；恢复是超时回滚、释放资源或终止部分任务。工程里最常用的是固定锁顺序、缩小临界区和加超时。

### epoll 为什么适合高并发？

回答思路：对比阻塞 IO 和 select/poll，强调事件驱动和就绪通知。

回答模板：

epoll 适合高并发连接，因为它不是为每个连接创建一个阻塞线程，而是让内核维护关注的 fd 集合，应用只处理已经就绪的事件。相比 select/poll 每次都需要线性扫描 fd 集合，epoll 在大量连接但活跃连接较少的场景下开销更低。它的本质优势是事件驱动、减少无效轮询和线程上下文切换。
