# 哈希表

## 知识点解析

### 概述

哈希表是笔试和面试都高频的数据结构，常用于去重、计数、两数之和、前缀和统计和缓存索引。Java 面试还会追问 HashMap。

### 核心机制

哈希表通过 hash 函数把 key 映射到桶。理想情况下 key 分布均匀，每个桶元素很少，所以查找、插入、删除平均 O(1)。

哈希冲突解决方式：

- 链地址法：同一个桶里的元素用链表或树组织。
- 开放寻址法：冲突后继续探测其他位置。

### HashMap 高频点

- JDK 1.8 底层是数组 + 链表/红黑树。
- 容量是 2 的幂，便于用 `(n - 1) & hash` 定位桶。
- 负载因子过高会扩容，降低冲突概率。
- HashMap 线程不安全，并发场景用 ConcurrentHashMap。

## 面试应对

### 哈希表为什么平均 O(1)？

回答思路：hash 分桶、均匀分布、冲突退化。

回答模板：

哈希表通过 hash 函数把 key 映射到桶，理想情况下 key 分布均匀，每个桶里的元素很少，所以查找、插入、删除平均是 O(1)。但如果 hash 冲突严重，很多 key 落到同一个桶里，就需要在桶内继续查找，最坏可能退化到 O(n)。因此哈希表性能依赖 hash 函数、负载因子和扩容策略。

### HashMap 为什么容量通常是 2 的幂？

回答思路：位运算定位桶，减少冲突。

回答模板：

HashMap 容量取 2 的幂，可以用 `(n - 1) & hash` 快速计算桶下标，比取模更高效。同时当 n 是 2 的幂时，`n - 1` 的低位全是 1，可以更好利用 hash 的低位信息，帮助元素分布更均匀。扩容时元素位置也更容易判断，要么留在原位置，要么移动到原位置加旧容量。
