## 知识点解析

### 概述

数据结构与算法是笔试和技术面试的基础能力，核心不是背题，而是根据数据规模、访问模式和约束条件选择合适的数据结构，并能分析时间复杂度和空间复杂度。笔试侧重编码正确性和边界条件，面试侧重思路表达、复杂度分析和优化过程。

### 复杂度分析

时间复杂度描述输入规模增长时算法运行时间的增长趋势，空间复杂度描述额外空间占用。常见复杂度从低到高大致是：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n)
```

分析复杂度时要关注循环层数、递归深度、每层工作量和数据结构操作成本。例如哈希表平均查找是 O(1)，但最坏情况下可能退化；平衡二叉搜索树查找是 O(log n)，有序数组二分查找是 O(log n)，但插入删除可能是 O(n)。

### 数组和链表

数组支持 O(1) 随机访问，但插入删除通常需要移动元素。链表插入删除节点方便，但查找第 k 个元素需要 O(n)。面试中常用数组处理连续区间、前缀和、双指针和滑动窗口；链表常考反转、快慢指针、环检测、合并链表。

### 栈和队列

栈是后进先出，常用于括号匹配、单调栈、表达式求值、DFS。队列是先进先出，常用于 BFS、层序遍历、任务调度。单调队列常用于滑动窗口最大值，单调栈常用于下一个更大元素、柱状图最大矩形。

### 哈希表

哈希表通过哈希函数把 key 映射到桶，平均 O(1) 查找、插入和删除。哈希冲突常见解决方法包括链地址法和开放寻址法。面试中常用于去重、计数、两数之和、前缀和计数、缓存索引。

### 树和二叉树

二叉树常考递归遍历、层序遍历、最近公共祖先、路径和、树的直径。二叉搜索树满足左子树小于根、右子树大于根，中序遍历有序。平衡树通过旋转控制高度，保证查找、插入和删除接近 O(log n)。

### 堆

堆是一种完全二叉树，常用于动态维护最大值或最小值。优先队列通常基于堆实现，插入和删除堆顶是 O(log n)，查询堆顶是 O(1)。常见题型包括 Top K、合并 K 个有序链表、数据流中位数。

### 图

图由点和边组成，常用邻接矩阵或邻接表表示。邻接矩阵适合稠密图，查询两点是否相连是 O(1)，但空间 O(n^2)；邻接表适合稀疏图，空间更省。图算法高频包括 BFS、DFS、拓扑排序、最短路、最小生成树、并查集。

### 排序

常见排序算法：

| 算法 | 平均时间 | 最坏时间 | 空间 | 稳定性 |
| --- | --- | --- | --- | --- |
| 冒泡排序 | O(n^2) | O(n^2) | O(1) | 稳定 |
| 插入排序 | O(n^2) | O(n^2) | O(1) | 稳定 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 快速排序 | O(n log n) | O(n^2) | O(log n) | 不稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 不稳定 |

快速排序平均性能好，但在极端划分下会退化；归并排序稳定且适合链表和外部排序；堆排序空间占用低，但缓存局部性通常不如快速排序。

### 二分搜索

二分搜索适合有序数组，也适合“答案具有单调性”的问题。关键是定义搜索区间、判断条件和边界收缩方式。笔试中很多题不是直接二分数组，而是二分答案，例如最小可行速度、最大可分配资源、满足条件的最小容量。

### 动态规划

动态规划适用于问题具有最优子结构和重叠子问题的场景。设计步骤：

1. 定义状态。
2. 写出状态转移方程。
3. 确定初始化。
4. 确定遍历顺序。
5. 考虑是否能做空间优化。

常见类型包括背包问题、子序列问题、区间 DP、树形 DP、状态压缩 DP。面试中要能解释状态含义，而不是只写公式。

## 笔试常考

### 高频题型

- 双指针：两数之和、三数之和、接雨水、移除重复元素。
- 滑动窗口：最长无重复子串、最小覆盖子串、窗口最大值。
- 前缀和：子数组和、区间求和、差分数组。
- 单调栈：下一个更大元素、每日温度、柱状图最大矩形。
- BFS/DFS：岛屿数量、最短路径、树遍历、回溯搜索。
- 动态规划：最长递增子序列、最长公共子序列、编辑距离、背包。
- 并查集：连通分量、朋友圈、冗余连接。
- 堆：Top K、数据流中位数、合并多个有序结构。

### 边界条件

- 空数组、单元素数组、重复元素、负数。
- 链表为空、只有一个节点、有环。
- 树为空、只有根节点、左右子树高度差极大。
- 图不连通、有环、自环、重边。
- DP 的初始状态和越界处理。

## 央国企与大厂查漏补缺

### 递归

递归函数必须有明确的结束条件，否则会无限递归直到栈溢出。一个完整递归通常包括递归边界、递归前进段和递归返回段。笔试中经常考“递归就是函数直接或间接调用自身”这类定义题，也常考斐波那契、树遍历、全排列、回溯搜索。

### 二叉树遍历

二叉树遍历顺序：

- 前序遍历：根、左、右。
- 中序遍历：左、根、右。
- 后序遍历：左、右、根。
- 层序遍历：按层从左到右，通常用队列。

二叉搜索树的中序遍历结果是有序序列，这是很多题目的隐含条件。

### 哈夫曼树

哈夫曼树用于构造带权路径长度最小的二叉树。构造方法是每次选择权值最小的两个节点合并成新节点，再把新节点放回集合，直到只剩一个根节点。哈夫曼编码是前缀编码，任一字符编码都不是另一个字符编码的前缀，适合无损压缩。

### KMP 字符串匹配

KMP 用 next 数组记录模式串前缀和后缀的最长匹配长度。当匹配失败时，主串指针不回退，模式串根据 next 数组跳转，从而把匹配复杂度降到 O(n+m)。笔试中常考 next 数组含义、字符串匹配次数和模式串回退位置。

### 图算法补充

| 算法 | 解决问题 | 关键限制 |
| --- | --- | --- |
| BFS | 无权图最短路、层次遍历 | 边权相同或不考虑权重 |
| DFS | 连通性、拓扑搜索、回溯 | 注意递归深度和 visited |
| Dijkstra | 单源最短路 | 边权不能为负 |
| Floyd | 多源最短路 | O(n^3)，适合点数较少 |
| Kruskal | 最小生成树 | 常配合并查集 |
| Prim | 最小生成树 | 适合稠密图 |
| 拓扑排序 | 有向无环图依赖顺序 | 图中不能有环 |

### 特殊矩阵和压缩存储

央国企笔试会考特殊矩阵的压缩存储。对称矩阵只需存上三角或下三角；三角矩阵只需存非零三角部分和一个常量；稀疏矩阵常用三元组 `(row, col, value)` 存储。核心是理解“逻辑位置”和“压缩数组下标”的映射关系。

### LRU

LRU，Least Recently Used，淘汰最近最久未使用的数据。典型实现是哈希表 + 双向链表：哈希表保证 O(1) 查找节点，双向链表维护访问顺序，每次访问把节点移动到头部，容量满时淘汰尾部节点。它常用于缓存、页面置换和热点数据管理。

### Top K

Top K 问题常用堆解决。求最大的 K 个元素，用大小为 K 的小根堆；遍历元素时，如果当前元素大于堆顶，就替换堆顶并调整堆。复杂度是 O(n log K)，适合 K 远小于 n 的场景。数据量特别大时，还可以结合分治、外部排序或哈希分桶。

## 面试应对

### 数组和链表怎么选？

回答思路：从访问、插入删除、内存布局和使用场景回答。

回答模板：

数组适合需要随机访问和连续遍历的场景，因为可以通过下标 O(1) 访问，缓存局部性也好，但中间插入删除需要移动元素。链表适合频繁插入删除且不需要随机访问的场景，修改指针就能完成插入删除，但查找位置需要 O(n)，缓存局部性也差。工程上如果读多查多通常用数组或动态数组，如果频繁在已知节点附近插入删除才考虑链表。

### 哈希表为什么平均 O(1)？

回答思路：说明哈希映射和冲突处理，再补充最坏情况。

回答模板：

哈希表通过哈希函数把 key 映射到桶，理想情况下 key 分布均匀，每个桶里的元素很少，所以查找、插入和删除平均可以认为是 O(1)。但如果哈希冲突严重，很多 key 落到同一个桶里，链地址法可能退化成链表查找，最坏是 O(n)。所以哈希表的性能依赖哈希函数、负载因子和扩容策略。

### 快排、归并和堆排怎么比较？

回答思路：从复杂度、稳定性、空间和工程表现回答。

回答模板：

快速排序平均 O(n log n)，原地排序，缓存友好，工程上常用，但最坏可能退化到 O(n^2)，而且不稳定。归并排序稳定，最坏也是 O(n log n)，适合链表排序和外部排序，但需要 O(n) 额外空间。堆排序最坏 O(n log n)，额外空间 O(1)，但不稳定，缓存局部性一般。选择时要看是否要求稳定、是否能接受额外空间，以及数据分布是否可能让快排退化。

### 动态规划题怎么讲思路？

回答思路：固定按状态、转移、初始化、遍历顺序、复杂度回答。

回答模板：

我会先判断这个问题有没有重叠子问题和最优子结构。如果适合 DP，就先定义状态，比如 dp[i] 表示前 i 个元素的最优解，或者 dp[i][j] 表示两个前缀之间的关系。然后根据最后一步选择写状态转移，接着确定边界初始化和遍历顺序，最后分析时间和空间复杂度。如果状态只依赖上一层或前几个状态，再考虑滚动数组做空间优化。
