## 知识点解析

### 概述

计算机组成原理关注程序在硬件上如何执行，核心包括数据表示、指令系统、CPU、存储层次、总线、IO 和性能指标。面试中它常和操作系统、编译、性能优化结合出现，例如 Cache 为什么快、CPU 为什么需要流水线、浮点数为什么有精度误差。

### 数据表示

整数通常用补码表示。补码的好处是加减法可以统一用加法器处理，并且只有一个零。对于 n 位有符号整数，补码表示范围是：

```text
-2^(n-1) 到 2^(n-1)-1
```

浮点数通常遵循 IEEE 754，由符号位、指数位和尾数位组成。浮点数能表示很大或很小的数，但不能精确表示所有小数，例如 0.1 在二进制中无法有限表示，所以浮点运算可能有误差。

### CPU 基本组成

CPU 主要包括运算器、控制器、寄存器和 Cache。控制器负责取指、译码和控制执行流程；运算器负责算术和逻辑运算；寄存器保存当前计算所需的高速数据；Cache 缓解 CPU 和内存速度差距。

### 指令执行过程

一条指令通常经历取指、译码、执行、访存、写回等阶段。程序计数器 PC 保存下一条要执行的指令地址，指令寄存器保存当前指令，通用寄存器保存操作数和中间结果。

### 流水线

流水线把指令执行拆成多个阶段，让多条指令在不同阶段并行推进，从而提高吞吐量。流水线提升的是单位时间完成的指令数，不一定降低单条指令的延迟。

流水线冲突包括：

- 结构冲突：硬件资源不够。
- 数据冲突：后续指令依赖前面指令结果。
- 控制冲突：分支跳转导致下一条指令不确定。

解决方法包括转发、暂停、分支预测和乱序执行。

### Cache

Cache 利用局部性原理提升访问速度：

- 时间局部性：最近访问过的数据，短期内可能再次访问。
- 空间局部性：访问某个地址后，附近地址也可能被访问。

Cache 命中时直接从高速缓存读取，未命中时需要从更低层存储加载。常见映射方式包括直接映射、全相联映射和组相联映射。

### Cache 一致性

多核 CPU 中，每个核心可能有自己的 Cache。如果多个核心缓存了同一内存地址，就需要一致性协议保证读写结果一致。典型协议如 MESI，通过 Modified、Exclusive、Shared、Invalid 状态协调缓存行。

### 存储层次

存储系统通常按速度和容量分层：

```text
寄存器 -> L1 Cache -> L2 Cache -> L3 Cache -> 内存 -> SSD/HDD
```

越靠近 CPU，速度越快、容量越小、成本越高。程序性能优化常关注减少内存访问、提高 Cache 命中率和顺序访问。

### 总线和 IO

总线用于连接 CPU、内存和外设。IO 方式包括程序查询、中断和 DMA。DMA 允许外设直接和内存交换数据，减少 CPU 参与，适合大块数据传输。

### 中断

中断是外设或异常事件打断 CPU 当前执行流程的机制。CPU 响应中断时会保存现场，跳转到中断处理程序，处理完成后恢复现场继续执行。中断让 CPU 不必一直轮询设备状态。

### 性能指标

常见性能指标包括主频、CPI、IPC、吞吐量、延迟。程序执行时间可以粗略表示为：

```text
CPU 时间 = 指令数 × CPI × 时钟周期时间
```

优化性能可以从减少指令数、降低 CPI、提高主频三个方向入手，但现代系统还要考虑内存访问、分支预测、并行度和 IO。

## 笔试常考

### 计算题

- 补码范围、补码加减法、溢出判断。
- Cache 地址划分：标记位、组索引、块内偏移。
- 平均访存时间 AMAT：

```text
AMAT = 命中时间 + 缺失率 × 缺失代价
```

- CPI 和程序执行时间计算。
- 流水线加速比和吞吐量计算。

### 高频判断题

- 流水线提高吞吐量，不一定降低单条指令延迟。
- Cache 命中率高通常能明显提升性能。
- 顺序访问数组通常比随机访问链表更容易利用 Cache。
- DMA 可以减少 CPU 在大块 IO 传输中的参与。
- 浮点数不能精确表示所有十进制小数。

## 央国企与大厂查漏补缺

### 单位换算

计组和操作系统里常用二进制换算：

```text
1 KB = 2^10 B
1 MB = 2^20 B
1 GB = 2^30 B
```

网络带宽常用十进制换算：

```text
1 Kb/s = 10^3 b/s
1 Mb/s = 10^6 b/s
1 Gb/s = 10^9 b/s
```

注意 `B` 是 Byte，字节；`b` 是 bit，比特；`1B = 8b`。

### 进制换算

计算机组成原理笔试常考二进制、八进制、十进制和十六进制之间的换算。二进制转十进制按权展开，例如 `1011B = 1×2^3 + 0×2^2 + 1×2^1 + 1×2^0 = 11D`。十进制整数转二进制通常用除 2 取余并倒序排列。

八进制和十六进制与二进制换算更适合分组记忆：

- 1 位八进制对应 3 位二进制。
- 1 位十六进制对应 4 位二进制。
- 十六进制 `A-F` 分别表示十进制 `10-15`。

例如：

```text
101101B = 101 101B = 55O
101101B = 0010 1101B = 2DH
```

笔试中要特别注意题目使用的是位还是字节，以及地址位数、存储容量和可寻址单元之间的关系。

### 原码、反码、补码

正数的原码、反码、补码相同。负数的反码是在原码基础上符号位不变、数值位取反；补码是在反码基础上加 1。计算机用补码表示有符号整数，是因为补码可以把加法和减法统一成加法，并且只有一个 0。

### 溢出判断

有符号数加法中，两个正数相加得到负数，或两个负数相加得到正数，说明发生溢出。一个正数和一个负数相加不会发生有符号溢出。

### 寻址方式

常见寻址方式：

| 寻址方式 | 含义 |
| --- | --- |
| 立即寻址 | 操作数直接写在指令中 |
| 直接寻址 | 指令给出操作数所在内存地址 |
| 间接寻址 | 指令给出地址的地址 |
| 寄存器寻址 | 操作数在寄存器中 |
| 寄存器间接寻址 | 寄存器中保存操作数地址 |
| 变址寻址 | 基址或变址寄存器加偏移量 |

### Cache 地址划分

Cache 计算题常把主存地址划分成标记、组索引和块内偏移：

```text
主存地址 = Tag + Index + Offset
```

块内偏移位数由块大小决定；组索引位数由 Cache 组数决定；剩余高位是标记位。直接映射每组一行，组相联每组多行，全相联没有固定组索引。

### 总线

总线按传输内容常分为数据总线、地址总线和控制总线。数据总线传输数据，宽度影响一次能传多少数据；地址总线传输地址，宽度影响可寻址空间；控制总线传输读写、中断、时钟等控制信号。

### 中断类型

中断可以分为外中断和内中断。外中断来自 CPU 外部设备，例如键盘、网卡、磁盘；内中断来自 CPU 执行指令过程中产生的异常，例如除零、缺页、非法指令。系统调用也可以通过软中断或陷入机制进入内核。

### 流水线计算

如果一条指令被拆成 k 个阶段，每个阶段耗时相近，执行 n 条指令的流水线总时间近似为：

```text
(k + n - 1) × 时钟周期
```

理想加速比接近 k，但实际会受数据冲突、控制冲突、结构冲突和流水线寄存器开销影响。

### 大端和小端

大端序把数据高位字节放在低地址，小端序把数据低位字节放在低地址。网络字节序通常采用大端序，x86 机器通常采用小端序。涉及跨平台二进制协议时需要特别注意字节序。

## 面试应对

### 为什么需要 Cache？

回答思路：从 CPU 和内存速度差距、局部性原理、命中和未命中回答。

回答模板：

CPU 的执行速度远高于内存访问速度，如果每次都直接访问内存，CPU 会大量等待。Cache 是放在 CPU 和内存之间的高速缓存，利用时间局部性和空间局部性，把最近访问或相邻的数据放到更快的存储层里。命中 Cache 时访问很快，未命中才去低层存储取数据。所以程序如果能顺序访问、重复访问热点数据，通常会有更好的 Cache 命中率和性能。

### 流水线为什么能提升性能？

回答思路：说明阶段拆分、并行推进、吞吐量提升，再补充冲突。

回答模板：

流水线把一条指令的执行拆成取指、译码、执行、访存、写回等阶段，让多条指令在不同阶段同时推进。这样单条指令的执行时间不一定变短，但单位时间内完成的指令数增加了，所以吞吐量提升。流水线也会遇到结构冲突、数据冲突和控制冲突，需要通过转发、暂停、分支预测等机制处理。

### 什么是局部性原理？

回答思路：分别解释时间局部性和空间局部性，并联系 Cache。

回答模板：

局部性原理是程序访问数据和指令时呈现出的规律。时间局部性指最近访问过的数据，短时间内可能再次访问；空间局部性指访问某个地址后，附近地址也可能被访问。Cache 正是利用这个规律，把最近或相邻的数据加载到高速缓存中，从而减少访问内存的次数。数组顺序遍历通常比链表随机跳转更快，一个重要原因就是空间局部性更好。

### 为什么浮点数会有精度误差？

回答思路：说明二进制有限位表示和尾数位限制。

回答模板：

浮点数用有限的符号位、指数位和尾数位表示实数，但很多十进制小数在二进制里不能有限表示，比如 0.1，所以只能近似存储。参与运算时，尾数位有限还会带来舍入误差。浮点数的优势是能表示很大或很小的数，但它不是精确小数，所以涉及金额等精确计算时通常不能直接用普通浮点数。
