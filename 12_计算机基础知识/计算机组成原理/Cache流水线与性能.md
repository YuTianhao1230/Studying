# Cache流水线与性能

## 知识点解析

### 概述

本文整理 Cache、流水线和 CPU 性能指标，包括局部性、地址划分、平均访存时间、流水线冲突、CPI 和执行时间。

### 局部性原理

时间局部性表示最近访问过的数据，短期内可能再次访问；空间局部性表示访问某个地址后，附近地址也可能被访问。Cache 利用局部性把热点数据放到高速存储中，减少访问主存的次数。

### Cache 地址划分

Cache 题常把地址划分为：

```text
Tag + Index + Offset
```

Offset 由块大小决定，Index 由 Cache 组数决定，剩余高位是 Tag。直接映射每组一行，组相联每组多行，全相联没有固定组索引。

计算步骤：

```text
块内偏移位数 = log2(块大小)
Cache 行数 = Cache 数据容量 / 块大小
组数 = Cache 行数 / 每组行数
组索引位数 = log2(组数)
Tag 位数 = 主存地址位数 - 组索引位数 - 块内偏移位数
```

直接映射等价于每组 1 行，全相联等价于只有 1 组。

### 平均访存时间

```text
AMAT = 命中时间 + 缺失率 × 缺失代价
```

降低 AMAT 可以提高命中率、降低缺失代价或降低命中时间。

多级 Cache 常从内向外展开。例如：

```text
AMAT = L1 命中时间
     + L1 缺失率 × (L2 命中时间 + L2 缺失率 × 主存代价)
```

### 流水线

流水线把指令执行拆成取指、译码、执行、访存、写回等阶段，让多条指令在不同阶段并行推进。它提升吞吐量，不一定降低单条指令延迟。

流水线冲突包括结构冲突、数据冲突和控制冲突。常见解决方法包括暂停、转发、分支预测和乱序执行。

理想情况下，k 级流水线执行 n 条指令的时间为：

```text
(k + n - 1) × 时钟周期
```

流水线加速比需要用“非流水时间 / 流水时间”计算。实际还要考虑阶段耗时不均、流水线寄存器开销和冲突停顿。

### 性能公式

```text
CPU 时间 = 指令数 × CPI × 时钟周期时间
```

优化性能可以从减少指令数、降低 CPI、提高主频入手，但实际还要考虑 Cache miss、分支预测、IO 和并行度。

如果不同类型指令数量和 CPI 不同：

```text
平均 CPI = Σ(某类指令比例 × 该类 CPI)
CPU 时间 = 指令数 × 平均 CPI / 主频
```

### 常见考法与解题步骤

| 题型 | 解题步骤 |
| --- | --- |
| Cache 地址划分 | 先偏移位，再组索引位，剩余为 Tag |
| Cache 命中判断 | 求主存块号、组号和 Tag，再模拟替换 |
| AMAT | 按各级命中和未命中概率计算期望 |
| 流水线总时间 | 先求时钟周期，再算装入、稳定和排空 |
| 流水线冲突 | 判断资源、数据依赖还是分支 |
| CPU 性能 | 统一单位后代入指令数、CPI、主频 |
| 加速比 | 原执行时间除以优化后执行时间 |

### 易错点

- Cache 容量题要确认是否只计算数据区，还是包含 Tag、有效位和脏位。
- 地址按字节还是按字编址会影响偏移位。
- 流水线提高吞吐，不保证单条指令延迟降低。
- 主频提高不代表程序一定同比加速，CPI 和访存瓶颈也会变化。
- 命中率是条件概率，多级 Cache 题要区分局部命中率和全局命中率。

## 面试应对

### Cache 为什么能提升性能？

回答思路：CPU 和内存速度差距、局部性、命中率。

回答模板：

CPU 比内存快很多，如果每次都访问内存，CPU 会大量等待。Cache 位于 CPU 和内存之间，利用时间局部性和空间局部性，把最近访问或相邻的数据放在更快的存储层里。命中 Cache 时访问很快，未命中才访问低层存储。所以顺序访问数组通常比随机访问链表更快，一个重要原因就是 Cache 友好。

### 流水线为什么提高吞吐？

回答思路：阶段并行，吞吐和延迟区分。

回答模板：

流水线把一条指令的执行拆成多个阶段，让多条指令在不同阶段同时推进。这样单条指令的延迟不一定降低，但单位时间完成的指令数增加了，所以吞吐量提升。流水线也会遇到结构冲突、数据冲突和控制冲突，需要通过转发、暂停、分支预测等机制处理。

### Cache 地址划分题怎么做？

回答思路：按 Offset、Index、Tag 顺序计算。

回答模板：

我会先根据块大小计算块内偏移位数，再用 Cache 容量除以块大小得到总行数，用总行数除以相联度得到组数，从而计算组索引位数，地址剩余高位就是 Tag。最后还要确认题目是按字节还是按字编址，以及容量是否包含标记位等额外开销。

### 如何比较两台 CPU 的性能？

回答思路：使用完整执行时间，不单看主频。

回答模板：

不能只比较主频，程序 CPU 时间由指令数、平均 CPI 和时钟周期共同决定，即 `CPU 时间 = 指令数 × CPI / 主频`。不同架构可能执行不同数量的指令，CPI 也会受到流水线、Cache miss 和分支预测影响。因此应该在相同工作负载下比较实际执行时间，并结合吞吐、功耗等目标判断。
