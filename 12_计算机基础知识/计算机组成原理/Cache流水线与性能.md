# Cache流水线与性能

## 知识点解析

### 概述

Cache、流水线和性能指标解释了 CPU 为什么快，以及程序为什么会受内存访问、分支预测和指令执行效率影响。大厂面试常结合性能优化追问，央国企笔试常考公式。

### 局部性原理

时间局部性表示最近访问过的数据，短期内可能再次访问；空间局部性表示访问某个地址后，附近地址也可能被访问。Cache 利用局部性把热点数据放到高速存储中，减少访问主存的次数。

### Cache 地址划分

Cache 题常把地址划分为：

```text
Tag + Index + Offset
```

Offset 由块大小决定，Index 由 Cache 组数决定，剩余高位是 Tag。直接映射每组一行，组相联每组多行，全相联没有固定组索引。

### 平均访存时间

```text
AMAT = 命中时间 + 缺失率 × 缺失代价
```

降低 AMAT 可以提高命中率、降低缺失代价或降低命中时间。

### 流水线

流水线把指令执行拆成取指、译码、执行、访存、写回等阶段，让多条指令在不同阶段并行推进。它提升吞吐量，不一定降低单条指令延迟。

流水线冲突包括结构冲突、数据冲突和控制冲突。常见解决方法包括暂停、转发、分支预测和乱序执行。

### 性能公式

```text
CPU 时间 = 指令数 × CPI × 时钟周期时间
```

优化性能可以从减少指令数、降低 CPI、提高主频入手，但实际还要考虑 Cache miss、分支预测、IO 和并行度。

## 面试应对

### Cache 为什么能提升性能？

回答思路：CPU 和内存速度差距、局部性、命中率。

回答模板：

CPU 比内存快很多，如果每次都访问内存，CPU 会大量等待。Cache 位于 CPU 和内存之间，利用时间局部性和空间局部性，把最近访问或相邻的数据放在更快的存储层里。命中 Cache 时访问很快，未命中才访问低层存储。所以顺序访问数组通常比随机访问链表更快，一个重要原因就是 Cache 友好。

### 流水线为什么提高吞吐？

回答思路：阶段并行，吞吐和延迟区分。

回答模板：

流水线把一条指令的执行拆成多个阶段，让多条指令在不同阶段同时推进。这样单条指令的延迟不一定降低，但单位时间完成的指令数增加了，所以吞吐量提升。流水线也会遇到结构冲突、数据冲突和控制冲突，需要通过转发、暂停、分支预测等机制处理。
