# 信息安全

## 知识点解析

### 概述

信息安全在银行、央国企和互联网面试中都常见。银行更关注数据安全、权限、审计和合规；大厂更常结合 Web 安全、接口安全和账号体系追问。

### CIA

信息安全三要素：

- 机密性：防止未授权访问。
- 完整性：防止数据被篡改。
- 可用性：保证系统持续可用。

### 常见攻击

| 攻击 | 含义 | 防护 |
| --- | --- | --- |
| SQL 注入 | 恶意 SQL 被拼接执行 | 参数化查询、输入校验、最小权限 |
| XSS | 页面注入恶意脚本 | 输出转义、CSP、HttpOnly |
| CSRF | 借用户登录态伪造请求 | CSRF Token、SameSite、二次确认 |
| DDoS | 大流量耗尽资源 | 清洗、限流、黑名单、弹性扩容 |
| 中间人攻击 | 拦截或篡改通信 | HTTPS、证书校验、HSTS |

### 加密

对称加密同一密钥加解密，速度快，适合大量数据加密，典型算法 AES。非对称加密使用公钥和私钥，适合密钥交换和身份认证，典型算法 RSA、ECC。哈希用于生成摘要，常用于完整性校验。

### 认证和授权

认证回答“你是谁”，授权回答“你能做什么”。常见方案包括 Session、Token、JWT、OAuth。JWT 适合无状态认证，但签发后吊销较麻烦，需要配合短过期时间、刷新机制或黑名单。

## 面试应对

### SQL 注入怎么防？

回答思路：参数化查询是核心，再补权限和审计。

回答模板：

SQL 注入是攻击者把恶意 SQL 放到输入里，如果服务端直接拼接 SQL，就可能改变查询逻辑。防护核心是使用参数化查询或预编译语句，让用户输入只作为数据而不是 SQL 代码执行。同时要做输入校验、最小权限控制、错误信息隐藏和审计告警。不要只靠前端校验，因为前端输入可以被绕过。

### 对称加密和非对称加密有什么区别？

回答思路：密钥数量、性能、用途。

回答模板：

对称加密加密和解密使用同一把密钥，速度快，适合大量数据传输，但密钥分发困难。非对称加密有公钥和私钥，公钥可以公开，私钥保密，适合身份认证和密钥交换，但性能较低。HTTPS 中通常先用非对称加密或密钥交换算法协商会话密钥，再用对称加密传输业务数据。
