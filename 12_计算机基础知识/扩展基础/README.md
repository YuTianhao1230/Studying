## 知识点解析

### 概述

扩展基础主要覆盖央国企、银行科技岗和部分大厂笔试中经常出现，但不完全属于操作系统、数据库、网络、数据结构或计组的内容，包括信息安全、软件工程、设计模式、中间件、Git、云计算、5G、区块链和金融科技。它们通常不会考得特别深，但覆盖面广，容易出现在选择题、多选题和简答题中。

### 信息安全

信息安全常见目标是机密性、完整性、可用性，也就是 CIA：

- 机密性：防止未授权访问，例如加密、权限控制。
- 完整性：防止数据被篡改，例如哈希、签名、校验码。
- 可用性：保证系统持续可用，例如容灾、限流、抗 DDoS。

常见攻击：

| 攻击 | 含义 | 防护 |
| --- | --- | --- |
| SQL 注入 | 把恶意 SQL 拼进查询语句 | 参数化查询、输入校验、最小权限 |
| XSS | 在页面注入恶意脚本 | 输出转义、CSP、HttpOnly Cookie |
| CSRF | 借用户登录态发起伪造请求 | CSRF Token、SameSite Cookie、二次确认 |
| DDoS | 大量请求耗尽服务资源 | 清洗、限流、黑名单、弹性扩容 |
| 中间人攻击 | 攻击者拦截并篡改通信 | HTTPS、证书校验、HSTS |

### 加密和认证

对称加密加解密使用同一密钥，速度快，适合大量数据加密，典型算法是 AES。非对称加密使用公钥和私钥，适合身份认证和密钥交换，典型算法是 RSA、ECC。哈希函数把任意长度输入映射为固定长度摘要，常用于完整性校验和密码存储，但密码不能直接明文哈希，应该加盐并使用专门的密码哈希算法。

### 软件工程

软件工程关注如何稳定地交付软件。常见生命周期包括需求分析、概要设计、详细设计、编码、测试、部署和维护。瀑布模型适合需求稳定的项目；敏捷开发强调短周期迭代、持续反馈和快速交付；DevOps 强调开发、测试、运维协同，通过 CI/CD 提升交付效率。

### 软件测试

常见测试类型：

| 类型 | 说明 |
| --- | --- |
| 单元测试 | 测函数、类或模块 |
| 集成测试 | 测多个模块协作 |
| 系统测试 | 从整体系统角度验证 |
| 回归测试 | 验证修改没有破坏旧功能 |
| 性能测试 | 测吞吐、延迟、并发和资源 |
| 压力测试 | 测系统极限和降级能力 |
| 黑盒测试 | 只看输入输出，不关心内部实现 |
| 白盒测试 | 关注代码路径、分支和覆盖率 |

### 设计模式

常见设计模式：

- 单例模式：保证一个类只有一个实例，常用于配置、连接池、全局管理器。
- 工厂模式：把对象创建逻辑封装起来，降低调用方和具体类的耦合。
- 策略模式：把可替换算法封装成不同策略，运行时选择。
- 观察者模式：一方状态变化时通知多个订阅者，常用于事件系统。
- 代理模式：在访问对象前后增加控制逻辑，例如鉴权、缓存、日志。

### 消息队列

消息队列用于异步、解耦和削峰。常见问题包括消息丢失、重复消费、顺序消息和消息积压。解决思路：

- 消息丢失：生产者确认、Broker 持久化、消费者手动 ACK。
- 重复消费：业务幂等、去重表、唯一请求 ID。
- 顺序消息：同一业务 key 投递到同一分区或队列。
- 消息积压：扩容消费者、提高消费速度、临时降级非核心逻辑。

### 云计算

云计算常见服务模型：

- IaaS：基础设施即服务，提供虚拟机、网络、存储。
- PaaS：平台即服务，提供运行环境、中间件、数据库等平台能力。
- SaaS：软件即服务，用户直接使用应用。

常见部署形态包括公有云、私有云、混合云。央国企和银行场景常关注私有云、混合云、数据安全、合规和国产化替代。

### 5G

5G 常见特点包括增强移动宽带、低时延高可靠通信和海量机器通信。典型应用包括高清视频、工业互联网、车联网、远程医疗、物联网。三大运营商笔试可能会结合通信行业背景考 5G、边缘计算、云网融合和物联网基础概念。

### 区块链

区块链是一种分布式账本技术，核心特征包括去中心化、不可篡改、可追溯和共识机制。常见概念包括哈希、区块、链式结构、共识算法、智能合约。金融科技场景通常关注可信存证、供应链金融、跨机构数据协作，但也要注意性能、隐私和监管合规问题。

## 面试应对

### SQL 注入是什么，怎么防？

回答思路：先说攻击方式，再说参数化查询和权限控制。

回答模板：

SQL 注入是攻击者把恶意 SQL 片段放进用户输入里，如果服务端直接拼接 SQL，就可能改变原本查询逻辑，造成越权查询、篡改或删除数据。防护上最重要的是使用参数化查询或预编译语句，让输入只作为数据而不是 SQL 代码执行；同时要做输入校验、最小权限控制、错误信息隐藏和审计告警。

### 消息队列有什么作用？

回答思路：从异步、解耦、削峰回答，再补风险。

回答模板：

消息队列主要解决异步、解耦和削峰。异步是把非核心流程放到后台处理，降低主链路延迟；解耦是让生产者不直接依赖消费者；削峰是把瞬时高流量缓冲到队列里，消费者按能力处理。代价是系统复杂度上升，需要处理消息丢失、重复消费、顺序性和积压问题，所以工程上要配合持久化、ACK、幂等和监控告警。

### 银行系统为什么重视安全和一致性？

回答思路：从资金属性、监管、审计和用户信任回答。

回答模板：

银行系统处理的是资金、账户和敏感身份信息，任何数据错乱、越权访问或不可追溯操作都会带来资金风险、合规风险和用户信任损失。所以银行系统会特别重视身份认证、权限控制、加密传输、审计日志、事务一致性、幂等、对账和容灾。技术选择上通常不会只追求性能，还要在一致性、安全性、可追溯和稳定性之间做平衡。
