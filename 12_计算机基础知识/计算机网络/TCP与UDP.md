# TCP与UDP

## 知识点解析

### 概述

TCP 和 UDP 是传输层最核心的两个协议。面试常问二者区别、TCP 三次握手、四次挥手、可靠传输、流量控制和拥塞控制。

### TCP

TCP 是面向连接、可靠、有序、面向字节流的协议。它通过序列号、确认应答、重传、滑动窗口、流量控制和拥塞控制保证可靠传输。

### UDP

UDP 是无连接、尽力而为、面向数据报的协议。它不保证可靠和有序，但头部简单、延迟低，适合 DNS、实时音视频、游戏等场景。

### 三次握手

```text
客户端 -> 服务端：SYN
服务端 -> 客户端：SYN + ACK
客户端 -> 服务端：ACK
```

三次握手用于同步双方初始序列号，并确认双方收发能力。

### 四次挥手

TCP 是全双工连接，两个方向要分别关闭。主动关闭方发送 FIN，被动关闭方先 ACK，等数据发送完再 FIN，主动关闭方再 ACK。

### TIME_WAIT

TIME_WAIT 的作用是保证最后一个 ACK 可重传，并让旧连接中的延迟报文自然消失，避免影响相同四元组的新连接。

### 可靠传输

TCP 通过序列号、确认应答、超时重传、快速重传和滑动窗口保证数据可靠、有序到达。流量控制通过接收窗口避免接收方处理不过来；拥塞控制通过慢启动、拥塞避免、快重传和快恢复调整发送速度，避免网络过载。

### CLOSE_WAIT

CLOSE_WAIT 表示对端已经发送 FIN，本端也已经回复 ACK，但应用程序还没有关闭连接。大量 CLOSE_WAIT 通常说明应用没有及时执行 close，可能存在连接泄漏。

## 面试应对

### TCP 和 UDP 有什么区别？

回答思路：连接、可靠性、有序性、开销、场景。

回答模板：

TCP 是面向连接的可靠传输协议，会通过三次握手建立连接，并用序列号、ACK、重传、滑动窗口、流量控制和拥塞控制保证可靠有序传输。UDP 是无连接协议，不保证可靠和有序，但头部小、延迟低。可靠性要求高的场景，比如 HTTP、数据库连接、文件传输，通常用 TCP；实时性更重要且能容忍少量丢包的场景，比如 DNS、音视频、游戏，可以用 UDP。

### 为什么 TCP 需要三次握手？

回答思路：确认双向收发能力，避免历史连接。

回答模板：

三次握手的核心是让双方都确认双向通信能力。第一次 SYN 让服务端知道客户端能发；第二次 SYN+ACK 让客户端知道自己能发能收、服务端也能发能收；第三次 ACK 让服务端确认客户端能收。如果只有两次，服务端无法确认客户端是否收到了自己的响应，而且历史失效的 SYN 也可能让服务端错误建立连接。

### TCP 如何保证可靠传输？

回答思路：从序列号、确认、重传、窗口和拥塞控制展开。

回答模板：

TCP 通过多套机制保证可靠传输。序列号保证数据按顺序组装，ACK 确认接收情况，超时重传和快速重传处理丢包，滑动窗口提升吞吐并配合接收窗口做流量控制，拥塞控制根据网络状态调整发送速度。因此 TCP 的可靠性是确认、重传、有序、窗口和拥塞控制共同实现的。

### 为什么 TCP 挥手通常是四次？

回答思路：强调 TCP 是全双工连接，两个发送方向需要分别关闭。

回答模板：

TCP 是全双工连接，两个方向的数据发送需要分别关闭。主动关闭方发送 FIN 表示自己不再发送数据，被动关闭方先回复 ACK，但它可能还有数据没有发送完，所以不能立即发送 FIN。等数据发送完成后，被动关闭方再发送 FIN，主动关闭方回复 ACK，因此通常需要四次挥手。
