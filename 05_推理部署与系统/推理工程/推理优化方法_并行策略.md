# 推理优化方法_并行策略

## 知识点解析

### 概述

推理优化是为了在保证效果的前提下，让模型推理更快、更省显存、更稳定；并行策略是把模型、数据或计算拆到多张 GPU / 多台机器上执行。

### 推理优化主要优化什么

核心目标通常有三个：

- 降低延迟：用户更快拿到结果。
- 提升吞吐：单位时间处理更多请求或 token。
- 降低成本：使用更少 GPU、显存和机器资源。

常见指标：

- TTFT：首 token 延迟。
- TPOT：每个输出 token 的生成时间。
- QPS：每秒请求数。
- Throughput：每秒处理 token 数。
- GPU 利用率。
- 显存占用。
- 错误率和超时率。

### 大模型推理的两个阶段

```text
输入 prompt
  -> Prefill：一次性处理输入上下文
  -> Decode：逐 token 生成输出
```

Prefill：

- 处理完整输入。
- 计算量大，但并行度较高。
- 输入越长，prefill 越慢。

Decode：

- 每次生成一个 token。
- 强依赖 KV cache。
- 容易受访存和调度影响。

### 常见推理优化方法

#### Batching

把多个请求合并成一个 batch，提高 GPU 利用率。

问题：

- 请求长度不同会造成 padding 浪费。
- 长请求可能拖慢短请求。

优化：

- dynamic batching。
- continuous batching。
- 按长度分桶。

#### KV Cache

缓存历史 token 的 Key 和 Value，避免 decode 时重复计算。

收益：

- 大幅降低自回归生成的重复计算。

代价：

- 占用大量显存。
- 长上下文和大 batch 会让 KV cache 爆显存。

#### FlashAttention

优化 Attention 的计算和显存访问。

核心价值：

- 减少中间 attention matrix 的显存占用。
- 提升 GPU 访存效率。

#### 算子融合

把多个小算子合并执行。

收益：

- 减少 kernel launch。
- 减少中间 tensor 读写。
- 提升吞吐。

#### 量化

把权重或激活从 FP16/BF16 压缩到 INT8、INT4、FP8 等。

收益：

- 降低显存。
- 提升吞吐。

风险：

- 精度下降。
- 长尾能力受损。
- 某些任务对数值误差敏感。

#### Speculative Decoding

用小模型先草拟多个 token，再由大模型验证。

适合：

- 大模型 decode 成本高。
- 小模型和大模型输出分布接近。

#### Prompt / Context 优化

减少输入 token 数也能直接优化推理成本。

方法：

- 压缩 prompt。
- 删除无用上下文。
- RAG 只放高相关片段。
- 控制 max_tokens。

### 并行策略

#### Data Parallelism，数据并行

多张 GPU 各自处理不同请求或不同 batch。

```text
GPU0: request batch A
GPU1: request batch B
GPU2: request batch C
```

特点：

- 模型在每张卡上都有完整副本。
- 实现简单。
- 适合模型能完整放进单卡的场景。

限制：

- 如果单卡放不下模型，就不能只靠数据并行。

#### Tensor Parallelism，张量并行

把单层里的大矩阵计算拆到多张 GPU。

例如一个 Linear 层权重很大，可以按列或按行切分：

```text
W = [W0, W1, W2, W3]
GPU0 算 W0
GPU1 算 W1
GPU2 算 W2
GPU3 算 W3
```

特点：

- 适合单卡放不下模型或单层计算太大的场景。
- 每层都可能需要通信。

限制：

- 通信开销高。
- 对网络带宽和拓扑敏感。

#### Pipeline Parallelism，流水线并行

把模型不同层放在不同 GPU 上。

```text
GPU0: Layer 0-7
GPU1: Layer 8-15
GPU2: Layer 16-23
GPU3: Layer 24-31
```

特点：

- 适合层数很多、模型很大的场景。
- 每个 micro-batch 像流水线一样经过不同 GPU。

限制：

- 有 pipeline bubble，GPU 可能等待。
- 推理场景下 decode 逐 token 生成，流水线调度更复杂。

#### Sequence Parallelism，序列并行

把序列长度维度拆到不同 GPU 上。

适合：

- 长上下文训练或推理。
- attention 或 norm 在序列维度上占用较大。

限制：

- 实现复杂。
- 通信模式要求高。

#### Expert Parallelism，专家并行

主要用于 MoE 模型，把不同专家放到不同 GPU。

```text
Router
  -> Expert 1 on GPU0
  -> Expert 2 on GPU1
  -> Expert 3 on GPU2
```

特点：

- 每个 token 只激活部分专家。
- 可以扩大模型总参数量，同时控制每次计算量。

限制：

- token 分发会产生 all-to-all 通信。
- 负载不均衡会影响吞吐。

### 训练并行和推理并行的差异

训练并行：

- 需要前向、反向、梯度同步。
- 还要处理优化器状态和激活保存。

推理并行：

- 只做前向。
- 更关注 KV cache、请求调度、decode 延迟和服务稳定性。

## 面试应对

### 推理优化方法_并行策略 是什么？

回答思路：先讲推理优化的三个目标（降延迟、提吞吐、降成本），再说并行策略是把模型/数据/计算拆到多卡多机，两者共同支撑单卡放不下或高并发的服务。

回答模板：

推理优化是为了在保证效果的前提下，让模型推理更快、更省显存、更稳定；并行策略是把模型、数据或计算拆到多张 GPU / 多台机器上执行。 它关注的核心不是提升模型本身能力，而是让已有模型在服务中更高吞吐、更低延迟、更稳定地运行。

### 推理优化方法_并行策略 解决什么问题？

回答思路：围绕 Prefill/Decode 两阶段瓶颈，用 batching、KV Cache、FlashAttention、算子融合、量化、投机解码等手段分别对应 TTFT、TPOT、吞吐和显存问题。

回答模板：

推理优化是为了在保证效果的前提下，让模型推理更快、更省显存、更稳定；并行策略是把模型、数据或计算拆到多张 GPU / 多台机器上执行。 在工程上通常要结合 p50/p95/p99 延迟、tokens/s、显存峰值、并发数和失败率来判断它是否有效。

### 推理优化方法_并行策略 的核心机制是什么？

回答思路：区分数据并行、张量并行、流水线并行、序列并行、专家并行各自切分的维度和适用场景，说明它们如何解决单卡放不下和通信/负载权衡。

回答模板：

推理优化是为了在保证效果的前提下，让模型推理更快、更省显存、更稳定；并行策略是把模型、数据或计算拆到多张 GPU / 多台机器上执行。 这类机制的价值在于减少无效计算、降低显存碎片、提升 GPU 利用率或稳定服务调度。

### 推理优化方法_并行策略 有哪些限制？

回答思路：强调各方法都有代价——TP 通信开销高、PP 有 bubble、量化掉精度、EP 有 all-to-all 和负载不均，且推理并行与训练并行关注点不同（只做前向、更看 KV cache 和调度）。

回答模板：
