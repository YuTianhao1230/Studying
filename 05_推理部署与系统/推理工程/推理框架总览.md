# 推理框架总览

## 一句话解释

推理框架是把训练好的模型高效运行起来的系统，负责模型加载、请求处理、显存管理、批处理、解码、并发调度和性能优化。

## 为什么需要推理框架

训练好的模型文件本身不能直接稳定服务线上请求。

真实推理需要解决：

- 模型权重如何加载到 GPU。
- 多个请求如何并发处理。
- 长上下文如何管理显存。
- 首 token 延迟和整体吞吐如何优化。
- 不同采样参数如何支持。
- 请求超时、取消、失败如何处理。
- 多卡、多机如何部署。

推理框架就是为这些问题服务的。

## 推理框架一般做什么

```text
用户请求
  -> tokenize
  -> 请求调度
  -> batching
  -> prefill
  -> decode
  -> detokenize
  -> 返回结果
```

核心模块：

- Model Loader：加载权重和 tokenizer。
- Scheduler：调度请求。
- Batching Engine：合并请求提升吞吐。
- Memory Manager：管理显存和 KV cache。
- Decode Engine：执行 greedy、top-k、top-p、beam search 等解码策略。
- Parallel Runtime：支持 tensor parallel、pipeline parallel 等并行策略。
- API Server：提供 HTTP / RPC / OpenAI-compatible 接口。

## 常见推理框架

- vLLM：开源 LLM serving 框架，核心特点是 PagedAttention 和 continuous batching。
- TensorRT-LLM：NVIDIA 推理优化框架，强调高性能算子和部署优化。
- TGI：Hugging Face Text Generation Inference。
- FasterTransformer：NVIDIA 早期 Transformer 推理框架。
- llama.cpp：适合本地 CPU/GPU 量化推理。
- xLLM：常见于内部或平台化推理服务语境，通常强调高吞吐服务化。
- ms-swift：更偏大模型训练、微调、部署、评测工具链，不是纯推理引擎。

## 推理框架关注的核心指标

- TTFT：Time To First Token，首 token 延迟。
- TPOT：Time Per Output Token，每个输出 token 的平均时间。
- Latency：整体请求延迟。
- Throughput：单位时间处理 token 或请求数。
- QPS：每秒请求数。
- GPU Utilization：GPU 利用率。
- Memory Usage：显存占用。
- Error Rate：错误率。

## 推理和训练的主要差异

训练：

- 需要前向和反向传播。
- 需要保存梯度和优化器状态。
- 通常 batch 比较规整。
- 目标是更新参数。

推理：

- 只需要前向传播。
- 不需要梯度。
- 请求长度和输出长度差异大。
- 目标是低延迟、高吞吐、稳定服务。

## 面试可能怎么问

1. 推理框架解决了什么问题？
   - 回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。
   - 回答模板：推理框架把离线模型变成可上线服务，处理请求调度、并发 batching、KV Cache、并行、流式输出、资源管理、监控和灰度。
2. 为什么不能直接用训练代码做线上推理？
   - 回答思路：先指出背后的核心约束，再解释收益，最后补充如果不这样做会带来的风险。
   - 回答模板：训练代码缺少高并发调度、延迟控制、streaming、资源隔离、灰度回滚和监控能力。线上推理需要面向稳定性、吞吐和成本专门优化。
3. 如何衡量一个推理服务的性能？
   - 回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。
   - 回答模板：我会把 衡量一个推理服务的性能 拆成几个步骤：先明确目标和输入输出，再设计关键模块或策略，然后加入失败处理和权限/质量约束，最后用离线指标、线上指标或回归测试验证效果。在 推理框架总览 场景里，重点是能落到真实工程流程。
4. vLLM、TensorRT-LLM、TGI 的定位有什么区别？
   - 回答思路：先分别定义两个概念，再从目标、机制、适用场景和工程取舍四个角度对比。
   - 回答模板：先分别定义两个对象，再比较目标、机制、适用场景和风险。围绕 推理框架总览，关键是说明它们解决的问题不同。
5. 推理框架如何处理多个并发请求？
   - 回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。
   - 回答模板：通过请求队列、dynamic/continuous batching、KV Cache 管理和调度策略把多个请求合并到 GPU 上执行，同时支持不同请求动态结束。
