# MLOps与模型生产化

## 知识点解析

### 概述

MLOps 是把模型从实验室带到生产环境的一整套工程体系，覆盖数据、训练、评测、部署、监控、回滚和持续迭代。

### 为什么大厂 JD 重视 MLOps

模型效果只是上线前的一部分。真实业务还关心：

- 能否稳定训练。
- 能否复现结果。
- 能否安全上线。
- 能否监控质量下降。
- 能否快速回滚。
- 能否解释指标变化。

大厂算法工程师常常不是只训练模型，而是要负责模型生命周期。

### 标准链路

```text
数据采集
  -> 数据清洗
  -> 数据版本
  -> 训练实验
  -> 模型评测
  -> 模型注册
  -> 灰度发布
  -> 线上监控
  -> A/B 测试
  -> 回滚 / 放量 / 迭代
```

### 核心模块

#### 数据版本

记录训练数据来源、过滤规则、采样策略和时间范围。

否则模型效果变化时无法判断是模型变了，还是数据变了。

#### 实验追踪

记录：

- 代码 commit。
- 数据版本。
- 模型配置。
- 超参数。
- 随机种子。
- 指标曲线。
- checkpoint。

#### 模型注册

模型上线前需要注册元信息：

- 模型版本。
- 训练配置。
- 评测结果。
- 适用场景。
- 依赖资源。
- 回滚版本。

#### 灰度与回滚

不能直接全量上线。

常见方式：

- 小流量灰度。
- 按用户分桶。
- 按地域 / 业务线灰度。
- 监控护栏指标。
- 异常自动回滚或人工回滚。

#### 线上监控

关注：

- 输入分布变化。
- 特征缺失。
- 模型输出分布。
- 业务指标。
- 延迟和错误率。
- 资源使用。

### 常见 Drift

- Data Drift：输入数据分布变了。
- Feature Drift：特征分布变了。
- Concept Drift：输入和标签之间的关系变了。
- Training-Serving Skew：训练和线上特征处理不一致。

### 面试回答框架

如果被问“如何把模型上线”，可以这样回答：

```text
我会先固定数据版本、代码版本和训练配置，保证实验可复现。
然后在离线评测和回归集上验证模型效果，并保存 bad case。
上线时通过模型注册、灰度发布和 A/B 测试控制风险。
线上持续监控业务指标、模型输出分布、特征漂移、延迟和错误率。
如果护栏指标异常，先回滚，再基于日志和 bad case 做归因。
```

### 常见误区

- 只保存模型文件，不保存数据和代码版本。
- 只看离线指标，不做线上监控。
- 没有灰度和回滚。
- 没有训练-serving 一致性检查。
- 线上指标异常时无法定位数据、模型还是系统问题。
