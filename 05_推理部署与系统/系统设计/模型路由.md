# 模型路由

## 知识点解析

### 概述

模型路由是指系统根据用户请求的任务类型、难度、风险、输入模态、延迟和成本，把请求分配给最合适的模型或处理链路。

它解决的是：

```text
不是所有请求都应该走同一个最强模型。
```

简单问题可以走小模型或缓存；复杂推理走 reasoning 模型；图片、视频走 [VLM](<../../06_视觉多模态与生成模型/多模态模型/VLM与Vision_Instruction_Tuning.md>)；企业知识问答走 [RAG](<../../02_大模型/应用与问题/RAG.md>)；高风险操作走带校验和人工确认的链路。

### 为什么需要模型路由

#### 提升精准性

不同模型擅长不同任务：

- 代码问题用代码模型更稳。
- 图像/视频问题用 VLM。
- 企业文档问答用 RAG + LLM。
- 数学推理用 thinking/reasoning 模型。
- 高频 FAQ 用小模型、规则或缓存即可。

把请求分给合适模型，比让一个通用模型硬做所有任务更可靠。

#### 提升稳定性

高风险请求可以进入更严格链路：

```text
普通问答
  -> 直接生成

涉及权限、删除、支付、审批
  -> 风险识别
  -> 参数校验
  -> 人工确认
  -> 执行
```

模型路由也能做降级：

- 强模型超时，切备用模型。
- VLM 不可用，明确返回无法处理图片，而不是乱答。
- 检索失败，拒答或让用户补充信息。
- 高峰期把低优先级请求转异步或限制输出长度。

#### 提升效率

大模型贵，小模型便宜。路由可以减少无效计算：

- 简单问题不走最强模型。
- 重复问题走缓存。
- 明确查知识的问题先走 RAG。
- 低价值任务限制输出长度。
- 复杂任务先用小模型分类，再决定是否升级。

### 常见路由维度

| 路由依据 | 例子 | 目标 |
| --- | --- | --- |
| 任务类型 | 问答、摘要、代码、数学、多模态、[Agent](<../../10_Agent/基础概念/Agent.md>) | 选择能力匹配的模型 |
| 难度 | 简单 FAQ vs 复杂推理 | 控制成本和准确率 |
| 风险等级 | 普通知识 vs 金融/医疗/权限操作 | 提升安全性 |
| 输入形态 | 文本、图片、视频、表格、代码库 | 选择 LLM/VLM/代码模型 |
| 上下文长度 | 短问答、长文档、长视频 | 选择长上下文或 RAG |
| 延迟预算 | 实时客服 vs 离线报告 | 选择快模型或强模型 |
| 成本预算 | 免费用户 vs 付费高优任务 | 控制 token 和模型成本 |

### 常见路由策略

#### 规则路由

根据业务规则直接分配：

```text
包含图片 -> VLM
包含代码文件 -> Code Model / Code Agent
命中内部知识库意图 -> RAG
涉及支付/删除/权限 -> 高风险链路
```

优点是稳定、可解释；缺点是覆盖有限，规则维护成本会变高。

#### 分类器路由

用小模型或分类模型判断请求类型：

```text
用户请求
  -> 小分类器
  -> {普通问答, RAG, 代码, 多模态, 高风险, 人工}
```

适合意图复杂、规则难完全覆盖的产品。

#### 级联路由

先用便宜模型处理，不确定再升级：

```text
小模型回答
  -> 置信度高：直接返回
  -> 置信度低 / 高风险：升级大模型或人工
```

它能显著降低成本，但要设计好置信度、拒答和升级条件。

#### 动态路由

根据线上状态实时切换：

- 某模型错误率升高，切备用模型。
- 某集群负载过高，切到低成本模型。
- p99 延迟超阈值，关闭高成本功能。
- 用户等级不同，使用不同服务链路。

### AI 产品里的路由例子

#### 企业知识助手

```text
用户问题
  -> 是否需要公司知识？
  -> 是：RAG 链路
  -> 否：通用 LLM
  -> 涉及制度/权限：引用校验 + 拒答兜底
```

#### AI Coding

```text
解释代码 -> 召回文件 + LLM 解释
修改代码 -> Code Agent + 测试验证
查 API 文档 -> RAG
运行命令 -> 工具权限校验
```

#### 多模态关键帧

```text
纯文本规则问题 -> LLM
视频理解/关键帧定位 -> VLM / 关键帧模型
低置信或高风险样本 -> 人工复核
```

### 评估指标

| 指标 | 含义 |
| --- | --- |
| 路由准确率 | 请求是否被分到正确链路 |
| 误路由率 | 本该走 A 链路却走到 B 链路 |
| 升级率 | 小模型升级到大模型或人工的比例 |
| 拒答准确率 | 信息不足或风险高时是否正确拒答 |
| p95/p99 延迟 | 路由后端到端响应是否满足要求 |
| 单请求成本 | 平均 token、模型调用和工具调用成本 |
| fallback 成功率 | 主链路失败后备用链路是否兜住 |

### 常见错误

- 只按关键词写死路由，不能处理复杂表达。
- 所有请求都走最强模型，成本高且延迟不可控。
- 高风险操作和普通问答走同一条链路。
- 没有 fallback，模型超时就整体失败。
- 不记录路由原因，线上问题无法复盘。
- 只看最终答案正确率，不单独评估路由准确率。

## 面试应对

### 模型路由是什么？

回答思路：一句话定义为“按请求特征选择模型或链路”，再讲效果、成本和稳定性。

回答模板：

模型路由是根据用户请求的任务类型、难度、风险、输入模态、上下文长度、延迟和成本，把请求分配给最合适的模型或处理链路。它的核心不是简单选一个最强模型，而是让简单请求走小模型或缓存，复杂推理走 reasoning 模型，多模态请求走 VLM，企业知识问答走 RAG，高风险操作走带校验和人工确认的链路。这样能同时提升准确率、降低成本，并在模型超时或失败时做降级兜底。

### 为什么 AI 产品需要模型路由？

回答思路：从多任务、多模型、多成本和高风险控制解释。

回答模板：

AI 产品需要模型路由，是因为真实请求差异很大。一个用户可能问 FAQ，另一个用户上传图片，还有人让系统改代码或执行权限操作。如果全部走同一个大模型，简单任务成本浪费，高风险任务又不够可控。模型路由可以让请求进入匹配的链路：低成本任务快速处理，复杂任务升级强模型，危险任务加校验和人工确认。它本质是在效果、稳定性和成本之间做动态平衡。

### 模型路由怎么设计？

回答思路：按规则、小模型分类、级联、动态路由和监控闭环回答。

回答模板：

我会先定义路由标签，比如普通问答、RAG、代码、多模态、高风险、人工处理。第一层用规则处理明确情况，比如有图片走 VLM、命中文档问答走 RAG、涉及删除支付走高风险链路；第二层用小模型或分类器判断模糊意图和难度；第三层用级联策略，低置信或失败时升级到更强模型或人工。上线后要记录路由原因、模型版本、延迟、成本和最终质量，用误路由 case 持续优化分类器和规则。

### 模型路由如何提升稳定性？

回答思路：强调风险隔离、降级、fallback 和可观测性。

回答模板：

模型路由提升稳定性主要靠风险隔离和降级兜底。高风险请求不会直接交给通用模型生成，而是进入带权限校验、参数检查和人工确认的链路；模型服务超时或错误率升高时，可以切备用模型、缩短上下文、关闭高成本能力或返回异步结果；检索证据不足时可以拒答，而不是硬编。路由层还会记录每次为什么选择这个模型，方便线上问题追踪和回滚。
