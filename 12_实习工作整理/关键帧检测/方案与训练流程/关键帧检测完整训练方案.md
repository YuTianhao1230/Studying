# 关键帧检测完整训练方案：阶段路由

## 知识点解析

### 概述

关键帧检测的目标是从移动端操作录屏中定位某个业务指标的“完成态第一次成立”的时间点，用于性能耗时计算、智能预标和人工标注提效。它不是普通视频分类，而是由业务规则约束的时空证据定位任务。

本文只负责完整训练路线的阶段依赖、入口/出口条件、方法选择和最终流水线。各阶段的参数、数据格式、reward、loss、实现细节与失败排查由对应详细卡片承载。

输入：视频 + `task_type` + 完成态定义 + 排除条件 + 豁免条件。

输出：`<answer>{"time": 6.97}</answer>`。

当前项目最新模型效果（ACC，单位：%）：

| 范围 | ACC |
| --- | ---: |
| 全量平均 | 89.982 |
| 国际电商 | 97.457 |
| 番茄系 | 89.055 |
| 搜索系 | 75.977 |

当前基础方案已经解决大部分视频输入、任务遵循和明显完成态识别问题。后续重点仍是低 ACC 业务线与长尾指标、early/late、局部异步加载、小 UI 元素、页面二次刷新，以及“当前看似稳定”和“首次满足完成态”的区分。

### 2. 阶段依赖

```text
业务录屏与 GT
  -> 阶段 0：任务定义与数据治理
  -> 阶段 1：Base / Prompt baseline
  -> 阶段 2：Direct SFT
  -> 阶段 3：Structured CoT SFT
  -> 阶段 4/5：按瓶颈条件路由
       -> 可验证决策偏差：Verifier-based GRPO
       -> 局部时间证据稀释：Temporal-OPSD（默认从通过准出的 Structured CoT SFT checkpoint 初始化）
       -> 两类瓶颈并存：按瓶颈与实验假设选择 GRPO、Temporal-OPSD 的先后或独立验证
  -> 阶段 6：固定评测、bad case 回流与上线
```

依赖原则：

1. 先统一完成态、时间坐标和评测口径，再比较模型方法。
2. Direct SFT 先建立基础能力，CoT-SFT 再增加过程证据监督。
3. GRPO 依赖稳定 policy 和可靠 verifier；Temporal-OPSD 依赖明确的 privileged gap 和 Teacher logits/log-prob。
4. GRPO 与 Temporal-OPSD 都不是必做阶段，也没有普适的固定先后；独立 Temporal-OPSD 默认从通过准出的 Structured CoT SFT checkpoint 初始化，顺序按当前瓶颈和实验假设选择。若明确采用 `GRPO -> Temporal-OPSD` 联合实验，则 Temporal-OPSD 从已通过准出的 GRPO checkpoint 初始化，并重新验证全量集与困难集。
5. 每次升级都必须通过同一固定回归集、困难集和业务分桶，不能只看训练 loss 或 reward。

### 3. 各阶段入口与出口

#### 阶段 0：任务定义与数据治理

入口：

- 已有业务录屏、`task_type` 和人工 GT。
- 可以访问原始视频与标注元数据。

核心动作：

- 为每个 `task_type` 定义必须满足条件、排除条件、豁免条件、首选/备选证据、防抢跑和防跳过规则。
- 检查视频可解码性、FPS、时长、帧数、黑屏、截断和损坏。
- 检查 GT 越界、时间坐标、冲突标签、`<video>` 与视频字段、assistant labels 和输出解析。

出口：

- 完成态和首次满足口径可执行、可复核。
- 视频、标签、多模态输入和时间坐标通过检查。
- train/dev/test 按原始视频实体隔离。

详细入口：[任务定义与标注标准.md](<../任务与数据治理/任务定义与标注标准.md>)、[Qwen3-VL关键帧数据格式.md](<../工程实现/Qwen3-VL关键帧数据格式.md>)。

#### 阶段 1：Base / Prompt baseline

入口：

- 阶段 0 的规则、数据和评测口径已冻结。

核心动作：

```text
规则/传统 baseline
  -> Base Model baseline
  -> Prompt baseline
```

出口：

- 固定全量与分业务线 ACC、`frame_err`、`time_err`、PASS、格式解析率、early/late 和 `task_type` 分桶。
- 建立可复现的 bad case 基线，能区分模型、数据、Prompt、采样配置和评测口径变化。

相关卡片：[Prompt 调优](<../../../02_大模型/应用与问题/Prompt调优.md>)、[部署上线与容量评估.md](<../工程实现/部署上线与容量评估.md>)。

#### 阶段 2：Direct SFT

入口：

- baseline 已固定。
- 单样本 forward、多模态输入、labels 和输出解析链路可用。

核心动作：

```text
单样本 forward
  -> 10~100 条小数据过拟合
  -> 小规模 dev 实验
  -> 完整 Direct SFT
```

出口：

- 模型能稳定接收视频与任务规则，并输出可解析时间。
- 明显完成态和基础业务分桶相对 baseline 改善。
- loss、格式解析率和业务 ACC 没有明显目标错配。
- 困难样本的剩余问题已归因到边界证据、数据或视觉输入，而非基础训练链路。

参数、视频预算、checkpoint 选择和失败排查见 [SFT 训练方案设计.md](<SFT 训练方案设计.md>)。

#### 阶段 3：Structured CoT SFT

入口：

- Direct SFT checkpoint 能稳定处理视频、遵循任务并输出短答案。
- 困难样本确实需要解释“之前未完成、当前首次满足、之后稳定或刷新”。
- CoT 数据可经过视频、时间、结构、视觉证据、GT 泄漏和语义一致性检查。

核心动作：

```text
Direct SFT checkpoint
  -> 任务无关的 State/Event 完整时间轴
  -> 问题驱动的原语引用与边界推理
  -> clean CoT SFT
  -> 困难边界评测
```

出口：

- 状态/事件原语、证据引用和 `answer.time` 可稳定解析。
- CoT 证据与视频、任务规则和最终时间一致。
- 困难集相对 Direct SFT 提升，且全量指标与格式稳定性不退化。
- direct 与 `structured_cot` 输出协议显式区分。

数据构造、质量门禁、训练输出与线上短答案策略见 [CoT-SFT 蒸馏方案设计.md](<CoT-SFT 蒸馏方案设计.md>)。

#### 阶段 4：Verifier-based GRPO

入口：

- CoT policy 能稳定生成可解析回答，`answer.time` 可稳定提取。
- verifier 与人工判断有较高一致性，reward 分项与真实 ACC 相关。
- 同一 prompt 的 group 内存在正确和错误候选，不是全对、全错或同分。
- 训练资源能够支持 rollout、验证和固定回归。

核心动作：

```text
CoT SFT checkpoint
  -> 同一视频/task_type 生成多条回答
  -> verifier 计算时间、格式、边界、证据和任务 reward
  -> 组内相对 advantage
  -> clipping + KL 更新 policy
```

出口：

- 困难指标或 early/late 边界相对 CoT-SFT 提升。
- reward 上升与真实 ACC 一致，不依赖格式、长度或幻觉漏洞。
- 全量 ACC、格式解析率、输出长度和 KL 在护栏内。
- reward 继续上升但真实 ACC 不升、KL 快速上升或通用能力退化时停止。

同一批 CoT 数据的使用方式、reward 权重、训练参数、监控和失败记录见 [GRPO 训练方案设计.md](<GRPO 训练方案设计.md>)。

#### 阶段 5：Temporal-OPSD

入口：

- Student 的结构化输出、状态/事件原语与任务证据可稳定解析。
- Dense-window Teacher 相比 Full-video Student 存在明确 privileged gap。
- Teacher 质量稳定，并可取得 Student prefix 上的 logits 或 log-prob。
- Student/Teacher 的任务语义、输出 schema、FPS 和绝对时间坐标已对齐。

核心动作：

```text
测量 Full-video Student 与 Dense-window Teacher
  -> 验证 Teacher 质量和泄漏风险
  -> Frozen Teacher + sampled-token smoke test
  -> JSD/KL + CE anchor 正式训练
  -> 必要时再引入 EMA Teacher / Top-K JSD
```

出口：

- 困难集 ACC 相比 CoT-SFT/GRPO 有提升。
- 全量 ACC、格式解析率和无完成态准确率不明显退化。
- early/late、首次完成边界或二次刷新样本至少一项改善。
- Teacher-Student KL/JSD gap 缩小，输出长度与重复率在护栏内。
- 若只有教师文本、没有 logits，则降级为 Response Distillation/RFT，不称为严格 OPD。

双视图字段、时间窗口、Prompt、loss mask、训练器、参数、对照实验和失败记录见 [OPD 训练方案设计.md](<OPD 训练方案设计.md>)。

#### 阶段 6：评测、回流与上线

入口：

- 候选 checkpoint 已通过对应阶段出口条件。
- 评测集、困难集、业务分桶和解析器版本已冻结。

核心动作：

```text
候选 checkpoint
  -> 固定回归与困难集评测
  -> task_type / early / late / 二次刷新分桶
  -> 视频、GT、规则三方复核
  -> relabel / hard negative / Prompt / 训练阶段回流
  -> 上线配置对齐与容量验证
```

出口：

- 全量、低 ACC 指标、`frame_err`、`time_err`、PASS、格式解析率、evidence accuracy、early/late 和成本均有记录。
- GT 错误、标准冲突、覆盖不足、视觉输入不足和模型能力不足已分开归因。
- checkpoint、processor、chat template、FPS、帧数、分辨率、视觉 token、生成参数和解析规则一致。
- 视频下载、解码、processor、推理、后处理、队列与并发完成性能拆分。

### 4. 方法选择

| 观测到的主要问题 | 首选方法 | 进入前必须确认 |
| --- | --- | --- |
| 模型不会处理视频、遵循任务或稳定输出 | Direct SFT | 数据与 labels 链路正确 |
| 模型会答，但不会表达首次完成边界 | Structured CoT SFT | CoT 证据真实且可过滤 |
| 同题多个候选有好坏差异，业务 reward 可验证 | GRPO | verifier 可靠且 group 有方差 |
| Reward 可靠，但暂不承担在线 RL 成本 | RFT baseline | 高 reward 样本可稳定筛选 |
| 完整视频漏掉局部时间证据，Teacher 有明确优势 | Temporal-OPSD | 可取得 Teacher logits/log-prob |
| 只有教师 API 文本答案 | Response Distillation/RFT | 不按严格 OPD 归因 |
| 线上只需要短答案 | CoT 离线增强、双模式或 answer-only distillation | direct/cot 协议分离 |

选择关系：

```text
先判断基础能力是否缺失
  -> 是：Direct SFT
  -> 否：判断是否缺边界证据
       -> 是：Structured CoT SFT
       -> 否：判断优化缺口（可多选）
            -> 可验证决策偏差：GRPO / RFT
            -> 局部时间证据稀释且有 Teacher logits：Temporal-OPSD
            -> 两类缺口并存且各自准入条件成立：按瓶颈与实验假设选择先后或独立验证
            -> 数据、GT 或规则问题：回到任务与数据治理
```

方法卡片：[GRPO](<GRPO 训练方案设计.md>)、[RFT](<../../../03_训练优化与对齐/后训练与对齐/RFT 拒绝采样微调.md>)、[OPD / Temporal-OPSD](<OPD 训练方案设计.md>)。

### 5. 最终流水线

```text
1. 冻结任务规则、标注标准、时间坐标和数据切分
2. 固定规则/Base/Prompt baseline
3. Direct SFT 建立视频输入、任务遵循和短答案能力
4. Structured CoT SFT 补充状态、事件、证据引用和首次完成边界
5. 根据瓶颈和准入条件路由：
   - 仅有可验证决策偏差，且 verifier 可靠、候选有差异 -> GRPO
   - 仅有局部时间证据稀释，且 Teacher 明显更强、有 logits -> 从通过准出的 Structured CoT SFT checkpoint 初始化 Temporal-OPSD
   - 两类瓶颈并存，且上述两组条件同时成立 -> 按瓶颈与实验假设选择 GRPO、Temporal-OPSD 的先后或独立验证
   - 明确采用 `GRPO -> Temporal-OPSD` 联合实验 -> Temporal-OPSD 从已通过准出的 GRPO checkpoint 初始化，并重新验证全量集与困难集
   - 对应条件不满足 -> 停留当前阶段并修数据、规则、verifier 或 Teacher
6. 用同一固定回归集、困难集和业务分桶选择 checkpoint
7. 将 bad case 按 GT、规则、数据、视觉输入和模型能力分类回流
8. 对齐训练/推理配置，完成容量、延迟和上线验证
```

任何阶段都不得用训练 loss、总 reward 或 Teacher 指标单独宣告收益。最终判断始终以固定评测、业务分桶、失败样本复核和上线配置一致性为准。

## 面试应对

### 回答模板

我会把关键帧训练组织成任务与数据治理、baseline、Direct SFT、Structured CoT SFT、条件式 On-Policy 优化和上线回流六个阶段。Direct SFT 先建立视频输入、任务遵循和稳定短答案；CoT-SFT 再学习完整时间轴、证据引用和首次完成边界。之后根据瓶颈选方法：如果同题候选可以被可靠业务 reward 区分，就用 GRPO；如果完整视频遗漏局部时间证据，而且高密度窗口 Teacher 明显更强并能提供 logits，就从通过准出的 Structured CoT SFT checkpoint 初始化 Temporal-OPSD。GRPO 与 Temporal-OPSD 没有普适的固定先后；若实验明确采用 `GRPO -> Temporal-OPSD`，后者从已通过准出的 GRPO checkpoint 初始化，并重新验证全量集和困难集。每一阶段都有明确准入和准出条件，并用同一固定回归集、困难集、early/late 与业务分桶验证，bad case 再按 GT、规则、数据、视觉输入和模型能力回流。
