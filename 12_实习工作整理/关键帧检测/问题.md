# 关键帧检测项目问答

## 讲一下项目背景、目标和我主要的工作

这个项目面向移动端性能评测场景。传统流程需要人工逐帧查看操作录屏，判断页面加载、加购、滑动或弹窗等动作在什么时刻完成，再用结束时间减去起始时间计算性能耗时。这个过程成本高、主观性强，而且不同业务线、不同 `task_type` 的完成态标准并不一致。例如商详页加载要等待头图、价格和营销组件清晰稳定，购物车加购则优先看角标数字变化。因此，任务不是普通视频分类，而是给定录屏、任务类型和业务规则，定位“完成态第一次成立”的时间点。

项目目标是训练一个多模态关键帧模型，自动输出结束帧或时间戳，用于性能耗时计算、智能预标和人工标注提效。除了提高全量准确率，还要重点解决低样本长尾指标、early/late 边界偏差、局部异步加载、小面积 UI 元素和页面二次刷新，避免模型只判断“页面看起来差不多完成”，却找不到第一个满足业务标准的帧。

我的工作主要分为四部分。第一是任务和数据治理：把人工经验整理成完成态、排除条件、豁免条件、证据优先级和防抢跑规则，并通过 bad case 归因区分 GT 错误、规则冲突、数据链路问题和真实模型错误。第二是训练方案设计：基于 Qwen-VL 系列模型先做 Direct SFT，建立视频理解、任务遵循和稳定短答案能力；再构造 State/Event 视频原语和 before/current/after 证据链做 Structured CoT SFT；对于可验证的困难边界，设计时间、格式、边界和视觉证据 reward，并评估 GRPO；对于完整视频中局部证据被稀释的问题，进一步设计 Temporal-OPSD。第三是评测闭环：建立固定全量集、困难集以及业务线、`task_type`、early/late 等分桶，结合模型分歧和低 ACC 指标筛选高价值样本，形成人工复核、重标、回流训练和回归评测的数据飞轮。第四是工程落地：对齐训练与推理的视频采样和输出协议，完成服务接口、能力映射、耗时拆解、并发压测和线上回测。

当前项目全量 ACC 为 89.98%，其中国际电商为 97.46%；国际电商线上三帧误差回测平均为 90.05%，标注成本下降 19.00%，提效贡献占比为 9.50%。后续重点不是盲目增加训练阶段，而是继续治理搜索系和长尾指标，检查 reward 与真实 ACC 的一致性，并围绕局部 UI 证据和首次完成边界做针对性优化。

## 介绍一下DPO和GRPO
DPO（Direct Preference Optimization，直接偏好优化）是一种离线偏好优化方法。它输入同一任务下的 chosen 和 rejected 回答，结合冻结的 Reference Model，直接提高优选回答相对拒绝回答的概率优势，不需要单独训练 Reward Model、Critic 或在线采样，因此链路简单稳定，适合安全、风格和主观偏好对齐。GRPO（Group Relative Policy Optimization，组相对策略优化）属于在线策略优化：当前 Policy 对同一输入采样多条回答，由 verifier 评分，再根据组内奖励均值和标准差计算相对 advantage，通过 clipping 和 KL 约束更新 Policy。它省去了 PPO 的 Critic，但增加了 rollout 成本，并依赖可靠 reward 和组内差异，更适合数学、代码、结构化输出和关键帧定位等结果可验证的任务。

## 为什么没有尝试其他的RL方法
没有把其他强化学习方法逐一作为主实验，并不是因为它们无效，而是算法必须匹配任务信号、资源成本和当前瓶颈。PPO 需要训练 Critic；若采用经典 RLHF，还要维护 Reward Model、Reference Model 和多套优化器，在视频多模态 rollout 下成本和调参难度更高。REINFORCE 等基础策略梯度方差较大，稳定性不足。RFT 只是筛选高分回答继续做 SFT，适合作为低风险 baseline，但不能直接利用组内相对 advantage。DPO 及其变体更依赖离线偏好数据，而本项目已有 GT 时间、格式、首次完成边界和视觉证据等可计算 reward。因此优先选择无需 Critic、能直接使用 verifier 的 GRPO。若 reward 与真实 ACC 不相关、组内同分，或 CoT-SFT 已达到目标，也不会强行上 RL，而会先修数据、规则和评分器。

## DPO和GRPO的区别，为什么我这里不用DPO而用GRPO
DPO 与 GRPO 的核心区别在数据形式和优化方式。DPO 使用固定的 chosen/rejected 偏好对，学习“两个回答中更偏好哪一个”，成本较低但主要覆盖离线回答分布。GRPO 让当前 Policy 对同一视频生成多条 rollout，用连续 reward 计算组内相对 advantage，学习“当前回答分别好到什么程度”，能持续覆盖模型真实产生的 early、late、格式和边界错误。关键帧任务已有 GT time，可以计算时间误差，并校验 JSON、before/current/after 时序和视觉证据。若改用 DPO，还需先采样、排序和构造偏好对，并把连续分数压成二元胜负，损失奖励强度信息，所以这里优先采用 verifier-based GRPO。但 DPO 并非不能使用：在线 rollout 成本过高或已有稳定人工偏好对时，可以作为离线 baseline。
