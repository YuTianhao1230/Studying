# 关键帧检测项目问答

## 讲一下项目背景、目标和我主要的工作

这个项目面向抖音、番茄等公司内app性能评测场景。传统流程需要人工逐帧查看操作录屏，判断页面加载、加购、滑动或弹窗等动作在什么时刻完成。这个过程成本高、主观性强，而且不同业务线、不同任务的完成态标准并不一致。比如说抖音商城会有各种指标，举个例子，购物车加载耗时必须要等到界面完全加载出来才算，但是购物车加购耗时就只需要弹出加购成功的第一帧/购物车数量增加。因此，这个完成态的定义并不是一个通用的，而是和业务需求强耦合的。

项目目标是训练一个多模态关键帧模型，通过模型判断自动输出结束帧，用于智能预标。除了提高全量准确率，还要重点解决低样本长尾指标、early/late 边界偏差、局部异步加载、小面积 UI 元素和页面二次刷新，避免模型只判断“页面看起来差不多完成”，却找不到第一个满足业务标准的帧。

我的工作主要分为四部分。
第一是任务定义与数据治理：针对不同业务线和任务类型，把主观的完成态判断转化为可执行的标注协议，明确有效证据、排除条件、豁免条件、证据优先级以及“首次满足完成态”的防抢跑约束；同时通过人工独立复标和分层归因，识别标注错误、数据质量问题、标准沉淀错误和规则映射错误，减少脏标签对训练与评测的干扰。
第二是训练方案设计：基于 Qwen-VL 系列模型先做 SFT，建立视频理解、任务遵循和稳定短答案能力；再基于任务情况设计 CoT 思维链格式，包含 State/Event 视频证据原语（不涉及任务，只理解视频）和 before/current/after 证据链，完成 Structured CoT SFT；对于可验证的困难边界，设计时间、格式、边界和视觉证据 reward，并实现 GRPO 训练；对于完整视频中局部证据被稀释的问题，进一步研究 Temporal-OPSD。
第三是评测与迭代闭环：建立固定全量集、困难集以及业务线、任务类型、early/late 等分桶，结合模型分歧和低 ACC 指标筛选高价值样本，对真实模型错误进行细粒度归因，并形成人工复核、数据回流和回归评测的数据飞轮。
第四是工程落地：对齐训练与推理的视频采样和输出协议，完成服务接口、能力映射、耗时拆解、并发压测和线上回测。

当前项目全量 ACC 为 89.98%，其中国际电商为 97.46%；国际电商线上三帧误差回测平均为 90.05%，标注成本下降 19.00%，提效贡献占比为 9.50%。后续重点不是盲目增加训练阶段，而是继续治理搜索系和长尾指标，检查 reward 与真实 ACC 的一致性，并围绕局部 UI 证据和首次完成边界做针对性优化。

## 介绍一下DPO和GRPO
DPO（Direct Preference Optimization，直接偏好优化）是一种离线偏好优化方法。它输入同一任务下的 chosen 和 rejected 回答，结合冻结的 Reference Model，直接提高优选回答相对拒绝回答的概率优势，不需要单独训练 Reward Model、Critic 或在线采样，因此链路简单稳定，适合安全、风格和主观偏好对齐。GRPO（Group Relative Policy Optimization，组相对策略优化）属于在线策略优化：当前 Policy 对同一输入采样多条回答，由 verifier 评分，再根据组内奖励均值和标准差计算相对 advantage，通过 clipping 和 KL 约束更新 Policy。它省去了 PPO 的 Critic，但增加了 rollout 成本，并依赖可靠 reward 和组内差异，更适合数学、代码、结构化输出和关键帧定位等结果可验证的任务。

## 为什么没有尝试其他的RL方法
这个项目最终实现了 GRPO，但没有把所有 RL 方法都跑一遍，因为方法选择不是做算法枚举，而是看哪种训练信号最匹配当前问题。我们先用 SFT 和 Structured CoT SFT 建立视频理解、格式遵循和边界判断能力；在此基础上，模型已经能够生成合理候选，但困难样本上仍存在正确边界概率不够高的问题。同时，任务已有 GT 时间，格式、early/late 边界和部分视觉证据也可以程序化验证，因此具备使用 verifier 做策略优化的条件。

具体选型时，PPO 也能优化这些业务 reward，但需要额外训练 Critic，在视频多模态场景下显存、rollout 和调参成本更高；RFT 只保留高分回答再做 SFT，不能直接利用同组候选的相对 advantage。GRPO 既能直接使用现有 verifier，又不需要 Critic，所以在监督信号和工程成本之间更合适。我的选择依据不是 GRPO 在所有任务上都最好，而是它最匹配这个任务“结果可验证、同题可采多条候选、视频 rollout 成本较高”的特点，因此没有再把其他 RL 方法逐一实现。

## DPO和GRPO的区别，为什么这里不用DPO而用GRPO
DPO 更适合“我已经有稳定的偏好对，希望模型更倾向 chosen、远离 rejected”的离线对齐任务，例如回答风格、安全性和主观质量对齐。它不需要单独训练 Reward Model，也不需要训练时在线 rollout，但训练前必须先构造可靠的 chosen/rejected。GRPO 则是当前模型对同一个输入在线生成多条候选，再由 verifier 给每条候选打分，根据组内相对分数更新模型，更适合结果能够自动验证的任务。

关键帧任务的核心不是主观偏好，而是预测结果是否满足可验证的业务边界。例如预测时间与 GT 相差多少、是否发生 early/late、输出格式是否合法，以及 before/current/after 证据是否自洽，这些都可以直接形成多档 reward。使用标准 DPO 时，需要先离线采样并把候选两两配成偏好对；例如把误差 1 帧的回答作为 chosen、误差 5 帧的回答作为 rejected。这样也能训练，但固定偏好对主要覆盖采样时模型产生的错误，而且二元偏好不能直接表达同组多个候选的完整分数结构。GRPO 可以让当前模型在线暴露最新的边界错误，并直接利用同组多条回答的相对 reward，因此项目最终选择并实现了 GRPO。

不过这不是说 DPO 不能用于关键帧任务。如果在线视频 rollout 成本过高，或者已经积累了大量稳定的边界偏好对，DPO 会是更简单的离线 baseline。准确的说法不是“DPO 不适合、GRPO 一定更好”，而是当前任务具备可计算 verifier，且希望优化模型自身产生的 early/late 候选，所以 GRPO 与目标更直接匹配。

## 数据飞轮怎么评估效果，怎么判断需要多少轮？为什么会觉得有收益？

评估数据飞轮时，我会冻结测试集、评测脚本、训练和推理配置，只改变回流数据，比较本轮相对上一轮的增量。模型效果看全量 ACC、业务线和任务分桶、帧误差；数据效率看单位标注带来的提升和重复 bad case 的下降速度；业务价值看线上命中率、人工复核时长和标注成本。困难集用于诊断，最终还要在固定回归集和时间外样本上复验。

轮数不是提前写死的，而由边际收益决定。项目做过三轮返修只是实际记录，不代表三轮最优。当核心指标达到业务门槛，或连续两轮提升低于最小有效差异、同类错误不再下降时，就应停止或切换策略。如果候选样本主要是 GT 错误、规则冲突或链路异常，也应先修数据，而不是继续训练。

数据飞轮预期有收益，是因为它优先回流模型分歧、低 ACC 指标、边界帧、小 UI 元素和高优业务样本，让标注预算覆盖高价值信息；人工复核还能拦截错误 GT。但这只是收益机制，仍需在相同标注量和训练预算下，对比主动筛选与随机采样。只有前者在固定回归集和线上回测中持续更优，且全量能力和格式稳定性不退化，才能把提升归因于数据飞轮。
