# Hive、Spark 与 Feature Store

## 一句话解释

Hive 和 Spark 解决大规模离线数据处理问题；Feature Store 解决训练和线上服务之间的特征统一、复用、版本管理和一致性问题。

## 为什么算法工程师需要掌握

大厂算法岗不是只训练模型，还要处理真实业务数据。

常见工作包括：

- 从 Hive 表中取训练样本。
- 用 Spark 清洗、聚合、 join 大规模日志。
- 构造用户、商品、内容、上下文特征。
- 保证训练特征和线上特征一致。
- 做数据版本、特征版本、数据质量检查。

## Hive

Hive 是建立在大数据存储之上的 SQL 查询和数仓工具。

常见用途：

- 存储离线日志。
- 建训练样本表。
- 做日级、小时级数据聚合。
- 用 SQL 做指标统计。

常见概念：

- 表。
- 分区。
- 分桶。
- UDF。
- 离线任务调度。

算法工程师需要会：

- 写复杂 SQL。
- 按时间分区取数。
- 避免全表扫描。
- 检查样本量、空值、重复、标签分布。

## Spark

Spark 是分布式计算引擎，适合处理大规模数据清洗和特征工程。

常见用途：

- 大表 join。
- 样本构造。
- 特征聚合。
- 日志解析。
- 数据去重。
- 训练数据导出。

常见接口：

- Spark SQL。
- DataFrame。
- PySpark。
- RDD。

## Feature Store

Feature Store 是特征管理系统，核心目标是解决特征复用和训练-Serving 一致性。

它通常包含：

- 离线特征库。
- 在线特征库。
- 特征定义。
- 特征版本。
- 特征血缘。
- 特征质量监控。

## 训练-Serving Skew

训练-Serving Skew 指训练时使用的特征和线上推理时使用的特征不一致。

常见原因：

- 离线 SQL 和线上代码逻辑不一致。
- 特征时间窗口不一致。
- 缺失值处理不一致。
- 实时特征延迟。
- 特征版本错配。

解决思路：

- 特征定义统一。
- 离线和在线共享特征转换逻辑。
- 做样本回放。
- 监控线上特征分布。
- 记录特征版本。

## 数据质量检查

常见检查：

- 样本数。
- 正负样本比例。
- 空值率。
- 重复率。
- 特征分布。
- 标签泄漏。
- 时间穿越。
- 分区完整性。
