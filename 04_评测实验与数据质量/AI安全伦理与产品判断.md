# AI安全伦理与产品判断

## 知识点解析

### 概述

AI安全伦理与产品判断 是一个复习总纲，主要用于整理该方向的高频面试问题、核心知识点和回答要点。

#### 高频问题

1. AI 模型有哪些常见安全风险？
2. 什么是 prompt injection？RAG 和 Agent 系统为什么更容易受影响？
3. 如何防止模型泄露隐私、密钥或训练数据？
4. 如何处理有害内容、偏见、歧视、幻觉和版权风险？
5. 安全评测应该覆盖哪些维度？
6. 什么是 guardrail？它应该放在模型前、中、后哪个位置？
7. 如何设计人工审核和自动审核结合的机制？
8. 如何在用户体验和安全限制之间做平衡？
9. 如何处理模型拒答过多的问题？
10. Agent 工具调用有哪些安全边界？
11. AI 产品上线前需要哪些评估？
12. 算法工程师如何理解业务指标，而不是只优化模型指标？

### 核心知识点

- 安全风险：隐私泄露、越权访问、提示注入、有害内容、偏见歧视、幻觉、版权、数据投毒。
- 防护机制：输入过滤、输出审核、权限校验、工具白名单、沙箱、审计日志、敏感信息脱敏。
- RAG 安全：文档权限、检索污染、恶意上下文、引用真实性、知识边界。
- Agent 安全：工具权限、确认机制、动作幂等、危险操作审批、状态隔离。
- 安全评测：红队测试、越狱测试、隐私测试、偏见测试、事实性测试、鲁棒性测试。
- 产品判断：用户价值、成本收益、延迟体验、失败兜底、可解释性、运营闭环。

#### 回答要点

- 安全不能只依赖模型拒答，应结合权限、数据、工具、审计和产品流程做系统性防护。
- Prompt injection 的本质是外部输入试图覆盖系统指令或诱导模型执行越权动作。
- RAG 系统必须保证用户只能检索到自己有权限看的内容，否则模型会成为数据泄漏通道。
- Agent 工具调用要遵循最小权限原则，高风险动作需要显式确认、审批或回滚机制。
- 产品上不能只看模型指标，还要看用户完成率、满意度、成本、延迟、投诉率和风险事件。
