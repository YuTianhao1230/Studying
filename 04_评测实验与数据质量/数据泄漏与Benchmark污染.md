# 数据泄漏与Benchmark污染

## 知识点解析

### 概述

数据泄漏是训练阶段看到了本不该看到的信息；Benchmark 污染是模型训练数据中混入了评测集或相似题，导致评测结果虚高。

### 为什么严重

评测的目标是估计模型在未知数据上的泛化能力。

一旦泄漏：

- 离线指标会虚高。
- 模型真实能力被高估。
- 上线效果可能不符合预期。
- 不同模型对比不公平。
- 训练迭代方向被误导。

### 常见泄漏类型

#### 标签泄漏

特征中直接或间接包含标签。

例子：

- 用了未来点击行为预测当前点击。
- 用了人工审核结果作为输入特征。
- 数据字段里包含答案。

#### 时间泄漏

训练集使用了预测时刻之后才会出现的信息。

例如用未来 7 天行为预测今天是否转化。

#### 切分泄漏

训练集和测试集不是独立样本。

常见：

- 同一用户数据同时出现在训练和测试。
- 同一问题不同改写进入不同集合。
- 同一视频不同抽帧进入不同集合。

#### 评测集污染

Benchmark 样本或答案出现在训练语料、SFT 数据、偏好数据或合成数据中。

大模型尤其容易出现，因为预训练语料来源广、规模大、难以完全审计。

### Benchmark 污染的信号

- 模型在某公开 benchmark 上异常高。
- 换成新构造数据后表现明显下降。
- 答案和标准解析高度相似。
- 对题目轻微改写后性能大幅下降。
- 模型能复述题目来源或标准答案。

### 如何检测

- Exact match：精确匹配。
- Near-duplicate：近重复检测。
- MinHash / SimHash。
- Embedding 相似度检索。
- n-gram overlap。
- 题目改写鲁棒性测试。
- 时间切分验证。

### 如何避免

- 严格区分训练集、验证集、测试集和回归集。
- 数据版本可追踪。
- 评测集单独权限管理。
- 构造 private eval。
- 对训练数据做去重和污染扫描。
- 避免把评测 bad case 直接加入训练集后继续用原测试集评估。

### 和线上效果的关系

Benchmark 分数高不等于线上好。

需要同时看：

- 未公开评测集。
- 业务真实数据。
- Bad case。
- A/B 测试。
- 人工抽检。
- 线上安全指标。

## 面试应对

### 什么是数据泄漏？

回答思路：先给一句话定义，再说明它解决什么问题，最后补一个工程例子或常见风险。

回答模板：

数据泄漏 是 数据泄漏与Benchmark污染 里的核心概念，主要解决系统在能力、效率、稳定性或可控性上的问题。面试中要说明它的定义、适用场景、限制，以及在真实工程中如何验证它有效。

### Benchmark 污染为什么会导致评测虚高？

回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。

回答模板：

数据泄漏与Benchmark污染 的核心含义是：数据泄漏是训练阶段看到了本不该看到的信息；Benchmark 污染是模型训练数据中混入了评测集或相似题，导致评测结果虚高。 面试回答时我会先给定义，再说明它解决的背景问题，接着讲核心机制和适用场景，最后补充限制与工程风险。这样回答比只背一句概念更完整。

### 如何检测训练数据和测试集重复？

回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。

回答模板：

可以做精确匹配、n-gram overlap、MinHash/SimHash、embedding 近邻检索和改写鲁棒性测试。发现近重复后要按题目、用户或内容源整体隔离。

### 为什么按用户或时间切分有时比随机切分更合理？

回答思路：先指出背后的核心约束，再解释收益，最后补充如果不这样做会带来的风险。

回答模板：

随机切分可能让同一用户、同一内容或未来信息同时进入训练和测试，造成泄漏。按用户或时间切分更接近真实上线时面对未知用户或未来数据的场景。

### 如果发现测试集被污染，应该怎么办？

回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。

回答模板：

污染后的指标不能作为结论，应重新构建干净测试集或 private eval，并记录污染来源。已用污染集调参的模型也要用新测试集重新评估。
