# LLM_Judge

## 知识点解析

### 概述

LLM Judge 是用大模型作为评审器，根据预设 rubric 对模型输出进行打分、比较或错误归因。

### 为什么需要

传统指标适合有标准答案的任务，例如分类准确率、BLEU、ROUGE、Exact Match。

但大模型输出常常是开放式的：

- 摘要。
- 问答解释。
- 多轮对话。
- Agent 轨迹。
- 代码解释。
- 多模态描述。

这类任务很难用单一字符串匹配指标评估，因此会引入 LLM Judge。

### 常见评测方式

#### 单答案打分

给定 prompt、参考信息和候选回答，让 Judge 按 rubric 打分。

适合：

- 摘要质量。
- 答案完整性。
- 安全性判断。

#### Pairwise 比较

比较 A 和 B 哪个更好。

优点：

- 比绝对打分更稳定。
- 更接近偏好标注。

缺点：

- 可能有位置偏差。
- 需要随机交换顺序。

#### 维度化评分

按多个维度分别评分：

- 正确性。
- 完整性。
- 忠实性。
- 格式。
- 安全性。
- 简洁性。

### 好 Rubric 的标准

- 标准具体。
- 每个分数档有明确描述。
- 区分事实错误和表达问题。
- 明确哪些错误是一票否决。
- 要求 Judge 给出证据引用。
- 对格式和语义分别评分。

### 常见风险

- Judge 偏向长答案。
- Judge 偏向某种表达风格。
- 位置偏差：更偏好 A 或 B。
- 自评偏差：同系列模型可能偏爱同系列输出。
- 被待评答案 prompt injection。
- 评分不稳定。

### 提升可靠性的做法

- 固定 Judge 模型和版本。
- 多次采样取平均或投票。
- Pairwise 顺序随机交换。
- 加入人工抽检。
- 用黄金集校准 Judge。
- 保存 Judge 理由，便于审计。
- 对高风险结论使用规则或人工复核。

### 和 Reward Model / Grader 的关系

- LLM Judge 是一种 Grader。
- Reward Model 常用于训练奖励。
- LLM Judge 常用于离线评测、bad case 标注、数据筛选。

## 面试应对

### 为什么开放式生成任务需要 LLM Judge？

回答思路：先指出背后的核心约束，再解释收益，最后补充如果不这样做会带来的风险。

回答模板：

因为 开放式生成任务需要 LLM Judge 背后有明确工程约束：如果不处理，容易带来质量不稳定、成本上升、错误难排查或安全风险。在 LLM Judge 场景里，这个问题的关键是说明它如何提升系统可控性、可验证性和线上稳定性。

### 如何设计一个可靠的 Judge rubric？

回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。

回答模板：

我会把 设计一个可靠的 Judge rubric 拆成几个步骤：先明确目标和输入输出，再设计关键模块或策略，然后加入失败处理和权限/质量约束，最后用离线指标、线上指标或回归测试验证效果。在 LLM Judge 场景里，重点是能落到真实工程流程。
