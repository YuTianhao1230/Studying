# 模型评测与实验设计

## 知识点解析

### 概述

模型评测与实验设计用于回答三个问题：模型是否真的变好、提升来自哪里、结论能否复现。完整评测不能只报告一个平均分，还要同时覆盖任务质量、关键分桶、统计不确定性、系统成本和失败模式，并通过受控实验排除随机波动、数据污染与实现差异。

#### 高频问题

1. 如何设计一个模型评测体系？
2. 离线指标和线上指标有什么区别？二者不一致时怎么办？
3. Accuracy、F1、AUC、BLEU、ROUGE、BERTScore、pass@k 分别适合什么任务？
4. 生成式模型如何评估？自动评测和人工评测分别有什么问题？
5. LLM-as-Judge 如何设计？如何降低 judge 偏差？
6. A/B Test 的基本流程是什么？如何判断实验显著？
7. 什么是置信区间、p-value、统计功效？
8. 如何做消融实验？消融实验能说明什么，不能说明什么？
9. 模型效果提升 1% 是否可信？你会如何验证？
10. 如何分析 bad case？如何区分数据问题、模型问题、评测问题？
11. Benchmark 污染是什么？如何规避？
12. 如何构建一个长期可用的回归测试集？

### 核心知识点

- 评测对象：分类、排序、生成、检索、多模态、Agent、代码生成。
- 离线指标：Accuracy、Precision、Recall、F1、AUC、PR-AUC、NDCG、MRR、BLEU、ROUGE、EM、F1、pass@k。
- 生成评测：人工偏好、规则评测、模型裁判、事实一致性、格式遵循、覆盖度、多样性。
- 实验方法：train/valid/test 划分、交叉验证、holdout、bootstrap、显著性检验。
- A/B Test：流量分桶、实验周期、最小样本量、护栏指标、业务指标。
- Case 分析：错误聚类、分桶分析、长尾样本、标签噪声、难度分层。
- 回归体系：固定 benchmark、版本管理、指标看板、阈值报警、失败样本追踪。

#### 回答要点

- 一个好的评测体系需要覆盖总体指标、关键子场景、长尾场景、稳定性、成本和延迟。
- 离线评测强调可复现和快速迭代，线上评测强调真实用户分布和业务收益。
- LLM-as-Judge 需要明确 rubric、输出结构化结果、控制位置偏差、顺序偏差、长度偏差，并用人工标注集校准。
- 消融实验应一次只改变一个关键因素，并保证数据、随机种子、训练步数、推理参数等条件一致。
- Bad case 分析应先分桶，再抽样复核，避免只看几个极端样本得出结论。
- 回归集应稳定、分层、可追溯，避免被训练集污染，同时保留代表性失败样本。

### 评测体系设计

一个可落地的评测体系通常分为五层：

| 层次 | 关注问题 | 典型指标 |
| --- | --- | --- |
| 任务质量 | 模型是否完成目标任务 | Accuracy、F1、NDCG、pass@k、胜率 |
| 场景覆盖 | 哪些人群、难度或任务类型受益 | 分桶指标、长尾召回、最差分组表现 |
| 稳定性 | 换随机种子、提示或版本后是否稳定 | 方差、置信区间、一致率、回归失败数 |
| 系统表现 | 上线后能否满足服务约束 | p50/p95/p99、吞吐、错误率、可用性 |
| 成本与风险 | 提升是否值得，是否引入新风险 | 单请求成本、Token 消耗、安全违规率 |

评测集应明确来源、时间范围、去重规则、难度分层和版本。固定回归集用于版本比较，挑战集覆盖已知薄弱场景，动态集用于发现新问题，三者不能混为一套。

### 统计显著性与不确定性

#### 置信区间

点估计只能说明当前样本上的结果，置信区间用于表达估计的不确定性。分类准确率可以使用二项分布近似或 Wilson 区间；复杂指标和生成任务常使用 Bootstrap：

1. 从原评测集有放回抽取与原集等大的样本。
2. 计算一次指标或两个模型的指标差。
3. 重复多次，得到经验分布。
4. 使用分位数构造置信区间。

比较两个模型时，优先对同一批样本做配对 Bootstrap，因为它能消除样本难度差异带来的部分方差。

#### p-value、效果量与统计功效

- p-value：原假设成立时，观察到当前或更极端结果的概率。
- 效果量：提升究竟有多大，例如胜率提升、CTR 相对增幅。
- 统计功效：当真实提升存在时，实验发现它的概率。

显著不等于有业务价值，不显著也不等于完全无效。样本量不足时，较大的真实提升也可能无法被检出。因此实验前应根据基线水平、最小可接受提升、显著性水平和目标功效估算样本量。

#### 多重检验

如果同时尝试很多模型、指标或切分，总会有一部分结果偶然显著。应预先确定主指标，并使用 Bonferroni、Holm 或 FDR 等方法控制多重比较风险，避免只汇报最好的结果。

### 人工评测与 LLM Judge

人工评测需要明确 rubric、样本抽样方法、盲评方式和冲突仲裁。常用一致性指标包括 Cohen's Kappa、Fleiss' Kappa 和 Krippendorff's Alpha。只报告平均分而不报告标注一致性，无法判断结果差异来自模型还是标注噪声。

LLM Judge 上线前至少要做：

1. 用人工金标集验证与人类偏好的相关性。
2. 交换候选答案顺序，检测位置偏差。
3. 控制长度和格式，检测冗长偏差。
4. 多次采样或多 Judge 复核不稳定样本。
5. 保存 Judge 模型、Prompt、解码参数和版本。
6. 对高风险决策保留人工仲裁。

### 消融与归因

有效的消融实验要回答“哪个因素带来了提升”，而不是简单删除模块：

- 一次只改变一个关键变量。
- 固定数据、代码版本、训练预算和推理参数。
- 报告重复实验的均值与方差。
- 同时观察总体指标、关键分桶和成本指标。
- 检查模块之间是否存在交互效应。

当多个改动一起上线时，可以使用逐项消融、全因子实验或分阶段上线识别贡献。不能把相关性直接写成因果结论。

### Bad Case 分析

Bad case 分析建议采用固定流程：

```text
确认指标实现
  -> 对齐输入输出与解析
  -> 按任务、来源、长度、难度分桶
  -> 抽样人工复核
  -> 建立错误 taxonomy
  -> 估算各类错误影响面
  -> 设计针对性实验
  -> 回归验证
```

优先处理高频、高损失、可修复且不会破坏其他能力的问题。个别极端样本不能代表总体趋势，但稳定重复出现的长尾错误也不能被平均指标掩盖。

## 面试应对

### 如何设计一个完整的模型评测体系？

回答思路：从目标、数据、指标、统计、归因和回归六个环节展开。

回答模板：

我会先明确模型服务的真实目标和失败成本，再构建有代表性、分层且与训练数据隔离的评测集。指标上不仅看总体任务指标，还看关键场景、长尾、安全、延迟和成本。比较模型时使用同一批样本，报告置信区间并做配对检验，避免把随机波动当成提升。对生成任务会结合规则指标、人工评测和经过人工金标校准的 LLM Judge。最后通过消融和 bad case 分类定位提升来源，并把稳定样本沉淀为版本化回归集。

### 两个模型胜率 52% 对 48%，能否说明前者更好？

回答思路：先拒绝只看点估计，再检查样本量、配对关系、置信区间和偏差。

回答模板：

只看 52% 对 48% 不能直接下结论。我会先确认有效样本量、平局处理和评测是否配对，再对胜率差计算置信区间或做配对 Bootstrap。如果区间跨过零，说明当前证据不足；即使统计显著，也要看提升幅度是否有业务价值。同时要检查 Judge 的位置偏差、长度偏差和样本分布，确保差异不是评测流程造成的。

### 自动指标和人工偏好冲突时怎么办？

回答思路：判断指标与业务目标是否对齐，再做分桶和校准。

回答模板：

我不会直接选择其中一个结果，而是先检查自动指标测量的能力是否与业务目标一致。例如 BLEU 更关注词面重合，人类可能更关注事实性和可读性。接着对冲突样本分桶，检查人工标注一致性和自动指标实现。如果人工标准可靠，就用这些金标样本校准规则指标或 Judge，并重新定义主指标和护栏指标。最终选择应由真实业务目标决定，而不是由某个指标是否方便计算决定。
