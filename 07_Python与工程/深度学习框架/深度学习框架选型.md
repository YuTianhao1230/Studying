# 深度学习框架选型

## 知识点解析

### 概述

深度学习框架是把张量计算、自动求导、模型构建、训练循环、分布式训练和部署工具组织起来的软件基础设施。算法工程师常见选择包括 PyTorch、TensorFlow/Keras、JAX，以及围绕大模型训练形成的 Hugging Face Transformers、DeepSpeed、Megatron-LM、FSDP 等生态。

面试里问“PyTorch、TensorFlow、JAX 怎么选”，本质不是让你背 API，而是看你是否理解不同框架在研究迭代、工程部署、编译优化、分布式训练和生态兼容上的取舍。

### 选型原则

如果目标是研究迭代、快速调试、自定义训练逻辑，通常优先 PyTorch。PyTorch 的动态图机制直观，和 Python 控制流结合紧密，适合写自定义 loss、复杂 forward、强化学习、Agent 训练和多模态训练。现在大模型开源生态也大量围绕 PyTorch 展开，例如 Transformers、Accelerate、PEFT、DeepSpeed、FSDP、vLLM。

如果目标是传统工业部署、移动端、端侧、Serving 体系或已有 TensorFlow 生产链路，TensorFlow/Keras 仍然有价值。Keras 上手快，SavedModel、TensorFlow Serving、TFLite、TFX 等工具在部分企业生产系统里较成熟。但在大模型研究和开源训练生态里，TensorFlow 的主流程度已经明显低于 PyTorch。

如果目标是高性能数值计算、TPU、编译优化、函数式变换和大规模研究系统，JAX 更常见。JAX 的 `jit`、`vmap`、`pmap/pjit` 和 XLA 编译能力很强，Google/DeepMind 生态使用较多，但工程门槛和生态通用性相对 PyTorch 更高。

### 常见框架对比

| 框架 | 主要优势 | 主要限制 | 更适合的场景 |
| --- | --- | --- | --- |
| PyTorch | 动态图直观、调试方便、开源大模型生态强 | 生产部署需要额外工程组件 | 研究实验、大模型训练、多模态、RL、快速迭代 |
| TensorFlow/Keras | 部署生态成熟、Keras 简洁、端侧工具完整 | 大模型开源训练生态相对弱 | 传统工业链路、移动端、已有 TF 系统 |
| JAX | 函数式、XLA 编译强、TPU 生态好 | 学习曲线高，工程生态相对集中 | 高性能研究、TPU、大规模数值计算 |
| Hugging Face | 模型、数据、训练组件生态完整 | 抽象较厚，深度定制时要理解底层 | LLM/VLM 微调、推理、开源模型复现 |
| DeepSpeed/FSDP/Megatron | 解决大模型显存和并行训练 | 配置复杂，排障成本高 | 大规模分布式训练 |

### 工程使用方式

实际项目里通常不是只用一个框架，而是组合使用。

模型训练常见组合是：PyTorch 写模型和训练逻辑，Transformers 加载模型和 tokenizer，Datasets 处理数据，PEFT 做 LoRA/QLoRA，Accelerate 或 DeepSpeed/FSDP 做分布式训练，Weights & Biases / TensorBoard 做实验追踪。

模型推理常见组合是：训练产物保存为 Hugging Face 格式或 checkpoint，离线评测用 PyTorch/Transformers，线上服务可能交给 vLLM、TensorRT-LLM、TGI 或自研 Serving。

### 常见误区

框架不是越新越好。选型要看团队已有生态、训练规模、部署目标、调试成本和人才熟悉度。比如 JAX 在编译和 TPU 上很强，但如果团队主要用 PyTorch、模型来自 Hugging Face、训练框架是 DeepSpeed，那么强行切 JAX 反而会增加成本。

另一个误区是把“会用框架”等同于“会训练模型”。真正的训练能力还包括数据 pipeline、loss 设计、优化器、混合精度、分布式、checkpoint、日志监控、评测和故障排查。

## 面试应对

### PyTorch、TensorFlow、JAX 怎么选？

回答思路：不要只说“PyTorch 最常用”，要从研究迭代、部署生态、编译性能、团队链路和大模型生态几个维度回答。

回答模板：

我会根据任务目标和工程约束选框架。如果是研究迭代、自定义训练逻辑、大模型微调或多模态训练，我通常优先 PyTorch，因为动态图调试方便，Hugging Face、DeepSpeed、FSDP、vLLM 等生态也更完整。如果团队已有 TensorFlow Serving、TFLite 或 TFX 链路，TensorFlow/Keras 仍然适合生产部署和端侧场景。如果是 TPU、高性能编译或 DeepMind/Google 风格的大规模研究系统，JAX/XLA 更有优势。框架选型不是看哪个更先进，而是看数据、训练、部署、团队和生态是否匹配。

### 只会 PyTorch 够不够？

回答思路：承认 PyTorch 是主线，但要体现迁移能力和底层概念通用性。

回答模板：

做大模型训练方向，PyTorch 是最重要的主线，尤其是 Hugging Face、FSDP、DeepSpeed、Megatron 这些生态都和 PyTorch 结合紧密。但只会 PyTorch API 不够，核心是理解张量、自动求导、计算图、优化器、混合精度、分布式和 checkpoint 这些通用概念。理解这些以后，迁移到 TensorFlow 或 JAX 时主要是适配编程范式和工程生态。

### 框架选型时你最关注什么？

回答思路：按目标、生态、性能、部署、团队成本回答。

回答模板：

我最关注五点：第一，任务目标是研究实验还是生产部署；第二，模型和工具生态是否成熟，比如是否支持目标模型、分布式训练和推理服务；第三，性能和显存优化能力是否满足规模要求；第四，部署链路是否顺畅；第五，团队是否熟悉，后续排障和维护成本是否可控。框架只是工具，最终要服务训练效率、效果验证和上线稳定性。

### 深度学习框架背后的共性是什么？

回答思路：抽象到张量、自动求导、模型参数、优化器、数据加载、训练循环。

回答模板：

不同框架表层 API 不一样，但核心抽象类似：用 Tensor 表示数据和参数，用计算图记录前向计算，用 autograd 计算梯度，用 optimizer 更新参数，用 dataloader 组织 batch，用 checkpoint 保存状态。面试里如果被问框架差异，我会先讲这些共性，再讲动态图/静态图、编译、部署和生态差异。
