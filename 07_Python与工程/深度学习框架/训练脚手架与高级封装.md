# 训练脚手架与高级封装

## 知识点解析

### 概述

训练脚手架是对训练循环的工程封装，用来减少重复代码，统一日志、评估、checkpoint、混合精度和分布式配置。常见选择包括 Hugging Face Trainer、Accelerate、PyTorch Lightning、DeepSpeed 配置化训练，以及完全手写 PyTorch loop。

面试里问这些工具，重点不是背库名，而是说明：什么时候应该用高层封装提高效率，什么时候应该回到手写 loop 保持控制力。

### 常见选择

手写 PyTorch loop 控制力最强，适合复杂训练逻辑、自定义 loss、多任务、多模态、RLHF/GRPO、在线采样和特殊分布式逻辑。缺点是重复代码多，日志、评估、checkpoint、混合精度都要自己处理。

Hugging Face Trainer 适合标准 NLP/LLM 监督训练。它快速、统一、生态好，但复杂自定义逻辑会受限。

Accelerate 更像轻量分布式适配层，可以让同一套 PyTorch 代码更容易跑在单卡、多卡、混合精度或不同设备上。它比 Trainer 更灵活，但比完全手写分布式更省事。

PyTorch Lightning 把训练拆成 `LightningModule`、`Trainer`、callback、logger 等模块，适合规范化实验和减少样板代码。它在视觉、常规深度学习实验里常见，但大模型训练中更常见的是 Transformers + Accelerate/DeepSpeed/FSDP。

DeepSpeed/FSDP/Megatron 更偏大规模训练系统，不只是脚手架。它们解决的是显存切分、并行策略、通信优化和训练吞吐问题，复杂度也更高。

### 选型判断

| 场景 | 推荐选择 | 原因 |
| --- | --- | --- |
| 快速 SFT baseline | Hugging Face Trainer | 少写训练循环，生态完整 |
| PyTorch 代码想兼容多卡/混合精度 | Accelerate | 保留自定义 loop，同时降低分布式复杂度 |
| 常规视觉/分类实验 | PyTorch Lightning | 结构清晰，日志和 callback 方便 |
| 复杂 RLHF/GRPO/在线 rollout | 手写 loop + 专用框架 | 需要强控制力 |
| 大模型多机训练 | DeepSpeed/FSDP/Megatron | 解决显存和并行训练 |

### 使用边界

高层封装能提高开发效率，但也会隐藏细节。遇到 loss 异常、梯度不更新、显存暴涨、checkpoint 恢复失败、分布式卡死时，必须能回到底层理解训练循环。

一个成熟训练工程师应该做到：简单任务会用封装快速跑通，复杂任务能拆开封装定位问题，必要时能手写最小可复现训练循环。

## 面试应对

### Trainer、Accelerate、Lightning、自定义 loop 怎么选？

回答思路：按任务复杂度和控制力需求回答。

回答模板：

如果是标准 SFT、分类或序列标注，我会优先用 Hugging Face Trainer 快速建立 baseline。如果已有自定义 PyTorch loop，但希望兼容多卡和混合精度，可以用 Accelerate。如果是常规深度学习实验，需要规范化日志、callback 和 checkpoint，可以用 Lightning。如果是 RLHF、GRPO、多模态复杂 batch 或在线 rollout，我更倾向手写 loop 或专用训练框架，因为需要更强控制力。

### 高层封装有什么风险？

回答思路：说明效率收益和隐藏细节之间的矛盾。

回答模板：

高层封装的好处是减少样板代码，快速支持日志、评估、checkpoint 和分布式。但风险是隐藏了训练细节，出问题时不好排查。比如 label mask 错、梯度没有更新、混合精度溢出、checkpoint 没保存 optimizer 状态，这些问题只看封装 API 很难定位。所以我会用封装提高效率，但保留理解和改写底层训练循环的能力。

### 为什么算法工程师仍然要会手写训练循环？

回答思路：强调复杂任务和排障需要底层理解。

回答模板：

手写训练循环能帮助理解训练真正发生了什么：数据如何进入模型，loss 如何计算，梯度如何反传，optimizer 如何更新参数，日志和 checkpoint 如何保存。复杂训练任务经常需要自定义 loss、动态采样、多任务权重、梯度累积或特殊评测，这时高层封装不一定够用。即使平时使用 Trainer，也应该能写出最小训练 loop 来复现和排查问题。

### 训练脚手架和分布式框架是什么关系？

回答思路：区分训练流程封装和底层并行能力。

回答模板：

训练脚手架主要封装训练流程，比如日志、评估、checkpoint、callback 和训练循环；分布式框架主要解决多卡多机训练中的显存切分、通信和并行效率。二者可以组合，例如 Trainer 接 DeepSpeed，PyTorch loop 接 Accelerate 或 FSDP。面试里要把“流程编排”和“分布式执行”区分开。
