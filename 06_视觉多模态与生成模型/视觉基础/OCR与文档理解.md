# OCR与文档理解

## 知识点解析

### 概述

OCR 是把图片中的文字识别出来；文档理解是在 OCR 基础上进一步理解版面、结构、表格、语义和任务答案。

### OCR 解决什么

OCR，Optical Character Recognition，主要解决：

- 图片文字检测。
- 文本行识别。
- 表格文字提取。
- 票据、合同、证件、截图识别。

传统 OCR 更关注“识别出文字”；文档理解更关注“理解这些文字在文档里的含义和结构”。

### 文档理解任务

常见任务：

- Layout Analysis：版面分析。
- Table Understanding：表格理解。
- Key Information Extraction：关键信息抽取。
- Document VQA：基于文档图像问答。
- Chart Understanding：图表理解。
- Multi-page Reasoning：跨页推理。

### 大模型时代的变化

多模态大模型让 OCR 和文档理解开始融合：

```text
图像输入
  -> 视觉编码
  -> 文本识别 / 版面理解
  -> 多模态推理
  -> 结构化输出
```

模型不只是读字，还要理解：

- 字在哪里。
- 属于哪个字段。
- 和其他元素有什么关系。
- 是否支持用户问题的答案。

### 关键难点

- 低清晰度图片。
- 复杂表格。
- 多栏排版。
- 手写体。
- 旋转、遮挡、噪声。
- 图文位置关系。
- 跨页字段关联。

### 评测指标

- 字符准确率。
- 文本行召回率。
- 字段抽取准确率。
- 表格结构还原准确率。
- VQA 准确率。
- Grounding 准确率。

## 面试应对

### OCR 和文档理解有什么区别？

回答思路：抓住“识别文字 vs 理解结构和语义”这个层次差异。

回答模板：

OCR 解决的是“把图里的文字识别出来”，包括文字检测、文本行识别、表格文字提取，输出是纯文本。文档理解是在此基础上更进一步，要理解这些文字在文档里的版面、结构、字段关系和语义，比如哪块是标题、哪块是表格、某个数字属于哪个字段、能不能支撑用户的问题。简单说 OCR 关心“读出字”，文档理解关心“读懂文档”，后者才是真正有业务价值的部分。

### 大模型时代 OCR 和文档理解发生了什么变化？

回答思路：讲从“分步 pipeline”到“端到端多模态”的转变。

回答模板：

传统做法是分步 pipeline：先检测、再识别、再单独做版面分析和信息抽取，各模块独立，误差会累积。多模态大模型出现后，OCR 和文档理解开始融合成端到端：图像直接过视觉编码，模型内部同时完成识别、版面理解和推理，最后直接输出结构化答案或回答文档问题。好处是少了模块间的误差传递、能利用上下文纠错，也更容易泛化到新版式，代价是对分辨率和推理成本要求更高。

### 文档理解有哪些典型任务和评测指标？

回答思路：任务和指标对应着讲，突出不同任务要用不同指标。

回答模板：

典型任务有版面分析、表格理解、关键信息抽取、文档问答 DocVQA、图表理解和跨页推理。评测要按任务选指标：纯识别看字符准确率和文本行召回率；关键信息抽取看字段抽取准确率；表格看结构还原准确率；文档问答看 VQA 准确率；如果要求答案定位到证据区域，还要看 grounding 准确率。核心是识别质量和理解质量要分开衡量，不能只报一个总分。

### 文档理解的主要难点在哪？怎么应对？

回答思路：从图像质量、复杂版式、细粒度识别、跨页关联几个角度给难点和对策。

回答模板：

难点主要有几类：一是图像质量差，低清晰度、旋转、遮挡、手写体会拉低识别率，通常靠图像增强和更强的视觉编码器；二是复杂版式，多栏排版、复杂表格容易让字段错位，需要专门的版面和表格结构建模；三是细粒度识别，小字、密集文本对分辨率要求高，用动态分辨率或切图分块编码来解决；四是跨页字段关联，长文档里一个字段可能跨页，需要更长上下文或先检索定位再理解。落地时我会重点盯 bad case，因为文档场景的错误往往集中在少数难样本上。
