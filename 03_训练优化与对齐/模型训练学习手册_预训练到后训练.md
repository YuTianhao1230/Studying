# 模型训练路线：预训练到后训练

> 来源：https://bytedance.larkoffice.com/docx/Fm4TdqbHpo1MPgx7nT1cuW4in0e

这是一张训练项目导航卡。它负责说明阶段顺序、选择条件和交付物；模型结构、训练算法、数据评测和部署细节分别链接到02、03、04、05中的权威卡。

其中，训练前后的数据构造、切分、治理和评测统一由 [04_评测实验与数据质量](<../04_评测实验与数据质量/README.md>)维护；本卡只说明这些环节如何进入训练流程。通用方法与个人项目事实也保持分离：[关键帧检测](<../12_实习工作整理/关键帧检测/README.md>)记录实习中的实际选择、实施过程和结果，这里不复制项目方案。

## 目录学习顺序

训练工程可以按[超参数与优化器](<超参数与优化器/README.md>)、[训练框架与并行](<训练框架与并行/README.md>)、[训练稳定性](<训练稳定性/README.md>)的顺序学习，先理解参数更新，再理解系统实现，最后建立故障排查闭环。

强化学习后训练先读[强化学习基础](<../01_机器学习基础/概率与序列决策/强化学习基础.md>)，推导回报、优势和策略梯度，再读 [PPO](<后训练与对齐/PPO 近端策略优化.md>)与 [GRPO](<后训练与对齐/GRPO 组相对策略优化.md>)，理解策略更新和奖励设计。数据准备与效果验证分别从[训练数据构造与合成数据](<../04_评测实验与数据质量/训练数据构造与合成数据.md>)、[数据工程与数据质量](<../04_评测实验与数据质量/数据工程与数据质量.md>)和[模型评测与实验设计](<../04_评测实验与数据质量/模型评测与实验设计.md>)进入，不在训练目录重复维护数据正文。

## 总体路线

```mermaid
flowchart LR
  A[任务与评测定义] --> B[底座选择]
  B --> C[数据构造与隔离]
  C --> D[SFT baseline]
  D --> E{主要缺口}
  E -->|偏好与风格| F[DPO/RLHF]
  E -->|可验证能力| G[RLVR/GRPO]
  E -->|模型成本| H[蒸馏]
  F --> I[评测与错误分析]
  G --> I
  H --> I
  I --> J[部署与监控]
  I -->|未达标| C
```

核心原则是先定位问题，再选择训练方法。数据不足先补数据，格式不稳先做 SFT，偏好不对再做偏好优化，结果可自动验证才考虑 RLVR/GRPO；模型已经达到质量目标后，再处理推理成本和服务约束。

## 继续预训练、SFT、RAG 与后训练怎么选

| 主要现象 | 优先方案 | 判断理由 |
| --- | --- | --- |
| 模型不理解领域术语和文本分布 | 继续预训练 | 需要改变模型对领域语料的表示与语言建模分布 |
| 模型知道内容，但不按任务格式稳定回答 | SFT | 监督样本直接定义输入输出映射 |
| 知识频繁变化，答案必须引用外部资料 | [RAG](<../02_大模型/应用与问题/RAG.md>) | 外部知识比反复写入参数更易更新和追溯 |
| 同一问题能生成多种答案，但偏好排序不稳定 | DPO 或 RLHF | 偏好数据描述“哪个回答更好” |
| 数学、代码、格式或定位结果可自动打分 | RLVR/GRPO | 可执行 reward 能支持采样和策略更新 |
| 强模型效果好，但线上成本过高 | 蒸馏、量化或模型路由 | 问题是能力迁移与系统成本，不是继续堆训练阶段 |

继续预训练时应使用较小学习率，并混入必要的通用数据以监控灾难性遗忘；领域指标和通用能力必须同时评测。SFT、DPO、GRPO 不是固定流水线，后一阶段只有在前一阶段暴露出对应问题时才进入。

## 每个阶段的进入检查

### 训练前

- [ ] 任务输入、输出格式、失败成本和主指标已经固定。
- [ ] train/dev/test 按用户、文档、视频或时间等正确独立单位切分。
- [ ] 数据经过精确与近重复检查，评测集未进入训练、提示示例和合成链路。
- [ ] Tokenizer、Chat Template、最大长度和截断策略与底座一致。
- [ ] 先用未训练底座跑完固定基线，保存配置和逐样本结果。

### SFT 前

- [ ] Assistant 目标区间和 loss mask 已抽样解码确认。
- [ ] 常规例、边界例、负例和困难例都有覆盖。
- [ ] 几十条干净样本能够完成小样本过拟合测试。
- [ ] 学习率、有效 batch、Warmup、精度和 Checkpoint 策略已记录。

### DPO/RLHF 前

- [ ] Chosen 确实优于 rejected，偏好准则可复述且标注一致。
- [ ] 已检查答案长度、拒答比例和格式等系统性偏差。
- [ ] SFT baseline 已稳定，训练后会同时回归任务能力与通用能力。

### RLVR/GRPO 前

- [ ] Reward 在人工样例上与最终指标一致，Parser 失败会返回明确结果而不是崩溃。
- [ ] Reward 各分项、KL、响应长度和格式正确率可以单独监控。
- [ ] 组内采样有足够差异，Reward 不会只鼓励格式、长度或其他捷径。
- [ ] 真实终止、长度截断和 rollout 边界的 bootstrap 语义已经定义。

### 上线前

- [ ] Checkpoint、Adapter、Tokenizer、模板、stop words 和解码参数已锁定。
- [ ] 离线与线上使用相同输入处理和输出解析协议。
- [ ] 延迟、吞吐、显存、错误率、成本和质量护栏均达到阈值。
- [ ] 灰度、监控和回滚路径已经演练。

## 训练运行与故障分诊

训练时至少同步记录 loss、eval metric、learning rate、grad norm、有效 batch、序列长度、tokens/s、显存和 Checkpoint。RL 训练还要记录 reward 分项、KL、响应长度和格式正确率。

| 现象 | 首查方向 | 权威排查入口 |
| --- | --- | --- |
| loss 不动、震荡、突刺或 NaN | 数据、label/mask、学习率、梯度、混合精度 | [Loss异常与收敛排查](<训练稳定性/Loss异常与收敛排查.md>) |
| 梯度爆炸或消失 | 初始化、激活、归一化、残差与裁剪 | [梯度爆炸与梯度消失](<训练稳定性/梯度爆炸与梯度消失.md>) |
| OOM 或模型状态放不下 | 激活、序列长度、优化器状态、参数切分 | [训练框架与并行](<训练框架与并行/README.md>)、[ZeRO](<训练框架与并行/ZeRO.md>)、[FSDP](<训练框架与并行/FSDP.md>) |
| 多卡吞吐低或任务卡住 | 数据等待、计算、集合通信与负载均衡 | [多GPU通信与吞吐优化](<训练框架与并行/多GPU并行通信与吞吐优化.md>)、[分布式故障排查](<训练框架与并行/分布式训练通信与故障排查.md>) |
| 恢复后学习率或结果跳变 | 优化器、调度器、随机状态和数据位置 | [Checkpoint](<训练框架与并行/Checkpoint.md>) |
| reward 升但真实指标不升 | Reward hacking、解析器或指标错位 | [RLVR](<后训练与对齐/RLVR 可验证奖励强化学习.md>)、[Reward Collapse](<后训练与对齐/Reward Collapse 奖励坍缩.md>) |
| 训练指标变好但评测不变 | 过拟合、泄漏、分布偏移或评测实现 | [数据泄漏与污染](<../04_评测实验与数据质量/数据泄漏与Benchmark污染.md>)、[实验排查](<../04_评测实验与数据质量/实验分析与问题排查.md>) |
| 离线正常但线上退化 | 模板、解码参数、服务版本或流量漂移 | [MLOps](<../05_推理部署与系统/生产系统设计/MLOps与模型生产化.md>) |

| 周次 | 学习重点 | 实践产出 |

| 4 | SFT、DPO、偏好数据 | 跑通SFT baseline并构造偏好样本 |
| 5 | RL基础、RLVR、GRPO、Reward与KL | 测试可执行Reward并跑小规模实验 |
| 6 | 多模态、评测、故障排查与部署 | 形成训练到上线的可复现闭环 |

## 最终决策表

| 现象 | 优先怀疑 | 下一步 |
| --- | --- | --- |
| 模型完全不会任务 | 底座能力或SFT数据不足 | 先做SFT小基线，必要时更换底座 |
| 模型不懂领域术语 | 领域语料分布缺失 | 评估继续预训练或RAG |
| 内容基本正确但格式不稳 | 模板和格式样本不足 | 补格式SFT并固定解析协议 |
| 答案可用但偏好不稳 | 缺少偏好信号 | 构造高质量偏好对并尝试DPO |
| 可验证任务仍有提升空间 | 需要采样探索 | 验证Reward后尝试GRPO/RLVR |
| 强模型可用、小模型不足 | 需要能力迁移 | 生成并过滤教师数据做蒸馏 |
| 训练指标提升但测试不升 | 过拟合、泄漏或目标错位 | 检查切分、统计区间和错误分桶 |
| 模型质量达标但上线慢 | 推理与服务约束 | 优化量化、Batch、KV Cache和路由 |

每次迭代只改变能回答当前问题的关键变量，并保存数据版本、代码版本、模型版本、完整配置和逐样本结果。这样训练路线才可解释、可复现，也能明确下一轮应该改数据、训练、Reward、评测还是部署。

## 面试应对

### 如何从业务目标设计一条完整的模型训练路线？

回答思路：从目标指标倒推数据、底座、训练阶段、评测和部署门槛，先建立最小基线，再按误差证据增加训练复杂度。

回答模板：

我会先把业务目标转成可度量的离线指标、线上指标和资源约束，再建立数据切分与评测集，避免训练后才定义成功标准。随后选择满足基础能力和部署条件的底座，用零样本或少样本结果确认起点，再以高质量 SFT 建立最小可用基线。之后根据错误分桶决定是否需要继续预训练、偏好优化、RLVR、蒸馏或 RAG。每进入一个新阶段都设置收益、稳定性和成本门槛，最终通过离线评测、灰度验证和监控完成闭环。

### 继续预训练、SFT、DPO、RLVR 和 RAG 应该怎么选？

回答思路：按知识缺口、任务行为、主观偏好、可验证能力和时效知识分类，并说明方法可以组合但不能互相替代。

回答模板：

领域语言和知识分布明显缺失时，我会评估继续预训练；模型已有基础能力但不会按任务格式回答时，用 SFT；答案基本正确但风格、安全或主观偏好不稳定时，用 DPO 等偏好优化；数学、代码、工具调用这类结果可自动验证且需要采样探索的任务，才考虑 RLVR；知识更新快、需要引用或来自私有库时，优先用 RAG。实际系统可以组合这些方法，但必须先定位误差来源，不能用更重的训练手段掩盖检索、数据或评测问题。

### 如何判断一个训练阶段可以结束并进入下一阶段？

回答思路：用进入门槛和退出门槛管理阶段，联合观察任务指标、分桶表现、泛化、稳定性和成本，不能只看训练 Loss。

回答模板：

我会在训练前定义阶段目标和停止条件。比如 SFT 阶段不仅看 Loss，还要看独立评测集上的任务正确率、格式通过率、关键分桶和通用能力回退；只有基线稳定、数据质量可解释且主要剩余问题确实属于偏好或探索不足，才进入 DPO 或 RL。若收益只出现在训练集、多个随机种子不稳定、通用能力明显下降或成本超过预算，我会停止升级并回到数据、目标函数或评测口径排查。

### 训练指标提升但线上效果没有提升，应该如何定位？

回答思路：沿数据、目标、评测和系统四层核对离线与线上链路，先复现差异，再逐层排除，避免立即继续调参。

回答模板：

我会先固定模型版本、提示词和解码参数，用线上真实样本复现问题，再检查四层一致性：数据层看训练与线上分布、切分和污染；目标层看 Loss 或 Reward 是否真正对应业务目标；评测层看聚合方式、阈值和样本权重；系统层看模板、检索、工具、量化和服务版本是否一致。定位后每轮只改变一个关键变量，并保留逐样本结果和错误分桶。只有离线改进能稳定迁移到线上指标，才能认定训练方案有效。
