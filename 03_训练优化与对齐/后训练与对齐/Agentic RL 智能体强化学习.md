# Agentic RL 智能体强化学习

## 知识点解析

### 概述

Agentic RL 可以翻译为“智能体强化学习”或“面向 Agent 行为的强化学习”。它关注的不是单轮文本回答，而是多步行动轨迹：模型需要规划、调用工具、读取工具结果、调整下一步动作，并最终完成任务。

Agentic RL 和 RLVR 有交集，但不是同一个概念。RLVR 关注 reward 是否可验证；Agentic RL 关注训练对象是否是 Agent 的多步行为。一个 Agent 任务可以使用可验证 reward，也可以使用人工偏好、LLM Judge 或环境反馈。

### 背景

随着模型从聊天助手扩展到工具调用、代码执行、搜索、浏览器操作和 GUI 自动化，训练目标也从“回答质量”变成“任务完成率”。普通 SFT 可以教模型模仿工具调用格式，但很难保证模型在长任务中持续做对：

- 第一步工具选错，后面都会偏。
- 工具参数不对，返回结果无法使用。
- 工具结果已经否定原计划，但模型仍继续错误计划。
- 长任务中上下文变长，模型忘记目标。
- 模型可能完成局部动作，但没有完成最终任务。

Agentic RL 的目标是用环境反馈或轨迹级 reward 优化这些多步决策能力。

### 方法原理

Agentic RL 通常围绕 trajectory 训练。一个 trajectory 包含：

1. 用户任务。
2. 模型的计划或中间思考。
3. 工具调用名称和参数。
4. 工具返回结果。
5. 模型对结果的观察和下一步动作。
6. 最终回答或任务完成状态。
7. 轨迹级 reward 和可能的步骤级 reward。

训练时可以只奖励最终成功，也可以引入中间 reward：

| Reward 类型 | 作用 |
| --- | --- |
| 任务成功 reward | 任务最终是否完成 |
| 工具选择 reward | 是否选对工具 |
| 参数正确 reward | 工具参数是否有效 |
| 证据引用 reward | 是否基于工具结果回答 |
| 安全约束 reward | 是否避免危险操作 |
| 成本 reward | 是否减少无效调用和过长轨迹 |

### 和 RLVR 的区别

| 维度 | RLVR | Agentic RL |
| --- | --- | --- |
| 核心问题 | reward 是否可自动验证 | 多步 Agent 行为如何优化 |
| 训练对象 | 答案、代码、结构化输出、行动结果 | 工具调用轨迹、计划、观察、执行 |
| 典型任务 | 数学、代码、格式、检索命中 | 搜索 Agent、代码 Agent、GUI Agent、工具 Agent |
| 主要难点 | reward hacking、验证器覆盖不足 | credit assignment、环境成本、长轨迹稳定性 |
| 关系 | 可以作为 Agentic RL 的 reward 来源 | 可以使用 RLVR，也可以使用偏好或 Judge |

简单说，RLVR 是“怎么打分”，Agentic RL 是“训练什么行为”。当 Agent 任务最终结果可以验证时，两者会结合，例如代码 Agent 通过单测、搜索 Agent 找到证据、GUI Agent 完成操作。

### 适用场景

Agentic RL 适合需要多步行动的任务：

- Tool-use Agent：选择工具、组织参数、处理返回结果。
- Code Agent：编辑代码、运行测试、根据失败日志修复。
- Search Agent：查询、筛选证据、整合答案。
- Computer-use Agent：操作浏览器、GUI 或远程桌面。
- Data Agent：查询数据库、清洗数据、生成报告。
- Multi-agent coordinator：分配子任务、聚合结果、处理冲突。

如果任务只是单轮问答、没有工具、没有环境反馈，通常不需要直接做 Agentic RL。

### 常见挑战

Agentic RL 的难点比单轮 RL 更复杂：

- 奖励稀疏：最终失败时，不知道是哪一步错了。
- Credit Assignment：工具选错、参数错、理解错、环境变化都可能导致失败。
- 环境成本高：每条 trajectory 都可能要真实调用工具、跑测试或操作浏览器。
- 状态不可控：外部网页、API、文件系统和数据库可能变化。
- 安全风险：Agent 可能执行危险命令、泄露数据或误操作。
- 轨迹过长：模型可能反复搜索、重复调用工具、上下文膨胀。

### 工程实践

Agentic RL 落地时，通常要先做好观测和评测：

1. 记录完整 trajectory，包括工具名、参数、返回、错误和最终结果。
2. 设计任务级 success metric，例如测试是否通过、文件是否正确修改、答案是否有证据。
3. 尽量把高风险操作放在 sandbox 或模拟环境里。
4. 给关键子目标设置中间 reward，缓解奖励稀疏。
5. 对失败轨迹做错误归因，构造 SFT 或偏好数据。
6. 控制工具调用次数、轨迹长度和执行成本。
7. 维护回归任务集，防止 Agent 在某类任务上提升但破坏基础行为。

## 面试应对

### Agentic RL 是什么？

回答思路：先说明它训练的是多步 Agent 行为，而不是单轮回答。

回答模板：

Agentic RL 是面向 Agent 多步行动轨迹的强化学习。普通后训练更多优化单轮回答质量，而 Agentic RL 要优化模型如何规划、调用工具、读取工具结果、调整下一步动作并最终完成任务。它的 reward 可以来自任务是否完成、工具调用是否正确、代码测试是否通过、搜索证据是否命中，也可以来自人工或 LLM Judge。核心目标是提升 Agent 的真实任务完成率，而不是只让回答看起来更好。

### Agentic RL 和 RLVR 有什么关系？

回答思路：区分“训练对象”和“奖励来源”。

回答模板：

Agentic RL 和 RLVR 有交集，但不是同一个概念。RLVR 关注 reward 是否可验证，比如数学答案、代码单测、工具执行结果；Agentic RL 关注训练对象是否是多步 Agent 轨迹，比如计划、工具选择、参数、观察和最终执行结果。当 Agent 任务可以被自动验证时，可以用 RLVR 作为 Agentic RL 的奖励来源，例如代码 Agent 通过单测就给正 reward，搜索 Agent 找到正确证据就给正 reward。

### Agentic RL 为什么比普通 RLHF 更难？

回答思路：讲长轨迹、环境交互、credit assignment 和安全成本。

回答模板：

Agentic RL 更难，是因为它优化的是长轨迹而不是单个回答。一个任务失败可能是计划错、工具选错、参数错、工具返回理解错，也可能是外部环境变化导致的。最终 reward 很稀疏，很难判断是哪一步贡献了成功或失败。另外，每条轨迹都可能要真实执行工具、跑代码或操作网页，训练成本和安全风险都比普通对话 RLHF 更高。因此 Agentic RL 往往需要完整 trajectory 记录、步骤级 reward、sandbox 和回归任务集。

### 什么任务适合 Agentic RL？

回答思路：强调任务要有多步交互和可衡量完成结果。

回答模板：

适合 Agentic RL 的任务通常有两个特征：第一，需要多步工具或环境交互；第二，最终结果可以被衡量。例如代码 Agent 可以通过测试判断是否修好 bug，搜索 Agent 可以判断是否找到指定证据，GUI Agent 可以判断是否完成操作流程，数据 Agent 可以判断查询结果或报告是否符合要求。如果只是单轮开放问答，没有明确环境反馈，就不一定需要 Agentic RL。

### Agentic RL 怎么避免模型乱调用工具？

回答思路：从工具权限、格式约束、成本惩罚和轨迹回归回答。

回答模板：

我会从训练和系统两层控制。训练上，reward 不只奖励最终成功，还要惩罚无效工具调用、错误参数、重复调用和过长轨迹；同时保留高质量工具调用轨迹做 SFT 或偏好训练。系统上，要给工具设置权限边界、参数 schema、sandbox、危险操作确认和调用次数限制。评测时还要看任务完成率、平均调用次数、失败类型和安全违规率，不能只看最终答复是否好看。

### 如果 Agent 任务失败，怎么做错误归因？

回答思路：按 trajectory 拆解每一步，而不是只看最终答案。

回答模板：

我会先查看完整 trajectory，把失败拆成任务理解、计划、工具选择、参数构造、工具返回理解、状态更新和最终回答几个阶段。比如代码 Agent 失败，可能是没定位到文件、修改了错误位置、测试没跑、或者测试失败后没有根据日志修复。每类错误对应不同优化方式：任务理解错补 SFT，工具参数错补 schema 和示例，执行后不会修复就补失败轨迹训练，最终答案没证据就加证据引用 reward。
