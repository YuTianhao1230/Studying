# 后训练发展史与方法对比

## 知识点解析

### 概述

后训练（Post-training）是指基座模型完成预训练后，为了让模型更好地遵循指令、对齐偏好、提升推理能力、适配业务场景而进行的一系列训练和优化。它不是单一算法，而是一条方法体系：从最早的任务微调、指令微调，到 RLHF、DPO，再到面向数学、代码和 Agent 的 RLVR / GRPO。

如果用一句话概括后训练的发展史：**后训练从模仿高质量答案发展到学习人类偏好，再发展到用可验证结果强化推理和行动能力。**

预训练解决的是“模型有没有知识和语言能力”，后训练解决的是“模型会不会按人的方式使用这些能力”。同一个基座模型，经过不同后训练流程，可能变成聊天助手、代码模型、数学推理模型、多模态助手、工具调用 Agent 或安全审核模型。

### 发展主线

后训练的最早形态可以看作传统 fine-tuning：在特定任务数据上继续训练模型，例如分类、翻译、摘要、问答。这个阶段的目标比较直接，就是让模型在某个监督任务上表现更好。后来随着 GPT-3 这类通用语言模型出现，问题变成：模型虽然会续写文本，但不一定会“听懂用户指令”。于是 Instruction Tuning 和 SFT 成为关键方法，用人工或合成的指令-回答数据，把模型从“文本补全器”调整成“指令跟随助手”。

2022 年 InstructGPT 把现代 RLHF 流程推成主流：先 SFT，再训练 Reward Model，最后用 PPO 优化策略。OpenAI 对 InstructGPT 的公开介绍中明确描述了这条流程：先收集示范数据做监督微调，再让标注者对多个输出排序训练奖励模型，最后用这个奖励模型作为 reward，通过 PPO 微调模型。这个阶段的核心突破是：模型的目标不再只是拟合标准答案，而是拟合“人类更喜欢什么样的回答”。

RLHF 解决了指令遵循、帮助性、安全性和对话体验问题，但工程链路很重。它需要偏好标注、Reward Model、Reference Model、PPO、KL 约束和复杂的训练稳定性控制。2023 年 DPO 出现后，偏好优化进入简化阶段。DPO 的论文把 RLHF 中的 KL 约束 reward maximization 重新参数化，直接在偏好对上优化一个分类式目标，不需要显式训练 Reward Model，也不需要在线 PPO 采样。这让大量团队可以用更低成本做偏好对齐。

2023 到 2024 年，DPO 系列方法快速扩展，包括 IPO、KTO、ORPO、SimPO、CPO、TDPO 等。它们的共同目标是降低 RLHF 工程复杂度，但在偏好数据形式、是否需要 reference model、对 chosen/rejected 的处理、长度偏差控制、token 级别优化等方面做不同改造。这个阶段可以理解为“偏好优化工程化”：大家不再只追求最完整的 RLHF，而是追求更稳定、更便宜、更容易复现的对齐训练。

2024 到 2025 年，后训练重点明显转向推理能力和可验证奖励。DeepSeekMath 提出 GRPO，DeepSeek-R1 进一步让 RLVR 和 GRPO 成为推理模型训练的代表范式。GRPO 去掉 PPO 中昂贵的 Critic / Value Model，用同一个 prompt 下多条回答的组内相对 reward 构造 advantage。对于数学、代码、工具调用这类可以验证结果的任务，模型可以通过采样、验证、强化不断提升推理路径质量。

到这一步，后训练的目标已经从“回答更像人喜欢的样子”扩展为“在可验证任务中真的做对”。这也是为什么今天讨论后训练时，不能只讲 SFT 和 DPO，还要讲 Reward / Grader、RLVR、Agentic RL、trajectory 评测、数据合成、拒绝采样和蒸馏。

### 时间线

| 阶段 | 代表方法 | 核心变化 | 主要解决的问题 |
| --- | --- | --- | --- |
| 传统微调阶段 | Task Fine-tuning | 用监督数据适配单一任务 | 分类、翻译、摘要、问答等具体任务 |
| 指令微调阶段 | Instruction Tuning、SFT、FLAN、T0 | 从文本补全转向指令遵循 | 让模型理解任务指令和对话格式 |
| RLHF 主流化阶段 | InstructGPT、ChatGPT、PPO-RLHF | 引入人类偏好和 Reward Model | Helpful、Honest、Harmless，对话体验 |
| 偏好优化简化阶段 | DPO、IPO、KTO、ORPO、SimPO | 用离线偏好数据直接优化策略 | 降低 PPO/RLHF 复杂度，提高稳定性 |
| 合成数据与蒸馏阶段 | Self-Instruct、Rejection Sampling、Distillation | 用强模型或模型自身生成训练数据 | 降低人工标注成本，迁移强模型能力 |
| 可验证强化学习阶段 | RLVR、GRPO、DAPO 类方法 | 用规则、单测、执行结果做 reward | 数学、代码、工具调用、推理能力 |
| Agentic RL 阶段 | Tool-use RL、Trajectory RL | 优化多步行动轨迹，而非单轮回答 | 搜索、代码执行、GUI、长任务 Agent |

### 核心阶段

SFT 是后训练的基础层。它使用 `(instruction, response)` 数据让模型学会回答格式、角色边界、任务风格和基本指令遵循。它的优点是稳定、简单、成本低；限制是只能模仿数据分布，不能直接表达“两个回答谁更好”，也很难通过 SFT 本身持续探索更优解法。

Reward Modeling 是偏好对齐的中间层。它把人类或 AI 对多个回答的排序训练成一个可打分模型，用来近似“人类偏好”。Reward Model 的价值是把主观偏好变成可优化信号；风险是 reward hacking、分布外不可靠、长度偏差和标注偏差。

RLHF / PPO 是经典对齐层。它让当前模型生成回答，再由 Reward Model 打分，用 PPO 更新策略，并通过 KL 约束限制模型不要偏离参考模型太远。它的优点是能直接优化非可微偏好目标，支持在线采样；缺点是工程复杂、显存成本高、训练不稳定、调参困难。

DPO 是偏好优化简化层。它把 RLHF 的目标转成离线偏好对上的分类式 loss，直接提高 chosen 相对 rejected 的概率优势。它的优点是简单、稳定、容易复现；缺点是依赖偏好数据质量，探索能力弱，不适合需要在线试错和可验证反馈的任务。

RLAIF 和 Constitutional AI 是偏好信号自动化层。它们用 AI 反馈或规则宪法替代部分人工标注，降低人工成本，并强化安全和规范性。但 AI 反馈可能继承评审模型偏差，最终质量仍取决于 judge / constitution 的设计。

RLVR / GRPO 是推理强化层。它不再主要依赖主观偏好，而是依赖可验证结果，例如数学答案、代码单测、JSON schema、工具执行成功率。GRPO 用组内相对 reward 去掉 Critic，在推理任务上更轻量。它的风险是 reward 设计不完整会导致模型钻空子，且 rollout 成本和训练稳定性仍然需要控制。

Distillation 和 Rejection Sampling 是能力迁移层。Rejection Sampling 先生成多条候选，再用规则、Reward Model 或 LLM Judge 过滤高质量样本；Distillation 则让小模型学习强模型的回答或推理轨迹。它们常和 SFT、DPO、RLVR 组合使用，用于降低训练和部署成本。

### 方法对比

| 方法 | 数据形式 | 优化信号 | 是否在线采样 | 额外模型 | 主要优点 | 主要风险 | 适合场景 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| SFT | 指令-答案 | 标准答案 token loss | 否 | 不需要 | 简单稳定，建立指令遵循 | 数据质量决定上限，容易学表面格式 | Chat 基座、领域微调、冷启动 |
| Reward Model | 回答排序或打分 | 偏好排序 loss | 否 | 需要 RM | 把偏好变成可优化分数 | reward hacking、标注偏差 | RLHF、拒绝采样、评测打分 |
| RLHF / PPO | prompt + 在线回答 | RM reward + KL | 是 | RM、Critic、Reference | 可直接优化偏好目标，探索能力强 | 链路重、显存高、训练不稳 | 通用对话、安全对齐、复杂偏好 |
| DPO | chosen / rejected 偏好对 | 相对 logprob 差异 | 否 | Reference | 简单稳定，不需要 RM/PPO | 依赖离线偏好对，探索弱 | 风格对齐、指令偏好、低成本对齐 |
| IPO / KTO / ORPO / SimPO | 偏好对或正负样本 | DPO 变体目标 | 否 | 视方法而定 | 进一步简化或修正 DPO 问题 | 方法多，收益依赖数据和实现 | DPO 替代、偏好优化实验 |
| RLAIF / Constitutional AI | AI 反馈、规则原则 | AI preference / rule feedback | 可选 | Judge 或规则 | 降低人工标注成本，强化规范性 | Judge 偏差、规则覆盖不足 | 安全对齐、内容规范、企业策略 |
| RLVR | 带验证器任务 | 可验证 reward | 是 | Verifier | 信号明确，适合推理 | reward 稀疏、验证器漏洞 | 数学、代码、工具调用 |
| GRPO | 同 prompt 多回答 | 组内相对 reward | 是 | Reference，可无 Critic | 比 PPO 轻，适合推理 RL | rollout 成本、reward hacking、方差 | DeepSeek-R1 类推理训练 |
| Distillation | teacher 输出或轨迹 | 模仿 teacher | 否 | Teacher | 低成本迁移能力 | 继承 teacher 错误，上限受 teacher 影响 | 小模型、部署、推理模型蒸馏 |

### 算法关系

后训练方法不是互斥关系，更像一条流水线。一个常见现代流程是：先做 Continual Pretraining 适配领域语料，再做 SFT 建立指令遵循和输出格式；然后用 Rejection Sampling 或 Reward Model 过滤数据；再用 DPO 做低成本偏好对齐；如果任务有可验证结果，再用 RLVR / GRPO 强化推理；最后把强模型的推理轨迹蒸馏到小模型，并通过评测集和线上回归验证效果。

可以把它们理解成不同层次的优化：

- SFT 优化“会不会按示范回答”。
- DPO 优化“两个回答里更偏好哪个”。
- RLHF/PPO 优化“当前模型生成什么能拿高 reward”。
- RLVR/GRPO 优化“模型生成的解法是否真的通过验证”。
- Distillation 优化“小模型能不能学会大模型的行为”。

### 工程选型

如果你的模型还不会稳定遵循指令，优先 SFT，而不是直接 DPO 或 RL。因为偏好优化和 RL 都默认模型已经有基本可用的回答分布。

如果你有高质量 chosen/rejected 数据，但没有稳定 Reward Model 和 RL 训练系统，优先 DPO 或 DPO 变体。它能用较低成本改善回答风格、偏好、安全边界和任务表现。

如果你有大量人类排序数据、明确的偏好标准、足够工程资源，并且要做通用助手级别对齐，可以考虑 RLHF/PPO。但要准备好 reward model 质量、KL 控制、训练稳定性和评测回归。

如果任务是数学、代码、工具调用、结构化输出这类可验证任务，优先考虑 RLVR / GRPO。核心不是“用了 GRPO 就强”，而是验证器是否可靠、reward 是否覆盖真实目标、rollout 成本是否可接受。

如果目标是降低部署成本或把大模型能力迁移到小模型，考虑蒸馏。蒸馏适合把强模型的答案、推理轨迹、工具调用轨迹迁移给小模型，但必须防止 teacher 的错误被系统性放大。

### 关键风险

后训练最常见的风险不是算法名字选错，而是目标信号不可靠。SFT 数据低质会让模型学坏格式和错误知识；偏好数据不一致会让 DPO 学到噪声；Reward Model 不可靠会导致 reward hacking；RLVR 验证器过窄会让模型钻规则漏洞；蒸馏数据如果来自错误 teacher，会把错误稳定注入学生模型。

另一个核心风险是评测不可信。后训练很容易在某个 benchmark 上变强，但在真实任务上退化。因此必须做分桶评测、bad case 归因、数据泄漏检查、长度和格式统计、成本监控，以及基座能力回归。

## 面试应对

### 后训练的发展史可以怎么讲？

回答思路：按“监督微调 -> 人类偏好 -> 直接偏好优化 -> 可验证 RL -> Agentic RL”组织，不要只罗列算法名。

回答模板：

后训练的发展可以概括为三次目标升级。第一阶段是 SFT 和 Instruction Tuning，让预训练模型从文本补全器变成能遵循指令的助手。第二阶段是 RLHF，以 InstructGPT 为代表，通过人类偏好训练 Reward Model，再用 PPO 优化模型，让模型更 helpful、honest、harmless。第三阶段是 DPO 及其变体，把复杂 RLHF 简化为离线偏好优化，降低工程成本。最近一阶段是 RLVR 和 GRPO，重点从主观偏好转向可验证结果，特别适合数学、代码和工具调用任务。整体趋势是：从模仿答案，到学习偏好，再到用验证器强化真实任务成功率。

### SFT、DPO、RLHF、GRPO 的核心区别是什么？

回答思路：围绕数据形式、优化信号、是否在线采样、复杂度和适用场景对比。

回答模板：

SFT 用标准答案做监督学习，目标是让模型学会基本指令遵循和回答格式。DPO 用 chosen/rejected 偏好对，直接提高好回答相对坏回答的概率，不需要 Reward Model 和 PPO。RLHF 通常先训练 Reward Model，再用 PPO 让模型在线生成并最大化 reward，探索能力强但链路复杂。GRPO 也是强化学习，但它用同一个 prompt 下多条回答的组内相对 reward 计算 advantage，不需要 Critic，更适合数学、代码这类有可验证奖励的推理任务。

### 为什么不能只做 SFT？

回答思路：说明 SFT 的能力边界：模仿示范，但不直接学习偏好和探索。

回答模板：

SFT 很重要，但它主要是在模仿数据里的标准答案。它能让模型学会格式、风格和基本任务能力，但很难表达两个回答之间细粒度的偏好差异，也不能通过在线探索发现更好的解法。如果训练数据覆盖不足，模型只会学到表面模式。对于回答质量、安全边界、复杂推理和代码验证这类问题，通常还需要 DPO、RLHF 或 RLVR 来进一步优化。

### 为什么 DPO 能替代一部分 RLHF？

回答思路：讲清楚 DPO 是对 RLHF 目标的重写，不是简单 pairwise classification。

回答模板：

DPO 能替代一部分 RLHF，是因为它把带 KL 约束的 reward maximization 目标重新写成了偏好对上的直接优化目标。在 RLHF 里，我们先训练 Reward Model，再用 PPO 优化策略；DPO 则直接利用 chosen/rejected 数据，让模型提高 chosen 相对 rejected 的概率优势，同时通过 reference model 控制偏离程度。所以它不需要显式 Reward Model，也不需要在线 PPO 采样，工程上更简单稳定。但它依赖离线偏好数据，探索能力不如真正的 RL。

### 为什么现在推理模型更强调 RLVR / GRPO？

回答思路：强调推理任务的 reward 可验证，和主观偏好任务不同。

回答模板：

推理任务更强调 RLVR / GRPO，是因为数学、代码、工具调用这类任务往往有可验证结果。数学可以检查最终答案，代码可以跑单测，工具调用可以检查执行结果，结构化输出可以做 schema 校验。这类 reward 比人类主观偏好更明确，适合在线采样和强化学习。GRPO 又进一步降低了 PPO 的 Critic 成本，用组内相对 reward 训练模型，因此成为推理模型后训练里很常见的选择。

### 如果让你设计一个后训练流程，你会怎么做？

回答思路：按任务目标、数据、训练阶段、评测和风险控制回答。

回答模板：

我会先定义目标能力和评测指标，比如指令遵循、代码通过率、数学正确率或业务任务成功率。然后检查基座模型能力，如果指令遵循不足，先做高质量 SFT；如果有偏好对，做 DPO 或相关变体；如果任务有可验证 reward，比如代码和数学，再考虑 RLVR / GRPO。训练过程中要保留 reference model 或 KL 控制，防止模型漂移。评测上不能只看平均分，要做分桶、bad case、数据泄漏检查、长度和格式统计，还要关注训练成本和推理成本。

### 后训练最容易踩的坑是什么？

回答思路：不要只说过拟合，要覆盖数据、reward、评测、成本和能力退化。

回答模板：

后训练最容易踩的坑有四类。第一是数据问题，比如 SFT 数据低质、偏好对标注不一致、训练集污染评测集。第二是 reward 问题，Reward Model 或 verifier 不可靠会导致 reward hacking。第三是评测问题，只看单一 benchmark，忽略分桶、bad case 和能力回归。第四是工程问题，比如 KL 没控制好导致模型漂移，RL 训练不稳定，或者 rollout 成本过高。实际项目里必须用消融实验和护栏指标判断后训练是否真的带来净收益。
