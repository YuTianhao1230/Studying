# RLVR 可验证奖励强化学习

## 知识点解析

### 概述

RLVR 的全称是 **Reinforcement Learning with Verifiable Rewards**，中文可以理解为“可验证奖励强化学习”。它指的是：在后训练阶段，让模型生成答案或行动轨迹，再用规则、程序、单元测试、判题器或环境反馈自动验证结果，并把验证结果作为 reward 来优化模型。

RLVR 的核心不是某一个具体算法，而是一类训练信号。它回答的问题是：**如果任务结果可以被自动判断对错，能不能不依赖主观偏好标注，而直接用可验证结果训练模型？**

### 背景

传统 RLHF 主要依赖人类偏好或 Reward Model。它适合优化回答是否 helpful、honest、harmless，但也有明显成本：

- 偏好标注昂贵。
- Reward Model 可能学到标注偏差。
- 主观偏好不一定等于任务正确性。
- PPO/RLHF 链路复杂且不稳定。

数学、代码、格式化输出、工具执行这类任务不完全需要主观偏好判断，因为结果本身可以验证。例如数学最终答案是否正确、代码是否通过单测、JSON 是否符合 schema、工具调用是否完成目标。这类任务天然适合 RLVR。

### 方法原理

RLVR 的基本流程是：

1. 给定一个可验证任务，例如数学题、代码题、检索任务或结构化输出任务。
2. 当前模型对同一个 prompt 采样一个或多个回答。
3. 验证器执行检查，返回 reward。
4. 使用 PPO、GRPO、REINFORCE 或其他策略优化方法更新模型。
5. 通过 KL、长度惩罚、格式约束和能力回归控制模型不要跑偏。

常见验证器包括：

| 验证器 | 典型任务 | Reward 示例 |
| --- | --- | --- |
| 数学判题器 | 数学推理 | 最终答案等价得分 |
| 单元测试 | 代码生成 | 通过测试比例 |
| 编译器/解释器 | 代码执行 | 是否可运行、是否无报错 |
| Schema 校验 | JSON/XML 输出 | 格式合法得分 |
| 检索证据校验 | 搜索/RAG | 是否找到指定证据 |
| 环境反馈 | 工具调用/Agent | 任务是否完成 |

### 和 GRPO 的关系

RLVR 和 GRPO 不是同一层概念。

- RLVR 描述 reward 从哪里来：来自可验证结果。
- GRPO 描述怎么优化 policy：用同一个 prompt 下多条回答的组内相对 reward 更新模型。

因此可以说“用 GRPO 做 RLVR”，但不能把 RLVR 简单等同于 GRPO。PPO、GRPO 或其他 RL 算法都可以使用可验证 reward，只是 GRPO 在大模型推理训练中更常见，因为它不需要额外 Critic，工程上比 PPO 轻。

### 适用场景

RLVR 适合结果可以自动验证的任务：

- 数学推理：最终答案、步骤约束、格式约束可以自动检查。
- 代码生成：单测、编译、静态检查可以作为 reward。
- 结构化输出：JSON schema、字段完整性、解析成功率。
- 检索和问答：证据命中、引用正确性、答案可追溯性。
- 工具调用：API 是否调用正确、参数是否正确、执行结果是否达成目标。
- 视频时间定位：预测时间段和 GT 的 IoU、边界误差、格式合法性。

不适合 RLVR 的场景，是那些没有可靠验证器、目标高度主观、或者 reward 和真实质量相关性很弱的任务，例如开放创意写作、复杂价值判断、纯风格偏好。

### 优势与局限

RLVR 的优势是 reward 更客观、可规模化、成本低于人类偏好标注，尤其适合数学、代码和工具任务。它还能让模型通过采样和验证发现比 SFT 数据更好的解法，而不只是模仿离线答案。

它的局限也很明确。第一，reward 可能稀疏，只有最终成功/失败，中间步骤没有信号。第二，验证器可能不完整，模型会 reward hacking，例如过拟合单测或钻格式规则漏洞。第三，环境执行成本高，代码运行、工具调用和搜索验证都比普通 SFT 昂贵。第四，RL 训练仍然有 KL、采样温度、reward scale 和 rollout 成本等稳定性问题。

### 工程实践

落地 RLVR 时，重点不是先选算法，而是先验证 reward：

1. reward 是否可执行、可复现。
2. reward 是否和最终业务指标正相关。
3. reward 是否覆盖格式、正确性、长度和安全约束。
4. 是否有人工抽检高 reward 样本，防止 reward hacking。
5. 是否记录 reward 分项、KL、response length、pass rate、format accuracy。
6. 是否保留 SFT baseline、DPO baseline 和不做 RL 的对照组。

## 面试应对

### RLVR 是什么？

回答思路：先定义 reward 来源，再说明它和 SFT、DPO、GRPO 的关系。

回答模板：

RLVR 是 Reinforcement Learning with Verifiable Rewards，也就是用可验证结果作为奖励信号的强化学习后训练。它不是一个具体算法，而是一类训练范式。比如数学题可以验证最终答案，代码可以跑单测，结构化输出可以检查 schema，工具调用可以检查执行结果。模型先生成答案或轨迹，再由验证器打分，然后用 PPO、GRPO 等 RL 方法更新。它和 DPO 的区别是，DPO 主要用离线 chosen/rejected 偏好对，而 RLVR 依赖在线采样和可执行验证信号。

### 为什么推理模型更强调 RLVR？

回答思路：强调推理任务有客观正确性，主观偏好不足以训练真实解题能力。

回答模板：

推理模型强调 RLVR，是因为数学、代码、工具调用这类任务的目标不是“看起来更像好回答”，而是结果真的对。SFT 可以让模型模仿解题格式，DPO 可以优化偏好，但它们都主要依赖离线数据。RLVR 允许模型自己采样多种解法，再用判题器、单测或执行环境验证结果，把真正成功的解法强化起来。所以它更适合提升可验证任务的真实成功率。

### RLVR 和 GRPO 有什么区别？

回答思路：一句话区分概念层级：RLVR 是 reward 类型，GRPO 是优化算法。

回答模板：

RLVR 和 GRPO 不是同一个概念。RLVR 说的是 reward 从哪里来，也就是用数学判题、代码单测、schema 校验或工具执行结果这类可验证信号作为奖励。GRPO 说的是怎么用 reward 更新模型，它对同一个 prompt 采样多条回答，用组内相对 reward 计算 advantage，不需要 Critic。实际项目里可以用 GRPO 做 RLVR，也可以用 PPO 做 RLVR。

### RLVR 最大的风险是什么？

回答思路：围绕 reward hacking、验证器覆盖不足和真实指标不一致回答。

回答模板：

RLVR 最大风险是 reward 不等于真实目标。如果数学 reward 只看最终答案，模型可能学会猜答案；如果代码单测覆盖不足，模型可能写出只过测试但不泛化的代码；如果格式 reward 太强，模型可能牺牲内容质量。实际训练时不能只看 reward 上升，还要看真实测试集、分桶指标、人工抽检、长度分布、格式合法率和能力回归，确认模型不是在钻验证器漏洞。

### 如果在关键帧识别中做 RLVR，reward 怎么设计？

回答思路：结合你的项目，把时间精度、格式、边界证据和长度约束讲清楚。

回答模板：

关键帧识别是一个适合尝试 RLVR 的任务，因为预测时间可以和 GT 做自动比较。我会把 reward 拆成几部分：第一是时间 reward，比如预测时间和 GT 的误差或 IoU；第二是格式 reward，确保输出能被解析；第三是边界证据 reward，要求模型说明为什么前一段未完成、当前段首次完成；第四是长度惩罚，避免模型输出过长 CoT。训练时还要人工抽检高 reward 样本，防止模型只学会格式或利用 GT 噪声。
