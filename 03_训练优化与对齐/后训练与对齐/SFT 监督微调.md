# SFT 监督微调

## 知识点解析

### 概述

SFT，Supervised Fine-Tuning，是用高质量指令-回答数据对预训练模型进行监督微调，让模型学会按人类期望的格式和任务方式回答。

### 为什么需要 SFT

预训练模型主要学习“预测下一个 token”，不天然等于好用的助手。

SFT 解决的是：

- 学会遵循指令。
- 学会对话格式。
- 学会特定领域任务。
- 学会输出结构化结果。
- 为后续 RLHF / DPO / GRPO 打基础。

### 数据格式

常见样本：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个专业助手"},
    {"role": "user", "content": "解释 KV Cache"},
    {"role": "assistant", "content": "KV Cache 是..."}
  ]
}
```

关键不是数量越多越好，而是质量、覆盖面和格式一致性。

### 训练目标

SFT 通常仍然是 next-token prediction，只是训练数据变成了人类整理好的指令数据。

常见做法：

- 只对 assistant 部分计算 loss。
- user/system 部分只作为上下文。
- 多轮对话要保留角色边界。

### 常见数据来源

- 人工标注。
- 专家问答。
- 业务日志清洗。
- 高质量模型蒸馏。
- 合成数据。
- 失败 case 修正。

### 常见问题

- 数据格式不统一，模型学坏输出格式。
- 低质量合成数据太多，导致能力退化。
- 领域数据覆盖不足，模型只学到表面模式。
- 多轮对话 mask 错误，导致训练目标污染。
- 过拟合小数据，通用能力下降。

### 和后续对齐的关系

```text
Pretrain -> SFT -> Reward Model / Preference Data -> RLHF / DPO / GRPO
```

SFT 让模型“会做任务”；偏好优化让模型“更符合人类偏好或业务目标”。

## 面试应对

### SFT 和预训练有什么区别？

回答思路：从训练目标形式一致、但数据和目的不同来对比。

回答模板：

两者的训练目标形式其实都是 next-token prediction，区别在数据和目的。预训练用海量无标注文本，目的是让模型学会语言规律和世界知识，学到的是"预测下一个 token"，但不天然是一个好用的助手。SFT 用的是人工整理的高质量"指令-回答"数据，目的是让模型学会遵循指令、按对话格式和特定任务方式回答。所以预训练打底座、给知识，SFT 在此之上把模型对齐到"会做任务、会好好回答"，是后续 RLHF/DPO 对齐的前置步骤。

### 为什么 SFT 通常只对 assistant 部分算 loss？

回答思路：讲清 user/system 是上下文、不该被模型"学着生成"。

回答模板：

因为我们训练的目标是让模型学会"作为助手怎么回答"，而不是学会去生成用户的提问或系统提示。user 和 system 部分是给定的上下文条件，只应该作为模型看到的输入，不该计入 loss；只有 assistant 部分才是我们希望模型模仿输出的内容。如果对 user/system 也算 loss，训练目标就被污染了，模型会浪费容量去拟合本不该它生成的内容，甚至学着"自问自答"，反而降低指令遵循质量。多轮对话时还要保留好角色边界，避免 mask 错位。

### SFT 数据质量怎么控制？

回答思路：强调质量重于数量，从格式一致性、覆盖面、去噪几点落地。

回答模板：

SFT 的关键不是数据越多越好，而是质量、覆盖面和格式一致性。我会从几方面控制：一是格式统一，保证对话结构、角色边界、输出格式一致，否则模型会学坏输出格式；二是控制合成数据比例，低质量合成数据太多会导致能力退化，需要人工抽检和过滤；三是保证领域覆盖，避免模型只学到表面模式；四是清洗和修正，用业务日志、失败 case 修正来补齐短板。最后用小而精的高质量集，往往比堆量效果更好，还能避免过拟合导致通用能力下降。

### SFT 后模型能力退化怎么办？

回答思路：先定位退化类型，再从数据配比、正则、混通用数据等角度给对策。

回答模板：

SFT 后最常见的退化是过拟合小数据导致通用能力下降，或者领域数据太窄让模型只学到表面模式。我会先评估是哪类能力掉：是通用对话、还是推理、还是原有知识。对策上：一是在 SFT 数据里混入一定比例的通用/多样性数据，防止灾难性遗忘；二是控制训练轮数和学习率，避免在小数据上过拟合；三是检查数据质量，把低质合成数据和格式错误清掉；四是必要时用 LoRA 这类参数高效微调，减少对原模型的破坏。验证时要同时跑目标任务和通用基准，确认是净提升。

### SFT、RLHF、DPO 的关系是什么？

回答思路：按"SFT 打基础、RLHF/DPO 做偏好对齐"的顺序讲，再点出 RLHF 和 DPO 的路线差异。

回答模板：

SFT、RLHF、DPO 都是后训练方法，但定位不同。SFT 用人工示范数据教模型按指令回答，是能力和格式的基础；RLHF 先训练 Reward Model，再用 PPO 等方法优化偏好，流程复杂但有在线优化能力；DPO 直接用 chosen/rejected 偏好对训练，不需要 Reward Model 和 PPO，工程更简单稳定，但更依赖离线偏好数据质量。
