# SFT 超参数怎么设与怎么调

## 知识点解析

### 概述

这篇是一份**从具体配置出发**的 SFT 调参卡片。它不铺开讲所有超参数（那部分见同目录的《训练超参数调参指南》），而是拿一份真实的 SFT 脚本片段做锚点，讲清楚**每个值为什么这么设**，以及**怎么根据 loss 的表现回头调**。

用来做例子的配置片段：

```bash
learning_rate=1.0e-5
warmup_ratio=0.05
num_train_epochs=1
gradient_accumulation_steps=2
```

### 先算有效 batch size（EBS）

调参前必须先算出**有效 batch size**，因为大多数参数都是相对它来选的：

```text
EBS = per_device_train_batch_size × gradient_accumulation_steps × GPU 数
```

`gradient_accumulation_steps` 本身不改变梯度的数学结果，它只是**用时间换显存**：累积若干个 micro-batch 的梯度再更新一次，等价于 batch 大若干倍，但峰值显存只按单个 micro-batch 算。所以 `=2` 通常意味着"单卡显存塞不下想要的 batch，于是攒 2 步"。视频、多模态这类单条样本帧数多、token 长、显存吃紧的任务，累积很常见。

一个关键联动：**改了 EBS，learning rate 往往要跟着调**。EBS 变大梯度更稳，可适当调大 LR（常用经验是按线性或 √ 比例小幅上调）；EBS 变小则反之。

### learning_rate = 1.0e-5

**为什么这么设**：

- 全参数微调大模型的典型区间是 `5e-6 ~ 2e-5`，`1e-5` 是这个区间里的中间稳妥值。
- 注意区分微调方式：**如果是 LoRA/QLoRA，学习率要高一个量级**（`1e-4` 左右），因为只训练低秩 adapter，需要更大步长才学得动。看脚本里有没有 `--train_type lora` 决定该用哪一档。

**怎么根据 loss 调**：

| loss 表现 | 判断 | 动作 |
| --- | --- | --- |
| 几步内爆成 NaN / 直线飙升 | LR 太大 | 降到 `5e-6`~`7e-6`，并开 gradient clipping |
| 剧烈上下抖动、不平滑下降 | LR 偏大 | 减半再试 |
| 几乎不动、下降极慢 | LR 偏小（或数据/mask 有问题） | 上调到 `2e-5`，同时排查 label |
| 平滑下降到合理平台 | 合适 | 别动 |

### warmup_ratio = 0.05

**含义**：前 5% 的训练步里，LR 从 0 线性爬到 `1e-5`，之后再按 scheduler 衰减。目的是防止刚开始参数还没进入状态时，大梯度把预训练权重冲坏。

**为什么是 0.05**：`0.03 ~ 0.1` 是通用区间，1 个 epoch 的短训练用 5% 很常见。这是最不需要动的参数之一。

**怎么根据 loss 调**：

- 训练最开始（前几十步）loss 突刺、飙高再回落 → warmup 太短，加到 `0.1`。
- 数据集很小、总步数就几百步 → 5% 可能只有十几步太短，可适当加大比例，或直接改用固定 `warmup_steps`。

### num_train_epochs = 1

**为什么这么设**：SFT / 指令微调**最容易过拟合**，尤其数据量不大时。跑多了模型开始"背答案"，通用能力反而退化。1 个 epoch 是大模型 SFT 的常见默认，很多情况下 1 epoch 就够。

**怎么判断要不要加到 2~3**：这必须**看验证集**，光看 train loss 会误导。

- train loss 还在降、**eval loss 也还在降** → 可以多跑 1 epoch。
- train loss 降但 **eval loss 开始回升**（经典过拟合剪刀差）→ 1 epoch 附近就是最佳点，别加，甚至该早停。
- 脚本若没配 eval，强烈建议加 `--val_dataset` / `--eval_steps`，否则无法判断 epoch 该设几。

**更贴近真实目标的做法**：最终该信的是**下游指标**（比如关键帧任务的帧误差、time_err、PASS 率），而不是 loss 绝对值。可以每个 epoch 存一个 checkpoint，各自跑一遍评测集，选指标最好的那个。

### gradient_accumulation_steps = 2

**为什么这么设**：如前所述，显存不够时凑大 batch 的手段。

**怎么根据现象调**：

| 现象 | 动作 |
| --- | --- |
| 显存 OOM | 调大它，同时把 `per_device_train_batch_size` 调小，保持 EBS 不变 |
| loss 抖动太厉害、不平滑 | EBS 偏小、梯度噪声大 → 加大累积步数让 EBS 变大，曲线更稳 |
| 显存有富余、训练太慢 | 减小累积步数、直接加大 `per_device_train_batch_size`，减少无效前向 |

改完记得回头看 LR 要不要联动调。

### 一套可操作的调参流程

1. **先看前 50 步**：有没有 NaN / 爆炸 / 剧烈突刺 → 判断 LR 和 warmup 是否安全。
2. **再看整体趋势**：平滑下降 = 健康；抖动大 = EBS 太小或 LR 太大；不降 = LR 太小或数据/loss mask 有问题。
3. **必须配验证集**：看 eval loss + 下游指标，这才是决定 `num_train_epochs` 和选哪个 checkpoint 的依据。
4. **一次只改一个变量**：改完对比 loss 曲线和评测指标再定下一步。

### 一个容易踩的坑：训练/评测环境要对齐

这类任务里，如果训练时的 FPS、抽帧数、token 截断长度、采样参数和评测时不一致，loss 再好看，下游指标也可能对不上，很容易被误判成"参数没调好"。调参前先确认训练配置和评测配置严格对齐，再看指标。

## 面试应对

### gradient_accumulation_steps 是干什么的？会改变训练结果吗？

回答思路：点明它是"用时间换显存"来模拟更大 batch，数学上等价于放大 batch、不改变梯度期望，只是峰值显存按单个 micro-batch 算。

回答模板：

gradient accumulation 是在显存放不下大 batch 时，攒若干个 micro-batch 的梯度再统一更新一次，用来模拟更大的有效 batch size。它不改变梯度的数学期望，等价于把 batch 放大同样倍数，但峰值显存只按单个 micro-batch 计算。所以有效 batch size 等于单卡 batch 乘以累积步数再乘以 GPU 数，我一般用它在显存受限时把有效 batch 顶上去。

### SFT 的学习率大概怎么定？为什么全参微调用 1e-5 量级而 LoRA 用 1e-4 量级？

回答思路：抓住"改动参数量不同导致所需步长不同"——全参微调动全部权重需小步长防冲坏，LoRA 只训低秩 adapter 需更大步长才学得动。

回答模板：

全参数微调会更新模型的全部权重，步长必须小，否则容易把预训练学到的东西冲坏，所以典型区间是 5e-6 到 2e-5，1e-5 是稳妥的中间值。LoRA 只训练很小的一组低秩 adapter 参数，需要更大的步长才学得动，所以学习率通常高一个量级，在 1e-4 左右。判断该用哪档，先看是全参微调还是 LoRA。

### SFT 为什么常常只跑 1 个 epoch？怎么判断要不要多跑？

回答思路：核心是 SFT 极易过拟合，判断依据必须是验证集的剪刀差，而非 train loss。

回答模板：

SFT 数据量通常不大，跑多了模型会开始背训练答案、通用能力退化，所以 1 个 epoch 是常见默认。判断要不要加 epoch 不能只看 train loss，要看验证集：如果 train loss 和 eval loss 都还在降，可以多跑一个 epoch；如果 train loss 降但 eval loss 开始回升，就说明 1 epoch 附近已经是最佳点，该停甚至早停。最稳的做法是每个 epoch 存一个 checkpoint，各自跑下游评测集，选指标最好的。

### warmup 是解决什么问题的？什么时候需要调大？

回答思路：点明它让 LR 从 0 爬升以避免训练初期大梯度冲坏权重，训练初期 loss spike 或大 batch/大 LR 时调大。

回答模板：

warmup 是在训练初期把学习率从 0 逐渐升到目标值，因为刚开始参数和梯度都不稳定，直接用大学习率容易发散。0.03 到 0.1 是常见区间。如果训练最开始出现 loss spike，或者用了很大的 batch 和学习率，就把 warmup 调大；如果总训练步数很少，warmup 占比太大反而挤掉真正学习的阶段，就适当调小或用固定步数。

### 看到 loss 抖动很大，你会怎么排查和调整？

回答思路：抖动主要来自有效 batch 太小（梯度噪声大）或学习率偏大，其次是数据噪声；对应加大 EBS、降 LR、清洗数据。

回答模板：

loss 抖动通常有三个原因。一是有效 batch size 太小、梯度噪声大，我会加大 gradient accumulation 或 batch 把 EBS 顶上去；二是学习率偏大，我会减半再看；三是数据里有异常样本或分布不稳，我会做清洗和按长度分桶。我会一次只改一个，对比曲线再定，而不是几个一起改导致无法归因。
