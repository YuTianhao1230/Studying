# 梯度爆炸与梯度消失

## 直接回答

梯度消失和梯度爆炸本质上都是反向传播中梯度在多层链式相乘后数值失控的问题。

- 梯度消失：梯度越传越小，底层参数几乎不更新，模型学不动。
- 梯度爆炸：梯度越传越大，参数更新过猛，loss 震荡、发散，甚至出现 NaN / Inf。

常见解决手段可以分成四类：

1. 结构上改善梯度路径：残差连接、Pre-Norm、合理的归一化。
2. 数值上控制梯度规模：gradient clipping、合适学习率、warmup。
3. 激活和初始化上避免极端值：ReLU / GELU / SwiGLU、Xavier / Kaiming 初始化。
4. 精度和训练配置上减少溢出：BF16、loss scaling、检查异常 batch。

如果是面试回答，可以先这样说：

```text
梯度消失和爆炸都来自深层网络反向传播时梯度连乘导致的数值衰减或放大。
解决梯度消失主要靠残差连接、合适激活函数、归一化和初始化；
解决梯度爆炸主要靠梯度裁剪、降低学习率、warmup、归一化和更稳定的数值精度，比如 BF16。
真实训练中我不会只看 loss，而会同时看 grad norm、学习率曲线、异常 batch、混合精度溢出和分布式同步。
```

## 为什么会发生

反向传播本质是链式法则。

如果很多层的局部导数都小于 1，连乘后梯度会迅速变小：

```text
0.5 * 0.5 * 0.5 * ... -> 接近 0
```

这就是梯度消失。

如果很多层的局部导数都大于 1，连乘后梯度会迅速变大：

```text
2 * 2 * 2 * ... -> 非常大
```

这就是梯度爆炸。

在大模型训练里，梯度异常还可能来自：

- 学习率过大。
- warmup 太短。
- loss mask 错误。
- 超长样本或异常样本。
- FP16 overflow。
- attention logits 过大。
- checkpoint 恢复 optimizer state 异常。
- 多机同步或 gradient accumulation 配置错误。

## 怎么判断是哪一种

### 梯度消失的表现

- train loss 下降很慢，甚至基本不动。
- 底层参数更新量很小。
- grad norm 长期接近 0。
- 深层网络前几层学不到有效特征。
- RNN / 深层 MLP 中更常见。

### 梯度爆炸的表现

- loss 突然 spike。
- loss 变成 NaN / Inf。
- grad norm 突然变得极大。
- 参数 norm 异常变大。
- 训练在某个 step 后不可恢复。

## 具体怎么解决

### 解决梯度消失

#### 残差连接

残差连接给梯度提供更短的回传路径：

```text
x -> F(x) + x
```

即使 `F(x)` 的梯度路径不稳定，梯度也可以沿着 identity path 回传。

这也是 ResNet 和 Transformer 能做深的关键原因之一。

#### Pre-Norm

现代大模型更常用 Pre-Norm：

```text
x -> x + Sublayer(Norm(x))
```

相比 Post-Norm，Pre-Norm 的梯度路径更稳定，更适合训练很深的 Transformer。

#### 合适的激活函数

Sigmoid / Tanh 在饱和区梯度接近 0，容易造成梯度消失。

现代网络更常用：

- ReLU。
- GELU。
- SiLU / SwiGLU。

它们在更大输入范围内保持有效梯度。

#### 合理初始化

如果初始化权重太小，信号会层层衰减；太大则容易爆炸。

常见初始化：

- Xavier：适合 tanh / sigmoid 一类激活。
- Kaiming：适合 ReLU 系列激活。

### 解决梯度爆炸

#### Gradient Clipping

最直接、最常用。

例如把梯度范数限制在 `1.0`：

```text
如果 ||g|| > threshold
  -> g = g * threshold / ||g||
```

它不会解决根因，但能防止一次异常梯度把模型训练炸掉。

#### 降低学习率，增加 warmup

学习率过大时，即使梯度本身不算离谱，参数更新也可能过猛。

训练初期模型还不稳定，warmup 可以避免一开始就用大学习率冲坏参数。

#### 使用 BF16

FP16 的动态范围较窄，容易 overflow。

BF16 保留了和 FP32 接近的指数范围，虽然尾数精度低一些，但大模型训练中通常更稳定。

#### 检查异常 batch

梯度爆炸不一定是模型结构问题，也可能是某个 batch 有问题：

- 样本特别长。
- label 错位。
- loss mask 错。
- 数据里有异常 token。
- 某个任务 loss 权重过大。

## 面试常见追问

### 追问一：为什么残差连接能缓解梯度消失？

回答：

```text
残差连接让输出变成 F(x) + x，反向传播时梯度可以通过 identity path 直接传回前层。
这样即使 F(x) 这条路径的梯度变小，仍然有一条更短、更稳定的梯度通路。
所以残差连接不是简单加法，而是在深层网络里改善了优化路径。
```

### 追问二：Gradient Clipping 会不会影响模型学习？

回答：

```text
会有影响，但它主要在梯度异常大的时候生效。
如果 clipping 阈值设置合理，正常 step 基本不受影响，只是在异常 step 防止参数被一次大更新冲坏。
如果阈值太小，就会把正常梯度也压扁，导致训练变慢甚至欠拟合。
所以要结合 grad norm 分布来设置，而不是随便写一个值。
```

### 追问三：loss NaN 一定是梯度爆炸吗？

回答：

```text
不一定。loss NaN 可能来自梯度爆炸，也可能来自 FP16 overflow、除零、log(0)、softmax 输入过大、数据异常、label 越界或 loss mask 错误。
我会先看 NaN 出现前 grad norm 是否 spike，再检查混合精度、学习率、异常 batch 和 loss 计算。
```

### 追问四：为什么大模型常用 BF16 而不是 FP16？

回答：

```text
BF16 的指数位更多，动态范围接近 FP32，因此更不容易发生 overflow。
FP16 尾数精度更高一些，但动态范围窄，在大模型训练里更容易数值溢出。
所以很多大模型训练会优先用 BF16 来换稳定性。
```

### 追问五：如果训练中 grad norm 突然 spike，你会怎么排查？

回答：

```text
我会先定位 spike 出现的 step，看是否和某个数据 shard、超长样本、学习率变化或 checkpoint 恢复有关。
然后检查该 batch 的输入长度、label、loss mask、任务类型和 loss 权重。
同时看是否开启 gradient clipping、BF16/FP16 是否 overflow、分布式各 rank 的 grad norm 是否一致。
如果能复现，就用小 batch 或单卡复现来收敛变量。
```
