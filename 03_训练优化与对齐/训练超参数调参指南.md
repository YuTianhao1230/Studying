# 训练超参数调参指南

## 知识点解析

### 概述

### 先建立一个总认知

训练超参数不是孤立调的。它们共同决定三件事：

1. 模型每一步怎么更新参数。
2. 模型看多少数据、看多久。
3. 训练过程是否稳定、是否过拟合、是否学不动。

可以先把超参数分成几类：

```text
优化相关：
learning rate、optimizer、weight decay、warmup、scheduler、gradient clipping

数据相关：
batch size、gradient accumulation、epoch、max samples、sampling ratio、sequence length

模型/微调相关：
LoRA rank、LoRA alpha、target modules、dropout、freeze modules

生成/评测相关：
temperature、top_p、max_tokens、beam size

稳定性/工程相关：
precision、loss scale、checkpoint interval、eval interval、seed
```

### 最重要的原则

### 一次只改一个主要变量

否则你不知道效果变化来自哪里。

错误做法：

```text
同时改学习率、batch size、数据、epoch、LoRA rank。
```

正确做法：

```text
固定数据、模型、训练步数、评测集。
先只扫 learning rate。
再固定 learning rate，扫 epoch 或 LoRA rank。
```

### 先看训练是否稳定，再看效果是否提升

优先级：

```text
不崩、不 NaN、不 OOM
  -> loss 能下降
  -> 验证集指标能提升
  -> bad case 有真实改善
  -> 线上或全链路评测通过
```

### 不要只看 train loss

至少同时看：

- train loss。
- eval loss。
- 业务指标或 benchmark 指标。
- 格式正确率。
- bad case 类型。
- 训练耗时和显存。

只看 train loss 很容易误判，因为 train loss 下降不代表泛化能力提升。

### Learning Rate，学习率

### 它管什么

学习率决定每一步参数更新幅度。

```text
学习率大：走得快，但容易震荡或发散。
学习率小：走得稳，但可能学得慢或学不动。
```

### 常见现象

#### 学习率太大

表现：

- loss 一开始就剧烈震荡。
- loss 突然 spike。
- loss 变成 NaN。
- eval 指标不稳定。
- 模型输出变乱、格式崩。

调整：

- 降低 learning rate。
- 增加 warmup。
- 加 gradient clipping。
- 检查异常 batch。

#### 学习率太小

表现：

- train loss 下降很慢。
- 很多 step 后指标几乎不变。
- 模型看起来没有学到新任务。

调整：

- 提高 learning rate。
- 延长训练步数。
- 检查 LoRA target modules 是否生效。
- 检查数据 label 是否正确。

### 常见经验范围

不同任务差异很大，但可以作为起点：

| 场景 | 常见 learning rate |
|---|---|
| 全量微调 LLM | `1e-6` 到 `2e-5` |
| LoRA / QLoRA SFT | `5e-5` 到 `2e-4` |
| 小模型分类任务 | `1e-5` 到 `1e-3` |
| 视觉模型微调 | `1e-5` 到 `1e-4` |

LoRA 通常可以比全量微调用更大的学习率。

### Batch Size

### 它管什么

Batch size 决定每一步用多少样本估计梯度。

```text
batch size 小：梯度噪声大，训练不稳定，但可能泛化较好。
batch size 大：梯度更稳定，吞吐更高，但可能需要更大学习率和更多显存。
```

### Effective Batch Size

真实有效 batch size 要看：

```text
effective_batch_size =
per_device_train_batch_size
* GPU 数量
* gradient_accumulation_steps
```

例如：

```text
单卡 batch = 2
GPU = 8
gradient_accumulation_steps = 4

effective batch size = 2 * 8 * 4 = 64
```

### 怎么调

#### 显存不够

调整：

- 降低 per-device batch size。
- 增加 gradient accumulation。
- 降低 sequence length。
- 开启 gradient checkpointing。
- 使用 LoRA/QLoRA。

#### loss 抖动很大

可能原因：

- batch 太小。
- 学习率太大。
- 数据质量不稳定。

调整：

- 增大 effective batch size。
- 降低 learning rate。
- 做数据清洗或分桶。

#### 训练很慢

调整：

- 增大 batch size。
- 增加并行卡数。
- 使用 packing。
- 减少无效 padding。

### Gradient Accumulation，梯度累积

### 它管什么

梯度累积用于模拟更大的 batch size。

如果显存只能放小 batch，可以多跑几步 forward/backward，累积梯度后再更新一次参数。

```text
step 1: 算梯度，不更新
step 2: 算梯度，不更新
step 3: 算梯度，不更新
step 4: 算梯度，更新一次
```

### 什么时候用

- 显存不够但希望 effective batch size 更大。
- 小 batch 导致 loss 抖动。
- 多卡训练时想保持固定全局 batch size。

### 注意点

- gradient accumulation 变大后，每个 epoch 的 optimizer update 次数会变少。
- learning rate schedule 通常按 optimizer step 计算，不是按 micro step。
- 日志里的 step 含义要看框架定义。

### Epoch / Max Steps

### 它管什么

Epoch 表示模型完整看几遍训练集。

Max steps 表示最多更新多少步。

```text
数据少：epoch 太多容易过拟合。
数据多：可能不需要完整跑很多 epoch。
```

### 训练不够

表现：

- train loss 还在明显下降。
- eval 指标也还在提升。
- 模型明显没学会任务格式。

调整：

- 增加 epoch。
- 增加 max_steps。
- 确认学习率不是太小。

### 训练过头

表现：

- train loss 继续下降。
- eval loss 上升。
- eval 指标下降。
- 模型在训练风格上过拟合，泛化变差。

调整：

- 减少 epoch。
- 使用 early stopping。
- 增加数据。
- 加 dropout 或 weight decay。

### Warmup

### 它管什么

Warmup 是训练初期把 learning rate 从很小逐渐升到目标值。

```text
训练刚开始，参数和梯度都不稳定。
直接使用大学习率容易发散。
```

### 常见设置

- `warmup_ratio = 0.03` 到 `0.1`。
- 或固定 `warmup_steps`。

### 什么时候增大 warmup

- 训练初期 loss spike。
- 大 batch 训练。
- 学习率偏大。
- 模型较大或数据分布变化明显。

### 什么时候减小 warmup

- 总训练步数很少。
- warmup 占比太大导致真正学习阶段太短。

### Scheduler，学习率调度

### 它管什么

Scheduler 决定学习率随训练步数如何变化。

常见策略：

- constant：保持不变。
- linear decay：线性下降。
- cosine decay：余弦下降。
- step decay：每隔一段下降。

### 常见选择

LLM SFT 常见：

```text
warmup + cosine decay
warmup + linear decay
```

### 怎么判断

如果后期指标不稳定：

- 可以让学习率后期更低。
- 使用 cosine 或 linear decay。

如果训练步数很少：

- constant 或小 warmup 可能更直接。

### Optimizer

### 它管什么

Optimizer 决定如何根据梯度更新参数。

常见：

- SGD。
- Adam。
- AdamW。
- Adafactor。

### AdamW

大模型训练和微调常用 AdamW。

原因：

- 自适应学习率。
- 对不同参数维度调整更新幅度。
- weight decay 解耦，正则更清晰。

### 常见参数

- `betas`：控制一阶/二阶动量。
- `eps`：数值稳定项。
- `weight_decay`：权重衰减。

一般不优先调 betas 和 eps，除非训练非常不稳定。

### Weight Decay

### 它管什么

Weight decay 是正则化，限制参数不要过大。

作用：

- 缓解过拟合。
- 提升泛化。
- 让模型更新更平滑。

### 太大时

表现：

- 模型学不动。
- train loss 降得慢。
- 欠拟合。

### 太小时

表现：

- train loss 很低。
- eval 指标变差。
- 过拟合。

### 常见范围

- `0.0` 到 `0.1`。
- LLM SFT 中常见 `0.01` 左右，也有很多任务直接用 `0`。

### Gradient Clipping

### 它管什么

Gradient clipping 限制梯度范数，防止某一步梯度过大导致训练发散。

常见参数：

```text
max_grad_norm = 1.0
```

### 什么时候需要

- loss spike。
- 梯度爆炸。
- 出现 NaN。
- 长序列训练。
- 数据中存在异常样本。

### 注意

Gradient clipping 是稳定训练的保护措施，不应该用它掩盖严重数据问题或过大的学习率。

### Sequence Length / Max Length

### 它管什么

最大序列长度决定单条样本最多保留多少 token。

对 LLM 训练非常重要：

- 越长，显存越高。
- 越长，训练越慢。
- 太短会截断关键信息。

### 怎么调

#### OOM 或训练太慢

- 降低 max_length。
- 使用 packing。
- 按长度过滤极端长样本。
- 使用 gradient checkpointing。

#### 模型答非所问

可能是输入或 label 被截断。

检查：

- prompt 是否被截断。
- answer 是否被截断。
- label mask 是否正确。

### Packing

### 它管什么

Packing 是把多条短样本拼到一个长序列里训练，减少 padding 浪费。

```text
样本 A 100 token
样本 B 200 token
样本 C 300 token

不 packing：每条都 padding 到 max_length。
packing：拼成一条更满的训练序列。
```

### 适合什么

- 短样本很多。
- padding 浪费严重。
- 想提升训练吞吐。

### 风险

- 不同样本之间 attention mask 要处理正确。
- label mask 要处理正确。
- 否则模型可能跨样本学习到错误上下文。

### Dropout

### 它管什么

Dropout 训练时随机丢弃部分神经元，减少模型对局部特征的依赖。

作用：

- 缓解过拟合。
- 提升泛化。

### 怎么调

过拟合：

- 适当增大 dropout。

欠拟合：

- 降低 dropout。

LLM 微调里 dropout 通常不会调得很大，常见 `0.0` 到 `0.1`。

### LoRA 相关超参数

### LoRA rank，常写作 `r`

它决定 LoRA adapter 的容量。

```text
r 越大：可训练参数越多，表达能力更强，显存和过拟合风险也更高。
r 越小：更省，但可能学不动复杂任务。
```

常见范围：

- `r=4/8/16/32/64`。

怎么调：

- 任务简单、数据少：先用 `8` 或 `16`。
- 任务复杂、数据多：尝试 `32` 或 `64`。
- 过拟合：降低 rank。
- 欠拟合：提高 rank。

### LoRA alpha

控制 LoRA 更新的缩放强度。

常见经验：

```text
alpha 通常设为 r 的 1 到 2 倍。
```

例如：

- `r=8, alpha=16`
- `r=16, alpha=32`

### LoRA dropout

LoRA 分支上的 dropout。

作用：

- 缓解 LoRA 微调过拟合。

常见：

- `0.0` 到 `0.1`。

### Target Modules

决定 LoRA 插到哪些模块上。

常见位置：

- `q_proj`
- `k_proj`
- `v_proj`
- `o_proj`
- `up_proj`
- `down_proj`
- `gate_proj`

经验：

- 只调 attention：参数少，风险低。
- attention + FFN 都调：能力更强，成本更高。

如果模型学不动，除了调学习率，也要检查 target modules 是否覆盖关键模块。

### Precision，训练精度

### 常见选择

- FP32：稳定但慢、显存高。
- FP16：快、省显存，但更容易溢出。
- BF16：动态范围大，通常比 FP16 稳定。

### 怎么选

如果硬件支持，LLM 训练通常优先 BF16。

出现 NaN 时检查：

- 是否 FP16 溢出。
- loss scale 是否异常。
- 学习率是否过大。
- 梯度是否爆炸。
- 数据是否有异常值。

### Eval Interval / Save Interval

### 它管什么

`eval_interval` 决定多久评测一次。

`save_interval` 决定多久保存一次 checkpoint。

### 怎么调

数据少、训练快：

- 可以更频繁 eval。

训练很贵：

- eval 间隔可以大一点，但关键节点要覆盖。

建议：

- 至少保存 latest。
- 保留 best checkpoint。
- 保留关键 step 的 checkpoint 方便回溯。

### Seed

### 它管什么

随机种子控制初始化、采样、数据顺序等随机性。

### 为什么重要

小数据微调时，不同 seed 可能导致明显波动。

可靠结论最好：

- 固定 seed 做主实验。
- 关键结论用多个 seed 复验。

### 根据训练现象怎么调

### 情况 1：loss 一开始就 NaN

优先排查：

1. 学习率是否过大。
2. 是否 FP16 溢出。
3. 数据中是否有异常 token 或空 label。
4. loss mask 是否全 0。
5. 梯度是否爆炸。

调整：

- 降低 learning rate。
- 使用 BF16。
- 开启 gradient clipping。
- 增加 warmup。
- 抽查异常 batch。

### 情况 2：loss 不下降

可能原因：

- 学习率太小。
- 数据 label 错。
- label mask 错。
- LoRA 没挂到有效模块。
- 冻结了不该冻结的参数。
- 输入输出格式不匹配。

调整：

- 提高 learning rate。
- 检查训练样本 decode 后是否正确。
- 检查 labels 中有效 token 数。
- 检查 trainable parameters 数量。
- 小样本过拟合测试：用 10 条数据训练，看能不能把 loss 打下来。

### 情况 3：train loss 下降，eval loss 不降

可能原因：

- 过拟合。
- 训练集和验证集分布不一致。
- 验证集标签噪声。
- 训练目标和评测指标不一致。

调整：

- 减少 epoch。
- 降低 LoRA rank。
- 增加 dropout 或 weight decay。
- 增加数据。
- 重新检查验证集分布。

### 情况 4：train loss 和 eval loss 都很高

可能原因：

- 欠拟合。
- 模型能力不足。
- 学习率不合适。
- 训练步数不够。
- 数据太难或格式混乱。

调整：

- 增加训练步数。
- 提高 LoRA rank。
- 调大学习率。
- 扩大 target modules。
- 换更强 base model。
- 清洗数据格式。

### 情况 5：eval 指标提升，但实际 bad case 没改善

可能原因：

- 指标不匹配真实目标。
- 测试集太简单。
- 某些大类提升掩盖关键小类下降。
- 解析规则导致假提升。

调整：

- 做分桶指标。
- 看关键业务子集。
- 做 diff case。
- 复核输出原文。
- 增加难例回归集。

### 情况 6：模型开始复读、输出很长、格式变差

可能原因：

- 数据中有大量长回答或重复模式。
- 学习率过大。
- 训练过拟合。
- prompt/answer 模板不稳定。
- 推理参数不一致。

调整：

- 清洗重复样本。
- 降低 learning rate。
- 减少 epoch。
- 统一输出模板。
- 评测时固定 temperature、top_p、max_tokens。

### 情况 7：训练 OOM

调整优先级：

1. 降低 per-device batch size。
2. 降低 max_length。
3. 开启 gradient checkpointing。
4. 使用 BF16/FP16。
5. 使用 LoRA/QLoRA。
6. 增加 gradient accumulation 保持 effective batch size。
7. 使用 ZeRO/FSDP。

### 情况 8：训练吞吐很低

可能原因：

- padding 太多。
- 数据读取慢。
- sequence length 太长。
- batch size 太小。
- 多卡通信瓶颈。
- checkpoint/eval 太频繁。

调整：

- 开启 packing。
- 按长度分桶。
- 增大 batch size。
- 优化 dataloader workers。
- 减少频繁保存和评测。
- 检查 GPU 利用率。

### 推荐调参流程

### 第一步：先做小样本过拟合测试

目的：确认训练链路没问题。

用 10 到 100 条样本训练。

预期：

- train loss 应该明显下降。
- 模型应该能记住这些样本。

如果做不到，优先查代码、数据、label mask、LoRA 是否生效。

### 第二步：固定数据，扫 learning rate

例如 LoRA SFT 可以试：

```text
5e-5
1e-4
2e-4
```

观察：

- 哪个 loss 下降稳定。
- 哪个 eval 指标最好。
- 哪个输出格式最稳。

### 第三步：确定训练步数 / epoch

看 train loss 和 eval 指标：

- eval 还在涨：可以继续训。
- eval 开始掉：停止或减少 epoch。
- train loss 下降但 eval 不涨：可能过拟合或指标不对。

### 第四步：调 LoRA 容量

如果欠拟合：

- 增大 rank。
- 覆盖更多 target modules。

如果过拟合：

- 降低 rank。
- 增加 dropout。
- 减少 epoch。

### 第五步：做稳定性和回归评测

固定最终配置后：

- 全量评测。
- 分桶评测。
- bad case diff。
- 多 seed 或重复实验。
- 保存 config、数据版本、checkpoint、评测结果。

### 一个实用起始配置

假设是 LLM LoRA SFT，可以从这里起步：

```yaml
learning_rate: 1.0e-4
lr_scheduler_type: cosine
warmup_ratio: 0.03
per_device_train_batch_size: 1-4
gradient_accumulation_steps: 4-16
num_train_epochs: 1-3
max_length: 根据任务输入输出长度设置
optimizer: adamw
weight_decay: 0.01
max_grad_norm: 1.0
bf16: true
lora_rank: 8 或 16
lora_alpha: 16 或 32
lora_dropout: 0.05
target_modules: q_proj,k_proj,v_proj,o_proj
eval_steps: 每 200-1000 step
save_steps: 每 500-2000 step
seed: 42
```

这不是最优配置，只是一个安全起点。

### 面试回答模板

如果面试官问“你怎么调训练超参数”，可以按这个结构答：

```text
我会先保证训练链路正确，比如用小样本过拟合测试确认 loss 能下降。
然后优先调 learning rate，因为它对稳定性和收敛速度影响最大。
接着根据显存和梯度稳定性确定 effective batch size，通过 gradient accumulation 补偿显存限制。
如果出现发散，我会降低学习率、增加 warmup、打开 gradient clipping，并检查异常数据。
如果 train loss 降但 eval 不涨，我会考虑过拟合，减少 epoch、增加正则或改数据。
如果 train/eval 都不好，我会考虑欠拟合，增加训练步数、LoRA rank、target modules 或换更强模型。
最后会用固定回归集、分桶指标和 bad case diff 验证效果，而不是只看单个平均指标。
```

### 快速对照表

| 现象 | 可能原因 | 优先调整 |
|---|---|---|
| loss NaN | 学习率大、FP16 溢出、异常数据 | 降 LR、BF16、clip、查 batch |
| loss 不降 | LR 小、label mask 错、LoRA 未生效 | 提 LR、查数据、查 trainable params |
| loss 抖动 | batch 小、LR 大、数据噪声 | 增 batch、降 LR、清洗数据 |
| train 好 eval 差 | 过拟合、分布不一致 | 减 epoch、正则、加数据 |
