# 训练超参数调参指南

## 知识点解析

### 概述

这篇是一份系统的训练超参数调参指南。核心认知是：超参数不是孤立调的，它们共同决定模型每一步怎么更新、看多少数据看多久、以及训练是否稳定和过拟合。下面按优化、数据、模型/微调、生成/评测、稳定性几类逐一讲清每个超参数管什么、常见现象和怎么调。

### 先建立一个总认知

训练超参数不是孤立调的。它们共同决定三件事：

1. 模型每一步怎么更新参数。
2. 模型看多少数据、看多久。
3. 训练过程是否稳定、是否过拟合、是否学不动。

可以先把超参数分成几类：

```text
优化相关：
learning rate、optimizer、weight decay、warmup、scheduler、gradient clipping

数据相关：
batch size、gradient accumulation、epoch、max samples、sampling ratio、sequence length

模型/微调相关：
LoRA rank、LoRA alpha、target modules、dropout、freeze modules

生成/评测相关：
temperature、top_p、max_tokens、beam size

稳定性/工程相关：
precision、loss scale、checkpoint interval、eval interval、seed
```

### 最重要的原则

#### 一次只改一个主要变量

否则你不知道效果变化来自哪里。

错误做法：

```text
同时改学习率、batch size、数据、epoch、LoRA rank。
```

正确做法：

```text
固定数据、模型、训练步数、评测集。
先只扫 learning rate。
再固定 learning rate，扫 epoch 或 LoRA rank。
```

#### 先看训练是否稳定，再看效果是否提升

优先级：

```text
不崩、不 NaN、不 OOM
  -> loss 能下降
  -> 验证集指标能提升
  -> bad case 有真实改善
  -> 线上或全链路评测通过
```

#### 不要只看 train loss

至少同时看：

- train loss。
- eval loss。
- 业务指标或 benchmark 指标。
- 格式正确率。
- bad case 类型。
- 训练耗时和显存。

只看 train loss 很容易误判，因为 train loss 下降不代表泛化能力提升。

### Learning Rate，学习率

#### 它管什么

学习率决定每一步参数更新幅度。

```text
学习率大：走得快，但容易震荡或发散。
学习率小：走得稳，但可能学得慢或学不动。
```

#### 常见现象

##### 学习率太大

表现：

- loss 一开始就剧烈震荡。
- loss 突然 spike。
- loss 变成 NaN。
- eval 指标不稳定。
- 模型输出变乱、格式崩。

调整：

- 降低 learning rate。
- 增加 warmup。
- 加 gradient clipping。
- 检查异常 batch。

##### 学习率太小

表现：

- train loss 下降很慢。
- 很多 step 后指标几乎不变。
- 模型看起来没有学到新任务。

调整：

- 提高 learning rate。
- 延长训练步数。
- 检查 [LoRA](<../后训练与对齐/LoRA 低秩适配.md#lora-低秩适配>) target modules 是否生效。
- 检查数据 label 是否正确。

#### 常见经验范围

不同任务差异很大，但可以作为起点：

| 场景 | 常见 learning rate |
|---|---|
| 全量微调 LLM | `1e-6` 到 `2e-5` |
| LoRA / [QLoRA](<../后训练与对齐/PEFT 参数高效微调.md#qlora-和-lora-的区别是什么>) [SFT](<../后训练与对齐/SFT 监督微调.md#sft-监督微调>) | `5e-5` 到 `2e-4` |
| 小模型分类任务 | `1e-5` 到 `1e-3` |
| 视觉模型微调 | `1e-5` 到 `1e-4` |

LoRA 通常可以比全量微调用更大的学习率。

### Batch Size

#### 它管什么

Batch size 决定每一步用多少样本估计梯度。

```text
batch size 小：梯度噪声大，训练不稳定，但可能泛化较好。
batch size 大：梯度更稳定，吞吐更高，但可能需要更大学习率和更多显存。
```

#### Effective Batch Size

真实有效 batch size 要看：

$$
\text{effective batch size}
=\text{per-device micro-batch}
\times\text{gradient accumulation steps}
\times\text{data-parallel world size}.
$$

例如：

$$
\begin{aligned}
\text{per-device micro-batch}&=2,\qquad \text{data-parallel world size}=8,\qquad
\text{gradient accumulation steps}=4,\\
\text{effective batch size}&=2\times8\times4=64.
\end{aligned}
$$

这里的 data-parallel world size 是独立处理不同数据的副本数；tensor parallel、pipeline parallel 或 expert parallel 只是在副本内部拆分模型，不能直接计入。使用 packing 或变长样本时，样本条数 EBS 不能准确表示训练量，还应按每次 optimizer update 中实际参与 loss 的非 padding token 数衡量。

#### 怎么调

##### 显存不够

调整：

- 降低 per-device batch size。
- 增加 gradient accumulation。
- 降低 sequence length。
- 开启 gradient checkpointing。
- 使用 LoRA/QLoRA。

##### loss 抖动很大

可能原因：

- batch 太小。
- 学习率太大。
- 数据质量不稳定。

调整：

- 增大 effective batch size。
- 降低 learning rate。
- 做数据清洗或分桶。

##### 训练很慢

调整：

- 增大 batch size。
- 增加并行卡数。
- 使用 packing。
- 减少无效 padding。

### Gradient Accumulation，梯度累积

#### 它管什么

梯度累积用于模拟更大的 batch size。

如果显存只能放小 batch，可以多跑几步 forward/backward，累积梯度后再更新一次参数。

```text
step 1: 算梯度，不更新
step 2: 算梯度，不更新
step 3: 算梯度，不更新
step 4: 算梯度，更新一次
```

#### 什么时候用

- 显存不够但希望 effective batch size 更大。
- 小 batch 导致 loss 抖动。
- 多卡训练时想保持固定全局 batch size。

#### 注意点

- gradient accumulation 变大后，每个 epoch 的 optimizer update 次数会变少。
- learning rate schedule 通常按 optimizer step 计算，不是按 micro step。
- 日志里的 step 含义要看框架定义。

### Epoch / Max Steps

#### 它管什么

Epoch 表示模型完整看几遍训练集。

Max steps 表示最多更新多少步。

```text
数据少：epoch 太多容易过拟合。
数据多：可能不需要完整跑很多 epoch。
```

#### 训练不够

表现：

- train loss 还在明显下降。
- eval 指标也还在提升。
- 模型明显没学会任务格式。

调整：

- 增加 epoch。
- 增加 max_steps。
- 确认学习率不是太小。

#### 训练过头

表现：

- train loss 继续下降。
- eval loss 上升。
- eval 指标下降。
- 模型在训练风格上过拟合，泛化变差。

调整：

- 减少 epoch。
- 使用 early stopping。
- 增加数据。
- 加 dropout 或 weight decay。

### Max Samples / Sampling Ratio

这两个参数控制的是“训练数据怎么被使用”，不是 Optimizer 参数，但在多数据集或类别不均衡时很重要。

#### Max Samples 是什么

`max_samples` 表示本次训练最多使用多少条样本。它通常用于限制数据规模、控制训练成本或做快速实验，但具体是“全局上限”还是“每个数据集上限”要看训练框架的实现。

```text
max_samples = 10000
  -> 最多取 10000 条样本参与本次训练
```

它会影响：

- 训练耗时和显存外的整体计算成本。
- 每个 epoch 包含多少样本和 optimizer step。
- 模型能看到的数据多样性。
- 小数据集上重复训练和过拟合的风险。

通常先使用全部高质量数据；只有需要控制预算、做小规模实验或数据量过大时，才设置较小的 `max_samples`。比较不同配置时，要注意 `max_samples` 变大也可能让训练步数变多，不能把数据量增加带来的收益误认为是其他超参数的收益。

#### Sampling Ratio 是什么

`sampling_ratio` 表示不同数据源、任务类型或类别被抽到的相对频率。

例如有：

```text
通用对话数据：90%
业务数据：10%
```

如果设置 `sampling_ratio = 1:1`，训练时就可能让两类数据各占约一半。业务数据较少时，这通常意味着它会被重复采样；业务数据较多时，则意味着只抽取其中一部分。

它主要控制：

- 模型更重视哪类能力。
- 少数类是否会被充分训练。
- 多数据源之间是否互相稀释。
- 是否因为重复采样小数据而过拟合。

#### 两者怎么区分

| 参数 | 回答的问题 | 例子 |
| --- | --- | --- |
| `max_samples` | 总共最多拿多少条？ | 最多训练 10 万条 |
| `sampling_ratio` | 不同来源各拿多大比例？ | A:B = 3:1 |

假设两个数据源 A、B 合计最多取 4 万条，并且全局 `sampling_ratio = 3:1`，可以理解为约取 A 3 万条、B 1 万条。实际框架可能通过加权采样、分桶配额或重复采样实现，因此要查看具体实现确认边界。

#### 重要吗，怎么调

- **单一且分布均匀的数据集**：`sampling_ratio` 通常不重要，`max_samples` 主要用来控制实验规模。
- **多个数据集、多个任务或类别严重不均衡**：两者都重要，甚至可能比微调 `betas` 更影响最终结果。
- **少数类是核心业务能力**：适当提高它的采样比例，但要监控重复样本导致的过拟合。
- **某个数据源质量较差**：不要只靠降低 learning rate 修复，应降低采样比例或先清洗数据。

推荐顺序：

1. 先固定验证集，确认各任务和类别都能被评测。
2. 先按数据质量和目标场景确定采样比例，不要盲目追求原始数据比例。
3. 再用 `max_samples` 控制训练预算。
4. 比较不同配置时固定总训练 token 数或 `max_steps`，否则数据量、训练时长和采样比例会同时变化。

### Warmup

#### 它管什么

Warmup 是训练初期把 learning rate 从很小逐渐升到目标值。

```text
训练刚开始，参数和梯度都不稳定。
直接使用大学习率容易发散。
```

#### 常见设置

- `warmup_ratio = 0.03` 到 `0.1`。
- 或固定 `warmup_steps`。

#### 什么时候增大 warmup

- 训练初期 loss spike。
- 大 batch 训练。
- 学习率偏大。
- 模型较大或数据分布变化明显。

#### 什么时候减小 warmup

- 总训练步数很少。
- warmup 占比太大导致真正学习阶段太短。

### Scheduler，学习率调度

#### 它管什么

Scheduler 决定学习率随训练步数如何变化。

常见策略：

- constant：保持不变。
- linear decay：线性下降。
- cosine decay：余弦下降。
- step decay：每隔一段下降。

#### 常见选择

LLM SFT 常见：

```text
warmup + cosine decay
warmup + linear decay
```

#### 怎么判断

如果后期指标不稳定：

- 可以让学习率后期更低。
- 使用 cosine 或 linear decay。

如果训练步数很少：

- constant 或小 warmup 可能更直接。

### Optimizer

Optimizer 的定义、SGD/Momentum/Adam/AdamW/Adafactor 的原理、公式和选型见[《Optimizer 优化器》](<Optimizer 优化器.md#optimizer-优化器>)。本节只保留调参时需要的结论，避免两篇文档重复维护。

#### 调参时先分清三个旋钮

| 配置 | 负责什么 | 调参优先级 |
| --- | --- | --- |
| Optimizer | 把梯度加工成更新方向，决定是否利用历史梯度和参数级尺度 | 先按任务固定，通常不频繁更换 |
| `learning_rate` | 决定更新方向整体走多远 | 最优先扫描 |
| `weight_decay` | 抑制过拟合，独立收缩参数 | learning rate 稳定后再调 |

#### 怎么选和怎么调

- LLM、Transformer、SFT、LoRA/QLoRA：通常先用 `AdamW`。
- Optimizer 状态导致 OOM：先评估 8-bit AdamW；仍受限时再考虑 Adafactor。
- 视觉分类等已有成熟配方：可以把 SGD + Momentum 作为对照基线。
- 只有在更新规则本身成为明确瓶颈时才更换 Optimizer；loss spike、NaN 或不收敛通常先查 learning rate、warmup、精度、batch、数据和 label。

#### Optimizer 怎么调

Optimizer 类型通常先固定，推荐顺序是：

1. **先固定 Optimizer**：例如 LLM SFT 先固定 AdamW。
2. **扫描 learning rate**：不同 Optimizer 的有效步长不同，不能用同一个 learning rate 直接比较。
3. **再调 weight decay**：它主要处理泛化和过拟合，不是用来修复训练初期发散的。
4. **最后才动 `betas`、`eps` 或 Adafactor 特殊选项**：这些参数影响历史信息的响应速度和数值稳定性，影响更隐蔽。

AdamW 常先固定：

```yaml
optimizer: adamw
betas: [0.9, 0.999]
eps: 1.0e-8
```

参数含义：

- `beta1` 越大，方向越平滑，但对新梯度的响应越慢；通常保持 `0.9`。
- `beta2` 越大，梯度尺度估计越稳定，但对尺度突变响应越慢；通常保持 `0.999`。
- `eps` 是数值稳定项，防止除以接近 0 的数；通常保持默认，只有出现明确的数值问题才尝试修改。
- `weight_decay` 不是 AdamW 的“方向记忆”，而是独立的正则化旋钮，详见下一节。

一个实用的 AdamW 小范围实验可以是：

```text
固定 betas、eps、数据、effective batch size 和训练步数
  -> learning_rate：5e-5 / 1e-4 / 2e-4（LoRA SFT 示例）
  -> 选稳定且验证指标好的档位
  -> weight_decay：0 / 0.01（再看过拟合）
  -> 最后才考虑是否需要换 Optimizer
```

比较不同 Optimizer 时，应固定数据版本、有效 batch size、训练 token 数、评测集和总计算预算；每个 Optimizer 都要有自己的 learning rate 小扫描，最后比较 eval 指标、bad case、吞吐和显存，而不是只看训练 loss。

### Weight Decay

#### 它管什么

Weight decay 是[正则化](<../../01_机器学习基础/深度学习基础/正则化.md#正则化>)，限制参数不要过大。

作用：

- 缓解过拟合。
- 提升泛化。
- 让模型更新更平滑。

#### 太大时

表现：

- 模型学不动。
- train loss 降得慢。
- 欠拟合。

#### 太小时

表现：

- train loss 很低。
- eval 指标变差。
- 过拟合。

#### 常见范围

- `0.0` 到 `0.1`。
- LLM SFT 中常见 `0.01` 左右，也有很多任务直接用 `0`。

### Gradient Clipping

#### 它管什么

Gradient clipping 限制梯度范数，防止某一步梯度过大导致训练发散。

常见参数：

```text
max_grad_norm = 1.0
```

#### 什么时候需要

- loss spike。
- 梯度爆炸。
- 出现 NaN。
- 长序列训练。
- 数据中存在异常样本。

#### 注意

Gradient clipping 是稳定训练的保护措施，不应该用它掩盖严重数据问题或过大的学习率。

### Sequence Length / Max Length

#### 它管什么

最大序列长度决定单条样本最多保留多少 token。

对 LLM 训练非常重要：

- 越长，显存越高。
- 越长，训练越慢。
- 太短会截断关键信息。

#### 怎么调

##### OOM 或训练太慢

- 降低 max_length。
- 使用 packing。
- 按长度过滤极端长样本。
- 使用 gradient checkpointing。

##### 模型答非所问

可能是输入或 label 被截断。

检查：

- prompt 是否被截断。
- answer 是否被截断。
- label mask 是否正确。

### Packing

#### 它管什么

Packing 是把多条短样本拼到一个长序列里训练，减少 padding 浪费。

```text
样本 A 100 token
样本 B 200 token
样本 C 300 token

不 packing：每条都 padding 到 max_length。
packing：拼成一条更满的训练序列。
```

#### 适合什么

- 短样本很多。
- padding 浪费严重。
- 想提升训练吞吐。

#### 风险

- 不同样本之间 attention mask 要处理正确。
- label mask 要处理正确。
- 否则模型可能跨样本学习到错误上下文。

### Dropout

#### 它管什么

Dropout 训练时随机丢弃部分神经元，减少模型对局部特征的依赖。

作用：

- 缓解过拟合。
- 提升泛化。

#### 怎么调

过拟合：

- 适当增大 dropout。

欠拟合：

- 降低 dropout。

LLM 微调里 dropout 通常不会调得很大，常见 `0.0` 到 `0.1`。

### LoRA 相关超参数

#### LoRA rank，常写作 `r`

它决定 LoRA adapter 的容量。

```text
r 越大：可训练参数越多，表达能力更强，显存和过拟合风险也更高。
r 越小：更省，但可能学不动复杂任务。
```

常见范围：

- `r=4/8/16/32/64`。

怎么调：

- 任务简单、数据少：先用 `8` 或 `16`。
- 任务复杂、数据多：尝试 `32` 或 `64`。
- 过拟合：降低 rank。
- 欠拟合：提高 rank。

#### LoRA alpha

控制 LoRA 更新的缩放强度。

常见经验：

```text
alpha 通常设为 r 的 1 到 2 倍。
```

例如：

- `r=8, alpha=16`
- `r=16, alpha=32`

#### LoRA dropout

LoRA 分支上的 dropout。

作用：

- 缓解 LoRA 微调过拟合。

常见：

- `0.0` 到 `0.1`。

#### Target Modules

决定 LoRA 插到哪些模块上。

常见位置：

- `q_proj`
- `k_proj`
- `v_proj`
- `o_proj`
- `up_proj`
- `down_proj`
- `gate_proj`

经验：

- 只调 attention：参数少，风险低。
- attention + FFN 都调：能力更强，成本更高。

如果模型学不动，除了调学习率，也要检查 target modules 是否覆盖关键模块。

### Precision，训练精度

#### 常见选择

- FP32：稳定但慢、显存高。
- FP16：快、省显存，但更容易溢出。
- BF16：动态范围大，通常比 FP16 稳定。

#### 怎么选

如果硬件支持，LLM 训练通常优先 BF16。

出现 NaN 时检查：

- 是否 FP16 溢出。
- loss scale 是否异常。
- 学习率是否过大。
- 梯度是否爆炸。
- 数据是否有异常值。

### Eval Interval / Save Interval

#### 它管什么

`eval_interval` 决定多久评测一次。

`save_interval` 决定多久保存一次 checkpoint。

#### 怎么调

数据少、训练快：

- 可以更频繁 eval。

训练很贵：

- eval 间隔可以大一点，但关键节点要覆盖。

建议：

- 至少保存 latest。
- 保留 best checkpoint。
- 保留关键 step 的 checkpoint 方便回溯。

### Seed

#### 它管什么

随机种子控制初始化、采样、数据顺序等随机性。

#### 为什么重要

小数据微调时，不同 seed 可能导致明显波动。

可靠结论最好：

- 固定 seed 做主实验。
- 关键结论用多个 seed 复验。

### 根据训练现象怎么调

#### 情况 1：loss 一开始就 NaN

优先排查：

1. 学习率是否过大。
2. 是否 FP16 溢出。
3. 数据中是否有异常 token 或空 label。
4. loss mask 是否全 0。
5. 梯度是否爆炸。

调整：

- 降低 learning rate。
- 使用 BF16。
- 开启 gradient clipping。
- 增加 warmup。
- 抽查异常 batch。

#### 情况 2：loss 不下降

可能原因：

- 学习率太小。
- 数据 label 错。
- label mask 错。
- LoRA 没挂到有效模块。
- 冻结了不该冻结的参数。
- 输入输出格式不匹配。

调整：

- 提高 learning rate。
- 检查训练样本 decode 后是否正确。
- 检查 labels 中有效 token 数。
- 检查 trainable parameters 数量。
- 小样本过拟合测试：用 10 条数据训练，看能不能把 loss 打下来。

#### 情况 3：train loss 下降，eval loss 不降

可能原因：

- 过拟合。
- 训练集和验证集分布不一致。
- 验证集标签噪声。
- 训练目标和评测指标不一致。

调整：

- 减少 epoch。
- 降低 LoRA rank。
- 增加 dropout 或 weight decay。
- 增加数据。
- 重新检查验证集分布。

#### 情况 4：train loss 和 eval loss 都很高

可能原因：

- 欠拟合。
- 模型能力不足。
- 学习率不合适。
- 训练步数不够。
- 数据太难或格式混乱。

调整：

- 增加训练步数。
- 提高 LoRA rank。
- 调大学习率。
- 扩大 target modules。
- 换更强 base model。
- 清洗数据格式。

#### 情况 5：eval 指标提升，但实际 bad case 没改善

可能原因：

- 指标不匹配真实目标。
- 测试集太简单。
- 某些大类提升掩盖关键小类下降。
- 解析规则导致假提升。

调整：

- 做分桶指标。
- 看关键业务子集。
- 做 diff case。
- 复核输出原文。
- 增加难例回归集。

#### 情况 6：模型开始复读、输出很长、格式变差

可能原因：

- 数据中有大量长回答或重复模式。
- 学习率过大。
- 训练过拟合。
- prompt/answer 模板不稳定。
- 推理参数不一致。

调整：

- 清洗重复样本。
- 降低 learning rate。
- 减少 epoch。
- 统一输出模板。
- 评测时固定 temperature、top_p、max_tokens。

#### 情况 7：训练 OOM

调整优先级：

1. 降低 per-device batch size。
2. 降低 max_length。
3. 开启 gradient checkpointing。
4. 使用 BF16/FP16。
5. 使用 LoRA/QLoRA。
6. 增加 gradient accumulation 保持 effective batch size。
7. 使用 ZeRO/FSDP。

#### 情况 8：训练吞吐很低

可能原因：

- padding 太多。
- 数据读取慢。
- sequence length 太长。
- batch size 太小。
- 多卡通信瓶颈。
- checkpoint/eval 太频繁。

调整：

- 开启 packing。
- 按长度分桶。
- 增大 batch size。
- 优化 dataloader workers。
- 减少频繁保存和评测。
- 检查 GPU 利用率。

### 推荐调参流程

#### 第一步：先做小样本过拟合测试

目的：确认训练链路没问题。

用 10 到 100 条样本训练。

预期：

- train loss 应该明显下降。
- 模型应该能记住这些样本。

如果做不到，优先查代码、数据、label mask、LoRA 是否生效。

#### 第二步：固定数据，扫 learning rate

例如 LoRA SFT 可以试：

```text
5e-5
1e-4
2e-4
```

观察：

- 哪个 loss 下降稳定。
- 哪个 eval 指标最好。
- 哪个输出格式最稳。

#### 第三步：确定训练步数 / epoch

看 train loss 和 eval 指标：

- eval 还在涨：可以继续训。
- eval 开始掉：停止或减少 epoch。
- train loss 下降但 eval 不涨：可能过拟合或指标不对。

#### 第四步：调 LoRA 容量

如果欠拟合：

- 增大 rank。
- 覆盖更多 target modules。

如果过拟合：

- 降低 rank。
- 增加 dropout。
- 减少 epoch。

#### 第五步：做稳定性和回归评测

固定最终配置后：

- 全量评测。
- 分桶评测。
- bad case diff。
- 多 seed 或重复实验。
- 保存 config、数据版本、checkpoint、评测结果。

#### SFT 场景：特有默认值与调整顺序

本节只讨论 [SFT](<../后训练与对齐/SFT 监督微调.md#sft-监督微调>) 的参数起点和工程配置；训练目标、response-only loss 与数据格式由 SFT 专题卡维护。

##### 常用起点

| 配置 | 建议起点 | 调整边界 |
| --- | --- | --- |
| 全参数 SFT 学习率 | `1e-5` | 常见搜索区间为 `5e-6` 到 `2e-5`；全量更新权重时用小步长避免破坏预训练能力 |
| LoRA / QLoRA SFT 学习率 | `1e-4` 左右 | 常见搜索区间为 `5e-5` 到 `2e-4`；只训练 adapter 时通常可比全参数微调高一个量级 |
| `warmup_ratio` | `0.05` | `0.03` 到 `0.1` 常见；初期突刺可加到 `0.1`，总步数很少时改用固定 `warmup_steps` |
| `num_train_epochs` | `1` | SFT 容易过拟合；只有 eval loss 和下游指标仍改善时才尝试 `2` 到 `3` |
| `gradient_accumulation_steps` | 由目标 EBS 和显存反推 | 先定 per-device micro-batch 与 data-parallel world size，再用梯度累积补足有效 batch size |

选择学习率档位前先确认训练方式，例如检查脚本是否设置了 `--train_type lora`，不要把全参数 SFT 的学习率直接套到 LoRA / QLoRA。

一个全参数 SFT 的保守起始片段是：

```bash
learning_rate=1.0e-5
warmup_ratio=0.05
num_train_epochs=1
gradient_accumulation_steps=2
```

这组值不是固定答案。先按 `per-device micro-batch × gradient accumulation × data-parallel world size` 计算 effective batch size（EBS），再结合显存和序列长度确定梯度累积；tensor、pipeline 或 expert parallel 不增加数据并行副本，不能把 GPU 总数直接代入。使用 packing 或变长样本时，还要比较每次 optimizer update 中实际参与 loss 的有效 token 数。梯度累积是在多次 micro-batch 反向传播后再做一次 optimizer step，主要用于以时间换显存；只有 loss reduction、样本总数和更新时机一致时，才近似等价于直接使用大 batch。Dropout、依赖 micro-batch 统计的算子、数值误差和框架的 loss 缩放方式都可能造成差异。

EBS 改变后，学习率也要重新验证。EBS 变大时可以把线性缩放或平方根缩放作为候选起点，EBS 变小时反向调整，但不能把缩放规则当成定律，最终仍以 loss 稳定性和验证指标为准。

##### 调整顺序

1. 先看前 50 步：以全参起点 `1e-5` 为例，NaN 或直线飙升时可降到 `5e-6` 到 `7e-6`，并检查精度、异常 batch 和梯度裁剪；只在训练开头突刺时增加 warmup。
2. 再看整体趋势：loss 剧烈抖动时先区分 EBS 太小、学习率太大和数据噪声，确认是学习率后可先减半；loss 几乎不动且数据、mask 正常时，可在全参 SFT 中试到 `2e-5`。
3. 必须看验证集：train loss 和 eval loss 都下降时才延长训练；出现 train 降而 eval 升的剪刀差时停止或早停。
4. 每次只改一个主变量，保存对应配置、曲线和评测结果，避免无法归因。

##### Epoch、checkpoint 与工程检查

- 每个 epoch 至少保留一个 checkpoint，并分别跑下游指标；优先选择真实任务指标最好的 checkpoint，例如关键帧任务的帧误差、`time_err` 或 PASS 率，而不是 train loss 最低的 checkpoint。
- 如果脚本没有验证集或 `eval_steps`，应补充 `--val_dataset` / `--eval_steps`；否则无法可靠判断是否应从 1 epoch 增加到 2 到 3 epoch。
- 视频或多模态 SFT 要确保训练与评测的 FPS、抽帧数、token 截断长度和采样参数一致。环境不一致时，下游指标异常不能直接归因于超参数。
- OOM 时先减小 per-device batch，再增大梯度累积以维持 EBS；显存有余但吞吐低时，优先增大 per-device batch 并减少累积步数。

### 一个实用起始配置

假设是 LLM LoRA SFT，可以从这里起步：

```yaml
learning_rate: 1.0e-4
lr_scheduler_type: cosine
warmup_ratio: 0.03
per_device_train_batch_size: 1-4
gradient_accumulation_steps: 4-16
num_train_epochs: 1-3
max_length: 根据任务输入输出长度设置
optimizer: adamw
weight_decay: 0.01
max_grad_norm: 1.0
bf16: true
lora_rank: 8 或 16
lora_alpha: 16 或 32
lora_dropout: 0.05
target_modules: q_proj,k_proj,v_proj,o_proj
eval_steps: 每 200-1000 step
save_steps: 每 500-2000 step
seed: 42
```

这不是最优配置，只是一个安全起点。

### 面试回答模板

如果面试官问“你怎么调训练超参数”，可以按这个结构答：

```text
我会先保证训练链路正确，比如用小样本过拟合测试确认 loss 能下降。
然后优先调 learning rate，因为它对稳定性和收敛速度影响最大。
接着根据显存和梯度稳定性确定 effective batch size，通过 gradient accumulation 补偿显存限制。
如果出现发散，我会降低学习率、增加 warmup、打开 gradient clipping，并检查异常数据。
如果 train loss 降但 eval 不涨，我会考虑过拟合，减少 epoch、增加正则或改数据。
如果 train/eval 都不好，我会考虑欠拟合，增加训练步数、LoRA rank、target modules 或换更强模型。
最后会用固定回归集、分桶指标和 bad case diff 验证效果，而不是只看单个平均指标。
```

### 快速对照表

| 现象 | 可能原因 | 优先调整 |
|---|---|---|
| loss NaN | 学习率大、FP16 溢出、异常数据 | 降 LR、BF16、clip、查 batch |
| loss 不降 | LR 小、label mask 错、LoRA 未生效 | 提 LR、查数据、查 trainable params |
| loss 抖动 | batch 小、LR 大、数据噪声 | 增 batch、降 LR、清洗数据 |
| train 好 eval 差 | 过拟合、分布不一致 | 减 epoch、正则、加数据 |
| train/eval 都差 | 欠拟合、模型弱、步数少 | 加 step、升 rank、扩 target modules |
| OOM | batch/长度/模型太大 | 降 batch/长度、checkpointing、LoRA |
| 吞吐低 | padding 多、IO 慢、batch 小 | packing、长度分桶、增 batch |
| 输出格式差 | 数据模板乱、过拟合、推理参数不稳 | 统一模板、降 LR、固定 decoding |
## 面试应对

### 训练超参数调参的核心目标是什么？

回答思路：抓住“在稳定收敛、泛化效果和训练成本三者间求平衡”，并强调超参数不是孤立调的、要一次只改一个主变量做对照。

回答模板：

调参的目标是让模型在稳定收敛、泛化效果和训练成本之间取得平衡。关键超参数包括 learning rate、batch size、weight decay、warmup、scheduler、梯度裁剪和混合精度配置。

### Optimizer 有什么作用？不同 Optimizer 怎么选？

回答思路：先区分梯度、Optimizer、learning rate 和 weight decay，再说明 Optimizer 的差异主要是是否使用历史梯度、是否按参数自适应缩放以及状态显存开销。

回答模板：

Optimizer 不理解任务，它负责把反向传播得到的原始梯度加工成参数更新。SGD 直接使用当前梯度；Momentum 在此基础上累积历史方向以减少震荡；Adam 同时维护一阶动量和梯度平方的移动平均，对不同参数自适应缩放；AdamW 还把 weight decay 与梯度更新解耦。Transformer、LLM 和 LoRA SFT 通常先选 AdamW；如果 Optimizer 状态导致显存不足，再考虑 8-bit AdamW 或 Adafactor；视觉分类等已有成熟配方的任务，可以把 SGD + Momentum 作为强基线。Optimizer 类型选定后，优先为它扫描 learning rate，再调 weight decay，`betas` 和 `eps` 通常保持默认，只有出现明确证据时才修改。比较不同 Optimizer 时，不能直接使用同一个 learning rate，而要给每种 Optimizer 做自己的小范围搜索。

### 学习率怎么调？

回答思路：抓住学习率是最关键超参——太大 loss spike/震荡/NaN、太小收敛慢或欠拟合，配合 warmup 和 cosine/linear decay，通过小规模扫描看 loss 曲线、梯度范数和验证指标定值。

回答模板：

学习率通常是最关键的超参数。过大会导致 loss spike、震荡甚至 NaN；过小会收敛慢或陷入欠拟合。实际会结合 warmup、cosine decay 或 step decay，并通过小规模实验观察 loss 曲线、梯度范数和验证集指标。

### SFT 的学习率为什么全参常用 `1e-5` 量级，而 LoRA 常用 `1e-4` 量级？

回答思路：区分可训练参数范围。全参数微调直接改动全部权重，需要较小步长保护预训练能力；LoRA 只训练低秩 adapter，通常需要更大步长。

回答模板：

全参数 SFT 会更新模型全部权重，学习率过大容易破坏预训练能力，所以常从 `5e-6` 到 `2e-5` 搜索，`1e-5` 是稳妥起点。LoRA 只更新少量低秩 adapter 参数，通常需要更大步长才能学到任务变化，因此常从 `5e-5` 到 `2e-4` 搜索，起点可以放在 `1e-4` 左右。最终要结合有效 batch size、loss 曲线和验证指标确定，不能只按微调名称机械套值。

### Gradient accumulation 会不会改变训练结果？

回答思路：先说明它用时间换显存、用于模拟更大 EBS，再给出近似等价成立的条件和工程差异。

回答模板：

Gradient accumulation 会连续计算若干个 micro-batch 的梯度，再统一执行一次 optimizer step，所以有效 batch size 等于 per-device micro-batch 乘以累积步数再乘以 data-parallel world size。Tensor、pipeline 或 expert parallel 不增加数据副本，不能直接乘 GPU 总数；使用 packing 或变长样本时，还要比较每次 optimizer update 的有效 token 数。它主要是用时间换显存。在 loss 缩放、样本总数和更新时机一致时，它近似等价于直接使用大 batch；但 Dropout、依赖 micro-batch 统计的算子、数值误差和框架实现会带来差异，因此不能说任何场景下都完全相同。

### SFT 为什么常从 1 个 epoch 开始？怎么选 checkpoint？

回答思路：强调 SFT 容易过拟合，epoch 和 checkpoint 必须由验证集及下游指标决定，不能只看 train loss。

回答模板：

SFT 数据通常比预训练数据少，重复训练容易让模型背答案并损害通用能力，所以我会从 1 个 epoch 开始。若 train loss 和 eval loss 都继续下降，再尝试增加到 2 到 3 个 epoch；若 train loss 降而 eval loss 回升，就早停。我会每个 epoch 保存 checkpoint，分别跑下游任务指标，选择真实指标最好的版本，而不是简单选择 train loss 最低的版本。

### SFT 的 warmup 和 loss 抖动怎么处理？

回答思路：warmup 只针对训练初期冲击；全程抖动要区分 EBS、学习率和数据噪声。

回答模板：

SFT 常用 `0.03` 到 `0.1` 的 warmup ratio，`0.05` 是常见起点。如果只有前几十步出现 loss spike，我会增加 warmup；如果总步数很少，就改用固定 warmup steps，避免 warmup 占掉太多训练。若全程都抖动，我不会只调 warmup，而会检查有效 batch size 是否太小、学习率是否太大以及数据中是否有异常样本，再一次只改一个变量验证。

### 调参要避免什么误区？

回答思路：点明最大误区是一次改太多参数无法归因，以及只看 train loss——应有明确假设、固定 seed 做对照实验，同时看训练/验证指标、bad case 和资源消耗。

回答模板：

不要一次改太多参数，否则无法归因。每次调参应有明确假设、固定随机种子和对照实验，并同时看训练 loss、验证指标、bad case 和资源消耗。
