# Mixed Precision Training

## 知识点解析

### 概述

**混合精度训练（Mixed Precision Training）** 是大模型开发中的核心技术。它的目标非常明确：**用更少的显存、更快的速度，达到和全精度（FP32）训练几乎一样的模型效果。**

### 什么是混合精度训练？

在传统的深度学习中，所有的权重（Weights）、梯度（Gradients）和激活值（Activations）都使用 **FP32（单精度浮点数，32位）** 存储。

**混合精度训练的做法：**
在计算密集型的步骤（如矩阵乘法）中使用 **16位浮点数（FP16 或 BF16）**，而在需要高精度积累的步骤（如权重更新、损失函数计算）中保留 **FP32**。

**为什么要这么做？**
1.  **显存减半**：16位占用 2 字节，32位占用 4 字节。模型参数和激活值占用空间直接减半。
2.  **算力翻倍**：现代 GPU（如 A100, H100）拥有 **Tensor Cores**，处理 16 位计算的速度比 32 位快数倍（通常是 2-8 倍）。
3.  **带宽优势**：内存带宽压力减小，数据传输更快。

### FP16 vs BF16：核心区别

这是面试和实际工程中最常被问到的问题。虽然它们都是 16 位，但内部结构完全不同。

| 特性 | FP32 (标准) | **FP16 (半精度)** | **BF16 (Brain Float 16)** |
| :--- | :--- | :--- | :--- |
| **符号位 (Sign)** | 1 bit | 1 bit | 1 bit |
| **指数位 (Exponent)** | **8 bits** | 5 bits | **8 bits** |
| **尾数位 (Fraction)** | 23 bits | 10 bits | 7 bits |
| **数值范围 (Range)** | 非常大 | **非常窄** (最高 65504) | **非常大**（指数格式同 FP32，数量级接近） |
| **精度 (Precision)** | 极高 | 高 | 低 |
| **主要痛点** | 慢、占内存 | **容易溢出/下溢（通常配合 Loss Scaling）** | 精度略低 |

#### **FP16 (IEEE 754 标准)**
*   **特点**：为了保证精度，牺牲了指数位（只有 5 位）。
*   **主要限制**：**数值范围较小**。FP16 最小正规正数约为 $6.10 \times 10^{-5}$，但还可用非正规数表示到约 $5.96 \times 10^{-8}$；更小的非零值才会下溢为 0。
*   **常见解决办法**：配合 **Loss Scaling（损失缩放）**，在反向传播前把 Loss 放大，更新前再还原梯度，以降低梯度下溢风险。是否必须使用取决于模型和数值表现。

#### **BF16 (由 Google Brain 开发)**
*   **特点**：**它的设计思路是牺牲精度，换取范围**。它的指数位和 FP32 一模一样（8位），只是砍掉了尾数。
*   **优点**：
    1.  **指数范围与 FP32 相同，动态范围数量级接近**。由于尾数位数不同，两者的最大有限值和最小非正规数并不完全相同。
    2.  **通常不需要 Loss Scaling**。BF16 比 FP16 更少因动态范围不足而溢出或下溢，但仍需验证模型和算子的数值稳定性。
*   **缺点**：尾数精度低于 FP16，量化误差是否可接受要通过具体训练任务验证。

### 为什么现代大模型训练常用 BF16？

在硬件和算子原生支持 BF16 时，大模型训练经常优先评估 **BF16**，原因如下：

1.  **训练稳定性**：BF16 与 FP32 的指数位数相同，比 FP16 更少因动态范围不足导致 `NaN`、`Inf` 或梯度下溢，但不能消除所有数值问题。
2.  **简化工程**：通常不需要 Loss Scaling，代码和状态管理更简单。
3.  **硬件支持**：从 NVIDIA **Ampere 架构（如 A100）** 开始，GPU 对 BF16 提供了原生指令级支持，性能极强。

### 总结与建议

*   **如果你的显卡是 A100, H100, 3090, 4090 或更新的：**
    可优先测试 BF16，但仍应确认具体 GPU、框架和算子的 BF16 支持，并比较吞吐、收敛和最终精度。
*   **如果你的显卡比较老（如 V100, T4, 2080Ti）：**
    这些显卡通常不提供原生 BF16 Tensor Core 路径；做混合精度训练时一般选择 **FP16**，并建议启用动态 Loss Scaling（如 PyTorch AMP 的 `GradScaler` 或 [DeepSpeed](<DeepSpeed.md#deepspeed>) 配置）。
*   **全精度 (FP32) 什么时候用？**
    FP32 仍用于数值敏感算子、稳定性排查、缺少低精度加速的硬件，以及规模允许的训练；混合精度训练也通常保留 FP32 参数或优化器状态用于更新。

**一句话总结：**
**FP16** 像是一个短尺子，量得细但能量的长度有限（容易溢出）；**BF16** 像是一个长尺子，量得粗一点但能拉得非常长（训练更稳）。

**Loss Scaling（损失缩放）** 是 **FP16（半精度浮点数）** 混合精度训练中常用的数值稳定技术，用于降低**梯度下溢（Gradient Underflow）**风险。

简单来说：**它把极小的梯度放大，防止它们在计算过程中变成 0。**

### 为什么需要 Loss Scaling？（核心矛盾）

在深度学习中，梯度的值通常非常小。
*   **FP32（单精度）** 的数值范围非常广，可以表示极其微小的数字（低至 $10^{-38}$）。
*   **FP16（半精度）** 的数值范围非常窄。它能表示的最小正规正数约为 **$6.10 \times 10^{-5}$**，最小非正规正数约为 **$5.96 \times 10^{-8}$**。

**问题来了：**
在训练神经网络时，很多梯度的值会小于 $6.10 \times 10^{-5}$。这些值可能落入精度较低的非正规数区间；低于约 $5.96 \times 10^{-8}$ 时会**下溢（Underflow）**变成 **0**。

### Loss Scaling 的工作原理

Loss Scaling 的思路非常简单粗暴：**既然梯度太小了，那我在反向传播之前把它们集体放大不就行了吗？**

具体步骤如下：

1.  **正向传播：** 正常计算 Loss。
2.  **放大（Scale）：** 在开始反向传播之前，将 Loss 乘以一个很大的因子 $S$（例如 $1024$ 或 $65536$）。
    *   公式：$Loss_{scaled} = Loss \times S$
3.  **反向传播：** 根据链式法则，所有的梯度也会随之放大 $S$ 倍。
    *   原本是 $10^{-6}$ 的梯度，乘以 $1024$ 后变成了大约 $10^{-3}$，这个值在 FP16 的表示范围内，**成功活了下来**。
4.  **缩小（Unscale）：** 在优化器更新参数之前，把这些放大的梯度除以 $S$，还原回真实的大小。
    *   注意：这个还原过程通常是在 **FP32** 的主权重（Master Weights）上操作的，以保证更新的精度。
5.  **更新参数：** 使用还原后的梯度更新模型。

### 动态损失缩放 (Dynamic Loss Scaling)

我们该把 $S$ 设为多大呢？
*   如果 $S$ 太小，梯度依然会下溢。
*   如果 $S$ 太大，梯度会**上溢（Overflow）**变成 `NaN` 或 `Inf`。

因此，现代框架（如 PyTorch AMP, DeepSpeed）都使用**动态缩放**策略：
1.  初始给一个很大的 $S$（比如 $2^{16}$）。
2.  如果在这一步迭代中，梯度出现了 `NaN` 或 `Inf`（溢出了）：
    *   **丢弃**这一步的更新。
    *   把 $S$ 减小（通常减半，比如 $S = S / 2$）。
3.  如果连续很多步（比如 2000 步）训练都很稳定，没有溢出：
    *   尝试把 $S$ 增大（比如 $S = S \times 2$），以更充分地利用 FP16 的范围。

### 总结：什么时候需要它？

*   **使用 FP16 训练时：** 通常建议使用 Loss Scaling，尤其是观察到小梯度下溢或收敛异常时；它与 autocast 是可独立启用的机制。
*   **使用 BF16 训练时：** 通常**不需要** Loss Scaling。
    *   BF16 的指数位和 FP32 一样长，动态范围很大，因此比 FP16 更少遇到下溢，但低于其最小非零值时仍会下溢。
*   **使用 FP32 训练时：** 不需要。

**一句话总结：**
Loss Scaling 是 FP16 的“速效救心丸”，通过**先放大再缩小**的魔法，让微小的梯度在窄小的 FP16 空间里生存下来。

## 面试应对

### Mixed Precision Training 是什么？

回答思路：抓“算力密集步用 16 位、精度敏感步（权重更新/loss）保 FP32”的分工，点出目标是显存减半、Tensor Core 提速，同时逼近 FP32 的效果。

回答模板：

混合精度训练（Mixed Precision Training） 是大模型开发中的核心技术。它的目标非常明确： 用更少的显存、更快的速度，达到和全精度（FP32）训练几乎一样的模型效果。 它的作用通常体现在让更大模型、更长序列或更高吞吐的训练成为可能。

### Mixed Precision Training 的核心机制是什么？

回答思路：从 FP16 与 BF16 的位分布切入——FP16 尾数多但指数只有 5 位、范围窄，通常配合 loss scaling；BF16 指数位同 FP32、范围大，通常不需要 scaling；再讲 FP32 参数或优化器状态如何保留更新精度。

回答模板：

这是面试和实际工程中最常被问到的问题。虽然它们都是 16 位，但内部结构完全不同。在深度学习中，梯度的值通常非常小。FP32（单精度） 的数值范围非常广，可以表示极其微小的数字（低至 $10^{-38}$）。 核心判断是它改变了哪些训练状态的存储、计算或通信方式，以及由此带来的显存和吞吐变化。

### Mixed Precision Training 的工程取舍是什么？

回答思路：按硬件、算子支持和数值表现选型——原生支持 BF16 时优先评估 BF16；旧卡的混合精度路径通常使用 FP16 并建议动态 loss scaling；数值敏感场景保留 FP32。

回答模板：

原生支持 BF16 的硬件上可优先测试 BF16，因为它动态范围大且通常不需要 loss scaling；但仍要验证框架、算子覆盖、吞吐、收敛和最终精度。旧卡的混合精度路径通常使用 FP16，并建议启用动态 loss scaling。数值敏感或排障场景仍可能使用 FP32。训练系统选型还要结合模型规模、GPU 数量、网络带宽、batch size、序列长度、checkpoint 策略和排障成本。
