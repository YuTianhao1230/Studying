# 通信科技与商务词汇

## 知识点解析

### 概述

通信科技英语常描述数据如何传输、服务如何运行、故障如何处理，以及客户如何订购和使用产品。材料可能同时出现技术指标、运维动作和合同条件；理解指标名称之外，还要识别测量对象、时间窗口、上限和例外条款。

capacity、throughput 和 latency 分别侧重容量、实际传输速率和时延，不能都笼统翻译成“网速”。authentication 与 authorization 分别涉及身份核验和权限授予，availability 与 reliability 也描述不同性质。正确选词依赖这些差异以及句子本身的搭配。

| coverage | 覆盖范围 | extend coverage to rural areas |
| connectivity | 连接能力、连通性 | improve connectivity |
| access network | 接入网 | upgrade the access network |
| backbone | 骨干网；支柱 | backbone capacity |
| base station | 基站 | deploy a base station |
| router / switch | 路由器 / 交换机 | replace a faulty router |
| fiber / fibre | 光纤；纤维，美英拼写差异 | fiber-optic links |
| spectrum | 频谱 | spectrum allocation |
| bandwidth | 带宽 | available bandwidth |
| capacity | 容量、承载能力 | increase network capacity |
| throughput | 吞吐率、实际处理或传输速率 | measured throughput |
| latency | 时延 | low-latency applications |
| jitter | 时延变化、抖动 | reduce jitter |
| packet loss | 丢包 | packet-loss rate |

关键区别：

- 在通信物理语境中，bandwidth 可以是以 Hz 计量的频带宽度；在网络服务语境中，也常用来指以 bit/s 描述的传输能力。先看单位，不能把 MHz 与 Mbps 直接等同。
- throughput 是给定条件下实际达到的速率；capacity 通常描述容量上限或承载能力。受拥塞、协议、终端等影响，吞吐率不一定达到标称值。
- latency 是一次传输或交互所需时间；吞吐率提高不必然使每个请求时延下降。
- jitter 关注时延变化，不等于平均时延；packet loss 是未成功送达的数据包比例，不能与误码率直接互换。
- 覆盖扩大说明可接入区域变化，不直接证明每个地点服务质量相同。

backup 与 replication 不等同：实时复制可能把错误或删除同步到副本，不能自动代替可恢复的历史备份。edge computing 描述处理位置接近数据来源或用户的一类方式，不意味着所有运算都必须放在终端，也不自动保证零时延。

availability 关注观察窗口内服务可用程度；reliability 关注在规定条件下持续无故障完成规定功能的能力。快速恢复可能改善可用性，即使故障次数未减少；两者相关但不能简单互换。

| --- | --- | --- |
| authentication | 身份认证 | multi-factor authentication |
| authorization | 授权、权限授予 | authorization to access records |
| encryption | 加密 | encrypt data in transit |
| confidentiality | 保密性、机密性 | protect confidentiality |
| integrity | 完整性 | verify data integrity |
| vulnerability | 漏洞、脆弱性 | patch a vulnerability |
| threat | 威胁 | detect a security threat |
| breach | 违反、泄露或安全突破 | a data breach；breach of contract |
| access control | 访问控制 | enforce access controls |
| credential | 凭据、资格证明 | stolen credentials |
| outage | 服务中断 | an unplanned outage |
| downtime | 停机时间 | scheduled downtime |
| maintenance | 维护 | routine maintenance |
| incident | 事件，运维中常指故障或安全事件 | incident response |
| fault / failure | 故障缺陷 / 失效，具体用法依上下文 | detect a fault；equipment failure |
| alert / alarm | 提醒、告警 | trigger an alert |
| threshold | 阈值 | exceed a threshold |
| monitor | 监测；监视器 | monitor network performance |
| troubleshoot | 排查故障 | troubleshoot a connection problem |
| restore | 恢复 | restore service |

常见动作链可写成 `detect → verify → isolate → mitigate → restore → investigate`，即发现、核实、隔离、缓解、恢复、调查；这只是词义关联，实际事件可能并行处理或采用不同顺序。

`The issue has been mitigated but not resolved.` 表示影响已减轻，但根本问题尚未解决。不能把 mitigated 翻成“彻底修复”。`patch` 是修补动作，不证明从此不存在漏洞。

客户指标也需要口径：churn rate 的分母可能使用期初客户数、平均客户数等；ARPU 通常指每用户平均收入，但用户定义和统计周期由材料确定。题面没有说明时不能擅自选用某公司的定义。

## 题型与解法

### 根据受影响对象选词

| 题面现象 | 优先考虑的词 |
| --- | --- |
| 请求等待时间长 | latency |
| 实际每秒传输的数据少 | throughput |
| 数据包未到达 | packet loss |
| 认证码验证用户身份 | authentication |
| 限制谁可读取某数据 | authorization / access control |
| 故障期间暂时降低影响 | mitigate |
| 套餐外额外计费 | overage charge |

这张表提供定位线索，不代替上下文。同一故障可能影响多个指标，必须看题干问的是哪个现象。

### 商务通知的条件表

阅读升级、维护或合同通知时，分别提取“谁适用、何时生效、哪些费用、哪些例外、需要何种操作”。例如：

`The upgrade is free for existing customers, excluding on-site installation.`

免费对象是现有客户的升级，不包括上门安装。不能仅凭 free 推断所有相关服务都免费。

### 技术数字与单位

- `b` 表示 bit，`B` 表示 byte；理想条件下 8 bit = 1 byte。
- Mbps 与 MB/s 的换算需除以 8；实际传输还受协议开销影响。
- `up to` 表示上限式承诺，`at least` 表示下限，`on average` 表示平均值。
- 若简化定义 $\text{availability} = \frac{\text{总时间}-\text{不可用时间}}{\text{总时间}}$，先确认总窗口和排除项。
- SLA 如排除计划维护，就不能把自然月所有分钟不加区别地作为协议计算口径。

## 易错点与边界

- 技术升级不等于每项指标都改善；材料可能只验证一个指标。
- safety、security 与 privacy 相关但不同；保密性也不是完整安全性的全部。
- restore service 不证明根因已消除；monitor 不表示已经阻止问题。
- unlimited 若同时存在 fair-use policy 等条件，必须连同条款读取。
- billing credit 不自动等于现金退款；free replacement 不自动包含安装费。
- 这些词汇不证明某运营商、岗位一定设英语模块。移动、电信的统一考情尤其缺少足够证据，仍需核对当期通知。

## 笔试自测

以下题目均为原创。技术计算只使用题目说明的简化模型。

### 选择题

#### 1. 时延

Moving the server closer to users reduced the time each request spent travelling across the network. This mainly describes lower ____.

A. revenue；B. coverage；C. latency；D. storage

答案：C。描述的是请求传输所需时间，不是收入、覆盖面积或存储。

#### 2. 身份与权限

Entering a one-time code to prove one's identity is an example of ____.

A. authentication；B. procurement；C. replication；D. billing

答案：A。证明“你是谁”是身份认证；获准访问哪些资源才涉及 authorization。

#### 3. 维护通知

The service will be unavailable from 02:00 to 03:00 for scheduled ____.

A. retention；B. revenue；C. tendering；D. maintenance

答案：D。scheduled maintenance 表示计划维护，与这段不可用窗口对应。

#### 4. 超额费用

Customers who exceed their monthly data allowance may incur an ____.

A. interest payment；B. overage charge；C. access point；D. audit opinion

答案：B。超出套餐额度可能产生 overage charge；may 表示可能，并不说明每次都一定收费。

#### 5. 合同

The supplier must meet the response-time target specified in the ____.

A. SIM card；B. packet header；C. service-level agreement；D. password

答案：C。响应时间等服务承诺可以写入 SLA；其余不是该类合同。

#### 6. 缓解与解决

Traffic was rerouted to ____ the impact of the outage while engineers investigated its cause.

A. mitigate；B. guarantee；C. invoice；D. authenticate

答案：A。改道旨在减轻故障影响，根因仍在调查，不能据此说已永久解决。

#### 7. 供应商选择

Before purchasing the equipment, the company requested a price ____ from three suppliers.

A. latency；B. breach；C. withdrawal；D. quotation

答案：D。price quotation 是价格报价，语境是采购比较。

#### 8. 流失率

The provider lost fewer subscribers this month. Under the same calculation method and denominator, its ____ was lower.

A. storage capacity；B. churn rate；C. packet size；D. spectrum width

答案：B。题目明确计算方法与分母相同，流失人数更少对应更低流失率；如果分母不同，不能仅靠流失人数比较。

### 计算题

#### 9. 理想速率换算

一条链路速率为 80 Mbps，使用十进制单位且忽略协议开销，等于多少 MB/s？

答案：10 MB/s。$80 \div 8 = 10$。这只是单位换算，不保证应用层实测可达该速率。

#### 10. 计费条件

某原创套餐月费 100 元，包含 20 GB；超出部分每 GB 收费 5 元，无其他费用。当月使用 23 GB，总费用是多少？

答案：115 元。超额 3 GB，费用为 $100 + 3 \times 5 = 115$ 元。不能对全部 23 GB 再次收取超额费。

#### 11. 简化可用性

某题规定可用性按完整 30 天计算，计划维护也计入不可用时间，没有任何排除项。99.9% 可用性最多对应多少分钟不可用？

答案：43.20 分钟。总时间 $30 \times 24 \times 60 = 43{,}200$ 分钟；不可用占比 $1-99.9\%=0.1\%$；$43{,}200 \times 0.001 = 43.20$。真实 SLA 必须另看口径。

### 判断题

#### 12. 上限与保证

`Speeds of up to 300 Mbps` 表示任何时候都至少达到 300 Mbps。

答案：错误。up to 是上限式表达，不是 at least 所表示的下限。

#### 13. 备份与副本

只要有实时数据副本，就一定不需要历史备份。

答案：错误。误删除、错误写入等可能同步到副本；是否可恢复到历史状态取决于备份或版本机制。

#### 14. 条款阅读

`The contract renews automatically unless written notice is received ten days before expiry.` 表明自动续约存在通知例外，不能概括成“合同在任何情况下都会自动续约”。

答案：正确。unless 引出例外条件。具体通知方式、截止时点和接收标准仍应按合同定义，而非自行补充。

## 答案速查与关联

选择题：1C、2A、3D、4B、5C、6A、7D、8B。第 9 题 10 MB/s；第 10 题 115 元；第 11 题 43.20 分钟；12 错、13 错、14 对。

词汇记录宜包含“指标对象 + 单位 + 搭配”，合同记录宜包含“适用人群 + 费用 + 例外”。句子条件见[词汇语法与选词填空](词汇语法与选词填空.md#词汇语法与选词填空)，商务多文本练习见[阅读理解与长难句](阅读理解与长难句.md#阅读理解与长难句)，相关公开证据见[英语题源与案例](英语题源与案例.md#英语题源与案例)。

## 面试应对

### 常考点及考法

常通过技术说明、维护通知和服务合同考查带宽、时延、可用性、安全、备份与 SLA，回答要明确指标对象、单位和条件。

### 1. 带宽、吞吐量和时延有什么区别？

**回答思路：** 分别从理论传输能力、实际传输速率和单次传输耗时定义，并说明三者不能互相替代。

**回答模板：** “带宽描述链路的理论传输能力，吞吐量是考虑协议开销、拥塞和设备性能后实际达到的数据速率，时延则表示数据从一端到另一端所需的时间。高带宽不必然意味着低时延，标称 80 Mbps 也不能直接承诺应用层始终达到 10 MB/s。”

### 2. 怎样解读 SLA 中的可用性和 `up to`？

**回答思路：** 先区分承诺指标与上限宣传，再核对统计周期、排除项、测量点和补偿条件。

**回答模板：** “SLA 的可用性必须结合统计周期、故障起止口径、计划维护是否排除以及补偿规则理解。`Up to 300 Mbps` 只是上限式表述，不等于最低保证值；真正的服务承诺要看是否写明 `at least`、测量位置和适用条件。因此我不会只凭一个百分比或峰值判断服务质量。”

### 3. 数据副本、备份和灾难恢复有什么区别？

**回答思路：** 从高可用、历史恢复和业务恢复目标三个层面说明用途及相互补充关系。

**回答模板：** “实时副本主要提高可用性，但错误写入或误删除也可能同步；备份保留历史版本，用于恢复到过去状态；灾难恢复则关注发生严重故障后，如何在目标恢复时间和数据丢失范围内恢复业务。三者解决的问题不同，需要结合 RTO、RPO、演练和恢复验证形成完整方案。”

### 面试易错点

- 把 Mbps 与 MB/s 直接按相同数值换算。
- 把峰值、平均值、最低保障和实际上限混为一谈。
- 认为有实时副本就不再需要备份和恢复演练。
