# 搜索系统基础

## 知识点解析

### 概述

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。

### 典型链路

```text
Query 输入
  -> Query 理解
  -> 召回 / 粗排 / 精排 / 重排
  -> 展示
  -> 点击 / 转化反馈
```

四个筛选阶段的定义、模型、目标与权衡统一见[召回、粗排、精排与重排](<召回粗排精排重排.md>)。搜索页只说明搜索业务在 Query、库存、反馈和延迟上的差异。

### Query 理解

搜索通常有用户主动输入的显式 Query，但 Query 往往很短，可能包含歧义、错别字、实体别名、时间或地域限制。Query 理解的目标是恢复检索意图，同时避免改写偏离原始约束。

常见任务：

- 分词。
- 拼写纠错。
- 同义词扩展。
- 意图识别。
- 实体识别。
- Query 改写。
- 多轮上下文理解。

在 AI 搜索中，还会出现：

- 任务拆解。
- 子问题生成。
- 边想边搜。
- Deep Research。
- 搜索结果归纳和引用。

Query 改写不是越丰富越好：专有名词、型号、错误码和引号短语通常要求保留词面约束；多跳问题可以拆成子问题，但最终答案仍要回到原问题并绑定证据。

### 可检索库存与索引

搜索库存通常是网页、文档、商品或服务的可检索快照，质量不仅取决于内容是否存在，还取决于是否被抓取、解析、建索引并及时更新。

需要明确的边界：

- 索引覆盖：未入库或解析失败的内容无法被后续排序补回。
- 新鲜度：新闻、价格、库存和政策类内容需要增量更新与过期淘汰。
- 权限：企业搜索必须在召回前或召回中执行访问控制，不能仅靠展示层隐藏。
- 字段结构：标题、正文、实体、时间和站点质量等字段影响可检索性。
- 精确匹配：型号、错误码和专名对倒排索引仍有不可替代的价值。

### 反馈与偏差

搜索反馈来自点击、停留、满意点击、Query 改写、返回结果页和任务完成等行为。点击不是无偏相关性标签：

- 排名靠前的结果天然更容易被点击，存在位置偏差。
- 标题或摘要吸引点击，不代表落地页真正满足需求。
- 零结果和改写记录能暴露词典、索引覆盖或意图理解问题。
- 长尾 Query 反馈稀疏，需要人工相关性标注、规则样本或跨 Query 泛化。
- AI 搜索还要检查答案是否被检索证据支持，不能只看结果点击。

### 延迟边界

搜索是强交互请求，Query 到结果的尾延迟会直接影响改写、退出和点击。延迟预算需要覆盖 Query 理解、多路检索、排序、摘要生成和网络开销；复杂模型只适合逐层缩小后的候选。AI 搜索可以通过流式返回、检索与生成并行、缓存和超时降级控制等待，但不能用缓存旧答案掩盖库存时效问题。

### LLM 对搜索的影响

LLM 让搜索从“找页面”走向“完成任务”：

- Query 改写更强。
- 能进行多跳检索。
- 能综合多来源信息。
- 能生成摘要和答案。
- 能通过 Agentic Search 主动拆解问题。

但也带来新问题：

- 幻觉。
- 引用不可靠。
- 延迟变高。
- 成本增加。
- 搜索结果和生成答案难以对齐。

### 常见指标

指标定义、计算边界、线上线下差异和 A/B 解释统一见[排序指标与 A/B 测试](<排序指标与A_B测试.md>)。搜索场景通常组合使用：

- 离线检索与排序：Recall@K、Precision@K、NDCG、MRR。
- 在线行为：CTR、SAT Click、Zero-result Rate、Reformulation Rate、任务完成率。
- 生成式搜索：Answer Faithfulness、引用支持率、不可回答覆盖率。
- 系统护栏：p95/p99 延迟、错误率、单请求成本。

## 面试应对

### 1. 为什么搜索系统不能只依赖更强的排序模型？

回答思路：围绕 Query 约束、索引覆盖、反馈偏差和在线延迟解释，阶段职责直接引用通用链路。

完整回答模板：

更强的排序模型只能比较上游留下的候选，无法补回未抓取、未解析、未建索引或被错误 Query 改写漏掉的内容。搜索还要保留型号、错误码、时间和权限等硬约束，处理位置与摘要造成的点击偏差，并满足交互式尾延迟。因而我会先保证 Query 理解和库存索引正确，再按通用分层分配计算预算，最后结合满意点击、改写和任务完成反馈验证；不能把模型变大当成索引覆盖和业务约束的替代品。

### 2. 搜索系统和推荐系统的核心差异是什么？

回答思路：从显式 Query、可检索库存、反馈语义和交互延迟四方面回答，不重复背诵通用排序链路。

完整回答模板：

搜索通常从用户主动输入的显式 Query 出发，需要先处理歧义、实体、纠错和硬约束；推荐更多从用户与会话历史推断潜在兴趣。搜索库存强调抓取、解析、索引覆盖和时效，未入索引的内容无法被后续模型补回。搜索点击还受位置和摘要吸引力影响，Query 改写、零结果和满意点击比普通点击更能说明检索问题。延迟上，搜索每次 Query 都要在线检索，长尾 Query 又难以完全缓存，因此需要在相关性、索引新鲜度和尾延迟间权衡。

### 3. 如何评估搜索系统，并定位零结果或相关性差的问题？

回答思路：按 Query 理解、召回、排序、展示四层定位，分别选择覆盖、排序和用户满意度指标，避免只看 CTR。

完整回答模板：

我会先按链路定位问题。零结果先检查分词、纠错、过滤条件、索引覆盖和召回源是否命中；有结果但不相关，再检查 Query 意图、相关性标注、排序特征和规则。离线按头部、长尾、实体类和时效类 Query 分桶查看 Recall@K、Precision@K、MRR 和 NDCG，线上组合观察 Zero-result Rate、Reformulation Rate、SAT Click 与任务完成情况。指标口径使用统一排序指标定义；搜索侧的关键边界是 CTR 会受位置和标题影响，不能单独代表满意度。

### 4. LLM 或生成式答案接入搜索后带来什么价值和失败边界？

回答思路：先讲 Query 改写、多跳检索和答案综合，再从证据约束、时效、延迟、成本及不可回答场景说明边界。

完整回答模板：

LLM 可以用于 Query 改写、意图补全、任务拆解、多跳检索、结果摘要和基于证据的答案生成，使搜索从返回链接扩展到帮助用户完成任务。但生成能力不能替代检索事实：模型可能忽略证据、错误归因、生成不存在的引用，或在时效性和长尾知识上给出过度确定的答案。工程上应让答案绑定可追溯文档，检查引用是否支持具体结论，对高风险或证据不足的问题允许拒答，并同时评估检索相关性、答案正确性、faithfulness、覆盖率、延迟和成本。若检索阶段漏掉关键证据，单靠更强生成模型通常无法可靠补救。
