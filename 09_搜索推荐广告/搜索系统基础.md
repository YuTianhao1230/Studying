# 搜索系统基础

## 知识点解析

### 概述

搜索系统是根据用户 Query，从海量文档、商品、视频或服务中找到相关结果，并按相关性、质量和业务目标排序展示的系统。

### 典型链路

```text
Query 输入
  -> Query 理解
  -> 召回
  -> 粗排
  -> 精排
  -> 重排
  -> 展示
  -> 点击 / 转化反馈
```

### Query 理解

目标是理解用户到底想要什么。

常见任务：

- 分词。
- 拼写纠错。
- 同义词扩展。
- 意图识别。
- 实体识别。
- Query 改写。
- 多轮上下文理解。

在 AI 搜索中，还会出现：

- 任务拆解。
- 子问题生成。
- 边想边搜。
- Deep Research。
- 搜索结果归纳和引用。

### 召回

[召回](<召回粗排精排重排.md>)负责从海量候选中快速找出可能相关的结果。

常见方式：

- 关键词召回：BM25、倒排索引。
- 向量召回：Embedding + ANN。
- 图召回：基于用户、内容、关系图。
- 规则召回：运营规则、业务强约束。
- 多路召回：多个召回源合并。

### 排序

排序负责判断候选结果的相关性和价值。

常见特征：

- Query 特征。
- 文档 / 商品 / 视频特征。
- 用户画像。
- 行为历史。
- 上下文特征。
- 交叉特征。

常见模型：

- Learning to Rank。
- Cross-Encoder。
- Two-Tower + Reranker。
- [Transformer](<../02_大模型/基础架构/Transformer.md>) 排序模型。
- LLM Reranker。

### 重排

重排不仅看单个结果分数，还要优化列表整体体验。

关注：

- 多样性。
- 去重。
- 新鲜度。
- 安全过滤。
- 商业规则。
- 探索与利用。

### LLM 对搜索的影响

LLM 让搜索从“找页面”走向“完成任务”：

- Query 改写更强。
- 能进行多跳检索。
- 能综合多来源信息。
- 能生成摘要和答案。
- 能通过 Agentic Search 主动拆解问题。

但也带来新问题：

- 幻觉。
- 引用不可靠。
- 延迟变高。
- 成本增加。
- 搜索结果和生成答案难以对齐。

### 常见指标

- Recall@K。
- Precision@K。
- NDCG。
- MRR。
- CTR。
- SAT Click。
- Zero-result Rate。
- Reformulation Rate。
- Answer Faithfulness。

## 面试应对

### 1. 搜索系统为什么要经过 Query 理解、召回、排序和重排？

回答思路：围绕用户主动表达的 Query 串起链路，分别说明每一层解决的搜索特有问题。

完整回答模板：

搜索系统要把用户的短 Query 转成可检索意图，再从海量文档中返回相关且可用的结果。Query 理解负责分词、纠错、实体和意图识别、同义词扩展或改写；召回用倒排索引、BM25、向量 ANN 等方法快速找全候选；粗排和精排综合文本相关性、内容质量、时效性及必要的上下文信号精确打分；重排再处理去重、多样性、安全和业务约束。分层的原因是全库检索强调覆盖与效率，而后续排序强调精度与列表体验，两者的计算预算不同。

### 2. 关键词召回和向量召回有什么区别，为什么通常要混合使用？

回答思路：比较精确匹配、语义泛化、可解释性和计算特征，再说明多路召回合并后的去重与统一排序。

完整回答模板：

关键词召回依赖倒排索引和 BM25 等词项匹配，对专有名词、型号、精确短语和强约束 Query 较可靠，也容易解释，但对同义改写和语义表达差异不敏感。向量召回把 Query 与文档映射到同一表示空间，能覆盖语义相近但词面不同的结果，不过可能召回语义泛化过度的候选，且 ANN 存在近似检索误差。实际系统常并行使用多路召回，对候选去重并做分数校准或交给统一排序模型，从而兼顾词面精确性和语义召回率；不能把向量相似度直接等同于最终相关性。

### 3. 如何评估搜索系统，并定位零结果或相关性差的问题？

回答思路：按 Query 理解、召回、排序、展示四层定位，分别选择覆盖、排序和用户满意度指标，避免只看 CTR。

完整回答模板：

我会先按链路定位问题。零结果先检查分词、纠错、过滤条件、索引覆盖和多路召回命中率；有结果但不相关，再检查 Query 意图、召回来源、相关性标注、排序特征和重排规则。离线用 Recall@K 判断目标结果是否进入候选，用 Precision@K、MRR、NDCG 判断前排质量，并按头部、长尾、实体类和时效类 Query 分桶。线上还要结合 Zero-result Rate、Reformulation Rate、SAT Click 和任务完成情况，因为 CTR 会受标题吸引力和位置影响，不能单独代表搜索满意度。

### 4. LLM 或生成式答案接入搜索后带来什么价值和失败边界？

回答思路：先讲 Query 改写、多跳检索和答案综合，再从证据约束、时效、延迟、成本及不可回答场景说明边界。

完整回答模板：

LLM 可以用于 Query 改写、意图补全、任务拆解、多跳检索、结果摘要和基于证据的答案生成，使搜索从返回链接扩展到帮助用户完成任务。但生成能力不能替代检索事实：模型可能忽略证据、错误归因、生成不存在的引用，或在时效性和长尾知识上给出过度确定的答案。工程上应让答案绑定可追溯文档，检查引用是否支持具体结论，对高风险或证据不足的问题允许拒答，并同时评估检索相关性、答案正确性、faithfulness、覆盖率、延迟和成本。若检索阶段漏掉关键证据，单靠更强生成模型通常无法可靠补救。
