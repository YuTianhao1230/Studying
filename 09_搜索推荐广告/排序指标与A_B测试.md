# 排序指标与A_B测试

## 知识点解析

### 概述

排序指标衡量模型离线排序能力，A/B 测试衡量算法改动在线上真实用户中的业务效果。算法工程师需要同时理解二者，并能解释它们不一致的原因。

### 离线排序指标

#### AUC

AUC 衡量随机正样本得分高于随机负样本的概率，同分计半。设正、负样本分数分别为 $s_i^+$、$s_j^-$：

$$
\mathrm{AUC}
=
\frac{1}{n_+n_-}
\sum_{i=1}^{n_+}\sum_{j=1}^{n_-}
\left[
\mathbb{I}(s_i^+>s_j^-)
+\frac{1}{2}\mathbb{I}(s_i^+=s_j^-)
\right]
$$

适合：

- 二分类排序。
- CTR/CVR 预估。
- 阈值不固定的排序问题。

局限：

- 不直接反映 Top-K 体验。
- 对用户粒度差异不敏感。
- 类别极不平衡时可能误导。
- 只关心分数顺序，无法说明概率是否校准。
- 分组内只有正类或只有负类时 AUC 未定义，不能强行记为 0 或 1。

#### GAUC

GAUC 是在用户、请求或其他业务 group 内计算 AUC，再对有效分组加权：

$$
\mathrm{GAUC}
=
\frac{\sum_{g\in G_{\mathrm{valid}}}w_g\mathrm{AUC}_g}
{\sum_{g\in G_{\mathrm{valid}}}w_g}
$$

其中 $G_{\mathrm{valid}}$ 只包含同时有正、负样本的分组。$w_g$ 可以是样本数、曝光数、正负样本对数或等组权重，选择不同权重回答的是不同问题，必须随结果报告；还要报告被排除分组的数量和流量占比，避免只在少量活跃用户上得到漂亮结果。

更适合推荐/广告，因为排序通常发生在同一个用户或同一个请求内部。

#### NDCG

NDCG 衡量 Top-K 中高相关结果是否出现在更靠前的位置，适合多级相关性标签。常见指数增益定义为：

$$
\mathrm{DCG@K}
=
\sum_{i=1}^{K}\frac{2^{rel_i}-1}{\log_2(i+1)},
\qquad
\mathrm{NDCG@K}
=
\frac{\mathrm{DCG@K}}{\mathrm{IDCG@K}}
$$

$rel_i$ 是第 $i$ 位结果的相关性等级，IDCG 是同一候选标签按理想顺序得到的 DCG。也可以使用线性增益 $rel_i$，但不同实现不能混报。若某个 Query 的 $\mathrm{IDCG@K}=0$，NDCG 无法按该式计算，应预先约定跳过还是记 0，并报告有效 Query 比例。

适合：

- 搜索排序。
- 推荐列表。
- 多级相关性标签。

#### MRR

MRR 关注每个 Query 的第一个相关结果出现得多靠前：

$$
\mathrm{MRR}
=
\frac{1}{|Q|}
\sum_{q\in Q}\frac{1}{\mathrm{rank}_q}
$$

$\mathrm{rank}_q$ 是第一个相关结果的名次；若评估列表截断到 Top-K，且 Top-K 内没有相关结果，该 Query 的倒数排名通常记为 0。MRR 只看第一个相关结果，不反映其后结果的质量。

适合：

- 问答检索。
- 搜索首条结果质量。
- 工具或文档检索。

#### Recall@K

Recall@K 衡量 Top-K 覆盖了多少已知相关结果。设 Query $q$ 的相关集合为 $R_q$，前 K 个结果为 $P_q^K$：

$$
\mathrm{Recall@K}_q
=
\frac{|R_q\cap P_q^K|}{|R_q|}
$$

当 $|R_q|=0$ 时该 Query 的 Recall@K 未定义，需要约定过滤或单独统计。它与 Hit Rate@K 不同：Hit Rate 只判断 Top-K 是否至少命中一个相关结果，Recall@K 关心相关集合被覆盖的比例。

适合：

- [召回](<召回粗排精排重排.md>)阶段。
- 向量检索。
- [RAG](<../02_大模型/应用与问题/RAG.md>) 文档召回。

### 指标与阶段的对应

| 问题 | 优先指标 | 不能单独回答的问题 |
| --- | --- | --- |
| 正负样本能否正确区分 | AUC、GAUC | Top-K 展示质量、概率校准 |
| 高相关结果是否排在前面 | NDCG@K | 全库相关结果是否被召回 |
| 第一个正确结果是否足够靠前 | MRR | 第二个及以后结果的质量 |
| 正确候选是否进入候选集 | Recall@K、Hit Rate@K | 候选内部顺序和线上业务收益 |

同一任务还要固定候选集合、标签定义、K 值、分组权重和宏/微平均方式。AP、PR-AUC、置信区间和统计显著性见[指标与统计计算](<../04_评测实验与数据质量/指标与统计计算.md>)。

### 线上业务指标

线上指标按业务目标选择，不能把某个离线排序指标直接改名为业务收益。常见组合包括：

- CTR：点击率。
- CVR：转化率。
- GMV：成交额。
- Watch Time：观看时长。
- Retention：留存。
- User Satisfaction：满意度。
- Bad Case Rate：坏例率。
- Latency：延迟。
- Crash / Error Rate：稳定性。

搜索、推荐和广告的具体指标组合分别见[搜索系统基础](<搜索系统基础.md>)、[推荐系统基础](<推荐系统基础.md>)和[广告排序与 CTR 预估](<广告排序与CTR预估.md>)。

### A/B 测试基本流程

```text
提出假设
  -> 选择实验指标
  -> 设计实验分桶
  -> 计算样本量和实验周期
  -> 灰度上线
  -> 监控护栏指标
  -> 统计显著性分析
  -> 决策放量 / 回滚 / 继续实验
```

### 核心概念

#### 实验假设

不要只说“新模型更好”，而要说清楚：

```text
新模型通过提升 Query-Item 匹配能力，使 CTR 提升，同时不显著伤害延迟和转化。
```

实验前应固定随机化单位、目标人群、主指标、护栏指标、最小可检测效果（MDE）、显著性水平、功效、实验周期和停止规则。先看数据质量与实验设计是否可信，再解释指标涨跌。

#### 主指标和护栏指标

- 主指标：用于判断实验是否成功。
- 护栏指标：用于防止副作用。

例如推荐系统：

- 主指标：CTR、Watch Time、GMV。
- 护栏指标：负反馈率、延迟、投诉率、内容安全。

主指标应尽量唯一或有预先声明的层级检验顺序。大量切片和指标同时检验会抬高假阳性，需要做多重比较控制或把探索性结果明确标注为探索。

#### 显著性

线上指标存在随机波动，需要判断提升是否可信。p-value 是在零假设及统计模型成立时，观察到当前或更极端统计量的概率，不是“新模型无效的概率”。显著性不等于业务收益足够大，还需看效果量及区间。

按用户随机分桶时，不能把同一用户多次曝光当独立样本。应按用户聚合或使用匹配随机化单位的方差估计；样本量由基准转化率、最小可检测效果、显著性水平和功效共同决定。计算与配对/分组重采样见[指标与统计计算](<../04_评测实验与数据质量/指标与统计计算.md>)。

常见关注：

- p-value。
- 置信区间。
- 最小样本量。
- 实验周期。
- 新奇效应。

结果解释顺序：

1. 先检查埋点、分桶、SRM、样本污染和护栏异常。
2. 再报告绝对变化、相对变化、置信区间和 p-value，不能只报“显著”。
3. 判断区间是否排除 0，以及是否达到预先约定的最小业务收益。
4. 检查结论是否跨核心人群和时间稳定，区分预设切片与事后切片。
5. 结合延迟、成本、长期效应和回滚风险决定放量，而不是把统计显著直接等同于上线。

#### SRM

SRM，Sample Ratio Mismatch，表示实验分桶比例异常。

如果 AB 组流量比例明显不符合预期，实验结果不可信。

### 离线涨、线上不涨的常见原因

| 差异来源 | 典型表现 | 检查方式 |
| --- | --- | --- |
| 目标不一致 | AUC 上升但 Top-K 或业务收益不变 | 同时检查 NDCG/Recall@K、主指标和护栏 |
| 数据分布变化 | 离线测试集受益，线上长尾或新人群不受益 | 时间外验证、线上分桶和人群切片 |
| 选择/位置偏差 | 只在旧策略曝光样本上变好 | 随机流量、位置建模、倾向校正 |
| 训练-serving skew | 离线特征或模型版本与线上不一致 | 特征回放、版本与数值一致性检查 |
| 概率校准变化 | 排序大致正确但阈值、出价或融合失真 | 分桶校准曲线与场景切片 |
| 下游策略覆盖 | 模型收益被规则、重排或库存资格截断 | 分阶段漏斗和策略命中率 |
| 系统代价 | 延迟、错误或成本抵消效果收益 | p95/p99、超时降级和资源指标 |
| 实验设计问题 | 周期短、SRM、功效不足或反复偷看 | A/A、样本量、停止规则与 SRM 检查 |
| 异质性与长期效应 | 收益集中在少数人群，长期留存下降 | 预设分群、延长观察和 holdout |

### 面试回答框架

如果被问“离线 AUC 涨了但线上 CTR 没涨怎么办”，可以这样回答：

```text
我会先确认实验本身是否可信，比如分桶、样本量、SRM、实验周期。
然后检查链路一致性，比如训练-serving skew、特征缺失、模型版本和策略覆盖。
接着分析指标匹配问题，AUC 提升是否发生在真正影响 Top-K 展示的位置。
最后做分群和 bad case 分析，看收益是否只集中在部分用户或场景，并决定继续迭代、缩小流量或回滚。
```

## 面试应对

### 排序指标与A_B测试 解决什么业务问题？

回答思路：讲清楚离线排序指标衡量模型排序能力、A/B 测试衡量改动在真实用户上的业务效果，二者分别对应上线前评估和上线后验证。

回答模板：

离线指标帮助筛选模型，线上 A/B 用随机分桶估计实际业务收益。CTR 模型可以先看 AUC、GAUC 和校准，搜索列表重点看 NDCG；上线后再看点击、转化和留存，同时检查延迟与负反馈护栏。离线排序提升并不自动意味着线上收益，必须检查数据分布、展示位置和策略链路是否一致。

### 排序指标与A_B测试 的核心机制是什么？

回答思路：一边说离线指标各自适用场景（AUC/GAUC 看整体与分组排序、NDCG/MRR/Recall@K 看 Top-K 与召回），一边讲 A/B 的假设-分桶-显著性-护栏指标流程。

回答模板：

AUC 比较正负样本的分数顺序，同分计半；GAUC 在用户或请求内比较再加权；NDCG 对靠前位置的高相关结果给更高权重。A/B 测试则先固定实验假设、主指标、护栏、随机化单位和样本量，再分桶运行并检查 SRM，最后结合效果量、置信区间和业务成本决定是否放量。

### 排序指标与A_B测试 的常见风险是什么？

回答思路：聚焦“离线涨线上不涨”的成因——分布不一致、训练-serving skew、指标没覆盖真实目标、位置偏差、SRM 及实验周期太短等实验可信度问题。

回答模板：

我先排除 SRM、样本量不足和实验周期问题，再查特征、模型版本、训练与服务链路是否一致。如果实验可信，就判断 AUC 收益是否发生在实际展示的 Top-K，以及延迟、策略覆盖或校准变化是否抵消收益。统计上避免将重复曝光当独立样本，也不能每天重复检验直到显著；应按预先约定的停止规则和多重比较方案判断。

易错点：把 AUC 当准确率；不说明 GAUC 权重；把 p-value 当零假设为真的概率；将统计显著等同于值得上线；忽略分桶单位和用户间干扰。
