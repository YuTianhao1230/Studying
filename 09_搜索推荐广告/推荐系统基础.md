# 推荐系统基础

## 知识点解析

### 概述

推荐系统是根据用户、物品、上下文和历史行为，预测用户可能感兴趣内容并排序展示的系统。

### 典型链路

```text
用户请求
  -> 候选召回 / 粗排 / 精排 / 重排
  -> 规则过滤
  -> 展示
  -> 用户反馈
  -> 样本构造
  -> 模型训练
```

召回、粗排、精排和重排的统一定义、模型分工与效果/延迟权衡见[召回、粗排、精排与重排](<召回粗排精排重排.md>)。推荐页只说明推荐业务在 Query/意图、库存、反馈和延迟上的差异。

### Query 与用户意图

推荐通常没有用户当次主动输入的显式 Query，需要从用户画像、长期历史、当前会话、入口和时间地点等上下文推断潜在兴趣。这里的“Query”更接近一个随会话变化的用户状态表示，而不是固定关键词。

推荐意图具有多兴趣和时变性：

- 长期偏好与当前会话意图可能冲突。
- 点击、收藏、购买和跳过代表的兴趣强度不同。
- 连续消费可能表示喜欢，也可能只是位置和自动播放造成。
- 只拟合短期点击容易形成信息茧房，需要保留探索和多样性。

协同过滤、双塔、序列模型及精排特征交叉模型的阶段定位统一见链路权威页，本页不再按阶段重复定义。

### 动态库存与冷启动

推荐物品池可能达到百万到亿级，并持续发生上架、下架、过期和质量变化。进入排序前要先满足可用性、地域、版权、库存和安全等资格约束。

新用户或新物品缺少历史行为时，纯协同信号不足。常见处理包括：

- 使用文本、图像、类目等内容特征。
- 通过热门、规则或相似人群提供兜底。
- 给新物品受控探索流量，采集首批反馈。
- 区分“没有反馈”和“明确负反馈”，避免把未曝光当作不喜欢。

库存侧的关键权衡是新鲜度与稳定性：过度依赖历史热度会压制新内容，探索过多又会损害当期体验。

### 反馈闭环与曝光偏差

推荐主要依赖点击、停留、完播、收藏、购买、跳过、不感兴趣和留存等隐式反馈。反馈同时受到旧策略影响，日志不是“用户对全量物品的真实偏好”：

- 只有被展示的物品才有机会产生反馈，存在曝光选择偏差。
- 展示位置、封面和自动播放会影响行为，点击不等于长期满意。
- 转化和留存可能延迟发生，过早截断标签会制造假负例。
- 训练新策略后候选分布会改变，离线回放不能完全模拟策略反馈环。

可以保留随机/探索流量，记录曝光与位置，使用倾向校正或反事实评估，并按用户和时间切分数据。探索本身有体验成本，需要设置流量、质量和安全约束。

### 延迟与特征新鲜度

推荐 Feed 往往是高 QPS 请求，需要在较低尾延迟内完成多路候选合并、特征读取、排序和重排。用户兴趣又会快速变化，因此不能只依赖长期缓存。

常见工程权衡：

- 物品向量和稳定特征可离线预计算，最近行为与库存状态在线更新。
- 缓存可降低延迟，但要定义失效条件，避免推荐已下架或已消费内容。
- 精排复杂度随候选量增长，应同时监控各层耗时和正例保留率。
- 超时降级可以回退到轻量模型或合格热门集，但仍必须执行资格与安全过滤。

### 大模型对推荐的影响

LLM/VLM 正在进入推荐链路：

- 商品和内容理解。
- Query / 用户意图理解。
- 多模态特征增强。
- 生成式推荐理由。
- Agentic Reasoning，用工具和中间推理缩小候选空间。

但推荐系统仍然要面对线上约束：

- 低延迟。
- 高吞吐。
- 成本可控。
- 可解释和可监控。
- A/B 实验验证。

### 常见指标

指标定义、计算边界、线上线下差异和 A/B 解释统一见[排序指标与 A/B 测试](<排序指标与A_B测试.md>)。推荐场景通常组合使用：

- 离线召回与排序：Recall@K、AUC/GAUC、NDCG、MRR。
- 短期在线目标：CTR、CVR、GMV、Watch Time。
- 长期目标：Retention、用户活跃、负反馈率、内容生态指标。
- 系统护栏：p95/p99 延迟、错误率、内容安全与单请求成本。

## 面试应对

### 1. 推荐链路相对通用分层有哪些业务差异？

回答思路：不重复定义四阶段，围绕无显式 Query、动态库存、反馈闭环和高 QPS 延迟回答。

完整回答模板：

推荐沿用召回、粗排、精排和重排的通用分层，但通常没有显式 Query，需要从长期历史和当前会话推断多兴趣。物品池动态变化，候选先要满足库存、版权、地域和安全资格；反馈只来自旧策略展示过的物品，存在曝光与位置偏差，还要兼顾延迟转化和长期留存。服务侧通常是高 QPS、低尾延迟，因此会预计算稳定特征、在线更新近期行为，并为缓存和降级设置新鲜度及资格边界。

### 2. 没有显式 Query 时，推荐系统如何表示用户意图？

回答思路：区分长期偏好与会话意图，说明行为语义、时序和多兴趣边界。

完整回答模板：

推荐里的 Query 可以理解为当前用户状态。长期画像提供稳定偏好，最近点击、搜索、停留和跳过反映会话意图，入口、时间和设备提供上下文。建模时要区分不同行为强度和时间衰减，并保留多个兴趣方向，不能把全部历史压成单一静态偏好。模型的阶段分工使用统一链路定义；推荐侧额外关注的是状态是否足够新鲜、是否被位置和旧策略污染，以及短期兴趣是否挤掉长期价值。

### 3. 推荐系统如何处理冷启动和曝光偏差？

回答思路：先区分两类问题，再分别给出内容特征/探索兜底与随机流量/倾向校正等方案，说明二者不能混为一谈。

完整回答模板：

冷启动是新用户或新物品缺少历史交互，常用内容和多模态特征、注册信息、热门或规则召回、相似人群以及受控探索来建立初始信号。曝光偏差则是训练数据只包含系统曾展示过的候选，未曝光不等于用户不喜欢，直接学习点击日志会强化旧策略。处理时可以保留随机或探索流量，记录曝光与位置，使用倾向得分校正或反事实方法，并对探索成本设置约束。两者都需要探索，但冷启动关注信息不足，曝光偏差关注观测机制有偏，评估和修正方式不同。

### 4. 推荐系统应如何验证短期收益和长期体验？

回答思路：指标定义和 A/B 口径链接权威页，本页只讲推荐的多目标、反馈环和长期边界。

完整回答模板：

我会先按统一口径检查 Recall@K、AUC/GAUC、NDCG 等离线指标和特征一致性，再通过用户级随机 A/B 验证预先声明的主指标。推荐不能只看 CTR，还要同时观察 CVR、时长、留存、负反馈、多样性和延迟护栏，并给延迟转化及新奇效应足够观察窗口。由于新策略会改变曝光和后续训练数据，还要分新老用户、头尾内容与长期周期复查，避免短期点击提升以透支用户体验或内容生态为代价。
