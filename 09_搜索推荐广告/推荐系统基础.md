# 推荐系统基础

## 知识点解析

### 概述

推荐系统是根据用户、物品、上下文和历史行为，预测用户可能感兴趣内容并排序展示的系统。

### 典型链路

```text
用户请求
  -> 候选召回
  -> 粗排
  -> 精排
  -> 重排
  -> 规则过滤
  -> 展示
  -> 用户反馈
  -> 样本构造
  -> 模型训练
```

### 为什么要分层

线上候选物品可能有百万到亿级，不可能对所有物品都用复杂模型[精排](<召回粗排精排重排.md>)。

分层目标：

- 召回：尽可能找全相关候选。
- 粗排：快速过滤明显不相关候选。
- 精排：用更复杂模型精细预测。
- 重排：兼顾多样性、业务规则、体验约束。

### 常见模型

#### 协同过滤

根据用户-物品交互矩阵找相似用户或相似物品。

优点：

- 简单。
- 可解释。
- 不依赖复杂内容特征。

缺点：

- 冷启动困难。
- 稀疏矩阵效果差。

#### Two-Tower

用户塔和物品塔分别编码，最后用向量相似度匹配。

适合：

- 大规模召回。
- 向量检索。
- 用户和物品特征丰富的场景。

#### Wide & Deep / DeepFM / DCN

结合记忆能力和泛化能力，常用于 CTR/CVR 预估。

关注点：

- 稀疏特征 embedding。
- 特征交叉。
- 多目标学习。

#### 序列推荐

建模用户行为序列，例如点击、收藏、购买、停留。

常见方向：

- DIN / DIEN。
- Transformer-based RecSys。
- 生成式推荐。

### 大模型对推荐的影响

LLM/VLM 正在进入推荐链路：

- 商品和内容理解。
- Query / 用户意图理解。
- 多模态特征增强。
- 生成式推荐理由。
- Agentic Reasoning，用工具和中间推理缩小候选空间。

但推荐系统仍然要面对线上约束：

- 低延迟。
- 高吞吐。
- 成本可控。
- 可解释和可监控。
- A/B 实验验证。

### 常见指标

- CTR：点击率。
- CVR：转化率。
- GMV：成交金额。
- Watch Time：观看时长。
- Retention：留存。
- AUC / GAUC：排序能力。
- NDCG / MRR / Recall@K：排序和召回效果。

### 常见问题

#### 冷启动

新用户或新物品缺少历史行为。

解决：

- 内容特征。
- 热门兜底。
- 探索流量。
- 多模态理解。
- 规则召回。

#### 曝光偏差

模型只看到被展示过的样本，没展示的物品没有反馈。

解决：

- 探索策略。
- IPS / debias。
- 随机桶数据。
- 反事实评估。

#### 离线和线上不一致

离线 AUC 涨，不代表线上 CTR/GMV 一定涨。

原因：

- 样本分布变化。
- 训练-serving skew。
- 业务规则干扰。
- 多目标冲突。
- 用户体验指标未覆盖。

## 面试应对

### 1. 为什么推荐系统通常采用召回、粗排、精排和重排的分层架构？

回答思路：从候选规模与延迟约束出发，依次说明各层目标，并指出越靠后模型越复杂、候选越少。

完整回答模板：

推荐系统面对的物品池可能达到百万甚至更大规模，无法直接对所有物品运行复杂排序模型，所以要用分层架构平衡效果和时延。召回通过协同过滤、规则或向量检索从全库找回多个兴趣方向的候选，优先保证覆盖率；粗排用轻量模型快速压缩候选；精排结合用户、物品、上下文和交叉特征预测点击、转化或时长等目标；重排再处理多样性、去重、业务约束和用户体验。整个链路的原则是候选逐层减少、单条计算逐层增加，并同时监控各层耗时和信息损失。

### 2. 推荐召回和排序模型怎样选择，Two-Tower 与 DeepFM 等模型有什么分工？

回答思路：按服务阶段而不是只列模型名，比较可离线建索引的双塔召回与候选交互充分的排序模型。

完整回答模板：

模型选择首先取决于所在阶段。Two-Tower 将用户和物品独立编码，物品向量可以预计算并建立 ANN 索引，适合大规模召回，但两侧在打分前缺少充分特征交互。DeepFM、DCN、Wide & Deep 或序列模型可以显式或隐式学习特征交叉和兴趣演化，更适合候选量较小的粗排、精排。实际系统通常采用多路召回扩大兴趣覆盖，再由排序模型统一比较候选，而不是用一个模型包办所有阶段；选择时还要共同考虑效果、特征新鲜度、推理延迟和吞吐成本。

### 3. 推荐系统如何处理冷启动和曝光偏差？

回答思路：先区分两类问题，再分别给出内容特征/探索兜底与随机流量/倾向校正等方案，说明二者不能混为一谈。

完整回答模板：

冷启动是新用户或新物品缺少历史交互，常用内容和多模态特征、注册信息、热门或规则召回、相似人群以及受控探索来建立初始信号。曝光偏差则是训练数据只包含系统曾展示过的候选，未曝光不等于用户不喜欢，直接学习点击日志会强化旧策略。处理时可以保留随机或探索流量，记录曝光与位置，使用倾向得分校正或反事实方法，并对探索成本设置约束。两者都需要探索，但冷启动关注信息不足，曝光偏差关注观测机制有偏，评估和修正方式不同。

### 4. 为什么离线 AUC 提升不一定带来线上收益，应该怎样验证？

回答思路：从目标不一致、数据分布、链路效应和用户体验解释差异，再给出离线分层评估、回放检查与在线 A/B 的验证闭环。

完整回答模板：

离线 AUC 衡量的是给定样本上的区分能力，不直接等价于整页排序质量或业务收益。线上效果还会受到样本分布漂移、训练与服务特征不一致、召回候选变化、位置和曝光偏差、多目标权衡、重排规则以及延迟的影响；只优化点击还可能损害转化、时长、多样性或长期留存。因此我会先检查数据切分、特征一致性和分人群指标，再同时看 AUC、GAUC、NDCG、Recall@K 等与链路对应的离线指标，最后通过带护栏指标的在线 A/B 验证 CTR、CVR、时长、留存或 GMV。结论应以预先定义的业务目标和统计口径为准，不能只凭单个离线指标宣布上线有效。
