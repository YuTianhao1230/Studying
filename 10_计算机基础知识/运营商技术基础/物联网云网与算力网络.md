# 物联网、云网与算力网络

## 知识点解析

### 概述

物联网把物理设备接入网络并产生可感知、可传输、可处理的数据；云计算提供资源池化和弹性服务；算力网络进一步把计算资源、存储资源、网络连接和任务调度结合起来。运营商笔试常考技术分层、场景匹配以及“解决什么问题”。

### 物联网分层

物联网通常可以分为：

```text
感知层 -> 网络层 -> 平台层 -> 应用层
```

- 感知层：传感器、摄像头、RFID、执行器和智能终端。
- 网络层：蜂窝网络、Wi-Fi、低功耗广域网、工业网络和互联网。
- 平台层：设备管理、消息接入、数据存储、规则引擎和数字孪生。
- 应用层：智慧城市、工业互联网、车联网、智能家居和环境监测。

物联网系统不仅包括数据采集，还要处理设备身份、连接管理、数据安全、远程控制和生命周期管理。

### 常见物联网通信技术

| 技术 | 主要特点 | 常见场景 |
| --- | --- | --- |
| RFID | 非接触识别，距离和容量取决于具体类型 | 物流、门禁、商品识别 |
| NFC | 近距离通信 | 门禁、移动支付 |
| Wi-Fi | 速率较高，功耗和覆盖取决于版本与环境 | 家庭、园区 |
| 蓝牙 | 近距离、低功耗 | 穿戴设备、传感器 |
| NB-IoT | 低功耗、广覆盖、低速率 | 水表、烟感、环境监测 |
| LoRa | 低功耗、远距离，常用于专用网络 | 园区、农业、传感器 |

低功耗广域连接适合小数据量、低频上报和电池供电设备，不适合持续传输高清视频。

### 云计算服务模型

- IaaS：提供虚拟机、存储、网络等基础设施。
- PaaS：提供运行环境、数据库、中间件和开发平台。
- SaaS：直接提供可使用的软件应用。

部署形态包括公有云、私有云、混合云和多云。云计算的核心特征是资源池化、按需分配、弹性伸缩、服务化和计量使用。

### 边缘计算与中心云

边缘计算把计算、存储和网络服务部署到靠近数据源或用户的位置，适合需要快速响应、节省回传带宽或要求数据本地处理的业务。边缘节点通常资源有限、分布广，中心云则拥有更完整的资源池和全局视角，二者常通过云边协同共同完成任务。

| 对比项 | 边缘计算 | 中心云 | 算力网络 |
| --- | --- | --- | --- |
| 核心关注 | 就近处理和快速响应 | 集中资源池化和规模效率 | 跨边、云、数据中心统一发现与调度算力 |
| 典型优势 | 低时延、少回传、数据本地化 | 算力充足、统一管理、适合全局分析 | 联合考虑算力状态、网络路径和业务 SLA |
| 典型任务 | 工业控制、视频预处理、实时推理 | 模型训练、长期存储、离线分析 | 为任务选择满足约束的计算位置和传输路径 |
| 主要限制 | 单节点资源有限、运维分散 | 距终端较远、回传与时延压力 | 需要跨域资源感知、编排和协同控制 |

### 虚拟机、容器和云原生

| 对比项 | 虚拟机 | 容器 |
| --- | --- | --- |
| 隔离对象 | 虚拟化硬件和完整操作系统 | 进程及其运行环境 |
| 启动速度 | 相对较慢 | 相对较快 |
| 资源开销 | 较大 | 较小 |
| 隔离强度 | 通常较强 | 依赖内核和配置 |

容器并不是虚拟机的简单替代。容器适合快速交付和弹性伸缩，虚拟机适合更强隔离和不同操作系统环境。Kubernetes 主要负责容器编排，包括调度、服务发现、滚动更新、故障恢复和扩缩容。

### 大数据基础

大数据常用 5V 描述：

- Volume：规模大。
- Velocity：产生和处理速度快。
- Variety：数据类型多样。
- Veracity：数据真实性和质量。
- Value：数据价值。

典型组件：

- HDFS：分布式文件系统，负责大规模数据存储。
- MapReduce：分布式批处理计算模型。
- Hive：面向数据仓库的 SQL 查询和分析工具。
- Spark：通用分布式计算引擎，适合批处理、流处理和机器学习。
- Kafka：分布式消息和事件流平台。

以运营商设备遥测分析为例，一条具体数据链路可以是：

```text
设备指标 -> Kafka 消息主题 -> Spark 清洗、聚合和异常计算 -> HDFS 清洗区 -> Hive 外部表/明细表 -> SQL 报表与分析
                         \-> HDFS 原始区（原始流旁路归档）
```

设备采集程序先把指标写入 Kafka，生产者和下游消费者通过消息队列解耦。Spark 可以按批次或流式消费数据并完成清洗、关联和聚合，再把结果写入 HDFS 清洗区；Hive 在清洗区文件之上维护表结构和元数据，让分析人员使用 SQL 查询。原始流还可由另一消费者从 Kafka 旁路写入 HDFS 原始区，用于长期归档、重放或重新处理。HDFS 通过分块、副本和分布式存储提供容量与容错；Kafka 负责事件传递和削峰解耦，不替代长期存储；Spark 负责计算，不等于数据库；Hive 提供查询抽象，底层数据仍位于 HDFS。

OLTP 关注高并发事务处理，OLAP 关注多维分析和复杂查询。数据仓库通常通过 ETL 或 ELT 把多个业务系统的数据抽取、清洗、转换并装载后进行分析。

### 人工智能基础

- 监督学习：使用带标签数据训练分类或回归模型。
- 无监督学习：从无标签数据中发现聚类或结构。
- 强化学习：通过环境反馈和奖励学习策略。
- 深度学习：使用多层神经网络学习复杂表示。
- 生成式人工智能：生成文本、图像、音频或代码等内容。

常见概念包括训练集、验证集、测试集、过拟合、泛化、准确率、召回率和 F1。题目中出现“模型在训练集表现好、测试集表现差”，通常对应过拟合。

### 算力网络

算力网络把算力资源、网络资源、数据资源和调度策略统一考虑。它关注：

- 算力资源发现：各边缘节点、数据中心和云资源池注册 CPU、GPU、内存、存储、加速器类型、队列负载、地域和可用状态，控制系统持续更新资源目录。
- 网络路径选择：结合节点之间的带宽、时延、丢包、拥塞、成本和可靠性，选择满足业务 SLA 的传输路径，而不只比较地理距离。
- 任务调度：综合任务所需算力、数据位置、完成时限、隐私合规、能耗和费用，选择执行节点；必要时拆分任务、迁移实例或弹性扩缩容。
- 闭环调整：运行中持续观测任务进度和网络状态，出现拥塞、故障或负载变化时重新选路、迁移或降级。

典型流程可概括为“资源注册与发现 -> 任务需求解析 -> 候选节点筛选 -> 算网联合选路与调度 -> 部署执行 -> 监控反馈与动态调整”。算力网络不是单纯增加服务器，也不是只做网络带宽调度，而是让计算任务通过合适的网络路径到达合适的算力位置。

## 易错点

- 物联网不等于只有传感器，还包括连接、平台、数据和应用。
- 云计算的“云”不是某一种具体硬件，而是一种资源组织和服务方式。
- 容器通常共享宿主机内核，不能简单认为与虚拟机隔离强度完全相同。
- 大数据不等于数据量大，还涉及速度、多样性、真实性和价值。
- 算力网络同时考虑计算和网络，不能只理解成 GPU 调度。

## 面试应对

### 1. 物联网平台主要承担哪些职责？

**回答思路：** 按“接入设备、管理设备、处理数据、开放能力、保障安全”组织答案。

**回答模板：** 物联网平台位于连接层和业务应用之间，首先要完成多协议设备接入、身份认证和连接管理；其次负责设备注册、状态监控、配置升级和远程控制等生命周期管理；同时通过消息路由、规则引擎、数据存储与分析处理设备数据，并向上层应用开放 API。平台还要提供权限控制、密钥管理、审计和告警，不能只把它理解成数据存储系统。

### 2. NB-IoT 和 LoRa 应该如何选择？

**回答思路：** 从频谱与网络归属、覆盖、运维、成本和业务需求比较。

**回答模板：** NB-IoT 基于授权频谱和运营商蜂窝网络，覆盖与服务质量由运营商体系保障，适合水表、烟感等低速率、低功耗、广覆盖业务，但需要运营商网络和资费支持。LoRa 常由企业在非授权频段自建专网，部署灵活、终端功耗低，适合园区和农业场景，但覆盖规划、网关运维和干扰控制由建设方承担。选择时要结合覆盖范围、数据量、时延、成本和是否具备自建网能力。

### 3. 容器和虚拟机有什么区别？

**回答思路：** 比较虚拟化层级、启动与开销、隔离能力和适用场景，避免说成完全替代。

**回答模板：** 虚拟机通过虚拟化硬件运行完整客户操作系统，隔离通常更强，也能支持不同内核，但启动慢、资源开销较大。容器共享宿主机内核，只隔离进程及运行环境，因此启动快、密度高，适合微服务交付和弹性伸缩，但隔离能力依赖内核与安全配置。实际平台常用虚拟机提供基础隔离，再在虚拟机内运行容器。

### 4. 边缘计算和中心云如何协同？

**回答思路：** 按实时与非实时任务分工，再补充数据、模型和管理闭环。

**回答模板：** 边缘侧靠近设备，适合数据过滤、实时推理和快速控制，可以降低时延、回传流量并满足本地隐私要求；中心云资源更充足，适合模型训练、全局分析、长期存储和统一管理。典型协同方式是边缘采集并实时处理数据，把摘要或必要样本上传云端，云端训练和更新模型后再下发边缘，同时统一监控边缘节点。二者按任务特性分工，而不是相互替代。

### 5. 算力网络如何为一个任务选择执行位置？

**回答思路：** 依次回答资源发现、约束筛选、网络选路、综合调度和动态反馈。

**回答模板：** 算力网络先通过资源目录发现各节点的 CPU、GPU、内存、存储、负载和地域状态，再根据任务所需算力、数据位置、时限、隐私与成本筛选候选节点。随后评估到候选节点的带宽、时延、丢包、拥塞和可靠性，联合计算执行时间与数据传输代价，选择执行节点和网络路径。任务运行后还要持续监控，发生负载变化或故障时进行扩缩容、迁移或重新选路，形成闭环调度。
