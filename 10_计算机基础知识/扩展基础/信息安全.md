# 信息安全

## 知识点解析

### 概述

本文整理信息安全基本目标、常见 Web 攻击及防护、加密与哈希、身份认证、访问授权和安全分析方法。

### CIA

信息安全三要素：

- 机密性：防止未授权访问。
- 完整性：防止数据被篡改。
- 可用性：保证系统持续可用。

### 常见攻击

| 攻击 | 成立条件与影响 | 核心防护 |
| --- | --- | --- |
| SQL 注入 | 不可信输入被拼进 SQL 结构，并由数据库按代码执行，可导致越权查询或数据篡改 | 参数化查询、输入校验、数据库最小权限 |
| XSS | 不可信内容未经上下文编码进入页面或 DOM，并在受害者浏览器执行 | 按 HTML、属性、JavaScript、URL 上下文编码，配合 CSP、HttpOnly |
| CSRF | 用户已登录且浏览器会自动携带凭证，攻击者能诱导其发出状态变更请求 | CSRF Token、SameSite、来源校验、敏感操作二次确认 |
| DDoS | 大量恶意流量或高成本请求耗尽带宽、连接或计算资源 | 流量清洗、限流、黑名单、弹性扩容 |
| 中间人攻击 | 攻击者能够介入通信且客户端未正确验证对端身份 | HTTPS、完整证书校验、HSTS |

XSS 按恶意内容进入页面的方式分为：

- 反射型 XSS：恶意输入来自当前请求，服务端未经转义直接回显，需要诱导受害者访问特制链接。
- 存储型 XSS：恶意内容被服务器持久化，其他用户浏览相关页面时触发，影响范围通常更大。
- DOM 型 XSS：前端脚本把 URL、消息等不可信数据写入 `innerHTML` 等危险接口，漏洞可完全发生在浏览器端。

CSRF 不要求攻击者读取响应，其利用的是浏览器自动携带 Cookie 等凭证。CSRF Token 应不可预测、与用户会话或请求绑定，并由页面显式提交；跨站攻击者受同源策略限制，通常无法读取并构造正确 Token。若认证信息放在 Cookie 中，应同时合理设置 `SameSite`，但不能把它当作所有兼容场景下的唯一防线。

### 加密

对称加密使用同一密钥加解密，速度快，适合大量数据加密，典型算法 AES。非对称密码使用公钥和私钥，常用于密钥交换、数字签名和身份认证，典型算法 RSA、ECC。哈希是单向摘要函数，常用于完整性校验；需要防伪造时应使用 HMAC 或数字签名，不能只发送普通哈希值。

密码不应明文保存，也不应使用可逆加密或 SHA-256 等快速哈希直接保存。服务端应为每个密码生成唯一随机盐，并使用 Argon2id、scrypt、bcrypt 或 PBKDF2 等专用慢哈希提高离线破解成本；盐可以随哈希值存储，可选的 pepper 则应与数据库分离保管。验证时用相同参数重新计算并做恒定时间比较。

### 数字签名、数字证书与 CA

数字签名用于证明消息来自私钥持有者并检测内容是否被篡改。发送方通常先计算消息摘要，再用私钥对摘要签名；接收方用对应公钥验证签名。签名提供身份真实性、完整性和不可否认性，但不负责隐藏消息内容；需要保密时仍要加密。

数字证书把主体身份、域名、公钥、有效期和用途等信息绑定在一起，并由证书颁发机构（Certificate Authority，CA）签名。客户端验证证书时会检查信任链、域名、有效期、签名和必要的吊销状态，最终确认当前公钥属于目标服务。传输层安全协议（Transport Layer Security，TLS）通常通过证书认证服务端并协商会话密钥，再使用对称加密保护后续数据。

### 认证和授权

认证回答“你是谁”，授权回答“你能做什么”。认证完成后仍要在服务端按角色、属性或资源归属执行授权校验，不能依赖前端隐藏按钮。

JWT 是一种令牌格式，不等于完整的认证或授权方案。服务端必须固定允许的签名算法并校验签名、`exp`、`nbf`、`iss`、`aud` 等声明；负载通常仅做 Base64URL 编码，不能存敏感明文。JWT 的主要边界是签发后难以即时吊销、权限变更不能立刻生效以及客户端存储可能遭受 XSS 或 CSRF，因此通常使用短期访问令牌，并配合刷新令牌轮换、撤销机制和安全存储。

OAuth 2.0 解决第三方应用的委托授权，核心角色包括资源所有者、客户端、授权服务器和资源服务器。以授权码模式为例，用户在授权服务器完成登录和授权，客户端经重定向取得一次性授权码，再在后端用授权码换取访问令牌，最后携带令牌访问资源服务器；公共客户端应配合 PKCE 防止授权码被截获。OAuth 本身不是身份认证协议，需要登录身份时通常使用 OpenID Connect。

### 重放攻击与防护

重放攻击不必破解密文，而是截获一份合法请求后再次发送。防护通常组合使用：

- 时间戳和较短有效窗口，限制旧请求的可用时间。
- 一次性随机数 Nonce，服务端记录并拒绝已使用值。
- 将方法、路径、参数、时间戳和 Nonce 一并纳入 MAC 或数字签名，防止替换。
- 对转账等业务设置幂等键和唯一约束，避免重复请求造成重复执行。

### 常见考法与分析方法

| 题型 | 怎么判断 | 核心防护 |
| --- | --- | --- |
| SQL 注入 | 用户输入改变 SQL 结构 | 参数化查询、最小权限 |
| XSS | 恶意脚本在受害者浏览器执行 | 输出编码、CSP、HttpOnly |
| CSRF | 借用用户已有登录态发请求 | CSRF Token、SameSite、来源校验 |
| SSRF | 服务端替攻击者访问内部地址 | URL 白名单、网络隔离 |
| 越权 | 用户访问不属于自己的资源 | 服务端逐资源授权校验 |
| 重放攻击 | 截获合法请求后重复发送 | 时间戳、Nonce、签名、幂等 |

分析安全场景时，先判断攻击者能控制什么输入，输入进入了哪个解释器或敏感操作，再检查缺失的是认证、授权、校验还是隔离，最后分别从输入、执行、权限和审计层设置防护。

### 易错点

- Base64 是编码，不是加密。
- JWT 负载通常只是编码而非加密，不能存放敏感明文。
- 前端校验不能替代服务端校验。
- 认证成功不等于有权访问任意资源，仍需做授权。

## 笔试常考

- CIA 三要素：泄露客户数据破坏机密性，非法修改账务破坏完整性，系统中断破坏可用性。
- SQL 注入、XSS、CSRF：分别利用 SQL 结构、浏览器脚本执行环境和用户已有登录态，应按不同攻击面匹配核心防护。
- 密码学用途：对称加密适合大量数据，非对称密码适合密钥协商和签名，哈希用于摘要，HMAC 或签名用于防伪造。
- 数字签名与证书：签名验证来源和完整性，证书由 CA 签名并绑定身份与公钥，二者都不等于对业务数据加密。
- 认证与授权：认证先确认主体身份，授权再判断其能否对特定资源执行特定操作。
- JWT 边界：必须验证签名和关键声明；载荷不保密、令牌难即时吊销，不能把 JWT 当作万能会话方案。
- 重放防护：时间戳限制有效期，Nonce 保证请求唯一，签名防篡改，幂等机制防重复执行。

## 面试应对

### SQL 注入怎么防？

回答思路：参数化查询是核心，再补权限和审计。

回答模板：

SQL 注入是攻击者把恶意 SQL 放到输入里，如果服务端直接拼接 SQL，就可能改变查询逻辑。防护核心是使用参数化查询或预编译语句，让用户输入只作为数据而不是 SQL 代码执行。同时要做输入校验、最小权限控制、错误信息隐藏和审计告警。不要只靠前端校验，因为前端输入可以被绕过。

### 对称加密和非对称加密有什么区别？

回答思路：密钥数量、性能、用途。

回答模板：

对称加密加密和解密使用同一把密钥，速度快，适合大量数据传输，但密钥分发困难。非对称加密有公钥和私钥，公钥可以公开，私钥保密，适合身份认证和密钥交换，但性能较低。HTTPS 中通常先用非对称加密或密钥交换算法协商会话密钥，再用对称加密传输业务数据。

### XSS 和 CSRF 有什么区别？

回答思路：比较攻击执行位置、利用条件、攻击目标和防护方式。

回答模板：

XSS 是不可信脚本进入页面后在受害者浏览器执行，核心条件是输出或 DOM 操作缺少上下文编码，攻击者借此读取页面数据或冒用用户操作。CSRF 不需要注入脚本或读取响应，它利用用户已登录且浏览器会自动携带凭证，诱导用户发出状态变更请求。XSS 主要靠上下文编码、CSP 和安全 DOM API 防护；CSRF 主要靠不可预测且绑定会话的 Token、SameSite、来源校验和敏感操作二次确认。

### 使用 JWT 有哪些风险，应该如何控制？

回答思路：从校验、数据保密、吊销和客户端存储四方面回答。

回答模板：

JWT 只是签名令牌格式，不会自动解决认证和授权问题。服务端要固定允许的算法并校验签名、过期时间、签发方和受众，不能信任客户端传来的算法，也不能在载荷中放敏感明文。JWT 签发后通常难以立即吊销，权限变化也可能延迟生效，因此应使用短期访问令牌，配合刷新令牌轮换或撤销列表。存储方式还要结合 XSS 和 CSRF 风险选择，并始终在服务端做资源级授权。

### 用户密码应该如何安全存储？

回答思路：说明不可逆慢哈希、独立随机盐、参数和密钥管理。

回答模板：

密码不能明文保存，也不应使用可逆加密或快速通用哈希直接保存。服务端应为每个密码生成唯一随机盐，使用 Argon2id、scrypt、bcrypt 或 PBKDF2 等专用慢哈希，并根据硬件能力设置合理的时间和内存成本。盐可以和哈希值一起存储；如果使用 pepper，应放在数据库之外的密钥管理系统中。登录验证时按相同参数重新计算，并支持算法和成本参数逐步升级。
