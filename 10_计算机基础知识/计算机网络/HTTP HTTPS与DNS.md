# HTTP HTTPS与DNS

## 知识点解析

### 概述

本文整理 HTTP 方法与版本、状态码、缓存、TLS 握手、DNS 查询，以及从输入 URL 到页面展示的完整链路。

### HTTP

HTTP 是请求-响应模型的应用层协议。常见方法包括 GET、POST、PUT、DELETE。GET 通常用于获取资源，POST 通常用于提交数据。HTTP 默认无状态，需要 Cookie、Session 或 Token 维护用户状态。

GET 的参数通常放在 URL 中，便于缓存、收藏和重复获取；POST 的数据通常放在请求体中，更适合提交或修改数据。但安全性不由 GET/POST 决定，敏感数据仍然需要 HTTPS 和服务端权限校验。

### HTTP 版本

| 版本 | 核心特点 |
| --- | --- |
| HTTP/1.0 | 短连接为主 |
| HTTP/1.1 | 长连接、Host 头、管线化 |
| HTTP/2 | 二进制分帧、多路复用、头部压缩 |
| HTTP/3 | 基于 QUIC/UDP，减少握手和队头阻塞 |

### HTTPS

HTTPS = HTTP + TLS。TLS 提供身份认证、加密传输和完整性保护。客户端通过证书验证服务端身份，握手阶段协商密钥，后续用对称加密传输数据。

### DNS

DNS 把域名解析成 IP。解析链路可能经过浏览器缓存、操作系统缓存、本地 DNS、根域名服务器、顶级域名服务器和权威域名服务器。DNS 查询可分为递归查询和迭代查询。

### 状态码

- 2xx：成功，例如 200。
- 3xx：重定向或缓存，例如 301、302、304。
- 4xx：客户端错误，例如 400、401、403、404。
- 5xx：服务端错误，例如 500、502、503、504。

### HTTP 缓存

- 强缓存：浏览器根据 `Cache-Control` 或 `Expires` 直接使用本地副本，不发请求。
- 协商缓存：浏览器携带 `If-None-Match` 或 `If-Modified-Since`，服务端未变化时返回 304。
- `ETag` 基于资源版本，通常比只依赖修改时间更精确。

### TLS 握手怎么理解

TLS 的目标是认证服务端、协商会话密钥并验证握手未被篡改。现代 TLS 通常使用 ECDHE 协商共享密钥，证书和数字签名用于验证服务端身份，后续业务数据使用高效的对称加密。

客户端验证证书时会检查：

- 是否由受信任 CA 签发。
- 域名是否匹配。
- 是否在有效期内。
- 证书链和签名是否有效。

### DNS 查询

主机通常向本地 DNS 发起递归查询，本地 DNS 再迭代查询根、顶级域和权威 DNS。缓存会显著减少查询次数，TTL 决定记录可以缓存多久。

### 常见考法与排查

| 题型 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 协议顺序 | URL 访问时 DNS、TCP、TLS、HTTP 顺序 | 按分层和依赖关系排列 |
| 状态码 | 401/403、502/504 等区别 | 判断错误发生在哪一侧 |
| HTTP 版本 | 多路复用、队头阻塞、QUIC | 对比连接与传输机制 |
| 缓存 | 200、304、Cache-Control、ETag | 先判断强缓存，再判断协商缓存 |
| TLS | 为什么能防窃听和篡改 | 证书认证 + 密钥协商 + 对称加密 |
| DNS | 递归和迭代、缓存层级 | 按客户端、本地 DNS、权威链路分析 |

网页访问慢时按阶段排查：

```text
DNS 解析
  -> TCP/QUIC 建连
  -> TLS 握手
  -> 服务端处理
  -> 内容下载
  -> 浏览器解析与渲染
```

### 易错点

- POST 不天然比 GET 安全，安全性主要依赖 HTTPS、认证和授权。
- 401 表示未认证或认证失效，403 表示身份已知但没有权限。
- 502 通常是网关收到上游错误响应，504 是网关等待上游超时。
- HTTP/2 解决应用层多路复用问题，但底层 TCP 丢包仍可能阻塞连接；HTTP/3 使用 QUIC 改善这一问题。
- HTTPS 不能阻止服务端自身泄露数据，也不能替代业务权限校验。

## 面试应对

### HTTPS 为什么安全？

回答思路：认证、加密、完整性。

回答模板：

HTTPS 的安全性来自 TLS。第一，通过证书验证服务端身份，降低中间人攻击风险；第二，握手阶段协商会话密钥，后续使用对称加密保护数据内容；第三，通过消息认证码或 AEAD 机制保证数据完整性，防止传输过程中被篡改。所以 HTTPS 不只是加密，还同时解决身份认证、机密性和完整性。

### 从输入 URL 到页面展示发生什么？

回答思路：DNS、TCP、TLS、HTTP、浏览器渲染。

回答模板：

浏览器输入 URL 后，先解析 URL，再通过 DNS 把域名解析成 IP。然后建立 TCP 连接，如果是 HTTPS 还要进行 TLS 握手。连接建立后发送 HTTP 请求，服务端处理并返回响应。浏览器收到 HTML 后解析 DOM，加载 CSS 和 JS，构建渲染树，执行布局和绘制，最后展示页面。实际排查性能时可以把 DNS、建连、TLS、服务端处理和下载渲染分开看。

### HTTP/1.1、HTTP/2 和 HTTP/3 有什么区别？

回答思路：从连接复用、帧、多路复用和底层传输回答。

回答模板：

HTTP/1.1 支持长连接，但同一连接上的请求处理能力有限，管线化也没有广泛使用；HTTP/2 引入二进制分帧、头部压缩和多路复用，让多个请求共享一个 TCP 连接，但 TCP 丢包仍可能造成整个连接等待；HTTP/3 基于 QUIC 和 UDP，把不同流独立处理，并把传输层与 TLS 握手结合，减少建连开销和传输层队头阻塞。

### 强缓存和协商缓存有什么区别？

回答思路：是否向服务端发送请求。

回答模板：

强缓存命中时浏览器直接使用本地资源，不向服务端发请求，常由 Cache-Control 控制；协商缓存会向服务端发送条件请求，例如携带 ETag 或 Last-Modified，资源未变化时服务端返回 304。通常先判断强缓存，未命中后再走协商缓存。
