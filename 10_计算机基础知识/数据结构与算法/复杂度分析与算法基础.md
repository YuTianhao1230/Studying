# 复杂度分析与算法基础

## 知识点解析

### 概述

复杂度分析用于估计算法随着输入规模增长所需的时间和额外空间，是选择数据结构、判断算法是否可行和解答笔试题的共同基础。数据结构题不能只背一个 `O(...)` 结论，还要说明输入规模、实现方式、最好/平均/最坏情况、是否包含输出成本以及复杂度成立的前提。

### 输入规模与基本符号

设输入编码长度为 `n`：

- `O(f(n))`：渐进上界，算法增长速度不超过某个常数倍的 `f(n)`。
- `Ω(f(n))`：渐进下界，算法增长速度至少达到某个常数倍的 `f(n)`。
- `Θ(f(n))`：渐进紧确界，同时满足 `O(f(n))` 和 `Ω(f(n))`。
- `o(f(n))`：严格低阶，增长速度相对 `f(n)` 更慢。

常见复杂度从低到高：

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2^n) < O(n!)
```

常数、低阶项和对数底数在渐进分析中通常忽略：

```text
3n² + 5n + 10 = Θ(n²)
log2(n) = Θ(log10(n))
```

但在工程中，常数仍可能影响实际性能；渐进复杂度只描述规模足够大时的增长趋势。

### 最好、平均和最坏复杂度

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| 最好情况 | 某类输入中运行代价最低 | 线性查找第一个元素 |
| 平均情况 | 按输入分布或随机假设计算平均代价 | 随机快排的期望复杂度 |
| 最坏情况 | 所有合法输入中的最大代价 | 快排遇到极端划分 |

笔试没有给出输入分布时，默认优先报告最坏复杂度。说“哈希表是 `O(1)`”时应补充“平均或期望 `O(1)`，最坏情况取决于冲突”；说“快排是 `O(n log n)`”时应说明这是平均或随机化后的期望结论，最坏可达 `O(n²)`。

### 循环复杂度的计算

#### 顺序结构相加

```text
for i = 1..n       -> O(n)
for j = 1..n       -> O(n)
总复杂度             O(n) + O(n) = O(n)
```

顺序执行的代码取复杂度之和，再保留最高阶项。

#### 嵌套结构相乘

```text
for i = 1..n:
    for j = 1..n:
        work()
```

内层执行 n 次，外层也执行 n 次，总复杂度为 `O(n²)`。但嵌套不一定就是乘法，要看内层总迭代次数：

```text
for i = 1..n:
    for j = i; j <= n; j++:
        work()
```

总次数为 `n + (n−1) + ... + 1 = n(n+1)/2 = Θ(n²)`。

#### 对数循环

如果每轮把规模减半或乘二，循环次数通常为 `Θ(log n)`：

```text
i = 1
while i < n:
    i = i * 2
```

满足 `2^k >= n` 时结束，因此 `k = Θ(log n)`。

#### 双指针不能只看两层循环

```text
left = 0
for right = 0..n-1:
    while left <= right and invalid():
        left += 1
```

虽然代码有 `for` 和 `while` 两层，但 `left` 最多从 0 走到 n，`right` 也最多走 n 次，总复杂度是 `O(n)`，不是 `O(n²)`。分析双指针、滑动窗口和单调栈时，应统计每个指针或元素被推进、弹出多少次。

### 递归复杂度

递归复杂度要写出递推式，再求解：

| 递推式 | 典型算法 | 复杂度 |
| --- | --- | --- |
| `T(n)=T(n−1)+O(1)` | 单链递归 | `O(n)` |
| `T(n)=T(n−1)+O(n)` | 递归插入或逐层扫描 | `O(n²)` |
| `T(n)=T(n/2)+O(1)` | 二分查找 | `O(log n)` |
| `T(n)=2T(n/2)+O(n)` | 归并排序 | `O(n log n)` |
| `T(n)=2T(n−1)+O(1)` | 未剪枝的二叉递归 | `O(2^n)` |

递归空间通常等于递归深度加上每层局部变量。归并排序时间为 `O(n log n)`，递归栈为 `O(log n)`，数组辅助空间为 `O(n)`；不能只写一个空间复杂度而遗漏辅助数组。

### 主定理

对于：

```text
T(n) = aT(n/b) + f(n)
```

令 `d = log_b(a)`：

| 情况 | 条件 | 结论 |
| --- | --- | --- |
| 1 | `f(n) = O(n^(d−ε))`，`ε>0` | `T(n)=Θ(n^d)` |
| 2 | `f(n) = Θ(n^d log^k n)` | `T(n)=Θ(n^d log^(k+1)n)` |
| 3 | `f(n) = Ω(n^(d+ε))` 且满足正则条件 | `T(n)=Θ(f(n))` |

典型例子：

```text
T(n)=2T(n/2)+O(n)      -> Θ(n log n)
T(n)=4T(n/2)+O(n)      -> Θ(n²)
T(n)=2T(n/2)+O(1)      -> Θ(n)
```

主定理不适用于所有递推式，例如 `T(n)=T(n−1)+n`、子问题规模不均匀或递归项不符合 `n/b` 形式时，应使用递归树、代入法或其他方法。

### 摊销分析

摊销复杂度关注一串操作的总成本，而不是某一次操作的最坏成本。动态数组扩容时单次插入可能是 `O(n)`，但容量按倍数增长：

```text
容量 1 -> 2 -> 4 -> 8 -> ...
```

前 n 次扩容搬移元素的总数为：

```text
1 + 2 + 4 + ... + 2^k = O(n)
```

因此 n 次插入总成本为 `O(n)`，单次插入的摊销复杂度为 `O(1)`。摊销 `O(1)` 不表示每次操作都严格 `O(1)`，而是长期平均成本受常数限制。

并查集使用路径压缩和按秩合并后，单次操作摊销复杂度为 `O(α(n))`，实际规模下可近似看作常数；这也不等于完全没有树结构维护成本。

### 时间复杂度与空间复杂度

空间复杂度要区分：

- 输入空间：题目给定的数据，不一定计入额外空间。
- 输出空间：算法必须返回的结果，有时单独报告。
- 辅助空间：算法运行过程中额外申请的空间。
- 递归栈：递归调用产生的栈帧。

例如：

| 算法 | 时间 | 辅助空间 |
| --- | --- | --- |
| 数组二分 | `O(log n)` | `O(1)`，迭代实现 |
| 递归 DFS | `O(V+E)` | `O(V)`，含 visited 和栈 |
| BFS | `O(V+E)` | `O(V)`，含队列和 visited |
| 归并排序 | `O(n log n)` | `O(n)` |
| 原地快排 | 平均 `O(n log n)` | 平均 `O(log n)` 栈 |

如果算法返回长度为 n 的新数组，是否把输出空间计入要按题目口径说明；分析额外工作空间时通常不计输出本身。

### 正确性：循环不变量

循环不变量是在每次循环开始前都成立的性质。证明通常分三步：

1. 初始化：第一次循环前不变量成立。
2. 保持：如果本轮开始前成立，执行本轮后下一轮仍成立。
3. 终止：循环结束时，不变量结合终止条件推出算法结果正确。

**例：插入排序。** 第 i 轮开始前，前 i 个元素已经有序；把第 i+1 个元素插入正确位置后，前 i+1 个元素仍然有序；循环结束时整个数组有序。

双指针题也常用不变量：

- 滑动窗口 `[left,right]` 始终满足某个合法条件。
- 单调栈内元素保持单调性。
- 二分查找中，答案始终位于维护的搜索区间内。

### 其他正确性证明方法

- 数学归纳：证明基础规模成立，再证明由 n 推出 n+1。
- 反证法：假设算法结果错误，推出与算法不变量或题目约束矛盾。
- 交换论证：常用于贪心，证明存在一个最优解可以交换成包含当前贪心选择的最优解。
- 归纳结构：常用于树、递归和分治，分别证明基例和递归合并步骤。

算法“看起来能通过样例”不能代替正确性证明；尤其是贪心、二分答案、剪枝和状态压缩题，必须说明为什么不会漏掉最优解。

### 输入规模与算法选型

下面是常用经验，不是绝对规则，最终要结合常数、内存限制和题目结构：

| n 的量级 | 通常可接受的复杂度 |
| --- | --- |
| `n <= 20` | `O(2^n)`、回溯、状态压缩 |
| `n <= 40` | 折半枚举、剪枝、部分 `O(2^(n/2))` |
| `n <= 10^2` | `O(n³)` 常可接受 |
| `n <= 10^3` | `O(n²)` 需看语言和时限 |
| `n <= 10^5` | `O(n log n)` 或 `O(n)` |
| `n <= 10^6` | 通常要求线性或接近线性，并注意常数和 IO |

遇到数值参数 `W`、`T` 时，不能只看其数值上限，还要看输入是十进制还是二进制编码。`O(nW)` 可能是伪多项式时间，详见[NP与计算复杂性](<NP与计算复杂性.md>)。

## 笔试常考

- 给出多重循环，判断顺序相加、嵌套相乘还是双指针摊销。
- 根据递推式判断递归复杂度。
- 使用主定理计算分治复杂度。
- 区分最好、平均、最坏和摊销复杂度。
- 判断哈希、快排、并查集等“平均/期望”和“最坏”结论。
- 判断辅助空间、递归栈和输出空间。
- 找出二分、滑动窗口、单调栈中的循环不变量。
- 结合输入规模选择 `O(n²)`、`O(n log n)`、`O(2^n)` 或状态压缩。

## 解题步骤

1. 明确输入规模和输入编码。
2. 统计基本操作执行次数，而不是只数循环层数。
3. 对循环考虑是否存在总量受限的指针、元素或状态。
4. 对递归写出递推式，再选择主定理、递归树或代入法。
5. 分别计算时间、辅助空间和递归栈。
6. 报告最好/平均/最坏或摊销前提。

## 易错点

- 两层循环不一定是 `O(n²)`，双指针和单调栈经常是 `O(n)`。
- `O(1)` 额外空间不表示算法不需要保存输入或输出。
- 摊销 `O(1)` 不表示每次操作都 `O(1)`。
- 快排平均 `O(n log n)`，最坏可以是 `O(n²)`。
- 哈希表平均 `O(1)` 依赖哈希分布和实现，最坏不一定是 `O(1)`。
- 递归时间和递归栈空间是两个维度。
- `O(nW)` 在 W 以二进制输入时不一定是多项式时间。
- 复杂度分析的 n 必须对应真正变化的输入规模，不能把数值大小和编码长度混为一谈。

## 自测

1. `for (i=1; i<n; i*=2)` 的复杂度是 `O(log n)`。
2. 两个各执行 n 次的顺序循环总复杂度是 `O(n)`。
3. `while (n>1) n/=2` 的循环次数是 `Θ(log n)`。
4. 归并排序的递推式是 `T(n)=2T(n/2)+Θ(n)`，复杂度为 `Θ(n log n)`。
5. 动态数组倍增扩容的单次最坏插入可以是 `O(n)`，但摊销为 `O(1)`。

## 面试应对

### 如何分析一个算法的复杂度？

我会先明确输入规模和实现方式，再统计基本操作执行次数。顺序执行的部分取复杂度之和，嵌套循环要看实际迭代总量，双指针和单调栈则要统计每个元素被推进或弹出的次数。递归算法先写递推式，分别计算时间复杂度、辅助空间和递归栈，并说明这是最好、平均、最坏还是摊销结论。

### 为什么双指针常常是 O(n)？

关键不在于代码里有几层循环，而在于两个指针通常只单调向前移动。右指针最多移动 n 次，左指针也最多移动 n 次，因此所有移动的总次数是 O(n)。前提是指针不会反复退回，且每次移动和判断都是 O(1) 或可以摊销到线性次数。

### 主定理什么时候不能直接用？

主定理适用于 `T(n)=aT(n/b)+f(n)` 这类子问题规模相同的递推。如果子问题规模不均匀、递归项是 `T(n−1)`、递归次数依赖输入或不满足正则条件，就不能机械套主定理，应改用递归树、代入法或其他分析方法。
