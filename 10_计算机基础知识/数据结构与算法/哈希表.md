# 哈希表

## 知识点解析

### 概述

本文整理哈希函数、冲突处理、装填因子、扩容机制，以及去重、计数、前缀和统计、缓存索引等典型应用。

### 核心机制

哈希表通过 hash 函数把 key 映射到桶。理想情况下 key 分布均匀，每个桶元素很少，所以查找、插入、删除平均 O(1)。

哈希函数应尽量计算简单、分布均匀，并充分利用关键字信息。常见构造方式包括除留余数法、直接定址法、数字分析法和平方取中法。除留余数法常写为：

```text
H(key) = key mod p
```

其中 `p` 通常选择不大于表长的质数，以减少规律性冲突。

哈希冲突解决方式：

- 链地址法：同一个桶里的元素用链表或树组织。
- 开放寻址法：冲突后继续探测其他位置。

开放寻址常见方法：

- 线性探测：`h_i = (h(key) + i) mod m`，依次检查后续位置，简单但容易产生一次聚集。
- 平方探测：`h_i = (h(key) ± i^2) mod m`，按平方距离跳转，缓解一次聚集，但参数选择不当时不一定能访问所有位置。
- 双重散列：`h_i = (h1(key) + i * h2(key)) mod m`，第二个哈希函数决定步长。要遍历全部槽位，步长应与表长 `m` 互质。

探测从 `i = 0` 开始。查找成功要沿同一序列直到找到 key；查找失败遇到“从未使用”的空槽才能停止。

开放寻址的槽位通常区分 `EMPTY`、`OCCUPIED` 和 `DELETED`。删除时写入墓碑 `DELETED`，查找经过墓碑必须继续，否则会截断冲突元素的探测路径；插入可以复用遇到的第一个墓碑。墓碑过多也会拉长探测序列，因此实践中会通过重散列清理。

### 装填因子与查找效率

装填因子表示哈希表中已有元素数量与桶数量之比：

```text
alpha = 元素数量 / 哈希表长度
```

装填因子越高，冲突概率通常越大，平均查找长度 ASL 也会增大。开放寻址通常要求 `alpha < 1`，且会在较低阈值扩容；链地址法允许 `alpha > 1`，但桶内比较次数会增加。

例如表长为 7，`H(key) = key mod 7`，按线性探测插入 `10、17、24、8`，最终占用下标 `3、4、5、1`。成功查找探测次数依次为 `1、2、3、1`，所以：

```text
ASL_success = (1 + 2 + 3 + 1) / 4 = 1.75
```

失败查找要分别从 7 个初始地址探测到首个 `EMPTY`，次数为 `1、2、1、4、3、2、1`，所以：

```text
ASL_failure = (1 + 2 + 1 + 4 + 3 + 2 + 1) / 7 = 2
```

计算 ASL 时必须明确哈希函数、冲突策略、插入顺序，以及失败查找的关键字或初始地址分布。

达到负载阈值后，扩容通常按以下过程执行：申请更大的桶数组，遍历所有有效元素，根据新容量重新计算桶位置，再释放旧数组。桶下标依赖容量，所以一般不能只复制原数组；单次重散列为 `O(n)`，但容量按倍数增长时，连续插入的总迁移成本为 `O(n)`，单次插入均摊仍为 `O(1)`。

### 常见算法题型

| 题型 | 识别信号 | 解法 |
| --- | --- | --- |
| 两数之和 | 查找“是否见过 target - x” | 哈希表保存已遍历元素 |
| 频次统计 | 统计字符、数字、类别次数 | key 映射到计数 |
| 去重 | 判断元素是否重复出现 | 使用集合 |
| 子数组和等于 K | 连续区间和、可能有负数 | 前缀和 + 哈希计数 |
| 最长连续序列 | 无序数组中找连续整数 | 集合中只从序列起点扩展 |
| LRU 缓存 | O(1) 查找并维护访问顺序 | 哈希表 + 双向链表 |

以“子数组和等于 K”为例，若当前前缀和为 `prefix`，只需统计之前出现过多少次 `prefix - K`，即可知道以当前位置结尾的合法子数组数量。

### LRU 缓存

LRU，Least Recently Used，淘汰最近最久未使用的数据。典型实现是哈希表加双向链表：

- 哈希表把 key 映射到链表节点，保证平均 `O(1)` 定位。
- 双向链表按访问新旧维护节点，头部表示最近使用，尾部表示最久未使用。
- 查询命中或更新已有 key 时，把对应节点移动到头部。
- 插入新 key 且容量已满时，删除尾部节点，并同步从哈希表移除其 key。

双向链表能在已知节点时 `O(1)` 删除和插入；若只用单链表，删除当前节点通常还要寻找前驱。哈希表与链表必须同步更新，否则会产生失效索引或重复节点。完整实现中常加入虚拟头尾节点统一空表、首尾插入和淘汰的边界处理。

因此 LRU 的查询和更新平均都是 `O(1)`，空间复杂度为 `O(capacity)`。它常用于缓存、页面置换和热点数据管理；需要考虑访问频率而不只是最近访问时间时，应比较 LFU 等策略。

## 笔试常考

- 根据哈希函数计算元素初始地址和冲突处理过程。
- 使用线性探测、平方探测或链地址法构造哈希表。
- 计算查找成功和查找失败的平均查找长度 ASL。
- 分析装填因子变化对冲突和查找效率的影响。
- 判断删除操作是否会破坏开放寻址的查找路径。

### HashMap 高频点

- JDK 1.8 底层是数组 + 链表/红黑树。
- 容量是 2 的幂，`(n - 1) & hash` 等价于对 `n` 取模但位运算更直接；`n - 1` 的低位全为 1，配合高低位扰动后的 hash 利用低位信息。
- 容量翻倍时，元素的新位置只可能是原下标或“原下标 + 旧容量”，可依据新增的那一位快速拆分桶。
- 质数容量配合取模也是常见设计；2 的幂是工程实现选择，不是哈希表的理论要求。
- 负载因子过高会扩容，降低冲突概率。
- HashMap 线程不安全，并发场景用 ConcurrentHashMap。

### 易错点

- 哈希表平均 `O(1)` 不代表最坏也是 `O(1)`。
- 哈希冲突无法完全避免，只能通过设计降低概率并妥善处理。
- 链地址法和开放寻址法的 ASL 计算方式不同。
- 自定义对象作为 key 时，判等规则和哈希值必须保持一致。
- 可变对象不适合作为哈希 key，因为内容变化后可能无法在原桶中找到。

## 面试应对

### 哈希表为什么平均 O(1)？

回答思路：hash 分桶、均匀分布、冲突退化。

回答模板：

哈希表通过 hash 函数把 key 映射到桶，理想情况下 key 分布均匀，每个桶里的元素很少，所以查找、插入、删除平均是 O(1)。但如果 hash 冲突严重，很多 key 落到同一个桶里，就需要在桶内继续查找，最坏可能退化到 O(n)。因此哈希表性能依赖 hash 函数、负载因子和扩容策略。

### HashMap 为什么容量通常是 2 的幂？

回答思路：位运算定位桶，减少冲突。

回答模板：

HashMap 容量取 2 的幂，可以用 `(n - 1) & hash` 快速计算桶下标，比取模更高效。同时当 n 是 2 的幂时，`n - 1` 的低位全是 1，可以更好利用 hash 的低位信息，帮助元素分布更均匀。扩容时元素位置也更容易判断，要么留在原位置，要么移动到原位置加旧容量。

### 链地址法和开放寻址法有什么区别？

回答思路：从冲突存储方式、装填因子、删除和缓存局部性回答。

回答模板：

链地址法把冲突元素放在同一个桶的链表或树中，删除简单，装填因子可以大于 1，但需要额外指针。开放寻址法把所有元素都放在数组中，冲突后继续探测其他位置，缓存局部性较好，但装填因子不能太高，删除时还要使用删除标记，不能直接清空位置。两者的核心区别是冲突元素放在表外链结构中，还是继续占用表内其他槽位。

### 哈希表扩容为什么仍可认为插入均摊 O(1)？

回答思路：说明扩容不是每次发生，总代价可分摊。

回答模板：

单次扩容需要重新分配更大的表并迁移已有元素，成本是 O(n)，但扩容通常按倍数增长，不会每次插入都发生。连续插入 n 个元素时，历次迁移数量形成几何级数，总成本仍是 O(n)，均摊到每次插入就是 O(1)。这不代表某一次触发扩容的插入也是常数时间。
