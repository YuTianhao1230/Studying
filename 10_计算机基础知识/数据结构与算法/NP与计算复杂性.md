# NP 与计算复杂性

## 知识点解析

### 概述

NP（Nondeterministic Polynomial time，非确定性多项式时间）是一类判定问题：对于答案为“是”的输入，存在长度受输入规模的多项式限制的证据，确定性算法能够在多项式时间内验证该证据。NP 关注问题的计算复杂度，动态规划（DP）关注如何设计求解算法。P 中的问题可以在多项式时间内直接求解，因此也属于 NP；NP 完全问题既属于 NP，又至少与所有 NP 问题一样难。P 是否等于 NP 仍是未解决问题，所以不能把 NP 理解为“已经证明无法快速求解”。

### 1. 先区分判定、搜索、优化和计数

复杂度类 P、NP 的标准定义以判定问题为对象。一个业务问题可以有不同版本，分类前必须说清楚版本。

以旅行商问题（TSP）为例：

| 版本 | 要求 | 常见复杂度表述 |
| --- | --- | --- |
| 判定 | 是否存在访问每个城市恰好一次并返回起点、总长度不超过 K 的路线？ | 一般版本属于 NP 完全 |
| 搜索 | 给出一条满足长度上限的路线 | 搜索问题，不能直接套用判定问题的类名 |
| 优化 | 找出总长度最短的路线 | 一般版本是 NP 难优化问题 |
| 计数 | 统计满足约束的路线数量 | 计数复杂度问题，不能因验证一条路线容易就认为计数容易 |

以下涉及加权问题时，默认权值和阈值为有限二进制编码的整数；涉及背包、子集和时默认使用非负整数。不同的图结构、数值编码和约束条件可能改变问题难度。

### 2. 多项式时间看的是输入长度

设输入编码长度为 N。运行时间上界为 `O(N^c)`、其中 c 为固定常数的算法属于多项式时间算法。`O(N log N)` 也受多项式上界约束；`O(2^N)` 和 `O(N!)` 则不是多项式时间。

这里的 N 是“写下输入需要多少位”，不能直接替换为输入里某个整数的数值。

- n 个图顶点是规模的一部分，还要考虑边和权值的编码。
- 整数 T 的二进制编码长度约为 `log₂T`，不是 T。
- 计算大整数加法、比较时，也需要计算处理其二进制位的代价。

“多项式时间”是理论上的效率分类，不意味着现实中一定很快，例如 `O(N^100)` 的算法通常不可用；指数算法也可能在输入很小时实用。

### 3. P：可以在多项式时间内求解

P（Polynomial time）包含能够由确定性算法在多项式时间内给出“是/否”答案的判定问题。

典型例子：

- 图中 s 是否能够到达 t：BFS 或 DFS。
- 图是否为二分图：BFS/DFS 染色。
- 2-SAT 是否可满足：蕴含图及强连通分量算法。
- 两个字符串是否存在长度至少为 k 的公共子序列：LCS 动态规划。

排序通常要求输出排序后的序列，因此严格说属于函数计算任务；可以说“排序有多项式时间算法”，而不必把排序任务本身称作 NP 判定问题。

### 4. NP：可以在多项式时间内验证肯定证据

设判定问题对应输入集合 L，输入为 x，证据为 y。存在多项式 p 和多项式时间验证算法 V，使得：

```text
x ∈ L  ⇔  存在 y，满足 |y| ≤ p(|x|)，且 V(x, y) 接受
```

这一定义包含两点：

1. 若答案为“是”，至少存在一份合格证据，让验证器接受。
2. 若答案为“否”，任何候选证据都不能骗过验证器。

NP 不要求为每个“否”实例也提供容易验证的否定证据。比如 SAT 给出一份赋值，可以快速检验其是否满足公式；给出一份不满足公式的赋值，并不能证明公式对所有赋值都不可满足。

**例：子集和。** 输入 `[3, 5, 9, 12]`，目标 `T=17`。证据可以是选择第 2、4 个元素的下标列表，验证器检查下标合法、没有重复并计算 `5+12=17`。如果目标无法凑出，则没有任何合法下标列表能通过验证。

“非确定性”指理论机器可以选择一条计算分支，只要存在一条接受分支就接受；它不等于随机算法、并行计算或实际机器能免费尝试全部组合。

### 5. P、NP、NP 完全与 NP 难

| 类别 | 定义 | 是否一定属于 NP |
| --- | --- | --- |
| P | 确定性多项式时间可求解的判定问题 | 是 |
| NP | 肯定证据可在多项式时间内验证的判定问题 | 是 |
| NP 完全（NP-complete，NPC） | 既属于 NP，又是 NP 难 | 是 |
| NP 难（NP-hard） | 所有 NP 问题均可按指定的多项式归约方式归约到它 | 不一定 |

对判定问题，本卡采用常见的**多项式时间多对一归约**；对优化问题所说的 NP 难，是指能用其求解能力解决 NP 难判定问题。

已知关系：

```text
P ⊆ NP
NP 完全 = NP ∩ NP 难       （判定问题及上述归约约定下）
```

这些结论不能混淆：

- NP 完全问题是 NP 的一部分，不能把 NP 和 NPC 当作同义词。
- NP 难问题可以是优化任务，也不要求具备 NP 的多项式验证性质。
- 只要任何一个 NP 完全问题存在确定性多项式时间算法，就有 `P=NP`。
- 如果 `P≠NP`，所有 NP 完全问题都不属于 P。
- 对 NP 完全问题，目前没有已知的确定性多项式时间通用精确算法；这不等于已经证明必须用指数时间。

### 6. 哪些问题属于 NP：已知属于 P 的问题

**P 中的所有判定问题也属于 NP。** 因为验证器可以忽略额外证据，直接运行多项式时间求解算法。

| 问题及版本 | 可用的多项式算法 | 分类 |
| --- | --- | --- |
| 图可达性：s 是否能到达 t | BFS/DFS | P，因此属于 NP |
| 非负权图：是否存在长度不超过 K 的 s-t 路径 | Dijkstra 等最短路算法 | P，因此属于 NP |
| 无向图：是否存在权值不超过 K 的生成树 | 先检查连通性，再求最小生成树 | P，因此属于 NP |
| 是否存在大小至少 k 的二分图匹配 | 二分图最大匹配算法 | P，因此属于 NP |
| 是否存在访问每条边恰好一次的闭合欧拉回路 | 连通性及顶点度数条件判定 | P，因此属于 NP |
| 图是否能用两种颜色使相邻顶点异色 | 二分图判定 | P，因此属于 NP |
| 2-SAT：每个子句至多两个文字的合取范式是否可满足 | 蕴含图与强连通分量 | P，因此属于 NP |
| 两个字符串的 LCS 长度是否至少为 k | `O(mn)` 动态规划 | P，因此属于 NP |

这里的“文字”指一个布尔变量或其否定。例如 `x` 和 `¬x` 都是文字；子句是若干文字的“或”，合取范式是若干子句的“与”。

### 7. 哪些问题属于 NP：典型 NP 完全问题

以下是**一般输入上的判定版本**。表中的证据说明它们为什么属于 NP；要证明 NP 完全，还需要独立的 NP 难归约证明。

| 问题 | 明确的判定形式 | 肯定证据 | 如何验证 |
| --- | --- | --- | --- |
| SAT | 布尔公式是否存在满足赋值 | 每个变量的真/假取值 | 代入并计算公式是否为真 |
| 3-SAT | 每个子句至多三个文字的合取范式是否可满足 | 一份变量赋值 | 检查每个子句至少一个文字为真 |
| 团（Clique） | 无向图中是否存在至少 k 个两两相邻的顶点 | k 个顶点 | 检查每对顶点之间都有边 |
| 顶点覆盖（Vertex Cover） | 是否存在至多 k 个顶点，覆盖每条边的至少一个端点 | 顶点集合 | 检查集合大小和每条边的端点 |
| 独立集（Independent Set） | 是否存在至少 k 个两两不相邻的顶点 | k 个顶点 | 检查任意两点之间均无边 |
| 哈密顿回路 | 是否存在经过每个顶点恰好一次并回到起点的回路 | 顶点排列 | 检查顶点不重复、覆盖全部顶点及相邻边 |
| 旅行商 TSP 判定版 | 是否存在访问所有城市后返回起点、长度不超过 K 的路线 | 城市排列 | 检查访问约束并累加长度 |
| 子集和（Subset Sum） | 是否存在元素子集，其和恰好为 T | 被选元素的下标 | 检查不重复并求和 |
| 划分（Partition） | 是否能将一组正整数分为和相等的两部分 | 每个元素的分组标记 | 检查每个元素恰好分配一次及两组和相等 |
| 0/1 背包判定版 | 是否能使总重量 ≤ W 且总价值 ≥ V | 被选物品的下标 | 累加重量、价值，检查阈值 |
| 集合覆盖（Set Cover） | 是否可选至多 k 个给定子集覆盖整个全集 | 被选子集列表 | 检查数量和并集是否覆盖全集 |
| 3-着色 | 是否能用至多三种颜色使每条边的两端异色 | 每个顶点的颜色 | 检查颜色数量和所有边 |

如图以邻接矩阵表示，团证据只需列出 k 个顶点，最多检查 `k(k−1)/2` 对边即可。验证是多项式时间，但如何找到合格顶点集合仍可能很难。

备考时重点对比：

| 容易混淆的一组 | 多项式可解版本 | NP 完全版本 |
| --- | --- | --- |
| 布尔可满足性 | 2-SAT | 3-SAT |
| 图着色 | 2-着色 | 一般图的 3-着色 |
| 遍历约束 | 欧拉回路：每条边一次 | 哈密顿回路：每个顶点一次 |
| 路径 | 非负权最短路阈值判定 | 一般图中长度至少 k 的简单路径判定 |
| 背包 | 可切分物品的分数背包优化 | 0/1 背包判定版 |

最长简单路径中的“简单”表示不重复顶点；在 DAG 上，最长路径可以按拓扑序做 DP，因此不能脱离图类型宣称所有最长路径问题都 NP 完全。

### 8. 属于 NP，但不能简单标为 NP 完全的例子

**图同构判定：** 给出两张图，判断是否能通过顶点重编号使两图完全一致。

- 证据：两图顶点之间的双射。
- 验证：检查双射是否保持邻接关系。
- 分类：属于 NP；目前未知是否属于 P，也未知是否 NP 完全。

这个例子说明，不能因为“有证据可验证”，就直接推导出“NP 完全”。

**coNP 补充：** 若一个判定问题的补问题属于 NP，则它属于 coNP。例如 UNSAT 问“布尔公式是否不可满足”，它是 SAT 的补问题，属于 coNP 完全；不能仅凭检查某份赋值就证明它属于 NP。目前 `NP=coNP` 是否成立仍未知。

### 9. 如何证明一个问题属于 NP 或 NP 完全

**证明属于 NP：**

1. 把问题明确写成“是否存在……满足条件”的判定形式。
2. 写出肯定实例的证据，例如赋值、顶点排列、子集或调度表。
3. 证明证据长度是输入长度的多项式。
4. 给出验证算法，说明时间为多项式。
5. 说明所有合法肯定实例都有证据，所有否定实例都无法通过验证。

**证明 NP 完全：**

1. 先证明目标问题 B 属于 NP。
2. 选取一个已知 NP 完全问题 A。
3. 构造多项式时间转换 `A ≤p B`。
4. 证明原实例回答“是”，当且仅当转换后实例回答“是”。

归约 `A ≤p B` 的含义是：如果会解 B，就能先转换再解 A。因此要证明 B 难，应当**把已知难问题归约到 B**。只证明 `B ≤p A` 不能据此证明 B 是 NP 难。

**例：Clique 归约到 Vertex Cover。**

对有 n 个顶点的图 G 及整数 k，构造补图 `Ḡ`，其边恰好是 G 中不存在的顶点对：

```text
G 有大小至少 k 的团
⇔ Ḡ 有大小至少 k 的独立集
⇔ Ḡ 有大小至多 n−k 的顶点覆盖
```

补图可在 `O(n²)` 时间构造。这个归约从已知 NP 完全的 Clique 出发证明 Vertex Cover 的 NP 难性，再结合顶点覆盖证据可以多项式验证，得到其 NP 完全性。

### 10. NP 和 DP 的区别

| 对比维度 | NP | DP |
| --- | --- | --- |
| 全称 | Nondeterministic Polynomial time | Dynamic Programming |
| 性质 | 判定问题的复杂度类别 | 算法设计方法 |
| 核心要求 | 肯定证据可在多项式时间内验证 | 定义状态、复用子问题结果、进行状态转移 |
| 是否保证快速求解 | 不保证 | 也不保证，取决于状态数和转移开销 |
| 典型联系 | 子集和、背包判定版、TSP 判定版都属于 NP | 这些问题可以设计 DP，但未必获得多项式时间算法 |

DP 的复杂度通常按“状态数 × 每个状态的转移开销”估算：

- 两个字符串的 LCS：`O(mn)` 状态和计算量，可在多项式时间内求解。
- 非负整数子集和：`O(nT)` DP，是伪多项式时间。
- TSP 的 Held–Karp 状态压缩 DP：`O(n²2^n)` 时间、`O(n2^n)` 空间，仍为指数规模。

NP 不能和 DP、贪心、DFS、BFS 作为同一层级的“算法类型”并列分类。

### 11. 为什么背包能用 DP，却仍然 NP 完全

以非负整数子集和为例，设 `dp[i][s]` 表示前 i 个数能否凑出 s：

```text
dp[i][s] = dp[i−1][s]
           或（s ≥ a[i] 且 dp[i−1][s−a[i]]）

dp[0][0] = 真
dp[0][s>0] = 假
```

状态数约为 `nT`，常写时间复杂度 `O(nT)`、滚动数组空间 `O(T)`。对具体例子 `[3,5,9,12]`、`T=17`，DP 可以找到 `5+12=17`。

但 T 以二进制输入时：

```text
T = 2^m 只需 m+1 位表示
遍历 0 到 T 却需要约 2^m 次操作
```

因此 `O(nT)` 对 T 的数值是多项式，对完整输入的二进制长度却不一定是多项式，这叫**伪多项式时间**。0/1 背包的容量 DP `O(nW)` 也有相同问题；精确位复杂度还要计入价值加法和比较的开销。

若题目限制 T 或 W 的数值受其他输入规模的多项式约束，该受限版本可以高效求解；这不会改变一般二进制编码版本的 NP 完全性。

## 笔试与面试应对

### 常考点及考法

| 考点 | 常见考法 | 判断依据 |
| --- | --- | --- |
| NP 定义 | NP 是否指非多项式时间 | 指非确定性多项式时间；检查肯定证据 |
| 集合关系 | P 和 NP 是否互斥 | `P ⊆ NP` |
| 典型问题分类 | SAT、最短路、背包、TSP 如何归类 | 明确问题版本和输入限制 |
| NP 完全证明 | 只给出多项式验证是否足够 | 还需要证明 NP 难 |
| 归约方向 | `A ≤p B` 谁至少一样难 | B 至少和 A 一样难 |
| DP 复杂度 | 背包 `O(nW)` 是否证明 `P=NP` | 检查 W 的二进制长度 |

### 解法与回答思路

先区分“问题类别”和“算法方法”，再明确判定版本。分类题按照“是否已知多项式可解 → 是否存在多项式证据验证 → 是否已知 NP 难”逐层判断。复杂度计算题始终检查输入编码，尤其是容量、金额、目标和等数值参数。

工程场景遇到 NP 难优化问题时，可以按输入规模和精度要求选择小规模穷举、分支限界、状态压缩 DP、伪多项式 DP、参数化算法、近似算法或启发式。近似算法需要给出相应质量保证；启发式通常不保证全局最优。不同问题的可近似性不同，不能统一认为都有高质量近似保证。

### 易错点

- **NP 不等于 NP 完全。** 最短路阈值判定属于 P，也属于 NP。
- **发现一种指数算法，不代表证明问题不属于 P。** 可能仍存在更好的算法。
- **验证可行性不等于验证最优性。** 检查 TSP 路线长度 ≤ K 很容易，证明它是全局最短并不由此得到。
- **NP 难不保证属于 NP。** 优化版 TSP 不能直接称为 NP 完全判定问题。
- **归约方向不能写反。** 证明新问题 B 难，要从已知难问题 A 归约到 B。
- **“无解”与“这一份证据不合格”不同。** 一份赋值不满足公式，不能推出公式不可满足。
- **DP 不保证多项式复杂度。** 状态压缩可产生指数状态，容量 DP 可为伪多项式。
- **问题限制会改变分类。** 2-SAT 与 3-SAT、一般图与 DAG 的最长路径需要区分。
- **非确定性不等于随机性。** 随机算法不是 NP 定义中的“猜测机器”。

### 判断题自测

1. “所有 P 问题都属于 NP。”——**正确**，可以直接多项式求解来验证。
2. “只要答案可以快速验证，该问题就一定 NP 完全。”——**错误**，只能据此证明属于 NP，还需证明 NP 难。
3. “2-SAT 不属于 NP，因为它很容易解。”——**错误**，它属于 P，因此属于 NP。
4. “某个 NP 完全问题若能多项式求解，则所有 NP 问题都能多项式求解。”——**正确**，使用多项式归约即可。
5. “0/1 背包的 `O(nW)` DP 证明了 P=NP。”——**错误**，该算法是伪多项式时间。
6. “一般图的哈密顿回路判定与欧拉回路判定同为 NP 完全。”——**错误**，后者属于 P。
7. “图同构已被证明是 NP 完全。”——**错误**，当前不能作此断言。
8. “NP 完全问题已被证明必须花费指数时间。”——**错误**，连 P 是否等于 NP 都尚未解决。

### 回答模板：NP 是什么，哪些问题属于 NP？

NP 是非确定性多项式时间的缩写，标准定义针对判定问题：对于答案为“是”的输入，存在多项式长度的证据，能够由确定性算法在多项式时间内验证。P 中的问题可以直接在多项式时间内求解，所以 P 是 NP 的子集。SAT、3-SAT、团、顶点覆盖、哈密顿回路、子集和，以及背包和旅行商的判定版本都是典型 NP 完全问题，因此属于 NP；可达性、2-SAT 和最短路阈值判定也属于 NP，但它们已有多项式算法，属于 P。NP 并不表示已经证明无法多项式求解，P 是否等于 NP 仍未知。

### 回答模板：NP 和 DP 有什么区别？

NP 是判定问题的复杂度类别，DP 是通过状态转移和复用子问题结果求解的算法设计方法，两者不在同一分类层级。NP 关心肯定证据能否多项式验证，DP 的效率取决于状态数和转移开销。LCS 的 DP 是多项式算法，子集和的 O(nT) DP 是伪多项式算法，旅行商的状态压缩 DP 仍然需要指数时间。所以一个问题可以属于 NP 并使用 DP 求解，但有 DP 解法并不意味着它一定能在多项式时间内求解。
