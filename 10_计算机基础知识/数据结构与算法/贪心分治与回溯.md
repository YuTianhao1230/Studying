# 贪心、分治与回溯

## 知识点解析

### 概述

贪心、分治和回溯是三种不同的算法组织方式：

- 贪心：每一步选择当前最优方案，依赖正确性证明保证全局最优。
- 分治：把问题拆成相互独立的同类子问题，分别求解后合并。
- 回溯：沿着决策树尝试选择，发现当前分支不可能得到合法或更优答案时撤销选择。

动态规划也会拆子问题，但会显式保存重叠状态；不能把“递归搜索”自动称为回溯，也不能因为某个局部选择看起来好就直接使用贪心。

### 贪心算法

贪心算法每一步只保留当前选择，不回溯修改已经做出的决定。要得到全局最优，通常需要两个性质：

1. **贪心选择性质**：存在一个最优解包含当前贪心选择。
2. **最优子结构**：做出当前选择后，剩余问题的最优解和原问题最优解能够组合。

第二个性质单独存在不够。动态规划也常有最优子结构，但它会保留多个子问题状态，不一定能只保留一个局部选择。

### 贪心正确性：交换论证

交换论证的基本步骤：

1. 取任意一个最优解。
2. 观察它与贪心解的第一个不同选择。
3. 用贪心选择替换原最优解中的对应选择。
4. 证明替换后仍然可行，且目标值不变或不变差。
5. 重复交换，得到包含贪心选择的最优解。

书写证明时应明确三个对象：贪心解 G、任意最优解 O，以及两者第一次不同的位置 i。交换步骤必须分别证明“交换后仍满足约束”和“目标值没有变差”；完成第 i 个位置后，再对剩余子问题归纳。只说“贪心选择给后面留下更多空间”是直觉，给出可行性与目标值比较才构成证明。

如果找不到这种证明，只能说明贪心可能有效，不能说明它一定正确。

### 区间调度

问题：选择尽可能多的互不重叠区间。正确贪心策略是每次选择结束时间最早且与当前已选区间兼容的区间。

原因：在所有可选区间中，结束时间最早的区间给后续留下的空间最大。可以把任意最优解的第一个区间替换成贪心选择，不会减少剩余可选区间数量。

算法：

```text
按结束时间升序排序
last_end = -∞
for interval in intervals:
    if interval.start >= last_end:
        选择 interval
        last_end = interval.end
```

排序复杂度 `O(n log n)`，扫描复杂度 `O(n)`，总时间 `O(n log n)`，额外空间取决于排序实现。

按开始时间最早、区间长度最短或结束时间最晚都不能普遍保证选择数量最多。

### 分数背包与 0/1 背包

分数背包允许切分物品，按单位重量价值 `value/weight` 从高到低选择即可，时间复杂度主要是排序的 `O(n log n)`。

0/1 背包每件物品只能选或不选，按单位价值排序的贪心可能失败，通常使用动态规划、回溯或其他方法。两者的区别不在“背包容量”本身，而在物品是否可切分。

### 霍夫曼编码

霍夫曼算法构造带权路径长度最小的二叉树：

1. 把每个字符的频率放入小根堆。
2. 每次取出频率最小的两个节点合并。
3. 把合并节点重新放入堆。
4. 直到只剩一个根节点。

每次合并的局部选择可以通过交换论证证明存在最优树包含频率最小的两个字符作为最深兄弟。使用堆时，构造复杂度为 `O(k log k)`，其中 k 是字符种类数。

构造完成后，可把左分支记为 0、右分支记为 1，从根到叶的路径作为字符编码。字符只放在叶节点，因此任一字符编码都不是另一个字符编码的前缀，所得编码可以无歧义地逐位解码，属于前缀编码，适合无损压缩。左右分支取值互换只会改变具体码字，不会改变带权路径长度。

### 分治算法

分治通常包含三个步骤：

1. Divide：把原问题拆成若干规模更小的同类子问题。
2. Conquer：递归解决子问题。
3. Combine：合并子问题答案。

适合分治的问题通常具有：

- 子问题规模递减。
- 子问题相互独立或重叠很少。
- 子问题答案可以高效合并。

### 归并排序

归并排序把数组分成左右两半，分别排序，再用双指针合并两个有序数组：

```text
merge_sort(left, right):
    if left >= right:
        return
    mid = (left + right) // 2
    merge_sort(left, mid)
    merge_sort(mid+1, right)
    merge(left, mid, right)
```

每层合并总成本 `O(n)`，递归深度 `O(log n)`，总时间 `O(n log n)`，数组实现辅助空间 `O(n)`。归并排序稳定，适合链表和外部排序。

### 快速选择

快速选择借鉴快速排序的 partition，但每次只递归进入包含第 k 个元素的一侧：

1. 选择 pivot。
2. 将小于 pivot 的元素放左侧，大于 pivot 的元素放右侧。
3. 根据 pivot 最终位置判断递归哪一侧。

随机 pivot 时平均时间 `O(n)`，最坏时间 `O(n²)`；递归栈平均 `O(log n)`，原地版本的额外数组空间可以是 `O(1)`。如果要求稳定或不允许最坏退化，需要选择其他方案。

若 partition 返回 pivot 的最终下标 p，寻找升序数组下标 k 的元素时可迭代缩小区间：

```text
left = 0, right = n-1
while left <= right:
    p = partition(a, left, right)
    if p == k: return a[p]
    if p < k: left = p+1
    else: right = p-1
```

递归或循环都不能再次包含 p。每轮划分成本与当前区间长度成正比，随机枢轴的期望总成本为 `O(n)`；连续产生极端划分时为 `O(n²)`。求“第 k 大”时要先统一 k 是从 0 还是从 1 开始，并转换成升序目标下标。

### 回溯算法

回溯在决策树上深度优先搜索。每次做一个选择，递归处理剩余问题，返回前撤销选择：

```text
backtrack(state):
    if state 是完整答案:
        记录答案
        return
    for choice in 当前可选项:
        if choice 不满足约束:
            continue
        做出 choice
        backtrack(更新后的 state)
        撤销 choice
```

回溯的状态通常包括当前位置、已选元素、可选范围、约束集合和当前目标值。撤销操作必须与做选择完全对应，否则后续分支会受到前一条路径污染。

### 回溯的剪枝

剪枝是在不影响正确性的前提下，提前排除不可能产生答案或不可能超过当前最优解的分支：

- 可行性剪枝：当前已经违反约束。
- 上界剪枝：即使剩余部分全部取最优，也无法超过当前答案。
- 下界剪枝：当前代价已经不可能优于最优解。
- 对称性剪枝：等价排列只保留一种。
- 去重剪枝：同一层跳过相同选择。
- 记忆化：相同状态不再重复搜索，此时算法可能转化为 DP。

剪枝能显著降低实际搜索量，但除非能给出严格上界，否则不能把回溯的最坏复杂度从指数直接写成多项式。

### 典型回溯模型

#### 全排列

每层选择一个还未使用的元素，路径长度达到 n 时得到一个排列。最坏需要枚举 `n!` 个结果，时间至少与输出规模相关。

```text
permute(path, used):
    if len(path) == n: 记录 path
    for i in [0, n):
        if used[i]: continue
        used[i] = true; path.push(a[i])
        permute(path, used)
        path.pop(); used[i] = false
```

#### 子集与组合

对每个元素做“选/不选”或从起点向后选择，通常有 `2^n` 或组合数量级的状态。需要去重时，先排序，再在同一层跳过相同值。

```text
subsets(start, path):
    记录 path
    for i in [start, n):
        选择 a[i]; subsets(i+1, path); 撤销

combine(start, path, k):
    if len(path) == k: 记录 path; return
    for i in 闭区间 [start, n-(k-len(path))]:
        选择 a[i]; combine(i+1, path, k); 撤销
```

组合循环上界 `n-(k-len(path))` 保证剩余元素足够填满路径。排列用 `used` 从所有位置选，组合与子集用 `start` 只向后选，这是三类模板最关键的差别。

#### N 皇后

按行放置皇后，用列集合、主对角线和副对角线判断冲突。每行放置一个皇后后递归下一行，无法放置时回退。

#### 子集和

对每个元素选择加入或不加入，并在当前和超过目标时剪枝。若元素为非负数，排序后可用“当前和加后续最小/最大可能值”做界；一般问题可能仍是指数搜索，DP 则可能是伪多项式。

### 回溯去重与输出敏感复杂度

去重前通常先排序。层内去重用于阻止同一父状态选择相同值，例如组合、子集可写 `i > start and a[i] == a[i-1]` 时跳过；不应跨层无条件跳过相同值，因为不同深度选择相同值可能构成合法答案。排列还要用 `used[i]` 防止同一元素在一条路径中重复使用，并用 `i > 0 and a[i] == a[i-1] and not used[i-1]` 跳过同层的重复值。`used` 管的是路径上的元素占用，排序后的条件才是在消除重复分支。

枚举问题的复杂度必须包含复制输出的成本：

- 全排列有 `n!` 个长度为 n 的结果，时间为 `Theta(n*n!)`。
- 全部子集的元素总量为 `Theta(n*2^n)`，因此输出所有子集的时间也是该量级。
- 输出全部大小为 k 的组合需要 `Theta(k*C(n,k))`。

这些下界由输出规模决定，剪枝不能把“必须输出全部结果”的算法降为低于输出量级。若不计结果存储，回溯路径和递归栈通常为 `O(n)`；保存全部结果还要计入上述输出空间。

### 贪心、分治、回溯、DP 对比

| 方法 | 核心动作 | 是否保存多个状态 | 典型复杂度 | 典型题 |
| --- | --- | --- | --- | --- |
| 贪心 | 每步保留局部最优 | 否 | 常为多项式 | 区间调度、霍夫曼 |
| 分治 | 拆独立子问题再合并 | 通常否 | 由递推式决定 | 归并、快排 |
| 回溯 | 搜索决策树并撤销 | 可选记忆化 | 常为指数 | 全排列、N 皇后 |
| DP | 保存重叠子问题结果 | 是 | 状态数×转移 | 背包、LCS |

题目如果要求所有方案，回溯常是自然选择；题目如果只求最优值且子问题重复，DP 往往更合适；题目如果可证明局部选择安全，贪心更高效。

### 算法选择流程

1. 题目是否要求所有解或具体方案？是，先考虑回溯、搜索或构造。
2. 子问题是否独立且合并容易？是，考虑分治。
3. 是否存在重叠状态？是，考虑 DP 或记忆化搜索。
4. 是否能证明局部最优选择不损失全局最优？是，考虑贪心。
5. 如果都不满足，考虑图搜索、二分答案、数学性质或数据结构优化。

## 解题步骤

### 贪心题

1. 明确每一步的候选集合和局部目标。
2. 判断是否存在贪心选择性质。
3. 用交换论证或其他方式证明。
4. 排序或使用堆维护候选。
5. 检查相等值、边界和不可行情况。

### 分治题

1. 确定子问题如何划分。
2. 处理最小规模基例。
3. 写出递推式。
4. 设计合并过程。
5. 检查子问题是否重叠，若重叠则比较 DP 是否更合适。

### 回溯题

1. 定义路径、选择列表和结束条件。
2. 明确每层决策代表什么。
3. 在递归前做选择。
4. 递归返回后撤销选择。
5. 增加不会改变答案的剪枝和去重。

## 易错点

- 贪心没有证明不能直接当作正确算法。
- 0/1 背包不能套用分数背包的单位价值贪心。
- 分治子问题有大量重叠时，直接递归可能指数爆炸。
- 回溯必须撤销状态，否则不同分支会互相污染。
- 同层去重和跨层去重条件不同，排序通常是去重前提。
- 剪枝只能减少实际搜索，不能随意修改最坏复杂度结论。
- 快速选择平均 `O(n)` 不代表最坏也是 `O(n)`。
- 输出所有排列/组合时，输出本身的规模也必须计入复杂度。

## 自测

1. 最大数量区间调度应按结束时间升序选择，而不是按开始时间升序。
2. 0/1 背包不能因为物品单位价值高就一定优先选择。
3. 归并排序的合并阶段使用两个有序指针。
4. 回溯的撤销操作应放在递归调用之后。
5. 对 `[1,1,2]` 求不重复排列时，同一层的两个 `1` 只能选择一次。

## 面试应对

### 如何证明一个贪心算法正确？

回答思路：明确贪心选择、任意最优解和第一次不同的位置，再证明交换的可行性与目标值。

回答模板：

我会先说明贪心选择和剩余子问题，再证明存在一个最优解包含当前贪心选择。常用交换论证：取任意最优解，把它与贪心选择冲突的位置替换成贪心选择，证明替换后仍然可行且目标值不变或不变差。然后对剩余问题重复这个过程，得到完整的最优性证明。

### 回溯和动态规划有什么区别？

回答思路：比较搜索空间、重复状态、目标类型和是否保存结果。

回答模板：

回溯是在决策树上枚举选择，遇到不合法或不可能更优的分支就剪枝，通常适合求所有方案或组合结构；动态规划把具有重叠的子问题状态保存下来，通过状态转移避免重复计算，通常适合求最优值、方案数或可行性。相同的回溯状态如果大量重复，可以通过记忆化变成 DP。

### 分治和动态规划有什么区别？

回答思路：重点判断子问题是否重叠，以及答案是合并还是状态转移得到。

回答模板：

分治要求子问题通常相互独立，分别求解后合并，例如归并排序；动态规划处理的子问题可能重叠，因此需要保存状态避免重复计算，例如 LCS 和背包。如果分治递归中同一个子问题反复出现，就应考虑记忆化或改写成 DP。

### 排列、组合和子集的回溯模板如何区分并去重？

回答思路：从每层候选范围、路径状态、层内去重和输出规模回答。

回答模板：

排列的每一层都从全部元素中选择，用 `used` 防止同一元素在一条路径中重复使用；组合和子集用 `start` 限制只向后选择，组合在路径长度达到 k 时记录，子集则在每个节点都记录。存在重复值时先排序，再跳过同一层中与前一个值相同的候选；不能跨层无条件跳过相同值。复杂度还要计算输出，全排列是 `Theta(n*n!)`，全部子集是 `Theta(n*2^n)`，大小为 k 的组合是 `Theta(k*C(n,k))`。
