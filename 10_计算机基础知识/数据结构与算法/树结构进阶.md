# 树结构进阶

## 知识点解析

### 概述

树结构通过父子关系表示层次数据。二叉搜索树适合内存中的有序查找，但可能退化；AVL 和红黑树通过平衡保证对数级操作；Trie 通过字符路径支持前缀查询；B 树和 B+ 树通过高扇出减少磁盘 I/O，是数据库和文件系统索引的重要基础。

本卡片重点比较“树的排序关系”“树的平衡方式”“树的节点组织方式”和“数据所在位置”，不要把所有树都简单理解为二叉树。

### 基本术语

- 节点的度：该节点拥有的孩子数量。
- 叶节点：没有孩子的节点。
- 深度：从根到该节点经过的边数。
- 高度：从该节点到最深叶节点经过的边数。
- 子树：某个节点及其全部后代组成的树。
- 平衡：通常指左右子树高度差或整体路径长度受到约束。
- 扇出：一个内部节点可以拥有的孩子数量。

完全二叉树适合用数组表示；一般树和稀疏二叉树通常需要指针或邻接结构。堆是完全二叉树，但它只保证父子优先级关系，不保证整个序列有序。

### 二叉搜索树

BST 满足：

```text
左子树所有关键字 < 根关键字 < 右子树所有关键字
```

如果允许重复值，必须预先约定重复值放左侧、右侧或额外记录计数。BST 的查找、插入和删除复杂度取决于树高 h：

| 操作 | 平均情况 | 最坏情况 |
| --- | --- | --- |
| 查找 | `O(log n)`，随机或较平衡时 | `O(n)`，退化成链表 |
| 插入 | `O(log n)` | `O(n)` |
| 删除 | `O(log n)` | `O(n)` |
| 中序遍历 | `O(n)` | `O(n)` |

删除节点时分三种情况：

1. 叶节点：直接删除。
2. 只有一个孩子：用孩子替代该节点。
3. 有两个孩子：用右子树最小节点或左子树最大节点替代，再删除替代节点。

BST 的中序遍历是有序序列，这是验证 BST、求第 k 小元素和范围查询的基础。

### AVL 树

AVL 是严格平衡的二叉搜索树。对每个节点：

```text
平衡因子 BF = height(left) - height(right)
BF ∈ {-1, 0, 1}
```

插入或删除后，如果某节点的平衡因子超出范围，就通过旋转恢复平衡。

| 失衡类型 | 结构 | 修复 |
| --- | --- | --- |
| LL | 插入左孩子的左子树 | 对失衡节点右旋 |
| RR | 插入右孩子的右子树 | 对失衡节点左旋 |
| LR | 插入左孩子的右子树 | 先左旋左孩子，再右旋失衡节点 |
| RL | 插入右孩子的左子树 | 先右旋右孩子，再左旋失衡节点 |

AVL 的高度为 `O(log n)`，查找、插入和删除均为 `O(log n)`。它平衡更严格，查询路径更短，但插入和删除可能触发更多旋转，更新频繁时维护成本较高。

### 红黑树

红黑树是通过颜色约束控制高度的近似平衡二叉搜索树。常见性质：

1. 每个节点是红色或黑色。
2. 根节点为黑色。
3. 空叶节点（NIL）视为黑色。
4. 红节点不能有红色孩子。
5. 从任一节点到其所有后代 NIL 叶节点的路径，黑节点数相同。

这些性质保证红黑树高度为 `O(log n)`，因此查找、插入和删除均为 `O(log n)`。插入和删除通过重新着色与旋转恢复性质，具体修复分支比 AVL 更多，但单次更新的平衡维护通常更宽松。

### AVL 与红黑树

| 对比项 | AVL | 红黑树 |
| --- | --- | --- |
| 平衡程度 | 更严格 | 相对宽松 |
| 树高 | 通常更低 | 上界 `O(log n)` |
| 查找 | 通常更快 | 稳定对数级 |
| 更新 | 旋转可能更多 | 更新维护通常更灵活 |
| 典型场景 | 查询多、更新少 | 插入删除频繁的有序映射 |
| 核心手段 | 平衡因子和旋转 | 颜色约束、旋转和重新着色 |

两者都不是完全有序数组，也不能直接通过下标随机访问。题目只问“保证查找、插入、删除 `O(log n)` 的二叉搜索树”时，AVL 和红黑树都可能正确；若问严格平衡，优先选 AVL。

### Trie 字典树

Trie 按字符串从左到右的字符建立路径。具有相同前缀的字符串共享路径：

```text
tea
  ├── m
  └── r
```

每个节点通常包含：

- `children`：从当前字符到子节点的映射。
- `is_end`：是否有字符串在此节点结束。
- 可选的计数、权重、出现次数或词频。

设字符串长度为 L：

| 操作 | 复杂度 |
| --- | --- |
| 插入 | `O(L)` |
| 查找完整单词 | `O(L)` |
| 查询前缀是否存在 | `O(L)` |
| 删除 | `O(L)`，必要时回收无分支节点 |

复杂度与字符串长度有关，通常与词典中已有字符串数量 n 无关；空间复杂度约为所有字符总数，使用数组孩子指针时还要乘以字符集大小，使用哈希映射则更节省稀疏空间但常数不同。

Trie 适合自动补全、前缀统计、词典匹配和字符串集合查询，不适合只需要判断一个字符串是否存在且内存极其紧张的场景，此时哈希表可能更简单。

### B 树

B 树是多路平衡搜索树。一个内部节点可包含多个关键字和多个孩子，所有叶节点通常处于同一层。它通过提高扇出降低树高，减少磁盘随机 I/O。

以阶数 m 的 B 树为例，非根内部节点通常至少有 `ceil(m/2)` 个孩子，最多有 m 个孩子；具体最小占用约束以题目定义为准。插入节点溢出时分裂，删除节点不足时从兄弟借关键字或合并节点。

若树高为 h、节点扇出为 m：

```text
h = O(log_m n)
```

查找、插入和删除通常需要 `O(log_m n)` 次节点访问，节点内部查找还取决于使用线性扫描还是二分查找。

### B+ 树

B+ 树是数据库索引中常见的多路平衡树：

- 非叶节点只保存分隔键和孩子指针。
- 所有真实数据或数据行指针都在叶节点。
- 叶节点通常按关键字有序并通过链表连接。
- 所有叶节点处于同一层。

B+ 树的优势：

1. 内部节点不保存完整数据，一个磁盘页能容纳更多键，树高更低。
2. 所有数据集中在叶节点，查询路径结构统一。
3. 叶节点链表使范围查询和排序扫描效率高。
4. 高扇出减少磁盘 I/O 次数。

### B 树与 B+ 树

| 对比项 | B 树 | B+ 树 |
| --- | --- | --- |
| 数据存放 | 内部节点和叶节点都可存 | 主要在叶节点 |
| 叶节点链表 | 不一定有 | 通常有 |
| 单点查询 | 可能在内部节点提前结束 | 通常走到叶节点 |
| 范围查询 | 需要多次回到树结构 | 叶链表顺序扫描方便 |
| 内部节点扇出 | 相对较低 | 通常更高 |
| 数据库索引 | 可用但不如 B+ 常见 | 常见选择 |

B+ 树适合数据库索引不只是因为“树更平衡”，更重要的是磁盘页、扇出、数据集中在叶节点和叶链表共同降低了 I/O 成本。

### 结构选型

| 需求 | 更合适的结构 | 原因 |
| --- | --- | --- |
| 内存中有序查找且更新频繁 | 红黑树 | 对数级操作，更新维护相对灵活 |
| 内存中查询远多于更新 | AVL | 更严格平衡，查找路径通常更短 |
| 判断字符串是否存在 | 哈希表或 Trie | 哈希表简单，Trie 可继续做前缀 |
| 前缀补全和词频统计 | Trie | 路径天然表示前缀 |
| 磁盘上的范围索引 | B+ 树 | 高扇出和叶节点链表 |
| 只维护最大/最小优先级 | 堆 | 不需要维护全部有序关系 |

## 笔试常考

- BST 中序遍历是否有序。
- BST 删除三种情况。
- AVL 四种失衡类型和旋转方向。
- 红黑树的五条性质及其对数高度。
- AVL 与红黑树的平衡程度和适用场景。
- Trie 的插入、查找和前缀查询复杂度。
- B 树与 B+ 树的数据存放、叶链表和范围查询。
- 为什么数据库索引常用 B+ 树而不是普通二叉树或哈希。
- 完全二叉树、BST、堆、AVL、红黑树的区别。

## 易错点

- BST 平均 `O(log n)` 不代表最坏也是 `O(log n)`，未经平衡可能退化为 `O(n)`。
- AVL 的平衡因子通常是左高减右高，不同教材若定义相反要同步改变旋转判断。
- 红黑树不是“每条根到叶路径节点数相同”，而是黑节点数量相同。
- Trie 的 `O(L)` 不代表空间一定小，字符集和节点共享方式会影响内存。
- B+ 树的内部节点通常不存完整数据，叶节点链表是范围查询的重要原因。
- 堆只保证父子优先级关系，不等价于 BST 或完整排序数组。

## 自测

1. 插入序列 `30, 20, 10` 会产生 LL 失衡，AVL 需要对 30 右旋。
2. 插入序列 `10, 20, 30` 会产生 RR 失衡，AVL 需要对 10 左旋。
3. Trie 中“car”和“cart”共享 `c-a-r` 路径，但 `r` 和 `t` 处的结束标记不同。
4. B+ 树范围查询定位到起始叶节点后，可以沿叶节点链表顺序扫描。
5. 红黑树和 AVL 都能保证对数高度，但红黑树的平衡约束更宽松。

## 面试应对

### 为什么数据库索引常用 B+ 树？

B+ 树的非叶节点只保存分隔键和指针，一个磁盘页能容纳更多键，因此树高更低、查询需要的磁盘 I/O 更少。所有数据集中在叶节点，叶节点又按键有序并通过链表连接，所以范围查询可以定位起点后顺序扫描。它同时兼顾单点查询、范围查询和磁盘页访问效率。

### AVL 和红黑树怎么选？

AVL 平衡更严格，树高通常更低，适合查询远多于更新的场景；红黑树平衡约束更宽松，插入和删除时维护成本通常更低，适合更新频繁的有序映射。两者都能保证查找、插入和删除是 `O(log n)`，具体选择还要结合读写比例和实现成本。

### Trie 和哈希表有什么区别？

哈希表按完整 key 映射，平均查找可以是 `O(1)`，但不直接支持按字典序和前缀遍历。Trie 按字符建立共享前缀路径，查找和插入按字符串长度 `O(L)`，天然支持前缀查询，但空间可能更大。需要自动补全、前缀统计时更适合 Trie，只做完整 key 查找时哈希表通常更简单。
