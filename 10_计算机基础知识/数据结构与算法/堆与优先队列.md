# 堆与优先队列

## 知识点解析

### 概述

本文整理堆的数组表示、建堆、插入、删除，以及优先队列、Top K、多路归并和数据流中位数等应用。

### 堆

大根堆的父节点不小于子节点，堆顶是最大值；小根堆的父节点不大于子节点，堆顶是最小值。堆顶查询是 O(1)，插入和删除堆顶是 O(log n)，建堆可以做到 O(n)。

堆只保证父子之间的大小关系，不保证左右子树内部整体有序。因此不能在堆中使用[二分查找](<二分查找.md#二分查找>)，也不能认为第二大元素一定在固定位置。

### 堆的数组表示

完全二叉树适合使用数组存储。从 0 开始编号时：

```text
父节点：(i - 1) // 2
左孩子：2 * i + 1
右孩子：2 * i + 2
```

最后一个非叶子节点下标是 `n // 2 - 1`。自底向上建堆时，从该位置到根节点依次执行向下调整。

建堆不是 `n` 次完整的 `O(log n)` 调整。高度为 `h` 的节点至多约有 `n / 2^(h + 1)` 个，因此总工作量满足：

```text
sum(h * n / 2^(h + 1), h >= 1) = O(n)
```

多数节点靠近叶子，只需下沉很少层，所以自底向上建堆是 `O(n)`；把元素逐个插入空堆才是 `O(n log n)`。

### 插入与删除

- 插入：把新元素放到数组末尾，再不断与父节点比较并向上调整，复杂度 `O(log n)`。
- 删除堆顶：用末尾元素覆盖堆顶，缩小堆长度，再向下调整，复杂度 `O(log n)`。
- 查询堆顶：直接访问数组首元素，复杂度 `O(1)`。

向下调整时，大根堆要选择两个孩子中较大的一个交换；小根堆选择较小的一个。只与某个固定孩子交换会破坏堆性质。

以小根堆为例，可复用的调整逻辑是：

```text
sift_up(i):
    while i > 0 and heap[i] < heap[parent(i)]:
        swap(i, parent(i))
        i = parent(i)

sift_down(i, size):
    while left(i) < size:
        child = 左右孩子中值更小者
        if heap[i] <= heap[child]: break
        swap(i, child)
        i = child
```

大根堆只需反转比较方向。`sift_up` 修复“新节点与祖先”的关系，`sift_down` 修复“替换后的根与后代”的关系，两者最多经过树高，复杂度均为 `O(log n)`。

### 优先队列

优先队列不是按进入顺序出队，而是每次取优先级最高或最低的元素。它常用于任务调度、最短路、Top K 和多路归并。

堆是优先队列最常见的实现，但二者不是同一个概念：优先队列是抽象数据类型，堆是实现它的数据结构。

## 笔试常考

| 题型 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 建堆 | 给定序列，写出大根堆或小根堆 | 从最后一个非叶子节点开始向下调整 |
| 堆排序 | 写出每趟交换后的序列 | 建大根堆，堆顶与末尾交换并缩小范围 |
| Top K | 最大 K 个或最小 K 个 | 维护大小为 K 的反向堆 |
| 第 K 大 | 数据流不断到达 | 维护大小为 K 的小根堆 |
| 合并 K 个有序序列 | 每次取当前最小元素 | 堆中保存每个序列的当前头部 |
| 数据流中位数 | 随时查询中位数 | 大根堆维护较小一半，小根堆维护较大一半 |
| 最短路 | 每次取当前距离最小节点 | Dijkstra 使用小根堆 |

### Top K

求最大的 K 个元素时，维护大小为 K 的小根堆：

1. 前 K 个元素入堆。
2. 后续元素若不大于堆顶，直接丢弃。
3. 若大于堆顶，则替换堆顶并调整。
4. 遍历结束后，堆中就是最大的 K 个元素。

使用小根堆是因为堆顶代表当前 Top K 中最小、最应该被淘汰的元素。时间复杂度为 `O(n log K)`，空间复杂度为 `O(K)`。反过来，求最小的 K 个元素应维护大小为 K 的大根堆，让当前候选中的最大值位于堆顶、最先被淘汰。

### 海量数据 Top K

数据量无法一次装入内存时，仍可顺序扫描文件并维护大小为 K 的堆，只要单条记录可流式读取且内存能容纳 K 个候选，内存占用仍为 `O(K)`。若需要并行处理或单机扫描压力过大，可以分块读取或按哈希分桶：

1. 每个分块或分桶独立计算局部 Top K。
2. 汇总所有局部候选，再计算一次全局 Top K。
3. 分桶前估算数据倾斜，避免某个桶仍然超过内存或成为并行瓶颈。

若还要求完整有序结果，或 K 已接近 n，可以使用外部排序：内存中分别排序各数据块并写成有序段，再通过多路归并读取；只求 Top K 时，归并达到 K 个结果即可停止。选择流式堆、分块/分桶还是外部排序，取决于 K 的大小、是否要求全序、可用内存和并行条件。

### K 路归并

合并 K 个有序序列时，先把每个非空序列的首元素及其“序列编号、元素下标”放入小根堆。每次弹出全局最小元素后，只把它所在序列的下一个元素入堆，因此堆大小始终不超过 K：

```text
将每个序列的首元素入堆
while heap 非空:
    value, sequence_id, index = 弹出堆顶
    输出 value
    如果该序列还有下一个元素：将下一个元素入堆
```

若所有序列共 N 个元素，每个元素恰好入堆和出堆一次，时间复杂度为 `O(N log K)`，额外空间为 `O(K)`。保存来源位置是为了弹出后知道应从哪个序列补入元素。

### 数据流中位数

使用两个堆：

- 大根堆 `lower` 保存较小的一半元素。
- 小根堆 `upper` 保存较大的一半元素。
- 保持 `len(lower) == len(upper)` 或 `len(lower) == len(upper) + 1`。
- 大根堆堆顶不能大于小根堆堆顶。

插入 `x` 时，若 `lower` 为空或 `x` 不大于 `lower` 堆顶，则放入 `lower`，否则放入 `upper`。若 `lower` 比 `upper` 多两个元素，把 `lower` 堆顶移到 `upper`；若 `upper` 更大，把 `upper` 堆顶移到 `lower`。这样较小一半始终可比另一半多一个元素。

元素个数为奇数时，中位数是 `lower` 堆顶；为偶数时，中位数是两个堆顶的平均值。单次插入与再平衡为 `O(log n)`，查询为 `O(1)`。

### 易错点

- 建堆是 `O(n)`，不是把 n 个元素逐个插入得到的 `O(n log n)`。
- Python `heapq` 默认是小根堆；实现大根堆常存负数。
- 求最大 K 个元素使用大小为 K 的小根堆，不是大根堆。
- 堆排序是不稳定排序。
- 堆顶有序不代表整个数组有序。

## 面试应对

### 堆和优先队列有什么区别？

回答思路：区分抽象接口和具体实现。

回答模板：

优先队列是一种抽象数据类型，每次取出优先级最高或最低的元素；堆是一种满足父子大小关系的完全二叉树，是实现优先队列最常见的数据结构。使用堆后，查看最高优先级元素是 O(1)，插入和删除堆顶是 O(log n)。优先队列也可以用有序数组等结构实现，只是复杂度取舍不同。

### Top K 怎么做？

回答思路：堆，复杂度。

回答模板：

Top K 常用堆。求最大的 K 个数时，用大小为 K 的小根堆，遍历数据时如果当前元素比堆顶大，就替换堆顶并调整堆。这样堆里始终保留当前最大的 K 个元素，时间复杂度是 O(n log K)，空间复杂度是 O(K)。当 K 远小于 n 时，比全量排序更划算。

### 为什么自底向上建堆是 O(n)？

回答思路：说明多数节点位于底层，调整高度很小。

回答模板：

不能简单按 n 个节点乘每次 O(log n) 计算，因为自底向上建堆时，大多数节点都靠近叶子，向下调整的高度很小。高度为 h 的节点数量大约按指数减少，把各层的节点数乘调整高度求和后得到 O(n)。逐个插入建堆才是 O(n log n)。

### 数据流中位数怎么维护？

回答思路：使用两个堆分别维护较小和较大的一半。

回答模板：

我会用一个大根堆维护较小的一半元素，用一个小根堆维护较大的一半，并保证两个堆大小差不超过 1，且大根堆堆顶不大于小根堆堆顶。每次插入后通过移动堆顶重新平衡。元素总数为奇数时取较大堆的堆顶，偶数时取两个堆顶平均值。单次插入是 O(log n)，查询中位数是 O(1)。
