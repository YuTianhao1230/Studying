# 数据表示

## 知识点解析

### 概述

本文整理计算机中的容量与速率单位、进制转换、原码反码补码、整数溢出、IEEE 754 浮点数和字节序。

### 容量与速率单位

存储容量题通常按二进制换算：

```text
1 KiB = 2^10 B
1 MiB = 2^20 B
1 GiB = 2^30 B
```

很多教材和题目会把 `KB、MB、GB` 也按上述二进制口径使用，作答时应以题目约定为准；严格的国际单位制中，`kB、MB、GB` 分别表示 `10^3、10^6、10^9 B`。网络带宽通常采用十进制速率：

```text
1 kb/s = 10^3 b/s
1 Mb/s = 10^6 b/s
1 Gb/s = 10^9 b/s
1 B = 8 b
```

计算传输时间时必须先统一字节与比特。例如用 `100 Mb/s` 的链路传输 `100 MiB` 数据，忽略协议开销时：

```text
传输时间 = 100 × 2^20 × 8 / (100 × 10^6) ≈ 8.39 s
```

### 进制换算

二进制转十进制按权展开，十进制转二进制用除 2 取余倒序。八进制每 1 位对应 3 位二进制，十六进制每 1 位对应 4 位二进制。

```text
101101B = 45D
101101B = 55O
101101B = 2DH
```

### 原码、反码、补码

正数的原码、反码、补码相同。负数反码是符号位不变、数值位取反；补码是反码加 1。计算机使用补码，是因为补码能把加法和减法统一成加法，并且只有一个 0。

n 位有符号补码范围：

```text
-2^(n-1) 到 2^(n-1)-1
```

固定字长决定结果如何截断。例如 8 位补码中，`5 = 00000101`，按位取反加 1 得 `-5 = 11111011`；`127 + 1` 的 8 位结果为 `10000000`，按有符号解释是 `-128`，发生有符号溢出。补码最小值 `10000000` 表示 `-128`，没有对应的 `+128`。

### 溢出

有符号与无符号运算使用相同的固定宽度加法电路，但溢出判据不同。两个正数相加后，若截断结果的符号位为 1，则发生正溢出；两个负数相加后，若截断结果的符号位为 0，即结果为非负数（包括 0），则发生负溢出。一个正数和一个负数相加不会发生有符号溢出。例如 8 位补码中，`-128 + (-128)` 的固定宽度结果为 `00000000`，虽然截断后是 0，真实结果 -256 超出表示范围，仍属于负溢出。无符号加法溢出看最高位是否产生进位，无符号减法则看是否发生借位。例如 8 位 `11111111 + 00000001 = 00000000` 对无符号数是 `255+1` 溢出，但按有符号数解释为 `-1+1=0`，没有有符号溢出。

### 浮点数

浮点数由符号位、指数位和尾数位组成。它能表示很大或很小的数，但不能精确表示所有十进制小数。例如 0.1 在二进制中无法有限表示，因此浮点运算可能产生误差。

### 大端和小端

大端序把高位字节放在低地址，小端序把低位字节放在低地址。网络字节序通常是大端，x86 常用小端。

### 常见计算题

#### 进制转换

- 二进制转十进制：整数部分按 `2^0、2^1...` 展开，小数部分按 `2^-1、2^-2...` 展开。
- 十进制整数转二进制：除 2 取余，余数倒序。
- 十进制小数转二进制：反复乘 2，依次取整数部分。
- 二进制转八进制：从小数点向两侧每 3 位一组。
- 二进制转十六进制：从小数点向两侧每 4 位一组。

#### 补码运算

求负数补码：

1. 按固定字长写出对应正数的补码。
2. 包括最高位在内逐位取反。
3. 末位加 1。

例如求 `-5` 的 8 位补码：

```text
+5：    00000101
取反：  11111010
加 1：  11111011
```

因此 `-5` 的 8 位补码是 `11111011`。

补码转真值时，若符号位为 1，可以再次取反加 1 得到绝对值，再加负号。

#### 溢出判断

同号数相加后，截断结果的符号位与操作数符号位不同时发生有符号溢出：

```text
正 + 正 -> 结果符号位为 1：正溢出
负 + 负 -> 结果符号位为 0（包括结果为 0）：负溢出
```

也可以比较符号位的进位和最高数值位的进位，两者不同则溢出。无符号数溢出通常看最高位进位。

### IEEE 754 浮点数

单精度浮点数通常由 1 位符号、8 位阶码和 23 位尾数组成；双精度通常由 1 位符号、11 位阶码和 52 位尾数组成。

规格化数可理解为：

```text
(-1)^S × 1.fraction × 2^(exponent - bias)
```

单精度偏置为 127，双精度偏置为 1023。对单精度字段 `E` 和尾数字段 `F`：

- `1 <= E <= 254`：规格化数，值为 `(-1)^S × 1.F × 2^(E-127)`。
- `E = 0, F != 0`：非规格化数，值为 `(-1)^S × 0.F × 2^(-126)`；没有隐藏的前导 1，用于逐渐下溢。
- `E = 0, F = 0`：正零或负零。
- `E = 255, F = 0`：正无穷或负无穷。
- `E = 255, F != 0`：NaN；它与任何值（包括自身）的有序比较通常都为假。

做题步骤：

1. 把十进制数转换为二进制。
2. 规格化成 `1.x × 2^e`。
3. 写符号位。
4. 将真实指数加偏置得到阶码。
5. 保存小数点后的尾数并按规则舍入。

默认舍入模式通常是“舍入到最近， ties to even”，即恰好位于中点时让保留结果的最低位为偶数；另外还有向零、向正无穷和向负无穷舍入。舍入可能使尾数进位并进一步改变指数，不能简单截断多余位。

紧凑例子：把 `13.25` 编码为 IEEE 754 单精度。`13.25 = 1101.01B = 1.10101 × 2^3`，所以符号位 `S=0`，阶码 `E=3+127=130=10000010B`，尾数为 `10101000000000000000000`。拼接得到：

```text
0 | 10000010 | 10101000000000000000000
= 0x41540000
```

反向解码时取出 `S=0、E=130、F=101010...`，恢复隐藏前导 1 后的有效数为 `1.10101B`，得到 `(+1) × 1.10101B × 2^3 = 13.25`。

### 常见考法与解题策略

| 题型 | 解题方法 |
| --- | --- |
| 进制转换 | 按权展开、除基取余、分组转换 |
| 补码范围 | n 位有符号补码为 `[-2^(n-1), 2^(n-1)-1]` |
| 补码加减 | 统一按二进制加法，截取固定字长后判断溢出 |
| 浮点编码 | 符号、规格化、阶码加偏置、填写尾数 |
| 浮点误差 | 判断十进制小数能否有限表示为二进制 |
| 大小端 | 将多字节值拆成字节，再按低地址顺序排列 |

## 笔试常考

- 区分二进制存储容量与十进制网络速率，统一 `B`、`b` 后计算数据量或传输时间。
- 二、八、十、十六进制的整数与小数转换。
- 固定字长补码的编码、取值范围、加减结果和截断。
- 分别按符号变化、最高位进位或借位判断有符号与无符号溢出。
- 编码或解码 IEEE 754，处理偏置、隐藏位、舍入及指数全 0/全 1 的特殊值。
- 将多字节整数拆成字节，判断大端、小端内存布局和网络字节序。

### 易错点

- `B` 表示字节，`b` 表示比特，`1 B = 8 b`。
- `KiB` 明确表示 `2^10 B`，`kB` 严格表示 `10^3 B`；题目写 `KB` 时要先确认其约定。
- n 位补码最小值没有对应的正数表示。
- 移位和溢出必须结合有符号或无符号语义判断。
- 浮点数比较不宜直接依赖严格相等，通常使用误差范围。
- 大端和小端只影响多字节数据的字节排列，不改变位内顺序。

## 面试应对

### 为什么补码的正负范围不对称？

回答思路：固定编码数量、唯一的零和最高位权重。

回答模板：

补码只有一个零，n 位的 `2^n` 种编码被分成 `2^(n-1)` 个负数、`2^(n-1)-1` 个正数和一个零。最高位权重是 `-2^(n-1)`，因此范围为 `[-2^(n-1), 2^(n-1)-1]`，最小负数没有对应的正数。补码还让加减法共用加法器，硬件实现更简单。

### 怎样区分有符号和无符号溢出？

回答思路：同一位模式采用不同解释，判据分别是符号反常和进位。

回答模板：

固定宽度加法会丢弃最高位之外的结果。无符号加法看最高位进位，无符号减法看借位；有符号补码加法只在同号操作数相加且截断结果符号位改变时溢出：正数加正数的结果符号位为 1，或负数加负数的结果符号位为 0，包括结果为 0。比如 8 位 `-128 + (-128)` 截断为 0，真实结果 -256 不可表示，仍发生有符号溢出；而 `11111111 + 00000001` 按无符号数解释为 `255+1`，有无符号溢出，按有符号数解释为 `-1+1=0`，没有有符号溢出。硬件上也可比较符号位的进位与最高数值位的进位，两者不同即溢出。

### 为什么二进制浮点数不能精确表示 0.1？

回答思路：有限二进制小数的分母只能含因子 2。

回答模板：

有限位二进制小数只能精确表示分母约分后是 `2^k` 的数，而 `0.1 = 1/10` 的分母还含因子 5，所以其二进制表示是无限循环的 `0.000110011...B`。IEEE 754 只能保存舍入后的近似值，连续运算还会累积舍入误差，因此金额等精确场景通常使用定点数或十进制定点类型。

### IEEE 754 如何表示零、非规格化数、无穷和 NaN？

回答思路：按指数全 0、全 1 及尾数是否为 0 分类。

回答模板：

指数全 0 且尾数为 0 表示带符号的零；指数全 0 但尾数非零表示非规格化数，它没有隐藏前导 1，用于逐渐下溢。指数全 1 且尾数为 0 表示正负无穷，尾数非零表示 NaN。普通规格化数的指数既不全 0 也不全 1，数值使用隐藏前导 1 和偏置指数。

### 为什么网络字节序使用大端，程序怎样转换？

回答思路：统一线上表示，并在主机边界显式转换。

回答模板：

网络协议必须规定统一字节顺序，传统 TCP/IP 网络字节序采用大端。发送和接收多字节整数时，应使用 `hton*`、`ntoh*` 或协议库做主机序与网络序转换，而不是假定机器端序。例如 `0x12345678` 的网络字节依次为 `12 34 56 78`，在常见小端 x86 内存中则依次为 `78 56 34 12`。
