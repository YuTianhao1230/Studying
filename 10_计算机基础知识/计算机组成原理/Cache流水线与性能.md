# Cache流水线与性能

## 知识点解析

### 概述

本文整理 Cache、流水线和 CPU（Central Processing Unit，中央处理器）性能指标，包括局部性、地址划分、平均访存时间、Cache 一致性、流水线冲突、CPI 和执行时间。

### 局部性原理

时间局部性表示最近访问过的数据，短期内可能再次访问；空间局部性表示访问某个地址后，附近地址也可能被访问。Cache 利用局部性把热点数据放到高速存储中，减少访问主存的次数。

### Cache 分类

Cache 可以按层级、缓存内容、映射方式和写策略等不同维度分类。这些分类维度相互独立，例如 L1 数据 Cache 既可以采用组相联映射，也可以采用写回策略。

| 分类维度 | 类型 | 含义与特点 |
| --- | --- | --- |
| 层级 | L1 Cache | 最靠近 CPU 核心，容量最小、速度最快，通常每个核心私有，并常拆分为指令 Cache 和数据 Cache |
| 层级 | L2 Cache | 容量和延迟介于 L1 与 L3 之间，通常每个核心私有，也可能由少量核心共享 |
| 层级 | L3 Cache | 容量较大、延迟高于 L1 和 L2，通常由多个核心共享，用于减少对主存的访问 |
| 缓存内容 | 指令 Cache（I-Cache） | 缓存程序指令，主要服务取指阶段 |
| 缓存内容 | 数据 Cache（D-Cache） | 缓存程序读写的数据，主要服务 load、store 等指令 |
| 缓存内容 | 统一 Cache（Unified Cache） | 指令和数据共用同一 Cache，空间利用更灵活，但二者可能竞争容量和带宽 |
| 映射方式 | 直接映射 | 每个主存块只能放入唯一 Cache 行，硬件简单、命中快，但冲突缺失较多 |
| 映射方式 | 全相联映射 | 主存块可以放入任意 Cache 行，冲突缺失少，但比较电路复杂、成本高 |
| 映射方式 | 组相联映射 | 主存块映射到固定组，可放入组内任意一路，在命中速度和冲突缺失之间折中 |
| 写命中策略 | 写直达（write-through） | 同时更新 Cache 和下一级，状态简单但写流量较大 |
| 写命中策略 | 写回（write-back） | 只修改 Cache 并置脏，替换时才写回下一级，写流量较小但控制更复杂 |
| 写缺失策略 | 写分配（write-allocate） | 写不命中时先把缓存行调入 Cache，再在 Cache 中修改 |
| 写缺失策略 | 非写分配（no-write-allocate） | 写不命中时直接写下一级，不把该缓存行调入 Cache |

### Cache 命中与缺失

Cache 以固定大小的块或缓存行在层次之间搬运数据。CPU 发出地址后，Cache 用组索引定位候选行，再比较有效位和标记；匹配成功就是命中，可以直接返回数据。未命中时，控制器从下一级存储取回整个缓存行，选择空行或牺牲行填入后再完成访问。顺序遍历数组通常能复用同一缓存行，而链表随机跳转较难利用空间局部性。

### Cache 地址划分

Cache 题常把地址划分为：

```text
Tag + Index + Offset
```

Offset 由块大小决定，Index 由 Cache 组数决定，剩余高位是 Tag。直接映射每组一行，组相联每组多行，全相联没有固定组索引。

计算步骤：

```text
块内偏移位数 = log2(块大小)
Cache 行数 = Cache 数据容量 / 块大小
组数 = Cache 行数 / 每组行数
组索引位数 = log2(组数)
Tag 位数 = 主存地址位数 - 组索引位数 - 块内偏移位数
```

直接映射等价于每组 1 行，全相联等价于只有 1 组。

例：32 位字节地址、32 KiB Cache、块大小 64 B、4 路组相联。共有 `32 KiB / 64 B = 512` 行、`512 / 4 = 128` 组，因此 Offset 为 6 位、Index 为 7 位、Tag 为 `32-6-7=19` 位。地址 `0x00012340` 的 Offset 为 0、组号为 `0x0D`、Tag 为 `0x9`；访问时只在第 13 组的 4 路中并行比较 Tag。

每个 Cache 行除了数据和 Tag，通常还有有效位；有效位为 0 时该行不能命中。写回 Cache 还需要脏位，表示该行已被 CPU 修改但尚未同步到下一级。组相联访问未命中时优先使用无效行，否则按 LRU、伪 LRU、FIFO 或随机策略在该组内选择牺牲行；若牺牲行为脏，还要先写回。

### 写策略与缺失分类

- 写直达（write-through）：命中写同时更新 Cache 和下一级，状态简单、一致性较直观，但写流量大，通常配合写缓冲。
- 写回（write-back）：命中写只更新 Cache 并置脏，替换时再写回，降低下层流量，但控制更复杂。
- 写分配（write-allocate）：写不命中时先把块调入 Cache 再写，常与写回搭配。
- 非写分配（no-write-allocate）：写不命中时绕过 Cache 写下层，常与写直达搭配。

冷启动缺失来自第一次访问某个块；容量缺失来自工作集超过 Cache 总容量；冲突缺失来自多个块映射到同一组，即使 Cache 其他组还有空间也会替换。提高相联度主要减少冲突缺失，增大容量主要减少容量缺失，增大块可利用空间局部性但也会提高缺失代价并减少总行数。

### 多核 Cache 一致性

多核处理器通常为每个核心配置私有 Cache，同一内存块可能同时存在多个副本。Cache 一致性要保证对同一地址的写入最终传播到其他核心，并让各核心以一致的顺序观察该地址的写入。常见协议采用写失效：某核心准备修改共享缓存行时，先使其他核心中的副本失效，再取得写权限。

MESI 协议用四种状态描述缓存行：

| 状态 | 含义 | 是否可能存在其他有效副本 | 与内存是否一致 |
| --- | --- | --- | --- |
| M（Modified，已修改） | 本核独占且已写脏 | 否 | 否，替换前需写回 |
| E（Exclusive，独占） | 本核独占且未修改 | 否 | 是 |
| S（Shared，共享） | 多核可持有只读副本 | 是 | 是 |
| I（Invalid，无效） | 本行不可使用 | 不适用 | 不适用 |

读未命中时，核心通过一致性互连请求数据；若没有其他副本，通常进入 E，若已有共享者则进入 S。对 S 状态执行写操作前，需要广播失效其他副本并转为 M。若其他核心读取 M 状态的行，原持有者需要提供最新数据，双方通常转为 S。实际协议还可能扩展 O、F 等状态以减少写回或响应开销。

一致性不等同于内存一致性模型：前者关注同一地址的多个缓存副本是否一致，后者规定不同地址的内存操作能以什么顺序被其他核心观察。即使协议正确，线程间仍需使用锁、原子操作和内存屏障建立同步关系。不同线程频繁写同一缓存行中的不同变量还会产生伪共享，引发缓存行反复失效。

### 平均访存时间

```text
AMAT = 命中时间 + 缺失率 × 缺失代价
```

AMAT（Average Memory Access Time，平均访存时间）是一次访存的期望耗时。降低 AMAT 可以提高命中率、降低缺失代价或降低命中时间。

多级 Cache 常从内向外展开。例如：

```text
AMAT = L1 命中时间
     + L1 缺失率 × (L2 命中时间 + L2 缺失率 × 主存代价)
```

### 流水线

流水线把指令执行拆成取指、译码、执行、访存、写回等阶段，让多条指令在不同阶段并行推进。它提升吞吐量，不一定降低单条指令延迟。

流水线冲突包括结构冲突、数据冲突和控制冲突。常见解决方法包括暂停、转发、分支预测和乱序执行。

数据冒险中，RAW（Read After Write）是真数据依赖，后指令必须读到前指令的新值；WAR（Write After Read）和 WAW（Write After Write）是名字依赖，主要在乱序执行时出现，可用寄存器重命名消除。转发可把尚未写回寄存器的 ALU 结果直接送到后续阶段，减少 RAW 停顿，但典型五级流水线的 load-use 依赖可能仍需暂停一个周期。

理想情况下，k 级流水线执行 n 条指令的时间为：

```text
(k + n - 1) × 时钟周期
```

有停顿时，总周期数为 `k + n - 1 + 停顿周期数`。流水线时钟周期由最慢阶段加流水线寄存器开销决定；流水线加速比需要用“非流水时间 / 流水时间”计算。实际还要考虑阶段耗时不均、寄存器开销和冲突停顿。

例：五级阶段延迟为 `200、150、180、220、160 ps`，流水线寄存器开销为 `20 ps`，则时钟周期为 `220+20=240 ps`。理想执行 10 条指令需要 `(5+10-1)×240=3360 ps`；非流水逐条执行需要 `10×(200+150+180+220+160)=9100 ps`，加速比约为 `9100/3360=2.71`，而不是理想级数 5。单条指令的流水延迟为 `5×240=1200 ps`，反而高于非流水的 910 ps。

### 性能公式

```text
CPU 时间 = 指令数 × CPI × 时钟周期时间
```

CPI（Cycles Per Instruction，每条指令平均时钟周期数）把各类停顿计入平均执行成本。优化性能可以从减少指令数、降低 CPI、提高主频入手，但实际还要考虑 Cache miss、分支预测、IO 和并行度。

如果不同类型指令数量和 CPI 不同：

```text
平均 CPI = Σ(某类指令比例 × 该类 CPI)
CPU 时间 = 指令数 × 平均 CPI / 主频
```

### 常见考法与解题步骤

| 题型 | 解题步骤 |
| --- | --- |
| Cache 地址划分 | 先偏移位，再组索引位，剩余为 Tag |
| Cache 命中判断 | 求主存块号、组号和 Tag，再模拟替换 |
| AMAT | 按各级命中和未命中概率计算期望 |
| 流水线总时间 | 先求时钟周期，再算装入、稳定和排空 |
| 流水线冲突 | 判断资源、数据依赖还是分支 |
| CPU 性能 | 统一单位后代入指令数、CPI、主频 |
| 加速比 | 原执行时间除以优化后执行时间 |

## 笔试常考

- 根据容量、块大小和相联度计算 Tag、Index、Offset，并判断组相联命中及组内替换。
- 结合有效位、脏位和替换策略模拟 Cache 行状态。
- 计算多级 Cache 的 AMAT，区分局部命中率与全局命中率。
- 根据最慢阶段和寄存器开销计算流水线周期、总时间及加速比。
- 判断结构、控制和 RAW/WAR/WAW 数据冒险，计算转发或暂停后的周期数。
- 用 `CPU 时间 = 指令数 × CPI / 主频` 比较方案，并把 miss、分支和停顿计入 CPI。

### 易错点

- Cache 容量题要确认是否只计算数据区，还是包含 Tag、有效位和脏位。
- 地址按字节还是按字编址会影响偏移位。
- 流水线提高吞吐，不保证单条指令延迟降低。
- 主频提高不代表程序一定同比加速，CPI 和访存瓶颈也会变化。
- 命中率是条件概率，多级 Cache 题要区分局部命中率和全局命中率。

## 面试应对

### Cache 为什么能提升性能，局部性起什么作用？

回答思路：先说明 CPU 与主存的速度差距，再解释缓存行、命中和两类局部性。

回答模板：

CPU 的执行速度远高于主存访问速度，如果每次都访问主存，处理器会大量等待。Cache 位于 CPU 和主存之间，以缓存行为单位保存近期可能使用的数据。时间局部性表示最近访问的数据可能再次访问，空间局部性表示相邻地址可能随后被访问，因此热点和顺序访问更容易命中。命中时直接从高速 Cache 取数，未命中才访问下一级，所以提高命中率能够降低平均访存时间。

### 直接映射、组相联和全相联怎样取舍？

回答思路：比较冲突缺失、命中延迟和硬件复杂度。

回答模板：

直接映射每组只有一行，索引和命中判断最快、硬件简单，但冲突缺失多；全相联可把块放在任意行，冲突最少，但要比较所有 Tag，成本和延迟最高；组相联只比较组内若干路，在命中时间、功耗和冲突缺失之间折中，所以最常见。选择还要结合 Cache 层级、容量和目标周期。

### Cache miss 分为哪些类型？

回答思路：按首次访问、总容量不足和映射冲突分类。

回答模板：

经典 3C 分类包括 compulsory、capacity 和 conflict miss。第一次访问某个块是冷启动缺失；工作集超过 Cache 总容量是容量缺失；多个活跃块映射到同一组造成的是冲突缺失。增大块、容量或相联度针对的问题不同，而且会影响命中延迟和缺失代价，不能只追求单一参数。

### Write-through 和 write-back 如何选择？

回答思路：比较下层写流量、状态复杂度、脏位和一致性。

回答模板：

Write-through 每次命中写都更新下一级，实现和一致性处理较简单，但下层写流量大，通常需要写缓冲。Write-back 只修改 Cache 并置脏，替换时才写回，能合并多次写入，但要维护脏位并处理更复杂的一致性和替换流程。常见组合是 write-back 加 write-allocate，或者 write-through 加 no-write-allocate。

### 数据转发能解决所有 RAW 冒险吗？

回答思路：转发可用结果的时机和 load-use 特例。

回答模板：

转发是在结果产生后、不等寄存器写回就直接送给依赖指令，因此能消除很多 ALU 指令之间的 RAW 停顿。但如果后指令需要的数据在它的执行阶段之前还没产生，例如典型五级流水线紧邻的 load-use 依赖，仍要插入气泡。WAR 和 WAW 属于名字依赖，乱序处理器通常用寄存器重命名解决。

### 流水线为什么能提升性能？

回答思路：区分阶段并行、吞吐量和单条指令延迟，再补充冲突与开销。

回答模板：

流水线把指令执行拆成取指、译码、执行、访存和写回等阶段，让多条指令在不同阶段同时推进。流水线填满后，理想情况下每个周期都能完成一条指令，因此提升的是吞吐量，单条指令延迟不一定降低。实际加速比还会受最慢阶段、流水线寄存器开销以及结构、数据和控制冲突影响，需要通过资源复制、转发、暂停和分支预测等机制处理。

### MESI 如何保证多核 Cache 一致性？

回答思路：说明私有副本问题、四种状态、写失效和协议边界。

回答模板：

多核私有 Cache 可能保存同一内存块的多个副本，MESI 用 Modified、Exclusive、Shared、Invalid 四种状态跟踪每个缓存行。共享行被某个核心写入前，该核心先让其他副本失效并获得独占写权限；其他核心随后读取时，会从持有者或下一级取得最新数据。这样能保证同一地址的副本一致，但它不等同于线程同步或内存一致性模型，程序仍需用锁、原子操作和内存屏障约束跨地址的访问顺序。

### 如何比较两台 CPU 的性能？

回答思路：使用完整执行时间，不单看主频。

回答模板：

不能只比较主频，程序 CPU 时间由指令数、平均 CPI 和时钟周期共同决定，即 `CPU 时间 = 指令数 × CPI / 主频`。不同架构可能执行不同数量的指令，CPI 也会受到流水线、Cache miss 和分支预测影响。因此应该在相同工作负载下比较实际执行时间，并结合吞吐、功耗等目标判断。
