# CPU指令系统与IO

## 知识点解析

### 概述

本卡片从程序如何被硬件执行出发，整理 CPU（Central Processing Unit，中央处理器）的组成、指令系统与执行周期、存储层次、系统总线、IO（Input/Output，输入输出）控制和中断机制。数据编码与 Cache、流水线的计算细节分别见[数据表示](<数据表示.md>)和[Cache流水线与性能](<Cache流水线与性能.md>)。

### CPU 的基本组成

CPU 主要由运算器、控制器、寄存器组和片上高速缓存组成，各部分通过内部数据通路连接。

| 组成 | 主要职责 | 常见部件 |
| --- | --- | --- |
| 运算器 | 完成算术、逻辑、移位和地址计算 | ALU、移位器、状态标志寄存器 |
| 控制器 | 取指、译码并产生控制信号，协调数据通路 | 指令译码器、时序控制逻辑 |
| 寄存器组 | 保存指令、地址、操作数和中间结果 | PC、IR、通用寄存器、SP、状态寄存器 |
| 片上 Cache | 缓解 CPU 与主存之间的速度差距 | L1、L2，部分架构还共享 L3 |

ALU（Arithmetic Logic Unit，算术逻辑单元）负责加减、与或非、比较和移位等操作。控制器可以采用硬布线控制或微程序控制：前者直接由组合逻辑产生控制信号，速度快但修改困难；后者把控制步骤编码成微指令，设计规整、扩展方便，但通常多一层控制存储访问。

常见寄存器的职责如下：

| 寄存器 | 作用 |
| --- | --- |
| PC（Program Counter，程序计数器） | 保存下一条待取指令的地址，顺序执行时自动更新，转移时写入目标地址 |
| IR（Instruction Register，指令寄存器） | 保存当前正在译码或执行的指令 |
| MAR（Memory Address Register，存储器地址寄存器） | 保存本次主存访问的地址 |
| MDR（Memory Data Register，存储器数据寄存器） | 暂存从主存读出或准备写入主存的数据 |
| 通用寄存器 | 保存操作数、地址和中间结果 |
| SP（Stack Pointer，栈指针） | 指向当前栈顶，用于调用、返回和现场保存 |
| 状态寄存器 | 保存零、符号、进位、溢出、中断允许等状态 |

不同教材对 MAR、MDR 是否属于 CPU 的可见组成有不同抽象层次，但它们描述的地址暂存和数据缓冲功能仍然存在。程序员通常能直接访问通用寄存器，PC、IR 等控制寄存器则由指令执行过程隐式使用。

### 指令系统与指令格式

ISA（Instruction Set Architecture，指令集体系结构）是软件与处理器硬件之间的接口，规定机器能够执行哪些指令、寄存器如何组织、数据类型与寻址方式、指令编码、异常模型和可见内存语义。微体系结构是在 ISA 约束下对流水线、Cache、执行单元等内部机制的具体实现，同一 ISA 可以有多种性能和功耗不同的实现。

一条机器指令通常由操作码和地址字段组成：

```text
指令 = 操作码 + 寻址方式字段 + 寄存器/地址/立即数字段
```

操作码说明执行何种操作，地址字段说明操作数来自哪里以及结果写到哪里。操作码有 `n` 位时，固定编码最多能区分 `2^n` 种状态；实际指令集可能使用扩展操作码，把未使用的地址字段组合成更长操作码。

按显式地址数量可分为零地址、一地址、二地址和三地址指令。地址字段越多，一条指令能直接表达的信息越多，但编码空间和指令长度开销也越大。栈式机器常见零地址运算，累加器机器常见一地址指令，通用寄存器机器常见二地址或三地址指令。

#### 常见寻址方式

设指令地址字段为 `A`，寄存器内容为 `R`，主存单元内容为 `M[x]`，有效地址为 `EA`：

| 寻址方式 | 操作数或有效地址 | 特点 |
| --- | --- | --- |
| 立即寻址 | 操作数就是 `A` | 取数快，但数值范围受指令字段限制 |
| 寄存器寻址 | 操作数为 `R` | 不额外访问主存，速度快 |
| 直接寻址 | `EA = A` | 简单，但地址范围受字段长度限制 |
| 间接寻址 | `EA = M[A]` | 地址范围灵活，但求操作数前至少多访问一次主存 |
| 寄存器间接寻址 | `EA = R` | 适合指针，地址范围由寄存器宽度决定 |
| 基址/变址寻址 | `EA = R + A` | 适合数组、结构体、重定位和栈帧访问 |
| PC 相对寻址 | `EA = PC + A` | 适合分支和位置无关代码 |
| 隐含寻址 | 操作数由操作码隐含 | 指令短，但操作对象固定 |

计算访存次数时要先确认题目是否把取指计算在内。例如直接寻址读取操作数通常需要一次取指和一次数据访存；间接寻址还要先从主存取得有效地址，因此通常再多一次访存。

#### RISC 与 CISC

RISC（Reduced Instruction Set Computer，精简指令集计算机）倾向于采用数量较少、格式规整、执行步骤相对统一的指令，并通过 load/store 指令访问内存，便于译码和流水化。CISC（Complex Instruction Set Computer，复杂指令集计算机）提供更多复杂指令和寻址方式，强调单条指令的表达能力与代码密度。

二者是设计取向而非绝对分类。现代处理器经常融合两类思路，例如复杂指令可以在内部译成较简单的微操作执行，因此不能用“RISC 一定更快”或“CISC 一条指令完成更多工作所以一定更快”作结论。

### 指令执行过程

一条指令在非流水抽象下通常经历以下阶段：

1. 取指：PC 给出指令地址，经 MAR 访问主存或 Cache，读出的指令经 MDR 送入 IR，并更新 PC。
2. 译码与读寄存器：控制器识别操作码、寻址方式和源/目标寄存器，读取所需操作数。
3. 计算有效地址或执行：ALU 进行运算、比较、移位，或计算访存和转移目标地址。
4. 访存：仅 load、store 等指令需要读取或写入数据存储。
5. 写回：将结果写入通用寄存器或状态寄存器。
6. 中断检查：通常在指令边界检查可响应的中断，再决定继续顺序取指还是进入中断处理。

上述步骤是逻辑阶段，不表示所有指令都执行每一步。分支指令可能不访问数据存储，store 不需要把结果写回通用寄存器。流水线处理器让多条指令的不同阶段重叠执行，具体冲突和性能计算见[Cache流水线与性能](<Cache流水线与性能.md>)。

指令周期是完成一条指令所需的全部时间，可以包含若干机器周期；机器周期又由若干时钟周期组成。主频只决定时钟周期长度，程序时间还取决于指令数和每条指令平均周期数，不能只凭主频判断处理器快慢。

### 存储层次

存储系统通过多级结构同时追求速度、容量和成本：

```text
寄存器 -> L1 Cache -> L2 Cache -> L3 Cache -> 主存 -> SSD/HDD
速度更快、容量更小、单位成本更高  <---------------->  速度更慢、容量更大、单位成本更低
```

上层保存下层数据的活跃子集。寄存器由指令直接操作；Cache 按缓存行自动管理主存数据副本；主存保存运行中程序的工作集；辅存提供非易失的大容量持久化。层次结构有效的前提是程序具有时间局部性和空间局部性。

| 存储类型 | 常见实现 | 是否易失 | 典型用途 |
| --- | --- | --- | --- |
| Cache | SRAM | 是 | 保存近期使用的主存块 |
| 主存 | DRAM | 是，需要刷新 | 保存运行中的代码和数据 |
| 固件存储 | ROM、Flash | 否 | 保存启动代码和固件 |
| 辅存 | SSD、HDD | 否 | 持久化文件和程序 |

SRAM（Static Random-Access Memory，静态随机存取存储器）用触发器保存状态，不需要周期刷新，速度快但面积和成本高。DRAM（Dynamic Random-Access Memory，动态随机存取存储器）用电容保存电荷，需要刷新，密度高且成本低，因此主要用于主存。

Cache 和虚拟内存都是层次化存储，但粒度和管理者不同。Cache 在硬件控制下以缓存行为单位缓解 CPU 与主存的速度差距；虚拟内存由硬件和操作系统协同，以页为单位把虚拟地址映射到物理内存，并在必要时与磁盘交换，主要解决地址空间隔离、重定位和主存容量管理问题。

#### 存储容量与芯片扩展

若系统按字节编址，`n` 根地址线最多形成 `2^n` 个字节地址；若按字编址，则可寻址容量还要乘每个字的字节数。存储芯片常写成“字数 × 位数”，例如 `16K × 8 bit` 表示有 `16K` 个存储单元，每个单元 8 位。

用小芯片组成大存储器时：

```text
位扩展倍数 = 目标字长 / 芯片字长
字扩展倍数 = 目标字数 / 芯片字数
芯片总数 = 位扩展倍数 × 字扩展倍数
```

例如用 `16K × 8 bit` 芯片组成 `64K × 16 bit` 存储器，需要字扩展 `64K/16K=4` 倍、位扩展 `16/8=2` 倍，共 `4×2=8` 片。位扩展芯片共享地址和片选信号并并行提供不同数据位，字扩展则用高位地址经过译码器选择芯片组。

### 系统总线

总线是 CPU、主存和 IO 控制器之间共享或点对点传输信息的通路。按传输内容可分为：

| 总线 | 传输内容 | 位宽的主要影响 |
| --- | --- | --- |
| 数据总线 | 指令和数据 | 一次可并行传输的数据量 |
| 地址总线 | 主存或 IO 端口地址 | 可寻址单元数量 |
| 控制总线 | 读写、时钟、中断、请求与应答信号 | 操作时序和控制能力 |

地址总线宽度不等于数据总线宽度。32 位地址总线在按字节编址时最多寻址 `2^32 B = 4 GiB`；64 位数据总线表示一次可并行传送 64 bit，但不能据此推出地址空间大小。

总线事务通常经历申请与仲裁、寻址、数据传输和结束确认。多个总线主设备同时申请使用总线时，需要通过集中式或分布式仲裁确定使用者。同步总线按公共时钟规定时序，实现简单但速度受最慢设备和布线约束；异步总线使用请求/应答握手适配不同速度的设备，但控制更复杂。

忽略协议开销时，总线峰值带宽可估算为：

```text
带宽 = 数据总线宽度 / 8 × 总线频率 × 每周期传输次数
```

例如 64 位数据总线、200 MHz、每周期传输一次的理论带宽为 `64/8 × 200M = 1.6 GB/s`。实际有效带宽还会受仲裁、等待周期、地址阶段和突发长度影响。

### IO 系统

外设通常不直接连接 CPU 内部数据通路，而是通过设备控制器或适配器连接系统总线。控制器向处理器提供数据寄存器、状态寄存器和控制寄存器，负责协议转换、速度匹配、缓冲和错误报告。

IO 端口有两种常见编址方式：

- 独立编址：IO 端口使用独立地址空间和专用输入输出指令，不占用主存地址空间。
- 统一编址：也称内存映射 IO，把设备寄存器映射到内存地址空间，可使用普通 load/store 指令，但会占用部分地址范围并需要正确处理访问顺序和缓存属性。

#### 程序查询、中断与 DMA

| 方式 | CPU 如何参与 | 适用场景 | 主要代价 |
| --- | --- | --- | --- |
| 程序查询 | CPU 循环读取设备状态，满足条件后搬运数据 | 设备简单、等待极短或启动早期 | 忙等浪费 CPU 时间 |
| 中断驱动 | 设备就绪后发中断，CPU 执行处理程序搬运数据 | 低速、零散、事件型 IO | 每次事件有中断和现场切换开销 |
| DMA | CPU 只配置任务，DMA 控制器在设备与主存间批量传输 | 磁盘、网卡等大块高速传输 | 需要总线仲裁、缓存协同和完成通知 |

DMA（Direct Memory Access，直接存储器访问）的典型过程是：

1. CPU 设置源/目的地址、传输方向、长度和设备参数。
2. DMA 控制器向总线仲裁器申请控制权。
3. 控制器在设备与主存之间逐字、突发或连续传输，并更新地址与计数。
4. 传输完成或出错后，DMA 控制器通常用一次中断通知 CPU。

DMA 减少的是 CPU 逐项搬运数据的工作，并不表示 CPU 完全不参与。CPU 仍需初始化、处理中断和错误；DMA 与 CPU 共享主存通路，还可能争用总线。在非硬件一致性系统中，驱动还需在 DMA 前后维护 Cache，避免设备读到旧数据或 CPU 读到尚未失效的缓存副本。

### 中断与异常

中断和异常都会改变正常控制流，使处理器进入特权处理程序。常见分类如下：

| 类型 | 产生来源 | 与当前指令的关系 | 示例 |
| --- | --- | --- | --- |
| 外部中断 | CPU 外部设备或定时器 | 异步，通常在指令边界响应 | 键盘、网卡、时钟中断 |
| 故障类异常 | 当前指令执行条件不满足 | 同步，处理后可能重试该指令 | 缺页、可恢复的保护异常 |
| 陷阱 | 指令主动触发或调试事件 | 同步，通常返回下一条指令 | 系统调用、断点 |
| 终止类异常 | 严重且难以恢复的硬件或执行错误 | 同步或实现相关 | 严重机器检查 |

具体名称和返回语义取决于体系结构，不能把所有内部异常都简单称为“软件中断”。系统调用通常通过专用陷入指令进入内核，而缺页是在访问指令执行过程中由地址转换失败触发。

#### 中断响应过程

一次典型中断按以下顺序处理：

1. 设备或控制器提出中断请求。
2. CPU 在允许响应的时机检查请求，结合中断允许位、屏蔽位和优先级决定是否受理。
3. 硬件保存返回所需的 PC 和状态寄存器，切换到特权态，并根据中断向量取得入口地址。
4. 中断处理程序保存仍需使用的通用寄存器，识别并服务中断源。
5. 处理程序清除或确认中断条件，必要时唤醒等待任务。
6. 恢复软件保存的现场，执行中断返回指令，由硬件恢复状态和原控制流。

“保护现场”和“恢复现场”要区分硬件自动完成的最小现场与处理程序保存的通用寄存器。若设备条件未清除就返回，可能立即再次触发中断。

中断可按是否能被普通屏蔽位禁止分为可屏蔽中断和不可屏蔽中断；按入口获取方式分为向量中断和非向量中断。多个请求同时到达时，中断优先级决定先响应谁；若系统允许更高优先级中断打断当前处理程序，就形成中断嵌套。实现嵌套时必须保证现场保存完整，并控制允许嵌套的时机。

## 笔试常考

### 典型题型与解题步骤

| 题型 | 解题步骤 |
| --- | --- |
| CPU 部件判断 | 先区分数据运算、控制时序、地址暂存和数据暂存，再对应 ALU、控制器、MAR、MDR 等 |
| 指令格式 | 先由指令数求操作码位数，再由寄存器数量求每个寄存器字段位数，剩余位分配给地址或立即数 |
| 寻址方式 | 写出 `EA` 公式，区分取得有效地址和取得操作数所需的访存 |
| 指令执行顺序 | 按取指、译码、执行、访存、写回和中断检查判断数据流 |
| 存储芯片扩展 | 分别计算字扩展和位扩展倍数，再相乘并判断片选使用哪些高位地址 |
| 地址空间 | 明确按字节还是按字编址，再计算 `2^地址线数 × 每单元字节数` |
| 总线带宽 | 统一 bit、Byte 和频率单位，乘每周期传输次数，再判断是否要扣除协议开销 |
| IO 方式比较 | 根据 CPU 是否忙等、是否逐项搬运、通知次数和数据规模选择查询、中断或 DMA |
| 中断过程排序 | 按请求、判优、保存断点、取向量、执行服务、恢复现场和返回排序 |

### 高频计算

1. 32 根地址线按字节编址，可寻址 `2^32 B = 4 GiB`；若按 4 B 字长编址，则可寻址 `2^32 × 4 B = 16 GiB`。
2. 一条 32 位三地址指令支持 64 种操作和 16 个寄存器时，操作码至少 6 位，三个寄存器字段各 4 位，若无其他字段则还剩 `32-6-3×4=14` 位。
3. 用 `16K × 8 bit` 芯片组成 `64K × 16 bit` 存储器，需要 `4×2=8` 片。
4. 64 位、200 MHz、单倍数据率总线的理论带宽为 `64/8×200M=1.6 GB/s`；若每周期传输两次则理论值翻倍。

### 高频判断

- PC 通常保存下一条待取指令地址，IR 保存当前指令，二者作用不同。
- 指令周期可以包含多个机器周期，一个机器周期又可以包含多个时钟周期。
- 地址总线宽度决定可区分的地址数量，数据总线宽度决定单次并行传输量。
- 中断驱动仍由 CPU 执行中断处理程序；DMA 主要替代 CPU 的批量数据搬运。
- DMA 传输完成后通常仍用中断通知 CPU。
- Cache 一致性不能替代锁和原子操作提供线程同步。

### 易错点

- “主存容量”等于地址数量乘每个可寻址单元大小，不能默认所有系统都按字节编址。
- 操作码位数用向上取整的 `ceil(log2 N)` 计算，不能在指令数不是 2 的幂时向下取整。
- 间接寻址的访存次数要看题目是否包含取指，不能只背固定数字。
- RISC 与 CISC 是设计取向，不能直接推出某一方必然更快。
- 总线峰值带宽不等于应用有效吞吐，协议阶段、仲裁和等待都会产生开销。
- 中断请求出现后不一定立即响应，还受指令边界、屏蔽位、优先级和处理器状态影响。
- DMA 不经过 CPU 搬运寄存器，但仍要访问主存并参与总线或内存控制器仲裁。
- 缺页属于同步异常，外设完成通知属于异步中断，二者触发来源不同。

## 面试应对

### CPU 执行一条指令经历哪些步骤？

回答思路：按取指、译码、执行、访存、写回和中断检查展开，并说明并非每条指令都经过所有阶段。

回答模板：

CPU 首先根据 PC 给出的地址取出指令并送入 IR，同时更新 PC；控制器随后译码并读取源操作数。接着由 ALU 完成运算、比较或有效地址计算，load、store 等指令再访问数据存储，最后把结果写回寄存器并更新状态。处理器通常还会在指令边界检查中断。这个过程是逻辑划分，不是每条指令都需要访存或写回，流水线处理器还会让多条指令的不同阶段重叠执行。

### ISA、微体系结构、RISC 和 CISC 分别是什么关系？

回答思路：先区分软件接口与硬件实现，再用相同维度比较两种指令集取向。

回答模板：

ISA 是软件可见的硬件接口，规定指令、寄存器、数据类型、寻址方式和异常语义；微体系结构是对 ISA 的具体实现，包括流水线、执行单元和 Cache 组织，所以同一 ISA 可以有多种处理器实现。RISC 倾向于指令规整、load/store 访存和便于流水化，CISC 倾向于更复杂的指令和寻址方式以及较高代码密度。现代处理器往往融合两者，例如把复杂指令译成内部微操作，因此不能脱离工作负载直接判断谁一定更快。

### 程序查询、中断和 DMA 应该如何选择？

回答思路：按 CPU 等待方式、数据搬运主体、事件频率和数据规模比较。

回答模板：

程序查询由 CPU 反复检查设备状态，实现简单，但忙等会浪费处理时间，适合极简单或等待很短的场景。中断方式让设备就绪后再通知 CPU，适合低速、零散和事件型 IO，但每次中断都有现场切换开销。DMA 由控制器在设备和主存之间批量搬运数据，CPU 只负责配置和完成处理，适合磁盘、网卡等大块高速传输，但要处理总线仲裁和 Cache 一致性问题。

### CPU 响应中断时如何保护和恢复现场？

回答思路：区分硬件保存的最小现场与处理程序保存的通用现场，并说明向量、服务和返回。

回答模板：

CPU 在允许响应的指令边界受理中断后，硬件先保存返回所需的 PC 和状态寄存器，切换到特权态，并根据中断向量跳到处理程序。处理程序再保存自己会破坏的通用寄存器，识别和服务设备，清除中断条件，然后恢复这些寄存器。最后执行中断返回指令，由硬件恢复状态和原来的 PC。这样原程序能从被打断的位置继续执行；若允许中断嵌套，还要额外保证每层现场完整且优先级受控。

### 为什么计算机要采用存储层次？

回答思路：说明速度、容量和成本不可同时最优，再联系局部性和各层职责。

回答模板：

单一存储技术很难同时做到速度快、容量大、成本低和掉电不丢失，因此系统把寄存器、Cache、主存和辅存组成层次。越靠近 CPU 的层级越快但越小、单位成本越高，上层只保存下层数据的活跃子集。程序具有时间和空间局部性，所以多数访问可以在较快层命中，从整体上接近高速存储的性能，同时保留低速大容量存储的容量和成本优势。
