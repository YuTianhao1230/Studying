# 运营商网络协议与 QoS

## 知识点解析

### 概述

通用网络知识解决主机之间如何通信，运营商网络还要处理大规模接入、路由域、业务隔离、带宽保障和流量工程。运营商笔试常考 VLAN、STP、DHCP、动态路由、MPLS、QoS 和 IPv6 的基础概念。

### VLAN

VLAN 在同一物理交换网络上划分多个逻辑广播域。不同 VLAN 默认不能直接通过二层交换通信，通常需要三层交换或路由器转发。

- Access 端口：通常连接终端，属于一个 VLAN。
- Trunk 端口：通常连接交换机或网络设备，承载多个 VLAN。
- VLAN 标签：用于在链路上标识数据所属的逻辑 VLAN。

VLAN 能隔离广播域，但不是完整的安全边界。跨 VLAN 的访问仍需结合路由、防火墙和访问控制策略。

### STP

二层网络存在冗余链路时可能形成环路，引发广播风暴、MAC 地址表震荡和重复帧。STP 通过选举根桥、计算路径并阻塞部分端口形成无环逻辑拓扑。

STP 的基本计算过程是：

1. 比较桥 ID，优先级更低者胜出；优先级相同时比较 MAC 地址，选出根桥。
2. 每台非根交换机累计链路开销，选择到根桥路径开销最小的端口作为根端口；成本相同时继续比较上游桥 ID、端口 ID 等。
3. 每个二层网段选出一条到根桥路径最优的指定端口负责转发。其余冗余端口成为备用/阻塞角色，避免形成环路。

根桥上的端口通常是指定端口，非根交换机通常只有一个根端口。链路故障后 STP 会重新计算角色并启用备用路径。

RSTP 是对 STP 的快速收敛改进。链路冗余提高可靠性，但必须配合环路控制机制。

### DHCP

DHCP 用于自动分配 IP 地址、子网掩码、默认网关、DNS 等网络参数。经典过程常记为 DORA：

```text
Discover -> Offer -> Request -> ACK
```

DHCP Discover 通常是客户端广播寻找服务器；服务器 Offer 提供地址租约；客户端 Request 选择租约；服务器 ACK 确认配置。

租约到达 T1（通常为租期的 50%）时，客户端优先向原服务器单播 DHCP Request 续租；到达 T2（通常为 87.5%）仍未成功时，客户端广播请求，尝试向任意可用服务器重新绑定。租约到期仍未续租时，客户端必须停止使用该地址并重新获取。

客户端广播不能跨越路由器时，可由 DHCP Relay 接收请求并转发给异网段 DHCP 服务器。Relay 会携带网关地址或中继信息，帮助服务器选择正确地址池，再把服务器响应交回客户端。

### 动态路由协议

| 协议 | 类型 | 适用范围 | 主要特点 |
| --- | --- | --- | --- |
| RIP | 距离矢量 | 小规模网络 | 以跳数为主要度量 |
| OSPF | 链路状态 | 自治系统内部 | 基于链路状态计算最短路径 |
| BGP | 路径矢量 | 自治系统之间 | 根据路径属性进行路由选择 |

OSPF 会维护链路状态信息并计算路径；BGP 重点是自治系统之间的策略和路径交换。不能把 BGP 简单理解为“更快的 OSPF”。

RIP 以跳数为主要度量，配置和实现相对简单，但最大可用跳数有限、收敛较慢，更适合小规模网络。OSPF 基于完整的链路状态信息计算最短路径，通常能支持更大的网络规模和更快的拓扑收敛。

OSPF 邻居建立后会在区域内可靠泛洪链路状态通告（LSA），使路由器形成一致的链路状态数据库（LSDB），再各自运行 SPF 算法计算最短路径。对同一前缀的多条 OSPF 候选路由，先按区域内、区域间、E1 外部、E2 外部的路由类型优先级选优；仅在同类候选中比较度量：区域内、区域间和 E1 比较累计 Cost，E2 先比较外部度量，相同时再比较到 ASBR 或转发地址的内部 Cost。

BGP 只把选出的路径通告给邻居，并通过属性执行策略选路。常见比较因素包括更高的 `LOCAL_PREF`、更短的 `AS_PATH`、更低的 `MED`，以及 eBGP/iBGP 等规则；`NEXT_HOP` 还必须可达。MED 默认通常只在来自同一相邻 AS 的路径间比较，具体顺序和比较范围会受厂商实现与本地策略影响，不能脱离配置机械比较。IP 转发时仍先做最长前缀匹配，BGP 属性是在同一前缀的候选 BGP 路径之间选优。

### MPLS

MPLS 将具有相同转发特征的报文归入转发等价类（FEC），并在入口处为报文压入标签。核心设备不必逐跳查询 IP 路由表，而是根据标签转发表完成转发。典型标签操作包括：

- Push：入口标签边缘路由器（LER）为报文压入标签。
- Swap：中间标签交换路由器（LSR）将入标签替换为出标签。
- Pop：出口 LER 或倒数第二跳移除标签，再按普通 IP 报文处理。

标签只在相邻 MPLS 设备之间具有本地意义。一条报文还可以携带多层标签，例如 MPLS L3VPN 中通常使用外层标签把报文送到目标 PE，内层 VPN 标签用于选择客户所属的 VRF。PE 通过 VRF 隔离不同客户的路由，并通过 MP-BGP 传播 VPN 路由和标签。

MPLS 可以支持：

- 运营商 VPN。
- 业务隔离。
- 流量工程。
- 服务质量保障。
- 大规模骨干网络转发。

MPLS 并不是替代 IP 的全部功能，而是可以和 IP 网络结合使用的转发和承载技术。

### QoS

QoS 用于在网络拥塞或资源不足时对业务进行区分保障。常见流程包括：

1. 分类：按五元组、入接口、VLAN 或应用等条件识别业务类型。
2. 标记：在三层设置 DSCP，或在二层设置 802.1p 优先级，使后续设备沿用业务等级。
3. 排队：把不同业务放入不同队列。
4. 调度：决定各队列发送顺序和带宽。
5. 整形/限速：平滑或限制流量。

常见排队和调度方式包括先进先出、严格优先级队列和加权轮询/公平队列。例如语音可进入低时延优先队列，关键交互业务分配带宽保证，普通数据按权重分享剩余带宽。严格优先级队列必须限制流量，否则持续的高优先级业务可能使低优先级队列饥饿。

流量监管（Policing）和流量整形（Shaping）都可使用令牌桶判断流量是否符合速率，但处理超额流量的方式不同：

| 机制 | 超额流量处理 | 主要影响 | 常见位置 |
| --- | --- | --- | --- |
| Policing | 直接丢弃或重新标记 | 可能增加丢包，但不引入排队时延 | 网络入口 |
| Shaping | 先缓存，再以受控速率发送 | 减少突发，但会增加时延和抖动 | 网络出口 |

### 带宽、吞吐、时延和抖动

- 链路带宽：理论传输能力。
- 吞吐量：实际单位时间完成的数据传输量。
- 时延：数据从发送到接收的时间。
- 抖动：时延变化的幅度。
- 丢包率：丢失报文占总报文的比例。

网络总时延通常由发送时延、传播时延、处理时延和排队时延组成：

$$
\begin{aligned}
\text{发送时延} &= \frac{\text{数据长度}}{\text{链路带宽}} \\
\text{传播时延} &= \frac{\text{链路距离}}{\text{信号传播速度}} \\
\text{总时延} &= \text{发送时延} + \text{传播时延} + \text{处理时延} + \text{排队时延}
\end{aligned}
$$

发送时延取决于报文长度和链路带宽，传播时延取决于距离与介质中的信号传播速度。大文件经过低带宽链路时发送时延通常更突出，远距离传输小报文时传播时延可能更明显；处理时延和排队时延则随设备能力与拥塞程度变化。计算题应统一 bit、byte、bps 和时间单位后再代入。

视频、语音和工业控制对时延、抖动和丢包更敏感；备份和文件传输通常更关注吞吐量。高带宽不等价于低时延。

### IPv4 与 IPv6

| 对比项 | IPv4 | IPv6 |
| --- | --- | --- |
| 地址长度 | 32 位 | 128 位 |
| 表示方式 | 点分十进制，如 `192.0.2.1` | 冒号分隔十六进制，如 `2001:db8::1` |
| 基本首部 | 最少 20 字节，长度可变 | 固定 40 字节，可通过扩展首部增加功能 |
| 首部校验和 | 有 | 无，由链路层和传输层负责差错检测 |
| 分片 | 发送端和中间路由器都可以分片 | 只有发送端可以分片，中间路由器不分片 |
| 广播 | 支持广播 | 不使用广播，改用组播和任播 |
| 地址解析 | ARP | 基于 ICMPv6 的邻居发现协议 NDP |
| 地址配置 | 手工配置或 DHCP | 手工配置、SLAAC 或 DHCPv6 |
| NAT | 因地址不足而广泛使用 | 地址空间充足，通常不依赖 NAT |

IPv6 地址中的连续前导零可以省略，连续的全零字段可用 `::` 压缩，但一个地址中只能使用一次 `::`。常见地址包括全球单播地址、`fe80::/10` 链路本地地址和 `::1` 环回地址。

IPv4 与 IPv6 不能直接互通，网络演进通常采用双栈、隧道和翻译三类方案：

- 双栈：设备同时运行 IPv4 和 IPv6，兼容性最好，但需要同时维护两套协议。
- 隧道：将一种协议封装在另一种协议中，跨越暂不支持目标协议的网络。
- 协议翻译：通过 NAT64 等机制转换 IPv4 与 IPv6 报文，使两类节点通信。

运营商网络还会结合 SDN、NFV、云网协同和网络切片，把传统专用网络设备能力逐步软件化、虚拟化和集中编排。

## 笔试常考

- STP 选举：按桥 ID 选根桥，按累计路径 Cost 选根端口，每个网段选指定端口，其余冗余端口阻塞或作为备用。
- OSPF/BGP 选路：OSPF 先按区域内、区域间、E1 外部、E2 外部的路由类型优先级选优，再在同类候选中比较累计 Cost 或相应外部度量；BGP 对同一前缀按策略和 `LOCAL_PREF`、`AS_PATH`、`MED` 等属性选优。
- MPLS 标签栈：识别 Push、Swap、Pop；在 L3VPN 中外层标签把报文送往目标 PE，内层 VPN 标签选择客户 VRF。
- QoS 处理：根据流量特征分类并用 DSCP/802.1p 标记，再排队调度；Policing 丢弃或重标记超额流量，Shaping 缓存并平滑发送。
- 网络时延计算：统一长度、带宽和距离单位，分别计算发送时延与传播时延，再结合题目给出的处理时延和排队时延求和。
- IPv6 地址：每段前导零可省略，连续全零段可用一次 `::` 压缩；中间路由器不分片，报文过大时由源端结合 ICMPv6 和路径 MTU 处理。

## 易错点

- VLAN 隔离广播域，但不是天然的安全隔离。
- STP 通过阻塞部分链路防环，不是把所有链路同时用于转发。
- DHCP ACK 之前，客户端通常还没有最终确认租约。
- OSPF 主要用于自治系统内部，BGP 主要用于自治系统之间。
- MPLS 标签通常只具有本地意义，不是从入口到出口始终保持不变。
- Policing 通常丢弃或重标记超额流量，Shaping 则通过缓存平滑流量。
- QoS 不能凭空增加物理带宽，只能进行业务调度和资源保障。
- IPv6 没有广播，中间路由器也不会对 IPv6 报文进行分片。

## 面试应对

### STP 如何选出无环拓扑？

回答思路：根桥、路径开销、端口角色、故障收敛。

回答模板：

STP 先比较桥 ID，选择优先级最低、必要时 MAC 地址最低的交换机作为根桥。每台非根交换机再选择到根桥累计路径开销最小的端口作为根端口，每个网段选出到根路径最优的指定端口负责转发，其余冗余端口阻塞或作为备用。这样保留物理冗余但形成无环的逻辑转发拓扑，链路故障后再重新计算端口角色。

### OSPF 和 BGP 有什么区别？

回答思路：协议范围、信息传播、算法和选路目标。

回答模板：

OSPF 是自治系统内部的链路状态协议，通过泛洪 LSA 形成区域内一致的 LSDB，再运行 SPF 算法。对同一前缀先按区域内、区域间、E1 外部、E2 外部的路由类型优先级选优；同类候选再比较累计 Cost，E2 则先比较外部度量，相同时比较内部 Cost。BGP 是自治系统之间的路径矢量协议，传播可达前缀及路径属性，重点是按策略控制路由，常结合 `LOCAL_PREF`、`AS_PATH`、`MED` 等属性选优。因此 OSPF 更关注域内快速收敛和最短路径，BGP 更关注跨域规模与策略。

### MPLS L3VPN 为什么需要两层标签？

回答思路：外层负责传输，内层负责业务隔离和查表。

回答模板：

MPLS L3VPN 中，外层传输标签用于让核心 LSR 沿标签交换路径把报文送到目标 PE，途中通常执行标签交换并可能在倒数第二跳弹出。内层 VPN 标签由目标 PE 分配，用来标识客户 VRF 或具体 VPN 转发表项。目标 PE 收到报文后依据内层标签进入正确的客户路由空间，所以两层标签分别解决“送到哪台 PE”和“进入哪个 VPN”。

### Policing 和 Shaping 有什么区别？

回答思路：超额流量处理、时延丢包和部署位置。

回答模板：

Policing 和 Shaping 都可以用令牌桶判断流量是否符合约定速率，但 Policing 对超额报文通常直接丢弃或降低标记，不需要等待，因此可能增加丢包；Shaping 会把超额报文先放入队列，再按受控速率发送，能平滑突发但会增加时延和抖动。实践中入口常做监管，出口常做整形，具体仍取决于业务目标。

### IPv6 路由器遇到超 MTU 报文会怎样？

回答思路：路由器不分片、ICMPv6、源端分片和路径 MTU。

回答模板：

IPv6 中间路由器不会像 IPv4 那样对经过的报文分片。报文超过下一跳 MTU 时，路由器会丢弃它并返回 ICMPv6 Packet Too Big，其中携带可接受的 MTU；源主机据此调整报文大小，传输层通常通过路径 MTU 发现避免分片，确有需要时只能由源端添加 Fragment 扩展首部。若过滤这类 ICMPv6 报文，可能形成路径 MTU 黑洞。
