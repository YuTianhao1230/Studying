# 设计模式

## 知识点解析

### 概述

设计模式是对常见软件设计问题的经验总结。央国企笔试常考模式定义，大厂面试更看能否结合业务场景说明为什么使用某个模式。

### 单例模式

单例模式保证一个类只有一个实例，并提供全局访问点。参与者是持有唯一静态实例的单例类和通过统一入口获取它的调用方，构造器通常私有化。

常见线程安全实现包括：

- 饿汉式：类加载时完成初始化，依赖类初始化的线程安全，简单但不能延迟创建。
- 静态内部类：首次调用访问方法时加载内部类，兼顾延迟初始化和线程安全。
- 双重检查锁：实例字段必须用 `volatile` 防止指令重排，先判空、加锁后再次判空。
- 枚举单例：由语言机制保证实例唯一，并天然抵抗常规反射和反序列化破坏。

单例适合确实需要进程内唯一协调者的场景。配置对象若只是只读值、对象可由依赖注入容器管理，通常不必手写单例；连接池和线程池可以各自维护多组实例，也不天然等于单例。单例引入全局状态、隐藏依赖和测试隔离困难，分布式系统中更不能保证全局只有一个实例。

### 工厂模式

工厂模式把对象创建逻辑封装起来，调用方依赖抽象产品而非具体实现：

| 变体 | 参与者与交互 | 适用场景 | 主要代价 |
| --- | --- | --- | --- |
| 简单工厂 | 一个工厂根据参数创建不同具体产品 | 产品种类少、创建规则集中 | 新增产品通常要修改工厂分支，不属于 GoF 设计模式 |
| 工厂方法 | 抽象创建者声明工厂方法，各具体创建者返回一种具体产品 | 希望新增产品时扩展创建者而不修改原工厂 | 每种产品常伴随一个创建者，类数量增加 |
| 抽象工厂 | 抽象工厂声明一组相关产品的创建方法，具体工厂创建同一产品族 | 切换数据库、操作系统 UI 等整套兼容产品族 | 易于增加产品族，但增加新的产品等级结构会修改所有工厂 |

若对象构造简单、类型稳定，直接构造或依赖注入通常更清楚，不必额外引入工厂层。

### 策略模式

策略模式包含上下文、策略接口和多个具体策略。上下文持有策略并把算法委托给它，客户端按业务条件显式选择或注入策略。它适合支付方式、优惠规则、排序或风控规则等“同一目标、多种可替换算法”的场景。

状态模式在结构上也由上下文持有状态接口，但意图不同：对象的行为随内部状态改变，状态对象通常根据事件决定下一状态并触发迁移。策略通常由外部选择且彼此独立，状态则描述生命周期及合法转换。只有少量稳定分支时，清晰的条件语句可能比增加大量策略类更合适。

### 观察者模式

观察者模式包含主题、观察者接口、具体主题和具体观察者。观察者向主题订阅，主题状态变化后逐一通知，观察者再拉取状态或接收事件数据。它适合进程内事件、监听器和简单发布订阅，可降低发布者对订阅者的直接依赖。

观察者不是可靠消息系统的替代品。同步通知会让慢观察者阻塞发布者，异步通知则要处理顺序、重复、失败重试和最终一致性；长期对象还要及时取消订阅，避免内存泄漏。

### 代理、装饰器与适配器

- 代理包含服务接口、真实主题和代理。代理与真实主题接口一致，控制目标对象的访问，可用于远程调用、权限检查、事务、缓存或延迟加载。
- 装饰器包含组件接口、具体组件和持有组件引用的装饰器。多个装饰器可递归组合，重点是在接口不变时动态叠加职责。
- 适配器持有或继承被适配者，把已有接口转换为客户端期望的目标接口，重点是解决接口不兼容。

三者都可能包装对象，但代理关注访问控制，装饰器关注功能组合，适配器关注接口转换。若只需固定的一次功能修改，直接扩展原实现可能更简单；装饰层过多会使调用链和调试复杂。

### 常见考法与识别方法

| 题目特征 | 优先想到 | 核心目的 |
| --- | --- | --- |
| 全局只需要一个实例 | 单例 | 控制实例数量 |
| 创建对象逻辑复杂、类型会扩展 | 工厂 | 隔离创建与使用 |
| 多种算法或规则可以替换 | 策略 | 消除复杂条件分支 |
| 一个事件通知多个订阅者 | 观察者 | 建立发布订阅关系 |
| 不改原对象，增加鉴权、日志、缓存 | 代理 | 控制对象访问 |
| 接口不兼容需要转换 | 适配器 | 转换接口 |
| 动态叠加多个职责 | 装饰器 | 增强对象功能 |

场景题先指出变化点和耦合问题，再说明模式如何隔离变化、参与对象如何协作，最后补充类数量和理解成本。设计模式是解决问题的手段，不应为了套模式增加无意义抽象。

### 易错点

- 工厂解决对象创建，策略解决算法替换。
- 代理侧重访问控制，装饰器侧重功能增强。
- 观察者降低直接耦合，但要处理通知失败和订阅释放。
- 单例会引入全局状态和测试困难，不应滥用。

## 笔试常考

- 模式与场景匹配：唯一实例选单例，封装创建选工厂，可替换算法选策略，状态驱动行为选状态，一对多通知选观察者。
- 线程安全单例：饿汉式和静态内部类依赖类初始化安全；双重检查锁需要 `volatile`；枚举可防常规反射和反序列化破坏。
- 工厂变体：简单工厂按参数分支，工厂方法让子类决定一种产品，抽象工厂创建一整族相关产品。
- 策略与状态：结构相似，但策略由外部选择算法，状态由内部状态和事件驱动行为及迁移。
- 代理、装饰器与适配器：分别强调控制访问、动态增强和转换接口。
- 观察者关系：主题与观察者是一对多依赖；同步和异步通知的阻塞、顺序、重试语义不同。

## 面试应对

### 如何实现线程安全的单例？

回答思路：给出可靠实现，解释内存可见性、延迟初始化和边界。

回答模板：

Java 中优先考虑枚举单例或静态内部类。枚举由语言机制保证实例唯一，并能抵抗常规反射和反序列化破坏；静态内部类利用类初始化的线程安全，在首次访问时才创建实例。如果使用双重检查锁，实例字段必须加 `volatile`，外层判空减少加锁，锁内再次判空防止并发重复创建。还要说明单例只保证单进程唯一，会引入全局状态，并不适合所有共享对象。

### 简单工厂、工厂方法和抽象工厂有什么区别？

回答思路：按创建入口、扩展方向和产品数量区分。

回答模板：

简单工厂由一个工厂根据参数创建不同产品，集中但新增产品通常要修改分支。工厂方法把创建动作声明为抽象方法，每个具体创建者负责一种具体产品，新增产品主要通过扩展类完成。抽象工厂提供一组创建方法，用于生成相互兼容的一族产品，例如同一数据库下的连接、命令和事务对象。它容易切换产品族，但新增产品种类会影响所有具体工厂。

### 策略模式和状态模式有什么区别？

回答思路：先承认结构相似，再比较意图、选择者和转换关系。

回答模板：

策略模式和状态模式都可以让上下文组合一个接口实现，但意图不同。策略表示完成同一任务的可替换算法，通常由客户端或配置从外部选择，各策略彼此独立。状态模式表示对象生命周期中的不同状态，行为由当前状态决定，状态对象还可能根据事件触发下一状态。支付渠道选择适合策略，订单从待支付到已支付或已取消的转换更适合状态。

### 代理模式和装饰器模式有什么区别？

回答思路：结构可能相似，重点比较设计意图。

回答模板：

代理模式主要控制对目标对象的访问，例如远程调用、权限检查和延迟加载；装饰器模式主要在保持接口不变的情况下动态叠加功能。两者都可能包装原对象，但代理强调能否或如何访问，装饰器强调组合增强职责。

### 观察者模式有哪些风险？

回答思路：从耦合收益转到通知方式、失败语义和生命周期管理。

回答模板：

观察者模式让主题只依赖观察者接口，适合一个事件通知多个订阅者，但它不天然保证可靠性。同步通知中，慢观察者或异常会阻塞发布者；异步通知中，要明确顺序、重复消费、失败重试和最终一致性。订阅关系还需要在生命周期结束时解除，避免内存泄漏。如果业务要求持久化、重试和跨进程投递，应使用消息队列，而不是只靠进程内观察者。
