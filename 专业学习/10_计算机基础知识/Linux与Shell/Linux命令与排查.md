# Linux命令与排查

## 知识点解析

### 概述

本文整理 Linux 系统中的 CPU、内存、磁盘、进程、端口、网络、日志和权限检查方法，以及常见故障的排查路径。

### 系统资源

常用命令：

| 命令 | 作用 |
| --- | --- |
| `top` | 实时查看 CPU、内存、负载和进程 |
| `free -h` | 查看内存使用 |
| `df -h` | 查看磁盘分区空间 |
| `df -i` | 查看文件系统 inode 使用情况 |
| `du -sh` | 查看目录占用 |
| `iostat` | 查看磁盘 IO |
| `vmstat` | 查看 CPU、内存、上下文切换 |

Load Average 是最近 1、5、15 分钟处于可运行状态或不可中断睡眠状态的任务平均数，必须结合逻辑 CPU 核数判断。例如 8 核机器的负载长期接近 8，表示任务基本占满处理能力；明显高于 8，表示已有任务排队。负载不是 CPU 使用率：CPU 使用率高通常表示处理器忙，负载高还可能是大量进程处于 `D` 状态等待磁盘或网络 IO，应结合 `top`、`vmstat 1` 和 `iostat -xz 1` 判断。

`free -h` 中不能只看 `free` 列。`available` 是在不触发 swap 的情况下可供新进程使用的估算内存，`buff/cache` 中大部分页缓存可按需回收。Swap 已使用不一定代表当前内存不足；如果 `vmstat 1` 中 `si`、`so` 持续非零，并伴随延迟升高，才说明系统正在频繁换页。

“磁盘满”要区分两种情况：

```bash
df -h    # 检查数据块容量
df -i    # 检查 inode 数量
```

大量小文件可能在磁盘容量尚有剩余时耗尽 inode，同样会导致无法创建文件。容量耗尽时可用 `du -xhd1 /path | sort -h` 定位同一文件系统中的大目录；`df` 很满但 `du` 对不上时，还应使用 `lsof +L1` 检查已删除但仍被进程打开的文件。

### 进程排查

`ps aux` 可以查看进程列表，`ps -ef` 更适合看父子进程关系，`ps -eo pid,ppid,state,cmd` 可以直接观察状态。常见状态包括：`R` 表示运行或等待 CPU，`S` 表示可中断睡眠，`D` 表示不可中断睡眠且常见于 IO 等待，`T` 表示暂停，`Z` 表示子进程已退出但父进程尚未回收。

`kill PID` 默认发送 `SIGTERM`，进程可以捕获该信号并完成保存状态、释放锁和删除临时文件等清理。应先发送 `SIGTERM` 并等待，确认进程无法正常退出后才考虑 `kill -9 PID`。`SIGKILL` 由内核直接终止进程，不能被捕获、忽略或处理，可能留下未完成事务或外部资源。

进程因内存不足突然退出时，应检查内核 OOM 记录：

```bash
dmesg -T | grep -iE 'out of memory|killed process'
journalctl -k | grep -iE 'out of memory|killed process'
```

OOM Killer 会根据进程内存占用和 `oom_score_adj` 等因素选择牺牲进程。排查时还要结合 `free -h`、`vmstat 1`、进程 RSS、容器内存上限和服务日志，区分整机 OOM、容器 cgroup OOM 与应用主动退出。

### 网络和端口

常用命令：

| 命令 | 作用 |
| --- | --- |
| `ss -lntp` | 查看 TCP 监听端口和进程 |
| `netstat -anp` | 查看连接状态 |
| `lsof -i :端口` | 查看端口被哪个进程占用 |
| `ping` | 检查连通性和 RTT |
| `traceroute` | 查看路由路径 |
| `curl -v` | 排查 HTTP 请求、DNS、连接和响应 |

大量 `TIME_WAIT` 通常说明本机主动关闭了大量连接；大量 `CLOSE_WAIT` 通常说明对端已关闭，但本机程序没有正确关闭 socket。

### 日志排查

查看最后 100 行使用 `tail -n 100 app.log`，持续追踪新增日志使用 `tail -F app.log`；`-F` 在日志轮转后会按文件名重新打开文件。`grep` 用于搜索关键词，`less` 用于分页查看，`journalctl` 用于查看 systemd 服务日志。线上排查应先定位时间窗口，再按请求 ID、错误码、用户 ID 或 trace ID 过滤日志。

匹配行数与关键词出现次数含义不同：

```bash
grep -Fc 'ERROR' app.log                 # 包含 ERROR 的行数
grep -Fo 'ERROR' app.log | wc -l         # ERROR 的非重叠出现次数
```

同一行包含多个 `ERROR` 时，前者只计一行，后者会计多次。固定字符串使用 `-F` 可避免关键词被按正则表达式解释。

### 权限

Linux 权限分为读 `r`、写 `w`、执行 `x`，分别对应数字 4、2、1，三位数字依次表示所有者、所属组和其他用户。`chmod 644 file` 表示所有者可读写，组用户和其他用户只读，常用于普通文件；`chmod 755 file` 表示所有者可读写执行，组用户和其他用户可读执行，常用于脚本或目录。

目录权限的含义与普通文件不同：目录的 `r` 表示可列出条目，`w` 表示可创建或删除条目，`x` 表示可进入并访问其中的路径。`chown user:group path` 用于修改所有者和所属组。不要用 `chmod 777` 掩盖所有权或部署配置问题。

## 面试应对

### 线上 CPU 飙高怎么排查？

常考点及考法：给出“CPU 使用率或 Load Average 突然升高”的场景，要求说明从系统到代码的定位顺序。

解法/回答思路：先区分 CPU 真忙与 IO 等待，再定位进程、线程和代码栈。

易错点：不要把负载直接等同于 CPU 使用率，也不要一上来重启进程而丢失现场。

回答模板：

我会先用 `top` 看整体负载和 CPU 占用最高的进程，再用 `ps` 或 `top -H` 看具体线程。如果是 Java 服务，会把线程 ID 转成十六进制，再用 `jstack` 找对应线程栈，看是死循环、锁竞争还是频繁 GC。如果 CPU 高同时 load 高，还要结合 `vmstat`、`iostat` 判断是不是 IO 等待导致。排查时要保留现场信息，避免一上来直接重启丢失证据。

### 进程突然退出或机器内存告警怎么排查？

常考点及考法：给出“服务无明显异常日志但进程消失”或“内存看似被 cache 占满”的场景。

解法/回答思路：先看可用内存和换页，再检查内核 OOM 记录、进程内存与容器限制。

易错点：不能只看 `free` 列，也不能看到 swap 已使用就断定系统正在抖动。

回答模板：

我会先用 `free -h` 关注 `available`，再用 `vmstat 1` 看 `si`、`so` 是否持续非零，并用 `ps` 或 `top` 找 RSS 较高的进程。如果进程突然消失，会用 `dmesg -T` 或 `journalctl -k` 搜索 `out of memory` 和 `killed process`，确认是否触发 OOM Killer；在容器中还要检查 cgroup 内存上限和容器退出原因。最后结合应用日志和内存曲线判断是泄漏、瞬时峰值还是配置过小。

### 提示 No space left on device 怎么排查？

常考点及考法：磁盘仍有容量却无法创建文件，或 `df` 与 `du` 结果明显不一致。

解法/回答思路：依次检查数据块、inode、大目录和已删除但仍被打开的文件。

易错点：只执行 `du` 可能漏掉 inode 耗尽和未释放的已删除文件。

回答模板：

我会先执行 `df -h` 判断数据块是否耗尽，再执行 `df -i` 检查 inode；如果是容量问题，用 `du -xhd1 /path | sort -h` 逐层定位大目录。如果 `df` 显示空间已占用但 `du` 统计明显偏小，我会用 `lsof +L1` 查找已删除但仍被进程持有的文件，确认后通过正常重启或关闭对应文件描述符释放空间，而不是直接删除不明文件。

### 端口不通怎么排查？

常考点及考法：服务已启动但客户端连接超时或被拒绝，要求分层定位。

解法/回答思路：从本机监听、绑定地址、网络连通、防火墙到应用日志逐层排查。

易错点：`ping` 成功不代表 TCP 端口可用，监听在 `127.0.0.1` 也无法直接被远端访问。

回答模板：

我会先在服务端用 `ss -lntp` 或 `netstat` 看端口是否监听，再用 `lsof -i` 确认对应进程。然后从客户端用 `ping`、`telnet`、`nc` 或 `curl -v` 检查网络连通和应用响应。如果本机监听正常但远端访问失败，再看防火墙、安全组、路由和 DNS。最后结合服务日志确认请求是否到达应用层。
