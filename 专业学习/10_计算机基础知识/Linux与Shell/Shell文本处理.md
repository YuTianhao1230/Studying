# Shell文本处理

## 知识点解析

### 概述

本文整理 Shell 中用于日志分析和批量处理的管道、重定向、`grep`、`awk`、`sed`、`sort`、`uniq` 和 `wc`。

### 管道和重定向

管道 `|` 把前一个命令的标准输出作为后一个命令的标准输入。重定向 `>` 覆盖写标准输出，`>>` 追加标准输出，`2>` 重定向标准错误。常见用法：

```bash
grep -F 'ERROR' app.log > error.log
command 2> err.log
command > all.log 2>&1
```

重定向按从左到右的顺序生效。`command > all.log 2>&1` 先让标准输出指向文件，再让标准错误复制标准输出的当前去向，因此两者都进入 `all.log`；`command 2>&1 > out.log` 则先让标准错误复制原来的标准输出，随后只改变标准输出，标准错误仍输出到原终端。

### grep

`grep` 用于按模式搜索文本。常用参数：

| 参数 | 作用 |
| --- | --- |
| `-n` | 显示行号 |
| `-i` | 忽略大小写 |
| `-v` | 反向匹配 |
| `-r` | 递归搜索目录 |
| `-E` | 使用扩展正则 |
| `-F` | 按固定字符串而非正则匹配 |
| `-o` | 每行只输出匹配到的部分 |
| `-c` | 输出匹配行数 |

统计“包含关键词的行数”和“关键词出现次数”不能混用：

```bash
grep -Fc 'ERROR' app.log                 # 匹配行数
grep -Fo 'ERROR' app.log | wc -l         # 非重叠出现次数
```

如果同一行出现三次 `ERROR`，第一条只计一行，第二条计三次。`wc -l app.log` 统计的是文件总行数。

### awk

`awk` 适合按字段过滤、计算和分组。默认把连续空白视为分隔符，`$1` 表示第一列，`$NF` 表示最后一列。条件写在动作前即可过滤记录，关联数组可完成分组统计：

```bash
awk '{print $1, $NF}' access.log
awk '$9 >= 500 {count[$9]++} END {for (code in count) print code, count[code]}' access.log
awk -F',' '$3 > 0 {sum[$1] += $3} END {for (name in sum) print name, sum[name]}' data.csv
```

`-F','` 只适合字段中不含逗号、引号和换行的简单数据，不是完整 CSV 解析器。对于 `"Beijing, China",10` 这类带引号字段，应使用 Python `csv`、`csvkit` 等结构化解析工具。默认空白分隔也不适合把“包含空格的字段”当作一个整体。

### sed

`sed` 适合流式替换和按行处理。批量修改前应先去掉 `-i` 预览输出；确认无误后，在 GNU/Linux 中用备份后缀保留原文件：

```bash
sed 's/old/new/g' file.txt
sed -n '10,20p' file.txt
sed -i.bak 's/old/new/g' file.txt
```

最后一条会修改 `file.txt`，同时保留 `file.txt.bak`。`sed` 的模式是正则表达式，替换内容中的 `&`、`\` 和分隔符有特殊含义；变量或内容不受控时不能直接拼接，应先转义或改用适合该数据格式的工具。

### 排序和统计

`sort` 默认按字符串排序，`-n` 表示按数值排序，`-k` 指定排序键：

```bash
sort -n numbers.txt
sort -k2,2 users.txt
sort -t',' -k3,3n data.csv
```

`uniq` 只合并相邻的重复行，不会自动在整个文件中查重。因此全局计数通常要先 `sort`，再 `uniq -c`：

常见组合：

```bash
grep -Fc 'ERROR' app.log
awk '{print $1}' access.log | sort | uniq -c | sort -nr
```

第一条统计包含 `ERROR` 的行数，第二条统计访问 IP 次数并按次数倒序。使用这些命令处理路径列表时还要注意 Shell 的空白分词和通配符展开：不要用 `for file in $(find ...)` 处理可能包含空格或换行的文件名，应优先使用 `find ... -print0` 配合 `xargs -0`，或使用 `find -exec`。

## 面试应对

### grep、awk、sed 怎么区分？

常考点及考法：要求说明三者的主要职责，并给出组合处理日志的顺序。

解法/回答思路：按“行过滤、字段计算、流式编辑”区分。

易错点：`awk -F','` 不是完整 CSV 解析器，`sed` 替换也不是结构化配置编辑器。

回答模板：

`grep` 主要查找包含某个模式的行，适合过滤；`awk` 主要按字段过滤、计算和分组，适合格式稳定的文本；`sed` 主要按行替换、删除和打印，适合流式编辑。日志分析时可先用 `grep` 缩小范围，再用 `awk` 提取字段，最后用 `sort` 和 `uniq` 统计；如果输入是带引号和嵌套结构的 CSV、JSON 或 YAML，我会改用对应解析器。

### 如何区分匹配行数和关键词出现次数？

常考点及考法：同一行可能出现多次关键词，要求写出两种统计命令。

解法/回答思路：匹配行用 `grep -c`，匹配片段用 `grep -o` 后再计行。

易错点：`grep -c` 即使与 `-o` 同用，统计的仍是匹配行数，不是出现次数。

回答模板：

如果要统计包含 `ERROR` 的行数，我用 `grep -Fc 'ERROR' app.log`；如果要统计 `ERROR` 的非重叠出现次数，我用 `grep -Fo 'ERROR' app.log | wc -l`。同一行出现三次时，前者计一行，后者计三次。关键词按字面匹配时加 `-F`，可以避免其中的正则元字符改变语义。

### 如何统计访问次数最多的 IP？

常考点及考法：给定格式固定的访问日志，要求提取字段、分组计数并倒序输出。

解法/回答思路：先确认日志格式和 IP 所在字段，再提取、排序、合并相邻项并按数值倒序。

易错点：`uniq -c` 只统计相邻重复行；字段中存在空格、引号或嵌入分隔符时，不能套用简单分列。

回答模板：

如果确认访问日志第一列是 IP，我会执行 `awk '{print $1}' access.log | sort | uniq -c | sort -nr | head`。第一次 `sort` 让相同 IP 相邻，`uniq -c` 才能完成全局计数，第二次 `sort -nr` 按次数从大到小排列。如果日志是 JSON 或字段规则复杂，我会用 `jq` 或日志平台的结构化查询，不用脆弱的空白切分。

### `2>&1` 为什么放置顺序不同结果不同？

常考点及考法：比较 `command > all.log 2>&1` 与 `command 2>&1 > out.log`。

解法/回答思路：按从左到右顺序跟踪文件描述符 1 和 2 的当前去向。

易错点：`2>&1` 是复制文件描述符 1 的当前去向，不是“永久绑定”到标准输出。

回答模板：

Shell 从左到右处理重定向。`command > all.log 2>&1` 先把标准输出指向文件，再让标准错误复制这个去向，所以两者都写入 `all.log`。`command 2>&1 > out.log` 先让标准错误指向原标准输出，随后只把标准输出改到文件，因此标准错误仍显示在原终端。

### 如何安全地批量替换文件内容？

常考点及考法：要求用 `sed` 原地替换，同时考虑误改和恢复。

解法/回答思路：先预览，再用 `-i.bak` 创建备份，最后抽样检查和比较。

易错点：直接原地修改没有回滚文件；未转义的变量、`&`、反斜杠或分隔符会改变替换结果。

回答模板：

我会先运行 `sed 's/old/new/g' file.txt` 预览结果，确认范围后再执行 `sed -i.bak 's/old/new/g' file.txt`，让原内容保存在 `file.txt.bak`。修改后会用 `diff` 和抽样检查验证。如果模式来自外部输入，或目标是 JSON、YAML、复杂 CSV，我不会直接拼接进 `sed`，而会先正确转义或使用结构化编辑工具。
