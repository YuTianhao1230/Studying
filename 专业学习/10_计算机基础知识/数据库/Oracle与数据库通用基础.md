# Oracle 与数据库通用基础

## 知识点解析

### 概述

银行科技岗常见数据库考查不只限于 MySQL，还可能涉及 Oracle、关系数据库对象、事务、权限、备份和恢复。复习重点是掌握通用数据库概念，再识别 Oracle 的常见语法和对象，不必把所有厂商命令都当成重点。

### Oracle 常见对象

- 表：保存业务数据。
- 视图：保存查询定义，对外提供逻辑表。
- 索引：加速查询，但增加写入和存储成本。
- 序列：生成递增或按规则变化的数值，常用于主键。
- 同义词：为对象提供别名。
- 存储过程/函数：把业务逻辑封装在数据库端。
- 触发器：在插入、更新、删除等事件发生时自动执行。

视图通常保存查询定义而不是独立复制一份数据。索引并不改变 SQL 逻辑结果，触发器则可能在隐式情况下修改或校验数据，使用时需要关注副作用。

### Oracle 常见伪表和伪列

- `DUAL`：Oracle 提供的单行单列表，常用于计算或查询系统表达式。
- `ROWNUM`：结果行的伪列，常用于限制返回行数，但与排序结合时要注意执行顺序。
- `ROWID`：用于标识物理行位置的伪列，不应当作为长期稳定的业务主键。

`ROWNUM` 在行通过查询块时分配，早于同一查询块的 `ORDER BY`。因此下面这种写法限制的是“先取到的 N 行”，再对它们排序，并不保证得到工资最高的 N 行：

```sql
-- Oracle SQL：错误的有序 Top N 写法
SELECT employee_id, salary
FROM employees
WHERE ROWNUM <= 3
ORDER BY salary DESC;
```

Oracle 11g 及更早版本通常先在子查询中排序，再由外层限制：

```sql
SELECT employee_id, salary
FROM (
    SELECT employee_id, salary
    FROM employees
    ORDER BY salary DESC, employee_id
)
WHERE ROWNUM <= 3;
```

Oracle 12c 及以上也可以使用 `FETCH FIRST 3 ROWS ONLY`。若第 N 名并列是否全部保留有业务含义，应改用 `RANK()` 或 `DENSE_RANK()`；若严格返回 N 行，则用 `ROW_NUMBER()` 并补充稳定的次级排序键。

### 常见函数

| 类型 | 函数示例 | 作用 |
| --- | --- | --- |
| 空值处理 | `NVL`、`COALESCE` | 把 NULL 转换为指定值 |
| 字符串 | `SUBSTR`、`LENGTH`、`INSTR` | 截取、计算长度和查找 |
| 日期 | `SYSDATE`、`ADD_MONTHS` | 获取和计算日期 |
| 数值 | `ROUND`、`TRUNC`、`MOD` | 舍入、截断、取模 |
| 转换 | `TO_CHAR`、`TO_DATE`、`TO_NUMBER` | 类型转换 |

在标准 SQL 语义中，`NULL` 表示未知或不存在，与 0、零长度字符串 `''` 和空格都不是同一概念。当前 Oracle 对字符型零长度字符串有特殊处理：SQL 中的 `''` 会按 `NULL` 处理，向 `VARCHAR2` 等字符列写入零长度字符串也会得到 `NULL`；单个空格 `' '` 则是长度为 1 的字符值，不是 `NULL`。因此 Oracle 中判断这类空值应使用 `IS NULL` 或 `IS NOT NULL`，不能使用 `= NULL`，跨数据库迁移时也不能照搬这一厂商特性。

聚合时，`COUNT(*)` 统计分组中的行数，`COUNT(column)` 只统计该列非 `NULL` 的行数。例如三行的 `bonus` 分别为 `100`、`NULL`、`NULL`，则 `COUNT(*)` 为 3，`COUNT(bonus)` 为 1。`SUM`、`AVG` 等聚合函数也通常忽略 `NULL`；若需要把空值按 0 计算，应显式使用 `NVL` 或 `COALESCE`，并确认这符合业务语义。

### 序列与 DDL 事务语义

Oracle 序列是独立于表的数据库对象，通过 `sequence_name.NEXTVAL` 取下一个值；同一会话先调用过 `NEXTVAL` 后，才能用 `CURRVAL` 读取该会话最近取得的值。

```sql
-- Oracle SQL
CREATE SEQUENCE account_seq START WITH 1 INCREMENT BY 1;

INSERT INTO accounts (account_id, account_name)
VALUES (account_seq.NEXTVAL, 'Alice');
```

序列保证并发取值不会重复，但不保证连续。事务回滚、序列缓存丢失等都可能产生空号，所以不能把序列值当作无间断的业务流水号。

Oracle 执行 DDL（如 `CREATE`、`ALTER`、`DROP`、`TRUNCATE`）时会隐式提交：执行 DDL 前先提交当前事务，DDL 成功后再提交其数据字典变更。因此不要把 DDL 与希望一起回滚的 DML 混在同一事务中。

### DELETE、TRUNCATE 与 DROP

| 操作 | 对象是否保留 | 典型范围 | Oracle 事务特性 |
| --- | --- | --- | --- |
| `DELETE` | 保留表结构 | 可按 `WHERE` 删除部分或全部行 | DML，可在提交前回滚，会逐行产生 undo/redo |
| `TRUNCATE TABLE` | 保留表结构 | 清空整张表 | DDL，隐式提交，通常更快且不能普通回滚 |
| `DROP TABLE` | 删除表对象及其数据 | 整张表 | DDL，隐式提交；相关依赖对象可能受影响 |

三者不能只按“快慢”选择，还要考虑是否保留对象、是否需要条件删除、事务可回滚性、外键约束和权限。

### Oracle 与通用 SQL

SQL 的基本思想仍然是关系查询、连接、过滤、聚合和排序。不同数据库可能在以下方面存在差异：

- 分页语法。
- 日期和字符串函数。
- 自增主键实现。
- 空值和空字符串语义。
- 连接符号和层级查询语法。
- 存储过程语言。

迁移数据库时不能只做语法替换，还要检查事务、锁、索引、执行计划、字符集、时区和数据类型。

SQL 语句常按职责分为：

| 类型 | 常见语句 | 作用 |
| --- | --- | --- |
| DDL（Data Definition Language，数据定义语言） | `CREATE`、`ALTER`、`DROP`、`TRUNCATE` | 定义或修改数据库对象 |
| DML（Data Manipulation Language，数据操纵语言） | `SELECT`、`INSERT`、`UPDATE`、`DELETE` | 查询或修改数据 |
| DCL（Data Control Language，数据控制语言） | `GRANT`、`REVOKE` | 管理对象权限 |
| TCL（Transaction Control Language，事务控制语言） | `COMMIT`、`ROLLBACK`、`SAVEPOINT` | 控制事务边界 |

部分教材会把 `SELECT` 单独归为 DQL（Data Query Language，数据查询语言），分类口径不同不影响语句本身的用途。还要注意事务语义具有数据库差异，例如 Oracle 的 DDL 会触发隐式提交，不能直接套用 DML 的回滚规则。

### 事务与锁

事务保证一组操作的原子性、一致性、隔离性和持久性。常见命令包括：

- `COMMIT`：提交事务。
- `ROLLBACK`：回滚事务。
- `SAVEPOINT`：建立局部回滚点。

锁用于协调并发访问。读写冲突、更新冲突和长事务都可能导致等待。银行业务中要特别关注余额更新、库存扣减、流水状态和批量处理的锁范围。

### Oracle 物理文件

- 数据文件：保存表、索引等实际数据库对象。
- 控制文件：记录数据库结构、检查点和文件状态等元数据。
- 重做日志文件：记录变更信息，用于实例恢复。
- 归档日志：保存已切换的重做日志，便于时间点恢复。

“数据文件存业务数据，控制文件存数据库结构信息，重做日志用于恢复”是常见基础判断题。

在线重做日志是循环使用的，记录数据库变更。实例异常终止后，Oracle 可利用在线 redo 将已提交但尚未写入数据文件的修改重演，并结合 undo 回滚未提交事务。开启 `ARCHIVELOG` 模式后，写满并切换的 redo 会在复用前归档；介质故障恢复时，可以先还原数据文件备份，再连续应用归档日志和仍可用的在线 redo，把数据库恢复到故障前或指定时间点。只有当前 redo、没有历史归档日志，通常无法覆盖跨越多个日志切换的时间点恢复。

### 备份与恢复

- 冷备：数据库停止后复制文件。
- 热备：数据库运行时进行备份。
- 物理备份：复制数据文件、日志等物理文件。
- 逻辑备份：导出表、对象或逻辑数据。
- 完全备份：备份完整数据集。
- 增量备份：只备份上次备份后发生变化的数据。

备份策略要结合 RPO、RTO、数据量、恢复速度和存储成本。备份本身必须经过恢复演练，否则不能证明可用。

物理备份面向数据文件、控制文件、归档日志等数据库物理结构，适合整库或数据文件级恢复，通常恢复速度快但与数据库版本、平台和存储布局关系更紧。逻辑备份通过 Data Pump 等工具导出表、模式及元数据，便于对象级迁移和选择性恢复，但大规模整库恢复通常较慢，也不能单独替代完整的物理灾备方案。

RPO 是最多可接受丢失多少时间的数据，RTO 是故障后最多可接受多久恢复服务。例如“最多丢 5 分钟、30 分钟内恢复”分别约束日志归档/复制频率和恢复流程、备用资源与自动化程度；每天一次全备并不能独自满足 5 分钟 RPO。

### OLTP 与 OLAP

- OLTP：面向交易处理，强调高并发、低延迟和事务一致性。
- OLAP：面向分析，强调聚合、报表、多维查询和历史数据。

银行核心账务偏 OLTP，经营分析、风险建模和监管报送偏 OLAP。一个系统也可能同时建设交易库、ODS、数据仓库和数据集市。

## 笔试常考

- 判断有序 Top N：`ROWNUM` 与同层 `ORDER BY` 不能保证先排序，应使用排序子查询、12c 的 `FETCH FIRST` 或排名窗口函数。
- 计算含空值的行数：`COUNT(*)` 统计行，`COUNT(col)` 忽略 `col` 为 `NULL` 的行；`AVG(col)` 的分母也是非空值数。
- 判断空字符串：标准 SQL 区分 `NULL`、`''` 和 `' '`；当前 Oracle 把零长度字符串 `''` 按 `NULL` 处理，但单个空格 `' '` 不是 `NULL`。
- 判断序列行为：`NEXTVAL` 取新值，`CURRVAL` 要求本会话先取过值；回滚不会归还序列号。
- 根据职责区分 DDL、DML、DCL、TCL；遇到 `SELECT` 时注意题目是否采用单列 DQL 的分类口径。
- 判断事务边界：Oracle DDL 前会隐式提交当前事务，成功后再提交 DDL；`COMMIT`、`ROLLBACK`、`SAVEPOINT` 用于 DML 事务控制。
- 区分 `DELETE`、`TRUNCATE`、`DROP`：分别关注条件删除、是否保留表对象、是否为 DDL 及能否普通回滚。
- 区分数据文件、控制文件、在线 redo 与归档日志，并判断实例恢复和介质/时间点恢复分别需要哪些日志。
- 区分逻辑备份与物理备份：对象级迁移灵活性、整库恢复速度和平台依赖不同。
- 根据“可丢失数据时长”和“恢复服务时长”分别识别 RPO、RTO，并据此选择备份、归档和容灾方案。
- 区分 OLTP 的短事务、高并发和低延迟，与 OLAP 的大范围扫描、聚合和历史分析。

## 易错点

- `ROWNUM` 不是稳定的业务编号，也不等价于排序后的行号。
- `ROWID` 是物理定位信息，不能替代业务主键。
- `NULL` 不能用 `= NULL` 判断。
- Oracle 的 `''` 按 `NULL` 处理是厂商特性，不能推导出标准 SQL 或其他数据库也如此；`' '` 仍是非空字符值。
- 视图通常保存查询定义，不等于自动复制数据。
- 有备份不等于可恢复，恢复时间和恢复结果必须演练验证。

## 面试应对

### Oracle 中如何查询排序后的前 N 条？

回答思路：先说明 `ROWNUM` 的分配时机，再给 11g 与 12c 之后的写法，并交代并列规则。

回答模板：

`ROWNUM` 在行通过查询块时分配，早于同层 `ORDER BY`，所以不能直接用 `WHERE ROWNUM <= N ORDER BY ...` 表示有序 Top N。Oracle 11g 可先在子查询中排序，再由外层用 `ROWNUM` 限制；12c 以上可用 `ORDER BY ... FETCH FIRST N ROWS ONLY`。如果并列第 N 名都要保留，我会用 `RANK` 或 `DENSE_RANK`；若只要严格 N 行，则用 `ROW_NUMBER` 并增加稳定的次级排序键。

### Oracle 如何处理空字符串和 NULL？

回答思路：先说明标准 SQL，再说明当前 Oracle 的特殊语义，并区分零长度字符串与空格。

回答模板：

标准 SQL 区分 `NULL`、零长度字符串 `''` 和空格。当前 Oracle 会把字符型零长度字符串 `''` 按 `NULL` 处理，所以应使用 `IS NULL` 判断；单个空格 `' '` 是长度为 1 的字符值，并不是 `NULL`。这是 Oracle 的厂商特性，跨数据库迁移时需要单独检查。

### 普通视图和物化视图有什么区别？

回答思路：比较是否存储结果、数据新鲜度、读写成本和使用场景。

回答模板：

普通视图主要保存查询定义，访问时通常实时执行底层查询，因此数据新鲜但复杂查询成本仍在。物化视图保存查询结果，需要按需、定时或在满足条件时快速刷新，会占用额外存储并承担刷新成本，但能加速聚合和复杂连接。选择时要在查询延迟、数据实时性、刷新开销和一致性要求之间权衡。

### redo 和归档日志如何配合恢复？

回答思路：区分在线 redo、归档副本、实例恢复和介质恢复。

回答模板：

在线 redo 循环记录数据库变更，实例崩溃后可用它重演已提交但尚未写入数据文件的修改，再结合 undo 处理未提交事务。开启归档模式后，日志切换时会保存已写满 redo 的归档副本。发生数据文件损坏时，可以先还原物理备份，再依次应用归档日志和可用的在线 redo，实现完整恢复或时间点恢复。

### 逻辑备份和物理备份如何选择？

回答思路：从恢复粒度、速度、可移植性和灾备目标回答。

回答模板：

逻辑备份导出表、模式和元数据，适合对象级迁移、选择性恢复以及跨环境搬迁，但数据量大时导入恢复较慢。物理备份复制数据库物理文件，适合整库或数据文件级快速恢复，但对版本、平台和存储结构的约束更强。生产方案通常以物理备份和归档日志满足 RPO、RTO，再用逻辑备份补充对象级恢复能力，并定期做恢复演练。

### OLTP 和 OLAP 的设计重点有什么不同？

回答思路：比较工作负载、模型、查询形态和性能目标。

回答模板：

OLTP 面向账户交易等高并发短事务，重视低延迟、强一致性和快速点查，模型通常较规范化并严格控制事务范围。OLAP 面向报表和分析，常扫描大量历史数据并做复杂聚合，更关注吞吐、列式计算和分析维度，模型可以采用星型结构等方式减少分析连接。实际架构常把交易库与数仓分离，通过数据同步服务不同负载。
