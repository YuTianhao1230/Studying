# Python 模块入口与 `__name__`

## 知识点解析

### 概述

Python 在加载模块时会为模块设置内置变量 `__name__`。利用 `if __name__ == "__main__":` 可以区分“文件被直接执行”和“文件被其他模块导入”两种运行方式，避免导入模块时误执行脚本入口、演示代码或测试代码。

### `__name__` 的取值

- 文件被直接执行时，`__name__` 的值是 `"__main__"`。
- 文件被导入时，`__name__` 通常是模块的限定名称，例如包中的 `tools/parser.py` 可能是 `"tools.parser"`。

```python
print(__name__)
```

假设代码位于 `demo.py`：

```bash
python demo.py
```

此时输出：

```text
__main__
```

若另一个文件执行：

```python
import demo
```

则 `demo.py` 中的 `__name__` 是 `"demo"`。

### 模块入口保护

常见写法如下：

```python
def main():
    print("程序开始执行")


if __name__ == "__main__":
    main()
```

解释器执行该文件时，会先定义 `main()`，再判断 `__name__`。只有文件作为程序入口直接执行时，条件才成立；文件被导入时，函数仍可复用，但 `main()` 不会自动调用。

命令行程序还可以让 `main()` 返回退出码：

```python
def main():
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

这种写法把业务逻辑放在可测试的函数中，并由最外层入口统一处理进程退出状态。

### 它不能阻止模块顶层代码执行

入口保护只控制保护块内部的代码。模块被首次导入时，保护块外的顶层语句仍会执行：

```python
print("导入时也会执行")

if __name__ == "__main__":
    print("只有直接执行时才会执行")
```

因此，可复用模块不应在顶层执行网络请求、启动线程或修改全局环境等高副作用操作。顶层通常只保留定义、常量和必要的轻量初始化。

### 适用场景与易错点

适合放入入口保护的内容包括：

- 命令行程序的启动逻辑。
- 本地演示和简单调试代码。
- 参数解析以及最终退出码处理。

常见误区：

1. `__main__` 是字符串，判断时必须写引号。
2. `if __name__ == "__main__":` 不是函数定义，也不会自动创建 `main()` 函数。
3. 被导入模块的顶层代码仍会执行，只有保护块中的代码被跳过。
4. 一个文件作为 `python -m package.module` 的入口运行时，该模块的 `__name__` 同样是 `"__main__"`。

## 面试应对

### `if __name__ == "__main__":` 是什么意思？

回答思路：先说明直接执行和导入时 `__name__` 的不同取值，再说明入口保护的作用。

回答模板：

每个 Python 模块都有内置变量 `__name__`。文件被直接执行时，它等于 `"__main__"`；文件被其他模块导入时，它通常等于模块的限定名称。因此，`if __name__ == "__main__":` 用于保护脚本入口，使命令行启动、测试或演示代码只在直接执行文件时运行，而模块中的函数和类仍可被安全导入复用。

### 使用入口保护后，导入模块时是否完全不会执行其中的代码？

回答思路：区分保护块与模块顶层代码，指出 Python 首次导入模块时仍需执行顶层语句。

回答模板：

不会。入口保护只能阻止条件块内部的代码在导入时运行。Python 首次导入模块时，仍会执行模块顶层语句来创建函数、类和全局变量，所以网络请求、线程启动等有副作用的逻辑不应直接放在顶层，而应封装进函数并由入口显式调用。
