# 算子

## 知识点解析

### 概述

算子是模型计算中的一个基本操作单元，例如矩阵乘法、卷积、LayerNorm、Softmax、[Attention](<../../02_大模型/基础架构/Self-Attention.md#self-attention>)、激活函数等。

### 直观理解

神经网络看起来是一个完整模型，但真正执行时会被拆成很多计算步骤。

例如一个 [Transformer](<../../02_大模型/基础架构/Transformer.md#transformer>) block 里有：

```text
输入
  -> LayerNorm
  -> Q/K/V 线性变换
  -> Attention
  -> 残差连接
  -> LayerNorm
  -> FFN
  -> 激活函数
  -> 残差连接
```

这些步骤里的每个计算都可以称为算子。

### 常见算子

#### 基础数学算子

- Add：加法。
- Mul：乘法。
- MatMul：矩阵乘法。
- ReduceSum：求和。
- ReduceMean：求均值。
- Exp / Log / Sqrt：指数、对数、开方。

#### 神经网络算子

- Conv：卷积。
- Linear / GEMM：线性层，本质通常是矩阵乘法。
- [ReLU](<../../01_机器学习基础/深度学习基础/常见激活函数.md#relu-rectified-linear-unit-整流线性单元>) / GELU / SiLU：激活函数。
- BatchNorm / LayerNorm / [RMSNorm](<../../02_大模型/基础架构/RMSNorm.md#rmsnorm>)：归一化。
- Softmax：归一化为概率分布。
- Embedding：查表获取 token 向量。

#### Transformer 相关算子

- QKV Projection：生成 Query、Key、Value。
- Attention Score：计算 $QK^\top$。
- Masked Softmax：带 mask 的 softmax。
- Attention Value：计算 attention 权重和 V 的加权和。
- RoPE：[旋转位置编码](<../../02_大模型/基础架构/RoPE.md#rope>)。
- FFN：前馈网络。

### 算子为什么重要

模型推理和训练速度很大程度取决于算子的效率。

同一个模型结构，如果算子实现不同，速度和显存可能差很多。

例如：

- 普通 Attention 显存占用高。
- FlashAttention 通过优化计算和访存，显著提升速度、降低显存。
- 算子融合可以减少中间结果读写，提升吞吐。

### 算子融合是什么

算子融合是把多个连续小算子合并成一个更大的算子执行。

例如：

```text
MatMul -> BiasAdd -> GELU
```

可以融合成：

```text
Fused MatMul + Bias + GELU
```

好处：

- 减少 GPU kernel launch 次数。
- 减少中间 tensor 的显存读写。
- 提升吞吐和降低延迟。

### Kernel 和算子的区别

- 算子是逻辑上的计算操作。
- Kernel 是硬件上执行该操作的具体程序，通常指 GPU kernel。

例如 MatMul 是算子，CUDA 里具体执行 MatMul 的实现可以是一个或多个 kernel。

## 面试应对

### 算子和 Kernel 有什么区别？

回答思路：区分计算图中的逻辑语义与硬件上的具体执行程序，并说明两者不是一一对应。

回答模板：

算子是计算图中的逻辑操作，例如 MatMul、LayerNorm、Softmax 或 Attention；Kernel 是这些操作在 GPU 上实际执行的程序。一个算子可能拆成多个 Kernel，多个算子也可能融合成一个 Kernel。同一个算子可以有不同 Kernel 实现，所以模型结构不变时，Kernel 选择、Shape 和数据类型仍会显著影响延迟与显存。

### 算子融合为什么能加速？

回答思路：从减少 Kernel Launch、避免中间 Tensor 落到显存和提升数据局部性解释。

回答模板：

以 MatMul、Bias 和 GELU 为例，分开执行时每个算子都可能触发 Kernel Launch，并把中间结果写回再从显存读出。融合后可以在一次或更少的 Kernel 中保留中间值，减少 Launch 和全局显存流量。它对由小算子和访存主导的链路尤其有效，但是否加速仍取决于 Shape、融合后的资源占用和编译器实现。

### 如何定位一个慢算子？

回答思路：先用 Profiler 找热点，再判断计算、访存、Launch、同步或 Shape 问题，最后做同口径基准。

回答模板：

我会先用 Profiler 按总耗时和调用次数定位热点 Kernel，再查看计算单元利用率、显存带宽、Kernel 间空隙和同步等待。带宽高而算力低通常应减少访存或做融合；算力高则关注 Tensor Core、精度和算法；大量短 Kernel 则关注 Launch Overhead。优化后要覆盖真实 Shape 做预热和重复测量，并同时检查数值误差与显存峰值。

### 算子融合是不是越多越好？

回答思路：指出寄存器与 Shared Memory 压力、并行度、动态 Shape、编译成本和数值正确性边界。

回答模板：

不是。融合能减少中间读写和 Launch，但融合范围过大会增加寄存器与 Shared Memory 占用，降低 Occupancy，也可能让动态 Shape 的编译和缓存更复杂。有些操作之间存在同步或数据依赖，也不能安全融合。判断标准应是端到端延迟、吞吐、显存和数值一致性，而不是融合的算子数量。
