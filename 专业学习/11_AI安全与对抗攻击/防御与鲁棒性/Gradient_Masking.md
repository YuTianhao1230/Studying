# Gradient Masking

## 知识点解析

### 概述

Gradient Masking 是防御评估中的常见陷阱，指模型或防御机制让梯度变得不可用、不稳定或误导攻击，使梯度攻击看似失败，但真实决策边界并没有变鲁棒。

### 解决的问题

理解 Gradient Masking 是为了避免把“攻击没优化好”误判成“模型真的鲁棒”。很多防御方法表面上降低 [PGD](<../视觉攻击方法/PGD.md#pgd>) ASR，但换成更强攻击、黑盒迁移或自适应攻击后会失效。

### 常见表现

- 白盒攻击弱于[黑盒迁移攻击](<../迁移与通用攻击/黑盒迁移攻击.md#黑盒迁移攻击>)。
- 增大攻击步数，攻击成功率不上升。
- 增大扰动预算，攻击成功率不上升。
- 随机防御导致梯度噪声大，但 EOT 后被打穿。
- 非可导预处理让普通反传失效，但 BPDA 后失效。

### 典型原因

| 原因 | 说明 | 绕过方式 |
| --- | --- | --- |
| 非可导操作 | JPEG、[量化](<../../05_推理部署与系统/推理工程/量化.md#量化>)、round | BPDA |
| 随机化防御 | random resize、noise | EOT |
| 饱和激活 | 梯度接近 0 | 换 loss、换优化 |
| 破碎梯度 | 梯度方向不稳定 | 黑盒攻击、迁移攻击 |

### 如何检查

1. 比较白盒攻击和黑盒攻击强度。
2. 增加 PGD steps 和 restarts。
3. 增大 `epsilon`，观察 ASR 是否合理上升。
4. 使用 BPDA/EOT 处理不可导或随机防御。
5. 使用无梯度攻击或迁移攻击交叉验证。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 概念题 | 什么是 gradient masking | 梯度攻击失败但真实边界不鲁棒 |
| 判断题 | 防御 PGD 打不穿是否可信 | 看黑盒、步数、预算、BPDA/EOT |
| 方法题 | 随机防御怎么攻 | EOT |
| 方法题 | 非可导防御怎么攻 | BPDA |

### 易错点

- 看到 PGD ASR 低就认为防御强。
- 不做 restarts，低估攻击强度。
- 不测黑盒迁移。
- 随机防御不做 EOT。

## 面试应对

### 1. 什么是 Gradient Masking，它为什么会造成虚假的鲁棒性？

回答思路：区分攻击优化通道失效与决策边界真正改善，并说明非可导、随机化和梯度饱和等来源。

完整回答模板：

Gradient Masking 是指防御使输入梯度为零、不连续、噪声很大或方向失真，导致基于梯度的攻击难以优化，但攻击者可达的错误决策区域并未真正消失。常见来源包括量化、取整等不可导预处理，随机变换造成的梯度方差，以及饱和激活或数值问题造成的梯度消失。此时低 ASR 反映的可能只是攻击算法没有找到反例，而不是模型在既定扰动集合内保持正确，所以不能把普通梯度攻击失败直接解释为鲁棒。

### 2. 如何从实验现象识别 Gradient Masking？

回答思路：用白盒与黑盒强弱关系、攻击迭代和预算曲线、随机重启及无约束攻击等一致性检查建立证据链。

完整回答模板：

我会检查多种反常信号：白盒攻击是否反而弱于黑盒迁移或无梯度攻击；增加 PGD 步数和随机重启后攻击是否没有增强；增大扰动预算后 robust accuracy 是否几乎不降；无约束攻击是否仍找不到明显反例；攻击损失是否剧烈震荡、梯度是否大量为零或不同随机种子差异异常。单个现象不能单独定性，但如果多个检查同时异常，就应优先怀疑梯度被遮蔽，并进一步使用针对防御机制的自适应攻击验证。

### 3. BPDA 和 EOT 分别怎样绕过 Gradient Masking？

回答思路：分别对应不可导与随机防御，说明前向保持真实防御、反向采用近似或期望梯度。

完整回答模板：

BPDA 主要处理不可导或梯度无意义的模块。攻击前向仍通过真实防御计算输出，反向则用恒等映射或可导近似替代该模块，以获得可用于优化的梯度。EOT 主要处理随机防御，它对多次随机变换下的损失或梯度取期望，用采样平均降低梯度方差。若防御同时包含不可导和随机操作，可以组合 BPDA 与 EOT。它们的目的不是改变威胁模型，而是在攻击者知道防御的前提下，更准确地优化原有攻击目标。

### 4. 哪些验证仍不足以排除 Gradient Masking，结论边界是什么？

回答思路：强调某一种增强攻击成功或失败都不是完整结论，需要覆盖攻击族、预算、重启和自适应性，并限定到已评估威胁模型。

完整回答模板：

仅增加 PGD 步数、只跑一次 BPDA、只加入一种黑盒攻击，或只看到某个预算下 robust accuracy 较高，都不足以排除 Gradient Masking。近似梯度可能不准确，EOT 采样可能不足，无梯度攻击也可能受查询预算限制，因此要联合使用多重随机重启、不同损失、BPDA/EOT、迁移或无梯度攻击，并报告攻击收敛和预算曲线。即使这些测试都未发现问题，也只能说明在已声明的模型访问权限、扰动集合和攻击配置下暂未找到更强反例，不能推出对所有攻击都鲁棒。
