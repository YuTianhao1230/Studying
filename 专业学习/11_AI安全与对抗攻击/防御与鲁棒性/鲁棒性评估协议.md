# 鲁棒性评估协议

## 知识点解析

### 概述

鲁棒性评估协议用于判断攻击或防御实验是否可信，核心是明确威胁模型、扰动预算、攻击强度、clean 性能、统计口径和自适应攻击。

### 解决的问题

对抗攻击和防御实验很容易因为设置不公平得出错误结论。鲁棒性评估协议要回答：

- 攻击者能访问什么？
- 能修改什么？
- 预算是多少？
- 用什么攻击？
- 如何定义成功？
- 防御是否伤害 clean 性能？
- 是否考虑 adaptive attack？

### 基本检查清单

| 维度 | 要检查什么 |
| --- | --- |
| 威胁模型 | 白盒、黑盒、查询预算、可修改模态 |
| 扰动预算 | `L_inf/L_2/L_0`、文本替换率、像素范围 |
| 攻击强度 | steps、alpha、restarts、loss、目标 |
| clean 性能 | 原始准确率或任务指标 |
| robust 性能 | 攻击后准确率、ASR、accuracy drop |
| 统计口径 | 样本量、clean correct 过滤、置信区间 |
| adaptive attack | 攻击者是否知道防御并重新优化 |
| 语义保持 | 图像可感知质量、文本语义一致性 |

### 攻击评估

攻击方法报告时至少包含：

- 数据集和样本量。
- 源模型和目标模型。
- 扰动预算。
- attack steps、step size、随机初始化。
- 是否使用动量、输入变换、模型集成。
- ASR 定义。
- 失败案例和边界。

### 防御评估

防御方法报告时至少包含：

- 防御前后 clean 性能。
- 多攻击方法和多预算。
- 强白盒攻击。
- [黑盒迁移攻击](<../迁移与通用攻击/黑盒迁移攻击.md#黑盒迁移攻击>)。
- adaptive attack。
- 计算成本和延迟。
- 误报率/漏报率，如果是检测防御。

### 多模态评估补充

多模态攻击还要额外说明：

- 图像扰动预算。
- 文本替换比例和语义相似度。
- prompt 模板。
- MLLM 版本和 decoding 参数。
- Judge 规则。
- 输出变化是否等价改写。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 实验设计 | 如何证明攻击更强 | 同预算、同数据、同目标、同 ASR 口径 |
| 防御判断 | 某防御 ASR 低是否可信 | 看 clean 性能、多攻击、adaptive attack |
| 多模态协议 | 怎么评估 MLLM 攻击 | 固定 prompt、judge、模型版本和样本过滤 |
| 公平比较 | baseline 怎么对齐 | 访问权限、扰动预算、文本替换率、查询预算 |

### 易错点

- baseline 威胁模型更弱，却直接比较 ASR。
- 不说明像素范围，`8/255` 口径不清。
- clean 下已经错的样本也算攻击成功。
- 只报平均值，不做分模型、分任务分析。
- 防御不测 adaptive attack。

## 面试应对

### 1. 一份可信的鲁棒性评估协议首先要明确什么？

回答思路：先定义攻击者能力、允许扰动和成功条件，再说明为什么不同威胁模型的结果不能直接横向比较。

完整回答模板：

首先要把威胁模型写清楚：攻击者是白盒、迁移黑盒还是查询黑盒，能访问参数、梯度、输出分数还是只有标签，能修改哪些模态，采用什么范数或语义约束，扰动与查询预算是多少，以及定向或非定向成功如何定义。随后固定数据、模型版本、预处理和样本过滤规则。不同访问权限、预算或成功条件对应不同问题，不能把弱威胁模型下的结果与强威胁模型下的结果直接比较，也不能把某个局部设定下的鲁棒性外推为普遍安全。

### 2. 攻击强度和公平性应该怎样验证？

回答思路：按同预算对齐、攻击收敛、自适应攻击和多攻击交叉验证回答，说明 baseline 也必须充分调参。

完整回答模板：

公平比较要求所有方法使用相同的评估样本、输入范围、扰动或查询预算、目标定义和 ASR 分母，并分别为各自方法提供合理调参，不能只强化自己的攻击而沿用弱 baseline。攻击强度要通过步数、步长、随机重启和预算曲线检查收敛，并用不同损失或攻击族交叉验证。评估防御时，攻击者应知道防御机制并构造 adaptive attack；遇到不可导或随机模块，要考虑 BPDA、EOT 或合适的无梯度方法。若更强配置持续降低 robust accuracy，原评估就尚未达到可信的强度。

### 3. clean、robust accuracy 和 ASR 应如何统计，为什么要过滤样本？

回答思路：先给出各指标含义和分母，再强调 clean-correct 子集、置信区间与分组结果，避免指标口径混用。

完整回答模板：

clean accuracy 衡量未攻击输入上的任务性能，robust accuracy 衡量攻击后仍预测正确的比例，ASR 衡量攻击成功比例。攻击能力分析通常应在 clean 下原本正确且满足攻击条件的样本上统计 ASR，因为模型原先就答错的样本不能算被攻击成功；同时要明确 targeted 与 untargeted 的成功条件。报告时应给出样本量、失败和无效样本处理方式、均值或置信区间，并按模型、任务或数据子集分组。防御若通过大量拒绝或损害 clean 性能降低 ASR，还应单独报告覆盖率、拒绝率和 clean-robust 权衡。

### 4. 多模态或生成式模型的鲁棒性评估有哪些额外失败边界？

回答思路：从双模态预算、语义保持、生成随机性和 Judge 可靠性展开，说明“输出变化”不等于“攻击成功”。

完整回答模板：

多模态评估必须分别声明图像扰动和文本修改的权限与预算，并验证文本语义、图像可感知质量及关键事实没有被攻击本身破坏。生成式模型还要固定模型版本、prompt、系统指令和 decoding 参数，预先定义任务级成功条件；仅出现措辞变化不能算攻击成功。规则或 LLM Judge 可能受格式、顺序和自身偏差影响，因此应校准判定模板，抽样人工复核并报告一致性。结论还受未覆盖的模型、任务、语言、攻击权限和预算限制，不能由单一数据集或单一 Judge 推广到所有多模态场景。
