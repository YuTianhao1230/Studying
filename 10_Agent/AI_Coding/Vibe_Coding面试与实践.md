# Vibe Coding 面试与实践

资料来源：飞书 Wiki《Vibe Coding 面试方式-实践分享》

## 核心结论

Vibe Coding 面试不是考“会不会让 AI 写代码”，而是考候选人在 AI 参与下是否仍能主导工程交付：定义问题、澄清需求、拆解任务、约束 AI、验证结果、调试错误，并对最终产物负责。

## 背景

AI 编程工具已经进入规模化应用阶段。以 Claude Code、Codex、Trae、Aime 等为代表的 Coding Agent，使开发者可以通过自然语言描述需求，由 AI 完成代码生成、调试和迭代。

这改变了工程师能力模型：

- 从“单人手写代码”转向“人机协同交付”。
- 从“知道答案”转向“能定义问题并验证结果”。
- 从“局部实现”转向“端到端交付和质量兜底”。

## Vibe Coding 面试本质考察什么

### 1. AI 协作中的决策质量

重点不是生成速度，而是候选人如何控制过程：

- 能否把模糊需求转成清晰 PRD。
- 能否给 AI 最少但有效的信息。
- 能否发现 AI 输出中的错误。
- 能否在 AI 跑偏时重新定义问题。
- 能否对工具选择、方案设计、实现路径做判断。

对应能力：

- 分析能力。
- 抽象能力。
- 总结能力。
- 工程基本功。

### 2. 真实 AI 生产力

面试不看概念展示，而看真实开发场景中的产出：

- 是否把 AI 放进完整研发流程。
- 是否能借助 AI 完成跨端、全栈或陌生领域 MVP。
- 是否有质量验收意识。
- 是否会把失败归责给 AI，而不是自己做最终把关。

对应能力：

- 扎实工程基础。
- AI 工具实践经验。
- 责任心。
- 端到端交付意识。

### 3. 过程可观察、可验证

Vibe Coding 面试需要观察过程，而不是只看最终代码：

- 候选人怎么向 AI 下指令。
- 如何拆分任务。
- 如何审查生成代码。
- 如何调试跑不通的问题。
- 如何解释技术方案和取舍。
- 是否能展示可运行 Demo。

## 常见考察形式

### 类型一：Vibe Coding 需求交付

核心目标：考察端到端交付能力。

典型流程：

1. 自我介绍和工具使用经验。
2. 面试官给出模糊需求。
3. 候选人澄清需求并形成 PRD。
4. 候选人与 AI 协作生成技术方案。
5. 编码实现。
6. 运行验证。
7. Demo 展示和追问。

考察维度：

- 业务场景理解。
- 需求边界界定。
- 技术选型。
- AI 协作策略。
- Demo 完整性。
- 验证和错误分析。

适合题型：

- 大前端。
- 桌面应用。
- 移动端 H5。
- 小型全栈应用。
- 可交互 MVP。
- 有明确验收标准的业务原型。

不太适合：

- 纯架构题。
- 纯算法题。
- 无法在 60 分钟内验证的复杂系统。

### 类型二：Vibe Coding 协作编程

核心目标：考察 AI 辅助下的编码、调试和工程维护意识。

典型流程：

1. 询问 AI 工具经验。
2. 讨论通用 Agent 或 Coding Agent 设计。
3. 给定可实现的小题。
4. 候选人共享屏幕，用 AI 辅助完成。
5. 面试官观察 prompt、调试和验收过程。

题目示例：

- 实现一个前端自动化测试 MCP，让 Agent 可以打开浏览器、搜索关键词并返回结果。
- 实现 Agent & Skill Loader，并 Mock 执行流程。
- 构建小型异步事件总线。
- 构建简化版 RAG 系统。
- 构建代码审查系统。

## 面试官观察点

### Prompt 和交互

- 是否能给出清晰任务边界。
- 是否能补充上下文，而不是只说“帮我写”。
- 是否能让 AI 先产出方案，再进入编码。
- 是否会让 AI 生成测试、解释代码、定位错误。
- 是否能在 AI 误解时及时纠偏。

### 工程基本功

- 是否能读懂 AI 生成代码。
- 是否能识别类型错误、接口错误、边界条件错误。
- 是否能运行和调试。
- 是否能解释代码结构。
- 是否知道如何维护生成代码。

### 交付质量

- 是否有可运行产物。
- 是否有基本测试。
- 是否覆盖核心场景。
- 是否记录已知限制。
- 是否能说明下一步迭代方向。

## 对候选人的准备建议

### 1. 建立标准工作流

```text
需求澄清
  -> PRD / 验收标准
  -> 技术方案
  -> 任务拆分
  -> AI 协作编码
  -> 本地运行
  -> 测试验证
  -> Demo 汇报
  -> 复盘限制
```

### 2. 把 AI 当协作者，不是答案生成器

候选人要体现主导权：

- 先定义目标。
- 再让 AI 给方案。
- 自己审查方案。
- 让 AI 执行局部任务。
- 自己负责集成和验证。

### 3. 强化“可验证交付”

面试中最有说服力的是可运行结果：

- 本地能启动。
- 核心路径能走通。
- 有测试或 demo 数据。
- 能解释失败 case。
- 能说明 tradeoff。

## 面试回答模板

如果被问“你怎么理解 Vibe Coding 能力”，可以这样答：

```text
我理解 Vibe Coding 不是把代码完全交给 AI，而是用 AI 扩展工程交付能力。
我会先把需求澄清成可验收目标，再拆成可执行任务，让 AI 辅助生成方案、代码和测试。
过程中我会持续审查 AI 输出，尤其关注接口契约、边界条件、错误处理和可运行性。
最终我对产物负责，所以必须完成本地验证、问题归因和限制说明。
```

## 和 Agent 的关系

Vibe Coding 是 Agent 能力在软件工程场景中的应用。它背后涉及：

- 任务规划。
- 上下文组织。
- 工具调用。
- 代码生成。
- 调试反馈。
- 评测与验收。
- 人机协同控制权。

因此它不应只放在“编程技巧”里，而应作为 Agent 工程能力的一部分单独沉淀。
