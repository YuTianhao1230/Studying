# Tool Call 与 Function Calling

## 一句话解释

Tool Call / Function Calling 是让大模型以结构化方式请求外部工具执行动作的机制，例如查数据库、读文件、调用 API、打开浏览器、运行代码。

## 为什么需要 Tool Call

LLM 本身只能生成文本，不能真正访问外部世界。Tool Call 让模型可以把“我要做什么”表达成结构化调用：

```json
{
  "tool": "search_files",
  "arguments": {
    "pattern": "**/*.py"
  }
}
```

真正执行工具的是外层 Orchestrator，而不是模型本身。

## 基本流程

```text
用户目标
  -> 模型判断需要工具
  -> 生成 tool call
  -> Orchestrator 校验参数
  -> 执行工具
  -> 工具结果返回给模型
  -> 模型继续推理或输出最终答案
```

## Tool Schema

工具需要给模型提供结构化描述，通常包括：

- 工具名。
- 工具说明。
- 参数名。
- 参数类型。
- 必填字段。
- 返回结果格式。
- 使用限制。

Schema 写得越清楚，模型越容易正确调用。

## 好的工具设计

- 名字清晰，动作明确。
- 参数少而精。
- 参数类型严格。
- 返回结构化数据，优先 JSON。
- 错误信息可诊断。
- 工具职责单一。
- 对高风险操作设置确认。

## 常见失败模式

- 参数名写错。
- 参数类型不匹配。
- 工具描述太模糊，模型不知道何时使用。
- 返回内容过长，污染上下文。
- 工具报错不可读，模型无法恢复。
- 高风险工具缺少权限和确认机制。

## Tool Call 和 MCP 的关系

Tool Call 是能力调用机制；MCP 是一种标准协议，用于统一发现和调用外部工具。

简单说：

```text
Tool Call：模型调用工具这件事
MCP：把工具标准化暴露给 Agent 的协议
```
