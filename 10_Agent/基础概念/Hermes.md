# Hermes

## 一句话解释

Hermes 通常不是一个行业统一标准名词，更多是不同公司或团队内部系统的名字。它常被用来表示“消息分发、任务调度、模型服务编排或异步执行系统”。

## 名字为什么容易混淆

Hermes 在不同上下文里可能指：

- 消息队列系统。
- 任务调度平台。
- 模型推理请求分发层。
- Agent 工具编排层。
- 异步评测执行系统。
- 内部服务网关或 RPC 框架。

所以听到 Hermes 时，第一步不是背定义，而是追问它在当前系统中承担什么职责。

## 在 AI 系统里 Hermes 常见职责

### 1. 任务调度

例如有 100 万条样本要评测，不能由一个脚本串行跑完。Hermes 可能负责：

- 创建任务。
- 拆分 shard。
- 分发给 worker。
- 记录任务状态。
- 失败重试。
- 汇总结果。

```text
评测任务
  -> Hermes 拆分任务
  -> 多个 Worker 执行
  -> 结果回传
  -> 汇总与状态更新
```

### 2. 消息分发

Hermes 也可能类似消息队列：

```text
Producer 生产任务消息
  -> Hermes / Queue
  -> Consumer 消费任务消息
```

用于削峰、异步执行、解耦系统。

### 3. 模型服务编排

在多模型服务中，Hermes 可能负责：

- 根据任务类型选择模型。
- 路由到不同 endpoint。
- 限流和熔断。
- 超时和重试。
- 收集调用日志。

### 4. Agent 编排

在 Agent 系统里，Hermes 可能是中间层：

- 管理工具调用。
- 维护任务状态。
- 分发多步任务。
- 接收工具结果。
- 做失败恢复。

## Hermes 和 Harness 的区别

```text
Harness 更偏评测逻辑：
读取数据、调用模型、计算指标、分析结果。

Hermes 更偏执行调度：
分发任务、管理队列、调度 worker、处理异步状态。
```

简单理解：

- Harness 关心“怎么评测”。
- Hermes 关心“怎么把任务可靠地跑起来”。

两者可以一起工作：

```text
Harness 创建评测任务
  -> Hermes 分发任务
  -> Worker 调用模型
  -> Harness 汇总评测结果
```

## 面试回答方式

如果面试官问“Hermes 是什么”，不要直接给死定义，可以这样答：

```text
Hermes 这个名字在不同团队里含义不完全一样。
如果放在 AI 工程链路里，我会先把它理解为任务调度或服务编排层。
它通常负责把上层评测、训练或推理任务拆分、分发、执行、重试和汇总。
和 Harness 相比，Harness 更关注评测逻辑，Hermes 更关注任务执行可靠性和系统编排。
```

## 常见误区

- 把 Hermes 当成固定行业标准。
- 不区分调度层、评测层和模型服务层。
- 只关注模型调用，不关注任务状态、重试和幂等。
- 没有保存任务级别和样本级别的状态，导致失败后难恢复。

## 面试可能怎么问

1. Hermes 在你们系统中承担什么职责？
2. 任务调度系统如何支持失败重试？
3. 如何保证任务幂等？
4. 如何设计 worker 扩缩容？
5. 如何处理部分任务成功、部分任务失败？
