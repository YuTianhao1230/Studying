# 生产级 Agent 案例

## 一句话解释

生产级 Agent 不是“能聊天的模型”，而是有明确任务边界、工具权限、状态管理、评测回归、观测告警和人工兜底的工程系统。

## 为什么需要单独理解

Demo 级 Agent 只需要完成一次任务；生产级 Agent 需要稳定、可控、可审计、可迭代。

区别在于：

| 维度 | Demo Agent | 生产级 Agent |
| --- | --- | --- |
| 目标 | 展示能力 | 稳定完成业务任务 |
| 工具 | 随意调用 | 权限受控、参数校验 |
| 上下文 | 临时拼接 | 可管理、可压缩、可追踪 |
| 失败处理 | 失败就重试 | 有降级、回滚、人工接管 |
| 评测 | 看几个例子 | 持续回归和线上监控 |
| 安全 | 依赖模型自觉 | Guardrails + 审计 |

## 案例 1：Code Agent

目标：根据需求修改代码、运行测试、修复失败。

典型链路：

```text
需求理解
  -> 读取仓库上下文
  -> 生成计划
  -> 修改代码
  -> 运行测试
  -> 根据失败日志修复
  -> 输出变更说明
```

关键能力：

- 文件检索。
- 代码理解。
- 工具调用。
- 测试执行。
- 错误定位。
- 回滚和最小修改。

生产风险：

- 改坏无关文件。
- 误删用户改动。
- 运行破坏性命令。
- 编译过但业务逻辑错。

需要的工程约束：

- sandbox。
- diff 审计。
- 测试门禁。
- 权限确认。
- 轨迹记录。

## 案例 2：Search / Deep Research Agent

目标：围绕复杂问题主动搜索、筛选、归纳并给出带证据的答案。

典型链路：

```text
问题拆解
  -> 生成搜索 query
  -> 多轮检索
  -> 证据筛选
  -> 交叉验证
  -> 汇总答案
  -> 引用来源
```

关键能力：

- Query planning。
- 多跳检索。
- 信息去重。
- 证据可信度判断。
- 引用和可追溯。

生产风险：

- 搜索结果污染。
- 引用和结论不匹配。
- 幻觉式归纳。
- 过度检索导致成本失控。

需要的工程约束：

- 证据必须可回溯。
- 结论和引用绑定。
- 设置搜索预算。
- 对高风险问题启用人工复核。

## 案例 3：数据分析 Agent

目标：根据自然语言问题查询数据、生成分析结论和图表。

典型链路：

```text
需求澄清
  -> 表结构理解
  -> SQL 生成
  -> 权限检查
  -> 查询执行
  -> 数据校验
  -> 分析和可视化
```

关键能力：

- Schema linking。
- SQL generation。
- 数据质量检查。
- 指标口径对齐。
- 可视化解释。

生产风险：

- SQL 查错表。
- 指标口径不一致。
- 泄露敏感数据。
- 大查询拖垮数据库。

需要的工程约束：

- 只读权限。
- 查询预算。
- 敏感字段识别。
- 指标字典。
- 人工确认高风险查询。

## 案例 4：GUI / Computer Use Agent

目标：操作浏览器或桌面 UI 完成任务。

典型链路：

```text
观察屏幕
  -> 识别 UI 元素
  -> 规划下一步
  -> 点击 / 输入
  -> 读取反馈
  -> 循环直到完成
```

关键能力：

- UI grounding。
- 状态识别。
- 长任务规划。
- 错误恢复。

生产风险：

- 点错按钮。
- 无法识别弹窗。
- 重复提交。
- 越权操作。

需要的工程约束：

- 操作前确认高风险动作。
- 关键步骤截图留痕。
- 幂等性设计。
- 失败自动停止。

## 生产级 Agent 的通用架构

```text
User Request
  -> Intent / Policy Check
  -> Planner
  -> Tool Router
  -> Executor
  -> Observation
  -> Memory / State
  -> Verifier / Grader
  -> Final Response
```

## 面试回答要点

如果被问“怎么设计一个生产级 Agent”，可以这样回答：

```text
我会先定义任务边界和成功标准，再设计可控的工具集合。
执行层采用 planner-executor-observer 循环，每一步工具调用都做参数校验和权限控制。
上下文用 memory/state 管理，关键轨迹落盘，方便复盘和评测。
质量上用离线 eval、线上监控、bad case 回归和人工兜底保证稳定性。
高风险动作必须有人审或策略拦截，不能只依赖模型自觉。
```

## 面试可能怎么问

1. Demo Agent 和生产级 Agent 有什么区别？
2. Code Agent 如何避免误改代码？
3. Search Agent 如何降低幻觉？
4. 数据分析 Agent 如何避免查错表或泄露数据？
5. GUI Agent 为什么需要 grounding 和人工确认？
