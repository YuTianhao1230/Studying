# Planning 与 ReAct

## 一句话解释

Planning 是 Agent 在执行前或执行中拆解任务、安排步骤的能力；ReAct 是把推理和行动交替进行的 Agent 模式，即 Reasoning + Acting。

## ReAct 是什么

ReAct 的核心循环：

```text
Thought -> Action -> Observation -> Thought -> ...
```

更工程化地说：

```text
分析当前状态
  -> 决定调用哪个工具
  -> 执行工具
  -> 读取工具结果
  -> 更新判断
  -> 继续或结束
```

## Planning 的类型

### 1. Upfront Planning

先生成完整计划，再执行。

适合：

- 需求明确。
- 步骤相对稳定。
- 需要用户先 review。

风险：

- 计划可能很快过期。
- 对未知环境假设过多。

### 2. Step-by-step Planning

每执行一步后根据结果重新规划。

适合：

- 调试。
- 代码库探索。
- 网页操作。
- 数据分析。

风险：

- 容易碎片化。
- 需要良好的终止条件。

### 3. Hierarchical Planning

先拆成大阶段，再在每个阶段内细化。

适合：

- 大型工程任务。
- 多 Agent 协作。
- 长周期自动化任务。

## 好计划的标准

- 目标明确。
- 每一步可验证。
- 有失败处理。
- 有终止条件。
- 能区分探索、修改、验证。
- 不把未知假设写成事实。

## 常见失败模式

- 只计划不执行。
- 计划太细，工具结果一变就失效。
- 计划没有验收标准。
- 遇到错误后继续按旧计划执行。
- 为简单任务引入复杂规划。

## 和 Workflow 的关系

- Workflow 是预定义流程。
- Planning 是 Agent 动态生成或更新流程。

生产系统常见组合：

```text
Workflow 固定边界
  -> Agent 在局部步骤内动态规划
  -> 关键节点由规则或人工确认
```
