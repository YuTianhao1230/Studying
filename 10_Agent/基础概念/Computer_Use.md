# Computer Use

## 一句话解释

Computer Use 是让 Agent 像人一样操作电脑界面，包括看屏幕、移动鼠标、点击、输入、打开应用、使用浏览器和处理文件。

## 和普通工具调用的区别

普通 Tool Call 通常是结构化 API：

```text
search(query="xxx")
read_file(path="xxx")
```

Computer Use 面向 GUI 环境：

```text
观察屏幕截图
  -> 判断按钮位置
  -> 点击
  -> 输入文本
  -> 等待页面变化
  -> 再观察
```

它更接近人类操作，但也更脆弱。

## 常见能力

- 浏览器操作。
- 桌面应用操作。
- 表单填写。
- 文件下载和上传。
- 截图理解。
- UI 元素定位。
- 键盘鼠标控制。

## 为什么 Computer Use 重要

很多系统没有稳定 API，或 API 接入成本很高。Computer Use 可以让 Agent 通过已有 UI 完成任务。

适合：

- 网页自动化。
- 内部系统没有 API 的流程。
- 跨多个应用的办公任务。
- 人类原本通过浏览器完成的重复操作。

不适合：

- 高并发批处理。
- 严格稳定的生产链路。
- 高风险金融、权限、删除操作。
- UI 经常变化且没有容错的流程。

## 关键工程难点

- 页面加载不确定。
- 元素定位不稳定。
- 截图理解可能出错。
- 点击位置可能偏移。
- 登录态和权限复杂。
- 错误恢复困难。

## 设计原则

- 能用 API 就优先用 API。
- UI 自动化必须有明确检查点。
- 每次关键操作后重新观察页面状态。
- 对提交、删除、支付等动作设置人工确认。
- 保存截图和操作日志，方便复盘。
