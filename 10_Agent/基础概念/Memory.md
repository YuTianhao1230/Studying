# Memory

## 一句话解释

Memory 是 Agent 保存和取回历史信息的机制，用来支持跨步骤、跨会话、跨任务的连续性。

## 为什么需要 Memory

没有 Memory 的 Agent 是短视的：

- 只知道当前上下文。
- 不记得用户偏好。
- 不知道历史失败。
- 不能复用过往经验。
- 长任务容易丢状态。

Memory 让 Agent 可以把重要信息保存下来，并在后续任务中按需取回。

## Memory 的常见类型

### 1. Short-term Memory

短期记忆，通常就是当前对话上下文。

适合：

- 当前任务的约束。
- 最近工具调用结果。
- 临时计划。

### 2. Working Memory

工作记忆，保存当前任务的中间状态。

适合：

- TODO 列表。
- 当前假设。
- 已验证事实。
- 失败重试状态。

### 3. Long-term Memory

长期记忆，跨会话保存。

适合：

- 用户偏好。
- 项目约定。
- 常用路径。
- 历史经验教训。

### 4. Episodic Memory

事件记忆，记录过去任务发生过什么。

适合：

- 某次 debug 过程。
- 某个评测结论。
- 某次上线事故复盘。

### 5. Semantic Memory

语义记忆，保存抽象知识。

适合：

- 概念解释。
- 领域规则。
- 常见问题答案。

## Memory 和 Context 的区别

- Context：当前模型调用能看到的信息。
- Memory：可长期保存、后续检索的信息。

Memory 只有被检索并放入上下文后，才会影响模型当前决策。

## 设计原则

- 只保存长期有价值的信息。
- 不保存秘密、token、密码。
- 不保存一次性中间日志。
- 写入时要去噪、压缩、结构化。
- 读取时要按任务相关性检索。
- Memory 内容要允许更新和失效。

## 常见失败模式

- 什么都记，导致噪声越来越多。
- 记了错误结论，后续持续污染决策。
- 把敏感信息写入长期记忆。
- 不区分用户偏好、项目约定和任务进度。
- 只存不取，或者无关任务乱取。
