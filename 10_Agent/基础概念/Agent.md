# Agent

## 一句话解释

Agent 是以大模型为决策核心，能够感知环境、规划步骤、调用工具、观察结果并迭代完成目标的系统。

## 和普通 Chatbot 的区别

普通 Chatbot 更像“问答器”：

```text
用户问题 -> 模型回答 -> 结束
```

Agent 更像“执行者”：

```text
目标
  -> 观察当前状态
  -> 规划下一步
  -> 调用工具 / 写代码 / 访问环境
  -> 读取结果
  -> 判断是否完成
  -> 继续迭代或交付结果
```

核心差异不是模型更强，而是系统允许模型进入闭环：它可以根据中间结果动态调整行动。

## Agent 通常包含什么

- LLM Core：负责推理、决策、规划。
- Tools：文件系统、浏览器、数据库、API、命令行等外部能力。
- Orchestrator：维护 agent loop，决定何时继续、停止、重试或升级给人。
- Memory：保存短期上下文、长期偏好、历史经验。
- Guardrails：权限、预算、超时、危险操作确认、输出校验。
- Observability：记录每一步输入、工具调用、输出、错误和耗时。
- Evaluator：判断任务是否完成、输出是否可靠。

## Agent Loop

常见执行循环：

```text
Observe -> Plan -> Act -> Observe -> Reflect -> ...
```

也可以叫：

- Thought-Action-Observation
- ReAct Loop
- Perception-Planning-Action-Reflection

## 什么时候适合用 Agent

适合：

- 任务需要多步执行。
- 中间结果会影响下一步决策。
- 需要调用多个工具或系统。
- 任务边界不完全固定，需要动态探索。
- 需要持续验证和纠错。

不适合：

- 单轮问答。
- 单个确定性 API 调用。
- 完全固定的 ETL 流程。
- 高风险且无法审计的自动操作。

## 常见误区

- 把 Agent 等同于“套了工具调用的 LLM”。
- 只关注规划，不关注执行状态和失败恢复。
- 没有终止条件，导致循环失控。
- 没有审计日志，出错后无法复盘。
- 把确定性流程硬做成 Agent，增加成本和不稳定性。

## 面试可能怎么问

1. Agent 和 Chatbot 的区别是什么？
   - 回答思路：先分别定义两个概念，再从目标、机制、适用场景和工程取舍四个角度对比。
   - 回答模板：Agent 和 Chatbot 的核心区别在于是否能围绕目标主动执行任务。Chatbot 主要是根据用户输入生成自然语言回复；Agent 除了对话，还会观察环境、拆解任务、选择工具、执行动作，并根据工具结果继续调整下一步。比如用户说“帮我修这个测试失败”，Chatbot 可能只给建议，而 Code Agent 会读代码、运行测试、修改文件并再次验证。
2. Agent Loop 一般由哪些阶段构成？
   - 回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。
   - 回答模板：一个典型 Agent Loop 包括目标理解、观察当前状态、规划下一步、调用工具执行、读取工具返回、更新判断、验证是否完成。如果没完成，就继续循环；如果失败，则进入重试、降级或人工接管。生产系统里还会加入权限校验、超时控制和轨迹记录。
3. 什么任务适合 Agent，什么任务不适合？
   - 回答思路：先给适用条件，再给不适用条件，最后说明真实系统里如何组合使用。
   - 回答模板：适合多步、开放、需要工具反馈和动态决策的任务；不适合规则固定、低延迟、强确定性的简单流程。稳定流程优先 Workflow。
4. Agent 系统的主要失败模式有哪些？
   - 回答思路：先定义问题，再说明核心机制、适用边界、风险和验证方式。
   - 回答模板：包括目标漂移、工具选错、参数错误、上下文污染、无限循环、幻觉、越权和失败恢复不足。需要轨迹记录和评测闭环来定位。
5. 如何设计一个可观测、可恢复的 Agent？
   - 回答思路：按“目标定义 -> 关键步骤 -> 风险控制 -> 指标验证”的顺序回答，避免只讲抽象原则。
   - 回答模板：记录每步输入、上下文、计划、工具调用、结果和错误；设置状态机、超时、重试、断点和人工接管。恢复时从最近稳定状态继续。
