# Context Engineering

## 一句话解释

Context Engineering 是为 Agent 设计“当前应该看见什么信息”的工程方法，目标是在有限上下文窗口内提供足够、准确、低噪声的信息。

## 为什么重要

Agent 的能力不只取决于模型，也取决于上下文质量。

上下文太少：

- 缺少约束。
- 错过关键文件。
- 工具选择错误。
- 输出不符合预期。

上下文太多：

- token 成本高。
- 注意力被稀释。
- 旧信息污染新判断。
- 更容易漏看关键点。

## Context Engineering 包含什么

- 信息选择：哪些内容该放进上下文。
- 信息压缩：如何总结而不丢关键事实。
- 信息分层：哪些常驻，哪些按需读取。
- 检索策略：如何从文档、代码、记忆中取相关内容。
- 上下文隔离：不同任务、不同 Agent 不互相污染。
- 过期处理：旧结论何时失效。

## 常见上下文来源

- 用户需求。
- 系统指令。
- Skill。
- Memory。
- 代码文件。
- 文档。
- 工具返回。
- 历史错误。
- 当前计划。

## 好的上下文应满足什么

- Relevant：与当前任务相关。
- Grounded：来自可靠来源。
- Concise：足够短。
- Structured：便于模型定位。
- Fresh：反映当前状态。
- Actionable：能指导下一步动作。

## 渐进加载

Agent 不应该一次性读取所有资料，而应按需展开：

```text
目录 / 摘要
  -> 相关章节
  -> 具体片段
  -> 必要时读取全文
```

这和 Skill 的设计逻辑一致：入口要短，细节按需加载。

## 常见误区

- 把所有文档直接塞给模型。
- 只做向量检索，不做结构化导航。
- 不区分事实、假设和历史结论。
- 忘记工具结果也会占上下文。
- 上下文压缩时丢掉关键约束。

## 面试可能怎么问

1. Context Engineering 和 Prompt Engineering 有什么区别？
2. 为什么 Agent 不能把所有资料都放进上下文？
3. 如何设计长期任务的上下文管理？
4. 如何避免旧上下文污染当前决策？
5. Skill 的 progressive disclosure 和 Context Engineering 是什么关系？
