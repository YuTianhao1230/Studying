# Harness

## 知识点解析

### 概述

Harness 是“测试/评测脚手架”，负责把数据、模型调用、输出解析、指标计算、日志记录和结果汇总串成一个可复现的流程。

### 为什么需要 Harness

模型不是只要能调用就算完成。算法工程中更重要的是回答：

- 这批数据跑完了吗？
- 哪些样本成功，哪些失败？
- 模型输出是什么？
- 解析后的预测是什么？
- 和标准答案相比对不对？
- 失败是模型错、数据错、服务错，还是解析错？
- 换模型、换 prompt、换参数后，结果有什么变化？

Harness 就是为了解决这些问题。

### Harness 通常包含什么

```text
输入数据
  -> 数据校验
  -> prompt / request 构造
  -> 模型调用
  -> response 解析
  -> 规则校验 / judge
  -> 指标统计
  -> 结果落盘
  -> bad case 分析
```

常见模块：

- Dataset Loader：读取 JSONL、CSV、Parquet、DataCard 等数据。
- Validator：检查字段、标签、图片 URL、视频路径、任务类型是否合法。
- Prompt Builder：把样本转成模型输入。
- Model Client：调用本地模型、在线服务或推理框架。
- Parser：把模型原始输出解析成结构化预测。
- Evaluator：计算准确率、F1、召回率、格式正确率等指标。
- Reporter：输出 summary、失败样本、diff case。
- Runner：负责并发、重试、断点续跑和进度管理。

### 一个简单例子

假设做图片分类评测：

```text
sample:
{
  "id": "case_001",
  "image": "xxx.jpg",
  "label": "cat"
}
```

Harness 做的事情：

1. 读取样本。
2. 检查图片是否存在。
3. 构造模型输入。
4. 调用模型。
5. 解析模型输出，例如 `"The image is a cat"` -> `cat`。
6. 和 label 比较。
7. 保存结果。

输出可能是：

```json
{
  "id": "case_001",
  "label": "cat",
  "prediction": "cat",
  "correct": true,
  "latency_ms": 532,
  "error": null
}
```

### 好的 Harness 应该具备什么能力

- 可复现：同样的数据、模型、参数能得到可追踪结果。
- 可恢复：中途失败后可以断点续跑。
- 可观测：能看到每条样本的 request、response、耗时、错误。
- 可对比：能比较不同模型、不同 prompt、不同 checkpoint 的结果。
- 可扩展：新增模型、新增指标、新增数据格式不需要大改。
- 可审计：保留版本、配置、日志、原始输出。

### 常见误区

- 只保存最终准确率，不保存逐样本结果。
- 失败样本直接跳过，导致指标虚高。
- 解析逻辑和评测逻辑混在一起，难以定位错误。
- 改了 prompt、数据、模型参数但没有记录版本。
- 没有断点续跑，大批量评测失败后只能重跑全部。

## 面试应对

### 你如何设计一个模型评测 Harness？

回答思路：先明确目标和约束，再拆系统模块，最后说明指标、风险和上线验证方式。

回答模板：

我会把 Harness 拆成数据读取、模型调用、输出解析、指标计算、错误归因、并发控制和结果落盘模块。核心要求是可复现、可断点续跑、能定位失败原因，并支持不同模型版本对比。

### 如何支持并发评测和断点续跑？

回答思路：核心是"稳定样本 ID + 增量落盘跳过已完成"，并发层控速率和重试。

回答模板：

每条样本要有稳定 ID，结果增量落盘，启动时跳过已完成样本。并发层控制速率、超时和重试，避免压垮服务。

### 如何区分模型错误、数据错误和服务错误？

回答思路：按"数据缺字段 / 服务超时异常 / 服务正常但答案不对"三类特征区分。

回答模板：

数据错误通常是样本缺字段或标注错，服务错误是超时、异常或依赖失败，模型错误是服务正常返回但答案不符合预期。要保留原始输入输出和异常。

### 为什么要保存原始 request 和 response？

回答思路：核心是它们是复现和 bad case 归因的最小证据，只存指标无法定位问题。

回答模板：

它们是复现、审计和 bad case 分析的最小证据。只保存指标无法判断失败来自输入、模型输出还是解析逻辑。

### 如何比较两个模型版本的 bad case 差异？

回答思路：按样本 ID 对齐，分共同错误/新增错误/修复错误，再分组归因。

回答模板：

按样本 ID 对齐结果，统计共同错误、新增错误和修复错误，再按任务类型、错误原因和数据来源分组分析。
