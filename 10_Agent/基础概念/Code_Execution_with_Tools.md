# Code Execution with Tools

## 一句话解释

Code Execution with Tools 是让 Agent 在沙箱中写代码来组合调用工具，而不是每一步都把工具结果完整塞回模型上下文。

## 为什么出现这个模式

随着 MCP 和工具生态扩张，Agent 可能同时连接几十甚至上百个工具。传统直接工具调用会遇到两个问题：

- 工具定义太多，占满上下文。
- 大量中间结果反复进出模型，成本高、延迟高、还容易复制错。

例如：

```text
读取长文档 -> 模型收到全文
写入另一个系统 -> 模型又要把全文作为参数传出去
```

中间数据完全经过模型上下文，既浪费 token，也容易出错。

## 基本思路

把工具暴露成代码环境里的 API：

```text
Agent 写一段脚本
  -> 脚本调用多个工具
  -> 在沙箱中处理大数据
  -> 只把摘要、统计或最终结果返回给模型
```

## 适合场景

- 多工具组合调用。
- 大文档处理。
- 大表格处理。
- 数据清洗和转换。
- 批量 API 操作。
- 需要循环、过滤、聚合的任务。

## 优点

- 减少上下文占用。
- 降低模型复制大数据的错误。
- 提升执行效率。
- 让确定性逻辑由代码完成。
- 便于复现和调试。

## 风险

- 沙箱权限必须严格控制。
- 代码生成可能有 bug。
- 外部工具调用仍需权限和审计。
- 大规模写操作必须 dry-run 和人工确认。

## 和 MCP 的关系

MCP 负责把工具标准化暴露出来；Code Execution with Tools 是一种更高效的调用方式。

直接模式：

```text
模型 -> MCP Tool -> 工具结果 -> 模型
```

代码执行模式：

```text
模型 -> 写代码 -> 代码调用 MCP Tools -> 返回压缩结果 -> 模型
```

## 常见误区

- 把所有工具定义一次性塞进上下文。
- 让模型搬运大段中间数据。
- 没有沙箱隔离。
- 把不可控写操作放进自动执行脚本。
- 脚本执行后不保留日志。
