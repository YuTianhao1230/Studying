# 鲁棒性评估协议

## 知识点解析

### 概述

鲁棒性评估协议用于判断攻击或防御实验是否可信，核心是明确威胁模型、扰动预算、攻击强度、clean 性能、统计口径和自适应攻击。

### 解决的问题

对抗攻击和防御实验很容易因为设置不公平得出错误结论。鲁棒性评估协议要回答：

- 攻击者能访问什么？
- 能修改什么？
- 预算是多少？
- 用什么攻击？
- 如何定义成功？
- 防御是否伤害 clean 性能？
- 是否考虑 adaptive attack？

### 基本检查清单

| 维度 | 要检查什么 |
| --- | --- |
| 威胁模型 | 白盒、黑盒、查询预算、可修改模态 |
| 扰动预算 | `L_inf/L_2/L_0`、文本替换率、像素范围 |
| 攻击强度 | steps、alpha、restarts、loss、目标 |
| clean 性能 | 原始准确率或任务指标 |
| robust 性能 | 攻击后准确率、ASR、accuracy drop |
| 统计口径 | 样本量、clean correct 过滤、置信区间 |
| adaptive attack | 攻击者是否知道防御并重新优化 |
| 语义保持 | 图像可感知质量、文本语义一致性 |

### 攻击评估

攻击方法报告时至少包含：

- 数据集和样本量。
- 源模型和目标模型。
- 扰动预算。
- attack steps、step size、随机初始化。
- 是否使用动量、输入变换、模型集成。
- ASR 定义。
- 失败案例和边界。

### 防御评估

防御方法报告时至少包含：

- 防御前后 clean 性能。
- 多攻击方法和多预算。
- 强白盒攻击。
- 黑盒迁移攻击。
- adaptive attack。
- 计算成本和延迟。
- 误报率/漏报率，如果是检测防御。

### 多模态评估补充

多模态攻击还要额外说明：

- 图像扰动预算。
- 文本替换比例和语义相似度。
- prompt 模板。
- MLLM 版本和 decoding 参数。
- Judge 规则。
- 输出变化是否等价改写。

### 常见考法与解题方法

| 考法 | 怎么考 | 怎么解 |
| --- | --- | --- |
| 实验设计 | 如何证明攻击更强 | 同预算、同数据、同目标、同 ASR 口径 |
| 防御判断 | 某防御 ASR 低是否可信 | 看 clean 性能、多攻击、adaptive attack |
| 多模态协议 | 怎么评估 MLLM 攻击 | 固定 prompt、judge、模型版本和样本过滤 |
| 公平比较 | baseline 怎么对齐 | 访问权限、扰动预算、文本替换率、查询预算 |

### 易错点

- baseline 威胁模型更弱，却直接比较 ASR。
- 不说明像素范围，`8/255` 口径不清。
- clean 下已经错的样本也算攻击成功。
- 只报平均值，不做分模型、分任务分析。
- 防御不测 adaptive attack。

## 面试应对

### 怎么判断一个对抗攻防实验是否可信？

回答思路：按威胁模型、公平性和攻击强度回答。

回答模板：

我会先看威胁模型是否清楚，包括攻击者能访问什么、能改哪些输入、扰动预算和查询预算是多少。然后看比较是否公平，baseline 和方法是否使用相同数据、模型、预算和 ASR 口径。接着看攻击强度是否足够，比如 PGD 的步数、restart、是否有黑盒迁移和 adaptive attack。最后还要看 clean 性能、样本量、语义保持和失败案例。只有这些都交代清楚，攻防结论才比较可信。
